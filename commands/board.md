按 `agent-team-board` skill 的 Status Board 流程打开网页看板。目标项目按两级优先级解析
（REQ-20260910-004）：

1. **提示词中提及的项目优先**：命令参数或用户消息里明确提到某个项目（项目名或路径）时，
   解析并打开**那个项目**的看板——即使当前会话位于另一个项目。
2. **左侧项目栏当前会话所属项目兜底**：提示词里没有提及任何项目时，打开当前会话项目的看板，
   行为与现状一致（项目根 = 向上找 git root 或含 `docs/agent-team-board/` 的目录，
   拿不准就用当前工作目录绝对路径，服务端会向上探测）。

**目标项目解析规则**（项目名解析依赖 `/api/health` 返回的已知项目列表，见下面第 1 步）：

- **绝对路径**（含 `~` 展开）：目录存在即用，沿用服务端对 `?project=` 的既有校验与首次访问
  自动登记（进注册表与顶栏项目切换器）；目录不存在按下面「解析失败」处理。
- **项目名**（如 `agent-team-board`）：与已知项目列表各路径的**末段**（basename）做
  **忽略大小写**匹配，**唯一命中**才用；不支持中间路径片段。
- **解析失败**（路径不存在 / 项目名无命中 / 多个同名项目 / 提示词同时提及多个项目）：
  **不要打开猜测的项目**，在会话中说明原因并列出已知项目（含完整路径）请用户澄清，
  用户答复后按澄清结果继续。

打开流程：

1. **探测服务**：`curl -sf http://127.0.0.1:8888/api/health`（响应含已知项目列表 `projects`
   与 `defaultProject`，留存供项目名解析）。
2. **未运行则拉起**：在项目根目录以**后台任务方式**执行
   `node <插件根>/scripts/server.mjs`（Bash 工具用后台运行模式，输出重定向到 /tmp/agent-team-board.log；
   不要用前台命令阻塞会话），约 1 秒后再次 curl 验证；失败读日志排查。
   端口被占用通常意味着看板已在运行，直接进入下一步。
3. **解析目标项目**：按上面两级优先级与解析规则确定目标项目根；提示词未提及项目时跳过解析，
   直接用当前会话项目根。
4. **打开页面**：加载 browser-use 的 control-browser skill，用浏览器打开
   `http://127.0.0.1:8888/?project=<encodeURIComponent(目标项目根绝对路径)>`——
   桌面端会展开内置浏览器面板，顶栏项目切换器应选中目标项目。不支持浏览器时，把 URL 告诉
   用户手动打开。目标项目尚未 `atb init` 时打开不报错：看板显示既有「当前项目尚未初始化看板」
   空态与「初始化」按钮，属正常引导，不算失败。
5. 告知用户看板上可做的人工操作：接受 / 确认完成 / 驳回完成 / 新建需求与 Bug / 拖拽换列；
   页面每 2 秒自动刷新。**不要**替用户执行任何 accepted / done 操作。

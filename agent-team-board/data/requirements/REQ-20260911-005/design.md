# 设计 — REQ-20260911-005 支持英文国际化资源

> 由 Agent 在 /dev 开发前补充，人可随时批注。

## 背景

Status Board 前端（`scripts/web/`）为原生 JS + 模板字符串渲染，中文文案硬编码在
`index.html`（静态）与 `app.js`（动态渲染，含大量模板字面量）中，约 850+ 条唯一文案
（文本片段 815 + 属性片段 130，其中约 210 条含动态插值）。需求要求全部文案支持英文、
按系统语言自动切换。

## 方案

**集中词典 + 运行时 DOM 翻译层**（新文件 `scripts/web/i18n.js`，`app.js` 零改动）：

1. **词典**（`i18n.js` 内）：
   - `EN`：静态精确映射，键 = 中文原文（trim 后全文匹配），值 = 英文；
   - `EN_DYNAMIC`：动态映射，键 = 含 `◇`（插值占位）的片段原文，运行时编译为
     `^…(.+?)…$` 锚定正则，值 = 英文模板（`$1` 回填）；
   - `ALLOWLIST`：显式豁免清单（逻辑键、保持中文的条目，注明原因）。

2. **语言检测与持久化**：
   - `detect()`：`navigator.languages`（回退 `navigator.language`）含任意 `en-*` → `en`，否则 `zh`；
   - `localStorage('atb.lang')` 存 `'en' | 'zh'`，**手动选择优先于自动检测**；
   - 值非法/缺失时按检测值初始化。

3. **运行时翻译**（`translateTree(root)`）：
   - 文本节点：trim 后全文精确匹配词典 / 动态正则，命中才替换（保留前后空白）；
     **不命中保持原文（优雅降级）**——用户数据（条目标题、描述、文档 markdown）天然不会
     命中界面词典，不会被误翻；
   - 属性：`title` / `placeholder` / `aria-label` / `aria-placeholder` 同口径翻译；
   - 跳过：`SCRIPT` / `STYLE` / `CODE` / `PRE` 与 `data-i18n-skip` 子树。

4. **动态内容跟随**：`MutationObserver`（childList + 上述属性，subtree）监听
   `document.body`；回调去抖后「断开 → 翻译 → 重挂」，自身写入不产生循环，
   2 秒轮询重渲染的内容即时按当前语言显示。

5. **切换入口**：顶栏「快捷键 ?」左侧新增语言按钮 `#btnLang`（中文界面显示 `EN`，
   英文界面显示 `中`）；点击即整树重译（`applyLang`），同步 `<html lang>` 与
   `document.title`。

6. **加载**：`index.html` 在 `app.js` 之前引入 `i18n.js`（脚本位于 body 末尾，DOM 已就绪，
   立即初始化）；静态 HTML 先译，后续 app.js 渲染由 Observer 接住。

**改动面**：`index.html`（+1 script、+1 按钮）；`app.js` **不改**；其余模块
（oncall/req-disc/marketing/release，当前暂态隐藏）机制自动生效，词条随恢复条目补录。

**开源选型（REQ-20260909-015）**：无合适库的原因——目标为「零构建、零依赖、以中文原文
为键的显示层翻译」，通用 i18n 库（i18next 等）要求键名抽取改造全部模板串，引入成本与
侵入性远高于 ~300 行自研运行时层；且本项目 Web 端零运行时依赖是既定约束（npm 依赖仅
electron 构建链）。未引入任何开源库，不创建 licenses.md。

## 实施记录

- **词典来源**：JS 字符串扫描器（测试库 `scripts/tests/lib/js-string-scanner.mjs`，正确处理
  引号/模板/转义/注释/正则字面量/嵌套 `${}` 递归；正则判别用「前一有效字符」启发式，
  失同步兜底为单/双引号串跨行回退）扫描 `app.js` + `index.html` 全量字符串 → 片段化
  （文本位置：剥离完整标签后取中文行；属性位置：`attr="…"` 两类，插值记 `◇`）→ 人工翻译入词典。
- **词条规模（终版）**：EN 精确 667 条、EN_DYNAMIC 动态 218 条、ALLOWLIST 豁免 3 条
  （`## 描述` / `## 现象` 两个 markdown 章节定位逻辑键、语言按钮双语初始 title）。
  覆盖测试卡点：扫描 + 片段化实时运行，全部 884 条片段必须命中三表之一。
- **反向词典**：切换回中文需把已渲染英文译回中文——EN 逆映射（精确）+ 英文模板反编译
  （`$N` 占位 → 锚定正则，替换回中文键）。测试 D1e 强制 EN 值唯一，保证逆映射无歧义
  （据此修正了 9 组同值词条，如 `开发中 → Developing` 与 `进行中 → In progress` 区分）。
- **模板匹配顺序**：动态键按长度降序编译——`编辑 ◇ 标题与描述` 必须先于 `编辑 ◇` 匹配，
  否则短模板吞掉长文案后缀产生半译（实测发现，R3b 回归用例锁住）。
- **组合/变体文案**（实测发现并补齐）：`本轮处理记录`（空插值形态，`◇` 为空串时
  `(.+?)` 不命中）、项目检测摘要带尾句组合形态、`共 N · 出局 M`、`子代理模式（…） · 创建 …`
  前后拼接形态、服务端生成展示于界面的固定句（批次收尾摘要、状态已变化 reason，
  best-effort 不在覆盖测试范围）、app 截断形态（`状态已变化（当前 submitte…`）。
- **初始检测不落存储**：`paintLang()`（只绘制）与 `applyLang()`（写存储 + 标记 manual）分离，
  首开按系统语言自动检测不写 `localStorage`，来源标记保持 `auto`。
- **测试**：五件套 `scripts/tests/i18n-{lang,runtime,dict,coverage,wiring}.test.mjs` 共 27 例
  + 全量回归 199 个测试文件 0 失败。
- **浏览器实测**：自动检测（en）→ 可见界面全英文，仅剩中文为用户数据（条目标题）与语言按钮
  本身；点击往返 中/英 完整还原（含 title/lang 属性）；2 秒轮询刷新内容跟随当前语言；
  需求/任务/设置/新建/项目管理/全局面板逐视图中文残留审计为零（用户数据除外）。

## 风险与边界

- **降级可见**：未收录文案显示中文原文，不阻塞使用；覆盖测试保证可见界面无漏网。
- **隐藏模块**（oncall/marketing/release/文件视图）：机制生效但词条未录全，恢复时按
  同一覆盖测试卡点补录（本需求边界，见 README）。
- **用户数据不翻**：条目标题/描述/文档内容是用户产出，保持原文；词典全文匹配保证
  不会误翻（用户文本恰与某界面短语完全相同的极端情形可忽略）。
- **Electron 壳**：无菜单/窗口文案，无需处理；终端 atb CLI 输出不在范围。

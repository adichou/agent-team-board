# 设计 — REQ-20260906-017 支持对需求或 bug 单批量接受

> 由 Agent 在 /dev 开发前补充，人可随时批注。

## 背景

看板已在详情页和拖拽路径提供单条接受，但待接受卡片没有快捷接受入口，也没有批量选择。条目仅有标题，实施前补齐了布局、交互、反馈和边界说明。

## 方案

在 scripts/web/app.js 的待接受列内增加操作栏及卡片控件。选择集合按当前项目保存在内存中，轮询只剔除失效选择，保留原有按列增量渲染。

单条和批量接受共用确认与提交路径，顺序调用现有 POST /api/item/:id/status?project=…，请求体为 { to: 'accepted' }。不新增后端批量端点，不修改状态机或 Agent 守卫。每条独立处理错误并汇总，不回滚已成功项。

每次操作冻结项目、选择单号及操作上下文；切换项目清空界面并替换上下文，旧响应不更新新项目，未发送的请求停止。轮询也在应用响应前核对项目，防止旧项目响应覆盖新看板。

新增 node:assert + node:vm 前端行为测试，直接加载 app.js 函数并模拟 DOM 事件与网络边界；复用现有 HTTP 状态流转集成回归。测试先跑红，实施后跑绿，再执行 npm test。

## 风险与边界

- 人工点击确认才发起接受，不对真实业务条目执行验收状态写入。
- 批量接受非事务：部分失败会保留成功结果，并显示失败单号及原因。网络中断时服务端可能已完成，重试前轮询收敛到实际状态。
- 接受期间遇到外部状态变化由原接口拒绝，不能把开发中或已完成条目回退。
- 切换项目时已发出的原项目请求可能完成；不会把旧单号发往新项目。
- 会话名修改因宿主应用禁止自动化访问而未完成；不影响看板认领者 codex-batch-accept。

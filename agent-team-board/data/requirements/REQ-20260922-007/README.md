# REQ-20260922-007 AI 开发过程中忽略文档的编写差异，不要提交文档到 git。文档有另外的流程提交

- 状态：submitted（待人工接受）
- 创建：2026-09-22T14:55:20.591Z

## 描述

### 背景与现状（代码事实）

Agent 开发单（`atb claim` → 编码 → `atb report`）的系统收口提交目前会把**条目文档一并提交到 git**：

- `scripts/lib/git-flow.mjs` 的 `autoCommitForRun`：以「认领时工作区快照 → 收口时差集」做归因，把本单改动按 **doc / test / 业务** 三组分别提交（只 commit 不 push）；
- 其中 **doc 组 = 看板板根（`agent-team-board/`，实际脏路径来自 `data/`）内当前全部脏路径**（排除其他条目目录，本单条目目录整体纳入；重命名 R 码与看板共享文件也归 doc 组），以 `doc: <标题> <单号>` 主题提交——即 AI 开发期间编写的 `design.md`、`test-cases.md`、条目 README 更新等条目文档会随收口自动入库；
- 手动 `/dev` 通道（BUG-20260915-007，`scripts/lib/manual-closeout.mjs`）复用同一内核，批量 run 与手动收口同口径；
- 文档本已有**独立的提交通道**：REQ-20260917-002 文档讨论轮放行口径（`scripts/state-guard.mjs`）——仅含条目目录用户数据（`agent-team-board/data/{requirements,bugs}/<条目ID>/` 内）+ 命令带 pathspec + 提交主题含条目编号（`doc: … REQ-/BUG-…`）的提交经 Agent Bash 放行；另有看板端人工提交。

问题：开发收口提交把文档差异一并入库，与「文档走另外的流程提交」的分工冲突——文档提交时机、审查节奏应由文档讨论轮/人工通道控制，收口提交不应替文档做主。

### 需求要点

1. **AI 开发过程中忽略文档的编写差异**：开发收口提交（批量 run 收口与手动 `/dev` 收口）在差集归因时**忽略本单条目目录（`agent-team-board/data/{requirements,bugs}/<本单ID>/`）下文档的改动**，不再将其纳入 doc 组提交到 git；
2. **不要提交文档到 git**：收口提交只含源码与测试改动（test / 业务组行为不变）；文档改动**保留在工作区**（不提交、也不还原/丢弃），不产生空提交；
3. **文档有另外的流程提交**：文档入库仍走既有通道——REQ-20260917-002 文档讨论轮（pathspec + 单号主题）与人工提交，本需求不改这两条通道的口径；
4. 相关流程表述（AGENTS.md / skills/agent-team-board/SKILL.md 中「收口提交含文档 / 留痕文档随收口提交入库」类描述）按新口径同步更新。

### 边界与待确认

- **板级共享路径**：doc 组现还收纳看板共享文件、迁移搬移（R 码）、留痕文档出库删除等**非本单条目目录**的板级路径。这些不属于「文档的编写差异」，初步口径为**维持现状仍随收口收纳**（否则迁移成对入库会断），**待人工确认**；
- **仅文档改动的收口轮**：本单若只有文档改动、无源码/测试改动，收口将无可提交分组——回执/账本如何呈现（skipped 原因文案、看板「已提交」徽标与 `atb commit log` 核验口径）**待设计阶段细化**，基线是不得误报 committed、不得报错中断；
- 根 `README.md` 提交例外（REQ-20260918-002）与发布文档「文档编写」页提交通道不在本需求范围内，行为不变。

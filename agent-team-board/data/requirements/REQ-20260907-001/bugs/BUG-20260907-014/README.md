# BUG-20260907-014 新建条目中的讨论单类型改为讨论

- 状态：in-progress
- 归属需求：REQ-20260907-001
- 创建：2026-09-07T13:50:48.021Z

## 现象

统一「＋ 新建」弹窗（REQ-20260907-004 交付）的类型下拉第三项文案为「讨论单（ASK）」（`scripts/web/index.html` `<option value="ask">`）。而 REQ-20260907-004 的口径是新建「类型选择需求、Bug、讨论」——模块/类型名为「讨论」，「讨论单」指列表中的条目本身。类型下拉混用「讨论单」与栏目名「讨论」不一致。

## 复现步骤

1. 打开看板，点击顶栏「＋ 新建」；
2. 展开「类型」下拉，观察第三项文案。

实际：「讨论单（ASK）」。期望：「讨论（ASK）」（与需求 / Bug 选项「需求（REQ）」「Bug（BUG）」同构，均为类型名）。

## 期望行为

- 新建弹窗类型选项 `<option value="ask">讨论（ASK）</option>`；
- 不改其余面向用户的「讨论单」文案（列表/详情/校验提示等指代条目本身的地方保持「讨论单」）；内部 API 路径与 ASK 编号不迁移。

## 关联（引入来源）

- 引入来源：REQ-20260907-004（统一新建入口实施时把类型选项文案写为「讨论单（ASK）」，与其需求自身描述「类型选择需求、Bug、讨论」的类型名口径不一致；经 `atb show REQ-20260907-004` 核验存在，该弹窗由其交付）。

## 修复记录（BUG-20260907-014，zcode-batch-009-01）

- `scripts/web/index.html`：类型下拉 `ask` 项文案「讨论单（ASK）」→「讨论（ASK）」。
- 测试：`scripts/tests/workbench-layout.test.mjs` W6 增加文案契约断言（先跑红后修复跑绿），全量 `npm test` 无回归。

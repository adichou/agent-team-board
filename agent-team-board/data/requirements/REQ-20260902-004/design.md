# 设计 — REQ-20260902-004 Status Board 一键派发需求给当前项目的全新会话，并注入预设提示词（支持 zcode / codex）

> 由 Agent 在 /dev 阶段一补充，人可随时批注。**状态：待对齐（方案初稿，未经人工确认不得实施）。**
> README 描述为空，本方案按标题语义起草，机制边界与开放点见文末。

## 背景

想在看板上看到合适的 accepted 条目时，一键把「开发这条」派发给一个全新会话（zcode 或 codex），自动带上预设提示词，免去手动开窗口、贴上下文。

## 机制边界（关键前提）

网页（本地 server）**无法直接创建** ZCode/Codex 的应用内会话——两者都没有公开的「新建会话」URL scheme 或 CLI（`codex` CLI 本机未装；`zcode://` scheme 未证实存在）。可落地的最接近形态：

1. **预设提示词一键复制**（确定性可用）：按钮生成完整派发提示词并写入剪贴板，用户在新会话粘贴回车即完成派发；
2. **URL scheme 尝试打开**（尽力而为）：按钮同时尝试 `open zcode://…` / Codex 对应 scheme，若客户端支持则直接拉起，不支持则静默失败（已复制提示兜底）。

## 方案（初稿，待对齐）

### 前端（app.js + index.html）

- 详情抽屉对 `accepted` 状态条目增加「派发」区：Agent 选择（`zcode` / `codex` 两个按钮或下拉）+「复制派发提示词」按钮；
- 提示词模板（按 Agent 差异化）：
  ```
  /dev <ID>
  ```
  就这么短——命令本身就是完备入口；增强版附加一行上下文：
  `/dev <ID>   # <标题>（看板：<项目名>；方案与验收见该条目 README/design）`
  codex 版把 `/dev` 换成其等价入口说明（Codex 无 slash 命令，则用「按 agent-team-board skill 的 TDD 流程认领并实施 <ID>」）。
- 复制用现有 navigator.clipboard 路径；成功反馈沿用「已复制 ✓」样式。

### 服务端

零改动（提示词纯前端拼装；条目数据已有）。

### 测试

静态契约（派发模板函数存在、含单号、zcode/codex 两模板、复制调用）；浏览器实测点按复制（IAB 输入管线允许时）。

## 影响面

`scripts/web/app.js`（抽屉 accepted 分支加派发区）、`style.css`（小量样式）；server/core 零改动。

## 风险与边界

- 「全自动开新会话」当前不可达（无公开机制），v1 交付「复制提示词 + scheme 尽力打开」；若你知道 zcode/codex 的会话 deeplink 或 CLI，请在对齐时提供，方案可升级为真·一键。
- 派发的会话仍受两阶段流程约束（认领→出方案→待对齐），不会绕过闸门。

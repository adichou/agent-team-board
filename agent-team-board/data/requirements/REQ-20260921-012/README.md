# REQ-20260921-012 发布模块的文档编写流程需优化成先写默认语言的文档，待默认语言的文档审核完毕后，再提供 AI 翻译的功能编写剩余语言的文档，然后再审查，最后是整体的审查完结流程

- 状态：submitted（待人工接受）
- 创建：2026-09-21T02:37:29.414Z

## 描述

### 背景与现状

发布模块五步流程（版本计划 → 关联条目与提交 → **文档编写** → 合并入 main → 正式发布）第三步「文档编写」，经 REQ-20260921-008 重构为「AI 总结 → 审查 → 提交」流水线，现状（代码事实）：

- 八个发布文档一次性混合处理：`scripts/lib/publish-flow.mjs` 的 `publishDocFiles()` 固定 README / CHANGELOG / FEATURES / AGENTS × 中英共八个文件（中文 `<KEY>.md`、英文 `<KEY>.en.md`）；
- 「AI 总结」一轮 run 覆盖全部八个文件（`scripts/lib/docs-summary-store.mjs` 账本 `files` 恒八项，进度 x/8），不区分语言先后；提示词 `buildDocSummaryPrompt()` 同样要求逐个总结八个文件；
- 逐文件四态：未总结 → 正在总结 → 已总结待审核 → 已审核（`DOCS_FLOW_STATES` / `evaluateDocsFlow`，前端 `scripts/web/build.js` 的 `renderDocsPane` / `renderReviewModal` 同口径渲染）；
- 提交门禁：8/8 已审核即可「提交」到本地 dev 分支（`canCommit`），无语言阶段与整体收口环节。
- REQ-20260921-010（进行中）已把上述固定中英清单泛化为**发布计划级语言集**：`version.json` 顶层 `langs`（默认 `cn,en`），首语言 = 默认语言（文件不带后缀），其余语言 `<KEY>_<lang>.md`（如 `README_en.md`），文档清单 = 4 类 × 语言数；本需求的分阶段流程在语言集清单之上落位。

问题：语言集内全部语言的文档在同一轮总结里并行推进，非默认语言文档可能在默认语言文档尚未定稿时就被总结，默认语言内容后续修改后其余语言容易过期失配；流程上也没有「默认语言先定稿 → 翻译 → 再审 → 整体收口」的阶段约束与最终完结动作。

### 需求要点（原文）

发布模块的文档编写流程需优化成：

1. **先写默认语言的文档**——AI 总结只覆盖默认语言（语言集首语言）的四个文件；
2. **待默认语言的文档审核完毕后**（默认语言四文件全部已审核），**再提供 AI 翻译的功能编写剩余语言的文档**（语言集其余语言的全部文件，翻译基准为已审核的默认语言文档）；
3. **然后再审查**——AI 翻译产出的各剩余语言文档逐文件人工审查；
4. **最后是整体的审查完结流程**——语言集内全部文档（4 类 × 语言数）整体核对收口，文档编写步骤完结后才进入提交。

### 术语与阶段状态机

- **默认语言 = 语言集首语言，剩余语言 = 语言集其余语言**（依据 REQ-20260921-010 落定的语言集方案：发布计划级语言集存 `version.json` 顶层 `langs`，默认 `cn,en`，可改为任意 2–3 字母缩写组成的语言集合，语言集是文档清单的唯一事实源）。文件命名沿用 010 口径：首语言 `<KEY>.md`（如 `README.md`），其余语言 `<KEY>_<lang>.md`（如 `README_en.md`、`README_fr.md`）；文档清单 = 4 类 × 语言集语言数（N 语言即 4×N 个文件）。**默认语言不一定是中文**——语言集 `en,cn` 时默认语言为英文（不带后缀），`cn,en,fr,jp` 时默认语言为中文、剩余语言为 en / fr / jp 三组。本 README 其余部分以默认语言集 `cn,en`（八个文件）为例展开，示例中的语言组、文件名与计数均随语言集等价泛化。
- 单文件四态沿用 REQ-20260921-008 口径：未总结 → 正在总结 → 已总结待审核 → 已审核；剩余语言文件在阶段二对应为 未翻译 → 正在翻译 → 已翻译待审核 → 已审核（枚举命名设计阶段定，语义与默认语言四态一一对应）。
- 阶段推进（本需求新增的分层门禁）：

```
阶段一 默认语言先行            阶段二 AI 翻译（解锁条件：默认语言 4/4 已审核）  阶段三 整体审查完结（条件：4×N 全部已审核）
默认语言四文件：                剩余语言各四文件：                               语言集全部文件整体核对：
未总结 → 正在总结               未翻译 → 正在翻译                                各语言与默认语言语义一致 / README 按语言互链 /
  → 已总结待审核                  → 已翻译待审核                                 内容与发布范围一致 → 确认完结
  → 已审核（人工通过）             → 已审核（人工通过）                           （完结后「提交」方可使用）
```

- 「整体的审查完结」：在逐文件已审核之上的最终收口动作，完结前「提交」不可用；**不得弱化**现有提交与合并门禁。
- `scopeStale`（发布范围变化）口径沿用：范围变化使逐文件审核与整体完结状态失效回退，重新走审查与完结。

### 涉及文件（现状）

- `scripts/lib/publish-flow.mjs`：`publishDocFiles()` 八文件清单、`buildDocSummaryPrompt()` 提示词、`DOCS_FLOW_STATES` / `evaluateDocsFlow()` 四态求值与 `canCommit` 提交门禁、`publishStepsState()` 五步门禁；
- `scripts/lib/docs-summary-store.mjs`：AI 总结执行账本（run 恒八文件、`summary.lock` 独立锁、`atb summary` 回执、任务模块 / 全局面板视图）；

- `scripts/server.mjs`：`/api/build/publish-plan`、`/api/build/docs-summary/start`、`/api/build/docs-summary/current`、`/api/build/docs/save`、`/api/build/docs/commit` 等接口；
- `scripts/web/i18n.js`：新增文案须中英同步（文件名等标识沿用 `data-i18n-skip` 豁免口径）。

## 验收标准

### 阶段一：默认语言文档先行（需求 1）

- [ ] 「AI 总结」启动后仅覆盖默认语言（语言集首语言）四个文件：账本 files 清单、进度计数（x/4）、任务模块与全局任务面板进度口径同步改为默认语言四文件；提示词（`buildDocSummaryPrompt` 后继形态）不再包含剩余语言文件。
- [ ] 剩余语言全部文件在阶段一不被 AI 总结触碰；其初始状态展示为「未翻译」（或等义空态，文案待设计定稿），不与默认语言的「未总结」混排歧义。
- [ ] 默认语言四文件状态流转沿用四态：AI 总结执行中「正在总结」→ 完成「已总结待审核」→ 人工「通过审核」→「已审核」；再次编辑保存回退「已总结待审核」。
- [ ] 不使用 AI 总结、直接审查修改默认语言文档的路径保持可用（现状能力不回收）。

### 阶段二：AI 翻译（需求 2 前半）

- [ ] 「AI 翻译」入口在默认语言四文件**全部已审核**前禁用，hover / 提示给出缺口明细（哪些默认语言文件未审核、各处什么状态）；满足后解锁。
- [ ] AI 翻译沿用「复制提示词到剪贴板交 AI Agent 执行」交互模式（与 AI 总结一致）；提示词要求以**已审核的默认语言文档内容为唯一翻译基准**，逐文件产出剩余语言全部文件（4×(N−1) 个，N 为语言集语言数），不得引入基准外信息、不得编造。
- [ ] AI 翻译逐文件回执进度（正在翻译 → 已翻译待审核），文档编写页按钮显示进度（如「翻译中 x/8」，随语言集剩余语言文件数动态），任务模块与全局任务面板可见任务信息与当前文件（口径对齐 AI 总结）。
- [ ] AI 翻译失败 / 中断有明确状态与原因，文件状态不悬挂「正在翻译」，可重启续跑（已翻译完成的文件跨 run 保留）。
- [ ] AI 翻译启动前执行基准变更检测：默认语言文档 mtime 晚于对应剩余语言文档时提示「基准已更新」，并按最新基准翻译。
- [ ] AI 翻译使用独立锁，与 AI 总结、AI 分析、AI 开发互不占用；锁命名与账本形态：**待确认**（设计阶段定）。

### 阶段二审查（需求 2 后半「然后再审查」）

- [ ] 剩余语言文件翻译完成后进入「已翻译待审核」，由人工在审查对话框逐文件审查：沿用类型四页签、默认语言栏与各剩余语言栏同步滚动对比（栏数 = 语言数）、编辑 / 预览切换、保存、「通过审核」；编辑已审核文件保存后回退待审核。
- [ ] 审查对话框对翻译场景可用：默认语言栏（已审核基准）与各剩余语言栏并排对比，同步滚动便于逐段核对翻译。
- [ ] **基准变更检测（mtime 对比）**：默认语言文档在翻译开始后被再次修改——**含外部编辑器 / IDE 直接落盘、不经审查界面保存**的场景——在进入 / 重新进入文档编写步、点击「刷新」或计算门禁时，通过磁盘 mtime 对比检测到变更（同类型文件：默认语言文档 mtime 晚于剩余语言文档）；受影响的剩余语言文档（含已翻译待审核 / 已审核）置回「未翻译」（未审核），界面提醒重新执行 AI 翻译；整体审查已完结的随之失效回退。
- [ ] mtime 对比检测**不依赖审查界面的保存按钮**（保存只是修改途径之一，外部编辑器修改同样触发）；经界面保存默认语言文档同样更新磁盘 mtime，纳入同一对比口径。

### 阶段三：整体审查完结（需求 3）

- [ ] 语言集内全部文件（4×N）已审核后，「整体审查完结」入口可用；此前禁用并说明缺口。
- [ ] 整体审查完结至少核对：各语言内容一致（各剩余语言与默认语言已审核基准语义一致）、README 按语言互链真实可达（README.md → CHANGELOG.md / FEATURES.md；README_en.md → CHANGELOG_en.md / FEATURES_en.md，其余语言同 `_<lang>` 规则）、文档内容与本版发布范围一致（未纳入本版的功能不得写成已发布）。
- [ ] 完结是明确的人工动作（按钮 / 对话框确认），完结后文档编写步骤呈现完结标识（如「文档编写已完结」终态与时间）。
- [ ] 「提交」按钮在整体审查完结**之前**禁用（在现有「全部文件已审核」门禁之上叠加完结条件，不弱化现有门禁）；完结后提交行为沿用现状（pathspec 限定语言集内文档、提交到本地 dev、成功显示提交 hash）。
- [ ] `scopeStale`（发布范围变化）触发时：逐文件审核与整体完结状态一并失效回退，提示重新审查与完结；合并入 main 前置口径不变。

### 阶段推进与状态展示

- [ ] 文档编写页呈现三阶段推进视图（默认语言先行 → AI 翻译与审查 → 整体审查完结），当前所处阶段、各阶段解锁条件与缺口一目了然。
- [ ] 刷新按钮沿用：重新读取磁盘语言集内全部文档内容与状态；外部 IDE 修改后可取回最新内容，读取失败有错误反馈与重试。
- [ ] merging / 已正式发布状态下文档编写步骤锁定口径保持（范围锁定不可改）。

### 兼容与回归

- [ ] 五步流程其余四步（版本计划 / 关联条目与提交 / 合并入 main / 正式发布）行为不变；「合并入 main」仍以文档已提交为前置。

```
┌─ 整体审查完结（BLD-20260921-001）──────────────────────────── ✕ ─┐
│ ☑ 默认语言四文件已全部审核（4/4）                                  │
│ ☑ 剩余语言文件已全部审核（4/4，随语言集动态）                      │
│ ☑ 各语言内容语义一致（以已审核默认语言为基准）                     │
│ ☑ README 按语言互链真实可达（README.md → CHANGELOG.md /            │
│   FEATURES.md；README_en.md → CHANGELOG_en.md / FEATURES_en.md）   │
│ ☑ 文档内容与本版发布范围一致                                      │
│ 提示：完结后「提交」方可使用；发布范围变化会使完结失效回退。        │
│                        [取消]  [确认完结]                          │
└──────────────────────────────────────────────────────────────────┘
```

## 交互行为

- **AI 总结**：点击复制提示词（剪贴板 + toast + 提示词预览），AI Agent 逐文件总结**默认语言四文件**（正在总结 → 已总结待审核，经 `atb summary` 逐文件回执，页面 15 秒轮询自动刷新）；按钮运行中显示「总结中 x/4」；也可不经 AI 总结直接审查（现状能力）。
- **AI 翻译**：默认语言 4/4 已审核前禁用（title 列出缺口）；解锁后点击复制翻译提示词，AI Agent 以已审核默认语言文档为基准逐文件产出剩余语言全部文件（正在翻译 → 已翻译待审核，逐文件回执、页面自动刷新），按钮运行中显示「翻译中 x/◇」（随语言集剩余语言文件数动态）；失败 / 中断不悬挂「正在翻译」，可续跑；启动前先做**基准变更检测**（见下条），检出基准更新时提示并按最新基准翻译。
- **审查**：打开对话框，类型四页签、默认语言栏与各剩余语言栏并排同步滚动（栏数 = 语言数）；翻译阶段默认语言栏即已审核基准、各翻译栏逐段核对；每栏独立编辑 / 预览 / 保存 / 通过审核；编辑已审核文件保存后回退待审核并有提示；页脚实时显示全部与本页签已审核计数。
- **整体审查**：全部文件（4×N）已审核前禁用并说明缺口；点击打开完结核对（清单见界面布局示意），确认完结后文档编写步骤呈现完结标识，「提交」解锁；发布范围变化使完结失效回退并提示。
- **提交**：整体审查完结前禁用（在全部文件已审核之上叠加完结条件）；完结后点击提交语言集内全部文档到本地 dev（pathspec 限定、不夹带业务源码），提交中反馈、成功显示提交 hash、失败可重试。
- **基准变更检测（mtime 对比，本轮落定）**：默认语言文档在翻译开始后再次被修改（**含外部编辑器 / IDE 直接落盘，不经审查界面保存**）时，通过磁盘文件**最近修改时间（mtime）对比**捕获：同类型文件两两对比（`README.md` ↔ `README_<lang>.md`、`CHANGELOG.md` ↔ `CHANGELOG_<lang>.md`，依次类推），默认语言文档 mtime **晚于**某剩余语言文档的 mtime → 该剩余语言文档置回**「未翻译」（未审核）**，提醒用户重新执行 AI 翻译；已完结的整体审查随之失效回退。检测发生在**每次求值读盘时**（进入 / 重新进入文档编写步、点击「刷新」、AI 翻译启动前、提交与整体完结门禁计算时），**不依赖审查界面的保存按钮**——保存按钮只是修改途径之一，外部编辑器修改同样能被检测到。
- **刷新**：重新读取磁盘语言集内全部文档内容与状态（外部 IDE 修改后取回最新），读取期间加载反馈，失败显示错误与重试；读取时同步执行基准变更检测（mtime 对比）。
- **状态联动**：任一文件状态、阶段条件变化即时反映到阶段条、文件列表、门禁条与各按钮可用性。

## 状态反馈

- **正常态**：阶段条标明当前阶段与解锁条件；文件列表按默认语言 / 各剩余语言成组显示四态（剩余语言侧为 未翻译 / 正在翻译 / 已翻译待审核 / 已审核）；门禁条显示「默认语言 x/4 · 剩余语言 y/◇ 已审核」（随语言集动态）与完结 / 提交缺口。
- **加载态**：刷新（正在读取最新内容…）、AI 总结（单文件正在总结 + 总进度 x/4）、AI 翻译（单文件正在翻译 + 总进度 x/4）、提交（提交中…）。
- **空态**：全新版本默认语言四文件「未总结」、剩余语言各文件「未翻译」，列表恒 4×N 行不出现空列表；任务模块无进行中任务时显示空态提示。
- **失败态**：刷新失败（错误横幅 + 重试）、AI 总结 / AI 翻译中断（失败原因 + 可续跑，文件状态不悬挂「正在…」）、提交失败（原因 + 可重试，内容保留）。
- **门禁反馈**：AI 翻译、整体审查、提交禁用时 hover / 点击给出缺口明细（哪些文件未审核、整体是否完结）。
- **完结终态**：整体审查完结后显示完结标识；提交后显示提交 hash 与「已提交到本地 dev 分支」，衔接「合并入 main」前置。
- **基准变更**：检测到默认语言文档更新（mtime 晚于对应剩余语言文档）时，受影响的剩余语言文档标记回「未翻译」，门禁条 / 提示给出「默认语言文档已更新：X 个翻译文档需重新 AI 翻译」；若整体审查已完结则完结标识失效回退并提示。
- **范围变化**：`scopeStale` 时逐文件审核与整体完结失效回退，门禁条提示需重新审查与完结。

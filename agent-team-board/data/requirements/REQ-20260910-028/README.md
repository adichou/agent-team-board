# REQ-20260910-028 新建讨论时支持上传截图，和新建需求、bug 一样

- 创建：2026-09-10T14:58:50.644Z
- 状态以系统维护的 status.json 为准。

## 描述

新建开放式讨论（ASK）时，与新建需求 / Bug 相同，支持在表单内上传或粘贴截图：截图随标题与背景（可选）一次性提交保存到该讨论名下，创建后在讨论详情中可查看、可放大，供后续讨论与 Agent 会话参考。推翻 REQ-20260909-004「讨论不回加截图」的旧口径（该口径系看板代答模式移除时一并去掉截图，如今讨论已改为外部 Agent 会话自由讨论，截图重新有了用途）。

### 已核实的现状与范围

- `scripts/web/index.html` 的新建表单已有完整截图区块（上传入口、n / 9 计数、缩略图、错误提示行、REQ-20260910-017 大图预览遮罩）；`scripts/web/app.js` 的 `syncNewFormFields()` 在类型切到「讨论（ASK）」时将该区块整体隐藏（注释明确「讨论不回加，沿用 REQ-20260909-004 口径」），本需求仅去掉这一隐藏，区块内部交互不动。
- `submitNew()` 中讨论走 `POST /api/discussion`（请求体仅 `title`、`background`），不带附件，也不做 BUG-20260909-010 的旧服务预检；服务端 `oncall.createDiscussion()` 只写 `question.md`（背景）与 `ticket.json`，不接收附件。
- 讨论单目录（`oncall/tickets/ASK-…/`）的附件基础设施已存在：`saveAttachment / readAttachment` 落盘与读取 `<讨论目录>/attachments/`，GET `/api/oncall/ticket/:id/attachment/:name` 已可访问（旧版看板代答轮次使用，oncall.js 历史问答已渲染附件并支持点击放大）。复用该口径不另建存储；最终技术方案由 design.md 定。
- 校验口径与需求 / Bug 完全一致：格式白名单 png / jpg / jpeg / gif / webp / svg / ico / bmp / avif、单张 ≤ 8MB、最多 9 张、前端即时校验 + 服务端 `/api` 二次校验兜底、任一附件非法整单拒绝不留半成品。
- 待确认（设计阶段定夺）：`question.md` 是否像需求 / Bug README 一样在背景末尾追加 `![截图](attachments/…)` 引用行；启动提示词是否向 Agent 提示截图位置；讨论详情中截图的具体摆放（建议随「讨论背景」区展示，点击放大沿既有 lightbox 先例）。无论形式如何，用户必须能在看板内看到已上传的截图。

### 界面布局

- 新建面板类型切到「讨论（ASK）」时，在「背景（可选）」下方显示与需求 / Bug 相同的截图区块：区块头（「截图（可选）」、n / 9 计数、「上传图片」按钮、「或直接 ⌘V 粘贴」「双击查看大图」提示）、缩略图列表（图片、文件名与大小、「查看大图」与「✕」移除按钮）、无截图提示与错误提示行。
- 大图预览沿用 REQ-20260910-017 既有全屏遮罩（顶部文件名 + 关闭按钮、居中按原比例完整展示），本需求不改变其布局。
- 创建成功后进入讨论模块定位新讨论（现状行为保持），讨论详情的「讨论背景」信息附近展示本次保存的截图（缩略图 + 文件名，点击放大）。

### 交互行为

- 添加截图：文件选择（accept 图片、多选）与弹窗打开期间粘贴剪贴板图片（自动命名 `paste-<时间戳>.<后缀>`），与需求 / Bug 路径完全一致、共用同一实现。
- 缩略图可移除单张（✕）、可双击或点「查看大图」放大；Esc / 关闭按钮 / 遮罩空白处只关预览一层，不关背景表单。
- 类型切换不丢失已添加的截图（仅重新打开面板时清空，对齐现状口径）；「创建并接受」按钮在讨论类型下仍不出现（讨论无接受概念）。
- 提交：点「创建」将标题、背景与截图一次提交；创建提交中禁用截图添加 / 移除入口与提交按钮（防重复、防竞态）。
- 讨论的既有流程不回归：创建成功后定位新讨论并展示启动提示词、复制到 Agent 新会话使用。

### 状态反馈

- 校验失败（非白名单格式 / 超 8MB / 超过 9 张）即时在错误行提示，不合法的项不进入缩略图列表，单张失败不影响其余；达到 9 张上限时「上传图片」入口禁用（粘贴路径仍有提示兜底）。
- 空态：无截图时显示「粘贴或选择图片…」提示与计数 0 / 9，不渲染缩略图列表与预览入口。
- 创建中：提交按钮变「创建中…」，截图入口全部禁用。
- 创建失败：toast 提示原因，表单、背景与已添加截图全部保留可重试，不产生重复讨论；带截图提交遇看板服务版本过旧（不识别附件字段）时拒绝提交并给出 `atb serve` 自愈指引，不静默丢截图（对齐 BUG-20260909-010 口径）。
- 成功：toast 确认已创建；详情中截图可加载查看，加载失败时给出明确失败提示（不展示破损图标，对齐条目文档图片先例）。

- [ ] 文件选择与剪贴板粘贴均可添加截图（粘贴自动命名），缩略图显示文件名与大小，可移除单张、可双击或经按钮放大查看；Esc / 关闭只关预览一层。

- [ ] 无截图 / 无背景的既有讨论创建路径行为与现状一致；旧讨论（无截图）的列表与详情展示不受影响；启动 / 继续提示词流程不因截图引入而破坏。

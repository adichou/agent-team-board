# REQ-20260922-006 发布版本的版本号改成 x.y.z 格式，发布时间以推送到远端仓库 main 分支的时间为准。

- 状态：submitted（待人工接受）
- 创建：2026-09-22T12:31:10.729Z

## 描述

1、发布时间作为版本计划的属性，在成功推送后更新为推送时的时间。

2、版本计划的版本号从计划编号派生格式（`BLD-20260921-001` → `20260921-001`）改为独立的 **x.y.z** 语义化格式（如 `0.1.0`），创建时分配、全流程（列表 / 详情 / 发布提示词 / 产品发布）统一使用。

### 现状（探索核实，2026-09-22）

- version.json 无独立 `version` 字段；「版本号」显示由前端与提示词从 `id` 派生（`publish-flow.mjs` `versionNumberOf`、`web/build.js` 两处 `v.id.replace(/^BLD-/, '')`）。
- 推送成功已记录 `release.pushedAt`（`build-store.mjs` `recordPushSuccess`，服务端 `/api/build/release/push` 在 `pushMainBranch` 成功后调用），但埋在 release 推送事实对象里，仅第五步「正式发布」面板显示，列表与详情头部不显示。

## 验收标准

- [ ] **版本号 x.y.z**：创建版本计划时分配独立版本号字段——表单预填自动分配值（既有计划中最大 x.y.z 的 patch +1，无历史则 `0.1.0`），可修改；校验 `^\d+\.\d+\.\d+$` 且不与既有计划版本号重复（重复返回明确错误）。
- [ ] **旧数据回退**：存量计划（version.json 无 `version` 字段）显示与提示词沿用原 `YYYYMMDD-NNN` 派生口径，不迁移数据、不报错。
- [ ] **显示统一**：发布模块列表卡片与详情头部的「版本号」改用 x.y.z 字段（旧数据回退除外）；发布文档 AI 总结 / 翻译 / 官网提示词中的版本号同源。
- [ ] **发布时间属性**：`recordPushSuccess` 在推送成功时同步写入版本计划顶层 `releasedAt`（= 推送成功时刻）；既有 `release.pushedAt` 语义不变（同基准不重置、基准变化更新，兼容 req-20260920-003 L2-3 断言）。
- [ ] **发布时间显示**：已发布（有 `releasedAt`）的版本在列表卡片与详情头部显示「发布于 <时间>」；未发布不显示。第五步既有推送完成时间展示保留。
- [ ] **产品发布联动**：第五步「创建产品发布」弹窗的发行版本号输入默认预填本计划 x.y.z 版本号（无则维持现状空值），手填仍可覆盖。
- [ ] **中英文同步**：新增/变更文案（版本号、发布于等）在 `scripts/web/i18n.js` 中英文同步。
- [ ] **测试**：新增 `scripts/tests/req-20260922-006.test.mjs` 覆盖上述数据层 / 服务层 / 前端契约用例，`npm test` 全量通过。

# REQ-20260909-004 开放式讨论模块重构与纪要生成需求或 Bug

## 背景与目标
将讨论模块定位为开放式讨论记录与成果管理。实际讨论在 Agent 会话中进行，看板负责启动/收尾提示词、读取纪要、编辑和创建候选需求或 Bug。讨论不需要绑定任何既有需求或说明文档。

### 现状（重构对象）
- 讨论模块即 REQ-20260907-001 的 Oncall 咨询看板：数据层 `scripts/lib/oncall-store.mjs`（事实源 `<dataDir>/oncall/tickets/ASK-YYYYMMDD-NNN/`，含 `ticket.json`、`question.md`、`attachments/`、`rounds/<N>/{question,answer}.md`），页面 `scripts/web/oncall.js`（`scripts/web/index.html` 的 `#oncallView` + `#oncallDrawer` 抽屉），接口为 `scripts/server.mjs` 的 `/api/oncall/*`。
- 现有状态为 pending / answering / answered / failed 四态筛选（`oncall.js` 的 `STATUS_LABEL`），讨论由看板直接派发 Agent 回答（`/api/oncall/dispatch` 与 runs 执行账本）；REQ-20260908-022 增加了讨论可选绑定需求（`ticket.req`）。
- 本需求将「看板代答」改为「Agent 外部会话讨论 + 看板沉淀成果」：旧执行状态如何映射到「讨论中 / 已归档」两态、旧 rounds 回答如何保留，须在 design.md 明确（见范围边界）。

## 界面布局（已确认）
复用需求模块的列表与详情形式：项目顶栏和模块导航下为「讨论中」「已归档」两档筛选；宽屏左侧讨论记录、右侧详情；窄屏先列表，点击记录进入详情，提供返回列表并保留筛选、滚动位置。
- 顶栏提供「新建讨论」。表单填写标题和背景，不强制关联需求。
- 列表展示讨论标题、讨论编号、两态状态、最近更新时间与成果提示。
- 详情顶部显示编号、标题、状态及启动提示词、讨论完毕、归档/继续讨论操作。
- 详情正文为「背景与纪要」「生成需求 / Bug」两个区域或标签。
- 背景与纪要包含讨论背景、共识、建议与取舍、未决问题、后续行动。
- 候选条目展示类型、标题、描述（Bug 包含复现、实际与预期）、验收标准；可以编辑和勾选，统一创建。
- 已创建成果展示真实条目编号、标题、状态与跳转入口。
- 使用现有项目的深浅色、按钮、胶囊筛选/标签、列表选中态与详情风格，不引入说明差异对比视图或聊天输入面板。

## 交互行为
- 新建讨论：顶栏「新建讨论」打开表单，标题必填（与现有 120 字上限一致，`core.mjs` createItem 口径）、背景可选，不强制关联需求；保存后分配唯一讨论编号并直接展示启动提示词。标题为空时阻止保存并就地提示。
- 启动提示词：详情顶部按钮，展示为只读文本与「复制提示词」；复制成功给出反馈；剪贴板不可用时自动全选文本并提示手动复制（⌘C / Ctrl+C）。复制只表示提示词已生成/复制，不代表 Agent 已连接。
- 讨论完毕：生成收尾提示词（粘贴回原 Agent 会话），同时详情进入「等待纪要」反馈态并提供重新读取入口；讨论状态保持「讨论中」。再次点击可重新查看提示词。
- 纪要读取：约定目录落盘后看板自动读取并渲染「背景与纪要」与候选草稿；读取过程显示加载反馈；输出编号/结构不完整或格式错误时展示可理解的错误说明与重试入口，不渲染半成品。
- 候选草稿：每条展示类型（需求 / Bug，只读）与标题、描述（Bug 含复现、实际、预期）、验收标准（可编辑字段）；默认勾选，可取消勾选；创建前对勾选项做必填校验并逐项提示，未勾选任何条目时提示先勾选。
- 批量创建：确认后逐条走既有条目创建机制（`scripts/lib/core.mjs` createItem，初始状态 submitted 待接受）；创建中按钮禁用并显示处理反馈；完成后逐条显示结果——成功项展示真实编号、标题、待接受状态与跳转入口，失败项展示原因并可单独重试；已成功项不可重复创建（防刷新/重试重复）。
- 归档 / 继续讨论：随时可归档，无须先生成条目；归档保留成果展示；「继续讨论」恢复讨论中，且不清空既有纪要与已生成条目。
- 列表与筛选：仅「讨论中」「已归档」两档胶囊筛选，计数实时；列表按最近更新时间排序（分组展示规则待确认）；点击记录切换详情，切换记录不丢失已填写的草稿编辑需二次确认或保存草稿（具体策略待确认，建议保存为本地草稿）。
- 窄屏：点击列表记录进入详情，「返回列表」保留筛选与列表滚动位置。

## 状态反馈
- 讨论状态（持久化，仅两种）：讨论中 / 已归档；筛选、列表、详情状态胶囊均只用这两档。
- 阶段反馈（非状态，仅提示）：「等待纪要」「纪要已生成」「有待创建草稿」，以列表行副标题与详情通知条呈现，不参与筛选。
- 操作反馈：提示词复制成功、纪要读取中、创建中、创建完成（含成功/失败计数）、归档与恢复确认，统一在通知区/页脚提示。
- 空态：无讨论记录时引导新建；无纪要时提示讨论仍在 Agent 会话中；纪要零候选时说明「可以只有结论，不必生成需求或 Bug」。
- 加载态：纪要读取、列表刷新时的过渡反馈，期间相关操作禁用。
- 失败态：Agent 输出不完整/格式错误（拒绝半写入并说明原因）、条目创建部分失败（逐项结果 + 仅重试失败项）、重复创建拦截提示。

## 状态与主流程
讨论持久化状态仅「讨论中」「已归档」两种。「等待纪要」「纪要已生成」「有待创建草稿」仅为阶段反馈或成果提示，不作为第三种讨论状态。
1. 新建讨论保存唯一编号和背景，生成启动提示词；用户复制到 Agent 新会话自由讨论。复制只表示提示词已生成/复制，不代表 Agent 已连接。
2. 讨论完毕生成收尾提示词，要求 Agent 将纪要与候选需求/Bug 草稿完整写入约定目录。等待过程中讨论仍为讨论中。
3. 看板自动读取完整成果，候选条目只作为草稿，未经人工确认不自动创建。
4. 用户编辑并勾选草稿，确认后通过既有条目创建机制创建需求或 Bug，初始状态待接受。支持一讨论生成多条、混合类型，也允许零条。
5. 来源讨论和生成条目双向关联，详情可跳转；创建结果持久化并防止重复创建。部分失败应显示每项结果，可只重试失败项。
6. 用户可归档讨论，无须以生成条目为前提；归档仍保留成果记录，继续讨论恢复讨论中。已有纪要不能因继续讨论丢失。

## 范围边界
- 单人使用，无后台常驻调度、看板聊天或子代理在线状态管理要求。
- 不基于某一需求说明做讨论，不展示 README 修改草稿或差异对比；成果是新需求/Bug 草稿。
- 不自动接受或完成生成的需求/Bug，不启动开发。
- 当前已有讨论数据需兼容，不删除旧记录；旧执行状态如何映射到两态、旧回答如何保留须在设计文档明确。
- Agent 输出格式需明确编号、纪要和候选项结构；拒绝不完整/错误输出并提供可理解反馈，避免半写入被读取。

## 验收标准
- [ ] 宽屏布局与需求模块一致；窄屏列表/详情切换，返回后保留筛选和位置。
- [ ] 只显示讨论中和已归档两个筛选与讨论状态；等待纪要仅为操作反馈。
- [ ] 无关联需求也可创建讨论，启动提示词携带背景、编号、项目及落盘约定。
- [ ] 收尾提示词用于原 Agent 会话，完整纪要及候选草稿落盘后看板自动展示；错误输出有反馈。
- [ ] 候选需求/Bug 可以编辑、取消勾选与混合批量创建，字段校验明确。
- [ ] 创建后为待接受，双向来源关联真实有效，可跳到条目详情；刷新与重试不会重复创建成功项。
- [ ] 可无成果归档或继续讨论，保留此前纪要和已生成条目。
- [ ] 无说明差异对比视图，无强制需求绑定，无多人模拟功能。
- [ ] 新建与草稿编辑的必填校验、空态、加载态、失败反馈按「状态反馈」节呈现；剪贴板不可用时有手动复制回退。
- [ ] 兼容旧讨论记录，既有需求/Bug 创建与状态规则不回归。

# 设计 — REQ-20260921-014 版本计划详细内容页面中的概况页签增加修改功能

> 由 Agent 在 /dev 开发前补充，人可随时批注。

## 背景

概况页签（五步流程第 1 步「版本计划」）现状只能靠点击名称 / 描述文本进入行内单字段编辑，
可发现性差；显式表单只存在于「AI 完善」弹窗，无法脱离 AI 流程手动修改。后端
`POST /api/build/version/save`（scripts/lib/build-store.mjs saveInfo）已具备名称 + 描述
同请求保存、长度校验（NAME_MAX=80 / DESC_MAX=4000）与 merging 锁定（409
「版本合并中，暂不可修改」），本单纯前端补显式入口与表单。

## 方案

**入口与表单（scripts/web/build.js）**

- 新增模块状态 `state.planEdit: { id, name, description, error, busy } | null`：
  概况页签编辑态，按版本 id 归属（选中版本变化后旧表单自然失效不渲染）。
- 概况页签描述块头部行新增显式「编辑」按钮（`#bldEditInfo`，title 说明可编辑名称与描述），
  与展示内容同屏可见；merging 版本按钮 `disabled` + title「版本合并中，暂不可修改」，
  且页签内已有合并中就地文字提示（不只靠颜色）。
- 点击后展示区（描述块）就地替换为编辑表单 `renderPlanEditForm`：名称单行 input +
  描述多行 textarea + 字数计数器（`N / 80`、`N / 4000`，输入时直接更新计数文本节点，
  不整页重渲染保焦点）+ 就地错误区 +「保存 / 取消」。表单预填当前名称与描述，打开后
  焦点落名称输入框；不弹新窗、不跳页、不离开当前步骤。
- 行为函数：`openPlanEdit / cancelPlanEdit / submitPlanEdit / syncPlanEditDraft`；
  纯函数 `validateVersionInfo(name, desc)`（导出供测试）——客户端校验镜像
  build-store validateInfo + 名称非空口径：名称 trim 后为空 →「版本名称不能为空」、
  名称 > 80 字 →「版本名称不超过 80 字」、描述 > 4000 字 →「版本描述不超过 4000 字」，
  校验失败不发请求、就地报错并聚焦出错字段（数据层校验兜底双保险，沿用 AI 完善表单口径）。
- 保存：两字段经同一请求 `POST /api/build/version/save` 提交；保存中（busy）保存 / 取消
  禁用、按钮显示「保存中…」防重复提交；成功退出编辑态 + `refresh()` 就地刷新（详情头部 /
  概况页签 / 左侧版本列表同步）+ toast「✓ 已保存版本信息」；失败（网络 / 服务端错误含
  merging 409）就地显示原因 + toast「✕ 保存失败：<原因>」，表单内容保留可重试或取消。
- 编辑态重置：切换版本（selectVersion）、切换步骤（setStep）、切换项目（enter）一律清空
  `planEdit` 回展示态，不把未保存草稿静默写入；后台重渲染（refresh 等）经
  `syncPlanEditDraft`（挂 render(syncModalDrafts) 既有路径）回同步输入框当前值防丢草稿。

**入口关系取舍（README「待确认」落定）**：显式表单与既有「点击文本行内编辑」**并存**——
行内点击（title「点击编辑名称 / 描述」提示）保留为快捷路径，两编辑态互斥（打开一个关闭
另一个；表单打开时点头部名称聚焦表单名称字段而非再开行内编辑）。merging 下行内点击同样
收口：不再进入编辑而是 toast「版本合并中，暂不可修改」，与新入口禁用口径一致。

**可编辑状态范围（README「待确认」落定）**：沿用现状——仅 merging 锁定名称 / 描述
（draft / merged / failed 可改；已正式发布只锁条目增删不锁名称描述），不在本单收窄。

**样式（scripts/web/style.css）**：新增 `.bld-desc-block-head`（描述标签 + 编辑按钮行）、
`.bld-plan-edit`（表单容器，沿用既有卡片边框变量）、`.bld-plan-count`（计数器）；
输入控件复用 `.field` / `.bld-edit-form` 既有样式；深浅色沿用 CSS 变量，窄屏纵向堆叠。

**i18n（scripts/web/i18n.js，BUG-20260912-001）**：新增词条（EN）——「版本名称」「版本描述」
「版本名称不能为空」「版本名称不超过 80 字」「版本描述不超过 4000 字」「版本合并中，暂不可
修改」「✓ 已保存版本信息」「（无描述）」「编辑版本信息」及欠账「点击编辑名称」「点击编辑
描述」；EN_DYNAMIC 补「✕ 保存失败：◇」（saveInfo 失败 toast 既有欠账）。空描述占位由
「（无描述，点击补充）」改为「（无描述）」（发现性由显式按钮承担）。

**开源选型（REQ-20260909-015）**：自研——单个就地编辑表单（两输入 + 校验 + 计数），
仓库内已有同款表单交互（AI 完善回填表单 REQ-20260913-006）与样式骨架可复用，无引入
表单库的必要（无合适库的理由：纯展示型单表单，引入库的体积与适配成本高于自研数十行代码）；
未引入开源库，不创建 licenses.md。

## 风险与边界

- 客户端校验与数据层口径需保持一致（80 / 4000 以 build-store NAME_MAX / DESC_MAX 为准，
  前端常量注释标注镜像来源）；越界值仍由服务端兜底拒绝。
- merging 锁定有窗口竞态（进入编辑后版本转 merging）：保存时服务端 409 按失败口径反馈
  （就地原因 + toast + 内容保留），不误报成功。
- 不改动五步导航、门禁、AI 完善弹窗、创建 / 添加面板、合并 / 删除等既有能力；
  `POST /version/save` 请求体与后端无接口变更。

# REQ-20260921-014 版本计划详细内容页面中的概况页签增加修改功能

- 状态：submitted（待人工接受）
- 创建：2026-09-21T07:58:44.377Z

## 描述

### 位置与术语对齐

「版本计划详细内容页面」指发布模块（原「构建」模块，REQ-20260920-003 改版）「版本计划」页签下、点击左侧版本卡片后的右侧详情页。详情页顶部为五步导航：**版本计划 → 关联条目与提交 → 文档编写 → 合并入 main → 正式发布**；其中第 1 步「版本计划」页签展示该版本的概况信息（名称、状态、计划号 / 版本号、目标 / 来源分支、描述、合并状态提示），即本单所称「概况页签」（历史上 BUG-20260915-014 曾直接命名「概况 / 发布」两页签，后被五步流程取代；若人工认为本单另有所指页面，请在接受时纠正）。

### 现状与缺口（代码事实：scripts/web/build.js、scripts/lib/build-store.mjs、scripts/server.mjs）

- 名称与描述在技术上已可修改，但入口完全隐性：需点击详情头部的名称或概况页签的描述文本本身才进入行内编辑（input / textarea + 保存 / 取消），可发现性仅靠悬停 title 提示「点击编辑名称 / 点击编辑描述」与指针样式，页面没有任何可见的编辑按钮或表单入口。
- 显式的名称 / 描述编辑表单目前只存在于「AI 完善」弹窗（REQ-20260913-006）：须先复制提示词、粘贴 AI 回答并解析成功后才出现可编辑表单，无法脱离 AI 流程手动修改。
- 后端能力已具备：`POST /api/build/version/save` 支持修改名称与描述。校验与锁定口径：名称去空白后不可为空（「版本名称不能为空」）、名称 ≤ 80 字（NAME_MAX）、描述 ≤ 4000 字（DESC_MAX）；merging 状态锁定（409「版本合并中，暂不可修改」）；保存成功 / 失败有 toast 反馈（「✓ 已保存版本信息」/「✕ 保存失败：原因」）。

缺口：概况页签缺少显式、可见的手动修改入口，用户难以发现标题与描述可以改、怎么改。本单要求在概况页签提供显式修改功能——手动修改版本计划标题（名称）与描述，不依赖 AI 完善流程、不依赖悬停提示。

### 目标

- 概况页签提供可见的「编辑」入口（按钮或等效形式），点开后就地编辑名称与描述（同一表单可同时修改两者），支持保存 / 取消。
- 校验、锁定与反馈口径沿用现状：名称必填、长度限制（80 / 4000 字）、merging 锁定；成功 / 失败反馈明确，失败保留内容可重试。
- 新增界面文案按 BUG-20260912-001 同步中英文入 `scripts/web/i18n.js` 词典；本单所涉既有行内编辑文案（「点击编辑名称」等）目前未入词典，属既有欠账，一并补齐。

### 待确认

- 可编辑状态范围是否收窄：现状仅 merging 锁定名称 / 描述（draft / merging / merged / failed 中除 merging 外均可改，已正式发布只锁条目增删不锁名称描述）。默认沿用现状；如需「已正式发布后锁定名称 / 描述」，由人工在接受或设计阶段明确。
- 显式「编辑」入口与既有「点击文本行内编辑」的关系（并存或替换）：默认并存（行内点击保留），最终取舍在设计阶段（design.md）落定。
- 是否提供字数计数器（如「12 / 80」）：可选优化，不作为验收硬性项。

## 界面布局

- 详情页整体结构不变：头部（名称 + 状态徽标 + 计划号 / 版本号 / 更新时间）→ 五步导航 → 步骤内容区；变化集中在第 1 步「版本计划」（概况）页签。
- 概况页签内容自上而下：概况信息行（计划号、版本号、目标分支、来源分支）→ 描述块（标签「描述」+ 内容）→ 合并状态提示（如有）。
- 新增显式「编辑」按钮：位于名称行 / 描述块区域，与展示内容同屏可见；点击后展示区就地替换为编辑表单——名称单行输入 + 描述多行 textarea + 保存 / 取消按钮 + 就地错误提示区（不弹新窗、不跳页、不离开当前步骤）。
- 描述为空时展示「（无描述）」类占位并可经编辑表单补充；名称为空时兜底显示计划号（现状 `name || id` 口径）。
- 深浅色跟随系统外观；窄屏纵向排列（沿用 REQ-20260920-003 口径）。

## 交互行为

- 进入编辑：点「编辑」按钮（行内点击入口若保留则同样生效）→ 表单预填当前名称与描述，焦点落名称输入框。
- 保存：名称与描述经同一请求提交（`POST /api/build/version/save` 现状支持同时携带两者）；保存中按钮禁用防重复提交；成功后退出编辑态、就地刷新名称 / 描述，左侧版本列表与详情头部同步更新，toast「✓ 已保存版本信息」。
- 校验（不发请求，就地拦截；数据层兜底双保险，沿用 AI 完善表单口径）：名称 trim 后为空 →「版本名称不能为空」；名称 > 80 字 →「版本名称不超过 80 字」；描述 > 4000 字 →「版本描述不超过 4000 字」；校验失败焦点回到出错字段。
- 失败：保存失败（网络 / 服务端错误，含 merging 409）→ 就地显示原因 + toast「✕ 保存失败：原因」，表单内容保留，可修改后重试或取消。
- 取消：放弃未保存修改回到展示态。
- merging 锁定：编辑入口禁用，悬停 / 就地提示「版本合并中，暂不可修改」。
- 编辑期间切换版本 / 项目 / 步骤页签：编辑态重置为展示态，不把未保存草稿静默写入（不产生误保存）。

## 状态反馈

- 正常：展示态（名称 + 描述）；编辑态（表单 + 保存 / 取消）。
- 空：描述为空显示占位文案，可进入编辑补充；不伪装成有内容。
- 加载：详情 / 模块数据读取中编辑入口不可用，操作暂缓。
- 保存中：「保存中…」+ 按钮禁用，防重复提交。
- 成功：toast「✓ 已保存版本信息」+ 展示态数据刷新。
- 失败：toast「✕ 保存失败：原因」+ 就地原因展示，内容保留、支持重试；不显示「已保存」假象。
- 锁定（merging）：入口禁用 + 文字原因提示；所有状态不只靠颜色区分（文字 + 禁用态）。

## 验收标准

- [ ] 编辑表单预填当前名称与描述，同一表单可同时修改两者，一次保存提交；取消放弃修改回展示态。

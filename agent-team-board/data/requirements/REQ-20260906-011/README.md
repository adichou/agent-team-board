# REQ-20260906-011 待接收和已接收的需求和 bug 要提供修改按钮，将用户要修改的内容整理成提示词复制到剪贴板

- 状态：accepted（in-progress，zcode-batch-005-1 实施中）
- 创建：2026-09-06T03:42:57.875Z

## 描述

Status Board 看板上，处于「待接受」（submitted）和「已接受」（accepted）两列的需求和 Bug 条目，
在开发尚未开始（未认领）前常需要人工补充或修订描述、方案、用例。目前用户只能手动打开
条目目录复制 markdown，再手写提示词交给 Agent 修改，步骤繁琐且容易漏上下文。

在卡片和详情抽屉为这两列条目提供「修改」按钮：点击后前端拉取该条目全部现状文档
（README.md / design.md / test-cases.md 等，按条目实际存在的为准），整理成一份修改提示词
复制到剪贴板。用户粘贴到本项目 ZCode 会话，在提示词的「修改要求」处补充想改什么后发送，
Agent 即可直接编辑条目目录下的 markdown。

界面行为：

- 卡片：待接受 / 已接受两列的卡片头部（单号复制按钮右侧）出现「修改」按钮；点击只复制提示词，
  不打开详情（不冒泡），复制期间按钮禁用防重入，成功后按钮短暂显示「已复制 ✓」并 toast 提示。
- 详情抽屉：待接受 / 已接受条目的操作区同样提供「修改」按钮，行为一致。
- 开发中 / 待确认 / 已完成条目不出该按钮（已进入实施或已完结，修改应走新 Bug / 驳回流程）。

提示词内容（按序）：

1. 首行说明：修改看板条目 `<单号>`「标题」（类型、状态），以及条目目录相对路径。
2. 约束：只编辑条目目录下 markdown；`status.json` 为机器状态禁止改动；不改变条目状态与流程位置。
3. 「修改要求：」占位段，用户粘贴后在此补充。
4. 「现状文档」：逐份附上条目目录下全部 markdown 全文（四反引号代码块包裹，防文档自身含三反引号）。

失败路径：条目详情或文档拉取失败、剪贴板写入失败时 toast 如实报错，按钮恢复可点击，可重试。

## 验收标准

- [ ] 待接受 / 已接受两列的卡片与详情抽屉均有「修改」按钮；需求与 Bug 一致提供。
- [ ] 点击按钮复制完整提示词：含单号、标题、类型与状态、条目目录路径、修改约束、修改要求占位段、
      以及条目全部现状 markdown 文档全文。
- [ ] 复制提示词不触发卡片打开详情等既有交互；复制期间防重复点击；成功有按钮与 toast 反馈。
- [ ] 开发中 / 待确认 / 已完成条目不出现「修改」按钮。
- [ ] 文档或剪贴板失败时报错可重试，不留下中间态。

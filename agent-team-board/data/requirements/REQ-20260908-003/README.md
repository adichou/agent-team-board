# REQ-20260908-003 支持待接受的需求删除

- 状态：in-progress（已认领实施）
- 创建：2026-09-08T00:43:15.707Z

## 描述

看板条目目前没有任何删除入口：误登记的占位单、重复单一旦创建，要么接受后走完全部流程，
要么永远挂在「待接受」列。本需求为待接受条目补上删除能力，让登记错误在进入流程前可以被清理。

**范围（含 Bug 的说明）**：待接受（submitted）的需求与 Bug（独立与归属）均可删除。
「待接受」列同时承载 REQ / BUG 两类单据，误登记都可能发生；且归属 Bug 经常挂在尚未接受的
需求下，若 Bug 不可删除，带下属 Bug 的待接受需求将永远无法删除（死路）。与
REQ-20260907-011（待接受改标题）的双类型口径一致。

**交互与规则**：

1. 仅 submitted 状态可删除；accepted / in-progress / done 已进入实施流程（有认领、报告、
   批次痕迹），不提供删除，走「驳回 / 新单」既有路径。
2. 删除即移除整个条目目录（status.json 与全部 markdown 文档）。单号计数器单调递增、
   不因删除回退，保证单号全局唯一不复用。
3. 需求仍有下属 Bug（任意状态）时不允许直接删除：错误信息指引先删除下属 Bug 或移动其
   归属——避免一次确认连带销毁多条单据。
4. 删除在看板层面不可撤销（条目目录随 `docs/` 在 git 内，找回只能依赖版本历史）。因此
   网页入口使用**页面内 danger 确认对话框**（异步 uiConfirm，不用 window.confirm，
   见 BUG-20260907-009）；REQ-20260906-014 的「免确认 + 撤销」范式适用于可撤销的状态
   流转，不适用于本不可逆操作。
5. 操作入口与既有人工操作一致：Status Board 网页（主入口）+ 终端 CLI（`atb delete <ID>`）。

## 验收标准

- [ ] submitted 需求 / Bug（独立与归属）可通过网页与 CLI 删除：条目目录整体移除，
      看板列表与详情不再出现，其余条目不受影响，单号计数器不回退。
- [ ] 非 submitted 状态（accepted / in-progress / done）删除被拒绝，明确报错且目录完好。
- [ ] 需求存在下属 Bug 时删除被拒绝，错误信息指明先处理下属 Bug；下属 Bug 删除或移走后
      可删除该需求。
- [ ] 不存在 / 非法单号删除报明确错误。
- [ ] 网页：待接受卡片与详情页提供「删除」按钮；点击弹页面内 danger 确认，确认后调
      `DELETE /api/item/:id` 并刷新列表；详情页正展示被删条目时自动关闭抽屉；
      非 submitted 条目不渲染删除按钮。
- [ ] API：`DELETE /api/item/:id` 仅受理 submitted；受既有 `/api/*` 跨站防护（Origin/Host）约束。
- [ ] CLI：`atb delete <ID>` 登记于 usage；仅 submitted 可删，输出删除结果。
- [ ] 全部既有测试保持通过。

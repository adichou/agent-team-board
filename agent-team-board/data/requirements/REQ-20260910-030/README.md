# REQ-20260910-030 在发布模块中支持将 electron app 构建成 mac app 和 Windows app

- 创建：2026-09-10T15:50:29.959Z
- 状态以系统维护的 status.json 为准。

## 描述

在 REQ-20260910-029 发布模块的目标类型中新增第三个可执行目标「桌面应用（Electron）」：以与 Git 远端 / Apple App Store 相同的可恢复、可追溯流水线，把当前项目的 Electron 应用（本项目即 Agent Team Board 桌面壳）构建为 macOS 应用包与 Windows 安装包。构建工具复用项目既有 devDependency electron-builder（MIT，符合 REQ-20260909-015 开源白名单），不复制开源源码入库。

沿用发布模块既有语义：发布是实际执行流程，预检只读不构建，启动前必须展示构建计划并由用户确认（确认即授权该明确计划）；构建在冻结提交的隔离工作目录执行，产物记录路径、大小、SHA-256、源提交 OID 与工具版本，可追溯到源提交；失败重试只重跑未完成阶段，可取消后续阶段，同目标并发互斥，服务重启后运行标记 interrupted 可重试；日志脱敏落盘。首期产物仅存本地并在「产物」页签展示，不自动上传或分发到任何渠道。

## 目标类型与配置

「桌面应用（Electron）」与 Git 远端、Apple App Store 并列出现在新建面板目标类型网格与列表筛选器中；网站 / 网络存储仍置灰「首期未开放」。对当前项目执行构建；预检发现项目不是 Electron 工程（无 package.json main 指向 Electron 入口、无 electron / electron-builder 依赖或构建配置）时明确阻塞并给出指引，不误构建。

新建运行配置字段（用户可见行为，字段名以实现为准）：

- 目标平台：macOS、Windows，可多选（可只构建其一）。
- 架构：macOS 与 Windows 分别选择（如 mac arm64 / x64 / universal、win x64；可选组合由 design 阶段的构建配置定夺，不可行的组合在预检或构建阶段明确失败）。
- 版本号：默认读取项目 package.json version（当前 0.1.0），可覆盖。
- 输出目录：默认 `dist/`（.gitignore 已忽略）。

同目标（桌面应用）并发运行互斥，沿用模块既有 `ACTIVE_STATUSES` 口径；与 Git / Apple 目标之间互不影响。运行状态机（draft / prechecking / running / waiting-manual / succeeded / failed / canceled）与页面信息架构不变。

## 构建流水线

五阶段（顺序即执行顺序；阶段拆分可在 design 阶段微调，用户可见闭环不变）：

1. 配置冻结：记录源提交 OID、平台 / 架构 / 版本 / 输出目录；启动后配置与源提交变化使计划失效阻塞（沿用模块口径）。
2. 本地预检（只读，不构建）：Git 仓库且工作区 / 暂存区干净（未提交修改只引导回现有提交功能，不自动 add/commit/stash）、Electron 工程与 electron-builder 构建配置就绪、node / npm 可用。
3. 依赖安装：在冻结提交对应的隔离工作目录安装依赖（命令选择由 design 定夺），失败不可继续。
4. 桌面构建：electron-builder 按选定平台与架构构建 macOS 应用包与 Windows 安装包（具体产物形态由构建配置定夺）；实时追加脱敏日志；无法完成的平台 / 架构明确失败并说明原因，不假成功。
5. 产物核验：逐个校验产物存在，记录路径、大小、SHA-256、源提交 OID、electron / electron-builder 版本，全部通过才标记成功；未配置签名证书时产物与界面明确标注「未签名」（首期不做签名 / 公证，是否支持待确认，不伪造签名状态）。

## 界面布局

- 沿用发布模块既有布局：模块内左右分栏——左侧运行列表（目标类型筛选新增「桌面应用（Electron）」，状态筛选不变），右侧运行详情；顶栏「发布」页签、项目选择器不变。
- 运行列表卡片：目标 chip 新增「桌面应用（Electron）」类型（与 Git / Apple chip 并列的第三种配色）；标识为 `应用名 版本 · 平台组合`（如 `Agent Team Board 0.1.0 · macOS + Windows`），摘要行含源提交、输出目录、创建时间；状态 chip 与既有七态一致。
- 运行详情：头部目标标识与状态摘要；下方阶段进度条为五阶段（✓ 已完成 → ◉ 进行中 → ○ 未开始，失败阶段红显并给出原因）；「概览 / 阶段日志 / 产物 / 操作历史」四页签不变；底部操作区按状态出现「预检 / 启动发布 / 重试失败阶段 / 取消后续阶段 / 刷新状态」。
- 「产物」页签按产物逐条展示：文件名、平台与架构、大小、SHA-256（截断展示）、源提交、electron-builder 版本；未签名产物带「未签名」标注；无产物（未构建 / 构建失败）时明确说明。
- 新建发布侧拉面板：目标类型网格新增「桌面应用（Electron）」可选卡；选中后动态渲染该类型字段（目标平台多选、架构、版本号默认值、输出目录）；底部「保存草稿 / 预检 / 启动发布」不变；网站 / 网络存储仍置灰。
- 窄屏（≤960px）分栏改上下排列、深浅色走既有 CSS 变量随系统自动适配，沿用全站约定。

## 交互行为

- 新建面板先选类型再填字段；平台多选实时反映到预检结果与构建计划（只勾 macOS 则计划只含 macOS）。
- 保存草稿 → 预检（只读：Git 状态、工程与配置检查，不安装依赖、不构建）→ 启动前弹出计划确认：展示平台 / 架构 / 版本 / 输出目录、冻结源提交与「产物未签名（如未配置证书）」提示，用户确认即授权该明确计划。
- 构建中当前阶段转圈、阶段日志实时追加（脱敏）；点击列表运行切换详情、页签内查看阶段输入与结果，均为只读不触发执行；活动运行自动轮询刷新，新开页面不重复执行已开始的阶段。
- 失败运行显示失败阶段与原因，「重试失败阶段」只重跑未完成操作（依赖安装已完成则不重装，从失败阶段续跑）；「取消后续阶段」后已完成阶段与日志证据保留。
- 同目标并发互斥：已有活动的桌面构建运行时再建 / 再启动同目标会被拒绝（HTTP 409 口径，前端引导到现有运行）；Git / Apple 运行不受影响。

## 状态反馈

- 空态：模块空态文案更新为三目标说明（Git 远端 / Apple App Store / 桌面应用）；项目缺 Electron 工程或构建配置时给出对应指引而非空列表。
- 加载态：列表与详情拉取显示加载指示；构建阶段执行中该阶段转圈并实时追加日志；依赖安装与构建耗时较长时展示进行中状态，不因耗时长判失败。
- 失败态：分阶段明确文案——预检不通过（脏工作区 / 非 Electron 工程 / 缺构建配置）、依赖安装失败（网络 / registry 错误）、构建失败（平台工具缺失 / 磁盘空间 / electron-builder 报错原文摘录）、产物核验失败（产物缺失）；保留全部输入、日志与已执行证据供重试。
- 成功态：全部产物核验通过才标成功，产物页签列出完整清单（含未签名标注）；操作历史记录关键证据（冻结提交、工具版本、产物摘要）。
- 服务重启：running 运行标记 interrupted（可重试），不自动重跑已开始的阶段，沿用模块既有口径。

## 验收标准

- [ ] 「桌面应用（Electron）」在新建面板目标类型网格与列表筛选器中可选可执行，与 Git / Apple 并列；网站 / 网络存储仍置灰「首期未开放」；非 Electron 工程项目预检明确阻塞并给出指引。
- [ ] 预检只读：脏工作区、缺 electron / electron-builder 依赖、缺构建配置、node / npm 不可用分别明确阻塞；不自动 add/commit/stash，不触发依赖安装与构建。
- [ ] 启动前展示构建计划（平台 / 架构 / 版本 / 输出目录 / 冻结提交 / 未签名提示），确认后执行；执行中源提交或配置变化使计划失效阻塞。
- [ ] macOS 主机产出 macOS 应用包与 Windows 安装包（产物形态以 design 阶段构建配置为准）；构建在冻结提交的隔离工作目录执行；交叉构建等做不到的组合明确失败并说明原因，不以部分产物冒充全部成功（平台多选时逐平台给出成败）。
- [ ] 产物核验记录每个产物的路径、大小、SHA-256、源提交 OID、electron / electron-builder 版本，可追溯到源提交；产物页签完整展示，未签名产物明确标注；产物仅存本地，不自动上传分发。

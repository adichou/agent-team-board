# REQ-20260910-010 项目管理中，提供自动检测不存在的目录并支持一键移出所有不存在的目录

- 创建：2026-09-10T01:48:25.208Z
- 状态以看板机器记录为准。

## 描述

在「管理项目」面板自动检查已登记项目的根目录是否存在，明确标出不存在的目录，并提供「移出所有不存在目录」入口，避免用户逐个处理失效的项目记录。检测本身只读；仅用户触发移出后才更新项目列表。

### 现有依据与范围

- `scripts/web/app.js` 的 `openProjPanel` 在打开面板时刷新项目列表，`renderProjPanelList` 展示名称、完整路径、当前标识、切换及单项移出入口。
- `scripts/server.mjs` 的 `/api/project/remove` 当前先通过 `resolveProjectPath` 校验目录存在，因此已不存在的路径无法沿此入口移出。本需求要求此类注册记录可被清理。
- 现有 `unregisterProject` 仅更新项目注册表并记录显式移出，保留磁盘文档与任务；本需求沿用这一语义，不能删除目录、需求、Bug、批次或停止任务，也不能由旧轮询自动登记回来。
- 检测范围为当前服务已登记项目的根路径，不扫描磁盘发现新项目，不把「缺少看板数据」等同于「目录不存在」。权限错误、读取失败应显示「检测失败/待确认」，不得纳入批量移出候选。
- 外接盘未挂载、断开的符号链接等具体检测归类及后台定时检测频率待确认；已确定打开面板即自动检测，并支持手动重新检测。

### 界面布局

沿用项目管理面板，在列表上方增加检测摘要（总数、不存在数、检测失败数）、「重新检测」和「移出所有不存在目录（N）」按钮。每行保留项目名、完整路径、当前项目标识及原有操作，增加「存在」「不存在」「检测中」「检测失败」文字状态，不能仅靠颜色区分。长路径可换行，小屏按钮可换行，列表可滚动。

### 交互行为

1. 打开面板后自动检测最新项目列表；检测期间显示进度，批量移出按钮不可用。重新检测更新状态，不执行移出。
2. 检测完成且有不存在目录时启用批量入口；点击后在面板内展示确认区，列出本次候选完整路径和数量，说明仅移出列表，可在目录恢复后重新导入。取消不变更列表。
3. 确认时重新核实候选；已恢复存在、已被其他窗口移出或无法确定状态的路径不再作为不存在目录移出，报告跳过原因。不得扩大到确认列表之外的新候选。
4. 移出期间防止重复提交；完成后刷新项目列表与项目切换器。部分失败保留失败记录，分别报告成功、跳过和失败数量及路径，支持重新检测后重试。
5. 当前项目被移出时沿用现有逻辑选择剩余首项；无剩余项目进入无项目引导空态，清除旧项目展示，初始化和导入入口仍可用。其他项目被移出不改变当前选择。

### 状态反馈

- 正常：逐项存在性标识与准确计数；不存在项目保留在列表等待用户处理。
- 空：无项目时显示初始化/导入引导；无不存在目录时提示「未发现不存在的目录」，批量按钮禁用。
- 加载：显示「检测中…」或「移出中…」，禁用冲突操作，保留已有列表。
- 失败：全局检测失败显示重试入口，不使用旧结果继续批量操作；单项检测失败展示路径与原因，不误判为不存在。移出失败不得显示全部成功。

## 验收标准

- [ ] 打开管理项目面板即自动检测全部已登记根目录，逐项显示结果及正确汇总；手动重新检测能反映目录恢复或消失。
- [ ] 只将明确不存在的根目录纳入候选；存在但缺看板数据、权限错误、检测失败不作为不存在移出。
- [ ] 检测中、检测整体失败、无候选时不可批量提交；失败提供明确原因及重试入口。
- [ ] 批量入口显示候选数量，确认区列出完整路径及仅移出列表的语义；取消不产生变更，确认期间重复点击不产生重复请求。
- [ ] 确认后重新核实候选，恢复存在及无法确定的项目被跳过并解释，不意外清理确认范围外的项目。
- [ ] 成功仅移出相应注册记录，不删除磁盘文件、不改变条目状态、不停止任务；轮询不能悄悄恢复已移出的记录。
- [ ] 部分失败明确展示成功/跳过/失败明细，失败项目保留且可重新检测重试，不能笼统提示全部成功。
- [ ] 列表与切换器同步更新；移出当前项目选择剩余首项，移出最后项目显示无项目引导并清除旧内容。
- [ ] 单项移出、初始化、导入和现有项目切换保持可用；长路径、小屏、键盘操作及文字状态可辨识。
- [ ] ui-demo.html 可直接离线打开，内联 CSS/JS，无构建或外网依赖，能演示检测、确认/取消、移出结果及正常/空/加载/失败状态。

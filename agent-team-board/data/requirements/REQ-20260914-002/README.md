# REQ-20260914-002 分支浏览中支持在当前分支中搜索提交记录

- 状态：submitted（待人工接受）
- 创建：2026-09-14T08:16:20.942Z

## 描述

### 现状（已核实）

- 构建模块「分支浏览」子页签（`scripts/web/build.js`，REQ-20260913-001 建立，BUG-20260914-009 补齐分页）：左侧分支列表（当前 / 本地 / 远端分组，头部「⟳ 和远端同步」「刷新」）+ 右侧所选分支的提交记录面板（`renderBranchesPane`，约 1105 行起）。
- 右侧面板头部 `bld-log-head`（约 1179 行）只有**分支名 + 「刷新」按钮**，没有任何搜索入口；列表行为「短 hash + 提交说明 + 作者 + 时间」，下方为分页条（上一页 / 页码 / 下一页 / 每页 20/50/100 条 / 「第 x–y 条 / 共 N 条」，`logPagerHtml`）。
- 点选分支懒加载：`selectBranch(branch)` → `loadLog()` 请求 `GET /api/build/branch-log?branch=<name>&limit=<size>&offset=<(page-1)*size>`；服务端（`scripts/server.mjs` 约 2091 行）调用 `buildGit.branchLog(root, branch, { limit, offset })`（`scripts/lib/build-git.mjs` 72 行）以 `git log <ref> -n <n> --skip <skip> --format=…` 取数并附 `rev-list --count` 总数，响应 `{ branch, commits, total, limit, offset }`。**接口与数据层均不支持关键词搜索参数。**
- 顶部模块搜索框（`#pageHead`，placeholder「搜版本 / 单号 / 分支…」，app.js 约 1176 行）在构建模块的解释是 `ATBBuild.setQuery()` → `filteredVersions()` 只**按版本名 / 单号过滤版本计划列表**，既不过滤分支列表，也与提交记录无关。
- 痛点（BUG-20260914-009 已述背景）：dev 分支每次开发运行自动提交、提交数持续增长；要在分支提交记录里定位某个提交（典型：按 REQ-/BUG- 单号核对首次提交、按作者或 hash 找某条改动），现在只能逐页翻看（每页最多 100 条），无任何关键词定位手段。

### 目标

在「分支浏览」提交记录面板内提供**关键词搜索**能力，搜索范围为**当前右侧面板正在查看的（所选）分支的全部提交记录**（不受当前分页窗口限制，能命中更早页的提交；跨分支搜索为范围外）：

1. **搜索入口与结果**：选中任一分支后，可在提交记录面板内输入关键词发起搜索；结果按提交时间新→旧排列，沿用现有行渲染口径（短 hash + 提交说明 + 作者 + 时间），并显示命中计数（如「共 N 条匹配」）；无命中有明确空态，与「该分支暂无提交」区分。
2. **匹配口径（最小集合，最终以 design.md 落定）**：提交说明（subject）、作者（author）、hash（短 hash / 完整 hash 前缀匹配）至少三项可命中；大小写不敏感（待确认）。匹配字段范围外（如按日期区间过滤）不在本需求内。
3. **清除恢复**：清空关键词即恢复默认全量分页列表（BUG-20260914-009 口径不回归）。
4. **实现路径待确认（design.md 落定）**：服务端搜索（`git log --grep` / `--author` 等扩展 `/api/build/branch-log` 或新增接口，支持分页与命中总数）或前端过滤（在已加载页内过滤）二选一——**若选前端过滤，必须先解决「未加载页不可搜」问题**（否则无法命中更早提交，等同没做）；本需求验收以「能命中当前分页窗口之外的提交」为准。
5. **只读边界不变**：搜索为纯只读能力，不引入任何 git 写操作；非 git 仓库引导空态、非法 ref 注入拒绝（`assertRefName`）等既有错误路径不回归。

## 界面布局

- 布局整体不变：左侧分支列表（当前 / 本地 / 远端分组 + 「⟳ 和远端同步」「刷新」）；右侧提交记录面板。
- 右侧面板在 `bld-log-head`（分支名 + 「刷新」）下方新增一行**搜索行**：关键词输入框 + 「搜索」触发 + 「清除」入口；具体形态（头部并排一行还是独立一行、是否带下拉限定匹配字段）待确认，以 design.md 为准。
- 搜索结果区沿用 `bld-log` 列表行（短 hash + 说明 + 作者 · 时间）；结果头部显示命中计数（「共 N 条匹配」）；搜索结果数量超过一页时沿用现有分页条（页码 / 每页条数 / 「第 x–y 条 / 共 N 条」），不引入第二套列表样式。
- 命中关键词在说明 / 作者 / hash 上高亮（`<mark>` 类样式）为可选增强（待确认）；深浅色继续走既有 CSS 变量。

## 交互行为

- 触发：输入关键词后回车或点「搜索」发起；关键词为空时点搜索等同清除。是否做输入即搜（防抖自动过滤）待确认，以 design.md 为准。
- 搜索状态独立于顶部模块搜索框：顶部搜索词（版本名 / 单号过滤）不注入提交搜索，提交搜索词也不影响版本计划列表；两套搜索互不串扰。
- 切换分支：重置搜索（清空关键词、结果回到新分支默认分页列表、回到第一页），与现有「切换分支重置回第一页」口径一致（是否保留关键词待确认，倾向重置）。
- 「刷新」：保持当前关键词重新执行搜索（无关键词则刷新默认列表）；「和远端同步」完成后对当前分支的重载（现有 `doSync` 内 `selectBranch(state.logBranch)` 链路）同样保持关键词口径重查（待确认，以 design.md 为准）。
- 每页条数切换（20/50/100）与页码跳转在搜索结果内正常生效；翻到结果末页有明确反馈。
- 搜索执行中防重复触发（输入框与按钮禁用或忽略重复请求）；不自动轮询。
- 快捷键 `/` 当前归属顶部模块搜索框（app.js 既有行为）；提交搜索是否绑定独立快捷键待确认，默认不绑定。

## 状态反馈

- **加载中**：搜索执行中在结果区显示「搜索中…」类指示（与「加载提交记录中…」同范式），期间搜索 / 翻页 / 刷新入口防重复；不白屏、不闪空。
- **空态**：搜索无命中显示「没有匹配的提交（关键词：xxx）」+ 一键「清除」回默认列表；分支本身无提交保持「该分支暂无提交」不变；未选分支保持「点击左侧分支查看提交记录」。
- **失败**：搜索请求失败沿用 BUG-20260914-009 口径——行内错误 + 「重试」，已加载内容保留不丢失；首次加载失败仍走 `logPhase='error'` 全区错误态。
- **成功**：命中计数即时更新；无 toast 打扰（列表型结果不以 toast 报数，具体以 design.md 为准）。

## 验收标准

- [ ] 选中任一分支后，提交记录面板内可输入关键词搜索**该分支全部**提交记录（不是只搜当前页）：在提交数超过一页（50 条）的分支上，用只出现在第 2 页及更早提交的关键词（如某 REQ-/BUG- 单号、作者名或 hash 前缀）搜索能命中并展示该提交，且按时间新→旧排列。
- [ ] 匹配口径覆盖提交说明、作者、hash（短 hash / 完整 hash 前缀）至少三项；大小写不敏感（待确认项以 design.md 落定口径为准验收）。
- [ ] 搜索结果有命中计数（「共 N 条匹配」类），无命中显示明确空态并区分「该分支暂无提交」；空态提供一键清除回默认列表。
- [ ] 清空关键词或点「清除」恢复默认全量分页列表；BUG-20260914-009 的分页行为（页码 / 每页 20/50/100 / 「第 x–y 条 / 共 N 条」/ 末页反馈）不回归。
- [ ] 搜索结果分页正常：翻页、每页条数切换、末页反馈在搜索态下生效；翻页失败保留已加载内容 + 行内错误 + 重试（沿用既有口径）。
- [ ] 切换分支重置搜索并回到新分支默认列表第一页；「刷新」保持关键词重查；顶部模块搜索框（搜版本 / 单号）行为不受影响，两套搜索互不串扰。
- [ ] 搜索执行中有加载指示且防重复触发；失败有行内错误 + 重试，已加载内容不丢失。
- [ ] 服务端实现路径（扩展 `/api/build/branch-log` 或新接口）保持只读，非法 ref 注入拒绝不回归；接口口径（参数名、命中总数返回形态）以 design.md 为准。
- [ ] 非 git 仓库引导空态、分支读取失败重试、「该分支暂无提交」等既有状态不回归。
- [ ] 新增文案接入 i18n 中英词条（REQ-20260911-005 范式，`scripts/web/i18n.js`）；深浅色走既有 CSS 变量。
- [ ] 既有测试全部保持通过（含 `scripts/tests/build-ui.test.mjs`、`build-serve.test.mjs` 的 branch-log 既有用例）；为搜索补充前后端用例（含跨页命中、无匹配、非法输入、切换分支重置）。

# REQ-20260929-002 发布模块删除 Web App 构建目标，不再校验任何构建目标

- 状态：submitted（待人工接受）
- 创建：2026-09-29T02:16:25.972Z
- 关联：REQ-20260915-002（Web App 自动识别与本机部署，本单收窄其适用面）、BUG-20260928-011（构建识别移出预检）、BUG-20260929-003（master 主干发布修复，本次失败运行的排查入口）

## 描述

cili_search（Chrome MV3 扩展，master 主干）发布 1.0.0：`sync-source` 成功后 `webapp-build` 阶段失败，报「无法识别冻结源码的 Web App 构建方式（预检已不含构建识别项；请检查冻结 main 的 package.json / index.html）」。冻结 master 树根目录只有 `manifest.json` / `popup.html` / `background.js` / `popup.js` 等，没有 `package.json` 也没有根 `index.html`——Web App 构建识别（`profile()`）对该类项目必然失败。

人工定夺（2026-09-29，两轮收窄）：

1. **首轮**：发布模块删除 Web App 构建目标，发布流程不再识别、不校验、不执行任何产品源码构建；
2. **二次收窄（本次人工修正）**：「构建」模块发布直线流程的「发布」按钮**不执行任何远端与仓库构建操作**——不推送 master/dev 至 origin，也不构建官网仓库（不执行 npm install / npm run build、不做本机回验）。发布动作收敛为「检查 → 二次确认 → **更新版本计划状态**」：二次确认通过后，仅将版本计划置为「已发布」，此外不做任何事。

### 改动范围

**范围：构建发布（BPUB）**——`build-publish` 模块（`scripts/lib/build-publish.mjs` / `build-publish-store.mjs` / `build-publish-api.mjs`）与「构建」模块发布直线流程（`scripts/web/build.js`，弹窗文案 / 计划步骤 / 错误消息均来自服务端数据，服务端删除后界面自动无残留）及 `scripts/web/i18n.js` 中被删错误消息的文案键。

**不在范围**：

- 「发布」模块两个页签：「发布流水线」（REL：Git 推送 / Apple App Store / Electron 桌面构建）与「产品发布」（PREL，`product-release-pipeline.mjs` 一侧，其列表/详情仍展示「Web App」目标）均保持现状，如需删除另立条目；
- 官网物料构建与部署、源码远端推送：自本条目起**不再由「构建」模块发布步承担**，本条目为纯删减、不新增替代入口（如仍需要，人工在仓库自行操作或另立条目处理）；
- `webapp-profile.mjs`（PREL 流水线与官网仓库构建识别共用）保留。

### 改动内容

1. **执行阶段全部删除**：删除 `sync-source`（源码 main/dev 原子推送）、`webapp-build` / `webapp-verify`（Web App 构建与本机回验）、`site-deploy` / `site-verify`（官网仓库构建与本机回验）全部执行阶段——发布全程无 `git push`、无官网仓库 `npm install` / `npm run build`、无本机回验服务启动；新发布不再产生阶段（stages）/ 目标卡（targets）/ 目录（directories）数据。
2. **发布动作收敛为状态更新**：二次确认（确认 token = 预检指纹）通过后，仅将版本计划状态更新为「已发布」——发布时间取确认时点，已发布不可逆，版本计划锁定仅可查看（如需调整请新建版本）。落账口径由现状「发布运行 succeeded 推导已发布」改为「确认动作直接写版本计划发布态」（实现细节开发阶段在 design.md 展开）。
3. **构建识别删除**：`profile()` 函数及预检中的 `profile` 计算/落库整体移除；发布计划（plan）步骤文案同步删除全部构建/推送步骤。
4. **前置条件收敛**：发布不再要求配置官网仓库与源码远端——「发布」按钮禁用条件仅剩「版本未合并 / 发布中 / 已发布」；「未配置官网仓库」禁用提示与「前往设置」入口从发布步移除。
5. **UI 同步**：发布计划仅 1 条步骤（更新版本计划状态为已发布）；BPUB 界面为「构建」模块发布直线流程弹窗（build.js），文案均取自服务端，服务端删除后自动无推送 / 构建残留；`scripts/web/i18n.js` 中已删错误消息的文案键（中英）同步移除，保证两语言键集一致。
6. **存量运行兼容**：旧运行记录（含各阶段/目标数据的 BPUB 运行）不做迁移，按原样展示；目录查看 API 对旧运行保留既有目录读取。

## 界面展示

可交互演示：[ui-demo.html](./ui-demo.html)——单文件 HTML（内联 CSS/JS）、无外网依赖、无构建步骤，浏览器直接打开即可交互。顶部可切换「版本口径（改动前 / 改动后）」与「项目形态（Chrome 扩展 / Vite Web App）」，并按场景演示：正常发布全流程、未配置官网仓库（改动前禁用 / 改动后可正常发布）、版本未合并、检查未通过、发布记录读取失败、已发布终态、存量运行记录（旧阶段数据按原样展示），支持深浅色切换。

本条目为**纯删减**：发布直线流程的弹窗结构、交互与状态反馈机制均不变，仅执行内容收敛为「更新版本计划状态」。以下小节按删减后口径描述。

### 界面布局

「构建」模块版本详情「发布」步，自上而下：

1. 五步导航（计划 › 关联条目 › 文档与翻译 › 合并入 main › **发布**）；
2. 发布动作区：唯一「发布」主按钮 + 就近原因说明（未合并 / 发布中… / 已发布时禁用；不再有「未配置官网仓库」禁用与「前往设置」）；
3. 结果面板：成功（✓ 发布成功 + 发布时间 + 计划锁定说明）/ 失败（原因 + 重试）/ 空闲（直线流程说明）/ 加载（正在加载发布记录…）；
4. 直线流程弹窗四形态：补填发行版本号 → 发布前检查（检查中）→ 发布二次确认（检查项列表 + 发布计划步骤，计划由 3 条减为 **1 条**）→ 检查未通过（失败项列表）。

改动后数据差异：发布计划步骤由 3 条（原子推送 / 构建 Web App / 官网构建回验）减为 1 条（仅「更新版本计划状态为已发布」）；不再产生流水线阶段与目标卡数据（改动前为 5 阶段）。

### 交互行为

- 点击「发布」→（版本号未预填时先补填发行版本号）→「开始检查」→ 按检查规则检查 → 全部通过进入二次确认（确认 token = 预检指纹）→「确认发布」→ 弹窗关闭即更新版本计划状态为「已发布」：无执行阶段、无中间进度界面，仅按钮禁用显示「发布中…」，结束后结果面板直接上屏；
- 检查弹窗 busy（检查中）不可关闭；检查未通过明确提示「本次不进入发布」，不进入二次确认、不触发执行；
- 状态更新失败时结果面板给失败原因 +「重试」，重试重新走同一发布流程（检查 → 确认，不跳过确认）；
- 本条目不新增任何交互入口与按钮，纯删减。

### 状态反馈

- 正常：检查通过 → 二次确认 → 版本计划即时置为已发布 →「✓ 发布成功（v…）」+ 发布时间（本地时间，取确认时点）+ 计划锁定说明；
- 空闲 / 禁用：尚未发布给出直线流程说明；版本未合并 → 按钮禁用 +「请先完成合并入 main」；改动前的「未配置官网仓库 → 按钮禁用 + 前往设置」在改动后移除——未配置官网仓库不再阻塞发布；
- 加载：检查中「正在按检查规则检查…」/ 按钮「发布检查中…」；状态更新中「发布中…」；发布记录「正在加载发布记录…」；
- 失败：检查未通过弹窗（列失败项，本次不进入发布）；状态更新失败「✕ 发布失败：<原因>」+ 重试；发布记录读取失败给原因 + 重试（只重新读取，不执行发布）；
- **核心对照**：Chrome 扩展形态（无 package.json / 无根 index.html）项目，改动前执行到「冻结源码构建」阶段失败（「无法识别冻结源码的 Web App 构建方式…」），改动后同一项目直接发布成功——发布成败不再依赖源码构建形态，也不再依赖官网仓库配置；
- 存量兼容：含旧阶段 / 目标数据的 BPUB 运行记录不做迁移，按原样读取展示不报错；新发布不再产生阶段 / 目标数据。

## 验收标准

- [ ] 二次确认通过后版本计划即时置为「已发布」，发布时间 = 确认时点；发布全程无 `git push`（master/dev 不推 origin）、无官网仓库 `npm install` / `npm run build`、无本机回验服务启动；新发布不再产生 stages / targets / directories 数据。
- [ ] 发布不依赖官网仓库配置与源码远端：未配置官网仓库（乃至无 origin 远端）的项目可正常完成发布；按钮不再因「未配置官网仓库」禁用，「前往设置」入口从发布步移除。
- [ ] 预检结果不再含 `profile` 字段，预检通过与否与源码构建形态无关；无 package.json / 无根 index.html 的项目（如 Chrome 扩展 cili_search 形态）不再出现「无法识别冻结源码的 Web App 构建方式」错误。
- [ ] 二次确认弹窗发布计划仅 1 条（更新版本计划状态为已发布）；弹窗与结果面板无 webapp / 推送 / 官网构建残留文案；i18n 键集两语言一致（`npm test` 含 i18n 一致性测试通过）。
- [ ] 已发布不可逆：版本计划锁定仅可查看（沿用现状 PUBLISHED_READ_ONLY 口径），发布后不可再调整版本内容。
- [ ] 存量 BPUB 运行记录可正常读取展示（含旧阶段/目标数据的运行不报错）。
- [ ] `npm test` 全量通过。

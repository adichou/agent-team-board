## 描述

### 背景与动机

REQ-20260922-007 将开发收口提交改为「忽略本单条目目录文档」，落地后条目文档（条目目录内 README / design.md / test-cases.md / test-report.md 等）不再随收口入库、滞留工作区，需另走文档讨论轮才能进 git。这与本看板的设计理念相悖：**条目目录（`agent-team-board/data/{requirements,bugs}/<条目ID>/`）是工程单据、属用户数据，应随开发收口正常提交**——收口归因（`scripts/lib/git-flow.mjs` `autoCommitForRun`，认领时工作区快照 → 收口时差集）原本就把它们作为 doc 组提交，这是应当保留的行为。

用户在 REQ-20260922-007 的原意是：AI 开发过程中应忽略的是**仓库根目录下文档**的编写差异——AGENTS.md、README.md、CHANGELOG.md、FEATURES.md、DESIGN.md 等根第一层发布/协作文档由人工与发布文档流程管理，收口提交不应替它们做主，也不应因它们阻塞自动收口。

实际运行已暴露错向口径的痛点：REQ-20260923-001（run-20260923-356）收口时，AGENTS.md 因「认领前已有人工未提交改动 + 本单运行期又修改」无法安全归因，触发 `pendingManual` 暂扣并连带暂扣 test / 业务组、批次暂停，需人工介入才能补提交。若按本需求口径（根文档不参与归因），该场景本可直接完成收口。

### 需求要点

1. **回退 REQ-20260922-007 的实现**：开发收口提交（批量 run 收口与手动 `/dev` 收口，`manual-closeout.mjs` 复用同一内核）恢复 007 之前的行为——本单条目目录（`agent-team-board/data/{requirements,bugs}/<本单ID>/`，含嵌套归属 `bugs/` 子目录）文档改动纳入 doc 组，以 `doc: <标题> <单号>` 主题随收口提交；回执/账本不再把本单条目目录路径列入 `ignoredDocs`。
2. **新口径：忽略根目录文档变更**：收口归因时**忽略仓库根第一层文档文件**的改动——无论认领前是否已脏、运行期是否被本单修改，根文档一律不纳入任何提交分组（doc / test / 业务均不含）、不触发 `pendingManual` 暂扣；差异保留在工作区（不提交、不还原），由人工 / 发布文档流程处理。
3. test / 业务组归因与提交行为不变（BUG-20260915-007 认领时快照归因口径不变）；板级共享路径（迁移搬移 R 码、留痕出库等）维持现状「仍随收口收纳」。
4. REQ-20260917-002 文档讨论轮放行口径、REQ-20260918-002 / REQ-20260923-001 发布文档守卫与提交通道口径不变——本需求只改**收口归因范围**，不动 Agent Bash 提交放行与守卫拦截规则。
5. 相关流程表述（AGENTS.md、skills/agent-team-board/SKILL.md 中 007 落地的「条目文档不随收口提交」类描述）按新口径同步更新：恢复「条目文档随收口提交」，改为「根目录文档不随收口提交、不触发暂扣」。

### 边界与待确认

- **「根目录文档」的精确范围**：初步口径为仓库根第一层的文档文件（AGENTS.md / README.md / CHANGELOG.md / FEATURES.md / DESIGN.md 及根目录其他 `.md`，含语言变体 `<KEY>_<lang>.md`）；LICENSE.md 及根目录非 `.md` 纯文档文件是否纳入**待人工确认**。
- **回退方式**：直接 revert 007 的相关提交，还是在现行实现上向前修改为「条目文档恢复入库 + 根文档忽略」的新行为，**待设计阶段定**（验收以行为口径为准，不限定实现路径）。
- **007 既有测试处置**：`scripts/tests/req-20260922-007.test.mjs` 按新口径修订（「收口不含条目文档」断言反转为「收口含条目文档」，并补根文档忽略断言）还是整体移除重写，**待设计阶段定**。

# 设计 — REQ-20260923-002 开发收口恢复提交条目文档并忽略根目录文档变更（回退 REQ-20260922-007）

> 由 Agent 在 /dev 开发前补充，人可随时批注。

## 背景

REQ-20260922-007 把开发收口改为「忽略本单条目目录文档」，落地后条目文档滞留工作区需另走文档讨论轮，与「条目目录是工程单据、属用户数据、应随收口提交」的设计理念相悖；且 run-20260923-356 已暴露反向痛点：根第一层文档（AGENTS.md 等）「认领前已脏 + 运行期又改」触发 pendingManual 暂扣，连带暂扣 test / 业务组并暂停批次。

## 方案

采用「在现行实现上向前修改」（README 边界第 2 条）：不 revert 007 的提交，直接把归因口径改为「条目文档恢复入库 + 根第一层文档忽略」，验收以行为为准。

### 1. `scripts/lib/git-flow.mjs`（收口归因内核，批量与手动共用）

- **根第一层文档判定**：新增 `isRootLevelDoc(p)` —— 相对仓库根路径不含目录分隔符且以 `.md` 结尾（AGENTS.md / README.md / CHANGELOG.md / FEATURES.md / DESIGN.md 及根目录其他 `.md`，含语言变体 `<KEY>_<lang>.md`；git porcelain 路径恒相对仓库根，已实测验证）。已验证 `git status --porcelain` 从任意 cwd 输出均为仓库根相对路径，判定与 cwd 无关。
  - **边界决策（README 待确认项 1）**：LICENSE.md **纳入**忽略范围——它是根第一层 `.md` 文档，属发布文档簇；「不自动提交、保留工作区」是保守方向（最坏情况由人工经发布通道提交），纳入可避免其「认领前已脏 + 运行期修改」再触发暂扣。根目录**非 `.md`** 文件不纳入，走常规归因。
  - 未跟踪（`??`）的根第一层 `.md` 同样忽略（新写的根文档也是根文档）。
- **`autoCommitForRun` 归因循环**：
  - 首位增加根文档分支：`isRootLevelDoc(p)` → 收集进 `ignoredDocs` 并 `continue`——不进 doc / test / 业务组、不进 pendingManual、不进 excluded；差异保留在工作区（不提交、不还原）。
  - **删除 007 的条目目录忽略分支**（`inItem && owner === itemId → ignoredDocs`）：本单条目目录文档回到 doc 组，以 `doc: <标题> <单号>` 随收口提交（恢复 007 之前行为）；其他条目目录排除、重命名（R 码）板级共享、留痕出库等逻辑不动。
  - `ignoredDocs` 字段语义调整为「收口忽略未提交的文档差异」＝根第一层文档路径（字段名与消费方结构不变：批量回执截断携带、运行账本、auto-commit.json 明细、confirm-store 完整性判定）。回执不再出现本单条目目录的 `ignoredDocs` 条目（验收 1）。
  - 兜底语义沿用 007 已落地形态、方向调整：仅根文档改动（无任何可提交分组）→ `skipped` + `ignoredDocs` + 原因短句，不产生空提交、不报错中断、不误报 committed、不挂起；`docsIgnoredReason` / summaryNote 文案改为根文档口径。
- **`confirmScopeForRun`**（人工确认候选范围，唯一口径）：根第一层文档跳过，不进入 attributed / uncertain / excluded——确认闭环的授权补交不再把根文档当候选（既不自动提交也不要求人工逐项排除）；根文档由人工 / 发布文档流程处理。测试 / 业务 / 条目文档 / 板级共享候选口径不变（条目文档按 007 之前的口径回归 attributed）。

### 2. `scripts/lib/confirm-store.mjs`

`commitIncompleteReason` 的 `skipped + ignoredDocs → 完整`分支保留（逻辑不变），注释同步为新语义：仅根目录文档差异被忽略的跳过是预期完整收口（根文档不随收口提交，人工 / 发布文档流程处理），不挂起。

### 3. `scripts/lib/manual-closeout.mjs`

## 风险与边界

- **根文档改动不再触发暂扣**：run-20260923-356 类场景直接完成收口；根文档差异保留工作区由人工 / 发布文档流程处理（正是需求要点）。反向风险：根文档被误改时系统不再拦（其不再出现在确认候选），由人工在发布文档审核轮把关——与「根文档不归收口管」口径一致。
- **`ignoredDocs` 语义迁移**：消费方（batch 回执、confirm-store、明细账本）字段名与结构不变，仅内容来源从条目目录变为根第一层文档；既有 UI 无引用（已核）。
- **重命名目标为根文档**（如 `git mv` 板内文件到根 `README.md`）：按根文档忽略，搬移对不自动提交、保留现场由人工处理（罕见边界，如实记录）。
- **历史暂扣单（run-20260923-356）**（README 待确认项 5）：不破坏既有留痕——已挂起「待人工确认提交」的运行，重试入口仍指向确认闭环（`retryAutoCommit` 拒绝直接提交），本单不改该链路；其确认补交按旧留痕现场执行。
- **板级共享 / test / 业务归因不变**：BUG-20260913-006 快照差集口径、迁移搬移 R 码收纳、其他条目排除均维持。

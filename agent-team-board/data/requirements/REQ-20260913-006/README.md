# REQ-20260913-006 版本计划 AI 完善界面支持针对 AI 完善的标题和文本进行修改后再保存

- 状态：accepted（已接受，文档完善中）
- 创建：2026-09-13T15:58:09.610Z

## 描述

构建模块（REQ-20260913-001）版本计划的「AI 完善」弹窗（BUG-20260913-004 更名并定为同一弹窗两段式）目前是「复制提示词 → 粘贴回答 → 解析并预览 → 应用」的直线流程：解析成功后预览区以**只读文本**展示「名称：旧值 → 新值」「描述：旧值 → 新值」，点「应用」即把解析结果原样写入版本名称与描述。用户对 AI 给出的标题或文本只能全盘接受或整体放弃（放弃后要关弹窗、走详情区行内编辑、再重开弹窗），没有「采纳大方向、微调措辞」的中间地带；而 AI 生成的版本名称与描述恰恰经常需要人工润色。

本需求为「AI 完善」弹窗的回填环节增加编辑能力：解析成功后，预览区从只读文本改为**可编辑表单**——版本名称（标题）与版本描述（文本）分别以输入框 / 文本域呈现并预填解析结果，用户可直接修改，点「应用」保存的是**修改后的值**。交互在既有弹窗内闭环完成，不新增入口、不改变提示词生成与回答解析口径，也不改变应用成功 / 失败的既有反馈。

## 已核实的现状与范围

以下均对照当前代码核实（2026-09-13）：

- **弹窗结构**（`scripts/web/build.js` `renderAnswerModal`）：`rel-modal` 弹窗标题「AI 完善（BLD-…）」，上段提示词框（只读 textarea + 「复制提示词」+ BUG-20260913-005 的「去新建 XX 会话」入口），下段回答输入框 + 「解析并预览」；底部「关闭 / 解析并预览 / 应用」三键。
- **解析口径**（`scripts/web/build.js` `parseAnswer`）：以「版本名称：」「版本描述：」起行解析（名称必含、描述可空），失败保留原文可重试；该函数已作为纯函数导出供测试复用，本需求不改变解析规则。
- **预览与应用**（`parseAnswerPreview` / `applyParsed`）：解析成功后预览区是只读 `<div class="bld-preview">`（旧值 → 新值纯文本对照）；「应用」直接调 `saveInfo(verId, { name: parsed.name, description: parsed.description })` → `POST /api/build/version/save`，中间没有任何编辑机会。
- **保存与校验**（`scripts/lib/build-store.mjs` `saveInfo`）：名称不能为空（报「版本名称不能为空」）、描述允许为空；merging / merged 状态锁定不可保存（`assertEditableStatus`）。
- **反馈口径**：成功关弹窗 + toast「✓ 已应用回填：版本名称与描述已更新」；失败 toast「✕ 保存失败：<原因>」、弹窗保留可重试；Esc 与「关闭」均可退出弹窗（不保存）。
- **入口锁定**：merging 状态版本卡片的「AI 完善」按钮禁用（title「合并中，请稍候……」）。
- **可复用交互范式**：详情区行内编辑（名称单行输入 / 描述多行文本域 + 保存 / 取消）已存在，编辑表单控件形态可直接对齐。

## 界面布局

- 「AI 完善」弹窗整体结构不变：仍为上段提示词、下段回答的两段式；变化集中在下段解析结果区。
- 解析成功后，「Agent 回答」输入框下方原只读预览区（`.bld-preview`）改为编辑表单：
  - 「版本名称」：单行输入框，预填解析出的名称；上方以 muted 小字展示当前值（旧值）作对照，保留「旧值 → 新值」语境。
  - 「版本描述」：多行文本域（约 3–4 行），预填解析出的描述；同样在上方展示当前值对照。
  - 表单标题或引导语注明「解析结果可直接修改，点应用保存修改后的值」。
- 弹窗底部仍为「关闭 / 解析并预览 / 应用」三键；「应用」保持主按钮样式，可编辑态下不因内容修改而变灰（名称非空即可用）。
- 弹窗宽度、深浅色与既有 `rel-modal` 一致；窄屏（≤960px）下表单字段纵向堆叠，不改弹窗内部横向布局。

## 交互行为

- 既有流程不变：复制提示词 → 去 Agent 会话 → 粘贴回答 → 「解析并预览」。解析失败路径不变（错误提示 + 原文保留可重试，不出编辑表单）。
- 解析成功：出编辑表单，名称与描述预填解析值；用户可像编辑普通文本一样修改（含清空描述、调整换行）。
- 「应用」：保存**编辑后**的名称与描述（不再直接使用解析原值）；保存期间「应用」「解析并预览」禁用防重复触发。
- 名称被清空：编辑表单下即时提示「版本名称不能为空」，「应用」禁用（title 说明原因）；数据层校验兜底双保险。
- 重新「解析并预览」（回答文本更新后）：以最新解析结果重新预填编辑表单，覆盖未保存的手工修改——回答原文是唯一解析来源，避免两处编辑互相覆盖产生歧义。
- 「关闭」、Esc 或弹窗外点击：退出弹窗，编辑中的内容与回答原文一并丢弃，不产生任何保存。
- 应用成功：弹窗关闭，左侧版本卡片与右侧详情即时反映修改后的名称与描述；应用失败：弹窗与编辑内容保留，可修改后重试。
- merging / merged 状态的保存锁定由数据层既有逻辑保证；merging 版本的「AI 完善」入口禁用口径不变。

## 状态反馈

- 解析成功：编辑表单出现，名称 / 描述预填解析值，旁边有当前值对照；无额外 toast（与现状一致）。
- 名称空：表单内即时错误提示「版本名称不能为空」，「应用」禁用。
- 应用进行中：「应用」显示进行中状态并禁用（防重复提交），弹窗保持展示。
- 应用成功：toast「✓ 已应用回填：版本名称与描述已更新」，列表与详情同步更新。
- 应用失败：toast「✕ 保存失败：<原因>」（错误样式），弹窗与编辑内容保留，可重试。
- 解析失败：既有错误提示不变（不出编辑表单，原文保留可重试）。
- 空态 / 加载失败：版本列表为空或加载失败时本就没有可操作的版本，「AI 完善」入口随列表一起不可用（模块既有空态 / 错误态不变）。

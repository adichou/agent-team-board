# 测试用例 — REQ-20260913-006 版本计划 AI 完善界面支持针对 AI 完善的标题和文本进行修改后再保存

> TDD 流程：先在这里列出用例并跑红，再实现代码跑绿。

| # | 用例 | 优先级 | 结果 |
| -- | ---- | ------ | ---- |
| E1 | 解析成功出编辑表单：引导语「解析结果可直接修改」；名称单行输入 / 描述多行文本域预填解析值；label 以 muted「当前：<旧值>」对照；旧只读「旧值 → 新值」样式不再出现 | 高 | ✅ |
| E2 | 编辑后应用保存编辑值：改名称 / 描述后点「应用」，`POST /api/build/version/save` 收到编辑后的值；未修改直接应用则保存解析原值（行为与现状一致）；描述编辑为空可成功保存；成功关弹窗 + toast「✓ 已应用回填：版本名称与描述已更新」 | 高 | ✅ |
| E3 | 名称空拒绝应用：解析出空名称（或清空输入）→ 表单内即时提示「版本名称不能为空」、「应用」禁用带 title；此状态点「应用」不发保存请求；改回非空即时恢复可用并可成功应用 | 高 | ✅ |
| E4 | 重新解析覆盖未保存修改：编辑后更新回答原文再「解析并预览」，以最新解析结果重新预填，手工修改被覆盖；解析失败路径不变（错误提示、原文保留、不出编辑表单） | 高 | ✅ |
| E5 | 应用失败保留可重试：保存接口报错 → toast「✕ 保存失败：<原因>」，弹窗与编辑内容保留、按钮恢复可点，修改后重试成功 | 高 | ✅ |
| E6 | 应用进行中防重复：「应用」「解析并预览」禁用，「应用」显示进行中状态；完成后恢复 | 中 | ✅ |
| E7 | 后台重渲染不丢编辑：弹窗打开且已编辑时触发其他重渲染（如复制提示词），编辑值与回答草稿保留 | 中 | ✅ |

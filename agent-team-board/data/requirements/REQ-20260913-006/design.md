# 设计 — REQ-20260913-006 版本计划 AI 完善界面支持针对 AI 完善的标题和文本进行修改后再保存

> 由 Agent 在 /dev 开发前补充，人可随时批注。

## 背景

构建模块「AI 完善」弹窗（REQ-20260913-001 建立、BUG-20260913-004 更名两段式）解析成功后以只读
`bld-preview` 展示「旧值 → 新值」，点「应用」把解析结果原样写入版本名称与描述——用户只能全盘接受
或整体放弃。AI 生成的名称 / 描述常需人工润色，本需求为回填环节补上「采纳大方向、微调措辞」的中间地带：
解析成功后预览区改可编辑表单，「应用」保存编辑后的值。

## 方案

纯前端单文件增量（`scripts/web/build.js` + `scripts/web/style.css`），数据层 / 服务端 / 接口契约不变，
`buildPrompt` / `parseAnswer` 口径不动：

- **状态**：`state.answer` 增加 `draft: { name, description }`——解析成功时以解析结果预填；它是编辑表单
  的唯一事实来源（渲染取值、应用取值都读它）。
- **渲染**（`renderAnswerModal`）：`a.parsed` 时原只读预览区渲染为编辑表单（`.bld-preview.bld-edit-form`）：
  引导语「解析结果可直接修改，点「应用」保存修改后的值」；名称单行输入（`.bld-name-edit`）/ 描述多行
  文本域（`.bld-desc-edit`）预填 `draft` 值，label 以 muted「当前：<旧值>」保留对照语境；名称空时表单内
  显 `rel-form-err`「版本名称不能为空」（hidden 类切换）、「应用」禁用带同文案 title、busy 时显示
  「应用中…」并禁用双键。控件复用既有 `.field` 输入样式，CSS 仅收紧表单内边距（窄屏随弹窗纵向堆叠）。
- **编辑同步**：`syncAnswerDraft` 从只同步回答原文扩展为同时把两个编辑框当前值写回 `a.draft`，调用点为
  ①`render()` 重渲染前（新增守卫：已渲染且弹窗打开时，防宿主探测刷新 / 复制提示词 / 应用失败重试等后台
  重渲染冲掉未保存输入）；②`applyParsed` 应用前（以编辑框当前值为准）；③输入即时校验。解析路径调
  `render(false)` 跳过回同步——回答原文是唯一解析来源，重新解析以最新结果预填并覆盖未保存的手工修改。
- **即时校验**（`onAnswerEditInput`，input 事件绑定）：名称 trim 为空即显错误 + 禁用「应用」（title 说明），
  只改错误显隐与按钮态、不整页重渲染（保输入焦点）；改回非空即时恢复。`applyParsed` 再兜底：名称空直接
  return 不发请求，数据层 `saveInfo`「版本名称不能为空」校验双保险。
- **应用**：`applyParsed` 保存 `draft` 值（未修改时即解析原值，行为与现状一致）；沿用既有
  `POST /api/build/version/save` → 成功关弹窗 + toast「✓ 已应用回填：…」/ 失败 toast
  「✕ 保存失败：<原因>」、弹窗与编辑内容保留可重试。顺带把 `saveInfo` 失败 toast 补上错误样式
  （isErr，与模块 ✕=失败口径一致，行内编辑同样受益）。
- 关闭 / Esc 丢弃一切（既有行为）；merging 入口禁用与 merging / merged 保存锁定均由既有逻辑保证。

**开源选型（REQ-20260909-015）**：自研。原生化输入框 + 既有 rel-modal / .field / toast 范式即可覆盖，
无合适开源库（也无引入必要），未新增依赖、不创建 licenses.md。

## 风险与边界

- 「重新解析覆盖未保存修改」是有意口径（回答原文是唯一解析来源），表单引导语已提示；避免两处编辑源
  互相覆盖产生歧义。
- 编辑即时校验只拦空名称；名称 / 描述长度上限等仍由数据层 `validateInfo` 统一裁定，前端不重复实现。
- 假 DOM 测试无法从 innerHTML 还原控件值：用例需先按渲染预填值落到输入节点再模拟用户改动（测试内已注明）。
- `parseAnswer` 对「版本名称：」后紧跟换行的捕获会吞行（`\s*` 贪婪），空名称场景需名称行居末——
  纯函数口径本需求不动，仅测试取材时规避。

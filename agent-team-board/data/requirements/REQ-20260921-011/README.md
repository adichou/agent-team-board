# REQ-20260921-011 发布模块的文档预览要支持 Markdown 格式预览

- 状态：submitted（待人工接受）
- 创建：2026-09-21T02:07:58.086Z

## 描述

### 现状与缺口

发布模块五步流程第 3 步「文档编写」（REQ-20260921-008）的编辑入口收敛在「审查」对话框：按文档类型四页签（README / CHANGELOG / FEATURES / AGENTS），页签内中英双栏并排（`README.md`（中）与 `README.en.md`（英）等八个文件），每栏独立「编辑 / 预览」切换、保存、通过审核，双栏按比例同步滚动。

缺口在**预览态**：当前实现直接把 Markdown 源文本放进等宽 `<pre>`（`scripts/web/build.js` 审查对话框渲染，预览态分支），审查者看到的是 `#`、`|---|`、`**` 等标记符号而非排版效果。八个发布文档全部是 Markdown，人工审查「总结 → 审查 → 提交」时需要所见即所得，拿源码当预览增加了阅读成本。

**目标**：审查对话框每栏「预览」态把 Markdown 渲染为富文本（标题 / 列表 / 表格 / 引用 / 链接 / 代码块等 GFM 常用元素）；「编辑」态保持源码 textarea 不变（编辑必须面对源码）。其余交互（页签切换、保存、通过审核、双栏同步滚动、关闭）不回归。

### 开源库调研与建议（对应描述第 1 点）

候选对比（浏览器端 Markdown → HTML 渲染，均在 REQ-20260909-015 License 白名单内）：

| 候选 | License | 现状与特点 | 评估 |
| ---- | ------- | ---------- | ---- |
| **marked v12.0.2** | MIT | **本仓库已 vendor**（`scripts/web/marked.min.js`，`index.html` 已加载）；`app.js` / `req-disc.js` / `oncall.js` 三处模块已有 `renderMd()`（`sanitizeHtml` + `marked.parse`，异常回落 `<pre>`）先例；社区口径为速度最快、轻量、GFM 开箱；输出非默认安全，需自行消毒——仓库已有 `sanitizeHtml` 兜底口径 | **推荐：直接复用，零新增依赖**，与既有三处渲染口径一致 |
| markdown-it | MIT | 社区活跃；100% CommonMark、默认更安全、插件体系丰富；体量大于 marked | 合格备选。但需新 vendor 一个库，与仓库现有三处 marked 用法割裂；本场景渲染的是自己仓库、经人工审查的文档，安全性收益有限 |
| remark / unified | MIT | AST 变换能力最强（MDX / lint / 插件生态）；较慢、学习曲线陡 | 对「纯预览渲染」过重，排除 |

**建议结论**：复用仓库既有 marked v12.0.2 + `sanitizeHtml` 消毒（即现有 `renderMd` 口径）即可满足需求，不新增第三方依赖；若开发阶段论证后改用其他库（如 markdown-it），须按 REQ-20260909-015 在条目目录维护 licenses.md 并在 design.md 记录对比结论。

**待确认**：预览态的围栏代码块是否需要 highlight.js 语法高亮（`highlight.min.js` 与 GitHub 深/浅主题 CSS 已在页面加载，但既有 `renderMd` 渲染态未对 code 元素做高亮）。默认按先例不做、仅样式化代码块；如需高亮在 design.md 明确。

## 界面布局

- 审查对话框整体结构不变：头部（标题「审查发布文档（版本 ID）」+ 关闭）→ 类型页签行（README / CHANGELOG / FEATURES / AGENTS，各带「已审核 n/2」计数）→ 中英双栏并排 → 底部说明与关闭。
- 变化仅在每栏内容体的**预览态**：由等宽字体纯文本 `<pre>` 变为渲染后的富文本容器（沿用看板既有 `.md` 富文本排版：标题层级、列表缩进、表格边框、引用竖线、行内/围栏代码底色），深浅色跟随系统外观。
- 每栏头部不变：文件名（中/英）、四态徽标、「编辑 / 预览」切换、保存、「通过审核」按钮。
- 空文档在预览态显示「（空文档）」占位，不渲染空白区。

## 交互行为

- 每栏「编辑 / 预览」切换保留：编辑态是源码 textarea，预览态渲染当前内容为 Markdown 富文本；切换即反映最新内容（含未保存草稿）。
- 双栏同步滚动按比例跟随，在「预览-预览」「编辑-预览」「编辑-编辑」组合下均生效（预览态渲染容器需纳入同步滚动绑定）。
- 页签切换、保存（已审核文件编辑保存后回退「已总结待审核」需重新审查）、「通过审核」（四态徽标与各处 n/2、门禁计数联动）、Esc / 关闭对话框等既有交互全部保留不回归。
- 预览为纯展示：不在渲染态直接改字（改字走编辑态 → 保存）。

## 状态反馈

- 读取中：内容体显示「正在读取文档内容…」（现状口径）。
- 空文档：预览态显示「（空文档）」占位。
- 读取失败：toast 报错（现状口径），栏内容置空不阻塞另一栏。
- 渲染异常：渲染器抛错时回退为纯文本源码展示（既有 `renderMd` 的 catch 回落 `<pre>` 口径），不白屏不崩溃。
- 保存 / 通过审核 / 审核回退的 toast 反馈与门禁条计数沿用现状。

## 验收标准

- [ ] 审查对话框每栏「预览」态将 Markdown 渲染为富文本：标题、有序/无序列表、GFM 表格、引用、链接、行内代码、围栏代码块、粗体/斜体等常用元素正确显示；「编辑」态保持源码 textarea 不变。
- [ ] 渲染前对输出 HTML 消毒（沿用 `sanitizeHtml` 或等效口径）：`<script>` 与 `on*` 内联事件不得进入预览 DOM；渲染器抛错时回退纯文本展示，不白屏。
- [ ] 复用仓库既有 marked v12.0.2，不新增第三方依赖；若改用其他库，在 design.md 记录对比结论并维护条目 licenses.md（REQ-20260909-015 白名单口径）。
- [ ] 双栏同步滚动在「预览-预览」「编辑-预览」「编辑-编辑」组合下按比例跟随不失效；页签切换、保存、通过审核、审核回退、Esc 关闭等既有交互不回归。
- [ ] 空文档、读取中、读取失败、渲染异常回退四类状态有明确反馈，口径与现状一致或更优。
- [ ] 预览排版深/浅色外观均正常；界面文案中英文同步（`scripts/web/i18n.js`，BUG-20260912-001 口径），i18n 相关测试通过。
- [ ] 围栏代码块是否启用语法高亮有明确结论（默认不做，见「待确认」；做则在 design.md 记录）。
- [ ] TDD：新增测试先行跑红后跑绿，交付前 `npm test` 全量通过。

## 2026-09-21 实施前排查与待决范围

已认领，尚未修改源码。`renderHolds()` 的隐藏、空清单、错误分支确实清空或替换 DOM，却保留签名和 `dataset.rendered`；建议在这些非卡片分支重置已渲染标记，保留正常卡片分支剪枝，不增加即时渲染或改变轮询周期。此为少量既有状态修正，引入库成本高于直接修复，不引入依赖。

按验收标准排查 `renderConfirmArea()`，发现可复现同类问题：使用 Node VM 执行从实际 app.js 提取的原函数，依次传入 waiting 条目 → 空清单 → 完全相同 waiting 条目，首轮卡片存在，恢复后卡片不存在，dataset.rendered 仍为 1。任务模块切换本身没有与 renderHolds 相同的视图隐藏分支，但清单清空再恢复足以触发同根因。

复现输出：`{"firstRendered":true,"restoredAfterEmpty":false,"staleRendered":"1"}`。

README 验收明确规定此同型缺陷「修复纳入或另行登记由人工确认（范围待确认）」。因此提交范围决策：建议本单同时修复两个渲染函数的失效标记并分别增加行为回归；若选择仅修需求页，则把任务页缺陷另行登记。等待人工补决策和复工，未代替人工选定范围，未开始代码实现或宣称测试通过。

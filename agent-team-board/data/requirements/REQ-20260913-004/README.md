# REQ-20260913-004 支持版本删除

- 状态：accepted（已接受，文档完善中）
- 创建：2026-09-13T15:28:41.856Z

## 描述

构建模块（REQ-20260913-001）的版本计划目前只能创建、编辑与合并，没有任何删除能力：版本计划一旦创建（含误建的草稿、已放弃的失败版本、以及早已合并完成的历史版本）就会永久留在版本列表里，无法清理。数据层 `scripts/lib/build-store.mjs` 无删除函数，服务端 `/api/build/*` 无删除端点，前端版本卡片也只有「AI 完善」「合并入 main」两个操作。

本需求为构建模块的版本计划增加「删除版本」能力：用户从左侧版本卡片发起删除，经确认弹窗显式授权后，把该版本的落盘数据（`<dataDir>/builds/versions/BLD-YYYYMMDD-NNN/` 整目录）从看板移除。删除是看板数据层面的清理，语义按版本状态区分：

- **draft（计划中）/ failed（失败）**：删除即放弃该版本计划，关联条目与 commit 关联一并移除；条目本身（需求单 / Bug 单）与提交不受影响，可随后重新纳入其他版本。
- **merged（已合并）**：删除仅移除看板上的版本记录；提交已实际合并入 main，代码与 git 历史不受影响。确认弹窗须明确提示这一点。
- **merging（合并中）**：禁止删除。合并正在执行，删除会破坏状态机；须等合并结束（置 merged / failed）后再删。

删除遵循项目既有破坏性操作口径（对齐批次删除 REQ-20260907-013、待接受条目删除 REQ-20260908-003）：显式确认后执行、整目录移除、不可恢复、失败有明确报错。

## 已核实的现状与范围

以下均对照当前代码核实（2026-09-13）：

- **版本数据与状态机**（`scripts/lib/build-store.mjs`）：版本计划落盘 `<dataDir>/builds/versions/BLD-YYYYMMDD-NNN/version.json`；状态机 draft（计划中）→ merging（合并中）→ merged（已合并）/ failed（失败，可重试回 merging）；列表按创建时间倒序（`listVersions`）。该文件当前没有任何删除版本的函数。
- **服务端**（`scripts/server.mjs`）：`/api/build/*` 路由（state / candidates / branches / branch-log / version / version/save / version/items / version/merge / fetch / push）均无删除端点；变更一律 POST + JSON。
- **前端**（`scripts/web/build.js`）：版本列表每张卡片（`.rel-card`）操作区 `card-acts` 目前仅「AI 完善」「合并入 main」两个按钮（BUG-20260913-004 已把版本操作从详情底部迁入卡片，详情 `renderDetail` 不再重复渲染操作区）；删除入口按同口径放在卡片操作区。合并执行中前端 `mergeBusy` 为全局口径（禁用所有卡片的合并键），删除键沿用同口径，避免删除正在合并的版本。
- **可复用范式**：确认弹窗沿用本模块 `rel-modal`（合并确认 `renderMergeConfirm`、推送确认 `renderPushConfirm`：标题 + 正文说明 + 「取消 / 确认」双键）；成功 / 失败反馈沿用 toast 口径（`✓ …` / `✕ …`，`isErr` 走错误样式）；选中版本失效回落已有既有逻辑（选中版本不存在时取列表最新，无版本时显示空态）——删除当前选中版本后直接复用。
- **破坏性删除先例**：`POST /api/batch/delete`（`scripts/lib/batch.mjs` `deleteBatch`，整目录 `fs.rmSync`，在途执行拒绝删除）。

## 界面布局

- 版本计划子页签布局不变：左侧版本列表 + 右侧选中版本详情（宽屏左右分栏，窄屏 ≤960px 上下排列）。
- 左侧每张版本卡片的操作区（`card-acts`）在「AI 完善」「合并入 main」之后新增第三个按钮「删除」：quiet / 危险弱化样式（不抢主操作），与其他两键同行排列；merging 卡片该键禁用。
- 确认弹窗沿用构建模块既有 `rel-modal` 居中弹窗：标题「删除版本（BLD-YYYYMMDD-NNN）」；正文列出版本名称、状态、关联单数，并按状态给出不可恢复提示（draft/failed：删除后不可恢复，条目可重新纳入其他版本；merged：仅删除看板版本记录，不影响已合并入 main 的提交与代码）；底部「取消 / 确认删除」双键，确认键为危险主样式。
- 删除后左侧列表即时移除该卡片；被删版本若是当前选中版本，右侧详情按既有回落规则取列表最新版本，列表为空时显示「暂无版本计划：点右上「＋ 新建版本」从需求单 / Bug 单创建」空态，详情区显示「点击左侧版本查看详情」。

## 交互行为

- 点击版本卡片「删除」：打开确认弹窗（弹窗打开期间列表不可再触发其他删除）。
- 弹窗内「取消」、点击遮罩或关闭键：关闭弹窗，不做任何改动。
- 弹窗内「确认删除」：按钮进入禁用（防重复触发），调用删除接口；期间弹窗保持展示。
- 服务端校验（与前端禁用双保险）：版本不存在报「找不到版本计划：BLD-…」；merging 状态抛冲突错误（409）「版本合并中，不可删除，请等合并结束后再删」。
- 删除成功：关闭弹窗、刷新版本列表、toast 成功反馈；被删版本为当前选中时详情回落。
- 搜索过滤下删除同样即时生效：被删卡片从过滤结果中消失；若过滤后列表为空，显示「没有匹配的版本（按名称 / 单号过滤）」。
- 合并执行中（`mergeBusy`）：所有卡片的「删除」与「合并入 main」一并禁用（title 提示「合并中，请勿重复触发」同口径）。

## 状态反馈

- 成功：toast「✓ 已删除版本（BLD-YYYYMMDD-NNN）」，列表与详情同步更新。
- 失败：toast「✕ 删除失败：<原因>」（错误样式），弹窗关闭、数据保持原状，版本仍留在列表中。
- merging 卡片：「删除」禁用，title 提示「合并中，不可删除」。
- 确认弹窗执行中：「确认删除」禁用并显示进行中状态，防重复提交。
- 空态：删除最后一个版本后，左侧显示「暂无版本计划：点右上「＋ 新建版本」从需求单 / Bug 单创建」，右侧详情回落「点击左侧版本查看详情」。

## 验收标准

- [ ] 数据层（`scripts/lib/build-store.mjs`）提供删除版本的函数（如 `deleteVersion`）：按编号读取版本，成功后整目录移除 `<dataDir>/builds/versions/BLD-YYYYMMDD-NNN/`，`listVersions` 不再返回该版本；版本不存在时报「找不到版本计划：<id>」。
- [ ] merging 状态禁止删除：数据层抛 `BuildConflictError`（HTTP 409），错误文案说明「合并中不可删除，请等合并结束后再删」；draft / failed / merged 状态均可删除。
- [ ] 服务端提供删除端点（如 `POST /api/build/version/delete`，对齐 `/api/batch/delete` 的 POST + JSON 范式）：透传数据层结果与错误；响应含删除后的最新版本状态（或由前端删除后统一刷新）。
- [ ] 前端版本卡片操作区新增「删除」按钮：与「AI 完善」「合并入 main」同行；merging 卡片禁用并带 title 提示；`mergeBusy` 期间所有卡片删除键禁用。
- [ ] 删除必经确认弹窗：标题含版本编号，正文列出版本名称、状态、关联单数；draft/failed 提示「删除后不可恢复，条目可重新纳入其他版本」；merged 额外提示「仅删除看板版本记录，不影响已合并入 main 的提交与代码」；「取消」不产生任何改动。
- [ ] 删除成功：toast「✓ 已删除版本（<id>）」，卡片从列表移除；被删版本为选中版本时详情回落列表最新版本；列表为空时显示既有空态文案；搜索过滤下同样即时生效。
- [ ] 删除失败：toast「✕ 删除失败：<原因>」（错误样式），版本保留在列表中，可重试。
- [ ] 确认删除执行期间「确认删除」按钮禁用，不产生重复删除请求。
- [ ] 现有测试全部通过；新增覆盖数据层删除函数（成功 / 找不到 / merging 拒绝）的单元测试，先红后绿。

# REQ-20260922-004 AI 分析要支持并行子代理模式，可同时最多展开 3 个子代理认领需求分析

- 状态：submitted（待人工接受）
- 创建：2026-09-22T04:18:02.057Z

## 描述

### 背景与现状

「AI 分析」（批量完善，refine 批次）对已接受未完善条目批量补全文档。当前执行链路为**严格串行**：

- 主调度提示词（`scripts/lib/refine-store.mjs` 的 `buildRefinePrompt`）中写明约束行：「每个子代理只做一项；**同一时间只运行一个**；不要让子代理再派发子代理」。主会话每轮只派一个子代理，收到回执并 `atb refine check` 核对后才派下一个。
- `nextRefineItem` 在存在未终态的当前运行（`batch.currentRunId` 指向的运行未到终态）时直接抛错「当前执行未收尾……不得创建第二个完善执行」，领取互斥由全局单锁 `runtime/.locks/refine.lock` 保证。
- `checkRefineBatch` 的核对协议只有单条 `current`，任一在途即返回 `nextAction=needs_attention`（「当前执行未收尾，等待子 Agent 回执后核对」）。
- 任务页 AI 分析面板（`scripts/web/app.js` 的 `renderRefinePanel`）概况区按**单个**当前项展示「当前条目 / 子代理会话 / 开始时间 / 耗时」，统计行「进行中」恒为 0 或 1。
- codex 后台执行器（`scripts/server.mjs` 的 refineRunners）项目内并发 1，逐项串行队列。

串行口径下，每个子代理的执行时间（读代码、写文档、做 ui-demo.html）远长于核对耗时，队列较长时整轮 AI 分析墙钟时间随条目数线性增长，吞吐有明确提升空间。

### 目标

AI 分析的**子代理模式**支持并行：主调度会话可同时展开**最多 3 个**子代理，各自领取**不同**条目做文档完善；每个子代理仍只做一项、不再派发子代理，领取/回执/check 协议与文档补全口径不变。

### 改动范围

1. **主调度提示词**（`buildRefinePrompt`）：移除「同一时间只运行一个」串行约束，改为并行调度口径——同时最多 3 个子代理在途，任一回执后核对（`refine check`），在途不足 3 且队列有余即补派下一项；队列取空即本轮结束。子代理仍不得再派发子代理。提示词缓存口径（REQ-20260921-006「静态段在前 + 尾部运行参数区」）应尽量保持。
2. **领取与互斥**（`nextRefineItem` / refine.lock）：在途运行 < 3 且队列有候选时允许领取新条目；同一时间一个条目仍只有一个执行者（不得两子代理领到同一单）；在途已达 3 时给出明确提示（等待回执，而非报错中断）。互斥粒度按需从「全局单锁」调整为支持多在途的形态（如按条目互斥 + 在途槽位上限），旧锁语义迁移不得造成存量账本误判。
3. **回执与核对**（`finishRefineRun` / `checkRefineBatch`）：done / fail / release / hold 任一回执只结算对应运行，不影响其他在途；核对协议需表达多在途（如 `current` 扩展为在途列表或新增聚合字段），`nextAction` 语义按「在途 < 3 且队列有余 → continue（补派）；队列取空且在途清零 → stop」调整；响应仍受 ≤2 KiB 上限约束。
4. **任务页 AI 分析面板**（`scripts/web/app.js` `renderRefinePanel`，涉及 UI，见下节）：概况区从单条「当前条目」扩展为**在途运行列表**（最多 3 项：条目编号、子代理会话、开始时间、已用时），统计行「进行中」为实际在途数；待完善队列、处理记录、提示词页签与三态徽标（未完善 / 完善中 / 已完善，`scripts/lib/refine-states.mjs` 按条目记录、天然支持多在途）不回归。相关界面文案在 `scripts/web/i18n.js` 中英文同步（BUG-20260912-001）。
5. **暂停 / 终止 / 挂起在并行下的口径**：沿用现有语义并明确适配——「暂停后续领取」只停新派发，在途继续执行完；「终止任务」剩余项出局、在途子代理仍需在对应会话人工停止；「待人工确认分析」（hold）声明后队列暂停、不派新项，在途不受影响。以上口径在并行 3 路下均需成立。

### 不变项（边界）

- 子代理补全口径不变：只补条目文档（README 描述 + 验收标准；涉及 UI 须含 ui-demo.html 演示）、条目全程保持 accepted、不写业务源码、未知事实标「待确认」。
- 每条目单执行者与「完善中的单不可驳回回待接受」拦截不放宽。
- 同一项目同一时间仍只有一轮完善执行（多轮排队语义不变）。
- 实施互斥（impl.lock）与 AI 开发、AI 总结 / AI 翻译锁互不占用关系不变。

### 待确认

- 并行上限「3」为固定值，还是在设置「批量任务」分区提供可配置项（0/1~3）？默认按固定 3 实施，配置项待人工确认。
- codex 后台执行器（当前项目内并发 1）是否同步并行化，还是本单仅覆盖子代理（主会话派发）模式？默认仅子代理模式，codex 执行器维持并发 1，待人工确认。
- 存量进行中任务（按旧串行提示词启动）升级后的兼容口径：按新领取逻辑继续即可，还是需要迁移提示词？默认兼容续跑，待人工确认。

## 界面（任务页 AI 分析面板）

涉及 UI：概况区由单条「当前条目」扩展为在途运行列表（最多 3），统计与操作反馈随之变化。可交互演示见 [./ui-demo.html](./ui-demo.html)（浏览器直接打开，含「现状串行 / 目标并行」对照开关）。

### 界面布局

- 面板整体结构不变：状态行（任务状态 chip · 执行模式 · 创建时间）→ 通知条（notice / 待人工确认横幅）→ **在途运行区**（并行模式为最多 3 张在途卡片，纵向排列；串行现状为单条 meta 网格）→ 统计行（完成 / 异常 / 进行中 / 剩余 / 总数）→ 操作区（暂停后续领取、终止任务）→ 二级页签（概况 / 队列 / 提示词 / 记录）。
- 每张在途卡片：条目编号（可点击跳条目）+ 标题、子代理会话名（refine-1/2/3…）、开始时间、已用时、单项操作（演示中用于模拟回执）。
- 队列页签：待完善队列（需求优先、最旧优先，条目 + 缺失原因 chips）；记录页签：最近执行记录（结果 / 摘要）。

### 交互行为

- 主会话按提示词派子代理：串行现状下一轮仅 1 个在途、须等回执核对后再派；并行目标下可同时派至 3 个，任一回执 + `refine check` 核对后在途不足 3 且队列有余即补派。
- 暂停后续领取 / 恢复：只控制新派发；终止任务：剩余项出局并提示「在途子代理请在对应子代理会话人工停止」；终止后可「启动新一轮」。
- 子代理回执：done（核验文档确有变更后记账）/ fail / release / hold（挂起待人工确认，队列暂停）。
- 在途卡片点击条目编号跳转条目详情（演示中以提示代替）。

### 状态反馈

- 正常：多在途并行推进，统计行「进行中 = 实际在途数（≤3）」，每张卡片实时显示已用时；回执后记录页签新增条目、队列与统计即时更新。
- 空态：无进行中任务时显示启动区（候选 0 项时禁用「启动」并说明）；本轮结束显示绿色收尾 notice。
- 加载：面板数据随主轮询刷新（演示中模拟「轮询中…」瞬态）。
- 失败：回执 fail / 释放 release 计入异常并在记录中展示原因；领取槽位已满时给「在途已达 3，等待回执」提示（不报错中断）。
- 挂起：出现「待人工确认分析」横幅，队列暂停、不派新项，人工作答确认后续跑。
- 终止 / 暂停：对应 warn / info 通知条常驻，操作按钮随状态禁用与切换。

## 验收标准

- [ ] 主调度提示词不再包含「同一时间只运行一个」串行约束，明确「同时最多 3 个子代理并行、每个只做一项、不再派发子代理；回执核对后在途不足 3 且队列有余即补派」；提示词静态段/尾部参数区结构保持缓存友好口径。
- [ ] `atb refine next`：在途 < 3 且队列有候选时可领取新条目（不同条目，不与在途重复）；在途已达 3 时返回明确的「等待回执」提示而非异常中断；并行下同一时间一个条目只有一个执行者。
- [ ] `atb refine done/fail/release/hold` 任一回执只结算对应运行，其余在途不受影响；done 核验「文档确有变更」口径不变；hold 声明后队列暂停（不派新项），人工确认后续跑。
- [ ] `atb refine check`：在途 < 3 且队列有余 → `nextAction=continue`（可补派）；队列取空且在途清零 → `stop`；核对响应 ≤2 KiB；多在途信息（条目/owner）在协议中可见。
- [ ] 任务页 AI 分析面板概况区展示全部在途运行（≤3：条目编号、子代理会话、开始时间、已用时），统计行「进行中」为实际在途数；队列/记录/提示词页签与三态徽标不回归；并行下「完善中的单不可驳回回待接受」拦截对每个在途条目均生效。
- [ ] 暂停（只停新派发）、终止（剩余出局 + 在途人工停止提示、可启动新一轮）在并行 ≤3 下行为正确。
- [ ] 实际并行度退化为 1（单子代理逐项执行）时，对外行为与现有串行口径一致（兼容旧用法与存量进行中任务续跑）。
- [ ] codex 后台执行器行为不回归（按「待确认」默认维持并发 1；若人工确认需并行化，以补充口径为准）。
- [ ] 界面文案中英文同步（scripts/web/i18n.js），相关测试（scripts/tests/）全量通过。

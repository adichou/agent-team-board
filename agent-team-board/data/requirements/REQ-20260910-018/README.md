# REQ-20260910-018 讨论逐轮持久化、文档资产展示与跨会话续聊

- 状态：accepted（已接受；实际状态以 status.json 为准）
- 创建：2026-09-10T08:15:08.173Z

## 描述

将开放式讨论从收尾时落盘升级为每轮保存用户原文与模型回复总结，维护可追溯的讨论纪要，在 ATB 展示，并支持任意可访问项目文档的 Agent 会话通过同一讨论编号接续。

## 验收标准

- [ ] 启动提示词包含项目位置、讨论编号、文档位置、上下文读取及逐轮保存规则；用户无需发送收尾提示词即可保存和展示交流。
- [ ] 每次用户输入及完整模型回复形成一轮，保存用户原文、模型回复总结、时间与可追溯的轮次标识；补充、纠正也保存，工具调用和进度播报不单独计轮。
- [ ] 回复总结包含关键观点、理由、取舍和未决问题；纪要明确区分已确认共识、模型建议和待讨论问题，不把未确认建议写成共识。
- [ ] 新轮次追加保存，旧记录不被覆盖；结论变化可追溯到对应轮次，纪要可从逐轮记录重新整理。
- [ ] ATB 展示讨论纪要、交流记录、后续行动三个标签；每轮保存后自动更新列表轮数、时间、摘要及详情，无需收尾发布。
- [ ] 任意可访问该项目文档的新会话使用继续讨论提示词后，读取已有上下文并写入同一讨论；不依赖原聊天窗口，不串项目或串讨论。
- [ ] 统一追加入口校验归属、确认保存结果，并防止同轮重试重复和多会话追加覆盖；纪要并发更新不静默丢失他人更新。
- [ ] 写入失败、路径不可访问或归属不符时明确反馈，不能宣称已保存；重试后不重复记录，ATB 不展示半成品轮次。
- [ ] 「整理结论」可更新纪要，且不作为交流保存的前提；归档、继续讨论保留全部历史与成果。
- [ ] 兼容既有讨论背景、纪要、旧问答与已创建条目关联；不伪造旧讨论缺失的逐轮记录。
- [ ] 宽窄屏布局、空态、加载、保存成功与失败反馈按以下约定实现；候选需求/Bug 仍需用户操作才创建。

## 背景与目标

现有开放式讨论通过启动提示词在 Agent 内交流，仅在收到收尾提示词后写入纪要及候选草稿，ATB 再读取发布成果。讨论过程未持续沉淀，新会话也无法仅依靠项目文档恢复完整讨论背景。

本需求将讨论作为独立的项目文档资产：问题与回复总结逐轮持久化，持续维护最新纪要，并支持跨会话接续。讨论不强制关联已有需求。

## 用户原始诉求

1. 讨论的问题和结论都要作为文档资产持久化，并在 ATB 上可以展示。
2. 讨论从一段提示词开始，用户在 Agent 内和模型多轮交流，每轮把用户原始问题和模型回复总结写入文档。
3. 用户可以在任意会话中通过提示词继续交流，模型必须将问题和回复总结写入对应项目文档。

## 文档与记录规则

- 事实源为项目内 `docs/agent-team-board/` 下的讨论资料，随项目保留并可纳入 Git；沿用现有讨论身份与目录兼容关系，具体结构在设计中确定。
- 每轮定义为一次用户输入及其完整模型回复；输入可以是问题、补充、纠正或确认。用户文字原样保存，模型保存忠实总结，不要求保存完整回复或内部推理。
- 每轮包含项目与讨论归属、稳定轮次标识、时间、用户原文、回复总结，并保留可用的来源会话信息。不依赖会话名称判定归属。
- 历史记录只追加，不因新会话、整理纪要、归档或结论改变而覆盖。最新纪要包含背景、已确认共识、模型建议与取舍、未决问题、后续行动，并引用支撑轮次。
- 后续推翻结论时更新当前纪要并注明变更依据，保留旧轮次。每轮检查纪要是否需要更新；无需变化时可保持纪要内容。
- 统一追加记录入口负责归属校验、幂等与并发保护，完整写入后才确认成功。纪要可以从已保存轮次重新整理；纪要更新失败不丢弃已保存的原始轮次，界面提示纪要待更新。

## 主流程与交互行为

1. 用户在 ATB 新建讨论，保存标题和背景，获得携带项目位置、讨论编号、文档位置与记录约定的启动提示词。
2. Agent 接收提示词后先校验目标项目与讨论，读取已有纪要和必要历史，再开始交流。新会话不能仅凭聊天记忆接续；讨论内容过长时先读纪要与近期轮次，按需追溯原文。
3. 每轮生成回复内容后，通过统一入口保存用户原文和回复总结，按需更新纪要，再向用户反馈保存结果。工具执行与进度播报不作为独立轮次。
4. ATB 自动读取已完整保存的轮次与纪要，不要求另发收尾提示词或生成候选需求/Bug。
5. 用户点击「复制继续讨论提示词」，可在任意能访问同一项目文档的 Agent 会话接续；新会话读取文档后追加到同一讨论。
6. 将现有「讨论完毕」改为「整理结论」，生成整理提示词以重新汇总已有轮次和可选候选行动；整理不终止讨论，不触发自动开发或自动创建条目。
7. 保留「讨论中 / 已归档」两种状态。归档保留记录与成果；已归档讨论通过「继续讨论」恢复并提供续聊提示词。

## 界面布局

- 沿用当前讨论模块视觉风格：宽屏左侧列表、右侧详情；窄屏先列表，点选后进入详情，返回保留筛选和滚动位置。
- 列表保留标题、编号、讨论状态，增加已保存轮数、最近更新时间与最新回复摘要；新记录落盘后自动刷新。
- 详情顶部显示标题、编号、状态、最近保存信息，提供启动提示词、复制继续讨论提示词、整理结论、归档/继续讨论操作。复制只代表提示词已复制，不显示 Agent 已连接。
- 「讨论纪要」标签展示背景、当前共识、建议与取舍、未决问题、后续行动及对应轮次引用；引用可定位到交流记录。
- 「交流记录」标签按时间从早到晚展示用户原文、回复总结、时间与轮次，可折叠历史并定位最新轮次；长内容可展开阅读。
- 「后续行动」标签沿用候选需求/Bug 编辑、勾选和人工创建流程，并展示已创建条目的关联。没有候选行动也可以正常保存、查看和归档讨论。

## 状态反馈与异常

- 新讨论空态：显示背景与启动提示词入口，说明尚无已保存交流；有轮次但暂无纪要时提示可整理结论。
- 读取时显示加载反馈；保存成功后展示最新保存时间与轮数；不凭提示词复制或会话回复推断保存成功。
- 项目不可访问、讨论编号不匹配、写入失败时 Agent 明确说明未保存及原因，保留可重试内容。ATB 对可检测的读取或格式错误显示原因和重试入口；无法访问项目的外部会话错误不冒充为看板可感知事件。
- 同轮重试不重复插入，不同会话并发追加不覆盖记录；纪要更新使用版本校验或等价机制，冲突后重新读取并整理。
- ATB 仅读取完整记录，出现失败仍保留此前可用内容。纪要落后于最新轮次时显示待更新反馈。
- 提示词复制成功有明确反馈，剪贴板不可用时提供手动复制方式。

## 界面展示

- **布局**：沿用讨论模块现有骨架（`scripts/web/oncall.js`：宽屏左列表右详情、窄屏先列表点选进详情）。改动面：列表卡片在现状「编号 / 状态 / 阶段提示 / 更新时间」基础上增加已保存轮数与最新回复摘要，新轮落盘后自动刷新；详情操作区由现状「启动提示词 / 讨论完毕 / 归档·继续讨论」调整为「启动提示词 / 复制继续讨论提示词 / 整理结论（原『讨论完毕』）/ 归档·继续讨论」；详情内容按「讨论纪要 / 交流记录 / 后续行动」三标签组织（现状为「概况 / 纪要 / 成果 / 提示词」四页签，见 `oncall.js` `DISC_TABS`；原页签信息的归并方式——概况元信息去向、提示词改由顶部操作承载——**待确认**，design.md 定稿）。
- **交互**：每轮经统一入口保存后，交流记录追加该轮（用户原文、回复总结、时间、稳定轮次标识、来源会话），历史可折叠并定位最新轮次，长内容可展开阅读；纪要条目携带轮次引用，点击定位到交流记录对应轮；「复制继续讨论提示词」后在任意能访问项目文档的新会话续聊，轮次编号接续、来源会话标记切换、不串讨论；「整理结论」弹出整理提示词（重新汇总已有轮次与可选候选行动），整理不终止讨论、不作为交流保存的前提；后续行动沿用候选需求/Bug 勾选、编辑、人工创建与已创建条目跳转流程。
- **状态反馈**：正常——每轮保存后通知条给出最新保存时间与轮数，列表轮数 / 摘要 / 时间自动刷新，无需收尾发布；空——新讨论显示背景与启动提示词入口并说明尚无已保存交流，零候选为正常空态；加载——打开详情与刷新显示「正在读取」反馈；失败——写入失败明确「本轮未保存」及原因并保留可重试内容（重试不产生重复轮次），读取或格式错误显示原因与重试入口，纪要落后于最新轮次时显示「纪要待更新」；深浅色沿用看板 `prefers-color-scheme` 双主题。

可交互演示：[./ui-demo.html](./ui-demo.html)（单文件、无外网依赖、无构建步骤，浏览器直接打开；内置讨论列表与详情三标签，可模拟逐轮保存、写入失败与重试、读取失败与重试、跨会话续聊、整理结论、归档 / 继续讨论、候选草稿勾选创建与新讨论空态，含加载反馈与深浅色切换）。

## 范围与兼容

- 实际多轮对话继续发生在 Agent 会话内，本次不增加看板聊天输入框或常驻 Agent 调度。
- 提示词配合统一写入入口构成记录协议；在支持的 Agent 工作流中验证逐轮调用，不能仅凭提示词宣称任意外部模型均必然执行。
- 不改需求/Bug 状态机，不自动接受、完成或实施条目；需求/Bug 创建继续由用户操作触发。
- 兼容历史纪要、旧问答和已创建成果，不删除历史资产；旧纪要缺少逐轮原文时按历史纪要展示，不补造问答。

# 测试用例 — BUG-20260903-001

现象：抽屉打开后，点击操作按钮（接受/确认完成/驳回）使条目状态流转，导航（上一条/下一条 + i/N）的
过滤条件跟着条目实时状态漂移，从「待接收列表」跳到「已接收列表」。期望：导航范围在打开抽屉时冻结，
状态流转后仍在原列表内浏览。

| # | 用例 | 优先级 | 自动化 |
| - | ---- | ------ | ------ |
| B1 | 打开抽屉时冻结导航范围：`scopeIdsFor` 快照打开时刻的同状态条目序列；之后条目状态流转，`drawerNeighbors` 仍用该快照计算 prev/next 与 i/N，不漂移到新状态列表 | P0 | ✓（静态契约） |
| B2 | prev/next 导航沿用冻结范围（`openDrawer(target.id, true)`），不按目标条目实时状态重算；点卡片、点跳转链接（data-goto）仍按新条目重算范围 | P0 | ✓（静态契约） |
| B3 | 冻结快照中的单号已不存在（被删）时从导航序列剔除，prev/next 不会指向打不开的条目 | P1 | ✓（静态契约） |
| B4 | 范围快照不可得（如打开时看板数据未就绪）时，回退为按实时同状态过滤（原行为兜底） | P1 | ✓（静态契约） |
| B5 | 浏览器实测：待接收 3 条 → 打开第 2 条 → 点「✓ 接受」→ 按钮与左右方向键导航仍访问待接收列表，i/N 显示不跳变 | P0 | 人工 |

# REQ-20260911-010 回退批量 Commit 的相关功能，但需保留已完成需求的 commit 号显示这个功能

- 状态：流程状态以系统维护的 status.json 为准（本单已接受，完善阶段不流转）。
- 创建：2026-09-11T15:33:33.667Z

## 描述

1、因为 REQ-20260911-009 已经支持了自动 commit（开发完进入待测试时由系统自动提交，并建立 commit 与单号的双向索引），人工再逐单归因提交的「批量 Commit」流程就不再需要，本单回退其相关功能。
2、已完成列表中的需求或 bug 需要根据 REQ-20260911-009 的 commit 号和单号关联的索引，显示对应的 commit 号。一个 commit 可以关联多个单号，但是一个单号只能关联一个 commit。

### 已核实的现状（基于当前代码盘点）

批量 Commit 功能由 REQ-20260910-013（CLI 流程）与 BUG-20260910-014（看板 UI）、BUG-20260911-005（已完成档快捷入口）、BUG-20260911-006（全局看板简报）陆续建设，现有组成：

- **CLI 命令组**：`atb commit create / next / done / fail / release / status / runs / check / pause / abort`（`scripts/atb.mjs`），usage 帮助中含「批量 commit」分组说明。
- **数据层**：`scripts/lib/commit-store.mjs`——CMT 批次账本（事实源 `docs/agent-team-board/commits/{settings.json, batches/CMT-YYYYMMDD-NNN/batch.json, runs/<runId>/run.json}`，`.gitignore` 含 `commits/runs/`、`commits/batches/`）、提交规范核验（消息「类型: 描述 单号」、业务/测试分离、条目文档归 doc 类）、幂等判定（`itemCommittedInGit`：git 历史消息含单号）、条目已提交索引 `committedItemIndex`（仅统计 phase=committed 的核验通过运行）。
- **服务端接口**（`scripts/server.mjs`）：`/api/commit/current`、`/api/commit/create`、`/api/commit/pause`、`/api/commit/abort`、`/api/commit/records`、`/api/commit/item-status`（最后一个为已完成条目提交状态徽标的数据源，读 `committedItemIndex`）。
- **看板 UI**（`scripts/web/app.js` 及配套 CSS）：
  - 任务模块「批量 Commit」页签与面板（启动/暂停/终止、主调度提示词复制、执行记录表）；
  - 需求模块「已完成」档列表头的「▶ 开始 Commit」快捷入口（仅导航，与勾选无关）；
  - 全局看板批量任务列表中 CMT- 前缀批次简报行（`commitBatchBrief`）；
  - **已完成条目提交状态徽标**（列表行「未提交 / 已提交 + N 个提交号」可展开、条目详情「提交状态」字段逐个 hash 可复制、加载失败可重试）——本单的**保留对象**。
- hooks（`scripts/state-guard.mjs` 等）目前不拦截 git 命令，与批量 Commit 无耦合授权；REQ-20260911-009 将按「批量开发批次内自动提交视同人工授权」另行更新口径，不依赖本功能存在。
- REQ-20260911-009 当前为 planned（未开发）；其 README 验收标准含「现有人工触发的批量 commit（CMT 批次）流程不回归；与自动 commit 并存时消息规范一致、索引同源」一句，与本单回退方向衔接（见待确认 4）。

### 目标细化（完善阶段口径）

**一、回退批量 Commit 流程（人工触发的批量提交能力整体下线）**

1. 移除 `atb commit *` 命令组与 usage 帮助中的批量 commit 条目；旧命令不可再驱动任何提交。
2. 移除看板「批量 Commit」页签/面板、「已完成」档「▶ 开始 Commit」快捷入口、全局看板 CMT 批次简报行，不留禁用态死控件与空占位。
3. 移除服务端 `/api/commit/current|create|pause|abort|records` 路由；`/api/commit/item-status` 的取数能力随显示功能保留（实现与命名可调整，前端同步，开发阶段定）。
4. `commit-store.mjs` 中 CMT 批次执行流程（创建/领取/回执核验/暂停/终止/排队）不再可达；其中可复用部分（如 `committedItemIndex` 聚合、`itemCommittedInGit` 幂等判定、提交规范常量与核验函数）是否迁移为 REQ-20260911-009 索引/自动提交的底层实现，由开发阶段 design 定（见待确认 3）。
5. 回退只删除本仓库功能代码与界面，**不做任何 git 历史改写**（不 push、不 reset / rebase）；回退改动本身按仓库现行提交规范正常提交（届时已上线 REQ-009 自动 commit 则随流程提交，否则人工提交）。

**二、保留并切换取数：已完成列表的 commit 号显示**

1. 看板中已完成（done）的需求与 Bug 条目保留提交状态显示：列表行徽标（未提交 / 已提交 + 提交号）与条目详情「提交状态」字段（提交号可复制），展示位置与现有布局一致。
2. 数据源从现行 `committedItemIndex`（CMT 批次运行记录聚合）切换为 REQ-20260911-009 建立的 commit 号与单号关联索引。
3. 关联规则按本单原文：**一个 commit 可以关联多个单号，一个单号只能关联一个 commit**（与 REQ-20260911-009 现行「一单多 commit（业务/测试/文档分组）」口径存在矛盾，须以人工确认结论为准，见待确认 1）。
4. 索引无记录、加载失败等场景的状态反馈沿用现有徽标口径（见「状态反馈」节）。

## 界面布局

本单界面改动 = 减法（移除批量 Commit 入口）+ 数据源切换（已完成档徽标取数换源，布局不变）：

- **任务模块页签组**：从「批量完善 / 批量开发 / 批量 Commit」回到「批量完善 / 批量开发」；「批量 Commit」面板整体移除，原页签位不残留空占位或禁用页签。
- **需求模块「已完成」档**：列表头快捷入口区移除「▶ 开始 Commit」（已接受档「开始完善」、已计划档「开始开发」不受影响）；已完成档默认仅列最新 100 项、更早走搜索的现行规则不变。
- **全局看板**：批量任务列表不再出现 CMT- 批次简报行；其余（批量完善/批量开发）简报不受影响。
- **保留部分（已完成条目提交状态显示）**：列表行尾徽标「未提交 / 已提交 + 提交号」，条目详情「提交状态」字段含提交号列表（逐个可复制）；布局与现行一致。按本单关联规则一个单号只关联一个 commit，展示为一个提交号（现行「N 个提交号」多 hash 展开随之取消；若待确认 1 结论为一单多 commit，则维持多提交号展示）。

## 交互行为

1. 已完成条目行点击打开详情、提交号点击复制、（若保留）多提交号展开收起——既有交互不回归；复制后有「已复制」就近反馈。
2. 提交状态数据随主轮询拉取，独立于看板主数据；拉取失败不伪装成「未提交」，点「重试读取」强制重拉。
3. 回退后看板与 CLI 均不再提供任何人工创建/驱动批量提交的入口；本地 git 提交唯一路径为 REQ-20260911-009 的「到待测试自动 commit」，push 仍由人工决定。
4. 被移除的面板、页签、快捷入口不留任何可点击但必然失败的入口，也不以禁用态灰显残留。
5. 本单为代码回退 + 取数切换，不新增弹窗/确认流程；详情、搜索、筛选等看板既有交互不回归。

## 状态反馈

已完成条目提交状态（保留功能的四态）：

- **正常**：索引中有关联 commit → 徽标「已提交」，悬停/展开可见提交号，详情页逐个可复制；一个单号展示其唯一关联的 commit 号。
- **空**：索引尚无该单记录（如刚回退、REQ-009 自动提交尚未产生任何记录）→ 徽标「未提交」；索引整体为空时全部条目显示「未提交」，不报错。
- **加载**：随主轮询拉取期间沿用上一次成功数据，不闪现「未提交」。
- **失败**：取数接口失败 → 徽标位置显示「提交状态加载失败」并提供重试入口；已加载的成功记录保留不消失，重试成功后恢复。

回退部分本身无运行态：移除即消失；若有回退时仍在途的 CMT 批次/运行，其处置口径见待确认 2。

## 待确认

1. **一单一 commit 与 REQ-20260911-009 的口径矛盾**：本单规定「一个单号只能关联一个 commit」，而 REQ-20260911-009 现行 README 按现行提交规范描述为「业务与测试分开、条目文档归 doc 类」的一单多 commit，且其验收标准写「从条目可查该单全部已核验提交」。两者需人工确认取舍：自动提交改为一单一个 commit，或本单索引/展示改为一单多 commit 号。
2. **存量数据与过渡期**：现有 `docs/agent-team-board/commits/` 批次账本、已核验提交记录（当前徽标数据）、`.gitignore` 条目与 `settings.json` 计数器如何处置（保留只读迁移、随回退清理、还是留待 REQ-009 索引接管）；回退后到 REQ-009 上线前的过渡期，已完成列表提交状态显示沿用存量索引还是显示「未提交」。
3. **`commit-store.mjs` 复用边界**：`committedItemIndex` / `itemCommittedInGit` / 提交规范核验（`validateCommitSubject` / `validateItemCommits`）等是否作为 REQ-20260911-009 自动提交与索引的底层实现保留复用，还是随回退整体删除由 009 重建（开发阶段 design 定）。
4. **REQ-20260911-009 验收口径同步**：其 README 中「现有人工触发的批量 commit（CMT 批次）流程不回归；与自动 commit 并存时消息规范一致、索引同源」一条在本单落地后失效，是否随本单同步修订该单文档（两单衔接，人工确认）。

## 背景与目标

在 REQ-20260906-003 的后台派发基础上，允许用户明确选择实施模型与推理强度，并在同项续跑、自动重试及服务重启后保持一致。调度器通过程序解析配置、构造参数，不额外调用模型决定用哪个模型。

登记时的代码现状：CodexExecAdapter 支持扩展参数，但 Scheduler 未传模型与推理强度；项目设置和面板没有模型选择字段。当前执行依赖本机 Codex 配置，尚不能保证本项要求的配置快照与续跑一致性。

## 配置与执行规则

| 场景 | 行为 |
| --- | --- |
| 项目默认 | 默认“沿用本机配置”；也可显式选择模型与推理强度，按项目保存 |
| 单项覆盖 | 需求及 Bug 的执行设置可选择“继承项目设置”或“本项指定”；本项指定优先 |
| 本机继承 | 按实际 CLI、工作目录、CODEX_HOME、受信任项目配置及适用的配置层解析有效值，不能只读全局配置第一行 |
| 首次派发 | 在实际启动前解析最终模型、推理强度和非敏感提供方标识，持久化后显式传参 |
| 同项续跑或自动重试 | 使用本次执行的配置快照及确切会话 ID，不重新套用后来修改的项目或全局默认值 |
| 主动切换模型 | 当前执行已停止且核对通过后，用户可为本项建立关联的新尝试；保留原记录及修改前后参数 |
| 模型不可用 | 暂停该项目 Codex 自动派发，提示处理原因；首期不自动换模型或降低推理强度 |

保存设置仅影响尚未创建配置快照的新执行，不触发任务启动、恢复或真实模型请求。已保存快照的执行，包括等待恢复的执行，继续使用原设置。不同需求始终创建独立会话。

## 界面布局、交互与反馈

### 项目设置

- 复用当前“批量实施”抽屉的 Codex 页；在运行配置中、超时和重试设置之前放置“模型与推理强度”区块，不恢复已被调整掉的顶栏批量入口。
- 第一行是配置方式：“沿用本机配置 / 指定模型”。继承时只读显示解析出的模型、推理强度、来源及解析时间，并提供“刷新配置”。
- 指定时显示可搜索模型选择框与推理强度选择框。强度选项随所选模型能力变化；切换模型后原强度不兼容时清空并提示重新选择，不静默替换。
- 模型列表使用所选 CLI/提供方的已验证只读能力获取；列表加载失败时显示原因并允许输入模型 ID，标注“尚未验证”。不能将固定模型清单当成当前账户可用列表。
- 无法可靠解析继承值或确认组合合法性时，显示具体缺失项；阻止依赖该配置的新派发，提供刷新或显式选择入口，不猜测默认模型。
- 区块底部提供“保存设置”和“验证所选模型”。真实验证明确提示会产生一次模型请求；验证结果绑定模型、推理强度及配置版本，变更后显示“需要重新验证”，旧响应不能覆盖新配置。
- 只读列表、静态参数校验、真实可达验证分别反馈，保存或轮询不逐个试跑模型。所有设置沿用本机登录，不收集密钥。

### 单项设置与执行记录

- 在需求/Bug 详情的既有执行设置中加入“Codex 模型”折叠区，默认继承项目。展开后可指定本项模型与推理强度，并预览最终值及来源。
- 条目列表保持简洁；当前执行摘要与历史记录详情展示模型、推理强度、来源、验证状态和运行标识。
- 用户执行中修改设置时提示“已保存，将用于后续新执行；当前执行与续跑保持原设置”。
- 历史记录缺少模型字段时显示“历史记录未记录”，不得用当前默认值填成历史事实。

### 模型异常与用户介入

- 模型不存在、账户无权使用、推理强度不支持、配置无法解析等导致执行受阻时，在当前项目顶栏项目选择器旁显示“待处理 N”；条目卡片显示“模型配置待处理”标记。
- 点击入口打开对应执行/配置抽屉，持续展示条目、所选模型和强度、受阻原因、发生时间及日志入口。提示持久化，刷新、切换项目再返回或重启后仍能找到；同一问题不会因轮询重复弹窗。
- 提供“检查设置”“重新验证”。有已停止且可恢复的原会话时提供“按原配置恢复本项”；需要改模型时展开新配置表单并提供“以新配置重试本项”。
- 在按钮旁直接展示恢复目标、模型及影响范围，沿用现有操作反馈，不额外增加二次确认弹窗。保存和验证成功都不会自行恢复执行；用户点击恢复/重试后才启动，重复点击只产生一次执行。
- 原执行仍活动、工具收尾未确认、工作区或 owner 不匹配时禁用恢复/重试，显示下一步处理原因。新配置重试仍需通过既有互斥和会话恢复检查。
- 认领前发现配置问题时不认领条目；认领后受阻时保留业务状态和实施记录，不自动转 done、回退状态或把整个队列逐项认领失败。暂停后不为等待用户反复启动模型。

## 范围与兼容

- 本项覆盖后台 Codex 派发以及将来复用同一执行器的单项派发，Zcode 的模型配置保持其原有入口。
- 模型异常使用看板内持久提示。本项不包含系统通知、通用需求问答表单或 App Server 实时命令审批通道；这些能力可单独扩展。
- 延续后台进程管理、确切会话 ID、项目互斥和人工验收规则。模型选择不修改沙箱、审批规则或本机全局配置。
- 没有新配置字段的项目默认进入“沿用本机配置”；旧运行缺快照时可查看，恢复前要求用户补全并记录一次明确选择，不能伪造旧模型。

## 验收标准

- [ ] 项目默认、本项覆盖及继承来源准确，多项目设置隔离且刷新后保留。
- [ ] 模型与推理强度按实际能力校验，不硬编码当前本机默认值，不静默替换无效组合。
- [ ] 真实模型验证使用待验证配置；旧验证结果不会用于新配置，也不会因保存/轮询额外请求模型。
- [ ] 每次新执行保存配置快照并显式传参；配置变化不影响同项续跑、重试和重启恢复。
- [ ] 用户主动切换模型产生关联的新尝试，原记录保留，重复点击无重复执行。
- [ ] 模型异常暂停派发，有持久待处理入口、具体原因、日志和可执行的恢复路径；无自动换模型或整队列失败。
- [ ] 历史缺字段如实反馈；迁移不破坏 Zcode、依赖设置、运行账本及状态铁律。
- [ ] 完成测试用例中的配置、参数、恢复、异常及界面验证，并如实记录真实模型验证证据。

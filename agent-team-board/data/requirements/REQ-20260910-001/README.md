# REQ-20260910-001 app 场景点击 Cmd+R 刷新后，需要回到刷新前的界面

- 状态：accepted（已接受；本轮仅完善说明，未实施开发）
- 创建：2026-09-09T16:03:38.387Z

## 描述

### 背景与现象

「app 场景」指 Electron 桌面壳（REQ-20260905-001，项目根 `npm run app`）。`electron/main.mjs` 未自定义应用菜单、未注册 `before-input-event` 或快捷键拦截（`electron/`、`scripts/` 全仓检索零命中），Electron 默认菜单含「View ▸ Reload（⌘R / F5）」加速键，因此在 app 中按 Cmd+R 会触发**整页重载**。重载不影响壳层自建的 server 子进程（数据目录无恙），页面重新走 `boot()` 初始化——结果用户被抛回默认初始界面，刷新前正在看的界面全部丢失。

现状（基于 `scripts/web/app.js` 静态核查，2026-09-10）只有少数状态能挺过刷新：

- **已保留**：当前项目（URL `?project=` 深链 + localStorage `atb.project`，`boot()` 4944–4954 行）、当前模块视图（`syncProjectUrl()` 509–515 行把非 status 模块写入 `?view=`，`boot()` 解析恢复；需求模块为默认无参同样回到需求模块）、需求列表排序（localStorage `atb.req.sort`，REQ-20260908-002）。
- **刷新即丢**（`state` 初始化 + `boot()` 后全部复位）：
  1. 需求模块详情抽屉——打开的条目与所在页签（基本信息 / 说明 / 设计 / 测试用例 / 讨论纪要，及 licenses.md / test-report.md 附加页签）复位为空态引导（`renderDrawerEmpty()`）；
  2. 需求状态筛选档（待接受 / 已接受 / 已计划 / 开发中 / 待测试 / 已完成六档）复位第一档「待接受」；
  3. 模块搜索关键词清空；
  4. 任务模块二级页签（概况 / 队列 / 提示词 / 记录；批量开发 `state.batch.pane` 与批量完善 `state.refine.pane` 各自独立记忆）复位「概况」；
  5. 讨论模块——打开的讨论详情、详情页签、状态筛选档、列表滚动位置（`oncall.js` 内部 state）全部复位；
  6. 文件模块——目录横幅层栈与正在查看的文件（`banner.js` 层栈 state）回项目根初始态；
  7. 勾选集合（批量接受 / 移入计划等多选）清空。

典型痛点：用户正在看某条目的「测试用例」文档或讨论详情，按 Cmd+R（web 开发肌肉记忆）后回到「需求模块 · 待接受档 · 抽屉空态」，需要重新一路点回去。

### 目标

Cmd+R 刷新后（app 场景为触发口径；浏览器直连的 F5 / Cmd+R 走同一 `boot()` 通道，同步受益），看板**回到刷新前的界面**：所在模块与模块内关键浏览状态按下述口径恢复；恢复目标已失效时安全回落，不报错、不白屏、不阻塞后续操作。

### 恢复口径（细化）

1. **基线（现状已具备，验收防回归）**：当前项目、当前模块（五模块）、需求列表排序。
2. **需求模块**：状态筛选档；详情抽屉——刷新前打开了某条目则重新打开同一条目，并回到刷新前页签（页签失效时沿用 `drawerTabValid` 回落「基本信息」的既有先例）。
3. **任务模块**：二级页签（概况 / 队列 / 提示词 / 记录）；批量开发与批量完善两面板各自记忆、互不串扰。
4. **讨论模块**：打开的讨论详情（记录 + 页签）与状态筛选档恢复；列表滚动位置是否纳入恢复见「待确认」。
5. **文件模块**：目录横幅层栈（所在目录层级）与正在查看的文件（md 渲染 / 源码切换态随既有逻辑）。
6. **搜索关键词**：搜索框内容随所在模块恢复，命中条带按既有逻辑重新生成（讨论 / 任务为前端过滤，需求 / 文件重新发 /api/search）。
7. **失效回落**：恢复目标在刷新间隙已不存在（条目 / 讨论被删、文档被删、文件被删、目录失效、项目已不在注册表）时，按各模块既有回落先例安全降级（抽屉空态、页签回落、文件视图回根），不得卡在加载态或抛未捕获错误。

### 明确不恢复（边界）

- 未提交的表单草稿（新建弹窗输入、设置页未保存输入）——维持浏览器惯例，刷新即弃。
- 勾选集合（`acceptance` / `impl` / `plan` 多选）与一次性反馈（toast、批量操作结果条）——操作草稿与瞬时反馈，不跨刷新。
- 深浅色外观跟随系统，不在恢复范围。

### 实现方向（供 design 参考，不预设结论）

- 持久化通道（URL 深链扩展 / sessionStorage / localStorage 及组合）由开发阶段 design.md 定夺；默认口径为**会话级**恢复（「刷新回到刷新前」），新开窗口 / 新标签回到默认初始界面，是否跨窗口或跨重启记忆见「待确认」。
- 状态快照须按项目隔离（`switchProject()` 已有按项目重置各 state 的先例），避免多项目互相串状态。
- 预期实现落点在 web 层（`scripts/web/app.js`，讨论 / 文件模块涉 `oncall.js`、`banner.js`）；Electron 壳层预期零改动（Cmd+R 仍整页重载，恢复由页面完成，与 BUG-20260909-020 拖动区「经受整页重载」口径兼容）——若 design 决定壳层配合（如拦截重载），须说明理由。
- 恢复发生在刷新后首轮 `boot()`（数据到达后应用），此后行为与现状完全一致；后续操作持续更新快照，供下一次刷新使用。

## 界面展示

本需求不改看板界面布局与交互结构，只让「刷新后的界面」回到刷新前；下述为恢复所覆盖的界面区域与反馈口径。**可交互演示：[./ui-demo.html](./ui-demo.html)**（单文件、无外网依赖、无构建，浏览器直接打开；提供「现状：刷新回初始界面 / 期望：刷新回到刷新前界面」两形态对照、模拟 Cmd+R 与真实整页重载、五模块状态快照与恢复、条目失效回落、正常 / 空 / 加载 / 离线状态与深浅色切换、操作日志）。演示中的快照通道为示意，实际通道以开发阶段 design.md 为准。

### 界面布局（均不变，恢复作用于各区域内部状态）

- 看板整体自上而下：顶栏（logo + 实时状态点 + 标题 + 项目路径 + 项目切换器 /「＋ 新建」）→ 模块导航（讨论 / 需求 / 任务 / 文件 / 设置）→ 当前模块工作区。刷新前后布局完全一致，区别只在工作区内部状态是否复位。
- 需求模块：第四行状态筛选条（六档 chips）+ 左侧条目列表（计数 / 排序 / 档位入口 + 卡片行）+ 右侧详情抽屉（五页签：基本信息 / 说明 / 设计 / 测试用例 / 讨论纪要，licenses.md / test-report.md 存在时附加）。
- 任务模块：批量开发 / 批量完善面板，各含二级页签（概况 / 队列 / 提示词 / 记录）。
- 讨论模块：状态筛选 chips + 左侧讨论列表 + 右侧讨论详情（概况 / 纪要等页签）。
- 文件模块：目录横幅（面包屑 + 分层条带）+ 文件内容区。

### 交互行为

- 刷新动作：app 内 Cmd+R（浏览器 F5 / Cmd+R 同通道）→ 整页重载 → `boot()` 读取快照 → 恢复模块与模块内浏览状态。恢复只在刷新后首轮发生一次，之后一切交互与现状一致。
- 被纳入快照的交互：切换模块、切换需求筛选档、打开 / 关闭详情抽屉与切换页签、切换任务二级页签、打开讨论详情与切换页签 / 筛选、文件视图进入目录层级与打开文件、搜索框输入——每次操作即时更新快照（通道由 design 定夺）。
- 演示形态对照：现状形态刷新后回到「需求模块 · 待接受档 · 抽屉空态 · 搜索清空」；期望形态刷新后逐项复原（模块 → 筛选 / 页签 → 抽屉 / 详情 → 文件 → 搜索词）。
- 刷新前状态若已失效（如条目在他端被删），恢复按回落口径降级，不弹出错误框、不阻断列表正常浏览。

### 状态反馈

- **正常**：刷新后短暂页面加载态，随后直接呈现刷新前界面（模块、筛选、抽屉、页签、搜索词就位），恢复过程无需用户额外操作、默认不打扰（不弹提示）；顶栏实时状态点保持「● 实时」，轮询照常。
- **加载中**：重载期间页面自身加载占位（与现状一致）；恢复在首轮看板数据到达后应用，不额外延长可感知的加载时间。
- **空**：项目未初始化时空态卡照常展示（恢复不掩盖空态；无可恢复对象时自然回落默认初始界面）。
- **失败（离线）**：服务不可达时状态点转灰「○ 服务离线」、列表停更提示——恢复逻辑不得掩盖离线态；网络恢复后按现状轮询自愈。
- **失效回落**：恢复目标不存在时的降级（抽屉空态 / 页签回落基本信息 / 文件视图回项目根）静默完成，界面停在可用状态。

## 验收标准

- [ ] app 场景（`npm run app`）需求模块：打开某条目详情并切到某页签（如「测试用例」）、切筛选档（如「已接受」）、搜索框输入关键词 → Cmd+R → 刷新后仍在本模块、同筛选档、同一抽屉条目与页签、搜索词保留。
- [ ] 任务模块：二级页签切到「队列」（或提示词 / 记录）→ 刷新 → 仍在该页签；批量开发与批量完善两面板页签各自恢复、互不串扰。
- [ ] 讨论模块：打开某讨论详情并切页签、切状态筛选 → 刷新 → 详情与筛选恢复（列表滚动位置按「待确认」结论验收）。
- [ ] 文件模块：进入某目录层级并打开某文件 → 刷新 → 横幅层栈与文件内容恢复（文件为 md 时渲染 / 源码切换态随既有逻辑恢复或回落，口径由 design 定夺并在测试用例体现）。
- [ ] 模块级基线不回归：切到任一非需求模块刷新后仍在该模块（`?view=` 深链能力不回归）；当前项目与列表排序（localStorage）刷新后保留；`node scripts/tests/refresh-default-view.test.mjs` 全部通过（BUG-20260907-002 默认视图刷新后数据可见不回归）。
- [ ] 失效回落：刷新前打开的条目 / 讨论 / 文档页签 / 文件在刷新间隙被删除 → 刷新后安全回落（抽屉空态、页签回落基本信息、文件视图回根），无报错、无白屏、无卡死。
- [ ] 边界维持：未提交表单草稿、勾选集合、toast 不恢复；状态快照按项目隔离——在项目 A 刷新不得恢复出项目 B 的状态；新开窗口 / 新标签默认进入初始界面（按「待确认」结论验收）。
- [ ] 浏览器直连 `http://127.0.0.1:8888` 刷新同样恢复且无回归；`electron/` 目录零改动（若 design 决定壳层配合，须在设计文档说明理由）。
- [ ] `node scripts/tests/run-all.mjs` 全部通过，新增行为测试覆盖各模块恢复路径与失效回落路径。

## 待确认

- 持久层级：默认会话级（刷新恢复、新开窗口回默认）；是否需要跨窗口 / 跨重启（localStorage 级）记忆浏览状态，待确认。
- 讨论列表滚动位置（`oncall.js` `listScrollTop`）与需求列表滚动位置是否纳入恢复——内容异步渲染、恢复时机需评估，待确认（默认不纳入，仅恢复状态不恢复滚动）。
- 恢复通道选型（URL 深链扩展 vs sessionStorage vs 组合）：URL 可复制分享但参数会变长，sessionStorage 不可分享但干净——由开发阶段 design.md 定夺，此处不预设。

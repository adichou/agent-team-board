# REQ-20260919-001 当 ATB 以插件形式为其他项目服务时，任何对插件功能的修改，都建议通过 PR 的形式提交到源仓库

- 状态：submitted（待人工接受）
- 创建：2026-09-19T02:12:18.229Z

## 描述

### 背景与现状（已核实）

- 本仓库是插件源码仓库（开发分支 `dev`，发布主干 `main`）；插件以 git 克隆形式装入 ZCode 插件缓存后加载生效，缓存副本的 remote 即本仓库的 GitHub 地址（根 README.md「插件形态」口径）。
- ATB 为其他项目服务时，Agent 在被服务项目内工作；插件源码受认领锁保护（REQ-20260901-003）——持有效认领锁即可修改插件源码（scripts/commands/skills/hooks/manifest 等），改动落在插件缓存副本上。
- 缺口：缓存副本里的修改不回流源仓库——本地改动无法进入上游分支，且可能随插件更新或重装被覆盖（具体更新机制待确认）；源仓库也不是这类改动的评审入口。当前使用侧文档（skills/agent-team-board/SKILL.md）只规定了「改前必须 claim」，没有规定改动完成后如何回流。

### 目标

在「使用本产品管理任务」侧文档（skills/agent-team-board/SKILL.md）固化一条**建议性**规则：当 ATB 以插件形式为其他项目服务时，对插件功能的任何修改，建议通过 PR 的形式提交到源仓库（fork 或特性分支 → 向源仓库 GitHub 发起 PR；源仓库地址以插件缓存克隆的 remote 为准，当前为 github.com/adichou/agent-team-board）——而非在缓存副本就地改完即止，或未经评审直接推送源仓库分支。

同时在规则文本中明确排除：本建议**不适用于 agent-team-board 源仓库项目自身的开发**——在源仓库内改插件功能走根 AGENTS.md 的看板流程（登记 → 人工接受 → 移入计划 → claim → report 自动收口提交到 dev），不经 PR。

本条为文档约定（建议性），不新增强制钩子、命令或状态机分支；与既有认领锁保护（REQ-20260901-003）叠加而不冲突。

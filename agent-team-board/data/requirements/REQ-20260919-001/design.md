# 设计 — REQ-20260919-001 当 ATB 以插件形式为其他项目服务时，任何对插件功能的修改，都建议通过 PR 的形式提交到源仓库

> 由 Agent 在 /dev 开发前补充，人可随时批注。

## 背景

- 插件以 git 克隆形式装入 ZCode 插件缓存后生效，缓存副本的 remote 即源仓库 GitHub 地址（已核实本仓库 origin：`https://github.com/adichou/agent-team-board.git`，开发分支 `dev`，发布主干 `main`）。
- Agent 在被服务项目内持认领锁即可改插件源码（REQ-20260901-003），但改动落在缓存副本：不回流源仓库即无法进入上游，且可能随插件更新或重装丢失（更新机制待确认）。
- 使用侧文档（skills/agent-team-board/SKILL.md）现只规定「改前必须 claim」，未规定改动完成后如何回流。

## 方案

（技术选型、接口设计、影响面）

- **纯文档改动，落点唯一**：skills/agent-team-board/SKILL.md「状态机与铁律」节**新增第 7 条**，紧随第 6 条「插件源码受认领锁保护」（改动回流与改前 claim 是同一件事的前后两半，语义上相邻）；原第 7 条「git 提交通道」顺延为第 8 条。已核查全仓库对铁律的编号引用只有「铁律 1/2」（SKILL.md 常见错误表），重编号无回归。
- **规则内容（建议性口径）**：适用范围限定「ATB 以插件形式（插件缓存 git 克隆）为其他项目服务」场景；对插件功能（scripts/commands/skills/hooks/manifest 等源码）的任何修改，**建议**以 PR 形式提交回源仓库——fork 或特性分支 → 向源仓库 GitHub 发起 PR；源仓库地址以插件缓存克隆的 remote 为准（当前 `github.com/adichou/agent-team-board`）。动机写明：就地修改停留在缓存副本，不回流即无法进入上游，且可能随插件更新或重装丢失；源仓库保持单一事实源。
- **显式排除源仓库自身开发**：规则文本写明在 agent-team-board 源仓库项目内开发本产品**不适用**本 PR 建议，走根 AGENTS.md 看板流程（登记 → 人工接受 → 移入计划 → claim → report 自动收口提交到 dev）。
- **未定事实不编造**：PR 目标分支（`dev`/`main` 待确认）、插件缓存更新机制（待确认）在规则文本中标注「待确认」。
- **软提示决策（README 留待 design 定）**：**不附加**代码级软提示（如在 claim 输出追加提醒文案）。理由：① 需求明确「建议性、不新增强制钩子/命令/状态机分支」，软提示需改 claim 命令输出代码，扩大改动面且无对应强制诉求；② 文档规则已随 claim 必读的 SKILL.md 生效；③ 后续确有需要时另登记条目实施。
- **双入口边界**：根 AGENTS.md 不改动（开发侧行为已由其覆盖）；根 README.md 不改动（既有「插件形态」段已含「插件以 git 克隆形式装入、缓存副本 remote 即本仓库 GitHub 地址」事实，呼应为可选项且无新增事实）。

**开源选型（REQ-20260909-015）**：动手自研前先评估是否有成熟、维护中的开源库，优先复用——以依赖方式引入
（Node/Web 项目走 npm，Apple 平台走 SPM / CocoaPods），禁止复制开源库源码进项目仓库；仅当库无包分发渠道
且确需使用时才允许 vendor（内嵌源码），须在 licenses.md 标注复制范围与原因。License 只用开源友好白名单：
MIT / Apache-2.0 / BSD-2-Clause / BSD-3-Clause / ISC / 0BSD / Unlicense；GPL / LGPL / AGPL / SSPL 等
强传染许可及 License 不明的库禁止引入。自研须写明理由（三选一）：引用了哪些库 / 无合适库的原因 /
引入成本高于自研的原因。引入开源库须在条目目录维护 licenses.md（库名 / 版本 / 引入方式 / License / 仓库地址），
未使用开源库的条目不创建该文件。

本条为文档约定，不引入任何代码依赖，未使用开源库，不创建 licenses.md（理由：无合适库——纯文档规则不涉及代码依赖）。

## 风险与边界

- **影响面**：仅 SKILL.md 一处文本 + 静态契约测试 scripts/tests/req-20260919-001.test.mjs；不改 hooks/、scripts/ 源码、状态机、CLI 速查。
- **边界 1**：不改变 REQ-20260901-003 认领锁的判定与拦截行为；「建议」不含强制手段，state-guard 不新增规则。
- **边界 2**：第 7→8 条重编号仅在本节内；「常见错误」表引用的「铁律 1/2」不受影响。
- **边界 3**：回归面——skill-desc.test.mjs（正文结构）、req-20260918-002.test.mjs（SKILL.md 仍属受保护源码）等既有测试必须全量通过。

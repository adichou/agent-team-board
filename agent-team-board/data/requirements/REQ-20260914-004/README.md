# REQ-20260914-004 优化需求说明、设计文档中右键讨论菜单生成的提示词

- 状态：accepted（已接受；实际状态以 status.json 为准）
- 创建：2026-09-14T12:19:34.660Z

## 描述

需求 / Bug 详情抽屉的文档页签自 REQ-20260909-014 起支持右键「讨论」轻量引用（BUG-20260913-003 已放开 Bug 单）：在文档内容区（`#docView`）右键，点「💬 讨论」即把一段自包含引用复制到剪贴板，粘贴到 Agent 会话即可就该处文档内容展开讨论。复制文本由 `scripts/web/app.js` 的 `buildDocRef`（约 4388–4394 行）组装，当前格式为：

```
REQ-20260909-014 / design.md 第 3–4 行
文档：<项目根>/docs/agent-team-board/requirements/REQ-20260909-014/design.md
原文：
（所选文字；无选中时省略本节）
```

该文本只解决了「让 Agent 定位到文档位置」，没有约定 Agent 修改文件后的落盘与提交口径，用户需在会话中反复口头补充要求。本需求优化这段右键讨论菜单生成的提示词：**在保留现有自包含引用（单号 / 文档名 / 源码行范围 / 文档路径 / 原文）的基础上，追加「讨论要求」部分**，明确要求 AI：

1. **同轮提交**：每轮回答中如需修改相关文件，完成修改后**同轮同步执行 git commit**，不留未提交改动；
2. **commit message 规范**：须带上**条目单号、本轮用户的问题摘要、回答（改动）摘要**；
3. **回显提交信息**：回显答案时须带上本轮 **commit log 与 commit 号**。

参考格式（措辞与排版为示意，开发阶段 design.md 定稿，见「待确认」）：

```
【文档讨论引用】
REQ-20260914-004 / design.md 第 3–4 行
文档：<项目根>/docs/agent-team-board/requirements/REQ-20260914-004/design.md
原文：
（所选文字；无选中时省略本节）

【讨论要求】请在本轮及后续讨论中遵守：
1. 围绕上方引用（文档路径 + 源码行范围）展开讨论与修改。
2. 每轮回答中如需修改相关文件：修改完成后同轮同步执行 git commit，不留未提交改动。
3. commit message 须包含：条目单号（如 REQ-20260914-004）、本轮用户问题摘要、本轮回答（改动）摘要。
4. 每轮回答回显本轮 commit log 与 commit 号。
```

### 现状依据（基于当前代码）

- 提示词组装：`buildDocRef`（`scripts/web/app.js` 约 4388–4394 行）——首行「单号 / 文档名 第 x[–y] 行」+「文档：路径」+ 可选「原文：」节；由 `onDocCtxMenu`（约 4457 行起，contextmenu 文档级委托）→ `openDocCtxMenu` / `onDocCtxDiscuss`（约 4397–4455 行）复制到剪贴板。
- 作用面：`buildDocRef` 为三份文档页签（README.md / design.md / test-cases.md）与需求 / Bug 详情抽屉共用的唯一组装点；本需求标题点名「需求说明、设计文档」，test-cases.md 与 Bug 单是否同口径生效见「待确认」。
- 回退链路：自动复制失败时 `uiCopyBox`（约 4481 行起）弹手动复制弹窗，只读 textarea 展示完整文本并全选——提示词变长后该弹窗是主要可视承载面。
- 相邻边界：REQ-20260909-003「文档讨论」区块（`scripts/web/req-disc.js`，另一套复制提示词）不在本需求标题范围内，默认不改（见「待确认」）。
- 既有测试基线：`scripts/tests/doc-ctx-discuss-20260909-014.test.mjs`（T4 断言 buildDocRef 现格式）、`scripts/tests/doc-ctx-discuss-bug-20260913-003.test.mjs`——新格式落地时相应断言需同步更新。

### 目标口径

1. 纯前端剪贴板文本优化：不新增后端 API、不写文件 / 记录、不改状态机、不改菜单交互流程（唤起 / 收起 / 复制 / toast 口径维持现状）。
2. 新提示词仍自包含：现有引用要素（单号 / 文档名 / 源码行范围 / 文档路径，有选中时含原文）一项不缺，「讨论要求」追加其后，整体为单次复制的纯文本。
3. 讨论要求须完整覆盖三条指令：同轮同步 commit、commit message 含「单号 + 用户问题摘要 + 回答摘要」、回显 commit log 与 commit 号。
4. 提示词对粘贴目标（Agent 会话）生效属约定层面：看板侧不校验、不追踪 Agent 是否真的执行了 commit。

## 交互行为

1. **唤起 / 收起 / 复制流程与现状完全一致**：文档内容区右键弹菜单 → 点「💬 讨论」→ `copyPlain` 双回退复制 → toast 反馈；收起通道（点外部 / Esc / 滚动 / 切页签 / 关抽屉）不变，本需求不新增任何交互。
2. **复制内容变化**：剪贴板文本 = 现有自包含引用（单号 / 文档名 / 源码行范围 / 文档路径 + 有选中时的原文）+ 追加的「讨论要求」（三条指令，见「描述」）。
3. **有选中 / 无选中两场景一致**：无选中时仍无「原文」节，但同样携带「讨论要求」；行号映射口径（源码 1 基行）不变。
4. **粘贴到 Agent 会话后**：提示词即对 AI 生效——每轮改文件同轮 commit、commit message 带单号 + 问题摘要 + 回答摘要、回答回显 commit log 与 commit 号。这是提示词约定，看板不回读、不校验执行结果。
5. **三份文档页签行为一致**：README.md / design.md / test-cases.md 与 Bug 单详情抽屉同走 `buildDocRef`（覆盖范围细则见「待确认」）。

## 状态反馈

- **正常**：点「讨论」后菜单关闭，toast 摘要维持现口径量级（「已复制 引用：README.md 第 x[–y] 行」），不因文本变长而变化；用户到 Agent 会话粘贴即见完整新提示词。
- **空**：文档未创建（「尚未创建，开发阶段补充。」）时右键不弹菜单——口径不变。
- **加载**：文档「加载中…」占位期间右键不弹菜单——口径不变。
- **失败**：自动复制失败 toast 报错 + 手动复制弹窗完整展示并全选新提示词，可 ⌘C / Ctrl+C 手动复制；文档加载失败态右键不弹菜单——口径不变。

# REQ-20260908-026 优化批量任务管理界面与 Agent 配置

- 状态：submitted（待人工接受）
- 创建：2026-09-08T15:12:58.998Z

## 描述

基于 REQ-20260908-020，按已确认 Demo 统一批量完善与批量开发的管理流程：启动自动复制调度提示词，支持状态监控、异常重试、暂停恢复与终止；候选和本轮记录仅展示最近 2 条；Agent 设置使用 Codex/Zcode 两行配置表。

## 验收标准

以下为可核验口径，与「已确认方案」及下文「补充验收标准」一并作为验收依据。基线为 REQ-20260908-020 的任务模块与批量能力（涉及 `scripts/web/app.js` 任务模块渲染、`scripts/lib/refine-store.mjs` 完善批次与执行记录、`scripts/lib/batch.mjs` 开发实时串行队列、`scripts/lib/task-settings.mjs` 四路任务设置）。

### 界面结构

- [ ] 任务模块为「批量完善 / 批量开发」两个子面板，使用一致布局与操作逻辑；沿用现有中文产品顶栏、项目上下文、横向「讨论 / 需求 / 任务 / 文件 / 设置」导航与深浅色主题，不新增侧边导航或独立视觉体系。
- [ ] 全模块不提供「复核本次修改」「查看完善结果」等复核、总结或新增审批入口；条目内容沿用需求面板查看。

### 启动与提示词复制

- [ ] 无进行中任务时展示执行 Agent 选择与「启动」按钮，两类任务按钮文案均为「启动」；被隐藏的 Agent 不出现在选择项中；全部隐藏时启动不可用并提示到任务设置取消隐藏。
- [ ] 点击「启动」创建任务并自动复制所选 Agent（Codex / Zcode）的差异化调度提示词；复制成功后显示「任务已创建、提示词已复制，请在对应项目会话粘贴发送」。
- [ ] 复制失败时保留已创建任务，提供「重新复制」与展开提示词手动复制两种恢复方式；重试复制不重复创建任务。
- [ ] 创建或复制成功均不代表已执行：仅收到真实执行登记后才显示运行中；未登记前展示待启动状态与粘贴指引。

### 运行面板与计数

- [ ] 运行面板显示当前项编号与标题、执行 Agent、子代理会话、耗时 / 最近活动，以及「已处理 / 异常 / 处理中 / 待处理」实际计数。
- [ ] 无当前项时按真实阶段展示待启动、等待领取、已暂停或已结束，终态不显示「等待领取」。
- [ ] 批量完善候选为已接受且未完善的条目、批量开发候选为已计划且未认领的条目，均实时读取并沿用现有队列规则；运行中新符合条件的条目自动纳入本轮。

### 最近两条列表

- [ ] 待处理队列只显示最近加入的 2 条（最新在前，不足 2 条全部展示），标注「最近 X 条 / 共 N 条」；展示顺序不改变实际领取顺序。
- [ ] 本轮处理记录只显示最近创建的 2 次执行尝试（最新在前，不足 2 条全部展示），能区分需求 / Bug，并含执行状态、执行次数、异常原因及适用操作。
- [ ] 2 条上限仅为界面展示限制：不删除账本、不缩减实际队列、不截断计数，也不新增完整列表或结果复核面板。
- [ ] 正常完成与终止后仍保留最近两条记录，显示明确终态并允许启动新一轮；候选为 0 / 1 / 2 / 超过 2 条时展示均正确。

### 暂停、终止与异常重试

- [ ] 「暂停后续领取」仅阻止后续领取，提示当前项继续执行；当前项结束后显示「已暂停」；恢复后继续领取。
- [ ] 终止有二次确认，说明停止领取范围、保留已有记录、当前子代理需到对应 Agent 会话手动停止；确认后任务转终态，不再显示暂停或恢复控件。
- [ ] 旧子代理未确认停止前，不允许重新派发同一条目造成重复执行，界面提供确认停止后的解除入口。
- [ ] 异常或已中断的执行记录提供「重新执行」：保留原记录并增加新尝试，不覆盖失败原因和执行次数；重复点击不产生重复在途执行。
- [ ] 活跃任务中的重试进入本轮队列并遵守暂停与串行领取规则；终态任务重试通过新的待启动执行任务承接并自动复制调度提示词，不把复制成功当成执行成功。
- [ ] 重试前核验条目当前业务状态与占用条件，不自动修改人工管理的业务状态；不可重试时显示具体原因和后续操作。

### 任务设置

- [ ] 任务设置按「批量完善 / 批量开发」分别配置；界面为四列表格（执行 Agent / 子代理模型 / 推理强度 / 是否隐藏），固定 Codex、Zcode 两行；行首 Agent 是配置对象而非当前执行者选择器。
- [ ] 新配置默认均不隐藏；隐藏仅影响对应任务的启动候选，不抹除历史任务或记录；两类任务四路配置独立保存（沿用 `scripts/lib/task-settings.mjs` 的 `tasks/settings.json` 存储）；已有用户配置迁移保留已保存选择。
- [ ] 保存后仅对后续新任务生效，运行中任务保留原配置；未保存的变更不生效；全部隐藏时启动不可用并提示到设置取消隐藏。
- [ ] 模型及强度选项使用 Agent 实际支持的值，不使用 Demo 占位模型（待确认：Codex / Zcode 各自生产可用的子代理模型与推理强度清单）。

### 回归与交付

- [ ] `atb refine` / `atb batch` CLI 既有命令（create / next / done / fail / release / check / summary / pause / abort / records 等）行为不受影响；claim / report 状态机与互斥锁等既有机制不受影响。
- [ ] 生产界面不包含 Demo 演示按钮与模拟数据（场景切换、模拟执行等仅存在于 `./ui-demo.html`）。

## 已确认方案

本需求是 REQ-20260908-020 的界面与管理流程优化。任务模块用于管理每轮处理的需求 / Bug、执行状态及控制操作，不承担内容总结或复核职责。不提供「复核本次修改」「查看完善结果」或新增审批步骤；需求内容与完整条目信息沿用需求面板查看。

沿用项目现有中文产品顶栏、项目上下文、横向「讨论 / 需求 / 任务 / 文件 / 设置」导航、靛蓝筛选按钮、紧凑面板、控件间距与深浅色主题，不新增侧边导航或独立视觉体系。

### 启动与状态反馈

- 保留「批量完善 / 批量开发」两个子面板，两类使用一致布局及操作逻辑。
- 无进行中任务时展示执行 Agent 选择与「启动」按钮；两类按钮均仅用「启动」，不使用「启动批量完善 / 启动批量开发」。
- 点击「启动」创建任务，并自动复制对应 Codex / Zcode 的差异化调度提示词。复制成功后明确显示「任务已创建、提示词已复制，请在对应项目会话粘贴发送」。
- 创建或复制成功均不代表已经执行；收到真实执行登记后才显示运行中。复制失败保留已创建任务，提供重新复制和展开提示词手动复制，重试复制不重复创建任务。
- 运行面板展示当前项编号与标题、执行 Agent、子代理会话、耗时 / 最近活动及实际计数。无当前项时按真实阶段展示待启动、等待领取、已暂停或已结束，不能在终态显示等待领取。
- 批量完善实时处理已接受且未完善的条目；批量开发实时处理已计划且未认领的条目，沿用现有队列规则。新符合条件的条目自动纳入运行中的本轮。

### 最近两条列表

- 待处理队列只显示最近加入候选的 2 条，最新在前；不足 2 条时全部展示。显示「最近 X 条 / 共 N 条」。展示顺序不改变实际领取顺序。
- 本轮处理记录只显示最近创建的 2 次执行尝试，最新在前；不足 2 条时全部展示。包括需求与 Bug、执行状态、执行次数、异常原因及适用操作。
- 两条上限仅为界面展示限制，不删除账本、不缩减实际队列、不截断计数。本轮处理记录不增加完整列表或结果复核面板，条目信息沿用需求面板查看。
- 正常完成与终止后仍保留最近两条记录，显示明确终态并允许启动新一轮。

### 暂停、终止和异常重试

- 暂停仅阻止后续领取，当前子代理继续执行；显示「暂停后续领取，当前项继续」，当前项结束后为「已暂停」。恢复后继续领取。
- 终止需二次确认，说明停止领取的范围、保留已有记录，并明确当前子代理若仍运行需到对应 Agent 会话手动停止。
- 已终止 / 已结束不再显示暂停或恢复控件；旧子代理未确认停止前，不允许重新派发同一条目造成重复执行。
- 异常或已中断的执行记录提供「重新执行」，保留原记录并增加新尝试，不覆盖失败原因和执行次数；重复点击不能产生重复在途执行。
- 活跃任务中的重试进入本轮队列，遵守暂停和串行领取规则，不打断当前项。终态任务重试通过新的待启动执行任务承接，并自动复制调度提示词，不把复制成功当成执行成功。
- 重试需核验条目当前业务状态和占用条件，不自动修改人工管理的业务状态；不可重试时显示具体原因和后续操作。

### 任务设置

按「批量完善 / 批量开发」分别配置，每类均用表格显示两个固定行记录：

| 执行 Agent | 子代理模型 | 推理强度 | 是否隐藏 |
| --- | --- | --- | --- |
| Codex | 模型选择 | 对应模型支持的强度 | 复选框，默认不勾选 |
| Zcode | 模型选择 | 对应模型支持的强度 | 复选框，默认不勾选 |

- 行首 Agent 是配置对象，不是选择当前任务的执行者。取消原来容易被误解为启动 Agent 选择器的设置方式。
- 两类任务四路配置独立保存；隐藏仅影响对应任务的启动候选，不抹除历史任务或记录。
- 新配置默认均不隐藏；已有用户配置迁移应保留已保存选择。
- 模型及强度选项使用 Agent 实际支持的值，Demo 中占位模型不作为生产模型配置。
- 保存后用于后续新任务，运行中任务保留原配置；未保存变更不能悄悄生效。全部隐藏时启动不可用并提示到设置取消隐藏。

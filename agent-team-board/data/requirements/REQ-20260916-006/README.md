# REQ-20260916-006 待人工确认的任务中的文件差异对比页面没法看出来差异点，需要优化

- 状态：accepted（已接受）
- 创建：2026-09-16T04:44:01.587Z

## 描述

![截图](attachments/paste-1789533784984.png)

待人工确认（develop 类挂起）侧拉面板中，文件表「差异」列的「查看差异」打开的内容看不出差异点：差异以纯文本形式整体平铺，无法快速定位改了哪些行、哪些字符。

### 已核实的现状（依据源码）

- 入口在 `scripts/web/app.js` 的 `renderConfirmForm`：文件表每行对「未提交」文件提供「查看差异」按钮（`data-confirm-diff`），「已入库」行显示「—」；i18n 键「查看差异」（EN：View diff）。
- 点击后 `loadConfirmDiff`（app.js）请求 `GET /api/confirms/<id>/diff?path=<p>`（`scripts/server.mjs`），服务端经 `gitFlow.fileDiffText`（`scripts/lib/git-flow.mjs`）返回：已跟踪文件为 `git diff HEAD -- <path>` 的原始 stdout（unified diff 纯文本）；未跟踪新文件为「（新文件，未纳入版本控制）」提示 + 文件全文。
- 前端渲染（`loadConfirmDiff` 内一行模板）：把返回文本整体转义后塞进单个 `<pre>`（`<details open class="confirm-diff">`，标题「<path>（工作区 vs Git 基线）」，i18n 动态键「◇（工作区 vs Git 基线）」）。没有任何差异语义渲染：`+` 行、`-` 行、`@@` hunk 头与上下文行同样式，无行号、无未变更上下文折叠、无并排视图、新文件全文平铺。
- 后果（与截图反馈一致）：较长的 diff 中改动行淹没在等宽文本墙里，必须逐行人工比对字符才能找到差异点；新文件场景则整屏全是「原文」，完全无从分辨。
- 现有状态反馈口径（须保持）：加载显示「正在读取差异…」；无差异显示「（与 HEAD 一致：无差异——可能已补交入库）」；读取失败显示「差异读取失败：◇（读取失败不冒充无差异）」并提供「重试」按钮——失败不冒充无差异。

### 期望优化

前端展示层优化（仍复用现有 diff 接口与只读 git 口径，不改变服务端语义与数据来源）：

1. **行级差异渲染**：新增行、删除行、hunk 头（`@@ … @@`）、diff 文件头与未变更上下文行有可区分的视觉样式（深浅色两套配色），行首保留 `+`/`-`/空格标记并显示旧/新文件行号，与 `git diff` 原文行号对应。
2. **未变更上下文折叠**：长段上下文默认收起（保留头尾若干行），改动行始终直接可见，折叠处可一键展开。
3. **新文件呈现**：未跟踪新文件整文件按「全部新增」着色呈现，不再纯文本平铺。
4. **视图切换**：提供「统一 / 并排（左右分栏）」切换，默认统一视图（并排视图是否纳入本期待确认）。
5. **行内字符级高亮**：成对的删除/新增行中真正变化的字符片段进一步高亮（是否默认开启、高亮粒度待确认）。
6. **文案**：新增界面文案（视图切换、展开上下文等）按 BUG-20260912-001 同步中英文至 `scripts/web/i18n.js`；现有键「查看差异」「◇（工作区 vs Git 基线）」「（与 HEAD 一致：无差异——可能已补交入库）」「正在读取差异…」「差异读取失败：◇（读取失败不冒充无差异）」沿用不改。

## 界面布局

差异查看区仍在待人工确认侧拉面板内、文件表下方（现 `#confirmDiffBox` 位置），宽度随面板，不新开全屏遮罩或独立页面。顶部为差异标题行「<path>（工作区 vs Git 基线）」与视图切换（统一 / 并排）；主体为差异内容区，统一视图每行依次为旧行号、新行号、标记列、内容；并排视图左右两栏各带行号、中间细分隔。行背景与标记列按行类型着色（新增 / 删除 / hunk 头 / 上下文），内容等宽字体、长行横向滚动不换行、不撑破面板。折叠的上下文显示为一条居中的「展开 N 行未变更」操作行。

## 交互行为

1. 文件表「查看差异」点击后在差异查看区加载该文件差异；再次点击其他文件的按钮切换内容；面板内其余操作（归属选择、保持挂起、重新核验、确认并继续）不受影响。
2. 统一 / 并排视图随时切换，切换保持滚动位置与展开状态不丢失；折叠行点击「展开」就地展开该段上下文，不重置其余折叠。
3. 读取失败时「重试」重新请求同一文件；请求与失败语义不变（失败不冒充无差异）。
4. 行内字符级高亮仅作用于成对的删除/新增行，未配对行与上下文行保持整行着色；复制行为不复制行号与标记列，仅内容（具体复制入口待确认）。

## 状态反馈

- 正常：渲染着色差异，标题行显示文件路径与「工作区 vs Git 基线」口径，改动行无需滚动即可见（上下文默认折叠）。
- 空：返回空 diff 时显示「（与 HEAD 一致：无差异——可能已补交入库）」，语义与现状一致。
- 加载：请求期间显示「正在读取差异…」，不显示残旧的上一份差异。
- 失败：显示「差异读取失败：<原因>（读取失败不冒充无差异）」与「重试」按钮，可重试恢复。
- 新文件：整文件按新增行呈现，文件头标注「（新文件，未纳入版本控制）」。

## 验收标准

- [ ] 「查看差异」打开后，无需逐行阅读原始文本即可视觉定位改动行：新增 / 删除 / hunk 头 / 上下文四类行样式可区分，深浅色两套主题下均可读。
- [ ] 统一视图行显示旧 / 新文件行号，与 `git diff HEAD` 原文行号一致；行首 `+`/`-`/空格标记保留。
- [ ] 长段未变更上下文默认折叠，折叠行可展开；展开不影响其他折叠段与视图切换。
- [ ] 未跟踪新文件整文件按新增呈现，头部标注「（新文件，未纳入版本控制）」，不再纯文本平铺。
- [ ] 统一 / 并排视图可切换且内容一致；并排视图左右对齐成对的删除 / 新增行（若本期裁掉并排视图，此项按「待确认」结论验收为不适用）。
- [ ] 状态反馈保持现有语义：加载「正在读取差异…」、空差异「（与 HEAD 一致：无差异——可能已补交入库）」、失败显示原因并可重试，失败不冒充无差异。
- [ ] 差异数据仍来自现有 `/api/confirms/<id>/diff` 接口与只读 git 口径，服务端无行为变更；长 diff 不撑破面板布局（横向滚动，不换行）。
- [ ] 新增界面文案中英文同步进 `scripts/web/i18n.js` 并通过 i18n 相关测试；现有差异相关键不改动。
- [ ] ui-demo.html 可离线直接打开并交互，含现状 / 期望对照、正常 / 空 / 加载 / 失败状态切换与深浅色切换。

## 待确认

- 并排（左右分栏）视图与字符级高亮是否纳入本期范围，还是仅交付统一视图的行级渲染。
- 上下文折叠的保留行数（如每段头尾各 3 行）与折叠交互形态（就地展开 / 全部展开按钮）。
- 超长 diff（如数千行新文件）的截断或分页策略；复制差异内容的具体交互入口。

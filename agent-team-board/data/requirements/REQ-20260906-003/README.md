## 背景与目标

用户选定 Codex 长期方案：看板服务以普通程序调度，持续选取已接受且依赖满足的条目，为每项直接后台启动独立 Codex 会话。无需一个长期主调度聊天，不把前面需求的聊天历史传给后面的需求。

当前派发使用 `.command + open` 打开 Terminal。本需求的自动派发采用后台非交互 `codex exec`，执行期间不打开终端窗口，并管理输出、失败恢复和进程收尾，避免积累空终端或遗留受管进程。

每次执行的完整结果必须在 Status Board 可查看。Codex 桌面侧栏默认不展示普通 exec 会话，本期如实展示该限制，不把桌面可见性当成已实现。

## 界面布局、交互与反馈

### 项目级面板

- 与 Zcode 共用顶栏“批量实施”入口及右侧抽屉，布局见 [REQ-20260906-002](../REQ-20260906-002/README.md)。不能新增一套重复入口。
- “Codex 自动派发”页顶端始终显示项目路径，开关默认关闭，未通过配置检查时禁用开启并给出原因。
- 配置包括 CLI 路径（自动探测、可修改）、单项超时（默认 60 分钟，可设 5～240 分钟）、自动重试次数（默认 2，范围 0～3）、重启后自动继续（默认关闭）。不在表单收集或展示密钥；沿用配置好的本机登录与模型设置。
- 显示项目并发固定为 1，首期全服务的自动实施并发也固定为 1；不同项目的等待状态可见，后续再扩展多项目并行。
- “检查运行环境”展示 CLI 版本、登录/模型可用性、项目访问、必需插件/工具、权限适配的结果。静态检查与真正向模型发送的最小验证分开标注；需要模型请求的验证由明确按钮触发，不能冒充静态检查已验证模型可达。
- 开关开启后自动选择工作；队列为空显示“等待已接受条目”，后续人工接受的新条目可被自动处理。页面刷新和切换项目不重建执行；配置与运行状态按项目存储。

### 当前执行与控制

- 显示当前单号、标题、阶段、开始时间、最后事件时间、尝试次数和已获取的会话 ID；ID 未获得时显示“等待会话创建”，不得显示假 ID。
- 关闭“自动派发”只停止领取新项，当前项默认继续，提示“当前执行完成后停止派发”。
- “停止当前执行”发出取消请求并显示“停止中”；确认该执行及相关工具停止后才显示“已中断”。无法确认时显示“收尾待核对”，保留项目占用。
- 超时、认证失败、额度不足、网络错误、依赖阻塞、测试失败和工作区遗留改动分别显示原因与下一步。环境级错误暂停执行器，不能自动认领并失败整批条目。
- “恢复本项”与“重新尝试”明确区分：有明确会话 ID、owner 和可继续状态时恢复；需要新上下文时创建新的尝试记录并关联同一条目。操作按钮必须受原执行状态和互斥检查约束。

### 执行记录与结果

- 历史记录按需分页，包含条目、runId、结果、时长、尝试次数和报告入口。点击后展示“摘要 / 执行日志 / 最终回复 / 测试报告”，日志增量读取，不在内存或页面反复加载全量记录。
- 条目详情显示最近执行结果及历史入口；执行账本状态不改变业务状态列。
- 必须能在看板查看每项最终回复、命令事件及错误原因；日志中无结果时明确显示“尚无最终回复”，不显示空白成功页面。
- 桌面跳转未接通时显示“桌面入口未接通，请查看看板日志”；只有当前接入方式完成可见性验证后才启用“在 Codex 桌面打开”。不得仅凭有会话 ID 或深链调用成功显示“已打开任务”。
- 依赖字段复用条目“批量执行设置”，前置条目默认为人工验收完成后才可实施；无对应模块时在本需求中按共用协议补齐。

## 执行与会话要求

1. 不同条目使用新会话；同一条目的续跑只使用已记录的确切会话 ID。禁止以 `resume --last` 定位，禁止把上一项 fork 后用于下一项。
2. 后台直接 spawn CLI，使用参数数组、明确 cwd、受控环境和标准输入；不通过 shell 拼接不可信标题或提示词，不调用 open/Terminal/AppleScript/.command。
3. 保存 `--json` 事件、stderr、最终回复及会话 ID，不使用 ephemeral 模式。非 JSON 行、未知事件、部分行或输出结束时的尾行不得使服务崩溃。
4. 只有 accepted 可新派发；预留与 worker claim 需原子衔接。项目内 Zcode、Codex 与手工实施共用互斥，不静默抢占旧 owner。
5. 完成判断核对本次 runId、owner、条目、新的 report、报告文件和测试结论；仅退出码 0、turn.completed 或“已完成”文字不足以进入 reported。
6. 模型已结束一轮但未完成本项时，可按确切会话 ID有限续跑（默认最多追加 2 轮），总时限覆盖本次尝试；超过上限记录阻塞，不能无限追问继续。
7. 首期总时限以单项尝试为单位；网络自动重试最多使用配置次数，退避且有持久化记录。副作用不明时不重试，已运行的旧任务未确认停止时不创建新执行。
8. 不自动清理用户改动、切换分支、提交、合并或推送。失败后的共享工作区不确定时暂停该项目。

## 进程与服务生命周期

- 正常完成、启动失败、取消、超时和服务退出都有收尾逻辑，确认结束后才释放实施占用并派下一项。
- 仅管理本次 run 归属明确的进程及工具。不能按进程名终止所有 Codex，也不能关闭用户共用的 app-server。
- 停止顺序为请求中断、等待宽限期（默认 10 秒）、对身份仍匹配的受管进程进行强制回收。进程身份至少校验 PID、启动时刻和运行归属，防止 PID 复用。
- CLI 退出不等于它启动的工具或共享服务上的 turn 已停止；需经实际会话状态或受管进程验证。不能确认时进入 cleanup_pending，显示待核对并保留项目锁。
- 服务重启先恢复账本、核对锁/进程/会话/报告。默认显示“已恢复记录，等待继续”；只有用户提前启用“重启后自动继续”且核对通过时才自动恢复取单。
- 浏览器标签关闭不停止独立服务。Electron 拥有服务时，退出前协调取消和落盘；复用外部服务时，关壳不杀外部服务。异常崩溃或断电后的残留在下次启动核对，不假称已保证系统级零残留。

## 范围与限制

- 本期优先落地 codex exec adapter，接口可为将来 SDK/app-server 留扩展点，不同时开发三套执行器。
- 不新增外部模型账户，不自动消耗使用量重置，不依赖 Agent 关闭安全约束以实现无人值守；权限需求在开启前配置，未授权操作转人工处理。
- 核心验收是后台执行与看板完整可追踪。独立桌面任务创建和桌面侧栏集成仍为后续扩展，保留能力探测与真实反馈。
- 原有手动“派发给 Codex”可保留，但界面应明确它会打开终端；自动派发永不降级为弹终端或复制粘贴流程。

## 验收标准

- [ ] 用户开启一次即可连续处理至少 3 项，队列清空后不空转调用模型；新接受条目可继续派发。
- [ ] 各项为不同会话 ID，同项恢复使用指定 ID，记录中可区分新尝试与续跑，无串上下文。
- [ ] 自动流程不增加 Terminal 窗口，不使用 .command/open，特殊字符路径与提示词不会变成 shell 代码。
- [ ] 配置预检、项目绑定、全局/项目并发、Zcode/手工互斥和原子认领均正确。
- [ ] 退出码、事件、报告和 owner/runId 核对一致；退出 0 但无 report 不能假成功。
- [ ] 看板可查看每次执行的完整保留日志、最终回复、测试报告和失败原因，长日志增量加载。
- [ ] 自动派发关闭、停止当前、超时、网络重试、登录/额度错误的行为与界面文案一致。
- [ ] 正常及受控故障中受管执行进程收尾，不误杀其他任务；收尾未确认时不放锁或派下一项。
- [ ] 服务在预留/建会话/保存 ID/report/收尾之间崩溃均可核对恢复，不重复实施或重置业务状态。
- [ ] Electron 自建服务与复用服务的关闭行为正确；重启后自动继续开关生效且默认关闭。
- [ ] 桌面可见性限制如实展示，不能把日志可读或已有 ID 宣称为侧栏任务可见。
- [ ] 假 CLI 故障矩阵、真实隔离项目小批次、相关状态守卫和既有派发回归有证据；上报后待人工确认完成。

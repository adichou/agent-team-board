# REQ-20260921-013 AI 完善按钮移动到版本详细内容的版本计划页签内。版本计划页签改名为概况

- 状态：以看板实时状态为准
- 创建：2026-09-21T07:57:22.199Z

## 描述

将发布模块左侧版本卡片上的「AI 完善」操作迁入右侧版本详情的第一个页签，并把详情第一个页签「版本计划」改名为「概况」。用户先选择版本，再在概况中完善该版本名称与描述，操作对象与展示信息保持一致。

### 已核对现状与范围

- `scripts/web/build.js` 的版本卡片通过 `data-ver-answer` 提供 AI 完善按钮；`openAnswerModal(verId)` 按版本 ID 打开既有弹窗，包含提示词复制、回答解析与编辑应用流程。
- 详情的 `STEP_LABEL.plan` 当前为「版本计划」，后续步骤为关联条目与提交、文档编写、合并入 main、正式发布。本单只改详情首个页签显示名称为「概况」，保留内部步骤标识及五步顺序；模块外层「版本计划 / 分支浏览」导航名称保留。
- 已有锁定规则：合并中（merging）或已正式发布（pushedOf）不能 AI 完善；已合并但未推送仍可使用。迁移入口沿用这些规则。
- 当前代码已有 REQ-20260921-014 的显式「编辑」入口。本单 AI 完善与手动编辑并存，不覆盖其表单或扩展保存权限；具体草稿互斥方式待确认，开发阶段须保证不会静默覆盖未保存输入。

## 界面布局

左侧继续展示版本列表；移除每张卡片内的 AI 完善按钮，其他操作维持原位置。右侧保持名称、状态和版本标识头部，下面是五步导航。首个页签显示「概况」，在其内容区顶部设置操作行，右对齐「AI 完善」按钮；下方保留计划号、版本号、分支、描述和既有编辑入口。按钮属于概况内容区，切至其他步骤时不显示。窄屏操作行允许换行，不遮挡信息或导航。

## 交互行为

1. 选中版本进入详情，在概况点击 AI 完善，打开当前版本的既有完善弹窗；标题展示版本 ID，提示词、解析与应用都绑定该 ID。
2. 复制提示词、打开 Agent 入口、粘贴回答、解析预览、编辑与应用沿用原能力；应用成功刷新对应版本的名称与描述，取消关闭弹窗不写入。
3. 切换版本后新打开的弹窗必须指向新选择版本，不能沿用上一版本 ID。弹窗在途数据与目标版本绑定，禁止应用到错误版本。
4. 迁移后卡片不再保留重复入口；详情导航仍正常切换，首个步骤内部标识不变，页面刷新或导航恢复继续落到正确步骤。

## 状态反馈

- 正常：概况操作行可见可用按钮，弹窗显示当前版本标识。
- 空：未选择版本或无版本时显示选择／创建引导，不显示能触发写入的按钮；无描述显示占位，仍可完善。
- 加载：读取版本详情期间不允许对未确定版本操作；应用处理中禁用重复提交并显示处理中。
- 失败：读取失败显示原因与重试；回答解析或应用失败保留输入并明确提示，不能假装成功，支持修正或重试。
- 锁定：合并中禁用并提示「合并中，请稍候……」；已正式发布禁用并提示「已正式发布，不允许再 AI 完善」。已合并未推送可用。
- 文案：详情「概况」对应英文 Overview；新增提示与按钮可访问名称同步中英文词典，状态不只依靠颜色表达。

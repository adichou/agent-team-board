# REQ-20260908-002 所有列表提供排序功能。已完成的需求或 bug 默认只显示最新的 100 项，其他的需要通过搜索获取

- 状态：accepted（已人工接受）
- 创建：2026-09-08T00:37:55.499Z

## 描述

（本节由实施 Agent 按标题补全，批次接受时描述未填；接受即视为设计认可。）

**背景**：需求视图与讨论视图的条目列表此前由服务端固定按创建时间升序返回（最老的在最上，
新建条目沉底），前端没有任何排序入口；条目规模增长后（本项目已 100+ 条）翻找最新/最近
活跃条目越来越难，「已完成」条目还会无限累积。

**范围**（标题中「所有列表」的具体化——看板中此前没有任何排序控制的条目卡片列表）：

1. 需求视图列表（五档状态筛选「待接受 / 已接受 / 开发中 / 待测试 / 已完成」共用的列表）。
2. 讨论视图列表（待回复 / 回复中 / 已回复 / 失败 筛选共用的列表）。

不涉及：文件视图（服务端已固定排序：目录在前、同层按名称）；任务 / CI 模块的分页记录
（服务端按时间倒序分页，分页与用户排序语义冲突，超出本需求）。

**界面布局 / 交互 / 状态反馈**（REQ-20260903-001 质量前置）：

- 需求视图：列表标题行（`.req-caption`，「N 个条目」与「选择可操作项」之间）新增排序
  下拉 `#reqSort`，五个选项：
  - `updated-desc` 最新更新（默认）
  - `updated-asc` 最早更新
  - `created-desc` 最新创建
  - `created-asc` 最早创建
  - `id-asc` 单号（升序）
- 讨论视图：状态筛选条行末新增同款排序下拉（讨论单无编号排序意义，仅四个时间键选项，
  默认 `updated-desc` 最新更新）。
- 切换排序立即重排当前列表（与搜索叠加：先搜索过滤、再按所选键排序）。
- **已完成档默认截断**：需求视图当前档为「已完成」且搜索关键词为空时，按当前排序只显示
  前 100 项；计数行显示 `100 / N 个条目（已完成默认仅显示最新 100 项，更早请用搜索获取）`
  （N 为该档总数）。其余各档与搜索期间不截断。
- 排序选择记忆在 localStorage（`atb.req.sort` / `atb.oncall.sort`），刷新后保留；读到
  非法值回退默认档。
- 轮询增量渲染机制保持：排序键纳入列表内容签名，排序变化或数据变化才重绘，不打断点击/勾选。

## 验收标准

- [ ] 需求视图五档列表均可按五种键排序，默认「最新更新」降序（最新活跃在最上）。
- [ ] 已完成档默认（未搜索时）只显示最新 100 项，计数行展示 `100 / N` 与搜索引导；其余档不截断。
- [ ] 搜索期间不截断：搜索命中集合作用于已完成档全量条目，更早条目可被搜索获取。
- [ ] 讨论视图列表可按四种时间键排序，默认「最新更新」。
- [ ] 排序选择本地记忆，非法存储值回退默认。
- [ ] 排序与截断不影响既有交互（行点击开详情、勾选批量接受 / 批量实施、增量重绘）。
- [ ] `npm test` 回归全绿。

# REQ-20260909-006 需求 bug 单详情页布局优化，使用页签式布局

- 状态：accepted（已接受；实际状态以 status.json 为准）
- 创建：2026-09-09T00:36:45.643Z

## 描述

Status Board 需求模块的条目详情抽屉（宽屏为常驻右栏，窄屏为覆盖层）目前把所有区块自上而下单列堆叠：基本信息（meta-grid）、状态通知与提示、操作按钮行、下属 Bug 列表、批量执行设置、需求讨论，最后才是文档页签（说明 / 设计 / 测试用例 / 测试报告）与文档内容。条目关联信息越多，滚动距离越长，文档正文与讨论被挤到抽屉底部。本需求将需求 / Bug 单详情抽屉改为页签式布局，固定五个页签：

1、首页签是基本信息
2、第二页签是说明
3、第三页签是设计
4、第四页签是测试用例
5、第五页签是讨论纪要

只重组详情抽屉内部的信息组织方式，不改变各区块自身的功能、数据来源与操作语义；列表、筛选、批量操作等抽屉外区域不变。

### 现状依据与范围

- `scripts/web/index.html`：`<aside id="drawer">` 为详情抽屉容器（需求工作区内，宽窄屏两形态见 REQ-20260907-004）。
- `scripts/web/app.js` 的 `renderDrawer()`：当前 `drawer-body` 依次渲染 meta-grid → Agent 完成提示 / 操作 notice → `.drawer-actions`（上一条/下一条导航 + 状态操作按钮）→ 下属 Bug 列表 → `batchSettingsHtml()`（批量执行设置：依赖与本项 Codex 模型）→ `reqDiscussionsHtml()`（需求讨论）→ `nav.tabs` 文档页签 → `#docView` 文档内容；`loadDoc()` 按需加载文档，`linkupDocDemo()` 接管文档内相对 `.html` 演示链接（BUG-20260908-021）。
- `scripts/web/app.js` 的 `DOC_LABEL`：`README.md=说明`、`design.md=设计`、`test-cases.md=测试用例`、`test-report.md=测试报告`。
- `scripts/lib/core.mjs` 的 `DOC_ORDER` / `orderedDocs()`：文档页签的存在性与顺序口径（仅列出条目目录中实际存在的 `.md`）。
- `scripts/web/style.css`：`.drawer-body`、`.meta-grid`、`.drawer-actions`、`.tabs` / `.tab` 等既有样式可复用。
- 适用范围：需求（REQ）与 Bug（BUG）两类条目的详情抽屉；讨论单（ASK）详情在讨论模块（`scripts/web/oncall.js`），不在本需求范围。

### 界面布局

抽屉头部（返回按钮、编号与复制、关闭、测试标记、标题）保持不变；头部下方新增一行页签栏，五个页签从左到右固定为「基本信息 / 说明 / 设计 / 测试用例 / 讨论纪要」，页签栏下方为当前页签的内容区，内容区独立滚动。

各页签内容与来源：

| 页签 | 内容 | 来源 |
| --- | --- | --- |
| 基本信息（默认激活） | 状态/类型/归属/认领者/创建/更新/最近报告等 meta-grid、完善徽标、Agent 已上报提示、操作 notice 与状态操作按钮、下属 Bug 列表、批量执行设置（依赖 + 本项 Codex 模型） | 现 `drawer-body` 文档页签之前的各区块整体迁入 |
| 说明 | README.md 渲染内容 | 现「说明」文档页签 |
| 设计 | design.md 渲染内容 | 现「设计」文档页签 |
| 测试用例 | test-cases.md 渲染内容 | 现「测试用例」文档页签 |
| 讨论纪要 | 需求讨论列表与「＋ 发起讨论」入口（REQ-20260908-022） | 现 `reqDiscussionsHtml()` 区块 |

- 上一条/下一条导航不放进任何页签内容区，固定在页签栏之外（实现位置可为抽屉头部或基本信息操作行），保证任意页签下都能切换条目。
- `test-report.md`（测试报告）不在五页签之列：默认保留为「测试用例」之后的附加页签，仅文件存在时出现，测试报告入口不因本改造丢失；是否改为并入「测试用例」页签待确认。
- Bug 单当前无讨论绑定能力（`reqDiscussionsHtml()` 仅需求单渲染）：Bug 的「讨论纪要」页签显示空态说明；Bug 是否支持发起/关联讨论待确认，本需求不新增该能力。
- 设计 / 测试用例文档在部分条目（如刚创建、尚未进入开发）不存在：默认五个页签固定显示，缺失文档的内容区给空态提示（如「尚未创建，开发阶段补充」）；是否改为隐藏缺失文档的页签待确认。

### 交互行为

1. 打开或切换条目时默认激活「基本信息」；同一条目内的轮询刷新沿用现有签名对比机制（`refreshDrawer()` 的 itemJson 比对），只更新数据不整抽屉重渲染，不重置当前页签、不打断阅读与输入。
2. 页签切换为纯前端行为，点击即切换内容区，不重新拉取条目；文档页签首次激活时按现有 `loadDoc()` 加载，再次激活不重复请求。文档内相对 `.html` 链接仍由 `linkupDocDemo()` 接管弹出演示。
3. 「讨论纪要」页签内：点击讨论项进入讨论模块并打开对应讨论抽屉，「＋ 发起讨论」打开新建讨论弹窗并预填本需求——行为与现 `reqDiscussionsHtml()` / `bindReqDiscussions()` 一致，仅位置移入页签；讨论状态徽标、轮次与时间展示口径不变。
4. 状态操作按钮（接受 / 移入计划 / 驳回接受 / 移出计划 / 确认完成 / 改标题描述 / 删除等）、完善徽标跳转、测试标记等交互全部保留在「基本信息」页签内，操作后的状态流转、资格与禁用规则不变。
5. 页签用 button 实现并支持键盘 Tab 导航与可见焦点态，active 页签有明确视觉区分（沿用 `.tabs` / `.tab` 视觉语言）；窄屏下页签行可换行，不产生横向滚动。

### 状态反馈

- 正常：五个页签固定可见，「基本信息」完整呈现迁移后各区块；文档页签渲染 markdown。
- 加载：打开抽屉沿用「加载中…」整抽屉占位；文档页签首次激活显示加载态；讨论列表沿用「加载中…」并由主轮询独立刷新。
- 空态：文档缺失时内容区显示固定文案空态；「讨论纪要」在需求单无讨论时显示「尚无讨论，点击『＋ 发起讨论』…」引导，Bug 单显示 Bug 暂不支持讨论的空态（文案待确认）。
- 失败：条目拉取失败沿用 toast + 关闭抽屉；单篇文档加载失败在内容区呈现错误并可重试（具体形态：页签内错误文案 + 重试入口，或沿用全局 toast，待确认）；讨论列表失败沿用静默重试，不出现空白页签。
- 切换条目（上一条/下一条、下属 Bug 跳转、`data-goto` 链接）后页签回到「基本信息」，旧条目的文档缓存不串显到新条目。

## 验收标准

- [ ] 详情抽屉头部下方为固定页签栏，五页签顺序为 基本信息 → 说明 → 设计 → 测试用例 → 讨论纪要；打开或切换条目后默认激活「基本信息」。
- [ ] 「基本信息」页签完整包含现 `drawer-body` 文档页签之前的全部区块（meta-grid、Agent 完成提示、notice、操作按钮行、下属 Bug、批量执行设置），各操作的行为、资格与禁用规则与迁移前一致。
- [ ] 说明 / 设计 / 测试用例页签正确加载并渲染 README.md / design.md / test-cases.md，markdown 渲染与文档内相对 `.html` 演示链接弹出（BUG-20260908-021）无回归。
- [ ] 「讨论纪要」页签在需求单展示讨论列表与「＋ 发起讨论」，点击列表项能跳转讨论模块并打开对应讨论抽屉，发起讨论弹窗预填本需求（REQ-20260908-022 无回归）；Bug 单显示空态而非空白。
- [ ] `test-report.md` 存在的条目仍能查看测试报告（附加页签或并入测试用例，按上文口径），入口不丢失。
- [ ] 页签切换不重复请求已加载文档；轮询刷新不重置当前页签、不因重建抽屉导致焦点丢失；切换条目后回到基本信息且文档内容不串显。
- [ ] 文档缺失、无讨论、加载中、加载失败均有明确反馈且可恢复（重试或沿用 toast），不出现空白页签。
- [ ] 页签可键盘操作、焦点可见；窄屏页签行可换行、无遮挡与横向滚动；宽屏并排右栏与窄屏覆盖层两种抽屉形态（1020px 断点，REQ-20260907-004）均正常。
- [ ] 列表、筛选、批量操作、行选中态等抽屉外区域无回归；讨论单（ASK）详情不受影响。
- [ ] 开发阶段补充 design.md 与 test-cases.md 并通过开发阶段检查；本完善阶段只交付 README 与可离线打开的 ui-demo.html。

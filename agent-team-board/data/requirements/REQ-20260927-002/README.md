# REQ-20260927-002 版本计划添加条目时自动关联该条目的全部提交

- 状态：accepted（已接受）
- 创建：2026-09-27T06:54:47.169Z

## 描述

五步发布流程下线「一键加入依赖提交」后，添加条目面板只能单选一个关联提交，且默认值 `commits[0]` 因候选索引排序（账本 run 升序在前、git 历史追加在后）实际取到最早的收口提交：REQ-20260926-002 加入 BLD-20260923-001 时仅关联 doc 提交 1b9c0ed，feat 主提交 7c29768 不会随挑选合并进 main。

本需求让「选择条目和提交」步骤（新建版本 / 添加条目两面板共用）在勾选条目时**自动关联该条目全部应属提交**（多提交整组、一次生效），不提供逐个提交的增删入口。

**自动关联口径**：

- 自动关联 = 收口账本核验提交（`committedItemIndex`）∪ 提交主题末尾单号严格归属（`subjectAttributionItemId`）命中的提交；
- 宽口径（主题任意位置含单号即关联，如 `6f2ead6` 大杂烩批量提交挂两百余单号）命中不进入自动关联，仅在面板内折叠展示「另有 N 个宽口径命中未关联」只读提示（如确需纳入，经版本详情换选调整）；
- 自动关联集为空时，回退为宽口径命中中最新的 1 个提交并标注回退来源，保证条目仍可加入版本；
- 提交按旧→新排序展示。

**数据链路现状**：后端 `addItems` / `createVersion` 已支持 `commits` 数组（`normalizeRow` 读 `raw.commits`），改动集中在前端两面板（createPanel / addPanel 的单值 commits map → 数组 map、整组自动关联逻辑与只读列表展示、payload 组装）与候选接口的提交元数据（需区分 账本核验 / 严格归属 / 宽口径 供前端自动关联）。换选（单提交整体替换）与已合入锁定语义不变。

## 验收标准

- [ ] 勾选条目即自动关联其全部自动关联口径提交（账本核验 ∪ 主题末尾单号严格归属），整组一次生效，不提供逐个提交的增删入口。
- [ ] 关联提交以只读列表展示，按旧→新排序，每项展示短 hash + 提交主题（含类型前缀），并标注来源（账本核验 / 严格归属）。
- [ ] 宽口径命中不进入自动关联，仅折叠展示「另有 N 个宽口径命中未关联」只读提示。

- [ ] 保存后版本计划条目行 `commits` 数组与自动关联结果一致，版本详情展示全部关联提交；创建版本与添加条目两口级行为一致。

### 界面布局

「选择条目和提交」侧滑面板（新建版本 / 添加条目两面板共用同一结构，仅标题、顶部字段与底部主按钮文案不同）：

- 面板头：标题 + 关闭（✕）按钮。创建面板标题「新建版本计划」，添加面板标题「添加条目」（待确认：以实现文案为准）。
- 面板体（自上而下）：
  1. 仅创建面板：版本名称输入框（留空自动命名「版本 YYYYMMDD-HHMM」）与版本号输入框（x.y.z，留空自动递增），置于候选清单之前（BUG-20260922-006 口径：候选加载中也可先行填写）；
  2. 候选操作条：「全选」「全不选」按钮 + 「已选 N 项 · M 个提交」实时计数（M 为已选条目自动关联提交数之和，回退提交计入）；
  3. 候选清单：每行 = 条目复选框 + 条目单号与标题。勾选后行内展开「关联提交（自动关联 N 个 · 旧→新 · 只读）」区块：逐项展示短 hash + 提交主题（含类型前缀）+ 来源徽标（自动·账本 / 自动·归属 / 回退·宽口径）；行内没有逐个提交的增删控件（无下拉、无删除按钮）；
  4. 宽口径命中折叠行：「另有 N 个宽口径命中未关联」只读提示，可点开展开查看 hash + 主题，不可勾选、不计入 M。
- 面板底：主操作按钮，创建面板「创建版本计划」、添加面板「添加条目」。

### 交互行为

- 勾选条目复选框 → 整组自动关联该条目全部自动关联口径提交（收口账本核验 ∪ 主题末尾单号严格归属），提交列表按旧→新展开；取消勾选 → 整组收起并从计数与保存 payload 中移除。
- 单个提交不可单独增删；提交的调整仍走版本详情条目行的换选（单提交整体替换，REQ-20260915-003 口径），该语义不变。
- 「全选 / 全不选」仅作用于可勾选条目；自动关联集与宽口径命中皆空的条目行禁用，提示「暂无关联提交（先完成开发提交）」。
- 自动关联集为空且存在宽口径命中 → 回退关联宽口径命中中最新的 1 个提交，徽标标「回退·宽口径」，保证条目仍可加入版本。
- 保存 payload 中条目的 `commits` 为数组（整组提交，每项 40 位 hash），不再有单值 commit 选择；两面板（创建版本 / 添加条目）行为一致。

### 状态反馈

- 候选加载中：清单区显示「正在读取条目…」；加载失败：面板内错误行 + 「重试」按钮，重试成功回到正常清单。
- 空态分两种（BUG-20260914-004 口径）：无已完成条目 →「暂无可纳入版本的条目」；已完成条目均已被其他版本占用 →「已完成的条目均已纳入版本计划：可从「计划中 / 失败」版本移出条目，或删除版本后重新纳入」。
- 保存中：主按钮置 busy（「创建中… / 添加中…」）并禁用；失败：面板内错误行回显服务端报错（如 commits 元素非 40 位 hash、空数组被拒绝的校验文案），不清空已选状态，可修正后重试；成功：面板关闭并刷新版本列表，新条目行展示全部关联提交短 hash。
- 徽标以颜色 + 文字双重区分（不只靠颜色）：自动·账本（收口账本核验命中）/ 自动·归属（主题末尾单号严格归属命中）/ 回退·宽口径（自动集为空时的兜底）。

### 旧行为对照（缺陷现象，演示页可切换）

旧行为：条目行内为单选下拉，默认选中 `commits[0]`；因候选提交索引按账本 run 升序在前、git 历史追加在后排序，`commits[0]` 实际取到最早的收口提交——REQ-20260926-002 加入 BLD-20260923-001 时仅关联 doc 提交 1b9c0ed，feat 主提交 7c29768 不会随挑选合并进 main。新行为取消逐个提交选择，改为整组自动关联。

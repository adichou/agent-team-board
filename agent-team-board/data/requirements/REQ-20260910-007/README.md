# REQ-20260910-007 支持快捷键

- 创建：2026-09-10T00:41:45.396Z
- 状态以同目录 status.json 为准。

## 描述

为 Status Board 增加可发现、可通过键盘完成的常用导航操作，减少搜索与查看详情时在键盘和鼠标之间切换。快捷键只触发现有界面入口对应的行为，不直接接受、计划、删除条目或启动批次。

### 现状与范围

项目 `scripts/web/app.js` 已有详情抽屉左右方向键切换及 Escape 关闭浮层逻辑；`scripts/web/index.html` 已有当前模块搜索框 `searchInput`。本需求在这些入口上统一快捷键说明与生效条件，不应重复注册导致单次按键执行两次。

以下为本次补全的交互契约（开发前「待确认」项已确认，结论见 design.md「键位与页面覆盖」：键位即下表；覆盖看板单页全部模块；当前讨论模块内嵌同一页面、无独立 oncall 页面；不做桌面原生全局快捷键与自定义键位）。演示仅展示网页内方案。

### 界面布局

在看板顶栏增加「快捷键 ?」按钮；当前模块搜索框旁显示 `/` 提示。帮助面板居中展示“操作 / 按键 / 生效条件”列表，窄屏可滚动且关闭按钮始终可达。详情抽屉保留上一条、下一条按钮，同时标注方向键。所有操作保留鼠标入口和清晰的键盘焦点样式。

### 交互行为

| 按键 | 行为 | 生效条件 |
| --- | --- | --- |
| `/` | 聚焦当前模块搜索框 | 无弹窗且焦点不在可编辑区域，搜索入口可用 |
| `?` | 打开快捷键帮助 | 焦点不在可编辑区域且无其他弹窗；重复按键不叠加面板 |
| `←` / `→` | 当前筛选列表中上一条 / 下一条详情 | 详情已打开、无弹窗、非输入态；边界停止，不循环 |
| `Esc` | 关闭最上层可关闭面板 | 一次只关一层；关闭后恢复至打开入口，入口不存在时回到合理的可见控件 |
| `Tab` / `Shift+Tab` | 顺序移动焦点 | 沿用原生规则；模态帮助开启时焦点留在帮助内 |

输入框、文本域、下拉选择、contenteditable 及中文输入法组合输入期间，不响应 `/`、`?`、方向键导航。忽略按住键产生的重复事件；未匹配的按键、带 Ctrl/Meta/Alt 的组合键保留浏览器默认行为。Escape 仍按浮层自己的关闭规则执行，遇到未保存内容沿用该界面既有保护规则，不新增自动保存或丢弃语义。

### 状态反馈

正常触发后用焦点或详情标题变化反馈；到达首尾时按钮禁用并提示“已是第一条 / 最后一条”。无条目时显示空态，方向键不打开空详情。加载期间禁用依赖列表数据的导航，帮助与关闭仍可用。加载失败显示错误及重试按钮，不把失败当作空列表，也不执行依赖失败数据的跳转。不可用操作不产生业务请求。帮助内说明输入态不触发快捷键；不对每次普通文字输入弹提示。

## 验收标准

- [ ] 顶栏帮助入口和搜索键位提示可见，帮助列出键位、作用域及输入态限制；按钮均可由键盘访问。
- [ ] 在可用看板页面按 `/` 聚焦当前模块搜索框；在输入框、contenteditable 或中文组合输入中输入相同字符不触发导航，也不吞字符。
- [ ] `?` 打开一份帮助，焦点进入帮助，Tab 双向移动不离开模态；关闭恢复打开前焦点。
- [ ] 详情内左右方向键与按钮使用同一当前筛选顺序；首尾不循环，输入态与其他弹窗开启时不切换。
- [ ] Escape 一次关闭最上层面板；现有项目管理、新建与详情的关闭优先级不被破坏，未保存保护沿用原规则。
- [ ] 正常、空、加载、失败状态均有明确反馈；加载与失败时不导航至无效条目，重试成功后恢复操作。
- [ ] 单次按键只触发一次动作，长按不连发；未声明及带 Ctrl/Meta/Alt 的组合键不被拦截，不直接执行任何状态变更或批次启动。
- [ ] ui-demo.html 可离线直接打开，鼠标入口与键盘入口均可交互，帮助、状态切换及失败重试可演示。
- [ ] 开发前确认具体键位与页面覆盖范围，并在本说明更新「待确认」项；design/test-cases 留至开发阶段。

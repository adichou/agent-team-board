# REQ-20260908-027 选择功能混乱，需要重构

- 状态：accepted（已接受）
- 创建：2026-09-08T15:45:17.104Z

## 描述

1、在哪个状态界面选择，就只针对当前界面的单子进行批量操作，例如在已接受状态界面选择，就只会显示移入计划，驳回待接受两个操作。
2、提供全选和全不选功能，全选只需要打勾，不需要边框变蓝色

### 现状与问题定位（Status Board 需求列表）

看板为六档筛选（待接受 / 已接受 / 已计划 / 开发中 / 待测试 / 已完成，见 `scripts/web/app.js` 的 `LANES` / `REQ_FILTERS`），复选框只出现在待接受 / 已接受 / 已计划三档的列表行上（`scripts/web/app.js` `reqRowEl`，`data-select-id` / `data-plan-id` / `data-impl-id`）。当前实现存在以下与需求冲突的点：

- 三档勾选集合互相独立且跨档保留（BUG-20260907-016 契约：切档不丢勾选），而选择工具条 `#selectionBar`（`scripts/web/index.html`）把三类勾选合并计数为「已选 N 项（待接受 x · 已接受 y · 已计划 z）」（`scripts/web/app.js` `syncAcceptance`），且「接受所选 / 移入计划 / 进入批量开发 / 移出计划 / 批量完善 / 清空选择」全部按钮常驻显示，与当前所在档无关——不同档的勾选与操作在同一个工具条里混杂，是「选择功能混乱」的直接来源。
- 已接受档只有批量「移入计划」（REQ-20260908-018），没有批量「驳回待接受」；驳回目前仅详情页单条「驳回接受（退回待接受）」（REQ-20260907-011，`accepted → submitted`，服务端状态机已支持，见 `scripts/lib/core.mjs` `TRANSITIONS`）。
- 全选 / 全不选入口不成对：现有「选择可操作项」（REQ-20260907-009，仅当前筛选档）与「清空选择」（一键清空三类勾选，`scripts/web/app.js` `clearSelections`），后者口径跨档，与「全不选」预期不符。
- 勾选行会被加 `.req-row.selected` 类，样式为主题蓝边框（`scripts/web/style.css` `.req-row.selected { border-color: var(--primary) }`）；用户要求全选的视觉反馈只有打勾，不要边框变蓝。

### 目标行为

1. 选择工具条按当前筛选档收窄：只显示、只统计、只作用于当前档的单子与该档对应的批量操作——
   - 待接受档：「接受所选」（批量接受）；
   - 已接受档：「移入计划」+「驳回待接受」（批量驳回为新增，逐条 `accepted → submitted`，口径对齐批量移入计划 `moveToPlan`：逐条流转、单项失败不回滚、失败项保留勾选便于重试；完善中 `refineState=refining` 的单被服务端拦截并计入失败清单，对齐 `scripts/lib/core.mjs` `setStatus` 现有校验）；
   - 已计划档：「进入批量开发」+「移出计划」；
   - 开发中 / 待测试 / 已完成档：无可勾选条目，工具条隐藏。
2. 提供成对的全选 / 全不选入口，均只作用于当前筛选档（叠搜索范围，保持 REQ-20260907-009 口径）；全选后行仅有复选框勾选态，不出现行级主题色边框高亮。

## 验收标准

需求 1 —— 批量操作按当前档收窄：

- [ ] 选择工具条仅呈现与当前筛选档匹配的操作按钮：待接受档只显示「接受所选」；已接受档只显示「移入计划」「驳回待接受」两项；已计划档只显示「进入批量开发」「移出计划」；不再出现跨档按钮同屏混排。
- [ ] 工具条计数只统计当前档勾选（不再显示「待接受 x · 已接受 y · 已计划 z」三类合并计数）；当前档勾选为 0 时工具条隐藏。
- [ ] 批量操作只作用于当前档的单子，不波及其他档的残留勾选；操作完成后仅当前档勾选被消费。
- [ ] 已接受档新增「驳回待接受」批量操作：勾选的已接受条目逐条 `accepted → submitted`；单项失败不回滚整批，失败项保留勾选可重试；结果区成功 / 失败分列反馈（对齐批量移入计划 `moveToPlan` / 批量移出计划 `removeFromPlan` 的既有交互）。
- [ ] 完善中的已接受单在批量驳回中会被拒绝并计入失败清单（提示与详情页 / CLI 同口径：完善中，待本轮批量完善结束后再驳回）。

需求 2 —— 全选 / 全不选与视觉反馈：

- [ ] 列表区提供成对「全选 / 全不选」入口：全选仅勾选当前筛选档内可见的可操作条目（叠搜索范围）；全不选仅取消当前档勾选；当前档无可操作条目时全选禁用。
- [ ] 全选后行只有复选框打勾，不出现主题蓝行边框（现状 `scripts/web/style.css` `.req-row.selected` 的 `border-color: var(--primary)` 不因全选出现）。
- [ ] 全不选后当前档计数归零、工具条隐藏；勾选单独取消时计数与按钮可用性同步更新。

状态反馈（随重构保持不回退）：

- [ ] 批量操作进行中：对应按钮禁用并显示进行中文案与逐条进度（如「移入中…」+「正在移入计划 1 / 3…」），进行中复选框与全选 / 全不选不可操作（防误触）。
- [ ] 批量操作完成：结果区（role=status）呈现成功数与失败清单（`id：原因`），失败项保留勾选；轮询刷新不重建列表行、不打断勾选状态（保持现有增量渲染策略）。

## 界面展示

可交互演示：[./ui-demo.html](./ui-demo.html)（单文件、无外网依赖，浏览器直接打开）。

- 界面布局：自上而下为状态筛选条（六档 chips + 各档计数，当前档高亮）→ 列表标题行（条目计数 + 排序占位 + 「全选 / 全不选」成对入口）→ 选择工具条（仅当前档勾选 > 0 时出现：当前档计数 + 该档专属批量操作按钮 + 清空选择）→ 批量结果区（成功 / 失败分列）→ 条目列表（行内：勾选框、单号、状态徽标、标题、认领人 / 更新时间；仅待接受 / 已接受 / 已计划行有勾选框）。
- 交互行为：切档后列表与工具条整体切换——在已接受档勾选即出现「移入计划」「驳回待接受」两个操作，切到待接受档则只剩「接受所选」；其他档的勾选保留（切回可见），但不参与当前档计数与操作；「全选」仅勾当前档可见可操作条目，「全不选」仅清当前档；演示页另提供「旧版蓝边框对比」开关，可对照勾选行边框变蓝的现状。
- 状态反馈：批量操作逐条推进（进行中文案 + 进度），完成后结果区分列成功 / 失败，失败项保留勾选；完善中的已接受单在「驳回待接受」中被拒绝并提示原因；空档显示「当前档暂无条目」，「刷新」模拟加载态；「模拟失败」开关可演示部分失败场景；支持深浅色（跟随系统）。

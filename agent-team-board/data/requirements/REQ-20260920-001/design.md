# 设计 — REQ-20260920-001 分支浏览界面的 git 历史树展示要展示分支合并记录，而不是现在的平铺。具体展示效果可查看截图

> 由 Agent 在 /dev 开发前补充，人可随时批注。

## 背景

「构建 → 分支浏览」右侧提交列表目前是平铺行（短 hash / 主题 / 作者 / 时间），
看不出分叉与合并。README「已核实的现状与范围」已锁定：连线必须以真实父提交
关系为依据，仅浏览只读，不新增 checkout / merge / rebase 等操作。

## 方案

### 1. 后端：提交记录附带父提交（scripts/lib/build-git.mjs）

- `branchLog` / `branchSearchLog` 的 `git log --format` 增加 `%P`（父提交 hash，
  空格分隔），解析为 `parents: string[]`（根提交为 `[]`）。两条路径口径一致，
  分页 / 搜索响应形状不变、仅每条 commit 多一个字段（旧前端不读该字段无影响）。
- server.mjs `/api/build/branch-log` 路由不动（透传数据层），仅补注释。
- 只读不变：仍是 `git log`，无任何写操作。

### 2. 前端：拓扑轨道图（scripts/web/build.js + style.css + i18n.js）

- **纯函数 `logGraph(commits, { hasAbove })`**（vm 测试接缝，经 `window.ATBBuild` 导出）：
  按 git log --graph 同型思路自研轨道布局——
  - 输入 commits（新→旧，含 `hash` / `parents`），维护「延续线」数组 `lanes`
    （下标即列 x 位置，每线带 hash 与颜色号）。
  - 逐行处理：本提交命中已有线 → 该线终止于节点（取其列与颜色）；未命中
    （搜索过滤 / 跨页断档）→ 新分配列，且该行有真实父提交时画**上方虚线短桩**
    （stubAbove，表示上下文未显示，不误判为根）。
  - 父边逐个按 `%P` 顺序生成：父在已展示集合 → 实线边（第一父优先复用本节点
    原列保持直线，其余父向右分叉新列或汇入已有列）；父不在集合（搜索隐藏 /
    页边界未加载）→ **虚线父边**并计入 `hiddenParents`，不进入下一行延续线
    （不与后续真实线混淆）。根提交（parents 空）无任何向下边。
  - 输出每行 `{ hash, lane, segments[{x1,x2,color,dashed}], merge, parents, hiddenParents, stubAbove }`
    与 `laneCount`；同一提交只出现一次（输入即 git log 去重序列）。
  - `hasAbove = offset > 0 || 搜索态`，只影响首行的上方虚线桩判定。
- **渲染**：每行 `<li>` 左侧新增固定对齐 SVG 列（viewBox 宽随 laneCount 自适应、
  行高一致、flex-shrink:0，窄屏随既有横向滚动容器不断行错位）；行内容包进
  `<button type="button" data-log-row="<hash>">`（键盘可达，click / focus 均触发
  选择）。合并节点双圈 + 文字标签「合并 · N 父提交」（非仅颜色）；选中行高亮，
  列表上方 `role="status"` 详情区显示该提交与父提交标识（根提交显示
  「无父提交（根提交）」）。
- **状态与文案**：既有加载 / 空 / 搜索无结果 / 首次失败 / 翻页失败（保留旧内容 +
  重试）口径全部不动，图仅替换行渲染。搜索隐藏中间提交时顶部加说明行；页边界
  有未加载父提交时列表尾加「父提交在后续页，轨道继续」提示；带隐藏父边的行内
  加「N 个父提交未显示（虚线延续）」文字说明（照顾无法辨色用户）。
- **颜色**：6 色轨道调色板走 CSS 变量 `--git-lg0..5`，浅色 / 深色
  （prefers-color-scheme）各定义一组；虚线、节点描边、选中态同用既有变量体系。

### 3. 开源选型（REQ-20260909-015：自研理由——引入成本高于自研）

评估过 `@gitgraph/core`（MIT）等 git 图库：均按 npm + 打包器（ESM bundler）分发、
面向完整交互式 gitgraph 组件，本产品前端为零构建静态 `<script>` 加载，引入需新增
打包工具链或 vendor 整库（违反「禁止复制库源码进仓库」前提）；且本单的
「隐藏上下文虚线断点 / 页边界延续 / 非颜色合并标识」是贴合本产品搜索分页语义的
定制渲染，通用库反而要绕开其模板管线。轨道布局为约百余行纯函数，无合适可直接
复用的零依赖 UMD 分发库，故自研，不引入依赖，不建 licenses.md。

## 风险与边界

- 后端 `%P` 是纯增量字段；`branchSearchLog` 全量读取口径不变。
- 布局为启发式轨道（非 git 内核 graph 算法），验收口径是「连接关系与 Git 数据
  一致、无假连线 / 漏父边 / 重复节点」，不追求与 `git log --graph` 列位逐格一致。
- 仅浏览只读：不新增任何 git 写路径，不切换工作区分支。
- i18n：新增文案全部落 scripts/web/i18n.js（EN 静态 + EN_DYNAMIC 插值），
  中文原文为键，值无中文、值唯一。

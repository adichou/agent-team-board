# REQ-20260922-001 命令看板中要隐藏那些只能在 AI Agent 中执行的命令，例如 AI 开发，AI 分析相关的

- 创建：2026-09-21T23:29:01.498Z
- 状态以看板实时记录为准；本文只描述需求，不改变条目状态。

## 描述

看板「命令」模块（REQ-20260920-004）目前把命令注册表的全部分组平铺给人用：其中「AI 开发（`batch *`）」「AI 分析（`refine *`）」以及同类的「发布文档 AI 总结（`summary *`）」「发布文档 AI 翻译（`translate *`）」「执行回执（`run *`）」等命令是 AI Agent 工作流的一部分——由主调度会话创建 / 核对批次、由 worker 子 Agent 领取（`batch next` / `refine next`）并回执（`run receipt` / `refine done` / `summary done` 等），所需 RUN-ID、批次 ID、会话标识等上下文都只存在于 Agent 会话里。人工在看板上看到并尝试执行这些命令，只会得到「缺少上下文 / 参数无从填写」的挫败体验，且徒增清单噪音、误触发风险（如 `refine abort`、`batch delete` 这类高危命令对人工毫无操作场景）。

本单要求：在命令看板（命令模块的「全部命令」列表、「最近执行」页签等所有入口）中**隐藏这些只能在 AI Agent 中执行的命令**，让人工入口只呈现人工可用的命令。隐藏仅限看板展示层，`atb` CLI 命令面不变——Agent 继续在各自会话中以 CLI 使用这些命令，白名单安全模型与注册表 / CLI 同步校验机制不受影响。

### 已核实的现状

- 命令清单唯一事实源是服务端注册表 `scripts/lib/cli-registry.mjs`（`GET /api/cli/commands`，前端不手抄清单）；当前分组：数据与分发、条目生命周期、AI 开发（`batch create|next|check|summary|pause|records|delete`）、执行回执（`run receipt|release|autocommit`）、人工决策（`hold declare|list|show|answer|resume|cancel`）、挂起确认（`confirm list|show`）、AI 分析（`refine create|next|done|fail|release|check|summary|pause|abort|records`）、发布文档 AI 总结（`summary start|file|done|fail|show`）、发布文档 AI 翻译（`translate start|file|done|fail|show`）、查询、服务、终端命令（`cli *`，界面已禁用并指引终端）。
- 这些命令确属 Agent 工作流：批量开发 / 完善由主会话建批、子 Agent `batch next` / `refine next` 领取并回执（`skills/agent-team-board/batch-execution.md`）；`run receipt` 等回执由执行 Agent 上报；发布文档三阶段流程的总结 / 翻译回执（`summary *` / `translate *`）同样由 AI 执行轮次上报。
- `claim` / `report` 是 Agent 的常规状态操作（根 `AGENTS.md`：「Agent 的常规状态操作只有 claim 与 report」）；`hold declare` 是 worker 声明待人工决策——三者属 Agent 例行命令，但与人工命令同组（条目生命周期 / 人工决策组）。
- 「最近执行」按项目持久化在 localStorage（BUG-20260921-010，`atb.cmd.recents:<项目>`），隐藏生效后其中残留的被隐藏命令不得继续展示。
- 注册表与 CLI 的同步性由测试兜底（`scripts/tests/req-20260920-004.test.mjs` C1 双向比对）；隐藏不得以「从注册表删除命令」的方式实现，否则破坏该校验与 CLI 命令面。

### 隐藏范围（默认清单）

判定口径：**AI Agent 工作流命令**——由 Agent 会话创建 / 领取 / 回执 / 调度，人工经界面执行无意义或无上下文（RUN-ID / 批次 ID / 会话标识）的命令。按此口径默认隐藏：

- 整组隐藏：**AI 开发（`batch` 全组）**、**AI 分析（`refine` 全组）**（需求标题点名）、**发布文档 AI 总结（`summary` 全组）**、**发布文档 AI 翻译（`translate` 全组）**、**执行回执（`run` 全组）**——五组全部命令在看板命令模块不可见。
- 组内隐藏（属 Agent 例行操作，与人工命令同组，隐藏后组内其余命令保留）：`claim`、`report`（条目生命周期组）、`hold declare`（人工决策组）。**此三命令是否纳入本单隐藏范围待人工确认**（见「待确认」）；确认前按「默认隐藏」设计演示。

保留给人用的：数据与分发（`init` / `migrate` / `rebuild` / `pack`）、`new req|bug` / `rename` / `delete` / `status` / `move` / `prune-locks`、`hold list|show|answer|resume|cancel`、`confirm list|show`、查询（`list` / `show` / `commit log` / `commit which`）、`serve`、终端命令（维持现状：禁用 + 终端指引）。

### 非目标（不做什么）

- 不改 `atb` CLI：命令面、参数、行为全部不变，Agent 会话照常使用被隐藏的命令。
- 不删除命令：命令仍保留在注册表中（`findCommand` 白名单查找、CLI 同步测试口径不变），只是不进入看板命令模块的展示与执行入口；具体实现层级（注册表标记后由 `GET /api/cli/commands` 过滤、还是前端过滤）留 design.md。
- 不隐藏专用界面已承载的人工能力（需求页接受 / 计划 / 确认完成按钮、任务页批量面板等）。
- 不新增「显示 AI 命令」开关：本单为直接隐藏，不做可切换展示。

## 界面布局

- 整体布局不变（REQ-20260920-004）：左缘竖排页签（最近执行在前且默认 / 全部命令）+ 平铺命令列表，右侧命令详情与执行，下方执行历史（最近 20 次）。
- 「全部命令」列表中上述隐藏范围的分组 / 命令不再出现：整组隐藏的五个分组整体消失；组内隐藏的命令从所属分组中消失，分组标题与其余命令保留。列表其余部分（分组顺序、按钮形态、高危 / 影响提示 / 终端执行标识）不变。
- 「最近执行」页签同步过滤：持久化记录中属隐藏范围的命令不再展示，其余记录顺序保留。
- 执行历史为会话内执行记录（含隐藏生效前的旧记录），保留可回看；隐藏命令不再有新的执行产生，不强制清除历史旧记录（是否过滤历史中的隐藏命令留 design.md，验收不要求）。

## 交互行为

- 点击保留命令 → 右侧详情、参数表单、命令预览、执行、输出回显：行为与现状完全一致，无新增交互。
- 被隐藏命令在看板命令模块内无任何入口：不出现在「全部命令」列表、「最近执行」页签；搜索框输入被隐藏命令名或说明关键词（如 `batch`、`refine`）同样搜不到（按「无匹配命令」空态处理，见「状态反馈」）。
- 深链 / 状态残留：若隐藏前已选中某被隐藏命令，隐藏生效后进入模块不再回显该命令详情（回到未选中空态）；localStorage 中该命令的最近执行记录被忽略（不展示、不报错）。
- 高危确认、必填校验、执行历史回看等既有交互对保留命令不变。

## 状态反馈

- 正常：列表只呈现保留范围命令；整组隐藏后相邻分组直接衔接，无空分组标题残留。
- 空：搜索无匹配时显示「无匹配命令」并给清除入口——搜索被隐藏命令名（如 `batch`）同样落入此空态，不提示「该命令已隐藏」（避免暗示存在感），文案沿用现状。
- 加载 / 失败：清单加载中、读取失败的状态反馈与重试入口沿用现状，不受隐藏影响。
- 降级：若 localStorage 最近执行数据全部由隐藏命令构成，该页签显示现状空态提示（引导切换「全部命令」），不显示空白。

## 界面展示

布局、交互与状态反馈的文字说明见上文「界面布局 / 交互行为 / 状态反馈」三节；可交互演示见 [ui-demo.html](./ui-demo.html)（单文件、内联 CSS/JS、无外网依赖、浏览器直接打开）。演示提供「现状（显示 AI 命令）/ 需求后（隐藏）」对照开关：现状侧可见 AI 开发、AI 分析、AI 总结、AI 翻译、执行回执五组及 `claim` / `report` / `hold declare`；需求后侧这些入口整体消失（含组内命令隐藏对分组的影响），并可验证搜索 `batch` 在需求后落入「无匹配命令」空态、最近执行中残留的 `batch next` 记录被过滤、清单加载中 / 读取失败状态、保留命令（如 `hold list`）的详情与执行反馈（成功 / 无输出 / 失败）。演示中的命令执行全部为本地模拟，不产生真实副作用。

## 验收标准

- [ ] 命令模块「全部命令」列表中不再出现：`batch` 全组、`refine` 全组、`summary` 全组、`translate` 全组、`run` 全组（五个分组及其命令整体不可见，无空分组标题残留）。
- [ ] `claim` / `report` / `hold declare` 按人工确认结论处理（默认隐藏：若确认维持默认，则三条命令从所属分组消失且 `new req|bug`、`rename`、`delete`、`status`、`move`、`prune-locks`、`hold list|show|answer|resume|cancel` 等保留命令不受影响）。
- [ ] 保留范围命令的行为与现状一致：详情、参数表单、命令预览、执行、输出回显、高危二次确认、必填校验均不变。
- [ ] 「最近执行」页签不展示隐藏范围的命令（含 localStorage 持久化的历史残留记录：被忽略而非报错）；记录全为隐藏命令时显示空态提示。
- [ ] 搜索框输入隐藏命令名或其说明关键词（如 `batch`、`refine`、`run receipt`）时落入「无匹配命令」空态并可清除搜索恢复；搜索保留命令仍正常过滤。
- [ ] 隐藏仅作用于看板命令模块：`atb help` 命令面不变；被隐藏命令在终端与 Agent 会话中照常可用；注册表仍包含全部命令，与 CLI 的同步校验测试（req-20260920-004 C1 口径）不回归。
- [ ] 清单加载中 / 读取失败 / 空态等状态反馈不因隐藏而缺失或异常。
- [ ] 界面文案若涉及改动，中英文同步（`scripts/web/i18n.js`）；`ui-demo.html` 可独立打开并覆盖现状 / 需求后对照、隐藏生效后的列表与搜索空态、最近执行过滤演示。
- [ ] 既有专用界面按钮与行为不受影响；任务页批量面板等由专用界面承载的能力照常可用。

## 待确认（留人工决策或开发阶段）

- `claim` / `report` / `hold declare` 三条组内命令是否随本单隐藏（上文按「默认隐藏」编写描述与演示；若人工结论为不隐藏，验收第二条相应调整）。
- 隐藏的实现层级（注册表标记 + API 过滤 / 前端过滤）与 `/api/cli/run` 是否对隐藏命令同步拒绝下发（防绕过界面直接调接口）留 design.md；本单验收只约束看板命令模块内不可见、不可执行。
- 执行历史（会话内最近 20 次）中隐藏生效前的旧记录是否过滤留 design.md；验收不要求。

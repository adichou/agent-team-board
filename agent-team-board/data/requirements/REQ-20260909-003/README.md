# REQ-20260909-003 需求文档引用讨论、纪要归档与说明同步

## 背景与目标
在 REQ-20260908-022 的需求绑定讨论基础上，面向单人使用优化文档讨论。实际对话在 Agent 新会话内完成，看板负责复制引用、讨论纪要归档和说明同步，不提供看板聊天或每轮派单。

## 现状核实与范围

本轮对照当前代码核实：`scripts/lib/oncall-store.mjs` 的 `createTicket` 已保存 `reqId`，`reqContext` 已读取关联需求的 README/design/test-cases；`scripts/web/app.js` 的 `reqDiscussionsHtml` / `refreshReqDiscussions` 已提供需求讨论入口与列表，现有入口进入 Oncall 问答流程。因此基础需求 REQ-20260908-022 的早期说明中“尚无绑定入口”不再代表当前实现。

当前 `buildOncallWorkerPrompt` 仍服务派单回答；本项新增的是用户在外部原会话持续讨论的文档工作流。文件查看器 `buildCodeView` 已有源码行号复制，但阅读模式的选文与 Markdown 源行映射、引用版本快照、成套纪要/修改草稿发布与人工应用，在本轮检查的 `scripts/web`、`scripts/lib`、`scripts/server.mjs` 中尚未找到对应实现。`demo.html` 只是已有交互参考，不代表真实功能已交付。

本项面向需求 README 的引用、归档和同步；保留现有普通讨论单能力，不把它们自动迁为本流程。Bug 绑定、开放讨论成果转需求、多会话实时聊天不纳入本项。读取 design/test-cases 作为讨论上下文不授权修改这些文档。

## 已确认流程
1. 需求详情点击「开始讨论」，先创建唯一讨论编号并绑定需求，生成含项目路径、需求编号、文档读取入口、讨论编号与落盘约定的启动提示词。用户复制到 Agent 新会话后持续交流。生成或复制提示词不表示 Agent 已连接。
2. 文档阅读模式选中句子或段落后显示「复制引用」；点击源行号可以引用整段。复制内容包含需求与讨论编号、文档路径、源行范围、版本和所选原文，方便用户粘贴至原 Agent 会话补充问题。看板保存引用快照，复制记录不等于实际讨论记录。
3. 点击「讨论完毕」生成收尾提示词，要求原 Agent 会话同时输出讨论纪要与说明修改草稿。看板显示等待纪要反馈，不能仅因复制提示词就认为纪要已生成。
4. Agent 完整落盘后，看板自动读取并展示纪要与草稿。纪要区分明确共识、Agent 建议、未决问题、原文引用、建议修改与后续行动。
5. 仅明确确认的结论进入 README 修改草稿；未确认建议和未决问题不默认纳入。每项修改关联纪要依据，显示修改前后内容，可勾选、取消。
6. 用户「确认应用」后更新勾选的说明内容，保存修改前版本，记录来源讨论、应用结果与时间。不自动改变需求状态或开始开发。纪要归档与说明同步分别操作。

## 界面布局与交互
沿用项目现有深浅色、顶栏、胶囊文档标签、按钮、详情与文档容器样式。需求详情内从上至下为：需求标题、讨论操作条、提示词预览（按需展开）、说明/讨论纪要标签与内容。
- 操作条：开始讨论、启动提示词、讨论完毕及当前操作反馈。
- 提示词区：可选择文本、复制按钮；复制失败保留文本供手工复制。
- 说明区：选文后在段落旁显示复制引用；源行范围来自 Markdown 源码映射，不能把浏览器视觉换行当行号。
- 纪要区：纪要正文、确认归档、继续讨论、说明修改草稿及逐项确认应用。
- 窄屏采用单栏文档，不再放聊天侧栏；复制按钮与所选段落相邻，所有主要操作可见。
- 引用点击可返回原文；原文变更时保留引用快照，不错误定位到无关内容。

### 状态反馈与操作边界

| 场景 | 展示与允许操作 |
| --- | --- |
| 尚无讨论 / 尚无纪要 | 各自展示空态文案；前者提供“开始讨论”，后者说明需在原会话执行收尾提示词。 |
| 创建或读取中 | 在原操作区域显示“正在创建讨论”或“正在读取纪要与草稿”，暂禁重复操作；保留已读说明和已有成果。 |
| 提示词已生成 / 已复制 | 显示绑定编号和复制结果；始终提示“请在 Agent 会话执行”，不能显示已连接、正在生成纪要等未获证实状态。 |
| 等待完整反馈 | 纪要与草稿未成套、尚未发布时维持“等待纪要与草稿”，不能开放应用按钮；“再次查看收尾提示词”始终可用。 |
| 读取失败 / 格式或绑定不符 | 显示具体原因与重试；不把上一版内容冒充新成果，不写入 README。 |
| 待确认 | 纪要六类内容可读；有明确共识依据的修改默认勾选，可逐项取消；未确认建议与未决问题只能展示，不能默认生成可应用项。 |
| 未选修改 / 无明确修改 | 显示“未选择修改”或“本次无说明修改”，禁用应用；纪要仍可独立归档。 |
| 应用中 / 应用失败 | 暂禁重复提交；失败保留选择与草稿，说明失败原因、实际写入结果及重试入口，不能提示成功。 |
| 已归档 / 已应用 | 独立标记归档与应用结果；应用显示选中项、时间、来源讨论、前版本与新版本，重复点击或刷新不会再次写入。 |

应用前需校验草稿基线仍对应当前 README；即使是单人也可能在讨论后自行编辑文件。基线不符时保留草稿与引用快照，提示“说明已变化，请在原会话重新生成草稿”，不得盲目覆盖或跳转到无关原文；这是写入保护，不增加多人冲突界面。成功写入前必须已保留旧版；一次确认中的勾选项作为一次应用结果，不能静默只应用一部分。未勾选项本次不写入，后续需基于最新说明再生成草稿。

键盘可聚焦行号、复制、标签与复选框，按钮有清晰名称与焦点样式；复制失败时展开可选择文本并说明手工复制方法。长路径与长引用可换行；在 375px 窄屏下操作条换行、内容单列，不出现页面级横向溢出。

## 界面展示

[打开单人讨论与说明同步交互演示](./ui-demo.html)。文件内联 CSS/JS，可直接离线打开，无外网或构建依赖；延续已有 `demo.html` 的单栏、深浅色、胶囊标签与逐项修改样式。

演示路径：开始讨论 → 查看/复制启动提示词 → 点击源行号或选文复制引用 → 讨论完毕 → 模拟完整反馈 → 核对共识与修改 → 独立归档 / 逐项应用 → 返回说明查看结果。顶部“演示场景”可切换正常、空态、加载和失败，失败可重试；示例编号、版本与路径仅作演示，不是已经创建的真实讨论，演示不会执行 Agent 或写入项目。浏览器本地保存演示结果以便刷新核对，无法使用本地存储时明确提示。

## 单人范围与持久化
仅单人使用，不添加多人协作、他人修改说明模拟按钮或冲突演示界面。启动时明确真实编号与落盘路径，纪要和草稿完整写入后再发布，避免半成品被读取。刷新可恢复讨论记录、纪要与应用结果；同一草稿不重复应用。讨论中不授权 Agent 自动覆盖说明；仅看板人工确认后应用。

## 验收标准
- [ ] 从需求详情创建真实绑定讨论，生成可在 Agent 新会话使用的启动提示词；收尾提示词沿用同一编号与路径。
- [ ] 支持选中文字和点击行号复制引用，原文、路径、源行范围、版本准确；换行、中文、Markdown 格式文本均可用。
- [ ] 不需要每轮看板派单，讨论在原 Agent 会话中持续完成；界面不虚构 Agent 在线状态。
- [ ] 收尾同时约定纪要和说明修改草稿；未落盘显示等待，读取失败显示错误与重试，完整文件出现后自动展示。
- [ ] 纪要明确区分共识、建议和未决问题；修改项可追溯依据并逐项选择。
- [ ] 确认应用仅写入所选修改，保留修改前版本、记录结果，不重复应用，不变更需求状态。
- [ ] 可独立归档纪要或继续讨论，刷新不会丢失已有成果。
- [ ] 窄屏单栏可完成全部流程，无聊天面板、多人冲突模拟或不必要派单步骤。

- [ ] 无纪要、创建/读取中、文件未完整发布、读取失败可明确区分；失败重试不丢已有成果，不允许将半成品应用。
- [ ] 启动、引用、收尾始终使用同一项目/需求/讨论标识；成果项目或讨论不匹配时拒绝读取为当前成果，不串单。
- [ ] 复制失败保留可手工复制文本；复制引用只产生引用快照，不伪造实际问答或用户共识。
- [ ] 只归档不改 README，只应用不强制归档；未选任何项、无明确修改时禁止应用，仍可归档与继续讨论。
- [ ] README 基线已变化时阻止覆盖；写入失败有可核对的结果，选中修改不出现无提示的部分成功，重试与刷新均不重复应用。
- [ ] 键盘、375px 窄屏与深浅色均可完成查看提示词、引用、归档和应用；演示正常/空/加载/失败状态及失败重试可操作。

## 待确认

- 真实讨论编号是否沿用 ASK，以及纪要、草稿、引用快照、README 旧版的正式目录/文件格式和发布标记协议：待确认。必须由实现生成并填入真实启动/收尾提示词，不能把演示 `DEMO` 编号与路径作为正式约定。
- “继续讨论”沿用同一讨论的纪要新版本还是新讨论关联旧成果：待确认；无论采用哪种方式，既有归档和应用记录必须保留，提示词需明确本轮标识，不能覆盖已归档版本。
- 自动检测周期、超时提示阈值、历史版本保留期限及已存在 Oncall 讨论如何进入新入口：待确认。本项不预设未经核实的 API 或 CLI 命令。
- Markdown 复杂结构（跨段选文、表格、代码块等）的映射实现方式：待确认。无法准确映射时明确提示并引导源码引用，不伪造行号；基础段落及中文多行选择必须支持。

# REQ-20260919-002 需求开发中遇到需人工决策的时候，决策界面需要优化布局

- 状态：submitted（待人工接受）
- 创建：2026-09-19T14:41:48.784Z

## 描述

### 背景与现状（已核实）

本条说的「决策界面」指开发中 worker 走 hold 流程（受阻待人工决策，见根 AGENTS.md「受阻走 hold」与 skills 口径）后，人工在看板上作答决策的两处界面：

1. **「待人工确认」持久聚合区**（看板页 `#holdArea`，REQ-20260911-007 引入）：位于看板页条目列表（`#reqList`）之后、板块尾部；`max-height: 40vh` 内部滚动，空态整体隐藏不占版面；加载失败显示错误条 + 重试。每条阻塞条目一张卡片，当前布局自上而下平铺：
   - 元信息行：条目 ID + `⚠ 等人工决策` 旗标 + 「已等待 <时长>」；
   - 条目标题；
   - 「未答 x/y」+ **全部问题平铺列表**（○ 未答加粗、✓ 已答），问题多时卡片显著拉长；
   - 操作行：**四个按钮同一行同权重平铺**——查看进展记录 / 补决策 / 复工 / 确认完成（未答 > 0 时「复工」禁用并有 tooltip 说明）；
   - 可展开「进展记录」（受阻原因 / 运行号 / 事件时间线）。
   - 看板列表行上另有 `⚠ 等人工决策` 角标（含引导到聚合区的提示文案）。
2. **「人工决策」右侧侧拉面板**（`#holdPanel`，点卡片「补决策」打开）：右侧贴边通高，宽 `min(560px, 92vw)`，≤640px 断点全屏；头部标题「人工决策 · <条目ID>」+ 范围说明 + 关闭；表单区为声明 meta 一行（声明时间 / 声明人 / 受阻原因 / 未答 x/y）+ **每个问题一组 fieldset**（问题 legend + 答复 `textarea` 固定 2 行 + 补充说明单行输入），问题多时纵向长列表；底部消息行 + 关闭 / 保存决策按钮。

既有交互口径（优化不得回退）：逐项作答可只保存部分（草稿语义）；未答 > 0 复工禁用；未答 > 0 时「确认完成」显式二次确认（越过未答完成）；Esc / ✕ 关闭面板且焦点回到触发按钮，保存中不可关闭；轮询按数据签名剪枝，不因重绘打断展开态与正在填写的内容；面板有读取中 / 读取失败（重试）/ 表单三态；看板侧 `/api/holds` 拉取失败保留上次数据 + 错误条重试。

### 布局痛点（优化动机）

1. **可见性不足**：聚合区在条目列表最尾部且限高 40vh 内部滚动；列表较长或决策项多时需滚动才能看到——而这些是阻塞开发、需人工优先处理的条目（是否调整位置或增加更醒目入口属方案取舍，**待确认**，须在 design 阶段定，本条不强制改位置）。
2. **卡片信息平铺、主次不分**：全部问题展开平铺 + 四个操作按钮同权重一行，问题多时卡片冗长，主操作（补决策 → 复工）不突出，扫读效率低。
3. **面板作答效率低**：问题多时是纵向长表单，除 meta 行外**缺少常驻的作答进度指示**（未答 x/y / 第 N 项），未答项需自行滚动寻找；答复框固定 2 行，长答复不便（是否做自适应高度**待确认**，属实现取舍）。
4. **视觉层级分散**：未答 / 已答、等待时长、旗标等信息的强调方式不统一，重要信息（缺几项、阻塞多久）不能一眼获得。

### 优化目标

在**不改变 hold 状态机、CLI（`atb hold *`）与 API 契约**的前提下，对上述两处界面做**布局层重构**（样式与前端渲染调整，纯前端改动）：

- 卡片信息分层：元信息 / 标题 / 问题摘要 / 操作区四层清晰，操作分组（主操作突出、次操作弱化）；
- 问题列表组织：未答优先呈现，已答收起或弱化，控制卡片高度；
- 聚合区可见性增强：有阻塞项时人工在一个视口内可发现（实现手段不限定）；
- 面板作答效率：常驻进度指示、未答项可达、答复输入可用性提升；
- 全部既有状态反馈与交互口径零回退，深浅色与窄屏（≤640px）均可用。

目标布局以本 README「界面布局 / 交互行为 / 状态反馈」三节与 ./ui-demo.html 演示为准；具体视觉细节（间距、配色、是否引入折叠动画等）留待 design 阶段定。

## 界面布局

以下为优化后的目标布局（对照演示见「界面展示」）：

**聚合区（看板页）**
- 区头：`⚠ 待人工确认（N）` 强调呈现（计数醒目）+ 一行说明（承接流程：补决策 → 复工回已计划队列；清单不随本轮任务结束消失）；N > 0 时整区保持可见性增强处理（区头强调 / 边界描边等手段，不强制改位置）。
- 卡片（每条阻塞条目一张）分层：
  1. 元信息行：条目 ID + `⚠ 等人工决策` 旗标，等待时长靠右弱化；
  2. 标题行：条目标题（可换行，不截断关键信息）；
  3. 问题摘要区：`未答 x/y` 计数 + 未答问题列表（加粗、置前），已答问题默认收起为「已答 n 项 ▸」可展开（或等价的弱化手段）；
  4. 操作区：分两组——主操作组（`补决策`、`复工`，视觉突出；未答 > 0 时「复工」禁用）与次操作组（`查看进展记录`、`确认完成`，弱化样式），组间有可辨识的视觉分隔或权重差；
  5. 展开记录区：受阻原因 / 运行号 / 事件时间线，默认折叠不占高。
- 多卡片纵向排列，区域内部滚动（沿用现状容器行为）；卡片内不再因问题多而无限制拉长。

**人工决策侧拉面板**
- 头部（常驻不压缩）：标题「人工决策 · <条目ID>」+ 关闭按钮；范围说明一行。
- 进度指示：`未答 x/y` 徽标常驻可见（头部或表单顶部，随保存实时更新）；问题多时问题列表独立滚动，当前填写项可达。
- 问题组（每组一项）：问题编号 + 问题文本（未答 / 已答语义色区分，沿用现状 ○/✓ 口径）+ 答复多行输入（建议随内容增高、最小 2 行，具体**待确认**）+ 补充说明单行输入（可选）。
- 底部（常驻）：消息行（保存结果 / 校验提示）+ `关闭` / `保存决策`。

## 交互行为

- **打开面板**：卡片「补决策」→ 侧拉面板拉取决策项并聚焦首个未答输入框；Esc / ✕ / 「关闭」关闭，焦点回到触发按钮；保存中不可关闭（全部沿用现状）。
- **作答与保存**：逐项填写答复（必填才计入已答）+ 可选补充说明；允许只保存部分（草稿）；保存后刷新聚合区与看板，进度指示与卡片 `未答 x/y` 同步更新。
- **复工**：未答 > 0 时按钮禁用 + tooltip「尚缺 N 项决策」；齐备后可点击，成功后条目离开聚合区回已计划队列。
- **确认完成**：未答 > 0 时显式二次确认（危险色，说明将越过未答完成），防呆保留。
- **查看进展记录**：展开 / 收起卡片内时间线，展开时拉取最新详情。
- **轮询不打断**：数据签名未变不重绘；重绘不丢失展开态与正在填写的内容（现状机制，不得回退）。

## 状态反馈

- 面板三态：读取中（加载提示）/ 读取失败（错误文案 + 重试 + 关闭）/ 表单，均保留。
- 保存反馈：部分保存提示「草稿已保存，尚缺 N 项（缺项编号）」；齐备提示「决策已齐备，可复工」；失败提示且**输入保留**可重试。
- 聚合区：拉取失败显示错误条 + 重试；空态整体隐藏不占版面；加载中状态无专门视图（现状如此，是否补充**待确认**）。
- 未答 / 已答视觉区分（○ / ✓ + 语义色）、等待时长、「复工」禁用态与 tooltip、确认完成二次确认弹层，均保留。
- 深浅色两套主题下新布局均正常可读；窄屏（≤640px）面板全屏、卡片换行无遮挡。

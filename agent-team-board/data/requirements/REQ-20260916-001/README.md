# REQ-20260916-001 AI 开发任务概括展示阻塞并集成人工确认与文档自动提交

- 状态：submitted（待人工接受）
- 创建：2026-09-16T00:53:42.097Z

## 描述

当前阻塞只隐含在任务记录中，AI 开发任务概括会显示“已结束”而没有阻塞提示。需将阻塞查看、人工确认、决策更新到需求说明/设计及自动提交文档形成可追踪流程；批次结束不等于阻塞解除或需求完成。

### 界面布局

- AI 开发任务概括区域在现有运行状态旁固定展示“阻塞 N 项 / 待人工确认 M 项”。有未解决阻塞时使用醒目图标、文字及颜色，结束批次显示“已结束 · 仍有 N 项阻塞”，不得只显示成功或结束。数量按当前项目、当前概括对应批次的条目去重，展开后列出各阻塞轮次；无阻塞显示“阻塞 0 项”。
- 点击数量展开阻塞列表：条目编号与标题、运行/批次标识、阻塞原因、等待时长、处理状态及“查看 blocker”“人工确认”入口。窄屏纵向排列、长原因换行；按钮有文字标签且支持键盘操作。
- blocker 在侧栏只读查看，显示文件路径与对应运行；缺失、读取失败、无权访问分别显示原因及重试，不将错误当无阻塞。
- 人工确认侧栏展示原问题、逐项答案输入、相关 README/design 入口及待写入文档的差异预览。未回答完整时可保存草稿，不能提交确认；用户可修改生成文本或取消。确认按钮命名“确认决策并提交文档”，旁注明仅确认实施边界。

### 交互与状态反馈

- 人工确认后将已审阅答案更新至对应条目 README.md 与 design.md，保留无关要求，记录问题/答案、运行及时间；设计不存在时创建。沿用已有 decisions.md 留痕时一并展示预览。
- 自动 Git 提交只包含此次已确认的对应文档变更，不提交业务源码、状态文件、执行账本或其他条目，不自动 push。提交前可见文件清单与差异，保存和提交期间禁用重复操作。
- 显示“待确认 / 草稿 / 正在保存文档 / 正在提交 / 已提交（短提交号） / 保存失败 / 提交失败”。失败保留答案，展示阶段及原因，提供重试；文档已落盘但提交失败必须明确显示，不能显示全部处理完成。
- 决策齐备且文档提交成功后，信息缺失类阻塞显示“决策已确认 · 待人工复工”；非决策类依赖/环境阻塞仍保持未解决。阻塞数量包含待复工项，待确认数量不包含已确认项。问题详情保留历史，不能因批次结束消失。
- 本需求不授权确认后自动恢复实施：沿用当前人工复工及批次核对入口，单独提示下一步；不得因保存答案或提交文档自动接受、置计划、认领、确认完成或重启执行。复工后的处理结果按真实运行状态更新。

## 验收标准

- [ ] 已结束批次仍有阻塞时，概括明确显示阻塞及数量，可定位条目、运行、原因和 blocker；无阻塞、加载、读取失败有独立反馈。
- [ ] 统计按项目和批次隔离，重试运行不重复计条目；同条目多轮未解决问题可逐项查看，刷新及重启后仍可追踪。
- [ ] blocker 安全只读查看；不存在或不可读可见且可重试，不能通过路径访问项目外文件。
- [ ] 人工逐项作答、草稿恢复、差异预览和取消有效；缺答案、失效问题或并发修改不能确认旧版本。
- [ ] 确认后 README/design 准确覆盖对应待决内容并保留其余要求，必要时创建 design；记录与确认答案一致。
- [ ] 只提交预览批准的对应文档差异；即使索引中已暂存无关内容或同文件有用户未提交修改，也不能夹带、覆盖或丢弃。无法隔离时明确阻塞提交并说明原因。
- [ ] 保存失败、Git 失败及中途重启均可定位并重试；重试不重复写决策或生成重复提交，不误报成功；成功展示真实提交号和文件清单。
- [ ] 人工确认与接受/完成/复工分离，Agent 无法代替人工确认；提交成功不自动重启实施，原条目状态不被确认动作改变。
- [ ] 窄屏、键盘操作、长文本及跨项目/批次切换可用，迟到响应不覆盖当前上下文。

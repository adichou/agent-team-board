# REQ-20260909-007 在已接受和已计划界面分别添加开始完善和开始开发快捷按钮

- 状态：accepted（已接受；实际状态以 status.json 为准）
- 创建：2026-09-09T02:34:45.209Z

## 描述

需求模块（状态看板）按六档状态筛选条切换列表（待接受 / 已接受 / 已计划 / 开发中 / 待测试 / 已完成）。用户在「已接受」档想启动批量完善、在「已计划」档想启动批量开发时，现有入口都不直接：

- **批量完善**：入口只剩任务模块的「批量完善」子面板（需先切到主导航「任务」再进子面板），以及已接受行 / 详情页的完善三态徽标（未完善 / 完善中 / 已完善，见 REQ-20260908-020）——徽标的首要语义是展示单条完善状态，不是显式的「开始完善」启动入口；REQ-20260908-027 又已把选择工具条上的「批量完善」按钮移除（批量完善面向已接受未完善单，与勾选无关）。
- **批量开发**：已计划档的「进入批量开发」按钮（`#implGo`）位于列表头右组批量操作条，而该操作条**整体仅在当前档勾选数 > 0 时出现**——零勾选时已计划档没有任何进入批量开发的入口，用户必须手动切到任务模块。

本需求在两个档位的列表界面各加一个**常驻快捷按钮**：

1. 「已接受」档列表头新增「**开始完善**」按钮：点击直接进入任务模块「批量完善」子面板（等价 `gotoRuns('refine')`），不依赖任何勾选。
2. 「已计划」档列表头新增「**开始开发**」按钮：点击进入任务模块「批量开发」子面板，行为对齐现有「进入批量开发」（`enterBatchImpl`）——当前档已有勾选则沿用勾选范围，无勾选则为默认范围（全部已计划条目）。

按钮只做**导航**，不创建任务、不弹确认框；任务创建仍由对应子面板内的「启动」承接（须显式选择执行 Agent，BUG-20260908-016 口径不变）。

### 目标口径

1. **只加入口，不改流程**：纯前端改动（`scripts/web/index.html` + `scripts/web/app.js`），不新增 API、不改状态机、不写任何 status.json；批量完善 / 批量开发的创建、领取、回执协议全部不变。
2. **常驻显隐**：两个按钮均不依赖勾选，分别在当前筛选档为「已接受」「已计划」时显示，其余档（含搜索命中条带场景仍随当前档）不显示；随切档即时显隐，轮询刷新不闪烁、不打断列表交互。
3. **行为对齐既有入口**：「开始完善」= `gotoRuns('refine')`；「开始开发」= `enterBatchImpl()`（有勾选沿用范围、无勾选默认全部已计划范围）。
4. **现有入口不回退**：完善三态徽标跳转、`#implGo`「进入批量开发」、任务模块子面板 tab 切换全部保留；REQ-20260908-027「选择工具条不设批量完善按钮」的口径不回退（新按钮在左组常驻，与右组批量操作条无关）。

## 交互行为

1. **开始完善（已接受档）**：点击 → `gotoRuns('refine')`：切换到任务模块、激活「批量完善」子面板并拉取 `/api/refine/current` + `/api/refine/candidates`。与勾选状态无关；当前档是否有勾选、勾选多少都不影响行为（完善候选口径 = 已接受未完善，由面板实时读取）。
2. **开始开发（已计划档）**：点击 → 复用 `enterBatchImpl()`：先复核勾选有效性（失效勾选被剔除并 toast 提示，现状行为）；有有效勾选则设为范围（`scopeActive` + `pushImplScope`，创建面板统计按范围过滤），无勾选为默认范围（全部已计划条目）→ 跳任务模块「批量开发」子面板。
3. **无确认弹窗、幂等**：跳转是纯导航，不弹确认；已在任务模块时重复点击仅重复拉取 / 无累积副作用。
4. **点击不创建任务**：任务创建仍由子面板内「启动」按钮承接（执行 Agent 未显式选择时启动禁用，BUG-20260908-016 口径不变）。
5. **键盘可达**：原生 `<button type="button">`，可 Tab 聚焦、回车触发，附 `aria-label`；不拦截列表行点击语义（按钮不在行卡片内）。
6. **批量操作进行中不禁用**：本按钮仅导航，`anyBatchPending()`（接受 / 移入计划 / 驳回 / 移出计划进行中）不禁用它；批量操作条自身的防误触逻辑不变。

## 状态反馈

- **正常**：点击立即切换到任务模块对应子面板；面板按现有逻辑呈现启动区（无进行中任务）或运行面板（有进行中任务）。「开始开发」带范围时，创建面板统计与已计划队列预览按勾选范围收窄（现状 `?ids=` 逻辑）。
- **加载**：跳转后面板数据拉取期间显示现有加载反馈（批量完善面板「加载中…」、批量开发沿用 `refreshBatch` 路径）；2 秒轮询签名无变化不重渲染。
- **空**：已接受档无未完善候选（或无已接受条目）时按钮仍可点击，面板显示现有空态「暂无可完善候选：已接受条目均已完善（或尚无已接受条目）」；已计划队列为空时面板显示「（空，等待已计划条目）」。按钮本身不做候选预判、不禁用（与完善徽标点击行为一致）。
- **失败**：面板数据拉取失败走现有 toast 错误提示（`refreshBatch` catch 路径）；失败不改变按钮显隐，可再次点击重试。
- **显隐切换**：按钮随筛选档切换即时显隐（切到已接受显示「开始完善」、已计划显示「开始开发」、其余档不显示）；搜索、排序、轮询刷新不影响显隐、不闪烁。

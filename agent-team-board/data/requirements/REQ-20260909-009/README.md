# REQ-20260909-009 新建条目的描述支持截图

- 状态：accepted（已接受；实际状态以 status.json 为准）
- 创建：2026-09-09T04:27:19.906Z

## 描述

看板顶栏「＋ 新建」打开的统一新建弹窗（REQ-20260907-004：需求 / Bug / 讨论三类同一表单）目前只有类型、标题（必填，120 字上限）和描述纯文本框。创建需求 / Bug 时用户经常手头有界面截图（Bug 的现象与复现步骤尤其依赖截图），但现在没有任何附图途径：只能先创建、再手动把图片文件放进条目目录并在 README 里手写 markdown 引用，门槛高且容易写错相对路径。讨论模块历史上支持截图附件（REQ-20260907-001），但该能力随 REQ-20260909-004 的讨论重构从新建表单移除。

本需求让**新建需求 / Bug** 的描述直接支持截图：在表单内粘贴或选择图片 → 缩略图预览与管理 → 创建时随请求提交 → 服务端校验落盘到条目目录 `attachments/` 子目录，并在 README 描述节（需求「## 描述」/ Bug「## 现象」）末尾按添加顺序追加图片引用 → 条目详情抽屉的 README 页签内联展示截图、点击放大。图片随条目目录进 git，与「文件为事实源」的口径一致。

### 现状依据（基于当前代码）

- 新建表单：`scripts/web/index.html` 的 `#modalWrap` / `#newForm`（类型 `#fType`、标题 `#fTitle`、描述 `#fDesc`）；`scripts/web/app.js` 的 `openModal` / `syncNewFormFields` / `submitNew`：需求 / Bug 提交 `POST /api/new`（`scripts/server.mjs`），`core.createItem`（`scripts/lib/core.mjs`）把描述写入 README，无任何图片能力。
- 可复用的附件设施（讨论单）：`scripts/lib/oncall-store.mjs` 的 `saveAttachment` / `readAttachment` / `attachmentMime`——单文件 8MB 上限（`ATTACHMENT_MAX_BYTES`，与 `/api/fs/raw` 一致）、图片后缀白名单（`ATTACHMENT_IMAGE_MIME`：png / jpg / jpeg / gif / webp / svg / ico / bmp / avif）、文件名防穿越校验、同名自动加序号不覆盖；创建接口以 `attachments: [{ name, dataBase64 }]` 随 JSON 提交；读取经 `GET /api/oncall/ticket/:id/attachment/:name`（白名单 MIME + `nosniff` + 收敛 CSP + `no-store`）；前端 `scripts/web/oncall.js` 以 `<img data-lightbox>` 内联展示、点击经 `#oncallLightbox` 放大。
- 详情抽屉 README 用 marked 渲染（`renderMd`），条目文档内相对 `.html` 链接已有接管先例（`linkupDocDemo`，BUG-20260908-021）；相对**图片**链接目前无接管，SPA 下按站点根解析必然 404，需同类处理。
- 待接受条目「✎ 修改」（REQ-20260908-011，`core.editItem`）对描述节**整体替换**——截图引用若写在描述节内，编辑流必须先载入现有内容、保存时不得意外清除图片行。

### 目标口径

1. 截图为描述的可选补充：标题仍为唯一必填项，无截图、无描述的创建口径不变。
2. 校验口径全面对齐讨论单附件：图片白名单、单张 8MB、防穿越文件名、同名去重、服务端二次校验（前端校验仅是体验优化）。
3. 截图落盘于条目目录 `attachments/` 子目录（`docs/agent-team-board/requirements|bugs/<ID>/attachments/`），README 描述节以相对引用（`![截图](attachments/xxx.png)` 形态）追加，人和 Agent 直接读 markdown 也能看到引用关系。
4. 范围仅需求 / Bug 两类：讨论（ask）沿用 REQ-20260909-004「标题 + 背景（可选）」口径，不回加截图。

## 界面布局

- 位置：统一新建弹窗内、描述字段（`#fDesc`）下方新增「截图（可选）」区块；类型选「讨论」时该区块隐藏（随 `syncNewFormFields` 切换，口径同现状字段切换）。
- 区块结构：
  - 标题行：「截图（可选）」标签 + 已附计数（如「2 / 9」）+「上传图片」按钮 + 提示文案「或直接 ⌘V 粘贴」；
  - 缩略图网格：每张含缩略预览、文件名与大小、右上角 ✕ 移除按钮；
  - 空态：一行引导文案「粘贴或选择图片，创建后写入描述（png / jpg / webp 等，单张 ≤ 8MB）」，不占多余高度。
- 弹窗尺寸沿用现状；窄屏（≤736px）截图区块完整可用、缩略图可换行。
- 创建成功后的展示：详情抽屉 README 页签描述（现象）节末尾按顺序内联图片，等宽缩略、点击放大（对齐讨论单 `figure.oncall-fig` 的既有形态与 `#oncallLightbox` 交互）；文件模块现状已能经 `/api/fs/raw` 预览 `attachments/` 下的图片，无需改动。

## 交互行为

- 添加截图（两个必做入口）：
  1. 点击「上传图片」→ 系统文件选择器（`accept` 限定图片），支持一次多选；
  2. 弹窗打开期间监听 `paste` 事件，读取剪贴板中的图片项，自动命名（如 `paste-<时间戳>.png` 形态，design.md 定稿）。
  拖拽图片文件到截图区是否作为第三入口，见「待确认」。
- 即时校验：类型白名单、单张 8MB、张数上限在本地即时校验；不合法的项不进入缩略图列表，就地提示错误，不影响已添加项与表单其余内容。
- 管理：缩略图逐张 ✕ 移除，即时生效、不弹确认；重新打开弹窗时截图区与标题 / 描述一并清空（对齐 `openModal` 现状重置口径）。
- 提交：截图与标题 / 描述一次提交；创建中提交按钮禁用并显示「创建中…」（现状口径），期间截图添加 / 移除入口同步禁用防竞态。
- 服务端兜底：`POST /api/new` 扩展携带附件数据（形态沿用讨论单 `dataBase64` 或等价方案，见「待确认」）；服务端按同口径二次校验（图片白名单、8MB、防穿越文件名），任一附件非法**整单拒绝、不留半写入条目目录**（对齐 `core.editItem`「先全量校验再落盘」的原子性口径）；落盘复用 / 泛化 `saveAttachment`（同名加序号不覆盖）。
- 展示：抽屉 README 渲染时接管相对图片引用，改写为条目附件端点（接管方式参照 `linkupDocDemo` 先例，端点口径对齐 `/api/oncall/ticket/:id/attachment/:name`：白名单 MIME + `nosniff` + 收敛 CSP + `no-store` + 8MB）；点击图片放大、点击任意处关闭（对齐 `#oncallLightbox`）。
- 编辑兼容：待接受条目「✎ 修改」编辑框载入现有描述（含图片引用行）并原样保留，保存不得意外清除既有截图引用；编辑时新增 / 删除截图的方案见「待确认」。

## 状态反馈

- 正常：添加成功缩略图即时出现、计数 +1；创建成功 toast「✓ 已创建 REQ/BUG-…（待接受）」（现状文案），README 描述（现象）节末尾出现图片引用。
- 空态：无截图时区块显示引导文案；无截图也可创建（描述可留空口径不变）。
- 加载态：创建中按钮禁用 + 文案变化，截图区入口禁用；不出现无反馈的长时间静默。
- 失败态（本地校验）：非图片（提示「仅支持 png / jpg / jpeg / gif / webp / svg / ico / bmp / avif」口径）、超 8MB（提示「截图 x.xMB 超过 8MB 上限」形态，对齐既有文案）、达张数上限——均就地提示，单张失败不影响其余。
- 失败态（服务端）：创建失败 toast 明确原因，弹窗不关闭、标题 / 描述 / 已附截图全部保留，可重试且不产生重复条目。
- 查看失败：抽屉内图片加载失败（文件被移动 / 超限）显示占位说明，不渲染空白破图。

## 验收标准

- [ ] 新建需求 / Bug 弹窗在描述下方提供截图区块；类型为「讨论」时不显示该区块（REQ-20260909-004 口径不回退）。
- [ ] 支持文件选择与剪贴板粘贴（⌘V / Ctrl+V）两种添加入口；粘贴的截图自动获得合法文件名（无路径、白名单后缀）。
- [ ] 仅接受白名单图片（png / jpg / jpeg / gif / webp / svg / ico / bmp / avif，与 `ATTACHMENT_IMAGE_MIME` 一致）；非图片本地即时拒绝并就地提示。
- [ ] 单张 ≤ 8MB（与 `ATTACHMENT_MAX_BYTES` / `/api/fs/raw` 一致），超限本地即时提示，不上传不落盘。
- [ ] 张数上限生效（取值待确认，建议 ≤ 9）：达上限后再添加被拒并有明确提示，计数显示「已附 n / 上限」形态。
- [ ] 缩略图区支持逐张查看文件名与大小、逐张移除；重新打开弹窗清空上次残留。
- [ ] 创建请求携带附件数据；服务端二次校验（白名单 / 大小 / 文件名防穿越），任一非法整单拒绝，不留半写入条目目录。
- [ ] 创建成功：截图落盘于条目目录 `attachments/` 子目录（同名自动加序号不覆盖，口径同 `saveAttachment`），README 描述（需求）/ 现象（Bug）节末尾按添加顺序追加图片引用行。
- [ ] 详情抽屉 README 页签内联渲染截图，SPA 下相对引用不 404（接管方式参照 `linkupDocDemo` 先例）；点击放大、点击任意处关闭（对齐 `#oncallLightbox` 交互）；图片缺失或超限显示占位提示。
- [ ] 附件读取端点口径对齐既有附件服务：白名单 MIME、`X-Content-Type-Options: nosniff`、收敛 CSP、`Cache-Control: no-store`、8MB 上限。
- [ ] 创建失败：保留标题、描述与已附截图，明确提示原因，可重试且不产生重复条目。
- [ ] 待接受条目「✎ 修改」（REQ-20260908-011）不丢既有截图引用：编辑框载入现有描述（含图片行），仅改标题保存不动描述节，改描述保存不意外清除图片行。
- [ ] 截图文件与 README 随条目目录进 git；不改状态机、不写任何 status.json；既有创建、编辑、删除与讨论能力不回归。
- [ ] 深浅色外观正常（沿用现有 CSS 变量）；窄屏弹窗内截图区完整可用；上传 / 移除按钮可键盘聚焦操作。

### 待确认（开发阶段 design.md 给出结论即可）

- 传输形态：单请求 JSON `dataBase64`（沿用讨论单）还是先传附件再创建的两步方案（base64 体积约 +33% 对本地服务的影响）。
- 拖拽是否作为第三添加入口（粘贴 + 文件选择已覆盖主要场景）。
- 张数上限取值与达上限交互（入口禁用 vs 继续选择后被拒提示）。
- 编辑（「✎ 修改」）入口是否支持新增 / 删除截图，本需求仅要求不丢既有引用。
- 抽屉图片接管实现（渲染前改写 src vs 渲染后拦截 img 节点）与附件端点形态（新增 `/api/item/:id/attachment/:name` vs 泛化 oncall 端点）。
- SVG 在白名单内但可含脚本：现状附件端点已用 CSP 防护，本需求沿用同口径即可，design.md 复核是否需收紧。

## 描述

### 原始需求背景（历史描述，非当前代码现状）

发布模块（主导航「发布」页签，`scripts/web/build.js`）五步流程的第 3 步「文档编写」当前自上而下为三个区块：

1. 顶部独立「AI 写作」区块（`bld-docs-ai`）：标题「AI 写作」+ 一句角色描述 + 只读提示词文本框（由 `scripts/lib/publish-flow.mjs` 的 `buildDocWritingPrompt` 生成，角色为「技术写作人员」子代理，主会话派发并接收短回执）+「复制提示词」「TRAE CN 打开」「TRAE 打开」按钮与 IDE 反馈行；
2. 「文档」区块（`bld-docs-edit`）：头部含类型（README / CHANGELOG / FEATURES / AGENTS）与语言（中 / 英）选择、「编辑 | 预览」模式切换按钮组、「保存」按钮，正文为编辑器或预览；
3. 提交区块（`bld-docs-commit`）：八个双语文档状态 chips、合并门禁提示与「提交文档到 Git」按钮。

该提示词目前只在发布模块内以「复制提示词」按钮手动复制派发：不进入任务模块的任务账本，也不出现在全局任务面板的类型筛选中（现有类型仅「AI 开发」「AI 分析」）。任务模块（主导航「任务」页签，`scripts/web/app.js`）现有一级页签「AI 分析」「AI 开发」两类面板：无任务时为启动区（功能说明 + 候选统计 + 「启动」按钮 = 创建任务并复制主调度提示词）+ 待处理队列，运行中按「概况 / 队列 / 提示词 / 记录」二级页签组织。全局区域类型筛选档为「全部类型 / AI 开发 / AI 分析」（`GLOBAL_KIND_FILTERS`），任务行类型标签与计数口径按类型分支（`GLOBAL_KIND_LABEL` / `globalCountsParts`），kind 缺失时按账本前缀兜底（`globalTaskKind`）。

### 目标行为

1. **「AI 写作」统一更名为「AI 总结」，并优化其描述。** 该功能的本质是按本版关联条目与实际提交核实变化、总结提炼为用户可读的发布文档，而非自由写作。更名覆盖发布模块文档编写步的区块标题、按钮、toast 等全部相关文案，并经 `scripts/web/i18n.js` 中英文同步更新，不得残留旧「AI 写作 / AI writing」文案。区块下方的描述同步改写为围绕「总结」语义：基于当前版本关联范围与实际代码核实变化、简练通俗、不编造能力、子代理执行并以短回执收口——与新名称一致，不再以「写作」为表述核心。

2. **AI 总结区域默认折叠，收纳进下方「文档」区块头部的「编辑」按钮菜单。** 文档编写步顶部不再保留独立 AI 区块；原「编辑 | 预览」所在位置扩展为含「AI 总结」的菜单，「AI 总结」为第一个菜单项且为默认选中项。默认进入文档编写步即处于 AI 总结菜单态，不再让提示词区块常驻占据顶部大块空间；「编辑」「预览」原有行为（切换前草稿同步、模式切换、保存反馈）保持不变，与 AI 总结菜单切换互不串扰。提示词正文移入任务模块（见第 3 点）后，文档编写步的 AI 总结菜单面板承载优化后的说明与「前往任务模块启动 AI 总结」的入口（携带当前计划号上下文）；「TRAE CN / TRAE 打开」IDE 入口与打开失败提示不因布局调整丢失（具体摆放位置可随新布局调整）。

3. **AI 总结的提示词移入任务模块，布局与 AI 开发 / AI 分析同口径，并在全局区域中显示。**
   - 任务模块新增第三个一级页签「AI 总结」，与「AI 分析」「AI 开发」并列，视觉与布局同口径：无任务时为启动区（功能说明 + 候选统计 + 「启动」按钮 = 创建任务并复制主调度提示词；复制成功不等于执行中，登记运行后才算执行中）+ 待处理队列；有任务时按「概况 / 队列 / 提示词 / 记录」二级页签组织，暂停 / 终止 / 启动新一轮等状态流转与既有两类任务同口径。
   - 候选为处于文档编写阶段的发布版本计划（已关联条目且文档未全部提交的 `BLD-…` 计划，每版一条）；具体候选判定细则（如「需重新编写」态是否计入候选）由开发设计确认。无候选时启动按钮禁用并说明原因，不制造空任务。
   - 主调度提示词内容要素沿用现 `buildDocSummaryPrompt`（`buildDocWritingPrompt` 已更名不存在）：项目路径、计划号与版本号、执行编号、关联范围（条目号 + commit + 标题）、文档清单、逐文件回执口径与总结约束，由任务模块统一生成与复制。其中「八个文档清单」为原始口径，与现「默认语言四文件 + AI 翻译阶段」冲突，按范围决策结果取其一（见待人工确认）。
   - 全局区域（全局任务面板）类型筛选档新增「AI 总结」；任务行类型 chip 显示「AI 总结」，计数口径（已完成 / 异常 / 待处理 / 共）合理展示，不回落「未知类型」档；kind 缺失的前缀兜底机制对新类型兼容；点击任务行可进入对应项目任务模块的 AI 总结面板，跳转行为与既有两类一致。
   - 后端任务类型（kind）、账本、路由与 CLI 子命令的扩展属开发实现范围（design.md 阶段设计），本单只约定界面与流程口径。

## 交互行为

- 进入文档编写步默认停在「AI 总结」菜单：面板展示优化后的说明（按关联条目与实际代码核实变化、总结成用户可读文档、不编造）与「前往任务模块启动 AI 总结」入口；点击入口跳转任务模块并定位到 AI 总结页签（携带当前计划号）。
- 「编辑 / 预览」菜单切换沿用现行为：切换前同步草稿、内容不丢失；「保存」仅作用于编辑态；类型 / 语言切换仍切换文档文件。
- 任务模块「启动」= 创建 AI 总结任务并复制主调度提示词（toast 提示复制成功与登记口径）；复制失败给手动复制指引，不重复创建任务。运行中可暂停后续领取 / 终止任务；收尾后可「启动新一轮」（无候选时禁用并说明原因）。
- 全局区域类型筛选可单独筛出 AI 总结任务；点击任务行（或「进入项目任务」）跳转对应项目任务模块的 AI 总结面板。

## 背景与目标

用户选定 Zcode 桌面子 Agent 方案：手动新建一次主调度会话，随后自动逐项实施本批已接受需求。选单、读取需求、实现、测试和上报全部交给每次新建的子 Agent，尽可能减少主会话累积的内容。

当前 `/dev loop` 由同一会话逐条实施，会累积多项的详细过程。本需求新增批次调度模式，保留原有单项 `/dev` 和 `/dev loop` 行为；每个子 Agent 只实施一项后结束，不在子 Agent 内运行 loop。主会话仅负责启动、接收短回执和最小核对。

## 界面布局、交互与反馈

### 看板入口

- 项目顶栏操作区增加“批量实施”，不与“看板/文件”或需求分类切换混用；窄屏可换行，不能遮挡项目名称。
- 点击打开右侧抽屉，宽度不超过 720 px 和视口宽度，窄屏铺满。抽屉内部滚动，顶部显示当前项目路径、关闭按钮和“Zcode 批次 / Codex 自动派发”模式入口。
- 仅实施本需求时，Codex 模式展示说明及关联需求，不出现可用的启动按钮。

### Zcode 批次面板

- 上部显示批次上限（默认 20，范围 1～100）、候选数量、受依赖阻塞数量和“创建批次并复制提示词”。数据绑定当前项目。
- 创建时冻结当时的候选范围，后续新接受的条目留给下一批；完整清单保存在文件中，不输出到主聊天。没有候选时显示空态，不启动 Agent。
- 创建成功但复制失败时保留同一批次，展示可选中的提示词和“重新复制”；不能因重试复制产生新批次。
- 复制成功显示“请在 Zcode 本项目中新建会话并发送”，状态为“待启动”；有效运行登记后才显示“执行中”。可保留“打开 Zcode 工作区”辅助入口，不声称深链会自动新建或发送会话。
- 中部只展示批次标识、当前条目、执行器、最后活动时间和累计计数；不随轮询读取全部日志。
- 操作区提供“暂停后续”“复制续接提示词”“查看批次记录”。暂停不取消正在运行的工具；立即停止需到 Zcode 原生任务界面操作，界面明确说明此边界。
- 执行记录按需分页，展示编号、结果、报告入口及简短原因。点击报告进入条目详情，查看详细记录时再加载正文。
- 失联显示“执行状态待核对”。旧子 Agent 未确认停止时，续接不能创建第二个实施任务。

### 条目详情

- 增加折叠的“批量执行设置”：依赖编号多选，可搜索现有条目；说明“前置条目人工验收完成后才自动实施”。保存时校验不存在编号、自依赖和依赖环，错误就地反馈。
- 展示最近执行结果、报告和批次入口。blocked/failed 等执行结果不变成业务状态列。

## 执行要求

1. 使用受控 `atb claim/report`，不直接修改条目 status.json，不代替人工接受或确认完成。
2. 子 Agent 配合确定性 helper 选单、检查依赖。需求优先于 Bug，同类按创建时间与编号排序；只开始可执行且未被认领的 accepted 条目。
3. 每项目串行，Zcode、Codex、手工实施共用互斥校验；不同路径指向同一项目时按真实路径归一。
4. 主会话不读完整队列、需求、代码、测试日志或完整报告，不高频轮询子 Agent，不逐单输出长总结。
5. 正常每项一份最终回执、一次最小状态核对，载荷分别不超过 2 KiB UTF-8；完整错误和测试信息落盘。
6. 核对本次 runId、owner、条目、报告及上报时间；旧报告和回执重放不能当作本次完成。
7. 上报后可处理下一项，不等人工验收；范围用尽、仅余阻塞项或工作区不能继续时结束。
8. 认领冲突可换单；未知依赖、实施失败或遗留改动需记录。无法确认可继续时暂停项目；环境错误不能把整批条目逐一领取后标失败。
9. 文件保存批次摘要与执行账本。主会话压缩、退出或重开后可续接；失联、锁超时或点击续接不等于允许抢占原 owner。
10. worker 通过 Zcode 支持的子 Agent 配置或外置规范加载，保留必要项目指令；子 Agent 不再派发其他子 Agent。

## 范围与限制

- 本期使用 Zcode 桌面原生 Agent 工具，不依赖尚未跑通的内置 headless CLI。
- 主会话仍随派发与回执增长。2 KiB 仅约束插件载荷，不是会话 token 上限；运行时可能注入项目或父会话信息。
- 不承诺提示词能删除历史、自动调用 `/compact`，或每个子 Agent 都能成为独立顶层任务。
- 首期为有限批次，不持续空轮询；退出后需要核对并续接，不冒充完全无人值守。
- 模型沿用 Zcode 配置，不新增自动换模型、嵌套子 Agent、多项目并行或自动 Git 合并。

## 验收标准

- [ ] 手动创建并发送一次主会话，即可连续处理至少 3 个独立条目；每项均使用新的子 Agent。
- [ ] 每个子 Agent 只实施一项并完成文档、测试和 report；主会话不承担实现。
- [ ] 正常每项只回传一份回执与一次核对，均不超过 2 KiB，无完整代码或日志进入主会话。
- [ ] 候选范围固定、排序稳定、依赖阻塞正确，父子归属不误当依赖；新增 accepted 不插队进入已有批次。
- [ ] 多入口仅有一个实施任务，复制、回执、续接重试均不产生重复执行。
- [ ] 无候选、全部受阻、环境错误、失败、遗留改动与失联均反馈准确，不反复选中同一阻塞项。
- [ ] 新主会话能从摘要续接；恢复核对原执行、owner、工作区和报告，不自动重置业务状态。
- [ ] 抽屉和依赖设置在桌面、窄屏可用；复制失败可恢复；待启动与执行中严格区分。
- [ ] 10 项模拟批次有主会话载荷对比记录，真实小批次有可追溯证据，未测部分明确标出。
- [ ] 单项派发、/dev loop、状态守卫无回归；最终上报后停在待人工确认。

# REQ-20260908-013 讨论单的问题正文改为可选，如果用户没有填则复制标题作为正文。

- 状态：submitted（待人工接受）
- 创建：2026-09-08T03:11:34.448Z

## 描述

讨论单（ASK，scripts/web/oncall.js 模块）新建时问题正文是硬性必填，但很多问题一句话标题已说清，强制再写一遍正文是重复劳动。现状三处入口都拦空正文：

- 网页统一新建弹窗（REQ-20260907-004，顶栏「＋ 新建」类型选讨论（ASK））：`submitNew()`（scripts/web/app.js）对 `type === 'ask' && !desc` 弹 toast「讨论单的问题正文不能为空」直接拦截；
- 服务端 `POST /api/oncall/ticket`（scripts/server.mjs）转调 `oncall.createTicket`（scripts/lib/oncall-store.mjs），store 层 `if (!question.trim()) throw new AtbError('问题正文不能为空')` 二次拦截；
- CLI `atb oncall new`（scripts/atb.mjs）要求 `--question-file` / `--question` 二选一，缺省 die「问题正文不能为空」。

而问题正文落盘为 `oncall/tickets/ASK-…/question.md`（第 1 轮问题），派单提示词 `buildOncallWorkerPrompt`（scripts/lib/oncall-store.mjs）以它作「当前待答问题（第 1 轮）」，详情抽屉 `roundHtml()`（scripts/web/oncall.js）也以 Markdown 渲染它——正文有内容是派单能获得有效回答的前提，因此不能简单放开为可空，需要在留空时回退为标题文本，保证 question.md、抽屉展示、派单提示词三处始终有内容。

本需求把**创建时**的问题正文改为可选：用户留空则自动以标题作为正文，其余流程（保存即入列表、无需人工接受）不变。

界面布局、交互与状态反馈：

1. **弹窗布局不变**：统一新建弹窗仍为类型下拉 + 标题单行输入（必填，maxlength 120）+ 问题正文多行文本域（类型为讨论时显示，标签现文案「问题正文（Markdown，支持粘贴截图）」，scripts/web/app.js `syncNewFormFields()`）+ 截图附件行（仅讨论显示，支持选择与 Ctrl/⌘+V 粘贴）。
2. **交互变化**：类型为讨论时问题正文可留空直接点「创建」，不再弹「讨论单的问题正文不能为空」；标签与 placeholder 需注明可留空及留空后果（候选「问题正文（Markdown，可留空＝以标题作为正文）」，最终文案待确认）。需求 / Bug 类型的「描述」字段本就可留空，不受影响。
3. **状态反馈**：留空创建成功后弹窗关闭、toast「✓ 已创建 ASK-…（待回复）」、自动进入讨论模块并定位打开新单（沿用既有 reveal 流程）；详情抽屉第 1 轮 `.oncall-q` 区显示的内容即标题文本。提交中按钮禁用 +「创建中…」防重复、失败 toast 报错且弹窗输入保留可重试，均为既有范式不变。

## 验收标准

- [ ] 统一新建弹窗类型选讨论（ASK）时，问题正文留空可提交成功，不再出现「讨论单的问题正文不能为空」拦截；创建成功 toast、跳转讨论模块并定位新单的既有行为不变。
- [ ] 留空创建后 `oncall/tickets/ASK-…/question.md` 内容为标题文本；详情抽屉第 1 轮问题区显示标题；派单提示词（buildOncallWorkerPrompt）「当前待答问题（第 1 轮）」为标题文本。
- [ ] 填写了正文时行为完全不变：正文原样落盘 question.md，不被标题覆盖（回归）。

- [ ] 标题必填与 ≤120 字校验保持（TITLE_MAX_CHARS，scripts/lib/oncall-store.mjs）；标题为空仍被拒绝。
- [ ] CLI `atb oncall new --title <标题>` 不带 `--question` / `--question-file` 可创建成功且正文为标题；带正文时行为不变（是否同步放开 CLI 待确认，默认同步）。
- [ ] 截图附件（选择 / 粘贴）可与留空正文组合使用，附件照常落盘并显示在第 1 轮。
- [ ] 追问正文必填口径不变；`askTicket`「追问正文不能为空」与网页追问校验不受影响。

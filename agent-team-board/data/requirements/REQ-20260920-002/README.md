# REQ-20260920-002 设置界面的初始化 dev 分支改为切换至 dev 分支

- 创建：2026-09-20T05:31:34.318Z
- 实时状态：以看板为准，本文不维护状态快照。

## 描述

设置页「Git 工作流」当前把主操作称为「初始化 dev 分支」，但对于 dev 已存在、当前处于 main/master 或其他分支的项目，该操作实际执行的是切换工作区。将面向用户的入口和确认流程改为以「切换至 dev 分支」表达目的，避免用户误以为每次都会重新初始化仓库或重建分支。

### 已核实的现状与范围

- `scripts/web/app.js` 的 `gitWorkflowAreaHtml` 展示当前分支、dev 是否存在与操作按钮；点击后显示确认框，加载和执行期间禁用操作；已在 dev 时显示禁用的「已在 dev 分支」。
- 当前确认框标题为「初始化 dev 分支？」、确认按钮为「初始化并切换」、执行提示为「正在创建并切换到 dev 分支…」。这些用户可见文案需同步改成切换导向。
- `scripts/server.mjs` 的 `/api/git/init-dev` 调用 `scripts/lib/git-flow.mjs` 的 `ensureDevWorkflow`：dev 存在时切换，不存在时按需创建并切换。保留此现有能力及本地操作边界，不将本单扩展为 API 重命名或 Git 工作流重构。
- 非 Git 项目仍提示先初始化 Git；不通过本按钮隐式初始化非 Git 项目。不自动 push，不强制丢弃或覆盖工作区修改。

### 界面布局与交互行为

1. 保持设置页「Git 工作流」分区及现有工作流说明，状态行展示当前分支与 dev 分支存在情况，其下保留主按钮与就近反馈区域。
2. 当前不在 dev 时，主按钮显示「切换至 dev 分支」；已在 dev 时显示「已在 dev 分支」且禁用。非 Git 项目禁用切换入口并显示初始化指引。
3. 点击主按钮弹出「切换至 dev 分支？」确认框，确认按钮为「切换至 dev」，取消按钮关闭弹窗且不发送切换请求。正文说明切换的是整个项目工作区，仅本地操作、不 push；明确 dev 不存在时会先创建再切换，不能用改名掩盖该行为。
4. 确认后按钮禁用并显示「正在切换至 dev 分支…」，防止重复提交。成功重新获取 Git 状态，显示 dev 与禁用就绪按钮，并反馈「已切换至 dev 分支」。
5. 失败在操作旁显示实际错误原因和可重试提示，恢复切换入口，不显示成功状态；状态获取失败有独立「重试」入口。不能将失败时未知的分支状态伪装成 dev。

### 状态反馈

- 正常：当前 main/master/其他分支、dev 已存在时可发起切换；dev 不存在时状态行显示「未创建」，确认说明按需创建。
- 已就绪：当前 dev（含当前处于尚无提交的 dev）显示「已在 dev 分支」。
- 空态：非 Git 项目显示「当前分支：—（不是 git 仓库）」及初始化指引；无提交的 Git 仓库不误判为非 Git 项目，沿用现有按需创建/切换语义。
- 加载：读取 Git 状态显示加载提示；执行切换显示执行提示，均不可重复操作。
- 失败：状态读取失败允许重试；切换失败保留错误原因并允许重试，不静默强制切换。
- 中英文同步：主按钮、确认标题/正文/按钮、加载、成功、失败反馈全部遵循 `scripts/web/i18n.js` 的双语机制；英文主操作使用「Switch to dev branch」，已就绪状态保持与中文一致。

# REQ-20260921-010 文档编写界面提供一个输入框，允许输入国际化语言集

- 状态：submitted（待人工接受）
- 创建：2026-09-21T01:46:44.005Z

## 描述

1、并不是每个用户都需要中英文的文档，也有用户有更多语言的文档需求，因此需要提供一个输入框，允许用户以逗号分隔的形式输入要包括的语言集合。例如 cn,en,fr,jp 等。语言缩写以国际规范为准。
2、以 README.md 为例， 假设语言集输入框中是 cn,en,fr,jp，那么默认不带后缀就是语言集合中的第一个语言，第二个是 en，因此是 README_en.md，第三个是 fr，那就是 README_fr.md，依次类推。
3、文档中的多语言切换需要涵盖语言集输入框的所有语言。
4、语言集输入框默认输入 cn,en，用户可自行更改。

## 背景（现状）

- 发布流程「文档编写」步（`scripts/web/build.js` 的 `renderDocsPane`）目前提供固定的**语言下拉框**，只有「中文 / 英文」两个选项（内部代码 zh / en）。
- 发布文档清单由 `scripts/lib/publish-flow.mjs` 固定为 4 类 × 2 语言共 8 个文件：中文 `<KEY>.md`（如 `README.md`）、英文 `<KEY>.en.md`（如 `README.en.md`），`KEY ∈ {README, CHANGELOG, FEATURES, AGENTS}`；保存接口按该白名单校验（`docFileOf` / `isPublishDocFile`），提交门禁与「提交文档到 Git」的 pathspec 也限定这 8 个文件。
- 文档内的多语言切换现状：根 `README.md` 顶部互链行（`中文 | [English](./README.en.md)`）仅中英两种；发布文档的 README 按语言链接同语言 CHANGELOG 与 FEATURES（`readmeDocLinks`）。
- AI 总结提示词（`buildDocSummaryPrompt`）也按「八个文档（中文 / 英文各四类）」展开文档清单。
- 界面文案中英文同步是项目质量基线（BUG-20260912-001，词典集中在 `scripts/web/i18n.js`）。

本需求将「固定中英两种语言」扩展为「用户可配置语言集」，文档数量、文件命名、语言选择、切换链接、门禁与提示词均随语言集动态展开。

## 需求规则

1. **语言集输入框**：文档编写界面提供语言集输入框，用户以逗号分隔输入语言缩写集合（如 `cn,en,fr,jp`），语言缩写以国际规范为准（默认值与缩写口径的落定见「待确认」）。
2. **文件命名**：语言集 `cn,en,fr,jp` 时，第一个语言为默认语言、文件不带后缀（`README.md`），后续语言带语言后缀：`README_en.md`、`README_fr.md`、`README_jp.md`，依次类推；CHANGELOG / FEATURES / AGENTS 同规则。文档清单 = 4 类 × 语言集语言数。
3. **文档内多语言切换**：文档内容中的语言切换行需涵盖语言集的全部语言，链接指向对应语言的文档文件。
4. **默认值**：语言集输入框默认 `cn,en`，用户可自行更改。
5. **联动范围**：语言集变更后，语言选择、文档清单（chips）、提交门禁、README 同语言链接提示、AI 总结提示词的文档清单均按新语言集展开；存量中英文档（`.en.md` 点号命名）的兼容口径见「待确认」。

## 界面布局

基于发布流程「文档编写」步现有三段式布局（上部 AI 写作、中部文档编辑、下部提交），变更点集中在中部「文档」标题行：

1. **AI 写作区**（不变）：技术写作子代理提示词 + 复制按钮 + TRAE / TRAE CN 打开按钮。
2. **文档编辑区**「文档」标题行，控件从左到右依次为：
   - **类型**下拉：README.md / CHANGELOG.md / FEATURES.md / AGENTS.md（不变）；
   - **语言集**输入框（新增）：文本输入，逗号分隔语言缩写，默认 `cn,en`；
   - **语言**下拉：选项由语言集动态生成，第一项为默认语言（第一个语言，不带后缀），替换现有固定「中文 / 英文」两项；
   - **编辑 / 预览**切换（不变）与**保存**按钮（不变）。
   - 标题行下方为编辑器（或预览）与保存状态反馈；类型为 README 时展示「README 需链接同语言 CHANGELOG 与 FEATURES」提示，文件名按当前语言展开。
3. **提交区**：文档 chips 按语言集展开（4 类 × N 语言，每个文件带编写状态）；门禁提示与「提交文档到 Git」按钮（不变位置，作用范围随语言集）。

## 交互行为

1. **编辑语言集**：在输入框修改后确认（回车 / 失焦，确认时机以实现统一口径为准），前端校验：非空、每项为合法语言缩写、自动忽略空白、重复项去重或报错（口径见「待确认」）；校验通过后应用。
2. **应用语言集后的联动**：语言下拉选项重建（第一项为默认语言并选中）、文档 chips 重建（语言集内已保存的文件保留状态，新增语言文件为「未编写」）、提交门禁按新清单重算、README 链接提示按新文件名展开；未保存的编辑草稿不丢失（沿用现有切换前草稿回同步逻辑）。
3. **选择文档**：切换类型或语言即加载对应文件内容（现有行为保留：切换前同步草稿、保存后切换以磁盘为准）。
4. **保存**：保存到语言集展开后的目标文件（如 `README_fr.md`），白名单按语言集校验；保存中按钮禁用。
5. **提交**：「提交文档到 Git」只提交语言集内的文档文件，不夹带其他文件；全部文件已提交才满足合并前置（门禁按语言集计算）；无变化不空提交。
6. **语言集持久化**：作用域与存储位置待确认（见「待确认」），重新进入界面时正确回显上次语言集。

## 状态反馈

1. **输入校验失败**：语言集输入框标红并给出行内错误提示（如「语言集不能为空」「存在非法缩写」「语言重复」），不应用非法值、界面保持上次有效状态。
2. **加载中**：进入文档编写步显示「正在加载发布流程数据…」，切换文档时编辑区显示加载占位（沿用现有占位文案）。
3. **保存中**：按钮显示「处理中…」并禁用；成功显示「已保存 <文件名>（未提交：需「提交文档到 Git」后才能合并）」；失败显示「保存失败：<原因>（内容已保留，可重试）」。
4. **提交中**：按钮显示「提交中…」并禁用；成功显示提交 hash 与文件范围；失败显示「提交失败：<原因>（内容已保留，可重试）」。
5. **文档编写状态**（chips，沿用四态）：未编写 / 未提交 / 已提交 / 需重新编写。
6. **门禁状态**：未全部提交时列出原因（各文件未编写 / 未提交）；全部提交后显示「文档已提交（hash）：满足合并前置」。

## 界面展示

- **布局**：见上文「界面布局」——AI 写作区在上；中部「文档」标题行依次为类型下拉、语言集输入框、语言下拉、编辑 / 预览切换、保存按钮；下方编辑器与 README 链接提示；底部提交区为文档 chips + 门禁 + 提交按钮。
- **交互**：可交互演示见 [./ui-demo.html](./ui-demo.html)（单文件 HTML，浏览器直接打开）：修改语言集（如 `cn,en` → `cn,en,fr,jp`）后语言下拉、文档 chips、门禁清单、README 链接提示即时联动；输入非法语言集（空值 / 非法字符 / 重复项）演示校验拦截；切换类型 / 语言加载对应文档；保存与提交演示加载中 → 成功 / 失败的状态切换；README 模板内容演示涵盖全部语言的多语言切换行。
- **状态反馈**：演示覆盖正常（保存 / 提交成功、门禁通过）、空态（文档全部未编写时提交按钮禁用与门禁提示）、加载中（保存 / 提交 / 切换文档的占位与按钮禁用）、失败（保存失败 / 提交失败的重试提示）四类状态；支持深浅色切换。

- [ ] 语言集应用后：文档清单 = 4 类（README / CHANGELOG / FEATURES / AGENTS）× 语言集全部语言；第一个语言的文件不带后缀（`README.md`），其余语言带后缀（`README_en.md`、`README_fr.md`……分隔符与存量兼容按「待确认 2」落定结果执行）。
- [ ] 语言下拉选项随语言集动态生成，第一项为默认语言（第一个语言），切换后加载对应文件。
- [ ] 文档内容中的多语言切换行涵盖语言集全部语言，链接指向对应语言文件且真实可达。
- [ ] README 的「链接同语言 CHANGELOG 与 FEATURES」提示按当前语言集文件名展开。
- [ ] 提交门禁按语言集展开后的全部文件计算：全部已提交才满足合并前置；「提交文档到 Git」只提交语言集内文档，不夹带其他文件，无变化不空提交。

## 待确认

1. **语言缩写口径与默认值**：需求原文示例 `cn,en,fr,jp` 且默认 `cn,en`，但「国际规范」（ISO 639-1）中中文为 `zh`、日语为 `ja`；现有实现中文的内部代码为 `zh`。需确认：是否以 ISO 639-1 为准（默认相应为 `zh,en`、示例 cn→zh / jp→ja），或按需求原文使用 cn / jp。
2. **后缀分隔符与存量兼容**：需求示例为下划线（`README_en.md`），现有实现为点号（`README.en.md`）。需确认：新命名采用哪种分隔符；存量 `.en.md` 双语文档是否迁移为 `_en.md`、或两种命名并存识别、或按语言首项归一。
3. **语言集作用域与持久化位置**：项目级（每个看板项目一份）、发布计划级（每个版本一份）还是全局设置；存储于何处（项目配置 / 看板数据）。需求未说明。
4. **校验细则**：重复项是自动去重还是报错；语言缩写的合法性校验范围（是否限制为 ISO 639-1 两字母码、未知缩写是否放行）；语言数量是否有上限。
5. **语言显示名映射**：文档内多语言切换行与语言下拉的语言显示名（如 zh→中文、en→English、fr→Français、ja→日本語）映射字典范围，超出映射的缩写如何显示（原样显示缩写 / 报错）。
6. **官网同步材料是否跟随扩展**：官网发布校验（`scripts/lib/build-publish.mjs`）目前要求中英成对材料（`faq.zh.md` / `faq.en.md` 等）；语言集扩展后官网材料是否同样支持多语言，需求未提及。

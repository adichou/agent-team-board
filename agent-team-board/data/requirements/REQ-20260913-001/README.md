## 描述

### 现状（已核实）

**顶栏与模块导航**：

- 模块导航位于顶栏 `header.topbar` 内的 `<nav class="module-nav">`（scripts/web/index.html）。当前可见页签自左向右为：需求（`data-view="status"`，默认激活）→ 任务（`data-view="runs"`）→ 设置（`data-view="settings"`）。
- 页签上移并入顶栏由 REQ-20260910-012 交付；历史上的完整页签顺序为 讨论 → 需求 → 任务 → 文件 → 营销 → 发布 → 设置（REQ-20260910-019 将营销插在「文件」与「设置」之间，REQ-20260910-029 将发布插在「营销」与「设置」之间）。
- 讨论（oncall）、文件（files）、营销（marketing）、发布（release）四个模块入口当前暂态隐藏：scripts/web/app.js 中 `HIDDEN_VIEWS = new Set(['oncall', 'files', 'marketing', 'release'])`，完整视图表 `VIEWS = ['status', 'oncall', 'runs', 'files', 'marketing', 'release', 'settings']`。切模块统一走 `setView(v)`：切换 `.view-tab` 激活态、对应容器显隐、深链 `?view=` 同步；隐藏模块的旧深链与间接入口回落需求模块。
- 每个模块对应 index.html 顶层一个 `<section>` 容器（如 `#reqView`、`#runsView`、`#releaseView`），初始 hidden；内容由各模块 JS 动态渲染（release.js / marketing.js / oncall.js 分别挂 `window.ATB*` 命名空间，在 app.js 之前加载），页签点击统一由 app.js 绑定。
- 顶栏下方第三行 `#pageHead` 为「模块副标题 + 当前模块搜索框」，搜索随模块解释，统一反馈条 `#searchFeedback` 按模块渲染关键词命中与各状态；快捷键 `/` 聚焦当前模块搜索框。

**需求模块与任务模块（新模块的两个邻居）**：

- 需求模块（`#reqView`）：六档状态筛选条 `#filterBar` + 宽屏「列表 `#board` 与详情并排（req-split 分栏）」，空态双卡（未初始化 / 无项目）。
- 任务模块（`#runsView`）：任务面板 `#batchDrawer` 集中呈现批次、队列、执行记录与对应操作。

**可复用的 git 能力（服务端已存在，均已核实）**：

- scripts/lib/git-flow.mjs：`isGitRepo()`、`gitBranchState()`（只读，返回 isRepo / 当前分支 / devExists）、`itemCommitStatusIndex()`（条目 ↔ commit 双向索引：自动提交账本 ∪ git log 消息含 REQ-/BUG- 单号，一次扫描服务全部条目）、`itemCommitLog()`、`itemOfCommit()`（commit hash/消息 → 条目）。
- `GET /api/git/branch-state`（只读，设置页加载用）、`POST /api/git/init-dev`（幂等创建/切换 dev 分支，非 git 项目明确拒绝）——见 scripts/server.mjs。
- `GET /api/release/targets`（scripts/server.mjs）：返回 git remotes（远端名列表）、currentBranch、branches（仅本地分支，`git branch --format` 取得）——**不含**远端分支列表，也**不含**分支提交记录。
- scripts/lib/release-git.mjs 提供七阶段 Git 发布流水线（预检只读不推送，启动须计划确认，逐阶段持久化）。

**缺口**：远端分支列表与分支提交记录目前无现成接口（需新增）；本地与远端分支同步（fetch / push）亦无现成接口（需新增）；版本计划的持久化、「选择条目对应 commit 合并入 main」的执行入口也均不存在。版本数据落盘位置与字段结构待确认（候选 `docs/agent-team-board/build/` 下，以 design.md 为准）。

### 目标

新增「构建」模块（版本管理），顶栏页签插在「需求」与「任务」之间，页签顺序变为：需求 → 构建 → 任务 → 设置。模块 view 键名待确认（候选 `build`，深链 `?view=build`），文案中英文（构建 / Build）接入 i18n（REQ-20260911-005 范式，词条组织方式待确认）。三项能力：

1. **版本计划创建**：按需求单或 Bug 单创建版本计划，为每个所选条目选择对应 commit（条目勾选支持「全选 / 全不选」），执行合并入 main 分支；版本创建后支持编辑条目——可继续添加或移出需求单 / Bug 单（连同其 commit 关联）。条目 ↔ commit 候选映射可复用 `itemCommitStatusIndex` 数据源（条目尚未有提交时该条 commit 候选为空并明确提示）；「合并入 main」的执行方式（本地 merge / 复用 release-git 流水线阶段 / 新接口）待确认，但必须是显式确认后的写操作，且与发布模块（release）的运行互斥关系待确认。
2. **版本名称与描述可修改 + Agent 回贴自动解析**：版本名称与描述支持编辑保存；提供「提示词与回答回填」弹窗：一键复制提示词给 Agent，收到回答后无需关闭，直接在同一弹窗粘贴回答，看板自动解析并更新版本的名称与描述；解析失败的原文保留并可改用手动编辑。提示词模板与解析格式约定待确认（design 阶段定）。
3. **git 分支浏览与同步**：可查看当前分支、本地分支与远端分支，点击分支查看其提交记录；支持本地与远端分支同步——一键「同步远端」（fetch 拉取最新远端分支与提交信息并刷新列表，是否附带清理失效远端分支引用待确认），本地分支支持「推送」到远端（未建立上游跟踪的分支首推时建立）；是否提供远端 → 本地的直接合并（pull）与快进口径待确认（design.md 定）。浏览与提交记录保持只读；同步操作为显式触发的受限写操作：推送等写远端动作需确认，执行中禁用重复触发，成功 / 失败有明确反馈；除同步外不提供其他 git 写操作（合并入 main 仍在版本计划中显式确认后执行）。非 git 仓库给引导空态。

## 界面布局

- 沿用既有三段范式：顶栏页签（`.module-nav` 新增「构建」按钮，插在需求与任务之间）→ `#pageHead` 模块副标题 + 模块搜索框（搜索解释为「搜版本 / 分支」，口径待确认）→ index.html 顶层新增 `<section>` 容器（id 候选 `#buildView`），内容由新模块 JS 动态渲染。
- 模块内两个子页签：**版本计划**（默认）与**分支浏览**。
- 版本计划子页签：宽屏左右分栏（参照 `#reqView` req-split 与 `#releaseView` 分栏模式，窄屏 ≤960px 上下排列）——左侧版本列表（版本名、状态 chip、关联单数、更新时间，顶部「＋ 新建版本」入口）；右侧选中版本详情，自上而下为：版本信息区（名称单行可编辑、描述多行可编辑）、关联条目与 commit 区（每行一条目：单号 + 标题 + commit 下拉/换选 + 「移出」；区头部「＋ 添加条目」入口，打开选择面板继续加入需求单 / Bug 单）、操作区（「提示词与回答回填」「合并入 main」两个入口，前者打开单一弹窗：上段复制提示词、下段粘贴回答回填）。
- 新建版本走右侧侧拉面板（对齐 REQ-20260910-014 统一新建与 REQ-20260910-029 发布新建的侧拉范式）：选择需求单/Bug 单（条目列表顶部提供「全选 / 全不选」与已选计数）→ 每条自动带出关联 commit 候选 → 填版本名（默认命名规则待确认）→ 创建。
- 分支浏览子页签：左侧分支列表（当前分支置顶并带「当前」标识，本地 / 远端 `remote/` 分组；列表头部「同步远端」入口，本地分支行带「推送」操作），右侧所选分支的提交记录列表（hash、提交说明、作者、时间）。
- 深浅色走既有 CSS 变量（对齐发布模块口径）。

## 交互行为

- 顶栏点击「构建」页签切换模块，激活态、容器显隐、`?view=` 深链与既有 `setView` 范式一致；旧深链兜底行为不回退。
- 新建版本：在侧拉面板勾选条目（需求/Bug 可搜索；提供「全选 / 全不选」——全选纳入全部有 commit 候选的条目，暂无 commit 的自动跳过并提示）→ 每条目出现 commit 候选下拉（默认取最近一次关联提交，可换选；无提交记录的条目给出提示且该条不可选 commit）→ 点「创建版本计划」生成草稿态版本并进入列表。
- 版本详情：名称点击进入行内编辑、描述进入多行编辑，「保存」生效；未保存离开给确认提示（口径待确认）。
- 条目增删：点「＋ 添加条目」打开选择面板（对齐新建版本选择范式：需求/Bug 可搜索、全选 / 全不选、每条带 commit 候选下拉；已在本版本中的条目不再出现在候选，暂无 commit 的条目不可纳入并提示），确认后加入版本；每行「移出」把该条目连同其 commit 关联移出版本。添加 / 移出即时生效并有成功反馈，移出后可重新添加；合并中禁用增删，已合并状态锁定条目增删（口径待确认，以 design.md 为准）；合并确认弹窗始终按当前条目清单生成。
- 提示词与回答回填（同一弹窗，复制与回贴不分离）：点「提示词与回答回填」打开两段式弹窗——上段根据版本当前信息与所选单据/commit 组装提示词文本并「复制」到剪贴板（复制成功有反馈；剪贴板不可用降级为全选手动复制）；下段把 Agent 的回答直接粘贴进同一弹窗的多行文本框 → 「解析并预览」→ 成功则并排显示新旧名称/描述预览，「应用」后更新版本；失败则明确报错且保留已粘贴原文，可在弹窗内修改重试，或关闭弹窗改用手动编辑。全程无需关闭再打开弹窗。
- 合并入 main：点击后弹确认框（列出将合并的 commit 清单）→ 确认后进入「合并中」状态，期间合并入口禁用防重复 → 成功置「已合并」/ 失败置「失败」并显示原因，失败可重试（重试口径待确认）。
- 分支浏览：点击左侧分支懒加载右侧提交记录；提供刷新按钮；列表不自动轮询（口径待确认）。
- 分支同步：「同步远端」执行 fetch 更新远端分支列表与提交信息，执行中按钮禁用并显示同步中提示，完成后刷新列表并 toast 成功，失败显示原因可重试；本地分支「推送」先弹确认框（显示目标远端与分支名，区分首推建立跟踪 / 更新已有远端分支）→ 确认后推送，成功后远端分组出现对应 `origin/` 分支；同步不自动轮询、不后台重试（口径待确认）。

## 状态反馈

- **加载中**：版本列表与分支提交记录加载、分支同步 / 推送执行中显示加载指示（骨架、spinner 文案或同步中提示），执行中相关按钮禁用防重复，不白屏。
- **空态**：无版本时列表区显示「暂无版本计划」引导新建；条目无关联 commit 时明确提示先完成开发提交；非 git 仓库时分支浏览显示引导卡（指向 `atb init` / 初始化入口，对齐设置模块 branch-state 空态口径）。
- **成功**：toast「✓ …」（创建版本、保存信息、复制提示词、解析应用、合并完成、同步远端、推送分支等），沿用既有 toast 范式。
- **失败**：创建/保存/合并/解析/同步/推送失败均给出明确错误反馈（toast 或行内错误 + 可重试），输入内容保留不丢失。
- **进行中**：版本状态 chip 完整覆盖 计划中 → 合并中 → 已合并 / 失败（最终档位命名待确认，以 design.md 为准）；合并中禁用重复触发与编辑冲突操作。

# REQ-20260911-004 在设置中支持对 commit 到 git 的目录进行设置，默认只 commit 源代码相关目录

- 状态：accepted（已接受；实际状态以 status.json 为准）
- 创建：2026-09-11T07:52:14.007Z

## 描述

为**批量 Commit**（REQ-20260910-013）增加目录范围设置：看板**设置模块**新增一个可查看、可修改、可保存的「提交目录范围」配置，控制批量 commit 子代理执行 `git add` / `git commit` 时**允许提交到 git 的目录范围**；**默认值 = 仅源代码相关目录**。范围外目录的工作区改动不提交、不暂存、不丢弃——原样保留在工作区。「只 commit 不 push」、消息规范（「类型: 描述 单号」）、业务与测试分离等既有约束全部不变。

### 背景与现状（均已在代码核实）

1. **批量 commit 是本项目唯一的系统化自动提交通道**：开发子代理不自动提交（全局规则）；发布流水线绝不自动 add/commit/stash，未提交修改只引导回看板提交功能（`scripts/lib/release-git.mjs` 6、159–163 行）。因此「commit 到 git 的目录」的作用对象就是批量 commit 流程。
2. **现行提交范围没有目录级约束**：调度提示词 `buildCommitPrompt`（`scripts/lib/commit-store.mjs` 190–228 行）只要求子代理「与 git status --short、git diff，从工作区未提交改动中找出属于该单的文件」「不属于任何候选单的改动保持原样，不得混入」——**任何目录**的改动只要能归因到候选单就可被提交，`output/` 素材、`.zcode/` 运行痕迹、看板数据等非源代码目录同样没有防线。
3. **done 回执核验无目录校验**：`validateItemCommits`（`commit-store.mjs` 579–611 行）校验消息格式 / 单号 / 描述长度 / 测试业务分离（`TEST_PATH_PREFIX = 'scripts/tests/'`，37 行）/ 条目文档归类，不含目录范围判定。
4. **设置模块现状**：设置页（`scripts/web/app.js` `paintSettingsView` 6921 行）仅剩「批量任务」分区（`taskSettingsHtml` 6877 行——完善流转开关 + 保存按钮 + 就近状态）；数据经 `/api/tasks/settings`（`scripts/server.mjs` 2270–2284 行）读写 `<dataDir>/tasks/settings.json`（`scripts/lib/task-settings.mjs` 209–350 行，patch 分区 `{ agents?, models?, refine? }`，非法值整体拒绝、缺省合并回退）。另有 `<dataDir>/commits/settings.json`——批量 commit 的**幂等计数器账本**（`ensureCommits`，`commit-store.mjs` 78–91 行），不是用户设置，两者勿混淆。
5. **生效时机天然是「批次创建时」**：调度提示词在批次创建时生成并冻结进 `batch.json`（`commit-store.mjs` 310 行 `prompt: buildCommitPrompt(...)`）——目录范围若随提示词注入，即自动满足「保存后仅对新创建批次生效」，与批量任务设置「保存仅对后续启动的任务生效」口径一致。
6. **与 REQ-20260911-003（批量 commit 功能暂隐藏）不冲突**：该单只隐藏看板面板入口，CLI 命令组（`atb commit create/next/done/...`）、`/api/commit/*` 接口与账本全部保留。本项设置挂在**仍可见的设置模块**，作用对象是被保留的提示词 / 领取输出 / 核验层；隐藏期间设置仍可配置并在功能恢复后生效。

### 目标细化（完善阶段口径）

1. **配置入口**：设置页新增「批量 Commit 提交目录范围」配置块（分区标题、是否并入「批量任务」分区由 design 定）：按已保存值回显，可勾选 / 编辑允许提交的目录，保存后持久化。
2. **默认值**：仅源代码相关目录。未配置、配置文件缺失或损坏时回退默认，不阻断批量 commit 的创建与执行（沿 task-settings「缺省合并、宽松读」精神）。
3. **范围语义**：范围内的文件才允许进入本功能产生的 commit；范围外目录的改动不 add、不 commit、不丢弃，原样保留在工作区（与现行「不属于任何候选单的改动保持原样」同一处置精神）。
4. **生效时机**：保存后仅对**新创建**的批量 commit 批次生效（范围随提示词在创建时冻结）；在途 / 存量批次不受影响。
5. **同一事实源贯通三层**：设置存储 → 批次创建时写入调度提示词（子代理约束）→ done 回执核验可发现超范围文件（处理口径见待确认 4）；CLI `atb commit next` 领取输出的提交规范摘要（`COMMIT_SPEC_SUMMARY`）同步携带现行范围。
6. **不变量**：非 git 仓库拒绝、只 commit 不 push、消息规范、业务 / 测试分离、条目文档归类等既有约束全部保持。

### 待确认

1. **默认「源代码相关目录」精确清单**：本仓库受版本控制顶层（`git ls-files` 事实）为 `bin/ commands/ docs/ electron/ hooks/ output/ scripts/ skills/ .codex-plugin/ .zcode/ .zcode-plugin/` 与根文件（`package.json`、`package-lock.json`、`README.md`、`.gitignore`）。建议默认 = `scripts/ bin/ commands/ electron/ hooks/ skills/` + 根文件（`output/` 素材、插件元数据目录默认排除），**待确认**，design 定稿。该清单是项目级配置的**默认值**，非硬编码本仓库专属——其他项目默认口径待确认（是否按通用约定推导，design 定）。
2. **`docs/`（看板数据与条目文档）默认是否排除**：按标题字面默认排除——这会改变现行「条目目录内文档改动属 doc 类提交」的默认行为（条目文档默认不再随批量 commit 提交；需要时把 `docs/` 加入范围即可恢复）；若希望条目文档仍默认提交、仅排除 `output/` 等其余非源代码目录，默认清单相应调整。**待确认（对现行行为影响最大的一项）**。
3. **配置形态**：允许清单（推荐——白名单语义与「默认只 commit 源代码相关目录」吻合）/ 排除清单 / 两者并用；是否支持自定义目录输入与根文件通配。design 定。
4. **范围外文件被误提交时的核验口径**：done 回执整体拒绝（严格）还是记录警告放行（宽松）；以及创建批次时是否对工作区超范围改动做前置提示。design 定。
5. **存储位置**：`tasks/settings.json` 新增 `commit` 分区（沿用批量任务设置的读写 / 校验 / 回退通道）还是 `commits/settings.json`（现用途为账本计数器，混放需迁移语义）。design 定。

## 验收标准

- [ ] 设置模块新增提交目录范围配置：进入设置页可见「批量 Commit 提交目录范围」（或等义分区），按已保存值回显；可修改并保存，保存后就近状态反馈成功；界面明确说明「保存仅对后续新创建的批量 Commit 任务生效；范围外改动保留在工作区」。
- [ ] 默认值正确：全新项目 / 未配置 / 配置文件损坏时，提交目录范围为「仅源代码相关目录」（默认清单以待确认 1 / 2 裁定结论为准），批量 commit 创建与执行不被阻断。
- [ ] 提交流程遵循范围：新创建批次的调度提示词（冻结于 `batch.json`）携带现行目录范围约束；`atb commit next` 领取输出的规范摘要与提示词口径一致（同一事实源，不含过期范围）。
- [ ] 范围外改动不被提交：范围外目录的工作区改动不出现在本功能产生的任何 commit 中（`git show --name-only` 抽查），且原样留在工作区（无 add 残留、无丢弃、无 stash）。
- [ ] 生效时机：修改设置后，已创建的在途批次行为不变；再次创建的新批次按新范围执行（提示词中范围已更新）。
- [ ] 核验兜底：范围外文件进入回执 commit 时按待确认 4 裁定口径被拒绝或有明确记录，不允许静默通过。
- [ ] 兼容不回归：REQ-20260911-003 隐藏口径保持（设置模块仍可见、`atb commit` 全部子命令可用、`/api/commit/*` 路由保留）；既有提交规范核验（消息格式 / 单号 / 描述长度 / 测试业务分离 / 条目文档归类）与 `commit-batch-20260910-013.test.mjs`、`commit-serve-20260910-014.test.mjs` 等既有断言不回归。
- [ ] UI 状态反馈齐全：加载中骨架、加载失败 + 重试、保存中禁用、保存成功（就近状态行 + toast）、保存失败（错误就近显示、草稿保留可重试）——与现有设置区（`taskSettingsAreaHtml` / `bindSettingsView`）交互一致。
- [ ] 新增 / 调整测试断言覆盖：默认回退、保存生效与批次冻结口径、领取输出携带范围、（按待确认 4 口径的）核验兜底；`npm test`（`node scripts/tests/run-all.mjs`）全绿。

## 界面展示

- **布局**：设置页在现有「批量任务」分区之后新增「批量 Commit」分区：标题 + 一句通用说明（目录范围仅约束批量 commit 的提交；范围外改动保留在工作区；保存仅对后续新创建的批次生效）+ 目录清单两组复选框——「源代码相关目录（默认勾选）」与「其他目录」，逐项带类型标注（源代码 / 看板数据 / 素材 / 插件元数据）+「恢复默认（仅源代码相关目录）」按钮 +「保存批量 Commit 设置」按钮与就近状态行。演示另附「范围效果预览」面板：模拟 `git status` 文件列表按当前草稿范围着色（将提交 / 保留工作区），直观呈现设置语义。
- **交互**：勾选 / 取消任一目录 → 状态行即时提示「有未保存的更改」，效果预览即时重算；「恢复默认」一键回到默认清单；「保存」→ 按钮禁用显示「保存中…」→ 成功（状态行 + toast「已保存，仅对后续新创建的批量 Commit 任务生效」）或失败（错误就近显示、草稿保留、可重试）；全部取消勾选触发空态警示（范围为空将无内容可提交，保存禁用并引导恢复默认）。
- **状态反馈**：正常态（已加载回显勾选）；空 / 未配置态（首次进入按默认口径显示并标注「未配置 · 默认生效（仅源代码相关目录）」）；加载态（「正在加载任务设置…」骨架，编辑与保存不可用）；失败态（设置加载失败错误条 + 重试；保存失败草稿保留）；深浅色适配沿用看板 `prefers-color-scheme` 双主题（可选项，演示内置主题切换）。

可交互演示：[./ui-demo.html](./ui-demo.html)（单文件、无外网依赖、无构建步骤，浏览器直接打开；内置加载 / 失败 / 未配置空态切换、目录勾选与恢复默认、保存三态模拟、范围效果预览与深浅色切换；全部数据为模拟，不访问真实服务、不执行任何 Git 操作）。

### 演示核对路径

1. 「正常加载」场景：设置页可见「批量任务」与新增「批量 Commit」分区；源代码目录默认勾选、其他目录未勾；预览面板中范围内文件标「将提交」、范围外文件标「保留在工作区」。
2. 勾选 / 取消任一目录：状态行变「有未保存的更改」，预览即时重算；「恢复默认」回到初始勾选并清除未保存标记。
3. 点「保存」：按钮禁用显示「保存中…」→ 成功状态行 + toast；打开「模拟保存失败」开关再保存：错误就近显示、草稿保留，再次保存可成功。
4. 切换「加载中」/「加载失败」：分别出现骨架与错误条 + 重试按钮，重试后回到正常；切换「未配置（空态）」：分区按默认口径展示并标注「未配置 · 默认生效（仅源代码相关目录）」。
5. 全部取消勾选：出现空态警示、保存禁用；「恢复默认」可解除。默认清单（尤其 `docs/` 是否纳入）以 README 待确认 1 / 2 裁定结论为准，演示中的清单仅为示意。

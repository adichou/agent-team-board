# REQ-20260909-013 隐藏文件模块

- 状态：accepted（已接受；实际状态以 status.json 为准）
- 创建：2026-09-09T12:18:00.147Z

## 描述

本项是**暂态隐藏，不是功能删除**：仅让相关入口在界面上不可见、不可达，数据与服务端能力全部保留，且要求以低成本可恢复的方式实现（具体手段由开发阶段 design.md 定稿）。

### 范围与现有依据

本条目标题为“隐藏文件模块”，既有验收同时涵盖讨论入口、详情讨论页签和新建类型收敛。本次保留既有目标，不把标题扩大解释为删除功能。开发前需按下列待确认项裁定附带范围；演示中的目标场景展示的是既有验收的完整收敛方案，不代表待确认项已获得确认。

- `scripts/web/index.html` 现有顶栏模块导航为「讨论 / 需求 / 任务 / 文件 / 营销 / 发布 / 设置」（`data-view` 依次为 `oncall` / `status` / `runs` / `files` / `marketing` / `release` / `settings`；营销为 REQ-20260910-019、发布为 REQ-20260910-029），统一新建弹窗类型含 `value="ask"`。本项只隐藏「讨论」「文件」两个入口，「营销」「发布」等其余模块不在隐藏范围、不受影响。
- `scripts/web/app.js` 的详情渲染包含“讨论纪要”页签及条件显示的“来源讨论”跳转；搜索结果包含 `data-goto-view="files"` 的“在文件查看”入口。因此仅隐藏顶栏不足以满足“界面不可达”，实施时还需覆盖搜索结果及详情中的间接入口。
- 隐藏限定为产品界面与路由入口；文档预览、附件查看和条目内 `ui-demo.html` 链接仍需可用。文件读取接口不能因隐藏整个文件模块而一并禁用。
- 本阶段仅完善 README 和演示；恢复方案、具体实现与开发测试用例留待开发阶段，本文未声明功能已经实现或测试已经通过。

### 待确认

1. 标题与既有正文范围不一致：是否同时隐藏讨论模块及详情“讨论纪要”，待确认；当前演示沿用既有正文目标，不能据此视为新增授权。
2. 新建类型是否同步移除“讨论（ASK）”，待确认；若保留，必须另行明确创建成功后的可达落点，不能继续跳转已隐藏模块。
3. “来源讨论”应整行隐藏还是保留不可点击的来源文字，待确认；两种方式均须保留底层关联字段，且不得跳入已隐藏模块。
4. 恢复入口的实现方式、开关默认值及恢复后是否保留历史视图选择，待确认，开发阶段记录于 design.md。

## 验收标准

- [ ] 顶栏模块导航仅隐藏「讨论」「文件」两个入口，收敛为「需求 / 任务 / 营销 / 发布 / 设置」（「营销」「发布」不在隐藏范围）；剩余入口点击切换正常，当前视图高亮正确，导航行无被隐藏入口的空占位。
- [ ] 地址栏带 `?view=oncall` 或 `?view=files` 打开 / 刷新页面：回落到需求模块，无空白视图、无控制台报错；URL 中的 view 参数被清理或改写为有效视图。
- [ ] 统一新建弹窗「类型」只有「需求（REQ）」「Bug（BUG）」两项（口径以「待确认 2」裁定为准）；需求 / Bug 创建全流程（含截图上传与粘贴，REQ-20260909-009）不回归。
- [ ] 需求与 Bug 详情抽屉页签行为「基本信息 / 说明 / 设计 / 测试用例」；「讨论纪要」页签按钮与分区不再渲染；打开详情后网络面板不再出现 `/api/oncall/tickets` 与 `/api/req-disc` 请求。
- [ ] 「基本信息」页签 meta-grid 不再展示「来源讨论」行（口径以「待确认 3」裁定为准）；其余 meta 字段（状态 / 类型 / 归属 / 认领者 / 创建 / 更新 / 最近报告）与下属 Bug 列表、批量执行设置不受影响。
- [ ] 详情页签失效回落机制不回归（REQ-20260909-006 口径）：文档页签对应文件缺失时仍给空态提示，不请求报错；会话内不残留指向已隐藏页签的激活态。
- [ ] 搜索结果中的“在文件查看”及其他间接入口不能进入隐藏模块；需求搜索、文档预览、附件查看和条目演示链接仍可正常使用。旧链接回落保留 project 等与模块无关的参数。
- [ ] 暂态可逆：服务端接口与数据零改动——`docs/agent-team-board/` 下 `discussions/`、`oncall/` 等目录无删改；`curl` 抽查 `/api/discussion/board`、`/api/req-disc` 等仍可用（带 project 参数）；不写任何 status.json；恢复方式记录在 design.md。
- [ ] `npm test`（`node scripts/tests/run-all.mjs`）全绿；因入口隐藏而失效的既有断言（如 `workbench-layout.test.mjs` 的 W2 导航顺序断言——现状为 `oncall/status/runs/files/marketing/release/settings`，更新后应保留 `marketing`/`release`、仅移除 `oncall`/`files`——与 W8 讨论 / 文件搜索占位符断言、`new-item-nav.test.mjs` 的创建讨论进入讨论模块断言）随本需求同步更新口径，不删除与本项无关的断言。
- [ ] 界面验证：深浅色两种外观下导航行、详情页签行、新建弹窗均无残留样式（如被隐藏按钮的空占位、页签行错位）。

## 界面展示

- **布局**：三处收敛——(1) 顶栏模块导航（REQ-20260910-012 页签已并入顶栏、无独立第二行）由「讨论 / 需求 / 任务 / 文件 / 营销 / 发布 / 设置」收敛为「需求 / 任务 / 营销 / 发布 / 设置」，导航行不再出现被隐藏入口的空位；(2) 需求 / Bug 详情抽屉页签行由五页签（基本信息 / 说明 / 设计 / 测试用例 / 讨论纪要）收敛为四页签，页签行宽度自适应、无「讨论纪要」残影；(3) 统一新建弹窗「类型」下拉由三项收敛为需求 / Bug 两项；基本信息 meta-grid 无「来源讨论」单元格。演示页内置「隐藏前 / 目标（隐藏后）」整体切换，并逐项标注对应改动点。
- **交互**：导航按钮点击切换模块（目标态仅剩「需求 / 任务 / 营销 / 发布 / 设置」五个入口，「营销」「发布」为占位演示、本项不改动）；详情页签点击切换内容区（目标态四页签；隐藏前五页签，可点开「讨论纪要」查看其原内容：关联讨论列表 + 文档讨论区块说明）；新建弹窗类型切换联动字段；演示页提供「模拟打开旧链接 ?view=oncall」按钮，触发深链回落反馈（回落到需求模块的提示条）。
- **状态反馈**：正常态（导航 / 页签 / 弹窗切换即时生效）；回落态（旧深链 view=oncall / view=files 打开后自动落回需求模块并给出一次性提示，URL 同步清理）；空态（文档页签缺失文件时维持「尚未创建，开发阶段补充」空态，不回归）；加载 / 失败（保留的说明与测试用例页签显示加载占位；勾选模拟失败后切换文档页签显示失败原因与重试按钮，重试恢复正文；目标态不发出讨论相关请求。快速切换页签时旧请求不得覆盖当前页签）。深浅色适配沿用看板 `prefers-color-scheme` 双主题。

可交互演示：[./ui-demo.html](./ui-demo.html)（单文件、无外网依赖、无构建步骤，浏览器直接打开；内置现状 / 目标场景切换、页签与导航交互、旧深链回落演示）。

### 演示核对路径

1. 切换“目标（隐藏后）”，检查需求 / 任务 / 营销 / 发布 / 设置可切换且没有隐藏入口空位（营销 / 发布为占位说明，本项不改动）；打开新建弹窗，检查类型与标题校验。
2. 分别模拟 `view=oncall`、`view=files` 旧链接，检查回落需求、高亮与模拟地址同步更新，并出现提示。
3. 在需求详情点击“设计”查看缺失文档空态；点击“说明”或“测试用例”查看加载与正常态；勾选模拟失败后切换文档页签，再点“重试”。
4. 隐藏前进入讨论模块或讨论页签，再切到目标场景，检查自动回落且无隐藏页签残留。演示使用虚拟数据与模拟请求，不访问真实服务、不创建条目。

# 设计 — REQ-20260924-006 文档编写流程优化

> 由 Agent 在 /dev 开发前补充，人可随时批注。

## 背景

发布模块「文档编写」步现状（REQ-20260921-008 / 012 / 022-003 / 024-001 / 004 累积）：
六按钮（刷新 / AI 总结 / AI 翻译 / 审查 / 整体审查 / 提交）+ 三阶段条 + 语言页签文件列表；
编辑能力在「审查」对话框（按类型页签、全语言 N 栏并排）；AI 校对入口只在「整体审查」
完结对话框内，结果以整段文本逐条列出并只提供「✎ 修改」跳转。本需求把主操作按
**AI 总结 → 二次编辑 → AI 校对 → AI 翻译 → 提交** 五步组织，并优化校对建议的查看与
处理交互；不改变既有门禁语义（边界第 1 条：未经人工确认不移除逐文件审核与整体审查完结）。

## 方案

### 1. 五步操作条（scripts/web/build.js renderDocsPane）

- 顶部新增五步操作条：`① AI 总结`（复用 data-pf-summary / summaryBtnText）、
  `② 二次编辑`（新 data-pf-edit，打开默认语言单语言编辑弹窗）、`③ AI 校对`
  （新 data-pf-proofstep，直接启动校对，不再要求先开整体审查对话框）、
  `④ AI 翻译`（复用 data-pf-translate / translateBtnText，叠加未处理建议计数门禁）、
  `⑤ 提交`（复用 data-pf-commit / commitBtnHtml）。
- 既有辅助动作 `刷新 / 审查 / 整体审查` 保留在语言集同行的 `.bld-docs-actions`
  （六按钮数据钩子全部保留，BUG-20260921-017 单行结构不变）；三阶段条、语言页签、
  门禁条、整体审查对话框（含自动检查与既有「AI 校对」入口）原样保留。
- 加载 / 失败态五步条恒渲染（按钮带「数据未就绪」title），与六按钮口径一致。
- startProofread 放开 `pf.finalize.open` 前置（整体审查对话框内入口照常可用）。

### 2. 二次编辑弹窗（默认语言单语言）

- 新状态 `pf.edit = { open, file, mode:'edit'|'preview', content(草稿), disk(最近已知磁盘
  内容，null=读取中), busy(保存中), loadErr, pending(未保存保护), savedNote }`。
- 文件下拉只列默认语言文件（4 类 + LICENSE + 自定义 KEY.md；不含其他语种对照列），
  取自 normalizeFlowEval().defaultFiles；读取走既有 GET /api/build/docs，保存走既有
  POST /api/build/docs/save 白名单通道（≤2MiB 口径），成功后同步 docsFlow。
- 未保存保护（不用 window.confirm——内置浏览器会冻结，BUG-20260907-009 口径）：
  有未保存修改时刷新 / 换文件 / 关闭（含 Esc / 遮罩）不直接执行，先在弹窗内联提示
  「保存并继续 / 放弃修改并继续 / 留在本文件」；保存失败不执行挂起动作、不丢输入、
  不显示已保存。
- 预览态复用 renderMd（Markdown 富文本）；编辑态 textarea input 即回写草稿防重渲染丢字。

### 3. AI 校对建议侧栏（文档区域右侧）

- 文件列表区与建议侧栏组成 `.bld-docs-main` 两栏栅格（窄屏纵向堆叠）。
- 数据源：既有 docscheck 账本（pf.plan.docsCheck，轮询自动吸收），不新增后端存储
  （边界第 2 条：建议生产/回执字段、存储、并发冲突检测待确认——本单不落新事实源）。
- 侧栏头部：文件下拉（默认语言非单文件清单）+ 待处理计数；状态：
  - 未运行：「尚未校对」空态（引导点 ③）；
  - 进行中：进度 x/y + 当前文件；
  - 中断：原因 + 「重试 AI 校对」；
  - 完成：选中文件无问题 → 「该文件未发现问题 ✓」；有问题 → 逐条建议卡片。
- 建议卡片：问题类型（classifyChkIssue 启发式：待确认 / 链接 / 错别字 / 语法 / 行文规范）、
  位置（parseIssueLineNo 行号，无行号显示「无行号」）、回执原文（data-i18n-skip，
  REQ-20260924-004 口径）；解析出「修改前 → 建议」对（parseChkSuggestion，兼容
  「原文「A」→ 建议「B」」格式）时提供展开差异（del/ins 高亮 + 「修改前（删除）/
  修改后（新增）」文字标签，不只靠颜色）与「接受 / 拒绝」；未解析出前后文本的条目
  接受禁用，保留「✎ 修改」跳二次编辑弹窗定位。
- 接受（acceptChkSuggestion）：先取磁盘最新内容，定位行/全文包含「修改前」文本才替换
  （单处替换），POST 保存成功才记「已接受」（保存失败不误标、可重试）；文本已变化或
  找不到 → 记「过期」不覆盖；已决断条目幂等不重复应用。接受产生的保存沿用既有语义
  （文件回退待审核、翻译基准失效由服务端 baselineShift 求值）。
- 拒绝（rejectChkSuggestion）：仅记「已拒绝」，原文不动。
- 决断仅存会话态 `pf.chkDecisions['<runId>|<file>|<idx>']`（新一轮校对 runId 变化自然
  重置；不持久化——存储口径待确认，边界第 2 条）。
- 含「待确认」的条目显示「待确认」状态（接受禁用）：与边界第 3 条一致——无法验证的
  链接不得判成有效或确定失效，只能人工核实或拒绝。

### 4. AI 翻译与提交的门禁衔接

- startTranslation / translateBtnHtml：最新完成 run 的未处理建议 > 0 时阻止并提示数量
  （未处理 = 待处理，已接受 / 已拒绝 / 过期视为已处理）；默认语言全部已审核且无剩余
  语言 → 明确「无翻译目标，可跳过翻译」单语言空态（不再报「尚缺 0 个」）。
- 默认语言文档在校对后又有修改（任一默认语言文件非 reviewed）时侧栏提示「接受前会
  核对原文，不一致标记过期」；重新校对/翻译的既有联动（baselineShift 回退、审核回退）
  不变。提交步沿用现有「全部已审核 + 整体审查完结」门禁与真实提交结果反馈。

### 5. AI 校对提示词（scripts/lib/publish-flow.mjs buildDocProofreadPrompt）

- 检查项在错别字 / 语法标点 / 行文规范之上补「超链接有效性」；并约束：网络不可达或
  需要登录才能验证的链接一律标「待确认」，不得判为有效或确定失效（外链验证的超时 /
  重定向 / 登录态判定策略待确认——先要求如实区分「确定失效」与「无法验证」）。
- 总结提示词既有「关联范围按实际代码与提交核实变化，不简单罗列需求 / Bug 原文」与
  「只总结默认语言」约束已覆盖验收第 2 条，不动。

### 6. 样式与 i18n

- scripts/web/style.css：五步条、两栏栅格、建议卡片（del 浅红 / ins 浅绿 + 文字标签，
  深浅色用既有 CSS 变量）、二次编辑弹窗样式。
- scripts/web/i18n.js：全部新增界面文案登记 EN / EN_DYNAMIC（中文原文为键；插值句走
  EN_DYNAMIC，◇ 占位；EN 值保持唯一——D1e）。
- 键盘可达：全部交互用原生 button / select / details；Esc 关闭二次编辑弹窗（未保存时
  先走内联保护）。

### 影响面

- scripts/web/build.js（renderDocsPane 内联五步条与建议侧栏；新增二次编辑弹窗、建议
  接受/拒绝行为；translateBtnHtml / startTranslation 门禁）、scripts/lib/publish-flow.mjs
  （校对提示词两行）、scripts/web/style.css、scripts/web/i18n.js、scripts/tests/
  req-20260924-006.test.mjs。不改服务端接口与状态机；不删任何既有入口 / 门禁 / 钩子
  （data-pf-refresh / summary / translate / review / finalize / commit 六钩子与
  docsStageBar、审查对话框、整体审查对话框全部保留）。
- 兼容约束：旧测试以 vm 提取 renderDocsPane（不带新纯函数）运行——建议解析 / 计数
  调用只出现在旧夹具不经过的分支（docsCheck 存在时）；translateBtnHtml 中对
  chkPendingCount 的调用以 typeof 守卫兜底，旧提取口径不回归。

**开源选型（REQ-20260909-015）**：纯前端原生实现（无新依赖）：diff 呈现用 HTML
del/ins 元素 + 少量 CSS（数据已是「修改前/修改后」文本对，无需引入 diff 库做行级
对齐）；Markdown 预览复用既有 vendored marked。自研理由：无合适库——所需能力为
数行字符串定位替换与标记渲染，引入开源 diff/虚拟 DOM 库的成本高于自研，且 license
审批与体积收益不匹配。

## 风险与边界

- 建议「接受」是单处字符串替换（基于回执的「原文→建议」文本对），不保证语义级合并；
  行级定位 + 包含校验 + 过期标记把误覆盖窗口压到最小，复杂改动引导走「✎ 修改」人工编辑。
- 决断不持久化：刷新页面后建议回到待处理（账本 issues 仍在，重新逐条处理即可）；
  持久化与并发冲突检测随边界第 2 条待人工确认后另立条目。
- 外链验证策略（超时 / 重定向 / 登录态）待确认：本单只在提示词与展示层区分
  「确定失效 / 待确认」，不做自动重试或登录探测。
- 不移除逐文件审核与整体审查完结门禁（边界第 1 条）；演示 ui-demo.html 已在条目目录，
  本单不改演示文件。

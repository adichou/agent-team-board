# REQ-20260913-003 批量任务去掉批次概念，每次启动到结束就实时执行当前的任务

- 状态：accepted（已接受，文档完善中）
- 创建：2026-09-13T13:06:33.959Z

## 描述

当前批量任务（任务模块的「批量开发」「批量完善」两类）以「批次」为核心概念运转：

- 点击「启动」= **创建批次**（生成 `batch-YYYYMMDD-NNN` 批次号）并复制调度提示词；批次在创建时点**冻结候选范围**（`scripts/lib/batch.mjs` `createBatch`）。
- 有未结束批次时可再创建批次**排队**（FIFO，REQ-20260906-025），队首结束后自动接续；界面展示「排队批次」「第 N 位」「排队新批次」「删除排队批次」等批次队列概念。
- 调度提示词绑定批次：包含「你是当前项目的**批次**调度员」「**批次**：`<batchId>`」「批次摘要入口 `batch check --batch <batchId>`」及批次排队接续说明（`generatePrompt`）。
- 运行概况显示批次号 chip；条目详情显示「已入批次 `<batchId>`（状态）」；全局任务视图按批次账本聚合简报。
- 运行中新置计划的条目在领取时才「并入批次」（`absorbNewCandidates`），对用户表现为多一层间接概念。

本需求要求**去掉「批次」这一层概念**：

- 点击「启动」不再创建批次，而是直接开始**一轮连续执行**（从启动到结束）；启动后每完成一项，就**实时**从当前已计划队列（最旧优先）领取下一项执行，直到实时队列取空或人工暂停/终止。
- 不再存在冻结候选范围：领取时刻队列里有什么就取什么，运行中新移入计划的条目**立即可见、立即可取**，不需要「并入批次」的间接说法。
- 提示词、面板、全局视图、条目详情不再出现批次号与「批次」字样；调度核对口径改为按本轮执行实时取单，不依赖批次标识。
- 同项目同一时间仍只有一个执行会话（实施互斥保持不变）；执行中再次点击「启动」不新建，而是明确提示已在执行中。
- 「暂停后续领取」「终止」的语义保持与现状一致；本轮全部处理记录保留可查，只是不再以「批次」为分组单位。
- 范围覆盖「批量开发」与「批量完善」两类批量任务（批量 Commit 已随 REQ-20260911-010 回退移除，不涉及）。

对需求口径的解读：一次「启动」开启一轮从启动到结束的连续执行，期间每一项任务都在领取时刻实时确定；不是「每次启动只执行一项」。若与预期不符，请在验收前指出修正。

## 验收标准

- [ ] 「批量开发」「批量完善」面板点击「启动」不再创建批次：无批次号生成或透出，直接进入本轮执行的待启动/执行中状态；启动行为仍保持「复制调度提示词，登记运行后才算执行中」的既有口径。
- [ ] 调度提示词不含「批次」「batchId」「批次摘要入口 --batch」及批次排队接续等字样；包含实时取单指令（每完成一项实时从已计划队列最旧优先领取下一项）。
- [ ] 执行期间每一项领取均实时读取当前已计划队列（最旧优先）；运行中新移入计划的条目立即出现在待处理队列并可被领取，无需任何「并入」操作；实时队列取空即本轮结束。
- [ ] 运行面板不再显示批次号、排队批次列表、「排队新批次」「删除排队批次」等批次队列概念；概况/队列/提示词/记录四分区的其余能力（当前条目、耗时、计数、暂停/恢复、终止、重新执行）保持可用。
- [ ] 全局任务视图不再按批次聚合展示批次号/排队简报，改为按项目与本轮执行状态聚合；条目详情不再显示「已入批次」。
- [ ] 同项目互斥保持：同一时间只有一个执行会话；执行中重复「启动」被拒绝并给出明确提示，不产生排队对象。
- [ ] 「暂停后续领取」（当前项继续、不再领取下一项）与「终止」（停止派发、剩余项出局、记录保留、在途需人工停止）行为与现状一致。
- [ ] 本轮处理记录保留可查（按本轮执行的运行记录展示，不以批次分组）；异常（失败/受阻/中断）计数与「重新执行」入口不受影响。
- [ ] 界面（面板 + 全局视图 + 条目详情）与提示词中不再出现「批次」相关文案与批次号。

## 界面布局

任务模块一级页签「批量完善 / 批量开发」不变；「批量开发」面板：

- 无进行中任务时：启动区——「启动」主按钮 + 实时已计划队列预览（最旧优先，前 3 项 + 等 N 项）+ 说明文案；下方为实时待处理队列（最近 2 条 / 共 N 条）。
- 有进行中任务时：运行面板四分区页签「概况 / 队列 / 提示词 / 记录」：
  - 概况：状态 chip（**不再有批次号 chip**）、当前条目（可跳转）、子代理会话、开始时间、耗时、最后活动、计数行（已处理/异常/处理中/待处理/共 N）、操作按钮（暂停后续领取/恢复、终止任务）。
  - 队列：**仅实时待处理队列**（已计划条目，最近 2 条 / 共 N 条，支持搜索过滤）；无排队批次节。
  - 提示词：主调度提示词全文 + 复制按钮（无批次行、无批次摘要入口、无接续说明）。
  - 记录：本轮处理记录表格（条目、结果、耗时、重新执行）。
- 「批量完善」面板同口径：候选为已接受未完善条目，实时读取。
- 全局任务视图：按项目聚合一轮执行的简报（状态、计数、最近记录），无批次号、无「排队中」批次行。

## 交互行为

- 「启动」：有实时候选时可用；点击复制调度提示词并进入「待启动」状态（复制成功 ≠ 执行中）；在 Agent 会话粘贴并登记运行后面板转为「执行中」。无候选时禁用并说明原因。
- 实时队列：随主轮询（约 2s）自动刷新；新条目「移入计划」后无需手动操作即出现在待处理队列；执行中主调度每完成一项即实时领取下一项。
- 「暂停后续领取」/「恢复后续领取」：只阻止领取下一项，当前项继续。
- 「终止任务」：二次确认后停止派发，剩余项出局，记录保留；终止后可再次「启动」开启新一轮。
- 执行中重复「启动」：按钮禁用或点击后明确提示「已在执行中」，不新建任何对象。
- 队列空时：本轮结束，概况显示「本轮已结束」，可再次启动。

## 状态反馈

| 状态 | 呈现 |
| --- | --- |
| 空闲无候选 | 「启动」禁用，提示「暂无已计划候选：请先在看板接受条目并『移入计划』」，待处理队列显示空态 |
| 空闲有候选 | 「启动」可用，预览「已计划队列（最旧优先）：REQ-…、BUG-… 等 N 项」 |
| 待启动（已复制未登记） | 状态 chip「待启动」，提示「请在 Agent 会话粘贴调度提示词」 |
| 执行中 | 状态 chip「执行中」，当前条目 + 已用时 + 计数行实时刷新；新移入计划条目即时入列 |
| 已暂停 | 状态 chip「已暂停」+ 提示「已请求暂停后续领取：当前项继续执行，完成后暂停」 |
| 本轮结束 | 「本轮已结束」成功提示 + 「启动新一轮」按钮（无实时候选时禁用并说明） |
| 已终止 | 警示「任务已人工终止：本轮全部处理记录已保留；在途子代理请在对应会话人工停止」 |
| 异常（失败/受阻） | 计数行「异常 N」+ 记录行标注结果，提供「重新执行」入口 |

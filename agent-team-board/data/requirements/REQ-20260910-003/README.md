# REQ-20260910-003 增加一个全局看板，可以看到当前在工作的批量任务

- 状态：accepted（已接受；实际状态以 status.json 为准）
- 创建：2026-09-09T16:12:50.387Z

## 描述

### 口径解读

- 「全局」＝**跨项目**。看板当前是单项目视角：顶栏项目选择器（`#projectSel`）一次只绑定一个项目，URL `?project=` + localStorage `atb.project` 记忆当前项目（`scripts/web/app.js` `switchProject()` 约 542 行）。「全局看板」指聚合**全部已注册项目**（`~/.agent-team-board/projects.json` 注册表，服务端 `/api/health` 已透出 `projects` 列表，`scripts/server.mjs` 约 1324–1336 行）的聚合视图，回答「现在哪些项目有批量任务在跑、各跑到哪了」。
- 「当前在工作的批量任务」＝**未收尾的批量任务**，覆盖两类账本（口径与现有 `unfinishedBatches()` 一致，`scripts/lib/batch.mjs` 约 291 行）：
  1. **批量开发**批次：`docs/agent-team-board/dispatch/batches/<batchId>/batch.json`，状态词表 `prepared / running / paused / needs_attention / finished`（`BATCH_STATUSES`，batch.mjs:38）+ `abortRequested/aborted` 人工终止标记；含批次队列中非队首的排队批次（REQ-20260906-025，非队首 `prepared` 显示「排队中」）；
  2. **批量完善**批次：`docs/agent-team-board/refine/batches/RFB-*/batch.json`（`kind: refine`），状态词表同上。

  「在工作的」包含：执行中 / 待启动（提示词已复制、尚未登记运行）/ 排队中 / 已暂停 / 执行状态待核对；**已结束（finished）与已终止（aborted）不出现**，收尾后下一轮刷新自动移出。
- Codex 后台自动派发执行器（`dispatch/settings.json` `codex.enabled`）是否纳入聚合：**待确认**——其看板入口已随 REQ-20260908-020 隐藏（渲染分支仅保留给存量执行记录深链），首期建议只聚合上述两类批次账本，不展示执行器状态。

### 背景 / 现状（基于代码静态核查，2026-09-10）

- 看板五模块导航：讨论 / 需求 / 任务 / 文件 / 设置（`scripts/web/index.html` 约 34–40 行，`VIEWS` 约 app.js:599 行），全部按当前项目渲染。
- 任务模块（「任务」页签 `#runsView` → `#batchDrawer`）只展示**当前项目**的一级页签「批量完善 / 批量开发」（`renderBatchDrawer()` 约 3288 行），数据来自项目绑定的 `GET /api/batch/current`、`GET /api/refine/current`（server.mjs 约 1464 / 1627 行，均随 `?project=` 解析 dataDir）。
- 批量任务本身是多项目的：批次账本存在**各项目自己的** `docs/agent-team-board/` 下，本项目注册表里已有 16 个项目。要查看其他项目的批量任务，用户必须逐个切换顶栏项目选择器、再进任务模块——没有一处能同时看到所有项目「正在工作」的批量任务及其进度。
- 服务端无任何跨项目聚合接口（`/api/*` 仅 `/api/health`、`/api/register` 与项目无关，其余全部绑定单项目）；前端无全局视图。

### 目标

在看板新增一个**全局视角的任务总览**：一处列出所有已注册项目中当前在工作的批量任务（批量开发 + 批量完善），随主轮询自动刷新，并能一键跳回对应项目的任务模块查看详情与执行操作。

### 范围与边界

1. **只读聚合 + 跳转**：全局面板首期只展示与导航，不提供暂停 / 终止 / 删除等操作——这些仍到对应项目的任务模块执行（沿用现有口径：「暂停后续」只阻止领取下一项，在途子代理须在对应会话人工停止）。是否后续在全局面板内直接操作，待确认。
2. 聚合数据**实时读盘**（与现有面板一致，不新增缓存状态机），不写任何账本、不改条目 `status.json`。
3. 展示口径对齐项目内任务面板：批次状态 chip（执行中 / 待启动 / 排队中 / 已暂停 / 待核对 / 已请求暂停标记）、当前条目与 owner、进度计数（已上报 / 异常 / 待处理 / 总数）、开发人员、创建 / 最后活动时间。
4. web 前端与 Electron 壳（`npm run app`）共用同一页面，同步受益，无需壳层单独适配。
5. 实现细节（聚合接口形态、轮询节奏、前端组件划分）由 design.md 定稿。

## 验收标准

- [ ] 看板提供全局任务总览入口（主导航或任务模块内，位置由 design.md 定稿并保持与其他模块导航一致的交互习惯），URL 深链可直达并随 `syncProjectUrl` 机制写入 `?view=`（与现有非 status 模块一致）。
- [ ] 总览聚合**全部已注册项目**（`/api/health` 的 `projects` 口径）的在工作批量任务：批量开发 `batch-*` 与批量完善 `RFB-*` 两类；已结束 / 已终止批次不出现。
- [ ] 每条任务至少展示：所属项目（名称 + 路径提示）、任务类型（批量开发 / 批量完善）、批次号、状态 chip（含排队中 / 已请求暂停等附属标记）、当前条目编号与标题、进度计数（已上报 / 异常 / 待处理 / 总数）、开发人员、创建时间与最后活动时间；口径与项目内任务面板一致（同一批次在两处显示相同状态与计数）。
- [ ] 提供按状态（执行中 / 待启动 / 已暂停 / 待核对等）与类型（批量开发 / 批量完善）的筛选，以及编号 / 项目名关键词过滤（复用任务模块现有搜索口径）。
- [ ] 点击某条任务（或其项目）可跳转到**对应项目**的任务模块并定位到该批次所在子面板：顶栏项目选择器同步切换、URL `?project=` 更新，跳转后可直接执行暂停 / 终止等既有操作。
- [ ] 随主轮询自动刷新（现有 2 秒节奏，app.js `setInterval(poll, 2000)`）：批次开始（他项目新创建并登记运行）与收尾（finished / aborted）在下一轮刷新内反映——新任务出现、收尾任务移出，无需手动刷新页面。
- [ ] 状态反馈完备：首次加载有加载态；所有项目均无在工作的批量任务时有空态说明；**单项目读盘失败（数据目录缺失 / JSON 损坏 / 路径已不存在）只影响该项目行**（行内标注错误原因），不阻塞其他项目展示、不整页报错。
- [ ] 全局面板纯只读：不调用任何写接口、不改变任何项目批次 / 条目状态；对未初始化（无 `docs/agent-team-board/`）的注册项目按「该项目无任务」处理而非报错。
- [ ] 无注册项目时给出引导空态（提示先在看板打开 / 注册项目）。
- [ ] 深浅色外观适配与现有模块一致（`prefers-color-scheme` 双主题，不引入只支持单主题的样式）。

可交互演示：**[./ui-demo.html](./ui-demo.html)**（单文件 HTML，浏览器直接打开；含布局、交互与状态反馈的动态演示）。

### 界面布局

- 沿用看板既有四行头部（品牌行 / 模块导航 / 模块副标题 / 筛选区），在模块导航「任务」旁新增「全局」页签；全局视图主体为**任务总览列表**，不依赖顶栏项目选择器（全局面板不随项目切换变化）。
- 列表上方一行**汇总条**：「N 个项目 · M 个在工作的批量任务（执行中 x · 待启动 y · 排队中 z · 已暂停 w · 待核对 v）」+ 右侧筛选 chips（全部 / 执行中 / 待启动 / 已暂停 / 待核对 + 类型：批量开发 / 批量完善）+ 关键词搜索框（复用模块搜索样式）。
- 列表按项目分组（组头：项目名 + 完整路径提示 + 该项目任务数），组内每条任务一行卡片：
  - 行首：状态 chip（执行中 / 待启动 / 排队中 / 已暂停 / 待核对，附「已请求暂停」小标）+ 任务类型 chip（批量开发 / 批量完善）；
  - 中部：批次号（等宽字体）· 当前条目编号（可点击）与标题 · 子代理会话 owner；
  - 行尾：进度计数「已上报 a / 异常 b / 待处理 c / 共 d」+ 开发人员 + 创建 / 最后活动时间（相对时间）。
- 底部一行说明文字：数据随看板轮询自动刷新；操作请进入对应项目任务模块。

### 交互行为

- 点击任务行（或行内「进入项目任务」按钮）：切换顶栏项目到该任务所属项目 → 打开任务模块并定位对应子面板（批量完善 / 批量开发）与运行概况页签；URL 更新为 `?project=<路径>&view=runs`，浏览器返回可回到全局视图。
- 点击当前条目编号：同上并高亮该条目（复用 `data-goto-item` 既有跳转语义）。
- 筛选 chips 与搜索框即时过滤列表（前端过滤，不发请求）；汇总条计数随筛选联动。
- 面板内无暂停 / 终止 / 删除按钮——只读聚合；行内不提供任何写操作入口。
- 2 秒轮询刷新：数据变化才重渲染（沿用签名比对口径，不打断用户正在进行的筛选与悬停）。

### 状态反馈

- **加载中**：首次进入或刷新时显示列表骨架占位（行级浅色块），不阻塞头部导航切换。
- **正常**：≥1 个在工作的批量任务，按项目分组展示；新任务出现 / 收尾任务移出随轮询自动发生，无全局 toast 打扰。
- **空态**：所有项目均无在工作的批量任务 → 居中说明「所有项目的批量任务均已收尾；到各项目任务模块可启动新任务」。
- **部分失败**：某项目数据不可读 → 该项目组降级为一行错误卡（项目名 + 「读取失败：<原因>」，如目录不存在 / JSON 损坏），其余项目不受影响；错误行不提供重试按钮，随下轮轮询自动重试读取。
- **无注册项目**：引导空态，说明先在顶栏注册 / 打开项目。
- **连接异常**：沿用看板顶栏轮询指示灯（`#pollState`）口径，接口失败时全局视图保留上一次数据并提示「刷新失败，正在重试」。

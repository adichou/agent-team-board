# REQ-20260907-013 支持当前已有批次执行中时，可以创建新批次。没在执行中的新批次可以被删除。

- 状态：submitted（待人工接受）
- 创建：2026-09-07T15:35:05.866Z

## 描述

批量实施的批次看板补两块能力：

### 1. 已有批次执行中时，可以创建新批次（看板入口）

核心层排队能力（REQ-20260906-025）已允许在批次未结束时创建新批次入队（CLI `atb batch create` / `POST /api/batch/create` 均可），但看板 UI 在当前批次未结束时没有任何创建入口（只有批次结束后才出现「创建下一批」）。本需求补齐看板入口：

- **界面布局**：Status Board → 任务抽屉 →「Zcode 批次」子面板，当前批次运行视图的操作区（与「暂停后续」「查看批次记录」同一行）新增「排队新批次」按钮。
- **交互行为**：当前批次未结束（执行中 / 已暂停 / 待启动）且非待人工核对（needs_attention）时显示；点击走与创建表单相同的创建流程（勾选集合为候选范围，未勾选时为全部可实施新候选），新批次 FIFO 排到队尾。
- **状态反馈**：创建成功 toast「✓ 已创建批次 X 并已加入队列，排第 N 位，当前批次结束后自动开始」（复用既有文案），下方「排队批次」列表即时新增该批次；无可实施新候选时 toast 报错说明。

### 2. 没在执行中的批次可以被删除

新增批次删除能力（core / CLI / API / UI 全栈）：

- **删除口径**（什么能删）：
  - 允许：无在途运行的批次——排队中未执行（prepared）、已暂停（paused）、项间空隙（running 但当前无执行）、已结束（finished）。
  - 拒绝：存在在途运行（reserved / running 等非终态）的批次，错误信息指明在途 runId；`needs_attention` 批次（须先人工核对并通过「暂停→恢复」解除项目占用，删除会丢失恢复入口，故不允许）。
- **删除效果**：仅移除批次账本目录（`dispatch/batches/<batchId>/`，与既有保留清理 pruneBatches 同口径）；条目业务状态、运行记录（runs/）不动；被删批次的候选条目回到可入批候选池，后续创建批次可重新入批。队列为动态计算，删除后位次自动前移，无需迁移；删除队首未执行批次后，下一批次自动成为队首并解除防抢阻塞。
- **界面布局与交互**：排队批次列表每项末尾提供「删除」按钮；当前批次视图在无在途执行（当前条目为空）且非 needs_attention 时，操作区提供「删除本批次」按钮。两者点击后弹页面内自绘确认框（danger 样式，说明删除后果），确认后才调用删除接口。
- **状态反馈**：删除成功 toast 提示，列表 / 面板即时刷新（删除队首后显示下一队首或回到创建表单）；删除被拒（在途 / 待核对 / 批次不存在）时 toast 显示服务端原因。
- **入口**：CLI `atb batch delete <BATCH-ID>`（必填显式批次号，防误删队首；`--batch` 等价）；API `POST /api/batch/delete { batchId }`，非法时 400。

## 验收标准

- [ ] 当前批次未结束（执行中/暂停/待启动）时，看板 Zcode 批次面板提供「排队新批次」入口，创建成功后新批次排到队尾并即时出现在排队列表
- [ ] 有批次在途执行时创建新批次仍成功入队（CLI/API，回归 REQ-20260906-025 口径）
- [ ] 删除排队中（未执行）批次：账本目录移除、队列位次前移、下一批次自动成为队首且可正常领取
- [ ] 删除有在途运行的批次被拒绝（CLI 非 0 / API 400），错误指明在途运行
- [ ] needs_attention 批次不可删除（提示先人工核对恢复）
- [ ] 已结束（finished）批次可删除；删除不存在的批次报「找不到批次」
- [ ] 看板：排队列表项与当前批次（无在途时）均有删除入口，操作前有确认框，删除后界面即时刷新

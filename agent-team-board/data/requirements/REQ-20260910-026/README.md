# REQ-20260910-026 全选和全不选使用图标，去掉文字，然后把操作按钮和开始完善按钮放在同一行

- 状态：以 status.json 与看板实时状态为准
- 创建：2026-09-10T09:52:47.462Z

## 描述

登记原文：全选和全不选使用图标，去掉文字，然后把操作按钮和开始完善按钮放在同一行。

本需求针对**需求列表头的单行工具栏**（`#reqCaption`，REQ-20260910-008 建立、REQ-20260910-016 起排序入口已迁走），做两处纯 UI 调整：

1. **全选 / 全不选改为图标按钮**：现状是带文字的小按钮「☑ 全选」「☐ 全不选」（`scripts/web/index.html` 第 118-119 行）；调整后去掉「全选」「全不选」文字，仅保留图标（沿用 ☑ / ☐ 字形或等价图标，最终图标样式见「待确认」），按钮语义通过 `title` 悬浮提示与 `aria-label` 保留，不损失可访问性。
2. **批量操作按钮与「开始完善」按钮同一行**：现状工具栏为 `flex-wrap: wrap`（`scripts/web/style.css` 第 354-362 行），「已选 N 项 + 批量动作」组（`#selGroup`）与「▶ 开始完善」快捷入口（`#laneQuickEntry`，`margin-left: auto` 靠右）是两个独立伸缩项，宽度不足时会各自换行、可能落到不同行；调整后两者恒定同行呈现（批量动作组与快捷入口绑定为同一行内的一组，空间不足时不拆散到两行）。

功能行为全部沿用现状：全选仅勾选当前筛选档内可见可操作条目（叠搜索范围，所见即所选，REQ-20260908-027）、全不选仅清当前档（其他档勾选保留，BUG-20260907-016 契约）、批量动作按档显隐与防误触、「开始完善 / 开始开发」仅导航不创建任务。本需求不新增任何交互能力，只改呈现。

### 已核实的现状（代码依据）

- `scripts/web/index.html` 第 114-134 行：工具栏结构为 提示 `#reqCount` → 全选 `#selectOperable`（「☑ 全选」）→ 全不选 `#selectNone`（「☐ 全不选」，初始 disabled）→ `#selGroup`（`#selCount`「已选 N 项」+ 按档批量动作「接受所选 / 移入计划 / 驳回待接受 / 移出计划」）→ `#laneQuickEntry`（已接受档「▶ 开始完善」/ 已计划档「▶ 开始开发」）。
- `scripts/web/style.css` 第 354-374 行：`.req-caption` 与 `.sel-group` 均 `flex-wrap: wrap`——宽度不足时按组整体换行，`#laneQuickEntry` 靠右独立成项，与 `#selGroup` 不绑定同行。
- `scripts/web/app.js`：
  - `syncAcceptance`（第 2364-2460 行）：零选择时 `#selGroup` 整组隐藏（勾选首项后出现）；批量进行中按钮文案变「接受中… / 移入中… / 驳回中… / 移出中…」；`#laneQuickEntry` 按档显隐与换文案、仅导航且批量进行中也不禁用；全选 / 全不选仅在三个可选择档（待接受 / 已接受 / 已计划）显示，非选择档整体隐藏（BUG-20260909-008）。
  - `selectOperable` / `deselectOperable`（第 2732-2751 行）：全选 = 当前筛选档内可见可操作条目（叠搜索范围）；全不选 = 仅清当前档勾选；`anyBatchPending`（第 2358-2361 行）任一批量操作进行中时两者防误触禁用。
  - 全不选在当前档零勾选时禁用；全选在当前档无可操作条目时禁用。
- 既有行为回归测试：`scripts/tests/selection-lane-scope.test.mjs`、`selection-bar-merge.test.mjs`、`caption-toolbar-20260910-008.test.mjs`（工具栏结构契约）——本需求实现时须保持其语义通过（「全选 / 全不选」若改为图标节点，相关静态断言需同步调整，属开发阶段事项）。

### 界面布局

- 工具栏左起：全选图标按钮、全不选图标按钮、批量动作组（「已选 N 项」计数 + 当前档批量动作）；「▶ 开始完善」（已接受档）/「▶ 开始开发」（已计划档）快捷入口与批量动作组**同一行**，空间足够时整组靠右。
- 全选 / 全不选为等宽小图标按钮（无文字），两按钮尺寸一致、与工具栏基线垂直居中；悬浮提示与无障碍标签保留完整语义（「全选：仅勾选当前筛选档内可见的可操作条目…」「全不选：仅取消当前筛选档的勾选」口径不变）。
- 批量动作组与快捷入口绑定为同一行内的一组：宽度不足时不把两者拆到两行（可整组换行，或压缩组内间距；极窄兜底口径见「待确认」）；全选 / 全不选图标按钮与提示文案仍允许按现状自然换行，不产生横向滚动与裁切。
- 非选择档（开发中 / 待测试 / 已完成）不显示全选 / 全不选与批量动作，不留空占位（沿用 BUG-20260909-008 口径）；待接受档无快捷入口（沿用现状，仅已接受 / 已计划两档有）。
- 零选择时批量动作组整组隐藏，工具栏不因零 / 非零选择切换改变行结构（沿用 REQ-20260910-008 口径）。

### 交互行为

- 点击全选图标：勾选当前筛选档内可见的可操作条目（叠搜索范围，所见即所选），其他档勾选不动；点击全不选图标：仅取消当前档勾选，其他档保留。语义与现状完全一致，仅入口外观变化。
- 全不选在当前档零勾选时禁用；全选在当前档无可操作条目（如空档 / 搜索无命中）时禁用；任一批量操作进行中两者与复选框均禁用防误触。
- 批量动作按档显隐与逐条流转行为不变：待接受「接受所选」、已接受「移入计划 + 驳回待接受」、已计划「移出计划」；进行中按钮文案与禁用态沿用现状。
- 「▶ 开始完善 / ▶ 开始开发」仍为仅导航入口（进入任务模块对应面板，与勾选无关，批量进行中不禁用），同行呈现不改变其点击行为。
- 键盘与无障碍：图标按钮保留 `aria-label` 与 `title`，Tab 顺序不变，焦点轮廓可见；图标按钮可被屏幕阅读器念出「全选 / 全不选」。

### 状态反馈

- 正常：勾选、全选、全不选即时更新「已选 N 项」与批量动作显隐；图标按钮禁用态（零勾选 / 无可选项）以灰显呈现，悬浮提示说明原因。
- 空档 / 搜索无命中：列表呈现空态说明；全选禁用（无可操作项）、全不选禁用（零勾选）；工具栏无批量动作组空占位。
- 批量处理中：批量按钮文案变「接受中… / 移入中… / 驳回中… / 移出中…」，全选 / 全不选 / 复选框禁用；结果区显示逐条进度文案，工具栏行结构保持稳定不跳动。
- 失败：结果区保留可读错误与失败条目清单（`编号：错误信息` 列表），部分成功口径沿用现状；图标化与同行调整不吞掉、不改变任何反馈。

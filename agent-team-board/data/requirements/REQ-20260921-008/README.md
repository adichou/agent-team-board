# REQ-20260921-008 发布模块的文档编写页面优化

- 状态：accepted（已接受）
- 创建：2026-09-21T01:09:03.904Z

## 描述

### 背景与现状

发布模块的五步流程（版本计划 → 关联条目与提交 → **文档编写** → 合并入 main → 正式发布，REQ-20260920-003）中，第三步「文档编写」由 `scripts/web/build.js` 的 `renderDocsPane` 渲染，现状为：

- 上部「AI 写作」区：提示词（`publish-flow.mjs` 的 `buildDocWritingPrompt`）+「复制提示词」+「TRAE CN / TRAE 打开」入口；
- 中部文档编辑区：类型 / 语言下拉（README / CHANGELOG / FEATURES / AGENTS × 中 / 英）+ 编辑 / 预览切换 + 保存；
- 下部提交区：八个文件 chip（状态为 未编写 / 未提交 / 已提交 / 需重新编写）+「提交文档到 Git」。

本需求重构该步骤的信息架构与工作流：把「AI 写作」更名为「AI 总结」，引入「总结 → 审查 → 提交」三段式流水线，为八个发布文档提供逐文件状态跟踪、集中审查对话框（中英双栏同步滚动对比）与提交门禁，并让 AI 总结作为独立锁的批量任务在任务模块与全局任务面板可见。

涉及文件（现状代码事实）：

- `scripts/lib/publish-flow.mjs`：八个发布文档清单（`publishDocFiles`：README / CHANGELOG / FEATURES / AGENTS × 中英共八个）、文档状态机（`evaluateDocsState`）、五步门禁（`publishStepsState`）；
- `scripts/web/build.js`：`renderDocsPane` / `STEP_LABEL` / `DOC_STATE_LABEL`（前端渲染）；
- `scripts/server.mjs`：`/api/build/publish-plan`、`/api/build/docs`、`/api/build/docs/save`、`/api/build/docs/commit`、`/api/build/docs/open-ide`；
- `scripts/lib/task-settings.mjs`：任务类型 `TASK_KINDS = ['refine', 'develop']`（AI 分析 / AI 开发）——AI 总结为新增第三类任务形态；
- 锁现状：AI 开发占用 `runtime/.locks/impl.lock`（项目实施互斥），AI 分析占用 `runtime/.locks/refine.lock`，两者已相互隔离。

### 需求要点（原文）

0、AI 写作改成 AI 总结。
1、文档编写页签下方显示副标题，阐述文档编写的目标和功能。
2、副标题右侧提供刷新按钮、AI 总结、审查，提交四个按钮。刷新是刷新所有文件以显示最新内容。AI 总结是拷贝提示词到 AI Agent 中执行。审核需要弹出对话框，通过多页签的方式显示每个文件的内容，并提供编辑和预览功能。中文和英文需要提供双栏对比视图，并且需要同步滚动。提交是提交文档到git 本地dev 分支。
3、副标题下方以列表形式显示所涉及的八个文件，并在右侧提供状态显示，状态包括未总结，正在总结，已总结待审核，已审核几个状态。
4、刷新和 AI 总结、审查按钮一直可用，也可以不用 AI 总结，直接审查修改。提交按钮必须等所有八个文件都是已审查状态才可用。
5、AI 总结是单独的锁，和 AI 分析、AI 开发是隔离的。在任务模块中可以查看 AI 总结的进度，例如到哪个文件了。在全局任务面板也能看到 AI 总结的任务信息。

### 术语与状态机

- 八个文件：`README.md`、`README.en.md`、`CHANGELOG.md`、`CHANGELOG.en.md`、`FEATURES.md`、`FEATURES.en.md`、`AGENTS.md`、`AGENTS.en.md`（与 `publishDocFiles()` 同源清单）。
- 文件状态四态（本需求新增，替代现状 未编写 / 未提交 / 已提交 / 需重新编写 在本页签的展示口径）：

```
未总结 ──（AI 总结执行中）──▶ 正在总结 ──（该文件总结完成）──▶ 已总结待审核
   │                                                              │
   └────────────（不经 AI 总结，直接审查修改后人工通过）───────────┤
                                                                  ▼
                                                              已审核 ──（再次编辑修改）──▶ 回到已总结待审核
```

- 「已审查」=「已审核」（需求原文两种写法，本单统一用「已审核」）。

### 副标题与操作区（需求 1、2）

- [ ] 「文档编写」页签（五步导航）下方显示副标题，说明本步骤目标与功能：围绕当前版本八个发布文档（README / CHANGELOG / FEATURES / AGENTS 中英）完成 AI 总结、人工审查与提交到本地 dev。
- [ ] 副标题右侧依次提供四个按钮：**刷新**、**AI 总结**、**审查**、**提交**。
- [ ] 刷新：重新从磁盘读取八个文件内容与状态并刷新展示（外部 IDE 修改后可取回最新内容）；读取期间有加载反馈，失败时显示错误与重试入口，不静默。

### 文件列表与状态（需求 3）

- [ ] 状态流转符合「术语与状态机」：AI 总结执行到某文件时该文件显示「正在总结」，完成后变「已总结待审核」；人工在审查对话框中通过后变「已审核」；对已审核文件再次编辑修改后回退为「已总结待审核」（需重新审查）。

## 交互行为

- **刷新**：点击后进入加载态（按钮禁用 / 列表显示读取中），重新读取磁盘八个文件内容与状态后刷新展示；失败显示错误横幅与「重试」。外部 IDE 修改后由此取回最新内容。
- **AI 总结**：点击复制提示词（剪贴板 + 成功 toast + 提示词预览），随后 AI 总结任务逐文件推进：文件依次「正在总结 → 已总结待审核」；运行期间按钮显示进度（如「总结中 3/8」）且任务模块 / 全局面板同步更新；已审核的文件跳过不再总结。也可不经 AI 总结直接进入审查。
- **审查**：打开对话框，按文档类型切页签；每页签中英双栏并排、同步滚动（编辑态同步 textarea 滚动、预览态同步内容区滚动）；每栏独立切换编辑 / 预览、独立保存、独立「通过审核」；对已审核文件再编辑即回退为已总结待审核并提示需重新审查；页脚实时显示已审核计数；关闭对话框随时可关（编辑内容已按栏保存为准）。
- **提交**：八个文件全部已审核前禁用（title / 提示说明缺口）；满足后点击进入提交中状态，成功显示提交 hash 与「已提交到本地 dev 分支」反馈，失败显示原因且内容不丢、可重试；提交仅含八个文档 pathspec。
- **状态联动**：任一文件状态变化即时反映到列表、门禁条与提交按钮可用性。

## 状态反馈

- **正常态**：列表显示八个文件与四态之一；门禁条显示「x/8 已审核」；AI 总结运行中列表与任务模块均显示当前文件。
- **加载态**：刷新（正在读取最新内容…）、提交（提交中…）、AI 总结（单文件正在总结 + 总进度 x/8）。
- **空态**：全新版本八个文件均「未总结」时，列表完整显示八行（文件恒为八行，不出现空列表）；任务模块 AI 总结分区显示「暂无进行中的 AI 总结任务」。
- **失败态**：刷新失败（错误横幅 + 重试）、提交失败（原因 + 可重试，内容保留）、AI 总结失败 / 中断（任务模块标记失败与原因，文件状态不悬挂在「正在总结」）。
- **门禁反馈**：提交按钮禁用时 hover / 提示给出缺口明细（哪些文件未审核、各处什么状态）。
- **锁隔离反馈**：AI 总结运行时任务模块标注其使用独立锁，与 AI 分析 / AI 开发互不占用。

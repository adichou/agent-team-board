# REQ-20260906-018 批量实施入口改造：已接受列多选后进入，移除顶栏按钮

- 状态：submitted（待人工接受）
- 创建：2026-09-06T08:50:54.709Z

## 描述

批量实施的入口从顶栏常驻按钮改为「已接受列内多选 → 进入批量实施」的交互，交互形态仿照 REQ-20260906-017（批量接受）落地后的多选模式；主界面（顶栏）的「⚡ 批量实施」按钮移除。批量实施界面本身（Zcode 批次 / Codex 自动派发的共用抽屉，REQ-20260906-002/003）保持既有功能不回退，仅入口与选择方式改变。

## 界面布局

- **顶栏**：移除「⚡ 批量实施」按钮及其事件绑定；顶栏不再有任何批量实施入口。
- **已接受列**：
  - 列内提供「批量实施」模式入口（与 REQ-20260906-017 批量接受的多选入口形态保持一致：同为列级操作，位置、按钮样式跟随其最终实现）。
  - 进入多选模式后，已接受列的每张卡片出现选择框（复选框或与 017 一致的选择态样式）；其他列（待接受/开发中/已完成）不出现选择框。
- **选择确认条**：多选模式下列内/列顶出现操作条，显示「已选 N 项」与「进入批量实施」「取消」操作。
- **批量实施界面**：进入后仍为现有共用抽屉（Zcode 批次 / Codex 自动派发两个页签），布局不变。

## 交互行为

1. 在已接受列点「批量实施」（或与 017 一致的入口）进入多选模式。
2. 勾选需要实施的已接受条目（可全选/清空，行为对齐 017 的多选工具）。
3. 点「进入批量实施」打开批量实施抽屉：
   - **Zcode 批次页**：创建批次时，批次候选范围 = 本次勾选的条目集合（而非当前全部自动可入批条目）；未勾选的已接受条目不进入本批。
   - **Codex 自动派发页**：自动派发的选单范围同样以本次勾选集合为准——仅勾选的条目可被自动派发；未勾选条目在本次会话中不被领取（关闭自动派发或清空选择后恢复默认「全部已接受」行为，需在界面明示当前生效范围）。
4. 点「取消」或按 Esc 退出多选模式，选择清空，不打开抽屉。
5. 勾选集合失效条件：条目被认领/流转离开已接受状态时自动从集合中移除，选择条计数同步更新。

## 状态反馈

- 多选模式：「已选 N 项」实时更新；无勾选时「进入批量实施」按钮禁用并提示原因。
- 进入抽屉后：Zcode 批次页与 Codex 页均显示当前生效的条目范围（如「本批范围：勾选 N 项」），与未过滤时的展示可区分。
- 勾选集合失效（条目被别人认领等）：toast 或行内提示告知「X 已不在已接受状态，已从选择中移除」。
- 顶栏按钮移除后，执行账本/当前执行的查看入口：从已接受列多选进入；若 017 的交互支持无选择直接查看，则对齐其行为（待对齐 017 最终形态后实施时确认）。

## 范围与协调

- 依赖交互形态对齐：REQ-20260906-017（批量接受，实施中）——本条目的多选 UI 跟随其最终实现，避免两套多选交互。
- 影响共用抽屉：REQ-20260906-002（Zcode 批次）、REQ-20260906-003（Codex 自动派发）——批次创建与自动派发选单需支持「指定条目集合」过滤；后端 API（/api/batch/create、调度器选单）需要相应扩展。
- 本条目只改入口与范围过滤，不改变抽屉内既有功能与账本协议。

# REQ-20260921-002 分支浏览提交记录升级为 git 提交树可视化并支持搜索

- 状态：submitted（待人工接受）
- 创建：2026-09-20T23:48:58.330Z

## 背景与动机

发布模块「分支浏览」（REQ-20260913-001）右栏目前是纯行式提交列表，分支拓扑（从哪个分叉、何时合并、tag 落点）只能靠 message 推断。多分支并行开发（main / dev / feat-*）已是常态，需要对标 VS Code「源代码管理 → 图形视图」的提交树展示：左侧彩色泳道 + 提交圆点 + 分支/合并曲线 + 分支名与 tag 标签，并支持搜索定位。

选型结论（对话中论证并本地 demo 验证）：

- **渲染层用 @gitgraph/js 1.4.0**（npm 包自带 `lib/gitgraph.umd.min.js`，约 36KB，MIT，在 REQ-20260909-015 License 白名单内）。它是当前唯一无框架依赖、免构建的浏览器 commit 树渲染库；gitgraph.js 仓库虽已归档，但 API 冻结、体积小，工具型项目风险可控。React 系替代（@tomplum/react-git-log、commit-graph、git-graph-svg）与本项目零框架零构建前端不匹配，已排除。
- **引入方式走 vendor 例外**：当前 web 前端无 npm 构建链，第三方库以 vendor 的 UMD bundle 放 `scripts/web/` 直接引用是既有先例（highlight.js、marked、wunderbaum）；按 REQ-20260909-015 标注复制范围（仅官方发布的 gitgraph.umd.min.js 构建产物）与原因（无构建链，无法以 npm 依赖方式引入），并在本条目目录维护 licenses.md。
- **搜索是数据层自建能力**（库不提供）：demo 已验证两种模式，「高亮定位」渲染后给 SVG `<text>` 加 class + 滚动定位；「过滤」按匹配提交沿 parent 算**祖先闭包**后把保留集重放重画，泳道连通不断线。该逻辑与渲染库解耦，后续换渲染方案可复用。

方案验证 demo（不入仓库，佐证见 `attachments/`）：@gitgraph/js 真实 bundle 渲染 + 模拟本仓库提交历史（main/dev/feat 分支、REQ/BUG 单号 message、merge、tag），两模式搜索实测通过（过滤 `BUG-20260920-005`：匹配 2 条、保留 5/11 条含祖先）。

## 界面展示

**可交互演示：[./ui-demo.html](./ui-demo.html)**（REQ-20260908-021 口径：单文件、内联 CSS/JS、无外网依赖、无构建步骤，浏览器直接打开；演示数据为模拟数据 + 内联自绘泳道渲染，实际实现按上文选型 vendored @gitgraph/js，分页控件沿用现状未纳入演示）。演示覆盖：

- **界面布局**：发布模块 → 分支浏览整屏——左分支列表（本地/远端分组、当前分支徽标、同步工具条与说明）+ 右提交树（泳道图形列 + 提交行 + 顶部搜索工具条与计数）。
- **交互行为**：搜索 message / 分支名 / tag（忽略大小写）双模式实时切换（高亮定位 / 过滤保留祖先）+ 快捷词（BUG-20260920-005 / i18n / v0.1.0）；点击提交行出/收详情（沿用 REQ-20260920-001 行选中口径）；切换分支重置搜索回默认列表；切换分支/刷新有加载反馈。
- **状态反馈**：正常（含「匹配 N 条 · 保留 M/T 条」计数、已到末尾提示）；加载（「加载提交记录中…」/「搜索中…」，输入与按钮随 loading 禁用防重复触发）；读取失败（错误提示 + 重试）；搜索无匹配（「没有匹配的提交（关键词：…）」+ 一键清除）；空分支（「该分支暂无提交」）；非 git 仓库（沿用引导空态，不出现搜索与树视图）。深浅色跟随系统并可手动切换。

ASCII 线框（结构示意，可选补充；完整交互见上方演示）：

```
┌─ 分支浏览 · 右栏 ────────────────────────────────────────────────────┐
│ [ 🔍 搜索 message/分支/tag…  ] [高亮定位 ◉|过滤 ○] 匹配2·保留5/11    │
├───────────┬──────────────────────────────────────────────────────────┤
│  泳道     │  提交                                                      │
│  ●──      │  711cd99  chore: 初始化 agent-team-board 仓库             │
│  ●──      │  f62d519  doc: README 环境与运行命令 REQ-…                │
│ ●─●────── │  d353523  feat: 看板骨架与条目状态机 REQ-…  ← dev        │
│ ●─●─●──── │  581a33b  test: 版本计划… BUG-…  ← feat/version-plan     │
│ ●─●─●─╮   │  ed0a331  fix: 版本计划… BUG-…                           │
│ ●─●───╰─● │  (merge dev)                                              │
│  ●────     │  …（tag: v0.1.0 落点以标签展示在对应提交旁）              │
├───────────┴──────────────────────────────────────────────────────────┤
│ （过滤模式：泳道只保留匹配+祖先，右侧计数实时更新；清空恢复全量）      │
└──────────────────────────────────────────────────────────────────────┘
```

交互行为与状态反馈（要点，详见演示）：

- **数据与外观**：提交树数据来自分支浏览既有 git log 链路；泳道配色、圆点、行距走 `templateExtend` 定制（按分支身份稳定配色，main/dev/feat-* 各一色；分支头节点外圈 + 分支名标签，tag 标签随提交展示，合并提交双圈 + 「合并 · N 父提交」），浅/深色跟随系统外观（与现有 highlight 主题切换同口径）。
- **搜索-高亮定位**：输入即匹配 message/分支名/tag（忽略大小写），匹配项高亮加粗、自动滚动到首条；清空关键字恢复。
- **搜索-过滤**：仅保留匹配提交及其全部祖先（沿 parent 闭包），泳道连通、无断线孤点；工具条显示「匹配 N 条 · 保留 M/T 条」；清空恢复全量。
- **空态**：非 git 仓库沿用现有引导空态，不出现搜索与树视图；空分支沿用「该分支暂无提交」；搜索无匹配与「该分支暂无提交」区分并附一键清除。

## 验收标准

- [ ] 分支浏览右栏渲染提交树：彩色泳道、提交圆点、分支合并曲线、分支名标签、tag 标签、message（+短 hash）；浅/深色跟随系统。
- [ ] 提交树数据复用分支浏览既有服务端 git log 链路，不新增后端服务依赖；分页/数量口径与现状一致或在设计中明确变更。
- [ ] 搜索框支持 message / 分支名 / tag 忽略大小写匹配，提供「高亮定位」与「过滤（保留祖先）」两种模式：高亮模式匹配项高亮并滚动定位；过滤模式保留集为匹配+祖先闭包、泳道连通，显示匹配/保留计数；清空恢复全量。
- [ ] 界面文案中英文同步（scripts/web/i18n.js，BUG-20260912-001 口径），i18n 相关测试通过。
- [ ] `scripts/web/` vendor 官方发布的 gitgraph UMD min bundle，标注复制范围与原因（REQ-20260909-015 vendor 例外口径）；条目目录维护 licenses.md（库名 @gitgraph/js / 版本 1.4.0 / 引入方式 vendor UMD / License MIT / 仓库地址 github.com/nicoespeon/gitgraph.js）。
- [ ] 非 git 仓库沿用空态口径，不出现失效入口。
- [ ] TDD：新增测试先行跑红后跑绿，交付前 `npm test` 全量通过。

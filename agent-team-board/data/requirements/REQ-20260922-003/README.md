# REQ-20260922-003 发布看板的文档编写页面支持增加多份自定义文档。增加的文档要在 AI 总结提示词中加上

- 状态：submitted（待人工接受）
- 创建：2026-09-22T00:00:43.781Z

## 描述

发布看板「发布流程 → 文档编写」步目前的发布文档清单固定为 4 类标准文档（README / CHANGELOG / FEATURES / AGENTS）× 语言集。本需求：

1. 文档编写页面支持**增加多份自定义文档**：用户可在标准 4 类之外自行添加若干份文档（如迁移说明 `MIGRATION.md`、安全策略 `SECURITY.md` 等），数量不限一份。
2. **增加的自定义文档要并入「AI 总结提示词」**：点击「AI 总结」生成并复制的提示词中，默认语言文档清单需包含全部自定义文档（与标准 4 类并列），使 AI 总结子代理一并逐文件总结这些文档（进度回执、待审核状态与其余文档同口径）。

自定义文档的命名规则、持久化作用域，以及是否同样进入 AI 翻译 / 审查门禁 / 提交 pathspec 等范围，需求原文未说明，见「待确认」；落定前不得弱化既有三阶段门禁与提交口径。

## 背景（现状）

- 文档清单固定 4 类：`scripts/lib/publish-flow.mjs` 的 `PUBLISH_DOC_KEYS = ['README','CHANGELOG','FEATURES','AGENTS']`，`publishDocFiles(langs)` 按「4 类 × 语言集」展开（REQ-20260921-010 语言集，默认 `cn,en`，存于版本记录 `v.langs`）；没有任何添加自定义文档的入口。
- AI 总结提示词：`publish-flow.mjs` 的 `buildDocSummaryPrompt` 静态段写死「本阶段只总结默认语言……的 4 个文档（4 类 × 1）」，运行参数区「默认语言文档清单」仅列 `defaultDocFiles`（默认语言 4 文件）；不含任何自定义文档。
- AI 总结执行账本：`scripts/lib/docs-summary-store.mjs` 的 `createSummaryRun` 按默认语言 4 文件初始化 run 的 files 账本（`pending` 起步）；`atb summary file` 逐文件回执按 run 自身账本校验（不依赖全局固定白名单，账本含新文件即可回执）。
- 保存 / 审核白名单：`scripts/server.mjs` 的 `/api/build/docs/save`、`/api/build/docs/review` 用 `flow.isPublishDocFile` 校验（仅语言集内 4 类展开文件）；提交 pathspec（`/api/build/docs/commit`）= `flow.publishDocFiles(langs)`。
- 三阶段门禁与审查界面：`publish-flow.mjs` 的 `evaluateDocsFlow`（阶段一默认语言全部已审核 → 解锁 AI 翻译；阶段二剩余语言全部已审核 → 解锁整体审查完结；完结后解锁提交）；`scripts/web/build.js` 的 `renderDocsPane`（文件列表按语言页签、七态 chip、六按钮、阶段条、门禁条）与 `renderReviewModal`（按 4 类文档页签 + 每类全语言栏对比）。
- 文档编写页布局现状：顶部一行 = 语言集输入框 + 六按钮（刷新 / AI 总结 / AI 翻译 / 审查 / 整体审查 / 提交）；其下为阶段条、AI 总结 / AI 翻译提示词预览、按语言页签的文件列表、门禁条。
- 界面文案中英文同步是项目质量基线（BUG-20260912-001，词典集中在 `scripts/web/i18n.js`）。

## 需求规则

1. **添加入口（多份）**：文档编写页提供「添加自定义文档」入口，可添加多份（>1）自定义文档；添加后即时出现在文件列表中（默认语言页签，沿用七态状态机，初始「未总结」），与标准 4 类文档并列展示。命名合法性与数量上限口径见「待确认」。
2. **并入 AI 总结提示词（核心）**：点击「AI 总结」时生成的提示词中，默认语言文档清单包含全部自定义文档（与标准 4 类并列逐行列出）；提示词中的文档总数、阶段说明（「共 N 个文档」）与实际一致；复制到剪贴板的口径不变。
3. **总结账本与进度联动**：自定义文档进入 AI 总结 run 的 files 账本（`pending` 起步，逐文件回执 `summarizing` / `summarized`）；进度分母 `total`、「总结中 x/N」按钮文案、语言页签审核计数角标、任务模块进度均随自定义文档数量联动；`atb summary file --file <自定义文档文件名>` 回执可被接受。
4. **状态机一致**：自定义文档沿用文档七态（未总结 / 正在总结 / 已总结待审核 / …… / 已审核）与「通过审核」hash 口径；是否进入 AI 翻译范围、整体审查完结、提交门禁与提交 pathspec 按「待确认」落定结果执行，落定前不得弱化既有门禁。
5. **校验**：非法命名、与标准 4 类或语言集展开文件重名、与已添加自定义文档重复等情形给出明确报错且不应用，界面保持上次有效状态。
6. **持久化与回显**：自定义文档清单持久化，重新进入文档编写页正确回显（作用域与锁定时机见「待确认」）。
7. **不回归**：标准 4 类文档、语言集展开、三阶段门禁、审查对话框、提交行为不受影响。

## 界面布局

基于文档编写步现有布局（顶部动作行 → 阶段条 → 提示词预览 → 文件列表 → 门禁条），变更点：

1. **顶部动作行**（不变）：语言集输入框 + 六按钮（刷新 / AI 总结 / AI 翻译 / 审查 / 整体审查 / 提交）。
2. **文件区表头行**（扩展）：左侧计数「文件（N · 默认语言 x/y 已审核 · 剩余语言 a/b 已审核）」随自定义文档联动；右侧新增「＋ 添加文档」按钮。
3. **添加文档行**（新增）：点击「＋ 添加文档」在文件区顶部展开内联输入行（文件名输入框 + 添加 / 取消按钮 + 行内错误提示）。
4. **文件列表**（扩展）：默认语言页签内新增自定义文档行——文件名（等宽字体）+「自定义」标识 + 七态状态 chip + 移除入口；语言页签审核计数角标分母随自定义文档变化。
5. **AI 总结提示词预览**（扩展）：details 折叠框内的提示词文本，「默认语言文档清单」含自定义文档行。
6. **门禁条 / 阶段条**（联动）：计数与缺口明细按含自定义文档的清单重算（参与口径按「待确认」落定）。

## 交互行为

1. **添加**：点击「＋ 添加文档」展开输入行 → 输入文件名（如 `MIGRATION.md`）→ 回车或点击「添加」→ 前端校验（非空 / 合法字符 / 不与标准 4 类、语言集展开文件及已有自定义文档重名 / 未超上限）→ 通过后即时加入默认语言文件列表（状态「未总结」）并收起输入行；校验失败行内报错、不应用、不破坏现有列表。
2. **移除**：自定义文档行提供移除入口；总结运行中禁止移除（按钮禁用并提示）；已总结 / 已审核 / 已提交后的移除口径见「待确认」。
3. **AI 总结**：点击后生成提示词（默认语言清单 = 标准 4 类 + 全部自定义文档）并复制到剪贴板、展开预览框；运行中按钮显示「总结中 x/N」（N 含自定义文档），文件行内显示当前文件「正在总结」标注、完成后转「已总结待审核」，非激活页签尾部显示 ◐ 运行角标；已审核文件跳过。
4. **联动刷新**：添加 / 移除自定义文档后，文件列表、表头与页签计数、提示词预览、总结进度分母、门禁条即时刷新；语言集变更时自定义文档的多语言展开口径见「待确认」。
5. **语言集**（既有行为保留）：逗号分隔缩写、回车 / 失焦应用、非法值报错不应用。

## 状态反馈

1. **添加中**：「添加中…」并短暂禁用按钮；成功 toast「已添加 <文件名>（初始状态：未总结）」。
2. **校验失败**：输入行下方行内错误（文件名不能为空 / 存在非法字符 / 与标准文档或已有文档重名 / 超出数量上限），红字提示，不应用非法值。
3. **AI 总结运行中**：按钮「总结中 x/N」+ 当前行「正在总结」标注 + 页签 ◐ 角标 + 状态行「AI 总结进行中：x/N · 当前：<文件>（正在总结）」；完成显示「AI 总结已完成：待总结文件均进入已总结待审核，等待人工审查」；中断显示红色「AI 总结中断：<原因>（可再次点击 AI 总结续跑）」。
4. **加载 / 失败态**（沿用既有口径）：进入文档编写步「正在加载发布流程数据…」；读取失败显示错误横幅 + 重试按钮，六按钮恒可见；「刷新」期间显示「正在读取最新内容…」。
5. **空态**：无自定义文档时列表仅显示标准 4 类（不显示空占位）；输入行为空提交给「文件名不能为空」错误。

## 待确认

1. **命名规则**：自定义文档文件名的合法字符集、长度上限、是否强制 `.md` 后缀、大小写口径；是否允许子目录路径（现状发布文档均在项目根）。数量上限（无限或封顶）。
2. **多语言展开**：自定义文档是否与标准 4 类一样按语言集展开多语言（`NAME_<lang>.md`）并进入 AI 翻译（阶段二）范围，还是仅默认语言单份；语言集变更时如何联动。需求原文只提「AI 总结提示词」，本 README 按「至少并入 AI 总结」为基线。
3. **门禁与提交参与**：自定义文档是否计入三阶段门禁（默认语言 x/N、整体审查完结、canCommit）与提交 pathspec；不参与时提交后磁盘上遗留未提交文件如何提示。
4. **持久化作用域与锁定**：发布计划级（类比 `v.langs` 随版本记录）还是项目级共享；merging / 已正式发布（pushed）后是否锁定增删；能否移除已总结 / 已审核 / 已提交的自定义文档，移除后审核记录与完结快照如何失效。
5. **基准变更检测**：`detectBaselineShift`（同类型默认语言 mtime 对比）是否适用于自定义文档的多语言版本。
6. **提示词与文案细节**：静态段「N 个文档（4 类 + K 自定义 × 1）」的表述形式；自定义文档在审查对话框中的页签形态（追加页签或其他）；README 互链约束确认不适用于自定义文档。

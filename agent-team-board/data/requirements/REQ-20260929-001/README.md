# REQ-20260929-001 版本计划关联放宽：已完成条目暂无关联提交也可纳入版本

- 状态：submitted（待人工接受）
- 创建：2026-09-28T16:58:20.750Z

## 描述

### 现状

版本计划「新建版本 / 关联条目」面板中，暂无关联提交（自动关联提交集为空、宽口径也无命中）的已完成（done）条目复选框被置灰，标注「暂无关联提交（先完成开发提交）」，无法纳入版本（scripts/web/build.js 候选行 `selectable = assoc.length > 0` 口径，REQ-20260927-002 延续）；「全选」跳过无提交条目并 toast 提示「N 个条目暂无关联提交已跳过」。数据层同步受限：scripts/lib/build-store.mjs 条目归一要求 commits 数组至少一个（空即判非法）。

### 问题

老项目（经数据迁移或人工确认完成的存量单）没有提交记录，条目本身已完成，却永远无法纳入任何版本计划，发布文档与版本关联清单随之缺失这些条目。例：老项目单 `BUG-20260901-001 [P0] 修复订阅权益宽限期与刷新生命周期`——完成但无关联提交，面板置灰不可选。

### 需求

只要条目为 done，无论有无关联提交，都可以在版本计划中关联：

1. **面板可选**：「新建版本」与「关联条目」两处候选面板中，done 条目一律可勾选，不再因无提交置灰；无提交条目行内标注改为中性提示（不再是「先完成开发提交」的引导，具体文案设计阶段定）。
2. **提交允许为空**：版本条目（items[].commits）允许 0 个提交；勾选无提交条目计入「已选 N 项」，不计入提交计数 M；「全选」纳入无提交条目、去掉跳过提示。
3. **下游按无提交贡献处理**：合并（挑选合并）步骤对空提交条目跳过提交合并动作、不报错；发布计划 / 文档装配、版本关联列表正常含该条目，提交区展示「暂无关联提交」空态。
4. **数据兼容**：既有含提交条目读写无回归；非法提交形态（非 40 位 hash）仍被拒；空提交的落盘形态（空数组 / 省略字段）与旧读取方兼容性在设计阶段定。

### 界面展示（创建阶段线框）

```
┌─ 新建版本 ──────────────────────────────────────┐
│ 版本名称 [                              ]        │
│ 版本号   [                              ]        │
│ [全选] [全不选]   已选 2 项 · 2 个提交           │
│ ┌────────────────────────────────────────────┐ │
│ │ ☑ REQ-20260927-002 关联提交整组自动关联…    │ │
│ │    └ 关联提交（自动关联 2 个 · 旧→新 · 只读）│ │
│ │ ☑ BUG-20260901-001 [P0] 修复订阅权益宽限期… │ │
│ │    暂无关联提交（仍可纳入版本）              │ │  ← 可勾选，不再置灰
│ │ ☐ REQ-20260905-002 …                       │ │
│ └────────────────────────────────────────────┘ │
│                                        [创建]   │
└────────────────────────────────────────────────┘
```

交互与状态反馈：

- 无提交条目复选框可用，勾选 / 取消与普通条目一致；计数条「已选 N 项」含无提交条目、M 不变。
- 「全选」纳入无提交 done 条目，不再出现「N 个条目暂无关联提交已跳过」toast。
- 勾选行内不再展开「关联提交」只读区块（无提交可展示），原宽口径命中折叠行行为保持。

## 验收标准

- [ ] done 且暂无关联提交的条目在「新建版本」「关联条目」两处面板均可勾选纳入版本，不再置灰；行内标注改为中性提示，中英文同步（i18n 词条同步更新）。
- [ ] 勾选无提交条目后创建 / 追加版本成功：版本 items 含该条目、提交为空；「已选 N 项 · M 个提交」计数口径正确（计入 N、不计入 M）。
- [ ] 「全选」纳入无提交条目；跳过类 toast 与「将被跳过」提示按新口径移除或调整。
- [ ] 挑选合并：空提交条目不产生提交合并动作、不报错；有提交条目行为不变。
- [ ] 版本关联列表 / 发布计划 / 文档装配：空提交条目正常展示与参与，提交区呈现「暂无关联提交」空态。
- [ ] 数据层：commits 允许为空并读写归一；既有含提交条目、旧单提交数据（items[].commit 别名）读写无回归；非 40 位 hash 非法形态仍被拒。
- [ ] 既有面板、合并、发布相关测试（build-ui / build-store / REQ-20260927-002 用例等）按新口径更新并全量 `npm test` 通过。
- [ ] 老项目（存在无提交记录的 done 条目）实测可正常纳入版本。

## 待确认（设计阶段）

- 无提交条目的行内标注与空态文案（中文原文 + EN 词条）。
- 空提交的数据落盘形态：`commits: []` 还是省略字段（影响 build-store 归一与旧读取方）。
- 发布文档（CHANGELOG 等）装配中空提交条目的呈现方式（无提交可链接时的条目行样式）。

## 实施口径（2026-09-29）

- 行内提示为「暂无关联提交（仍可纳入版本）」，详情空态为「暂无关联提交」，中英文同步。
- 空提交落盘为 `commits: []`，不写空 `commit` 别名；旧单提交仍可读取。
- 发布文档继续按条目纳入范围：需求列编号，Bug 计入修复数，无虚构提交链接。
- 自动验证使用同构临时项目与真实 Git 仓库；未修改真实老项目版本计划。

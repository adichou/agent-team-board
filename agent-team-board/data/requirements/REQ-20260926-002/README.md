# REQ-20260926-002 发布模块简化为条目与提交组版、挑选合并、文档翻译合并及官网更新流程

- 状态：submitted（待人工接受）
- 创建：2026-09-26T14:29:20.045Z

## 描述

重整发布模块：核心是挑选合适的已完成需求或Bug及对应提交组成版本计划，条目与提交为多对多关系。所选提交按hash去重并按历史顺序cherry-pick到main；功能变更合入后，依据本版本实际合入内容编写默认语言文档、翻译并审核，再单独提交文档并合入main；最后一步是发布，包含推送到远端和官网资料更新。取消多条目关联即混合提交的阻断及一键加入全部祖先的引导。版本计划保存关联快照，文档直接关联BLD，不要求额外REQ或BUG。

## 背景与目标

当前发布流程把提交标题引用、条目归属、Git 祖先关系和发布依赖混在一起，并要求先完成文档才能合入功能代码，导致组版困难、文档依据不明确。按用户确定的流程简化，不引入额外发布模式或多套分类工作流。

## 主流程与规则

1. **版本计划**：填写版本信息，选择已完成的需求 / Bug 和本版要包含的对应提交。条目与提交是多对多关系，允许检查与调整关联；标题中提及的单号不自动等于实际归属。计划保留条目编号、标题及提交关联快照，条目后来删除不抹除既有计划的追溯信息。
2. **挑选合并**：所选提交按完整 hash 去重，按 Git 拓扑先后顺序 cherry-pick 到 main。一个提交关联多个条目也只执行一次，不因多对多关系本身报混合提交错误。选择提交意味着包含该提交的完整变更，界面提供实际变更查看入口。不将未选祖先自动认定为必须加入的功能依赖，移除“一键加入所有依赖提交”的引导。
3. **文档编写与翻译**：功能变更合入成功后，依据本版本实际合入结果编写默认语言文档，再翻译其余语言并逐文件审核。默认语言沿用语言集首语言，不写死中文。文档依据限定为本版实际合入的变化，不能把 main 上其他变化都算进本版。
4. **文档合并**：审核通过的发布文档单独提交、合入 main 并记录到版本计划，直接关联 BLD，不要求额外创建 REQ / BUG，也不通过功能条目的 done 门禁。相关提交规范及守卫须同步支持该通道。
5. **发布（最后一步）**：发布包含推送到远端和官网资料更新两个动作：以明确的推送操作把本地 main 推送到远端，并根据版本最终文档更新官网资料；两个动作分别展示结果和失败原因。区分本地 main 已合入、远端已推送、官网资料已更新；不把本地合入等同于远端发布或网站部署成功。

失败恢复：cherry-pick 冲突展示具体提交、文件和原因；解决后可继续，已成功提交不重复执行，记录原始提交与 main 上重放提交的对应关系。文档合并或官网更新失败同样保留已完成结果并允许重试。

范围变化：功能合入后追加所选提交，需要先合入新增变化，再核对受影响文档；不回滚已有 main 提交，也不把已合入结果显示为未发生。修改计划不能静默移除已合入事实。

## 界面展示

创建阶段线框：

```text
版本计划：版本号 / 名称 / 说明
[1 选择条目与提交] → [2 挑选合并] → [3 文档与翻译] → [4 文档合并] → [5 发布]

所选需求 / Bug                 本版提交（按 hash 去重）
☑ REQ-A ────────────────┬──── abc123 [查看变更]
☑ BUG-B ────────────────┘     def456 [查看变更]
关联：abc123 → REQ-A、BUG-B；def456 → REQ-A

2 个条目 / 2 个提交                         [挑选合并到 main]
执行结果：abc123 已合入；def456 冲突 [查看详情]
```

- **布局**：版本详情保留一条五步导航；第一步同时展示条目、去重后的提交及关联，后续步骤各显示本步内容、结果和下一步入口。
- **交互**：查看和调整条目—提交关联，展开提交查看实际变更，确认所选范围后执行挑选合并；功能合入后进入文档编写 / 翻译 / 审核，再提交合并文档，最后执行发布：推送到远端并更新官网资料。
- **状态反馈**：逐步显示未开始、执行中、成功或失败；执行中防重复操作；失败展示具体原因和重试入口，保留已成功结果。不得仅因共享提交阻断，也不得以“祖先”暗示必须全部纳入。
- **可交互演示**：[./ui-demo.html](./ui-demo.html)（单文件、CSS/JS 全内联、无外网依赖、无构建步骤，浏览器直接打开）——覆盖五步导航与各步内容布局，条目—提交多对多关联勾选调整与提交「查看变更」展开，挑选合并拓扑顺序执行、冲突详情与重试（已合入提交不重复执行），文档两阶段推进（默认语言 AI 总结 + 逐文件审核解锁其余语言翻译审核、全审后提交合并解锁）与文档直接关联 BLD 合并，发布步包含推送到远端与官网资料更新两个动作，三类结果（本地合入 / 远端推送 / 官网更新）分别展示；内置正常 / 空 / 加载 / 失败恢复四种场景切换与深浅色外观切换。演示数据为示例，事实口径以本 README 与实现为准。

## 验收标准

- [ ] 一个条目关联多个提交、一个提交关联多个条目均可组版；共享提交只 cherry-pick 一次，各关联条目展示一致的合入结果。
- [ ] 标题引用其他单号不自动产生错误归属；用户能核对提交完整变更及实际关联。
- [ ] 不再出现“多个关联条目即混合提交”的阻断，不再引导一键纳入全部未选祖先。
- [ ] cherry-pick 按拓扑顺序执行；冲突可诊断，重试不会重复已成功的提交，并保存重放证据。
- [ ] 无需先完成发布文档即可合入所选功能提交；文档编写依据本版实际合入结果。
- [ ] 默认语言取语言集首语言，其余语言可翻译、逐文件审核；文档提交直接关联 BLD 并可合入 main。
- [ ] 版本计划关联快照不因条目后续删除而丢失；已合入事实不能被计划编辑静默抹除。
- [ ] 新增发布变更后，先合入新增变化，再提示核对文档，不将旧审核结果直接视为覆盖新范围。
- [ ] 最后一步为发布，包含推送到远端和官网资料更新：官网资料基于最终版本文档更新，推送以明确操作触发；本地合入、远端推送、官网资料更新分别显示真实结果，失败可重试。
- [ ] 界面中英文文案同步，旧版本计划及已有合入记录兼容，不要求重新执行已完成操作。

# REQ-20260909-005 批量任务中的智能体模型和智能或推理程度要保持和主调度会话一致

- 状态：accepted（已接受；实际状态以 status.json 为准）
- 创建：2026-09-09T00:27:36.224Z

## 描述

批量任务（批量完善 / 批量开发）当前把子代理的模型与智能档位固定在「设置 → 批量任务」的四路配置（任务类型 × 执行 Agent）里：创建任务时读取该设置，向主调度提示词注入一行固定的「子代理模型配置：<模型> · 智能档位 <档位>（来自设置「批量任务」，启动子代理时按此传递）」。该配置与主调度会话实际使用的模型 / 推理档位完全无关——用户以高档模型运行主调度会话时，子代理仍按设置值（默认完善=高、开发=中，或手填模型）执行；用户换主会话模型后，子代理档位也不跟随，导致批次内实际执行智能程度与主调度会话不一致、且随设置而非会话漂移。

本需求要求：批量任务的子代理模型与智能 / 推理程度默认**跟随主调度会话**（即用户粘贴主调度提示词、执行派发逻辑的那个 zcode / codex 会话）——主调度会话用什么模型与推理档位，本轮派发的每个子代理就用什么，不再由设置中的静态值决定。

### 现状依据（基于当前代码）

- 四路设置：`scripts/lib/task-settings.mjs` 读写 `<dataDir>/tasks/settings.json` 的 `models: { refine | develop × zcode | codex → { model, level(high/medium/low) } }`；默认 `model` 留空、`level` 完善=高、开发=中（REQ-20260908-020）。
- 提示词注入点（两处，均为创建时冻结进批次账本）：
  - 批量开发：`scripts/lib/batch.mjs` 的 `generatePrompt`——`子代理模型配置：${model || '（默认）'} · 智能档位 ${level}（来自设置「批量任务」，启动子代理时按此传递）`；
  - 批量完善：`scripts/lib/refine-store.mjs` 的 `buildRefinePrompt`——同一句式。
- 设置读取入口：`scripts/server.mjs` 的 `/api/batch/create`（读 `ts.models.develop[agent]`）与 `/api/refine/create`（读 `ts.models.refine[mode]`）；设置读写走 `/api/tasks/settings`。CLI 路径（`atb batch create` / `atb refine create`）目前不读该设置，生成的主调度提示词不含模型配置行（口径不一致的现状事实，开发阶段一并统一）。
- 设置界面：`scripts/web/app.js` 的 `taskSettingsHtml`（「批量任务」区，四列表格：执行 Agent / 子代理模型 / 推理强度 / 是否隐藏；保存后仅对后续新任务生效）。
- 主调度会话自身的模型与推理档位由用户在 zcode / codex 会话侧选择，看板当前不感知、不记录。

### 目标口径

1. **新增模型来源「跟随主调度会话」，并作为两类批量任务 × 两种执行 Agent 的默认值**：该路为跟随时，创建任务生成的主调度提示词不再注入固定模型 / 档位行，改为明确指令——启动每个子代理时，其模型与智能 / 推理档位必须与当前主调度会话保持一致；不得使用设置中的静态值，也不得落到与主会话不同的默认档。
2. **保留「手动指定」作为显式覆盖**（REQ-20260908-020 的四路 model/level 配置能力不回退）：仅当用户在某一路显式选择手动并填写模型 / 档位时，才沿用现状注入固定配置行；界面须明示「手动指定 = 主动接受与主调度会话不一致」。
3. **生效范围**：仅影响新创建的批次 / 完善任务（提示词创建时生成并冻结，沿用「保存后仅对后续新任务生效；进行中任务保持原设置」口径）；Agent 展示 / 隐藏配置、完善与开发的候选口径、执行流程与回执协议均不在本需求内改动。
4. **迁移语义**：存量已保存过 model / level 的路迁移后保留为「手动指定」且值不丢失（沿用 REQ-20260908-026「已有配置迁移保留已保存选择」口径）；从未保存过的路默认「跟随主调度会话」。

### 待确认（开发阶段 design.md 须给出结论或降级口径）

- zcode / codex 子代理启动参数是否支持显式指定模型与推理档位：支持则提示词指令为「显式传入与当前会话一致的模型与档位」；不支持则为「不另行指定、依赖子代理默认继承主会话配置」。当前项目内查不到依据，禁止臆断。
- 主调度会话能否在运行时感知自身模型与档位（影响提示词指令措辞与任务详情展示）：待确认。
- 任务模块「当前处理详情」是否展示生效的模型来源（跟随主会话 / 手动值）：建议展示，范围待开发阶段确认。

## 界面布局

改动集中在「设置 → 批量任务」区（`scripts/web/app.js` 的 `taskSettingsHtml`），从上到下：

1. 分区标题与说明：保留「批量任务」标题；说明文字增补——默认跟随主调度会话（子代理模型与智能 / 推理档位和主调度会话一致），手动指定为显式覆盖、仅在刻意需要不同模型时使用。
2. 两个配置块（批量完善 / 批量开发）各一张表格，行固定 Codex、Zcode 两行，列扩展为五列：

```
| 执行 Agent | 模型来源         | 子代理模型              | 推理强度      | 是否隐藏 |
| Codex      | [跟随主调度会话▾] | （禁用置灰+提示）        | （禁用置灰）  | [ ]      |
| Zcode      | [手动指定▾]      | [如 glm-5.3____]       | [高▾]        | [ ]      |
```

3. 「模型来源」为每行新增的下拉选择：跟随主调度会话（默认）/ 手动指定。来源为跟随时，该行「子代理模型」输入框与「推理强度」下拉禁用置灰，占位提示「跟随主调度会话，无需配置」；来源为手动时恢复现状交互（模型可留空沿用默认，强度高 / 中 / 低）。
4. 表格下方保留「保存批量任务设置」按钮与「保存后仅对后续新任务生效，运行中任务保留原设置」说明。
5. 窄屏沿用现有表格横向滚动容器（`.ts-table-wrap`），五列不换行堆叠、不遮挡；禁用态控件保留可读对比度并带 title 说明。

## 交互行为

1. **来源切换**：在某行切换「模型来源」即时切换该行模型 / 强度控件的可用性（跟随=禁用置灰，手动=可编辑），切换只改本地草稿，未保存不生效。
2. **保存**：点击「保存批量任务设置」提交 `/api/tasks/settings`（`models[kind][agent]` 增加来源字段；非法值整体拒绝、不产生半截配置，沿用现状）；成功后 toast「已保存批量任务设置（用于后续新任务）」，界面回显已保存来源；失败 toast 错误信息、按钮恢复可点。保存期间按钮禁用防重复提交（沿用现状）。
3. **提示词联动**：保存后新创建的批量完善 / 批量开发任务按所选 Agent 的来源生成主调度提示词——跟随时为「子代理模型与智能 / 推理档位须与当前主调度会话保持一致」指令（不再出现固定模型 / 档位行）；手动时沿用现状固定配置行。任务模块启动区在候选说明下增补一行「子代理模型：跟随主调度会话」或「手动：<模型 / 档位>」，使生效口径在启动前可见。
4. **迁移**：打开设置时读取 `/api/tasks/settings`，存量已保存 model / level 的路回显为「手动指定」且值原样保留；从未保存过的路回显「跟随主调度会话」。用户可随时改回跟随。
5. **兼容**：Agent 展示 / 隐藏复选框、隐藏全部 Agent 时启动区禁用并提示到此处取消隐藏的行为不变；「行首 Agent 是配置对象而非当前执行者选择器」语义不变。

## 状态反馈

- **正常**：来源=跟随时该行模型 / 强度控件禁用置灰并带占位提示；来源=手动时可编辑；已保存值与草稿不一致时以保存值为准回显。
- **加载**：进入设置视图读取任务设置期间沿用现有加载反馈；读取失败显示「设置加载失败：<原因> + 重试按钮」（沿用 `renderSettingsView` 现状），重试成功后回显五列表格。
- **保存中**：按钮禁用并保持原文（防重复提交）；成功 / 失败均有 toast，失败不清空草稿。
- **校验失败**：`/api/tasks/settings` 对非法档位 / 超长模型标识等整体拒绝（沿用 `saveTaskSettings` 现状），界面 toast 错误且不落半截配置。
- **空 / 初始化**：项目从未保存过任务设置时，全部路显示默认「跟随主调度会话」+ 默认档位占位（完善=高、开发=中仅作手动时的缺省建议）。

## 验收标准

- [ ] 两类批量任务（完善 / 开发）× 两种执行 Agent（zcode / codex）的模型来源默认为「跟随主调度会话」：按默认设置新创建任务生成的主调度提示词不再包含来自设置「批量任务」的固定模型 / 档位行，改为明确要求子代理模型与智能 / 推理档位和当前主调度会话保持一致的指令。
- [ ] 显式选择「手动指定」并保存后，新任务的提示词按该路配置注入固定「子代理模型配置」行（REQ-20260908-020 行为不回退）；跟随与手动两种口径在提示词文本中可明确区分。
- [ ] 存量已保存的 model / level 配置迁移后仍回显为「手动指定」且值不丢失；从未保存过的路默认「跟随主调度会话」。
- [ ] 设置「批量任务」区每行提供「模型来源」选择；来源为跟随时该行「子代理模型」「推理强度」控件禁用置灰并有「跟随主调度会话，无需配置」提示，来源为手动时恢复可编辑；未保存的变更不生效。
- [ ] 任务模块启动区展示所选 Agent 的生效模型口径（「跟随主调度会话」或手动值），启动前可见。
- [ ] 保存沿用防重复提交与成功 / 失败 toast；进行中任务不受保存影响、保持原提示词；设置加载失败有明确反馈且可重试。
- [ ] Agent 展示 / 隐藏、候选口径、批次执行与回执协议、窄屏表格滚动行为均无回归。
- [ ] CLI 路径（`atb batch create` / `atb refine create`）与看板路径生成的提示词模型口径统一（跟随 / 手动语义一致），不再出现一边注入一边不注入的口径分叉。
- [ ] zcode / codex 子代理能否显式指定模型与档位、主会话自身模型感知方式，在 design.md 有结论或明确的降级口径（不得以臆断实现）。

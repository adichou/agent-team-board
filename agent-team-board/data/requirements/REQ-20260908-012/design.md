# 设计 — REQ-20260908-012 Bug 单的说明文档中，针对引入来源单的描述需放置开头

> 由 Agent 在 /dev 开发前补充，人可随时批注。

## 背景

REQ-20260830-004（2026-08-30）确立「修复 Bug 必须归因引入来源」，落点为 Bug README **末尾**「关联（引入来源）」节（老样例 BUG-20260830-001）。实践中来源信息被压在文档最后，第一屏不可见：BUG-20260908-001 按现行口径只在末尾写 `## 关联（引入来源）`，被用户判为不对；BUG-20260907-017 的做法（头部元信息区第 5 行 `- 引入来源：REQ-20260907-003（经 atb list 核验存在；排查过程见「根因」）`，位于「归属需求」与「创建」之间）被用户指定为正例。本需求把「开头」固化为规范，涉及四处现状口径：

1. `skills/agent-team-board/SKILL.md` 数据规范：「修复时把来源写入 Bug README 末尾『关联（引入来源）』节（样式见 BUG-20260830-001）」。
2. `commands/bug.md` 末尾提示：「修复时在 Bug README 末尾『关联』节补写 `- 引入来源：…`」。
3. `commands/dev.md` TDD 第 4 步：「写入 Bug README『关联』节」。
4. `scripts/tests/traceability.test.mjs`（REQ-20260830-004 静态契约）：R2 断言 devCmd 含「关联」、R4 断言 SKILL.md 含「关联（引入来源）」、R5 断言样例 BUG-20260830-001 有 `## 关联` 节。

另：`scripts/lib/core.mjs` `bugReadme()` 登记模板头部只有 状态/归属需求/创建 三行，无引入来源行（与「登记阶段不填来源」的 REQ-20260830-004 修订一致，来源行历来是修复阶段手工补写——BUG-20260907-017 的头部行即后补）。

## 方案

（技术选型、接口设计、影响面）

**1. 规范口径变更（核心）**：引入来源的强制落点从「README 末尾『关联（引入来源）』节」改为「README 开头头部元信息区」——修复阶段归因时，在「归属需求」行之后、「创建」行之前补写一行：

```
- 引入来源：REQ-…（引入了什么）/ BUG-… / 未定位（排查过程：…）  三选一，ID 经 atb list/show 核验
```

正例样式即 BUG-20260907-017。末尾「关联」节降级为**补充关联**（其他相关条目，如 BUG-20260830-001 里的拥挤度相关需求）的可选位置，不再承载强制归因。REQ-20260830-004 其余语义（登记不填、三选一、核验、未定位附排查、禁止编造、根因/test-report 同样写明）一字不动，仅位置口径变化。

**2. 流程文档同步（3 个文件）**：

- `skills/agent-team-board/SKILL.md` 数据规范：改为「修复时把来源写入 Bug README **开头**头部元信息区（『归属需求』行之后，样式见 BUG-20260907-017）：`- 引入来源：…`；末尾『关联』节仅作补充关联」。
- `commands/bug.md` 提示：「修复时在 Bug README 开头头部补写 `- 引入来源：…`（登记仍不填）」。
- `commands/dev.md` 第 4 步：「写入 Bug README 开头头部 `- 引入来源：` 行」。

**3. 契约测试同步（`scripts/tests/traceability.test.mjs`，TDD 先改先红）**：

- R2/R4：把「写入『关联』节」类断言改为断言「开头/头部」口径（如 `assert.match(devCmd, /README 开头|头部元信息/)`），同时保留三选一/核验/未定位/禁止编造等原有断言不弱化。
- 新增正例守护断言：BUG-20260907-017 README（位于 `requirements/REQ-20260907-003/bugs/`，测试既有 bugDirs 搜索已覆盖该层级）头部元信息区含 `- 引入来源：REQ-20260907-003`。
- R5（老样例 BUG-20260830-001 有 `## 关联` 节）保留为样例存在性守护——新规范下「关联」节降级为可选补充，老样例不违新规。
- 反向断言：SKILL.md / dev.md 不再出现「README 末尾『关联（引入来源）』」措辞（防旧口径回潮）。

**4. 登记模板不改（推荐）**：`bugReadme()` 不加占位行，保持运行时代码零改动；来源行由修复阶段手工补写（与现状实践一致）。备选：模板预留 `- 引入来源：（修复阶段补写）` 占位行——自文档化但要动运行时代码且需与「登记不填」表述协调，**待确认**是否采用。

**5. 存量数据**：存量 Bug README（BUG-20260908-001、BUG-20260830-001 等）不强制回填，是否回填由人工定夺（**待确认**）。建议实施时在 REQ-20260830-004 README「修订记录」追加一行指向本需求（位置口径被本需求修订，保持因果链）。

## 描述

增加独立发布模块，以可恢复、可追溯的流水线支持代码推送 Git 远端和 Apple App Store 构建发布。首期仅启用这两个目标，网站与网络存储后续扩展。提供目标配置、阶段执行、日志证据、失败重试和发布历史；Git 遵循显式 ref、快进保护及推送后校验，Apple 参考 app-store-release skill 完成资料准备、构建、TestFlight、审核数据准备与状态跟踪，最终提审由用户在 ASC 手动操作。

### 已核实的现状与范围

- 顶栏模块导航现状见 `scripts/web/index.html` 的 `.module-nav`：讨论 → 需求 → 任务 → 文件 → 营销 → 设置（设置为末位辅助入口）。「发布」页签插在「营销」与「设置」之间，与既有模块同级；本仓库目前没有任何发布相关的前端视图、路由或脚本，发布模块为全新增量。
- 看板既有约定可复用：每模块一个 section 视图由专属 js 动态渲染（如营销模块 `marketing.js` 的页签 + 面板模式）；新建入口走右侧侧拉面板（REQ-20260910-014 先例）；深浅色全部走既有 CSS 变量、随 `prefers-color-scheme` 自动适配；窄屏（≤960px）分栏改上下排列。
- 任务（runs）模块已有「批次 / 队列 / 执行记录」列表形态，发布模块的「运行列表 + 运行详情」沿用同一信息架构，但数据模型、执行器与持久化均为新增，不与任务模块共用状态。
- 发布执行涉及外部系统（Git 远端、ASC API），执行端、凭据管理与运行持久化方案由 design.md 定夺（含开源选型 REQ-20260909-015 评估）；本 README 只定义用户可见行为与验收口径。
- 待确认：发布运行的持久化位置（建议 `docs/agent-team-board/dispatch/` 或独立 `releases/` 目录，随项目进 git 的口径由设计阶段确认）；「+ 新建发布」是复用顶栏统一「＋ 新建」侧拉面板还是模块内独立入口（演示按模块内入口示意）。

## 范围与入口

顶层导航增加「发布」，与需求、任务、文件、营销同级，按当前项目隔离配置与运行历史。首期目标只有 Git 远端、Apple App Store；网站、网络存储及其他商店仅保留目标类型扩展设计，不显示可执行入口。

发布是实际执行流程：不能以生成提示词、复制命令或人工勾选步骤代替执行成功。可复用现有 Agent 执行端，但必须有结构化阶段回执、实际执行证据和外部结果校验。发布模块不得擅自接受或完成关联需求。

## Git 远端流水线

1. 配置与冻结输入：选择已配置 remote、源分支、目标分支、可选版本标签、项目校验命令；记录源提交 OID、远端地址（脱敏）、明确 refspec。分支策略遵守仓库约定，不强制所有项目使用 Git Flow 或统一命名。
2. 本地预检：确认 Git 仓库、非 detached HEAD、源提交存在、无未完成 merge/rebase、工作区及暂存区干净；未提交修改引导回现有提交功能，不自动 add/commit/stash。无 remote、非法 ref、缺失校验配置明确阻塞。
3. 获取远端：fetch 目标引用，记录远端 OID，判断相同、可快进、落后或分叉。落后/分叉必须先解决，流水线不自动改写历史；受保护分支按仓库流程通过 PR/MR，展示阻塞原因及可用入口。
4. 质量检查：在冻结提交对应的隔离工作目录执行项目配置的测试、构建等检查，保存命令、退出码和日志；失败不可继续。Git 自身不规定测试或提交消息格式，这些按项目配置校验。
5. 推送计划：展示待发布提交、目标分支、可选标签和校验结果，dry-run 仅为预检。用户启动发布即授权该明确计划，执行中源提交、目标或配置变化时使计划失效。
6. 执行推送：只推明确选择的引用，默认只允许快进，禁止 force、mirror、隐式推全部分支/标签。标签指向冻结提交，拒绝覆盖已有不同标签；分支与标签同批使用 atomic，远端不支持时阻塞并说明，不静默降级成部分发布。
7. 结果核验：读取远端实际 ref，与冻结 OID 比较后才标记成功；网络超时先查询远端，避免已成功后盲目重推。远端并发变化触发重新检查，不能靠旧 dry-run 判定安全。

## Apple App Store 流水线

参考用户指定 [app-store-release skill](/Users/adichou/Documents/src/apple-app-store-release/skills/app-store-release/SKILL.md) 及其 workflow、阶段文档。此需求是模块设计，实际应用的 Bundle ID、SKU 在运行 Apple 流水线时定位，无需为 ATB 本身创建 App 材料。

1. 定位应用与材料：选择 Xcode project/workspace、scheme、平台和 ASC App；读取 Bundle ID，按 `/Users/adichou/Documents/src/app-info-repo/` 的 `app.yaml` 匹配 SKU。首次无登记时收集 SKU，默认 Bundle ID，持久化映射供后续复用。多 target 或匹配歧义时要求明确选择。
2. 环境与凭据：检查 macOS/Xcode、签名证书、profile、entitlements、ASC 权限；凭据引用 `~/.appstoreconnect/config.json` 与私钥，不复制内容到看板、日志或公开仓库。
3. 资料与合规：准备版本对应的多语言元信息、截图、隐私问卷、Review Notes、可选 IAP；校验截图规格、隐私清单和加密声明。`PrivacyInfo.xcprivacy` 留在应用项目；资料沿用 SKU 目录，版本运行保留材料摘要与内容指纹。含账号、私密截图、演示视频存本地私有目录，只记录脱敏引用。
4. 版本与构建：确认 version/build number，与 ASC 已有构建比较，检查签名与加密合规后 archive/export/validate；构建产物留本地，记录产物路径、摘要、源 OID、Xcode 版本和构建身份。平台分支按 Apple 当前文档执行，不能把站外 macOS 分发公证强加到 Mac App Store 流程。
5. 上传 TestFlight：上传并等待 Apple 处理，只有目标构建 VALID 才可继续；处理失败展示原因，等待超时保持可恢复状态，重试先按应用/平台/版本/build 查询已有上传。支持内部测试组及测试结果记录，不能把上传成功视为已上架。
6. 提审前检查：按 skill 的首次/更新 checklist 核验所有必填资料，确认测试结果；API 无法设置的项目提供 ASC 人工处理入口，未完成时阻塞后续。
7. 准备审核数据：创建或复用准确版本，绑定已验证构建、同步文案/截图/审核资料，并查询回验；只重试未完成操作。完成后状态为「待人工提审」，提供该应用的 ASC 后台链接。
8. 人工提审与跟踪：最终 Submit for Review 由用户亲手在 ASC 操作。模块不调用最终提交接口；随后读取真实审核/发布状态，区分待审核、审核中、被拒、待开发者发布、处理中及已上线。只有确认商店上线才标记已发布；审核通过但待手动发布不可提前完成。被拒时保留原因，修订版本启动关联新运行。

### 界面布局

- 顶栏：「发布」页签插在「营销」与「设置」之间；进入后模块区为左右分栏——左侧运行列表（含目标类型筛选、状态筛选），右侧当前运行详情；顶栏项目选择器切换项目，配置与运行历史随项目隔离。
- 运行列表项：目标（Git 远端 / Apple App Store）+ 标识（分支或 App 版本）、状态（草稿 / 预检 / 进行中 / 等待人工 / 成功 / 失败 / 已取消）、关键信息（源提交 / 版本 / 创建时间）；支持按目标与状态筛选。
- 运行详情：头部为目标标识与状态摘要（目标 / 源提交 / 版本 / 创建时间）；下方为阶段进度条（Git 七阶段、Apple 八阶段，✓ 已完成 → ◉ 进行中/等待 → ○ 未开始，失败阶段红显并给出原因）；再下为页签「概览 / 阶段日志 / 产物 / 操作历史」；底部操作区按状态出现「预检 / 启动发布 / 重试失败阶段 / 取消后续阶段 / 打开 ASC / 刷新状态」。
- 新建发布：右侧侧拉面板，先选目标类型（首期仅 Git 远端、Apple App Store 可选，网站 / 网络存储置灰标注「首期未开放」），再按类型动态渲染字段；底部为「保存草稿 / 预检 / 启动发布」。
- 窄屏（≤960px）沿用全站约定：分栏改上下排列，列表点进详情可返回；深浅色走既有 CSS 变量随系统自动适配。

### 交互行为

- 新建面板先选择类型，再填写该类型字段；保存草稿后可预检，预检（含 dry-run）不触发 push 或上传；启动前展示推送 / 发布计划（待发布提交、目标分支、可选标签、校验结果或 Apple 版本与构建绑定）供确认，用户启动即授权该明确计划。
- 点击运行切换详情：查看阶段输入、开始/结束时间、结果、脱敏日志与证据；页签内日志按阶段分组、时间戳排序，远端地址与凭据一律脱敏。
- 失败运行显示失败阶段、原因与「重试失败阶段」，仅重跑未完成操作（Apple 重试前先查询已有上传/版本，不重复创建）；等待人工（如待人工提审、受保护分支走 PR/MR）时展示待办说明与对应外部入口按钮。
- 支持取消后续阶段；已发送到远端的操作不宣称撤回，取消后仍核对外部结果。同目标并发运行互斥，重试不覆盖其他运行状态。
- 列表点击、筛选、刷新均为只读操作不触发执行；刷新与服务重启后运行状态可恢复，新开页面不重复执行已开始的阶段。

### 状态反馈

- 空态：项目无任何发布运行时显示引导（说明两目标定位 + 「新建发布」入口），配置缺失（无 Git remote / 未配置 ASC 凭据）给出对应配置指引而非空列表。
- 加载态：列表与详情拉取时显示加载指示；阶段执行中该阶段转圈并实时追加日志；上传 TestFlight 后等待 Apple 处理显示等待态与已等待时长，超时保持可恢复而非失败。
- 失败态：阶段失败红显原因（本地预检不通过 / 落后分叉 / 检查失败 / 标签冲突 / atomic 不支持 / 上传处理失败 / 网络中断等分别有明确文案），保留全部输入与已执行证据供重试；网络响应丢失先查询远端实际结果，不盲目重推。
- 等待人工态：Apple「待人工提审」显示 ASC 入口与提审 checklist 摘要；审核状态跟踪区分待审核 / 审核中 / 被拒 / 待开发者发布 / 处理中 / 已上线，被拒保留原因。
- 成功态：Git 以远端实际 ref 与冻结 OID 比对一致才标成功；Apple 仅确认商店上线才标已发布；两者都在操作历史记录外部操作前后的证据（时间、OID / 构建号、指纹）。

## 验收标准

- [ ] 发布导航和深链可用，跨项目配置、运行与日志隔离；仅支持 Git 和 Apple 两个目标，网站 / 网络存储只保留扩展设计不显示可执行入口。
- [ ] 草稿、预检、启动、阶段详情、失败恢复、取消与运行历史形成闭环；有真实执行证据，刷新不重复执行。
- [ ] Git 覆盖干净仓库成功推送、未提交修改阻塞、无 remote、detached HEAD、落后/分叉、受保护分支、检查失败、标签冲突及 atomic 不支持。
- [ ] Git 验证实际远端 OID；并发更新不覆盖历史，网络响应丢失可查询恢复；只推选定引用。
- [ ] Apple 正确解析应用/SKU，多 target 不误选；密钥、敏感审核材料及构建产物不进入公开资料仓库或日志。
- [ ] Apple 检查版本、签名、隐私和元信息，构建上传后等待有效结果，失败/重复上传可恢复；产物可追溯到源提交。
- [ ] 审核资料回验后停在待人工提审；最终提审由用户操作；审核通过、待发布和已上线明确区分。
- [ ] 外部操作前后记录证据；同目标并发运行互斥，重试不重复创建版本或覆盖其他运行状态。
- [ ] 通过临时 bare Git 远端的真实集成测试及 ASC 适配器的模拟状态/故障测试；真实 Apple 联调需要已配置应用与凭据，不把模拟测试表述成真实上传成功。
- [ ] ui-demo.html 可离线直接打开，覆盖布局、类型选择与动态字段、预检 / 计划确认 / 启动、页签切换、重试与取消，以及正常 / 空 / 加载 / 失败 / 等待人工状态切换。

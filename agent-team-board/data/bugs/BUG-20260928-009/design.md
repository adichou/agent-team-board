## 根因分析

（登记时初步定位，修复阶段细化）

1. **切换行丢失**：REQ-20260918-001 的切换行是手工维护的双语机制（README.md ↔ README.en.md 顶部互链）；REQ-20260921-012 上线流水线后，AI 总结重写默认语言文档时没有任何提示词要求保留或重新生成切换行，产物自然不含；AI 翻译提示词同样没有该要求，且「与基准语义一致、不增删信息」约束明确禁止翻译轮凭空补加——两阶段都不产生切换行，缺失在 `f1d15c7` 固化并跨轮延续（`7a71eab`、2026-09-28 翻译轮 tr-20260928-151839-37dc 均如此）。
2. **README.en.md 残留**：`f1d15c7` 改用 `<KEY>_<lang>.md` 命名的语言变体，但未清理被取代的旧 `README.en.md`（git 仍跟踪）；此后无发布文档引用它，内容冻结在 REQ-20260918-001 时点。

## 方案

（开发阶段定稿，2026-09-28）

1. **切换行规格（定稿）**：
   - 位置：文档首行一级标题（`# …`）之下，标题与切换行之间空一行，切换行与正文之间空一行。
   - 形态：语言集内全互链，每项 `[<语言显示名>](./<本KEY对应语言文件名>)` 以 ` | ` 分隔；默认语言（语言集首语言）不带后缀，其余 `<KEY>_<lang>.md`。语言显示名复用 publish-flow 既有 `langNameOf`（LANG_NAMES，未命中回退缩写），语言集扩展时按语言集动态生成。例（语言集 cn,en，KEY=README）：`[中文](./README.md) | [English](./README_en.md)`。
   - 关键性质：同一 KEY 的所有语言变体中该行**完全一致**（各链接分别指向对应语言文件）——翻译轮直接镜像基准行，无需任何改写。
   - 适用范围：四类标准发布文档 + `v.customDocs` 自定义文档（如 DESIGN）的全部语言变体；LICENSE.md 单文件类不适用（不进 AI 总结 / 翻译）。
   - 纯函数承载：publish-flow 新增 `docLangSwitchLine(key, langs)`，三处提示词共用同一生成器，示例行随语言集动态展开。
2. **提示词三处对齐**（scripts/lib/publish-flow.mjs，定稿）：
   - AI 总结提示词（写作约束节）：默认语言产物在首行一级标题下生成语言切换行（语言集内全互链、链接真实可达、自定义文档同口径、LICENSE 除外）；重写 / 总结既有文档时保留该行（跨轮稳定）。
   - AI 翻译提示词（翻译约束节，紧邻既有文内链接规则合并表述）：切换行属固定结构——目标文档在同样位置保留与基准**完全一致**的该行；该行链接已按各语言变体互链，直接镜像、不改写链接文本，**不视为基准外新增信息**（对「不增删信息」约束的显式例外）。
   - AI 校对提示词（校对约束节）：切换行核查——默认语言文档首行一级标题下应有语言切换行（语言集内全互链、指向本 KEY 各语言变体文件）；该行缺失、语言集不全或链接目标不正确必须按回执格式显式提示，交由用户确认处理。
3. **删除旧 README.en.md（定稿口径）**：删除前全仓检索确认引用面（复查：仅其自身与历史条目文档的叙述性提及，后者为冻结历史不改；根发布文档无引用）。执行 `git rm README.en.md`（出索引 + 删盘，`git ls-files` 即不再含它）。**提交口径**：按 REQ-20260923-002 根第一层文档不随收口自动提交，且 REQ-20260923-001 保守边界将点号命名排除在 Bash 发布文档提交通道之外——删除差异落在工作区（已出索引），与根第一层文档「保留在工作区由人工处理」口径一致，最终提交由人工完成（人工终端提交通道不受守卫限制）。
4. **存量文档处理（定稿）**：不手工补切换行——下一轮发布流程 AI 总结重写默认语言文档、AI 翻译镜像其余语言时自然带上（提示词已要求「重写时保留」）；如需提前，人工可在看板「文档编写」页补，不由 Agent 代改根第一层文档。

**开源选型（REQ-20260909-015）**：动手自研前先评估是否有成熟、维护中的开源库，优先复用——以依赖方式引入
（Node/Web 项目走 npm，Apple 平台走 SPM / CocoaPods），禁止复制开源库源码进项目仓库；仅当库无包分发渠道
且确需使用时才允许 vendor（内嵌源码），须在 licenses.md 标注复制范围与原因。License 只用开源友好白名单：

强传染许可及 License 不明的库禁止引入。自研须写明理由（三选一）：引用了哪些库 / 无合适库的原因 /
引入成本高于自研的原因。引入开源库须在条目目录维护 licenses.md（库名 / 版本 / 引入方式 / License / 仓库地址），
未使用开源库的条目不创建该文件。

## 风险与边界

- 切换行本质是「基准结构外新增内容」，必须与翻译「不增删信息」约束在提示词层面写清例外（总结轮生成、翻译轮镜像保留），否则翻译 / 校对轮会再次将其删除。
- README.en.md 删除后，外部指向该文件的历史链接（如旧版 GitHub 页面）将 404；本仓库无重定向机制，接受与否由人工确认。
- 语言集未来扩展多语言时切换行需按语言集动态生成，规格设计需留出扩展位（当前语言集 = cn + en）。

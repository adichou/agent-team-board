# 设计 — BUG-20260921-011 刷新时顶部的项目切换组件异常，没有显示数据，尺寸变小，导致模块页签位置变化，需修复

> 由 Agent 在 /dev 开发前补充，人可随时批注。

## 引入来源（源单）

- 引入来源：REQ-20260830-001（`atb list` 核验真实存在，done）。该需求建立多项目与
  顶栏项目选择器时即为「数据到达后才渲染 + 列表为空直接 hidden」的实现，且
  `.project-sel` 只有 `max-width: 200px` 无稳定下限——空 `<select>` 塌缩自始存在。
- 放大因素（非引入）：REQ-20260910-012（`atb list` 核验真实存在，done）把模块页签
  上移并入顶栏，选择器塌缩开始连带页签与右侧按钮横移，缺陷由「不易察觉」变为可见。

## 根因分析

- `scripts/web/index.html` 的 `#projectSel` 初始无任何 option；`scripts/web/app.js`
  的 `boot()` 要等 `/api/health` → 首轮 `poll()` → 浏览快照恢复 → `setView` 之后才调用
  `renderProjectSel()`，首帧到数据到达之间选择器是空 `<select>`。
- `style.css` 的 `.project-sel` 只有 `max-width: 200px`，宽度完全由内容撑开——空选项
  时塌缩到最小宽度，顶栏（模块页签 + 右侧操作按钮）整体横移，数据到达后再弹开。
- `renderProjectSel()` 在列表为空时 `classList.toggle('hidden', true)` 直接隐藏选择器；
  `/api/health` 请求失败时 `state.projects` 保持 `[]`，失败被伪装成「暂无项目」，
  没有失败反馈也没有重试入口，且隐藏/再现本身又是一轮布局跳动。

## 方案

前端为项目选择器建立显式状态机并全周期保持占位（服务端零改动）：

- 状态：`state.projectsState`（`loading` / `ok` / `empty` / `error`）；
  注册表更新统一走 `setProjectList(list)`（非空 ok / 空 empty），健康检查、初始化、
  导入、移出等所有局部路径不再各自裸赋值，防残留旧状态。
- 渲染：`renderProjectSel()` 四态渲染，任何状态都不隐藏选择器——
  - loading：未知项目显示「加载项目中…」，已知项目（URL 深链 / 上次选择）显示
    「项目名（加载中…）」，禁用选择（不允许选未加载的选项），title 指向全路径；
  - ok：原有列表与选中项逻辑不变，恢复可交互，title 为当前项目全路径（长名截断
    时悬浮可看完整路径）；
  - empty：显示「暂无项目」占位（禁用但不隐藏），「管理项目」入口不受影响；
  - error：显示「加载失败，点此重试」（可交互，与空态严格区分），选择器本身即
    重试入口——change 统一入口 `onProjectSelChange` 在 error 态触发 `refreshHealth()`
    重拉，不切换项目、不冒充空态、不自动改选。
- 时序：`boot()` 在等待 `/api/health` 之前先置 loading 并渲染占位；数据（或失败态）
  一到立即渲染，不再排队等首轮 poll 与快照恢复。`refreshHealth()` 带状态机重拉，
  切换项目后的刷新期间同样保持占位。
- 静态首帧：`index.html` 的 `#projectSel` 内置「加载项目中…」占位 option 并初始
  `disabled`，脚本加载失败 / JS 异常时也不呈现空选择器。
- 样式：`.project-sel` 由 `max-width: 200px` 改为固定 `width: 200px`（加载 / 空 /
  失败 / 常态同宽，长名沿用 `text-overflow: ellipsis` 截断）；≤640px 竖屏沿用既有
  「按内容自适应」口径但增加 `min-width: 120px` 最小占位防塌缩（页签在独立行，
  不受影响，行内按钮不再横移）。
- i18n：新增词条（「加载项目中…」「正在加载项目列表…」「加载失败，点此重试」
  「项目列表加载失败，点击本选择器重试」+ 动态「◇（加载中…）」），空态复用既有
  「暂无项目」「暂无项目：打开「管理项目」初始化或导入」，通过 i18n-coverage 卡点。
- 项目定位优先级不变：URL 深链 > 上次选择 > 服务端默认项目；刷新不误切换项目。

**开源选型（REQ-20260909-015）**：未引入开源库——需求是原生 `<select>` 的状态机
渲染与 CSS 宽度稳定（约 80 行），仓库顶栏组件均为原生实现，无合适且必要引入的库；
引入成本高于自研。

## 风险与边界

- 固定 200px 宽度：短项目名时选择器留白略多于原内容自适应形态，换取任意状态下
  顶栏零位移（README 期望行为明确以「位置稳定」为准）；竖屏保持自适应 + 最小占位。
- 失败态重试依赖 change 事件：占位 option 使用 `__retry__` 哨兵值确保选中即触发；
  重试期间回到 loading 占位，连点由状态机自然收敛，无并发副作用（幂等重拉）。
- 浏览器原生 `<select>` 的 option tooltip 兼容性不一（Chrome 不显示 option title），
  完整路径改由选择器自身 title 承载，长名截断不撑动导航的口径不变。

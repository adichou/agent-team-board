## 现象

用户反馈：刷新页面时顶部项目切换组件没有显示数据，组件尺寸变小，连带模块页签位置发生变化。影响是当前项目暂时不可辨识，导航在刷新过程中跳动。

代码核对发现：`scripts/web/index.html` 的 `#projectSel` 初始为空；`scripts/web/app.js` 的 `boot()` 先请求 `/api/health`，再等待首轮 `poll()` 与浏览快照恢复，之后才调用 `renderProjectSel()` 填充项目。`scripts/web/style.css` 的 `.project-sel` 设有最大宽度，但没有稳定占位宽度；`renderProjectSel()` 在列表为空时隐藏选择器。这些是排查线索，尚不能视为已验证根因。

实际复现浏览器、窗口宽度、请求延迟、异常持续时间，以及是否每次刷新均出现：待确认。本轮未运行真实产品复现，不把演示中的缺陷模拟视为复现证据。

## 复现步骤

1. 打开已注册项目的 Status Board，选中一个项目，记录项目名称、当前模块、选择器尺寸和页签位置。
2. 在同一窗口宽度下执行浏览器刷新（Cmd+R / Ctrl+R），观察首次绘制到数据加载完成期间，项目名是否为空、选择器是否缩小、模块页签是否横向移动或换行。
3. 为观察瞬态问题，可在浏览器开发者工具中限制网络速度，分别检查健康检查与首轮数据请求等待期间；这是诊断条件，是否为原始触发条件待确认。
4. 重复在长项目名、多个项目、窄屏和中英文界面下检查；分别记录加载成功、请求失败、真正没有项目时的表现，避免把接口失败误判为空列表。

## 期望行为

- 从首次绘制到加载完成，项目选择器区域有稳定占位；同一窗口尺寸、同一模块下，不因项目数据未到达、加载成功或失败而改变页签位置或造成新增换行。
- 尚不能确认项目时显示明确的「加载项目中」提示并禁用选择；已知项目可显示其名称并标明加载中，不能用空白选项或错误项目冒充成功。
- 成功后显示正确选中项目并允许切换；项目定位保持现有 URL 参数优先于上次选择、再优先于服务端默认项目的规则。长名称截断，完整路径可查看，不撑动导航。
- 确认没有项目时显示「暂无项目」，保留占位与管理项目入口；请求失败显示可辨识的失败反馈及重试入口，不伪装成暂无项目，不擅自切换项目。
- 窄屏遵循既有响应式换行规则，各状态下导航仍可访问；不要求不同窗口宽度使用相同位置。

演示为验收说明用的概念样例，不是实际产品实现或截图。布局采用标题、模块页签、项目选择器及管理入口；固定选择器区域展示期望的稳定布局，缺陷模式模拟加载时缩窄导致的页签移动。演示尺寸只是样例，最终尺寸沿用产品设计并以位置稳定、不裁切入口为准。

交互：切换「期望修复 / 缺陷模拟」，选择正常、加载、空、失败状态；点击「模拟刷新」经历加载再恢复正常；正常态可切换示例项目和模块，失败态可重试，空态可打开模拟项目管理反馈。控制区同时报告当前模式与状态。

状态反馈：正常显示项目名，加载禁用选择并显示提示，空态保留暂无项目占位，失败保留选择区域并提供重试。缺陷模式只用于对比空白与缩窄现象，其他状态不代表已有产品行为。

## 验收说明

- [ ] 在实际产品刷新时，从首次绘制开始选择器区域无空白缩窄；同一视口下模块页签的横纵位置和行数在加载前后保持稳定。
- [ ] 健康检查和首轮数据请求延迟时均有明确加载提示，不允许选择未加载的选项；数据到达后恢复正确名称与切换功能。
- [ ] URL 指定项目、上次选择、服务端默认项目的优先级不变；刷新不误切换项目，模块恢复逻辑不受影响。
- [ ] 请求失败显示失败而非空态，可以重试恢复；真实无项目时显示暂无项目且管理入口可用，两种状态都不导致导航跳动。
- [ ] 短名、长名、多项目，中英文和桌面/窄屏均检查通过；长名称不会撑开选择器，响应式布局内所有模块入口可达。
- [ ] 开发阶段补充实际复现环境及前后对照证据，确认根因和引入来源；本轮只交付说明与演示，design/test-cases 留开发阶段完善。

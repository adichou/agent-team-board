# BUG-20260908-006 “改为已计划”要改为“移入计划”

- 状态：in-progress（zcode-batch-015-01 实施中）
- 归属需求：无（独立 Bug）
- 创建：2026-09-08T06:07:56.070Z

## 现象

REQ-20260908-018 为已接受列表引入了批量「移入计划」操作后，同一个 accepted → planned 动作在界面上出现两套叫法：

- 详情页单条按钮（REQ-20260908-010 引入）：`➤ 改为已计划`（`data-act="planned" data-label="改为已计划"`）；
- 列表批量按钮（REQ-20260908-018 引入）：`移入计划`（工具条 `#planAdd`）。

同时各处指引文案（列提示、状态标签 title、详情提示、批量开发空态提示、CLI/文档指引）仍统一写「改为已计划」，与批量侧「移入计划」术语不一致，用户容易误解为两个不同操作。

## 复现步骤

1. 启动 Status Board，打开任一项目看板。
2. 在「待接受」接受一条新条目 → 变为「已接受」。
3. 对比两处入口文案：
   - 打开该条目详情，accepted 操作区按钮显示「➤ 改为已计划」；
   - 已接受列勾选条目后，工具条按钮显示「移入计划（N）」。
4. 另见指引文案：已接受列提示/未入批次 title 均写「可在详情页『改为已计划』排入开发计划」；批量开发空态写「并在详情页『改为已计划』」。

## 期望行为

- 同一动作统一叫「移入计划」：详情页按钮改为 `➤ 移入计划`（`data-label="移入计划"`），行为不变（免二次确认，accepted → planned）。
- 所有现存用户可见指引文案同步改称「移入计划」：LANE_HINT、未入批次标签/详情提示、详情「未入计划」notice、批量开发空态提示（`scripts/web/app.js`）、批量派发无候选提示（`scripts/lib/batch.mjs`）、Agent 指引（`skills/agent-team-board/SKILL.md`、`commands/dev.md`）、批量执行契约文档（`docs/agent-team-board/batch-execution.md`）。
- 「移出计划」等既有文案不动；历史需求文档（REQ-20260908-010/018 条目内记录）不改写；`data-act="planned"` 等机器契约不变。

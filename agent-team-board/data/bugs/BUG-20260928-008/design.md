# 设计 — BUG-20260928-008 AI 翻译图片语种对齐「不存在则保持原引用」措辞歧义：应保持语种变体引用而非默认语言引用

> 由 Agent 在 /dev 开发前补充，人可随时批注。

## 引入来源（源单）

- 引入来源：BUG-20260928-003（经 `atb show` 核验存在，已 done）——该单为 AI 翻译 / AI 校对提示词加入图片引用语种对齐约束，其措辞「存在才把引用改写为对应语种图片，不存在则保持基准原引用」中「基准原引用」可被直白读作「基准文档里的原引用（默认语言图）」，与本意「保持 `<name>_<lang>` 引用方式」相悖。tr-20260928-134647-4398 轮实际触发该歧义读法。

## 根因分析

翻译约束是自然语言提示词，由翻译子代理按字面语义执行；「保持基准原引用」的最直白读法即保持基准文档中的原引用路径（默认语言图片），与规则本意（缺图也保持语种变体引用、由用户补图检查）相反。同时发布文档提交流程按「文档实际引用且磁盘存在」收纳图片（缺图引用不阻塞、不收入），语义上支持「引用语种变体路径 + 图片后补」的口径，措辞与流程口径不匹配。

## 方案

1. 修改 scripts/lib/publish-flow.mjs 翻译约束（BUG-20260928-003 引入的那行）措辞为明确口径：目标语言文档的本地图片引用一律改写为 `<name>_<lang>.<原扩展名>`（仅文件名加语种后缀；不改扩展名、不换基名、不得指向不同基名的其他文件）；对应图片文件是否存在不影响引用改写，仅作为「不阻塞、不强求，界面显示不出图片由用户自行检查补图」的说明；不得虚构图片文件。
2. 同步更新 scripts/tests/bug-20260928-003.test.mjs 中针对旧措辞的断言（L1-1 一带），改为断言新措辞关键句（先跑红再改实现）。
3. 在本单认领锁有效期内，顺带修正本轮已产出的 README_en.md 图片引用为 `image/README/1790092127929_en.png`（语言变体文件受锁保护，需锁内修改）。
4. 校对提示词（publish-flow.mjs 校对约束）的图片语种核查口径本单不扩展：其现检查「默认语言文档引用语种后缀图须提示」，与翻译新口径不冲突；「非默认语言文档引用默认语言图」是否纳入校对提示属范围扩展，如需另行登记。

**开源选型（REQ-20260909-015）**：本单为提示词措辞与测试调整，无新依赖引入，自研（无合适库可复用——改动对象是自有提示词模板文本）；不引入开源库，licenses.md 不创建。

## 风险与边界

- README_en.md 修正后 `image/README/1790092127929_en.png` 缺失，英文 README 界面图暂不显示；由用户补图（上传同基名 `_en` 图，或改引用既有不同基名的 `1790092216439_en.png`），不阻塞发布。
- 校对阶段（en 文件待人工审核）人工仍可在看板「文档编写」页直接修正该引用，与本单修复二选一即可，不冲突。
- 旧轮次已产出的其他 `_en` 文档本轮无本地图片引用，不涉及。

# BUG-20260928-008 AI 翻译图片语种对齐「不存在则保持原引用」措辞歧义：应保持语种变体引用而非默认语言引用

- 状态：submitted（待人工接受）
- 归属：独立 Bug（引入来源见 design.md）
- 引入来源：BUG-20260928-003（其引入的翻译图片语种对齐约束措辞「不存在则保持基准原引用」存在歧义）
- 创建：2026-09-28T06:05:08.535Z

## 现象

执行 tr-20260928-134647-4398（BLD-20260927-001，en 语言 AI 翻译轮）时，README_en.md 的本地图片引用按提示词约束「对应语种图片不存在 → 保持基准原引用」处理，最终保持默认语言（中文）引用 `image/README/1790092127929.png`，未改写为语种变体引用 `image/README/1790092127929_en.png`。发布后英文 README 将显示中文界面截图。

## 复现步骤

1. 项目 `image/README/` 下仅有默认语言图 `1790092127929.png`，无同基名 `_en` 变体（另有不同基名的 `1790092216439_en.png`，非本图变体）。
2. 默认语言文档（README.md）引用该图，启动一轮 AI 翻译（`atb translate start`）。
3. 翻译子代理按提示词约束判定「对应语种图片不存在 → 保持基准原引用」，目标语言文档保持默认语言图片引用。

## 期望行为

用户澄清的规则意图：「不存在则保持原引用」指保持**「文件名_<lang>.<原扩展名>」的引用方式**，而不是保持默认语言（原文）引用——目标语言文档的本地图片引用一律改写为语种变体路径（如 `image/README/1790092127929_en.png`）；对应图片文件缺失不阻塞、不虚构图片文件，界面显示不出图片由用户自行检查补图；不得指向不同基名的其他图片文件。

## 验收标准

1. 翻译提示词模板（publish-flow.mjs 翻译约束）措辞消除歧义：明确「一律引用 <name>_<lang>.<原扩展名>，图片文件存在与否不影响引用改写（仅不阻塞、由用户检查补图）」。
2. 相应测试断言（scripts/tests/bug-20260928-003.test.mjs L1-1 一带）与新措辞同步。
3. 本轮已产出的 README_en.md 图片引用修正为 `image/README/1790092127929_en.png`。
4. `npm test` 全量通过。

## 验收说明

对上列验收标准的核验口径（已对照仓库现状核实：歧义措辞在 `scripts/lib/publish-flow.mjs` 翻译约束行、旧断言在 `scripts/tests/bug-20260928-003.test.mjs` L1-1、README_en.md 第 37 行当前仍引用 `image/README/1790092127929.png`，`image/README/` 下仅有 `1790092127929.png` 与不同基名的 `1790092216439_en.png`）：

1. 措辞核验：`scripts/lib/publish-flow.mjs` 翻译约束不再含「不存在则保持基准原引用」歧义句式，改为明确口径——目标语言文档的本地图片引用一律改写为 `<name>_<lang>.<原扩展名>`（仅文件名加语种后缀，不改扩展名、不换基名、不得指向不同基名的其他文件）；图片文件是否存在不影响引用改写，仅说明「不阻塞、不强求，界面显示不出图片由用户自行检查补图；不得虚构图片文件」。
2. 测试核验：`node scripts/tests/bug-20260928-003.test.mjs` 先红（旧断言「不存在.*保持|保持.*原引用」按新措辞应先失败）后绿；`npm test` 全量通过。
3. 产物核验：`README_en.md` 的本地图片引用为 `image/README/1790092127929_en.png`（该图文件当前缺失属预期，不阻塞，由用户补图或改引用；人工在文档编写页修正与本单修正二选一即视为达成，见 design.md 风险与边界）。
4. 范围边界：校对提示词「图片语种核查」口径不在本单范围（design.md 方案 4）；本单仅涉提示词措辞、测试断言与 README_en.md 引用修正，无界面源码改动，发布文档页面无代码变更。

## 界面展示

本 Bug 的界面影响在发布文档的最终呈现：英文 README（README_en.md）浏览与发布时应显示英文界面截图，缺陷状态下会显示中文界面截图。可交互演示见 [./ui-demo.html](./ui-demo.html)（单文件、无外网依赖，浏览器直接打开）。

- 界面布局：演示页顶部为状态工具栏（「修复前（缺陷）/ 修复后（期望）」切换、「`_en` 变体图已补 / 缺失」切换、「清空图片引用」空状态开关、「重新翻译」按钮）；左侧为英文 README_en.md 渲染预览卡（标题、正文与界面截图位，顶部带当前状态角标）；右侧为「引用与文件对照」面板——当前 markdown 引用行、`image/README/` 磁盘文件清单（标注哪张是默认语言图、哪张是不同基名不得指向）、翻译约束新旧措辞对照。
- 交互行为：「修复前 / 修复后」切换对照缺陷现象与期望修复后状态；「`_en` 变体图已补 / 缺失」切换演示修复后引用语种变体路径时图片缺失的占位表现；「清空图片引用」演示文档无本地图片引用的空状态；「重新翻译」进入加载态（骨架屏 + 按钮禁用），约 1 秒后按当前模式重新产出引用结果。
- 状态反馈：正常（英文文档配对应语种界面截图）；缺陷（英文文档配中文界面截图，角标红色警示）；失败 / 占位（引用 `_en` 变体但文件缺失 → 裂图占位 +「不阻塞发布，由用户自行检查补图」提示）；加载（翻译中骨架屏）；空（无本地图片引用）。演示页随系统深浅色自适应。

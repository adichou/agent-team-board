# 设计 — BUG-20260928-011 构建发布预检口径重构：文档与条目合并必检、已完成未挑选条目提醒

> 由 Agent 在 /dev 开发前补充，人可随时批注。

## 引入来源（源单）

- 引入来源：REQ-20260916-004（构建发布官网目标适配 app-homepage-repo 新站点架构（Vite + Vue），已 `atb show` 核验存在）。其「新架构（Vite + Vue 站点）双语材料口径」实现了 `scripts/lib/build-publish.mjs` 的 `siteMaterials`，按 2026-09-16 时点的**旧后缀规范**（`content/<id>/faq.zh.md`、`changelog/v<版本>.zh.md`、`docs/<slug>.zh.md`）硬编码校验；官网仓库 2026-09-18 二次重建（`73794f4`，统一双语内容、语言目录规范 `content/<app>/<locale>/<slug>.md`）后该口径与站点实际消费脱节，阻塞发布。

## 根因分析

- 预检 7 条口径中「双语材料」由 `siteMaterials` 实现：要求 `src/data/apps.js` 注册产品 id（现仍有效，本轮已通过）+ `content/<产品id>/` 下旧后缀规范成对中英文件（现已全部不存在）。
- 官网站点 9/18 重建后内容引擎（`src/composables/useContent.js`）只消费 `content/<app>/<locale>/<slug>.md` 布局；旧后缀路径无任何消费者。即：被校验的文件即使补齐也是死文件，校验本身已失效。
- 实测证据：BLD-20260927-001 运行 BPUB-711ea71f… 的 precheck 记录——仅「双语材料」失败，其余 6 项（冻结范围 / 工作区 / 官网全局配置 / 条目包含性 / Web App 构建识别 / 原子推送预演）全部通过。
- 深层原因：预检把「官网物料形态」写死为阻塞口径，而站点结构与物料规范由官网仓库独立演进，缺少对「发布真正依赖什么」的抽象——文档与条目是否就绪（审核、提交、合并）才是发布的语义前置。

## 方案

**目标口径（用户指定）：**

- 必选（阻塞）：①所有文档已审核通过且已提交合并到 main；②所有已挑选条目已提交合并到 main。
- 可选提醒（不阻塞）：存在已完成但未在挑选条目内的条目 → 提醒；无 → 通过。

**候选实现方向（开发阶段细化，接受后补充）：**

- 阻塞项①：复用发布文档两阶段既有事实源（docs-summary / docs-translate store 的逐文件审核状态、版本记录的文档合并落账与重放证据），不重新发明判定。
- 阻塞项②：现有「条目包含性」（`assertItemsIncluded`，含一条目多提交与 cherry-pick 重放证据口径）即为此语义，可整体保留或收紧命名。
- 提醒项：在预检结果中新增非阻塞提示位（advisory），扫描当前项目 `done` 条目与版本计划已挑选条目的差集；呈现于预检结果与看板发布条，文案中英文同步。
- 旧「双语材料」：移除阻塞校验；不再按任何官网物料形态做阻塞检查。
- **其余现有检查（冻结范围、工作区、官网全局配置、Web App 构建识别、原子推送预演）：人工已定夺（2026-09-28 用户确认「其余都不用管了」）——全部移除**，预检仅保留必选 2 项 + 提醒 1 项。

**开源选型（REQ-20260909-015）**：动手自研前先评估是否有成熟、维护中的开源库，优先复用——以依赖方式引入
（Node/Web 项目走 npm，Apple 平台走 SPM / CocoaPods），禁止复制开源库源码进项目仓库；仅当库无包分发渠道
且确需使用时才允许 vendor（内嵌源码），须在 licenses.md 标注复制范围与原因。License 只用开源友好白名单：
MIT / Apache-2.0 / BSD-2-Clause / BSD-3-Clause / ISC / 0BSD / Unlicense；GPL / LGPL / AGPL / SSPL 等
强传染许可及 License 不明的库禁止引入。自研须写明理由（三选一）：引用了哪些库 / 无合适库的原因 /
引入成本高于自研的原因。引入开源库须在条目目录维护 licenses.md（库名 / 版本 / 引入方式 / License / 仓库地址），
未使用开源库的条目不创建该文件。（本单为既有流程内逻辑重构，预计无新增第三方依赖。）

## 风险与边界

- 移除「工作区 / 原子推送预演 / Web App 构建识别」等执行安全检查后，相应失败会后移到执行阶段（推送、构建时才暴露）——该取舍已由人工定夺接受（2026-09-28），不设预检兜底。
- 预检结果结构变化（阻塞项 / 提醒项两类）影响前端展示与 i18n 文案，须双语同步（BUG-20260912-001）。
- 历史运行账本（run.json 的 precheck.checks 形态）只读展示，不做迁移。
- 提醒项只提示不阻塞：扫描口径为「当前项目已完成（done）条目 − 版本计划已挑选条目」，注意跨版本已随先前版本发布的条目是否重复提醒（可按「是否已属任一已发布版本」过滤，设计时定）。

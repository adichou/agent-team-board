# 设计 — BUG-20260922-006 创建版本的版本号和版本计划名称输入框要移到上方，便于输入

> 由 Agent 在 /dev 开发前补充，人可随时批注。

## 引入来源（源单）

- 引入来源：REQ-20260922-006（`atb list` 核验：REQ-20260922-006 done，「发布版本的版本号改成
  x.y.z 格式…」，提交 933033c）。
- 排查过程：`git log -S bldNewVersion` 指向 933033c（REQ-20260922-006 新增「版本号」输入框）；
  该提交把版本号输入框追加在 `renderPanel` 候选清单之后（`git log -S bldNewName` 显示「版本名称」
  自 REQ-20260913-001 起就在该底部位置）。两框同处面板底部、长清单下不可见的问题随 REQ-20260922-006
  把「版本号」也放到底部后变得突出，故归因 REQ-20260922-006。

## 根因分析

`scripts/web/build.js` 的 `renderPanel(p, …)` 为「新建版本」（createPanel）与「添加条目」
（addPanel）共用渲染：panel body 顺序为「读取错误 → 候选清单（全选栏 + 复选行）→
版本名称 / 版本号输入框（仅 createPanel）→ 提交错误」。done 条目多时清单占满面板，
两个输入框位于折叠线以下，用户需滚动才能填写。

## 方案

在 `renderPanel` 内把两个 `p === state.createPanel` 守卫的输入框（`bldNewName` / `bldNewVersion`）
从候选清单之后移到 panel body 顶部（读取错误提示之后、候选清单 / 加载态之前）：

- 打开面板即见即可输入；候选清单加载中（candidates 为 null）时输入框也可先行填写
  （版本号建议值本就预填，提前可见更利于确认）；
- 候选清单、全选 / 全不选、底部提交按钮与输入事件绑定（`q('#bldNewName')` / `q('#bldNewVersion')`
  的 input 监听）均不动，无行为变化；addPanel 不出现两框的口径不变；
- 纯 DOM 顺序调整，不改任何文案 / i18n 词典。

**开源选型（REQ-20260909-015）**：纯前端模板字符串内部两段标记位置对调，无外部能力引入，
无合适开源库场景；自研（不引入任何依赖，不创建 licenses.md）。

## 风险与边界

- 输入框上移后与「读取错误 + 重试」提示同屏：保留 loadError 在最前，重试入口仍第一优先可见；
- 版本号 / 名称输入的 state 写入路径（input 监听）与提交校验不动，回归以现有
  `req-20260922-006.test.mjs`（U1 前端契约）与全量测试保障；
- 不改「添加条目」面板与 i18n 词条，无中英文同步风险。

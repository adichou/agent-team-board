# BUG-20260920-001 在一个旧目录架构的项目中，点击设置界面提示如下文字，无法进行目录迁移

- 引入来源：REQ-20260909-001 × REQ-20260916-007（修复阶段归因，见 design.md「引入来源（源单）」）

## 现象

用户报告：旧目录架构项目打开设置，显示「设置加载失败：未找到 agent-team-board，请先初始化 重试」，无法从设置进行目录迁移。错误占据设置内容区，预期的「数据布局迁移」入口不可用。

旧布局指项目内 `docs/agent-team-board/`；目标布局为 `agent-team-board/data/`（条目文档）和 `agent-team-board/runtime/`（状态、账本、设置等应用数据）。用户实际项目路径、旧数据完整性、浏览器、运行服务版本及是否每次出现：待确认。本条目未对用户原项目执行迁移。

### 已核对的代码事实

- `scripts/web/app.js` 的 `renderSettingsView()` 并行发起布局检测等请求，但 `/api/dispatch/settings` 失败时直接替换整个设置视图并返回；因此迁移区无法保留。
- `scripts/server.mjs` 对 `/api/dispatch/*` 在 `dataDir` 缺失时返回上述未初始化错误。
- `/api/layout/state` 与 `/api/migrate` 已在服务端安排为无需已初始化看板、按请求中的项目路径执行的入口；旧布局本应可检测、可迁移。
- 上述为与报告相符的静态代码链路，用户现场的请求响应与确定引入来源待开发阶段验证。

## 复现步骤

1. 使用含有效旧布局 `docs/agent-team-board/`、尚未迁至新布局的项目副本。不要在用户唯一数据副本上进行验证。
2. 启动当前看板服务，打开该项目的看板，核对当前项目路径确为旧项目。
3. 使用新浏览器会话或刷新页面，使派发设置尚未缓存；点击「设置」。
4. 观察设置内容区是否显示上述错误，且无法看到或操作「数据布局迁移」。点击「重试」，记录是否仍然失败。
5. 开发验证时记录 `/api/dispatch/settings` 和 `/api/layout/state` 的响应；重点验证派发设置失败但旧布局检测成功的组合。具体现场响应待确认。

复现预期：在步骤 3–4 出现用户报告的整页失败，旧数据迁移入口被阻断。缓存已有设置、新布局项目是否出现相同现象需分别回归，不能用缓存成功替代旧项目首次打开验证。

## 期望行为

打开旧项目设置即可检测并展示旧布局，提供现有「一键迁移到新布局」操作；不得要求先初始化空看板才能迁移既有数据。依赖新布局的其他设置即使加载失败，也应局部显示原因及重试，保留迁移入口。

沿用迁移确认流程：明确源/目标与数据处理含义，取消不执行；确认后展示迁移中并防重复点击，成功后重新检测布局、刷新当前项目看板；失败保留原因与重试入口。迁移操作只作用于当前选中的项目，不自动提交 Git、不改其他项目。

## 界面展示

打开 [可交互界面演示](./ui-demo.html)。演示为离线交互说明，不连接真实项目、不执行真实迁移。

- 布局：顶部显示项目示意路径与设置标题；缺陷模式显示整页错误，期望模式保留「数据布局迁移」卡片，并将其他设置错误放在独立区域。
- 交互：切换缺陷/修复后视图，选择旧布局、已迁移、无数据、检测中、检测失败或迁移失败；迁移按钮打开确认框，取消返回，确认后经历加载再显示成功。可模拟迁移失败并重试。
- 状态反馈：旧布局正常态启用迁移；检测中、迁移中禁用重复操作；空态提示无可迁移数据与初始化指引；已迁移显示「已是新布局」；检测与迁移失败分别就近显示原因及重试。
- 演示中的路径与错误原因是样例；实际样式延续现有设置页，中文与英文提示须同步。

## 验收说明

- [ ] 仅含有效旧布局的项目，首次打开设置能够检测旧数据并操作迁移，不因派发或其他设置加载失败而整页失去迁移入口。
- [ ] 其他设置加载失败、布局检测成功时，两者反馈互相独立；检测失败可重试恢复，不能误显示「无可迁移数据」。
- [ ] 迁移确认取消不发起迁移；确认后仅迁移选中项目，执行中禁用重复提交并显示进度状态。
- [ ] 成功后显示新布局，当前项目看板重新可读；验证条目文档、状态与账本等数据按既有迁移规则保留，Git 行为沿用既有迁移能力、不自动提交。
- [ ] 迁移失败可见具体错误并可重试，不错误显示成功；部分迁移后的重试遵守既有幂等规则，不重复丢失或覆盖数据。
- [ ] 新布局项目正常加载设置；无数据项目显示无可迁移数据及初始化指引，不提供有效迁移按钮；项目切换后不残留上一项目的迁移状态。
- [ ] 正常、空、加载、失败反馈均可验证，中文与英文一致；README 演示可直接离线打开并完成上述交互。

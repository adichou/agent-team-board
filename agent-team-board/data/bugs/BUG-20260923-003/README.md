# BUG-20260923-003 AI 翻译的提示词优化

- 状态：submitted（待人工接受）
- 归属：独立 Bug（引入来源见 design.md）
- 创建：2026-09-23T15:36:52.333Z

## 现象

发布文档「AI 翻译」（REQ-20260921-012 阶段二）的翻译提示词由 `buildDocTranslatePrompt`（`scripts/lib/publish-flow.mjs` 约 334-382 行）生成，经 server `POST /api/build/docs-translate/start`（`scripts/server.mjs` 约 2844-2882 行）返回前端复制派发（预览 / 复制挂点 `scripts/web/build.js` 约 3133-3140 行）。对照当前 dev 分支实现，登记人提出三点优化诉求，逐项核对现状如下：

1. **不需要带上条目单号**：现状提示词含「关联范围」节（`publish-flow.mjs` 352-353 行调用 `docScopeLines`，约 254-270 行）——逐行列出 `- REQ-…` 条目单号、汇总句「修复了 N 个 bug（BUG 条目不逐条展开）」，并在有 REQ 时附「需求详情按上列编号自行读取条目说明文件：<项目根>/agent-team-board/data/requirements/<REQ-ID>/」路径规则行。翻译以已审核默认语言文档为唯一基准，条目单号对翻译语境价值低，反而拉长提示词。
2. **应按文件并行派发子代理**：现状为整批串行口径——提示词第 363 行「请逐个产出以下 N 个剩余语言文档」，即整份提示词派给一个子代理，由它按清单逐个文件翻译（串行），文件多时耗时长。诉求：针对每个文件的翻译分别安排子代理并行翻译，多少个文件就并行多少次（每个剩余语言目标文件一个子代理、全部并行）。
3. **不应内嵌文档全文**：现状把全部基准文档（默认语言 README.md / CHANGELOG.md / FEATURES.md / AGENTS.md 及自定义默认语言份）的**磁盘全文**经 `readFile`（server `docReadFile`，server.mjs 2643-2645 行）注入提示词——355-361 行逐文件输出 `===== <文件名>（默认语言 …，已审核基准） ===== 全文 ===== 基准结束 =====` 块。提示词体积随文档长度线性膨胀（多语言 × 多文件场景下主会话上下文开销大）。诉求：提示词不带文档内容，让子代理翻译时自行读取基准文件。

简言之：当前翻译提示词「带条目单号 + 全文内嵌基准 + 单子代理串行翻译」，需改为「无条目单号 + 只给基准路径、翻译时读盘 + 每文件一个子代理并行」。

## 复现步骤

前置：任一项目已有语言集 ≥2 个语言的版本计划，且默认语言（语言集首语言）非单文件文档全部人工审核（AI 翻译解锁门禁）；本项目自身即可。

1. 启动看板：项目根执行 `node scripts/server.mjs`，浏览器打开 `http://127.0.0.1:8888`，进入「构建」模块 → 选择版本计划 → 「文档编写」步。
2. 默认语言 4/4 已审核后点击「AI 翻译」，提示词复制到剪贴板，页面出现「AI 翻译提示词（已复制到剪贴板…）」折叠预览（build.js 3133-3140 行）；展开预览或在文本编辑器中粘贴查看该提示词。
3. 观察提示词内容，可逐项核对现象：
   - 实际：「关联范围」节列出 `- REQ-2026…` 等条目单号（及 BUG 汇总句 / 条目读取路径规则行）。预期（本单诉求）：不携带条目单号。
   - 实际：「翻译基准」节把每个默认语言文档全文以 `===== … =====` 块内嵌，提示词总长度 ≈ 全部基准文档字数之和。预期（本单诉求）：只给基准文档磁盘路径，不含全文。
   - 实际：「请逐个产出以下 N 个剩余语言文档」为单子代理整批任务口径。预期（本单诉求）：按目标文件逐个派发子代理并行翻译。
4. （可选）将提示词交给 AI Agent 执行：可观察到一个子代理按清单顺序逐文件翻译、逐文件回执 `atb translate file`，全程串行。

## 期望行为

1. **提示词不携带条目单号**：翻译提示词不再输出关联范围的 REQ 编号清单、BUG 汇总句与条目说明文件读取路径规则；翻译依据收敛为「已人工审核的默认语言基准文档」本身。关联范围参数（items）不再进入翻译提示词（AI 总结提示词阶段一口径不在本单范围内）。
2. **按文件并行派发**：提示词改为「单文件翻译任务」形态——主会话对每个剩余语言目标文件各派发一个子代理，全部并行（并行子代理数 = 目标文件数，即 4 类 ×(N−1) 语言（含自定义文档其余语言份）的目标文件总数）；每个子代理只负责翻译自己名下的一个文件，写盘后回执。回执口径不变：仍按同一执行编号（runId）逐文件回执 `atb translate file <执行编号> --file <文件名> --state translating|translated`，收尾 `atb translate done|fail`；账本（docs-translate-store）、独立锁 translate.lock 与门禁行为均不变。
3. **提示词不内嵌文档内容**：提示词只给出基准文档与目标文件的磁盘路径及语言对应关系（如 `README.md → README_en.md`），子代理翻译时自行读取基准文件内容。「唯一基准、不增删信息、不得编造」等翻译约束保留；基准语义变为「子代理翻译时点从磁盘读取的最新已审核内容」（等效且不旧于启动时点快照）；启动前基准变更检测提示（baselineShift，server.mjs 2872-2882 行）行为不变。
4. **不回归**：AI 翻译解锁门禁（默认语言非单文件全审）、单语言集报错、同时间单 run 互斥锁、已 translated 跨 run 保留续跑、文档编写页「AI 翻译」按钮 / 提示词预览折叠 / 复制交互均保持不变——本单不涉及界面布局与交互改动，仅提示词文本内容随生成逻辑变化，故不附 ui-demo.html 界面演示。

## 验收说明

- [ ] 翻译提示词不含条目单号：构造含 REQ / BUG 关联范围的版本计划，生成提示词中无 `REQ-` / `BUG-` 编号行、无「修复了 N 个 bug」汇总句、无 `<项目根>/agent-team-board/data/requirements/<REQ-ID>/` 路径规则行；空 items 时不再输出「关联范围」节（或不再输出该节内容）。
- [ ] 翻译提示词不含基准文档全文：无 `===== <文件名>（默认语言 …，已审核基准） =====` 内嵌块与基准正文片段；含各基准文档与目标文件的磁盘路径 / 文件名清单及语言对应说明；文件缺失时的占位与说明口径明确（现状为「（文件缺失：跳过该类型翻译并在回执说明）」，改动后路径化口径需对应覆盖）。
- [ ] 并行派发口径：提示词明确「每个目标文件派发一个子代理、并行翻译」及单文件任务边界；目标文件清单与 BUG-20260922-002 自定义文档口径一致（4 类 + 自定义 × 剩余语言）。
- [ ] 回执链路不回归：`atb translate file <RUN-ID> --file <文件名> --state translating|translated`、`translate done|fail` 按同一执行编号逐文件回执有效；账本计数（x/N）、当前文件、独立锁展示正常；已审核（reviewed）目标跳过口径保持。
- [ ] 门禁与锁不回归：默认语言未全审仍 400 带缺口明细；单语言集仍报「无剩余语言文档可翻译」；同时间第二轮 start 仍被互斥锁拒绝；baselineShift 提示行为不变。
- [ ] 翻译质量约束保留：唯一基准 / 不增删信息 / 不得编造 / 各语言地道行文 / README 同语言链接 / 短回执不粘贴全文等约束在提示词中仍在。
- [ ] 分层测试先红后绿（`scripts/tests/<前缀>-<单号小写>.test.mjs`），覆盖上述提示词口径断言（参照 `req-20260921-012.test.mjs`、`bug-20260921-005.test.mjs`、`bug-20260922-002.test.mjs` 的翻译提示词断言并按新口径调整）；`npm test` 全量通过。提示词相关文案若随改动调整，中英文同步（`scripts/web/i18n.js`，BUG-20260912-001 基线）。

## 待确认

1. **并行度是否设上限**：登记诉求为「多少个文件就并行多少次」（不设上限）；语言集较多时目标文件数可达 4 ×(N−1)（含自定义更多），是否需要并发上限（或由主会话自行斟酌）待人工确认；落定前按原文口径「不设上限」实现。
2. **条目单号精简范围**：按本单标题理解仅针对「AI 翻译提示词」；阶段一「AI 总结提示词」现同样带关联范围条目编号（`docScopeLines` 同源），是否同步精简待人工确认，落定前总结侧口径不动。
3. **单文件提示词模板形态**：派发说明、目标文件占位与回执指令如何在提示词中组织（一份主提示词 + 每文件参数代入，或其他形态）属实现设计，开发阶段在 design.md 落定，不作为本单验收门槛。

## 界面展示

**不涉及界面改动**：本单是 AI 翻译提示词的生成逻辑与内容口径优化，现象为提示词文本问题，不是界面缺陷。文档编写页「AI 翻译」入口、「AI 翻译提示词」预览折叠块（details，默认折叠，build.js 约 3133-3140 行）与「复制提示词」按钮的布局、交互行为与状态反馈（已复制 toast、进行中 / 失败 / 已完成提示）均保持现状，不新增、不移除、不调整任何控件；仅预览框内的提示词文本随新口径变化（属生成数据，非界面结构）。故本单不创建 ui-demo.html 可交互演示；开发时若最终方案需要改动上述任一界面元素，须先回到人工确认，不在本单范围内自行扩展。

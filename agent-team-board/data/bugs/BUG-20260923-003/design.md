## 根因分析

`buildDocTranslatePrompt`（scripts/lib/publish-flow.mjs）生成翻译提示词时的三个既定口径与实际使用形态不匹配：

1. **条目单号冗余**：提示词输出「关联范围」节（`docScopeLines`），列出 REQ 编号清单、BUG 汇总句与条目说明文件路径规则。翻译的唯一语境是「已人工审核的默认语言基准文档」，条目单号对翻译无增量价值，只拉长提示词。
2. **串行派发低效**：第 363 行「请逐个产出以下 N 个剩余语言文档」把整批文件交给单个子代理逐个翻译，文件多时全程串行、耗时长；而各目标文件翻译相互独立（各自回执 `atb translate file`），天然可并行。
3. **全文内嵌膨胀**：基准文档磁盘全文经 `readFile` 注入提示词（`===== <文件名>…===== 基准结束 =====` 块），提示词体积随文档长度线性膨胀，多语言 × 多文件场景下主会话上下文开销大；子代理本可自行读盘。

## 方案

**开源选型（REQ-20260909-015）**：本单为提示词文本装配逻辑调整，纯自研字符串拼装，不引入任何依赖，无需 licenses.md（未使用开源库）。

仅改 `buildDocTranslatePrompt`（scripts/lib/publish-flow.mjs）与两处生产调用（scripts/server.mjs `/api/build/docs-translate/start`、scripts/atb.mjs `translate start`），测试按新口径调整：

1. **去条目单号**：函数签名移除 `items` 参数，提示词不再输出「关联范围」节（`docScopeLines` 仍被 AI 总结提示词使用，阶段一口径不动——README「待确认 2」落定前不动总结侧）。
2. **去全文内嵌**：签名移除 `readFile` 参数，删除 `===== … =====` 内嵌块；改为「基准 → 目标文件名对应清单」（如 `README.md → README_en.md（English / README）`）+ 项目路径 + 明确指令：各子代理翻译前自行读取项目路径下基准文件磁盘内容（即翻译时点最新已审核内容，等效且不旧于启动快照）；基准文件缺失 → 该子代理跳过翻译并在回执说明，不得编造基准内容。`baselineShift`（mtime 基准变更检测）与门禁 / 互斥锁 / 账本链路均不动。
3. **并行派发口径**：提示词改为「派发协调」形态——头行声明对每个目标文件各派发一个子代理、全部并行（并行子代理数 = 目标文件数，不设上限，按 README「待确认 1」原文口径），每个子代理只负责翻译自己名下的一个文件（读自己名下基准 → 写自己名下目标 → 逐文件回执）；回执命令与门控不变（无 runId 仍不输出回执指令段），收尾仍 `atb translate done|fail`。
4. **约束保留**：唯一基准 / 不增删信息 / 不得编造 / 各语言地道行文 / README 同语言链接 / 不粘贴全文等翻译约束原样保留；目标清单仍为 `restDocFiles`（4 类 + 自定义 × 剩余语言，LICENSE 单文件类不进范围）。

**TDD**：新增 `scripts/tests/bug-20260923-003.test.mjs`（L1 纯逻辑，先红），并按新口径调整 `req-20260921-012.test.mjs`、`bug-20260921-005.test.mjs`、`bug-20260922-002.test.mjs`、`req-20260922-003.test.mjs` 的翻译提示词断言；界面零改动（build.js 仅渲染 `pf.translatePrompt.text`），无 i18n 文案变化（提示词为服务端生成数据，非界面词条）。

## 风险与边界

- **基准时效语义变化**：由「启动时点全文快照」变为「子代理翻译时点读盘」。因启动前已有 baselineShift 检测提示，且读盘内容恒不旧于启动快照，属等效或更优，README 期望行为 3 已认可。
- **并行写盘冲突**：各子代理目标文件互不相同（每文件恰一个子代理），无写冲突；账本 `translate file` 支持同 run 多文件乱序回执（既有能力，L2-1 已覆盖）。
- **派发说明属提示词建议**：实际并行度由执行的主会话决定；提示词只固化口径，不强制。
- **不回归面**：解锁门禁 / 单语言集报错 / 互斥锁 / 已 translated 跨 run 保留 / reviewed 跳过 / 前端预览与复制交互，全部由既有测试覆盖，本单不改其行为。

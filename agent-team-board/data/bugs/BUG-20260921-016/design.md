# 设计 — BUG-20260921-016 删除下方的描述标签和计划号等标签，把 AI 完善和编辑放在同一行

> 由 Agent 在 /dev 开发前补充，人可随时批注。

## 引入来源（源单）

现状概况页签布局由三个已实施条目叠加落定（编号均经 `atb list` 核验存在）：

- **REQ-20260920-003**（构建和发布流程整改）：引入五步流程导航与详情头部元信息行，同时在概况内容区保留了一行「计划号 BLD-… · 版本号 … · 目标分支 main ·（来源分支 …）」元信息——计划号 / 版本号与详情头部第二行完全重复，是本 Bug 冗余的起点。
- **REQ-20260921-014**（概况页签增加修改功能）：引入描述块头行（`.bld-desc-block-head`，左侧「描述」标签 + 右侧「编辑」按钮），「编辑」与当时位于概况顶部的「AI 完善」分处两行。
- **REQ-20260921-016**（版本计划列表中的操作按钮优化）：把「AI 完善」自概况顶部操作行（`.bld-plan-acts`）迁入描述块头行右侧（紧邻「编辑」左边）并删除了顶部操作行——两键虽同排，但「描述」标签行与重复元信息行仍占位，即本 Bug 截图所示冗余布局。

## 根因分析

概况内容区在多次增量改造中各自「加行」而没有回收前一步的占位：REQ-20260920-003 加了元信息行（与详情头部重复），REQ-20260921-014 加了描述块头行（承载「编辑」），REQ-20260921-016 把「AI 完善」并入该头行后，「描述」标签与元信息行已不承载增量信息，却仍占据两行，导致操作分散前的竖向浪费与视线跳动。

## 方案

**开源选型（REQ-20260909-015）**：无合适库——本单是既有自有 Web UI（`scripts/web/build.js` 内联模板 + `scripts/web/style.css`）的布局去冗余，不涉及新能力，自研（模板与样式调整）成本远低于引入任何前端库；未引入开源依赖，不创建 licenses.md。

改动面（全部在既有结构内，锁定口径零变化）：

1. `scripts/web/build.js` `renderDetail`（概况步 `planBody` 模板）：
   - 删除元信息行（`计划号 ${esc(v.id)} · 版本号 … · 目标分支 … · 来源分支 …`）——计划号 / 版本号详情头部已有；目标分支默认 `main`、合并目标固定，来源分支仅合并后存在，按 README 待确认口径默认不保留。
   - 恢复概况顶部一行右对齐操作行 `.bld-plan-acts`（`AI 完善` → `编辑` 次序，右对齐 + flex-wrap 沿用）；编辑态「编辑」键让位（表单自带保存 / 取消），「AI 完善」保留原位。
   - 描述展示简化为 `.bld-desc-block` 容器内直接放描述正文（`.bld-desc`），删除 `.bld-desc-block-head`（「描述」标签 + 操作组）。
   - `mergeState`（合并中提示 / 合并失败信息）随布局上移，展示口径不变。
2. `scripts/web/style.css`：移除 `.bld-desc-block-head` / `.bld-desc-block-acts`；恢复 `.bld-plan-acts`（右对齐、gap 8、flex-wrap，窄屏自动换行）。
3. i18n：无新增 / 删除词条——「描述 / 编辑 / AI 完善」为全文匹配共享键（其他界面在用），仅界面不再渲染「描述」标签。
4. 测试：新增 `scripts/tests/bug-20260921-016.test.mjs`（布局精简 / 锁定 title / 编辑让位 / 提示上移 / 头部信息完整 / i18n 沿用 / 静态契约 7 例）；同步调整受既有口径变化影响的断言（`req-20260921-016.test.mjs` T3/T4/S1、`req-20260921-013.test.mjs` T3、`bug-build-ver-card-acts-20260913-004.test.mjs` B1）。

- `.bld-plan-acts` 类名在 REQ-20260921-016 中刚被移除、本单恢复（同一位置同一用途，测试断言已同步），不存在新旧类名并存。

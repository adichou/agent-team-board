# BUG-20260909-006 已计划列表中的选择进入批量开发的功能去掉，因为已经有批量开发队列了。

- 状态：accepted（已接受；本轮仅完善说明，未实施修复）
- 归属：独立 Bug（引入来源见 design.md）
- 引入来源：REQ-20260906-018（引入已计划列多选进入批量开发与勾选范围推送链路）+ REQ-20260908-010（改口径为已计划队列但保留范围链路致两套并存）
- 创建：2026-09-09T01:00:14.700Z

## 现象

看板「需求」模块的「已计划」档列表仍保留一套「勾选进入批量开发」功能，与任务模块已有的批量开发队列（已计划队列）形成两套并存的开发范围口径：

1. 「已计划」档每行行首有常驻复选框（`scripts/web/app.js` 第 1155 行 `data-impl-id`，资格 = planned 且未被认领）。勾选后列表头右组（`#selGroup`）出现「进入批量开发」按钮（`#implGo`，`scripts/web/index.html` 第 95 行）与「移出计划」。
2. 点击「进入批量开发」（`enterBatchImpl`，`scripts/web/app.js` 第 1986–1994 行）会做两件事：
   - 把勾选集合推送为**派发范围**：`POST /api/dispatch/scope`（`scripts/server.mjs` 第 688 行）。范围生效后（`scopeActive`），此后每次勾选变化都会静默重推（`pushImplScope`，`scripts/web/app.js` 第 1957–1975 行）；调度器只在范围内取单（`scripts/lib/scheduler.mjs` 第 211–216 行），范围内无可派发候选时阻塞为 `scope-empty`（第 230 行）。范围为服务端内存态，重启恢复默认（`scripts/lib/scheduler.mjs` 第 132 行）；切换项目时前端向旧项目推空范围清理（`scripts/web/app.js` 第 450–453 行）。
   - 跳转到任务模块「批量开发」子面板（`gotoRuns('develop')`）。创建面板的候选统计也按勾选集合过滤（`/api/batch/current?ids=`，`scripts/web/app.js` 第 2670–2673 行、`scripts/lib/batch.mjs` 第 522–527 行）。
3. 与之重复的是：任务模块「批量开发」子面板的启动区本就展示**已计划队列**——「已计划队列（最旧优先）…运行中新置计划的条目自动进入队列」（`scripts/web/app.js` 第 2630 行；`docs/agent-team-board/batch-execution.md` 第 62 行），队列自动涵盖全部已计划未认领单，无需任何列表勾选。

由此产生的问题：

- **口径冲突**：从「已计划」列表勾选进入后，未勾选的已计划单不会被自动派发（被 scope 过滤），与「运行中新置计划的条目自动进入队列」的既定心智矛盾；同一批已计划单是否存在「自动开发」取决于用户是否曾经从列表勾选进入过。
- **隐性全局状态**：范围生效后仅任务模块 Codex 面板一处 notice 提示（「本批范围：勾选 N 项——仅自动派发勾选条目…」，`scripts/web/app.js` 第 2922 行）与批量开发创建面板的「本批范围：勾选 N 项」行（第 3457–3459 行）；「已计划」列表页本身无任何范围标记，用户在列表页看不到派发被限制在勾选子集。
- **死文案**：`#implGo` 的 tooltip 仍写「未勾选已计划条目时为全部候选」（`scripts/web/index.html` 第 95 行），但 REQ-20260909-002 起零勾选时整个批量操作组隐藏（`scripts/web/app.js` 第 1410 行 `group.classList.toggle('hidden', curCount === 0)`；已计划档计数取 `state.impl.selected`），该说明描述的路径已不可达。

待确认（登记时无法核实）：是否有真实使用流程依赖「只开发勾选子集」的范围语义（如故意把部分单留在范围外暂不开发）；修复时若有此类诉求，应由「移出计划」（退回已接受）承担同等效果，还是另行评估。

## 复现步骤

前置：看板服务已启动（`node scripts/atb.mjs serve`，默认 `http://127.0.0.1:8888`），当前项目内至少有 2 条「已计划」且未被认领的条目（无则新建需求后依次「接受」→「移入计划」）。

1. 打开看板，进入「需求」模块，切到「已计划」档：每行行首可见常驻复选框。
2. 勾选其中 1 条（留其余不勾）：列表头右组出现「已选 1 项」与「进入批量开发」「移出计划」两个按钮。
3. 点击「进入批量开发」：页面跳转任务模块「批量开发」子面板；同时浏览器网络面板可见一次 `POST /api/dispatch/scope`，请求体为勾选的 1 个条目编号——未勾选的其余已计划条目不在范围内。
4. 回到「已计划」档再勾/退选另一条：每次变化都会再触发一次 `POST /api/dispatch/scope`（签名去重，无变化不重推），全程无确认提示。
5. 观察范围的实际限制：在任务模块 Codex 面板开启自动派发后，调度器只在勾选范围内取单；未勾选的已计划条目不会被派发。范围提示只出现在 Codex 面板的「本批范围：勾选 N 项」notice，「已计划」列表页无任何提示。
6. 对照冗余：清空勾选（「☐ 全不选」），直接从顶栏「任务」进入「批量开发」子面板——启动区展示「已计划队列（最旧优先）」并预览全部已计划未认领单（含步骤 3 未勾选的），即不经过列表勾选、默认就是全量队列开发。

## 期望行为

- 「已计划」列表的「进入批量开发」入口整体移除：已计划档列表头批量操作组只保留「移出计划」（planned → accepted）。行首复选框与勾选集合目前同时服务「批量开发」与「移出计划」两个功能（`state.impl.selected`），移除后复选框仅为「移出计划」服务是否保留、呈现形式如何，由修复阶段在 design.md 定夺（不得因此回归批量移出计划）。
- 前端派发范围推送链路随之移除：`enterBatchImpl`、`pushImplScope`、`pushImplScopeClear`、项目切换清理及勾选 change 里的推送（`scripts/web/app.js`）不再存在，任何操作都不再发起 `POST /api/dispatch/scope`。服务端侧（`scripts/server.mjs` `/api/dispatch/scope` 路由、`scripts/lib/scheduler.mjs` 的 `scope` 字段/过滤与 `scope-empty` blocker、`scripts/lib/batch.mjs` 的 `ids` 过滤分支）是同步删除还是保留为无触发方的 dormant 机制，由 design.md 定夺；若保留须确认再无其他调用方（待确认）。
- 批量开发入口唯一收敛为任务模块：顶栏「任务」→「批量开发」子面板（`gotoRuns('develop')`）。开发范围口径唯一化为「已计划队列」：全部已计划未认领单、最旧优先、运行中新置计划的条目自动进入队列（现有行为保持不回归）。
- 依赖勾选范围的面板呈现一并清理：Codex 面板「本批范围：勾选 N 项」notice、批量开发创建面板「本批范围：勾选 N 项…」scopeLine、`/api/batch/current?ids=` 的 stats 过滤，不得残留指向已删除入口或永不可达的文案（含 `#implGo` tooltip「未勾选已计划条目时为全部候选」随按钮删除）。
- 「移出计划」批量功能保持可用：已计划档全选/全不选、批量 planned → accepted、进行中防误触与成功/失败分列反馈均不回归。
- 断言现状的既有测试随功能移除同步更新，不留红灯：`scripts/tests/batch-ui.test.mjs`（「列表头右组应提供『进入批量开发』」）、`scripts/tests/selection-lane-scope.test.mjs`（已计划档「进入批量开发」显隐系列）、`scripts/tests/planned-chip-dedup.test.mjs`（已计划行复选框断言，按复选框去留结论调整）。

## 界面展示

- 布局：「需求」模块 → 「已计划」档列表。现状（缺陷）：行首复选框 + 列表头右组「已选 N 项 / 进入批量开发 / 移出计划」；期望（修复后）：已计划档批量操作组只剩「移出计划」，开发入口只在顶栏「任务」模块。演示页对照呈现两种状态的列表头、行勾选、任务模块队列面板。
- 交互：勾选/取消复选框驱动「已选 N 项」计数与按钮显隐（零勾选整组隐藏）；现状态点击「进入批量开发」会「推送派发范围」并跳转任务模块，修复态该按钮不存在，勾选只服务「移出计划」；顶栏「任务」入口两种状态下都可进入「批量开发」子面板。
- 状态反馈：勾选计数、范围推送的静默请求日志（现状态演示「隐性范围」问题）、任务面板「已计划队列（最旧优先）」预览与「本批范围：勾选 N 项」notice（仅现状态）、移出计划的成功反馈；含已计划为空时的空态。

可交互演示：[./ui-demo.html](./ui-demo.html)（单文件、无外网依赖，浏览器直接打开；内置「现状（缺陷）/ 期望（修复后）」切换对照）。

# BUG-20260928-006 官网资料更新的 AI 提示词的版本号不对，请修改。

- 状态：submitted（待人工接受）
- 归属：独立 Bug（引入来源见 design.md）
- 创建：2026-09-28T04:37:45.687Z

## 现象

第五步「正式发布」→「动作二 · 官网资料更新」的官网提示词（复制到官网仓库执行的 AI 提示词）
中版本号错误：计划已使用独立 x.y.z 版本号（如 `BLD-20260927-001` → `1.0.0`），提示词仍写
「版本号 20260927-001」（计划编号派生的 `YYYYMMDD-NNN`），与同屏展示的版本号（x.y.z）不一致。

- 位置：`GET /api/build/publish-plan` 响应 `sitePrompt`，由
  `scripts/lib/publish-flow.mjs` `buildSiteWritingPrompt` 生成；
- 根因：`buildSiteWritingPrompt` 只接收 `planId` 并在函数内派生版本号，`scripts/server.mjs`
  调用点未传计划的 `version` 字段（REQ-20260922-006 引入 x.y.z 后该提示词未同步同源）。

## 复现步骤

1. 创建版本计划（自动分配或手填 x.y.z 版本号，如 `1.0.0`），完成前四步进入第五步「正式发布」；
2. 在发布设置中配置官网仓库根目录（未配置时提示词不展示，无法复现）；
3. 打开「动作二 · 官网资料更新」的官网提示词折叠盒查看全文；
4. 提示词首行与「发布计划号」行中的版本号为 `YYYYMMDD-NNN`（计划编号派生），而非计划的
   x.y.z 版本号。

## 期望行为

官网提示词中的版本号与计划 x.y.z 版本号同源（REQ-20260922-006 验收口径「官网提示词中的
版本号同源」）：新计划显示 x.y.z；存量计划（version.json 无 `version` 字段）沿用原
`YYYYMMDD-NNN` 派生口径（旧数据回退，不迁移）。修复后提示词两处版本号（首行说明 +
「发布计划号」行）均取同源值，完整计划号保留（提交消息匹配依据不变）。

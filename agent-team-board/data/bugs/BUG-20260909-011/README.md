# BUG-20260909-011 配置界面中的运行参数配置删除

## 现象

设置页仍显示「运行参数」配置分区。2026-09-09 核对当前源码，确认以下渲染内容存在；本次未运行浏览器复现，具体浏览器、窗口尺寸及用户截图待确认。

| 位置 | 当前可核实的表现 | 用户要求 |
| --- | --- | --- |
| 设置 →「运行参数」分区 | 分区标题「运行参数」；CLI 路径文本框（占位「自动探测（PATH / ChatGPT.app 内置）」）、单项时限（分钟）数字框（5～240，缺省 60）、网络重试次数数字框（0～3，缺省 2）、「重启后自动继续」「允许非 Git 项目执行」两个复选框、「保存设置」按钮及「不在此收集任何密钥；沿用本机 codex 登录与模型配置。」说明 | 删除该配置分区 |

以上属于界面精简要求（BUG-20260909-002 明确保留运行参数时留下的待确认边界）。尚无证据说明该分区导致任务执行失败或配置数据损坏，不将此类问题计入现象。

### 核实依据

- `scripts/web/app.js` `paintSettingsView`（约 4651-4681 行）：渲染 `<h4>运行参数</h4>` 分区与 `#stCliPath`、`#stTimeout`、`#stRetries`、`#stResumeRestart`、`#stAllowNonGit` 五个控件、`#stSave` 保存按钮及密钥说明文字。
- 同文件 `bindSettingsView`（约 4770-4798 行）：`#stSave` 点击后读取五控件值 POST `/api/dispatch/settings`（codex 键），成功 toast「已保存项目设置（用于后续新执行）」并重渲染设置视图；失败 toast 错误、按钮恢复。
- 同文件 `renderSettingsView`（约 4683-4700 行）：任务设置加载中（`state.tasks.loading`，REQ-20260909-001 两阶段渲染）五个运行参数控件与 `#stSave` 一并 `disabled`；`/api/dispatch/settings` 读取失败时整页显示「设置加载失败」+ `#stRetry` 重试。
- `scripts/tests/settings-simplify-20260909-002.test.mjs` T1/T3、`scripts/tests/settings-title-removed.test.mjs`、`scripts/tests/task-settings-simplify-20260909-001.test.mjs`（约 260 行）均有运行参数字段保留、照常提交、加载中禁用的现行断言；它们是现有行为依据，开发修复时需按新口径调整，不能当作本 Bug 已修复的证据。

## 复现步骤

前置：启动本项目 Status Board，选择已初始化且能正常读取设置的项目。无需启动任务、修改或保存任何配置即可观察。

1. 点击主导航「设置」进入设置页。
2. 页面加载完成后向下查看「批量任务」分区之下的「运行参数」分区，可见标题、五个控件、「保存设置」按钮与密钥说明文字。复现只需确认该分区存在，不必修改任何值或点击保存。
3. 观察加载过程：刚进入设置页、任务设置加载中时，「运行参数」五个控件与「保存设置」按钮呈禁用态，加载完成后恢复可编辑——该禁用联动也随分区存在而可见。
4. 刷新页面并在设置与其他模块之间切换，重复观察；「运行参数」分区稳定显示，不以任务正在运行作为显示条件。缺陷是否在用户实际环境中稳定复现、是否与特定版本有关，待开发阶段确认。

## 期望行为

1. 设置页删除「运行参数」分区：分区标题、五个控件（CLI 路径、单项时限、网络重试次数、重启后自动继续、允许非 Git 项目执行）、「保存设置」按钮与「不在此收集任何密钥…」说明一并移除。删除后不保留空卡片、空标题或不可操作的占位区域。
2. 「批量任务」分区（Agent 隐藏开关、模型来源 / 手动覆盖、完善流转开关及其「保存批量任务设置」按钮）不属于本单标题的删除对象，保持可用；其草稿提示「有未保存的更改」、保存成功 / 失败反馈、加载两阶段渲染与全部隐藏提示不受影响。
3. 删除配置界面入口不等于改变派发执行行为：服务端消费点（如 `scripts/lib/scheduler.mjs` 读取 `settings().cliPath` / `allowNonGit` / `resumeAfterRestart`，`scripts/lib/codex-adapter.mjs` 以 `allowNonGit` 追加 `--skip-git-repo-check`）仍按既有逻辑运行。删除后这些参数的取值来源——继续读取既有落盘配置，还是回落默认值（时限 60 分钟、重试 2 次、重启后自动继续关闭、非 Git 执行关闭、CLI 路径自动探测）——待确认；未确认前不得清空底层配置或连带改动派发消费逻辑。
4. 是否连带删除服务端 `/api/dispatch/settings` 对五项运行参数的读写与落盘字段，不由本单标题确认，均为待确认；本单先限定配置界面的分区删除。

### 界面展示与状态反馈（文字说明）

- 正常：设置页仅保留「批量任务」分区；「运行参数」标题、五个控件、保存按钮与密钥说明不再渲染，无残留空区域。
- 初始无配置：「批量任务」按现有默认值展示（两类任务的 Codex、Zcode 均未勾选隐藏）；不因已删除的运行参数控件缺少值而影响任何字段。
- 加载中：设置页仍两阶段渲染——任务设置加载中时「批量任务」编辑与保存禁用、完成后恢复；不再出现随之禁用的运行参数控件。
- 失败：设置读取失败仍可见整页「设置加载失败」+ 重试（该接口调用是否随分区删除调整，待确认）；「批量任务」加载失败显示分区级错误 + 重试；保存失败草稿保留、可重试，不误报成功。
- 可交互演示：[./ui-demo.html](./ui-demo.html)——单文件无外网依赖，对照展示缺陷现象（现状：设置页含「运行参数」分区）与期望修复后状态（分区删除、仅剩「批量任务」），覆盖加载中 / 加载失败 / 保存反馈等状态切换。本演示为验收口径示意，非已实现效果。

### 范围与待确认

- 本单承接 [BUG-20260909-002](../BUG-20260909-002/README.md) 的遗留待确认项：该单删除模型/强度配置与运行环境检查时明确「运行参数不连带删除、是否也需移除待确认」；本单标题确认删除配置界面中的运行参数配置，两单口径以此衔接，不冲突。
- 删除后运行参数的取值来源、服务端 `/api/dispatch/settings` 与落盘字段是否连带删除、Electron 外壳或其他视图是否存在运行参数的其他展示位置，均待确认。
- 锁定现行行为的测试（`scripts/tests/settings-simplify-20260909-002.test.mjs` T1/T3、`scripts/tests/settings-title-removed.test.mjs`、`scripts/tests/task-settings-simplify-20260909-001.test.mjs` 约第 260 行断言）需按本单新口径同步更新后通过。

## 验收说明

- [ ] 正常加载、刷新、切换项目并返回设置后，设置页均无「运行参数」分区：无分区标题、五个控件、「保存设置」按钮与密钥说明，无空卡片、空标题或失效按钮残留。
- [ ] 「批量任务」分区完整可用：Agent 隐藏开关、模型来源 / 手动覆盖、完善流转开关照常展示、可编辑、保存后刷新回显正确；全部隐藏时的禁用与提示行为保持。
- [ ] 设置页加载两阶段行为保持：任务设置加载中「批量任务」编辑与保存禁用、完成后恢复；不再出现被禁用的运行参数控件或保存按钮。
- [ ] 界面删除不影响任务派发执行：启动批量完善 / 开发仍按既有参数解析与执行（或按已确认的取值来源执行），不因删除界面清空既有落盘配置或改写运行中任务。
- [ ] 服务端口径按待确认项结论执行并记录：`/api/dispatch/settings` 读写与落盘字段的处理有明确结论，无超出本单编号依据的连带删除。
- [ ] 设置读取失败可见错误且可重试；「批量任务」保存失败草稿保留、不误报成功；窄窗口与模块切换无删除后遗留的横向空白、错位或死交互。
- [ ] 旧界面断言（settings-simplify-20260909-002 / settings-title-removed / task-settings-simplify-20260909-001 等）按本单口径更新后测试通过。

# BUG-20260913-003 bug 单的文档也要支持讨论菜单，参考需求的文档

- 状态以本条目 status.json 和看板为准。
- 归属：独立 Bug（引入来源见 design.md；被参照的既有功能为需求单右键「讨论」菜单 [REQ-20260909-014](../../requirements/REQ-20260909-014/README.md)）。
- 创建：2026-09-13T11:21:24.183Z。

## 现象

Bug 单详情抽屉与需求单一样带有「说明 / 设计 / 测试用例」文档页签（`scripts/web/app.js` 的 `DRAWER_FIXED_DOC_TABS`，`drawerDocTabs` 不按条目类型区分），文档可正常加载渲染，渲染后的源码行标注（`annotateDocLines`，在 `loadDoc` 内对所有条目类型执行）也已生效。但在 Bug 单的文档内容上右键，**不弹出自定义「💬 讨论」菜单**：

- `scripts/web/app.js` 的文档级 contextmenu 处理 `onDocCtxMenu`（约 3980 行起；全局绑定约 6927 行）在入口处显式排除非需求条目：`if (state.drawer.item?.type !== 'requirement') return;`（约 3983 行，注释「仅需求详情抽屉（README 默认口径，Bug 单不启用）」）。
- 因此用户在 Bug 单文档上选中一段文字或停在某个内容块上右键时，只有浏览器原生右键菜单/页面默认行为，无法像需求文档那样一键把「所选文字 + 文档路径 + 源码行号」复制到剪贴板、粘贴到 Agent 会话讨论（该能力由 REQ-20260909-014 为需求单建立），只能手动拼文档路径与行号。
- 关联缺口（修复须一并处理）：引用文本中的文档路径由 `docRefPath`（约 3902–3906 行）拼装，硬编码为 `docs/agent-team-board/requirements/<单号>/<文档名>`。Bug 单的真实磁盘位置是 `docs/agent-team-board/bugs/<BUG 编号>/`（独立 Bug）或 `docs/agent-team-board/requirements/<REQ 编号>/bugs/<BUG 编号>/`（归属需求的 Bug，见 `scripts/lib/core.mjs` `resolveItemDir` 的解析口径）。若只放开类型门槛而不改路径拼装，Bug 单复制出的引用路径必然是错的。

## 复现步骤

1. 启动 Status Board（`/board` 或 `node scripts/server.mjs`，端口 8888），浏览器打开看板。
2. 进入需求模块，打开任一 Bug 单的详情抽屉（独立 Bug 或归属需求的 Bug 均可；该 Bug 的说明 / 设计 / 测试用例至少一份已创建）。
3. 切到「说明」（或「设计」「测试用例」）页签，等文档渲染完成。
4. 在文档内容区选中一段文字后右键；再无选中地直接在某段落上右键一次。
5. 观察：两次右键均不出现「💬 讨论」单项自定义菜单，仅有浏览器原生右键菜单/默认行为；剪贴板未被写入任何引用。
6. 对照组：对任一需求单重复步骤 3–4——右键弹出「💬 讨论」菜单，点击后 toast 提示「已复制 引用：<文档名> 第 x–y 行」，剪贴板内容含所选原文、文档路径与源码行范围。
7. 另在 Bug 单文档处于加载中 / 未创建空态 / 加载失败态时右键，同样无自定义菜单（此点与需求单一致，属预期行为，仅作对照记录）。

## 期望行为

参照需求文档的既有实现（REQ-20260909-014），Bug 单详情抽屉的文档页签获得同口径的右键「讨论」轻量入口：

1. Bug 单的「说明 / 设计 / 测试用例」及已存在的附加文档页签（licenses.md / test-report.md，与需求单现有口径一致）内容区右键 → 弹出「💬 讨论」单项自定义菜单；菜单定位、视口边缘内收、点外部 / Esc / 滚动收起、深浅色样式均沿用需求单现状。
2. 有选中文字：点「讨论」复制「所选文字原文 + 文档路径 + 对应源码行号（范围）」；无选中：复制「文档路径 + 右键落点内容块的源码行号（行或行范围）」。行号以 `/api/item/<BUG 编号>/doc/<文档名>` 返回的源码为准（1 基）。
3. 文档路径必须按 Bug 单真实磁盘位置拼装：独立 Bug 为 `docs/agent-team-board/bugs/<BUG 编号>/<文档名>`；归属需求的 Bug 为 `docs/agent-team-board/requirements/<REQ 编号>/bugs/<BUG 编号>/<文档名>`；不得沿用需求单的 `requirements/<单号>/` 硬编码（具体拼装实现 design.md 定稿）。
4. 保持 REQ-20260909-014 的免流程口径：纯剪贴板能力，不生成讨论编号、不保存引用快照、不写任何记录；复制成功 toast 反馈，自动复制失败弹手动复制文本框兜底。
5. 边界不变：链接 / 图片上右键放行浏览器原生菜单；文档加载中 / 未创建空态 / 加载失败态不弹菜单；需求单现有右键菜单行为零回归；文档区外（列表、基本信息、页签行等）右键不受影响。

## 界面展示

[打开可交互演示](./ui-demo.html)：单文件 HTML，内联 CSS/JS，无外网依赖与构建步骤，浏览器直接打开即可操作。

布局：模拟 Bug 单详情抽屉——头部（编号 + 标题 + 关闭钮）、页签行（基本信息 / 说明 / 设计 / 测试用例 / 讨论纪要）、文档渲染区（内容块带源码行范围标注）；顶部提供「缺陷现状 / 期望效果」对照开关、「独立 Bug / 归属需求 Bug」归属开关与文档状态切换（正常 / 加载中 / 尚未创建 / 加载失败），下方有引用预览面板。

交互：在文档内容上选中文字或直接右键——期望效果模式弹出「💬 讨论」菜单，点击后按有无选中分别组装引用并复制（演示模式下同时展示引用全文预览）；缺陷现状模式仅出现浏览器原生右键并给出现象提示。可切换说明 / 设计 / 测试用例页签、切换归属查看两种真实路径拼装差异。

状态反馈：复制成功 toast、勾选「模拟复制失败」时走手动复制兜底文本框；加载中 / 空态 / 失败态下右键不弹菜单（失败态可重试恢复）；菜单支持 Esc / 点外部 / 滚动收起与视口边缘内收。演示中的行号、路径、所属需求均为示例数据，不代表真实条目；演示仅用于对照说明，不替代真实页面验收。

## 验收说明

- 打开独立 Bug 单与归属需求 Bug 单各一（对应文档页签有内容），在「说明 / 设计 / 测试用例」页签内：选中文字右键 → 弹「💬 讨论」菜单；点击后剪贴板含「单号 / 文档名 行范围 + 文档路径 + 原文」，路径与仓库内该 Bug 目录的真实磁盘位置一致（独立与归属两种拼法分别核对）。
- 无选中右键 → 复制内容为文档路径 + 落点块行范围；跨行段落 / 围栏内选文的行号与 `/api/item/<BUG 编号>/doc/<文档名>` 返回源码逐行一致。
- 附加文档页签（licenses.md / test-report.md 存在时）行为与需求单同口径。
- 边界与反馈：链接 / 图片右键为浏览器原生菜单；加载中 / 空态 / 失败态不弹菜单；复制成功有 toast，自动复制失败出现手动复制兜底；点外部 / Esc / 滚动可收起菜单；深浅色与窄屏抽屉形态下菜单定位正常。
- 回归：需求单右键「讨论」行为不变；Bug 单其他页签（基本信息 / 讨论纪要）与看板其他区域右键行为不变。
- [演示](./ui-demo.html)可在浏览器直接打开，完成缺陷 / 期望对照、归属切换、四类文档状态切换与复制反馈演示。
- 范围边界（待确认）：需求单「讨论纪要」页签内的成套「文档讨论」区块（REQ-20260909-003，当前仅需求单挂载）是否同步开放 Bug 单，待人工裁定；本单按标题口径只覆盖文档右键「讨论」轻量菜单。

# BUG-20260928-004 发布界面布局优化

- 状态：以看板机器记录为准，本文不维护状态。
- 归属：独立 Bug（引入来源见 design.md）
- 创建：2026-09-28T00:25:09.780Z

## 现象

用户诉求（原话概括）：「动作二 · 官网资料更新」采用折叠布局，官网提示词默认折叠，且改为可选。

本轮源码核实（`scripts/web/build.js`、`scripts/server.mjs`、`scripts/lib/publish-flow.mjs`）：

- 入口路径：构建模块 →「版本计划」页签 → 选中版本 → 右侧五步导航（`STEP_LABEL`：选择条目与提交 → 挑选合并 → 文档与翻译 → 文档合并 → 发布）→ 第 5 步「发布」（`renderReleaseFlowPane`，REQ-20260926-002 两动作布局：动作一 · 推送远端 + 动作二 · 官网资料更新）。
- 「动作二 · 官网资料更新」当前渲染顺序：说明文案 → **官网提示词文本框**（`<textarea class="bld-site-prompt" rows="7" readonly>`，常驻完全展开，无折叠）→「复制官网提示词」按钮 → 官网同步状态标签 +「立即检测」→ 检测证据 / 原因 / 时间行 → 底部口径说明。
- 提示词由服务端在**已配置官网仓库根目录**时才构建（`scripts/server.mjs` `/api/build/publish-plan`：`config.homepageRepoRoot` 非空才调 `flow.buildSiteWritingPrompt`），全文约十行（角色说明 + 项目仓库 / 基准 / 计划号 + 四条要求，`scripts/lib/publish-flow.mjs` `buildSiteWritingPrompt`）；`rows="7"` 固定高度使这块只读长文本**常驻占据发布步大块纵向空间**。
- 直接后果：官网同步状态标签（等待官网同步 / 已检测到官网同步等五种）、「立即检测」按钮与检测证据被长提示词推到折叠线以下，「发布」步纵向被拉长；提示词只在首次复制时需要查看，平时属低频只读内容。
- **同类提示词已有折叠先例而本处未随同收敛**：REQ-20260921-007 已把「文档与翻译」步的「AI 总结提示词」「AI 翻译提示词」改为 `<details class="bld-docs-prompt-box">` 默认折叠（摘要行说明已复制与回执口径，需要查看全文再展开，避免长提示词常驻占据大块空间；样式 `scripts/web/style.css` `.bld-docs-prompt-box`）。官网提示词与其同型（长提示词 + 复制按钮 + 回执口径），但仍是常驻展开，两处呈现口径不一致。

实际受影响安装版本与浏览器：待确认（用户未附截图与环境信息；现象为源码可见的布局问题，不依赖特定环境）。

## 复现步骤

前置：项目已初始化；在「设置」中配置官网仓库根目录（未配置时动作二只显示未配置提示，不渲染提示词，无法复现本现象）；无需真实推送或官网同步。

1. 打开「构建 → 版本计划」页签，选中任一版本计划，进入右侧五步导航第 5 步「发布」。
2. 查看「动作二 · 官网资料更新」：官网提示词文本框（只读、约 7 行高、含完整提示词全文）**默认完全展开常驻**，其下依次才是「复制官网提示词」按钮、官网同步状态标签与「立即检测」。
3. 对比同屏纵向长度：因提示词常驻展开，「动作一 · 推送远端」+ 展开的提示词 + 按钮与状态行整页被拉长；官网同步状态与「立即检测」需滚动或下移视线才可达。
4. 切到第 3 步「文档与翻译」，点击「AI 总结」触发生成后观察：「AI 总结提示词」为**默认折叠**的摘要行（REQ-20260921-007 口径，需点击才展开全文）——与第 2 步官网提示词常驻展开形成同型不同口径。
5. 刷新页面或重新进入「发布」步：官网提示词仍默认展开（既无折叠布局，也无默认收起）。

（第 2 / 5 步可对照 `scripts/web/build.js` `renderReleaseFlowPane` 的 `bld-site-prompt` textarea 与第 4 步 `bld-docs-prompt-box` details 核验。）

## 期望行为

- 「动作二 · 官网资料更新」区域采用**折叠布局**：官网提示词默认折叠（收起），只保留一行摘要 / 入口（含可展开标识与用途、复制口径说明），不再以 7 行只读文本框常驻占据发布步空间。
- 查看提示词全文**改为可选（按需展开）**，与 REQ-20260921-007「AI 总结 / AI 翻译提示词」同口径：需要查看全文再展开，展开后提示词全文与「复制官网提示词」按钮可达。
- 折叠布局只收敛呈现形态，不删能力：复制行为与回执反馈不变（成功 toast「✓ 官网提示词已复制：请切换到官网仓库会话粘贴执行（提交消息须含完整计划号）」、剪贴板不可用降级提示不变）；官网同步状态标签、「立即检测」、检测证据 / 时间行与底部口径说明全部保留且在收起状态下同屏可达（不再被长提示词推挤）。
- 展开为临时查看，刷新 / 重新进入「发布」步仍默认折叠（是否记忆展开状态：待确认，默认不记忆）。
- 未配置官网仓库时维持现状：显示「未配置官网仓库：先在设置中配置官网仓库根目录。」，不渲染提示词折叠区。
- 涉及文案增改（摘要行等）在 `scripts/web/i18n.js` 同步中英文（BUG-20260912-001）。
- 不改提示词内容本身（`buildSiteWritingPrompt` 输出不变）、不改官网同步检测逻辑与推送门禁——本 Bug 仅布局收敛。
- 「且改为可选」若另有所指（如「官网资料更新」整步设为可选 / 可跳过）：**待确认**，本 README 以上述「查看全文可选（按需展开）」口径编写；如人工确认为其他口径，期望行为以确认结论为准。

## 验收说明

1. 已配置官网仓库时进入「发布」步：官网提示词默认收起，仅显示摘要行（含展开标识）；不出现 7 行只读文本框常驻展开。
2. 点击摘要行可展开查看提示词全文，展开后「复制官网提示词」按钮可达；点击复制出现成功 toast（文案与现状一致），剪贴板不可用时出现降级提示。
3. 收起状态下，官网同步状态标签与「立即检测」同屏可达；五种检测状态（等待官网同步 / 扫描中 / 未命中（可继续检测）/ 已检测到官网同步 / 读取失败）展示与现状一致，不受折叠影响。
4. 刷新或重新进入「发布」步后提示词仍默认折叠。
5. 未配置官网仓库：仍显示「未配置官网仓库：先在设置中配置官网仓库根目录。」，不渲染提示词折叠区。
6. 「动作一 · 推送远端」区不受影响：推送状态文案、目标远端选择、推送按钮与禁用原因均与现状一致。
7. 折叠布局不改变能力：提示词内容（`buildSiteWritingPrompt` 输出）、复制链路、官网同步检测逻辑、推送门禁均不变。
8. 新增 / 调整文案在 `scripts/web/i18n.js` 有对应英文翻译，i18n 相关测试通过。
9. 「改为可选」的其他可能口径（官网资料更新整步可选）确认后如有额外验收项，随确认结论补充。

## 界面展示

涉及 UI：发布步（五步导航第 5 步）「动作二 · 官网资料更新」区域的布局呈现。可交互演示见 [./ui-demo.html](./ui-demo.html)（单文件、无外网依赖，浏览器直接打开）：

- **界面布局**：复刻「构建 → 版本计划」右侧详情——五步导航（发布步激活）+「动作一 · 推送远端」+「动作二 · 官网资料更新」（说明文案、提示词区、复制按钮、同步状态标签与「立即检测」、检测证据、时间行、口径说明）；顶部提供「缺陷态（现状）/ 期望态（折叠后）」对照开关。
- **交互行为**：缺陷态下提示词 7 行只读文本框常驻展开（不可折叠）；期望态下提示词默认收起为一行摘要，点击可展开全文与「复制官网提示词」按钮（复制为演示反馈，不写剪贴板）；「立即检测」模拟扫描中 → 结果状态流转；「推送主分支」模拟未推送 → 推送中… → 已推送（演示不执行真实推送）；展开状态在切换视图 / 状态后仍保持默认折叠口径。
- **状态反馈**：覆盖未推送 / 已推送、官网同步五态（等待 / 扫描中 / 未命中 / 已检测到 / 读取失败，含命中证据与失败原因行）、未配置官网仓库、发布状态加载中与读取失败（含重试）各态的状态标签与文案反馈；支持深浅色切换。全部为内存演示数据，不调用真实接口。

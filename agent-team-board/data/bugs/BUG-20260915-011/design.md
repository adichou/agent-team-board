# 设计 — BUG-20260915-011 需求模块的当前选择条目和右侧的条目没有同步，请修复

> 由 Agent 在 /dev 开发前补充，人可随时批注。

## 引入来源（源单）

本 Bug 由哪个需求 / Bug 引入？登记时可暂空或写「未定位」，修复阶段必须归因（三选一，禁止编造）：

- 引入来源：REQ-20260907-004（经 `atb list` 核验存在：看板整体布局优化——统一导航、三类新建入口与列表工作区）

归因依据：仓库初始提交为覆盖数百个单号的巨型合并提交，git 无法按单号区分。`openDrawer` 的
`state.listSig = ''`（重算行选中态注释）、`reqRowEl` 的 `picked` 机制与 `renderBoard` 的
内容签名增量渲染（签名含 `state.drawer.id`）均由 REQ-20260907-004 引入（app.js 内注释
「REQ-20260907-004：宽屏列表与详情并排」「REQ-20260907-004：列表行按内容签名增量更新」）；
该需求落地时打开路径只清签名未触发重绘，选中态依赖轮询顺带纠正，缺陷自始存在。

## 根因分析

- 左侧行选中态只在 `renderBoard()` 重建列表 DOM 时按 `state.drawer.id === it.id` 重算
  （`reqRowEl()`）；`renderBoard()` 内有内容签名剪枝（`sig !== state.listSig` 才重绘）。
- `openDrawer(id)` 更新 `state.drawer` 后写了 `state.listSig = ''`（意图「重算行选中态」），
  但其后只调用 `refreshDrawer()`（仅渲染右侧抽屉），从未调用 `renderBoard()`——签名被清空
  却无人消费，左侧行选中态无人重算。
- 高亮滞留窗口 = 到下一次「`/api/board` 载荷变化触发 `poll()` 重绘」为止：数据稳态时
  2 秒轮询的载荷比较（排除 `generatedAt` 后 `j !== state.boardJson`）永不成立，
  `renderBoard()` 不执行，不同步长期保持；任何条目数据一变，下一次轮询顺带重绘纠正
  ——与「有时过一两秒自己好了」的现象一致。
- 对照：`closeDrawer()` 在关闭时显式调用 `renderBoard()`（带 `state.board?.initialized`
  守卫）重算行选中态，关闭路径无此问题——仅打开/切换路径缺失同步。

## 方案

**开源选型（REQ-20260909-015）**：不引入开源库。纯前端既有状态同步缺陷修复——单点补齐
「状态变化后重算视图」的调用，无对应可复用的开源库场景（无新增状态管理/数据流需求），
引入任何库的成本都高于本一行调用。

修复口径：对齐 `closeDrawer` 的显式重算做法——`openDrawer` 在重置 `state.listSig` 之后、
`await refreshDrawer()` 之前，增加 `if (state.board?.initialized) renderBoard();`：

- 所有打开/切换详情入口（点行、抽屉「上一条/下一条」按钮、键盘 ←/→、搜索反馈条跳转、
  跨模块 `gotoItem` 类入口）均汇聚于 `openDrawer`，单点修复全覆盖；
- 同步执行（先于抽屉详情请求）：切换瞬间高亮即移动，不等待网络与轮询；
- 签名机制天然防抖：重绘仅在 `drawer.id` 变化（或 `listSig` 被重置）时发生一次，
  轮询期间的剪枝行为不变。

测试：新增 `scripts/tests/bug-drawer-picked-sync-20260915-011.test.mjs`（vm 模式控件级
stub，picked-row-hint-20260910-010 同法），6 用例覆盖点行/导航/跨模块/关闭/签名剪枝
不回退/静态契约（重算先于详情请求、初始化守卫、签名含 drawer.id）。

## 风险与边界

- 重绘时机提前到打开瞬间：列表 DOM 节点被替换一次。既有签名剪枝保证同一稳态下不再重复
  重绘（T5 用例断言重绘次数），行内点击/勾选不被轮询打断的口径不变。
- `state.board?.initialized` 守卫与 `closeDrawer` 一致：未初始化项目不渲染（openDrawer
  在未初始化时本就无列表可言）。
- 窄屏（≤1020px）覆盖式抽屉：列表在抽屉下方不可见，重算无可见影响；返回列表后高亮与
  抽屉状态一致（同一路径）。
- 抽屉详情加载失败路径不变：失败仍走 `closeDrawer()` 自动关闭，高亮随之清除。

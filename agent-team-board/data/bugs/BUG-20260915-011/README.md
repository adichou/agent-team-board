# BUG-20260915-011 需求模块的当前选择条目和右侧的条目没有同步，请修复

- 状态：submitted（待人工接受）
- 归属：独立 Bug（引入来源见 design.md）
- 创建：2026-09-15T07:33:13.767Z

## 现象

需求模块（「需求」页签）宽屏为左右分栏：左侧条目列表（`#reqList`），右侧详情抽屉（`#drawer`）。左侧当前被选中（`picked`）的行有明确选中态——边框加深 + 左缘 3px 竖条，悬停提示「详情打开中（右侧抽屉正展示此条目）」。

切换详情后右侧立即更新、左侧选中态却不跟随：点击另一条目行，或用抽屉内「← 上一条 / 下一条 →」按钮与键盘 ←/→ 切换时，右侧抽屉内容即刻变为新条目，但左侧列表的选中高亮仍停留在上一次渲染时的旧条目上——旧条目仍显示「详情打开中」标记，新条目无高亮，两侧指向不同条目。

持续性有条件：看板数据处于稳态（`/api/board` 载荷无变化，无新建 / 流转 / 编辑，是最常见状态）时不同步会一直保持；一旦任何条目数据发生变化，下一次 ≤2 秒的轮询重绘会顺带把高亮纠正过来（表现为「有时过一两秒自己好了」的瞬时不同步）。

## 复现步骤

1. 启动看板 Web 前端（`node scripts/atb.mjs serve`，缺省 `http://127.0.0.1:8888`，可用 `--port` 覆盖），进入「需求」模块，确保同一筛选档内至少有 2 个条目（如「待接受」档两个单）。
2. 点击条目 A 的行：右侧抽屉显示 A 详情，左侧 A 行出现选中高亮——此步正常。
3. 再点击同档条目 B 的行：右侧抽屉立即切换为 B 的详情。
4. 观察左侧列表：选中高亮与「详情打开中」悬停提示仍停在 A 行，B 行无高亮——与右侧实际展示的 B 不一致。
5. 保持看板数据不变（不新建、不流转、不编辑任何条目）等待数秒：高亮仍不纠正；对任一条目做一次数据变化（如接受一个待接受单）后 ≤2 秒，高亮才自动跳到 B。
6. 换入口同样复现：抽屉内「← 上一条 / 下一条 →」按钮、键盘 ←/→（详情打开时）、搜索反馈条中的条目跳转按钮——右侧切换、左侧高亮滞留旧条目。
7. 对照：关闭抽屉（Esc / 返回）后高亮正确清空（关闭路径有显式重算），说明仅「打开 / 切换详情」路径缺失同步。

## 期望行为

- 左侧列表「当前选择」与右侧抽屉展示的条目始终一致：点行、抽屉上一条 / 下一条、键盘方向键、搜索命中跳转等一切打开或切换详情的入口，在切换发生的瞬间左侧 `picked` 高亮同步移动到新条目，原条目恢复普通样式。
- 同步不得依赖看板数据变化与轮询时序：数据稳态（`/api/board` 载荷无变化）下也必须立即一致。
- 既有机制不回退：列表按内容签名的增量重渲染（轮询不打断行内点击 / 勾选）、抽屉打开时的导航范围冻结（navIds）、关闭抽屉后的高亮清除（现状已正确）均保持不变。

## 验收说明

- 复现场景验证：数据稳态下 A → B 点行切换，右侧显示 B 的同时左侧 B 行立即带 `picked` 高亮、A 行高亮立即消失；抽屉「上一条 / 下一条」按钮与键盘 ←/→ 同样即时同步。
- 交叉入口验证：搜索反馈条跳转按钮、其他模块定位条目（`gotoItem` 类入口）打开详情后，列表高亮同样同步到目标条目。
- 不回退验证：轮询期间行内勾选 / 按钮点击不被列表重渲染打断（签名剪枝仍生效）；关闭抽屉高亮清除行为不变；窄屏（≤1020px）覆盖式抽屉返回列表后高亮状态正确。
- 建议自动化测试：vm 模式模拟「点行 B → 不等待轮询立即断言列表中 B 行含 `picked`、A 行不含」，覆盖 `openDrawer` 后左侧未重渲染的路径（现有列表渲染测试未覆盖选中态即时同步）。

## 界面展示

可交互演示：[./ui-demo.html](./ui-demo.html)（单文件 HTML，内联 CSS/JS，无外网依赖，无构建步骤，浏览器直接打开可交互；支持「缺陷（当前）↔ 修复后（期望）」一键对比、深浅色切换）。

- 界面布局：还原需求模块宽屏左右分栏——左侧为状态筛选条（待接受 / 已接受 / 已计划 / 已完成，带计数）+ 列表头工具栏（条目计数提示 + 全选 / 全不选图标位）+ 条目卡片行（单号、标题、认领者、更新时间；选中行带边框加深 + 左缘竖条，悬停提示「详情打开中（右侧抽屉正展示此条目）」同真实产品，不再显示可见「详情打开中」标签）；右侧为详情抽屉（单号 + 标题、状态、文档页签占位、操作说明区、「← 上一条 / 下一条 →」导航）。顶部为演示控制条：缺陷 / 修复模式切换、「模拟一次数据变化（触发轮询重绘）」按钮、「下一次打开模拟加载失败」开关、深浅色切换与重置；底部为事件流记录。
- 交互行为：点左侧任意条目行 → 右侧抽屉先短暂「加载中…」再显示该条目详情；抽屉内「上一条 / 下一条」与键盘 ←/→ 可切换详情；筛选条可切档（含已完成空档 → 列表空态 + 抽屉引导文案「选择左侧列表中的条目查看详情」）。缺陷模式下点行 / 导航切换后，左侧选中高亮停留在旧条目不动，直到点「模拟一次数据变化」才被轮询重绘顺带纠正；修复模式下高亮随切换即时移动。
- 状态反馈：正常态——左右一致，右侧附「已同步」绿色标注；缺陷态——左右指向不同条目，左侧旧条目旁出现红色「高亮滞留」标注、右侧附「未同步」红色标注与原因说明（openDrawer 未触发列表重渲染，稳态数据下轮询不重绘）；加载态——抽屉「加载中…」占位；失败态——开启「模拟加载失败」开关后打开条目，出现错误 toast 且抽屉自动关闭（还原真实失败路径 closeDrawer）；每次操作在事件流中记录模式 / 抽屉条目 / 左侧实际高亮 / 是否同步，便于核对。

## 初步定位（供开发参考，已验证）

- 左侧行选中态：`scripts/web/app.js` `reqRowEl()` 按 `state.drawer.id === it.id` 为行加 `picked` 类（约 1904 行），仅在 `renderBoard()` 重建列表 DOM 时生效；`renderBoard()` 内有 `sig !== state.listSig` 内容签名剪枝（约 2053 行），签名已包含 `state.drawer.id`。
- 缺陷机制：`openDrawer(id)`（约 4189 行）更新 `state.drawer` 后写了 `state.listSig = ''`（注释「重算行选中态」），但其后只调用 `refreshDrawer()`（仅渲染右侧抽屉，不触碰列表），未调用 `renderBoard()`——左侧行选中态无人重算。
- 纠正时机：`renderBoard()` 的常规触发点是 2 秒轮询 `poll()`（约 1813 行），且仅当 `/api/board` 载荷变化时才执行（约 1823–1828 行）——数据稳态时永不触发，高亮长期滞留；数据一变则下一次轮询顺带重绘纠正，与「有时过一会自己好了」的现象一致。
- 对照佐证：`closeDrawer()`（约 4204 行）在关闭时显式调用 `renderBoard()` 重算行选中态（约 4213 行），关闭路径无此问题——仅打开 / 切换路径缺失同步，修复口径可对齐关闭路径的做法。

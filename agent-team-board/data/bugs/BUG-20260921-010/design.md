# 设计 — BUG-20260921-010 刷新后，最近执行的命令看不见了，请修复。

> 由 Agent 在 /dev 开发前补充，人可随时批注。

## 引入来源（源单）

- 引入来源：REQ-20260920-004（`atb list` 核验真实存在；commit 12ac4ae 引入
  scripts/web/commands.js，「最近执行」recents 自始为模块级内存态，无持久化设计）。

## 根因分析

- `commands.js` 的 `state.recents`（最近执行：按命令去重前 10，含参数回填值）是
  模块级内存态；浏览器刷新后 JS 上下文整体重建，recents 归零，列表回到空态。
- 服务端无可恢复数据：`/api/cli/run-status` 仅存每项目单槽内存 job（源码注释明确
  「执行记录仅存内存（会话内口径）：服务重启即丢」），不保存按命令去重的最近执行清单。
- 相邻 Bug BUG-20260921-009 修的是 render() 漏调 renderRecent（页签往返/重进模块
  丢失），与本 Bug（刷新即丢、内存态无持久化）根因不同，本单不改变其修复口径。

## 方案

前端将 recents 持久化到 localStorage（与仓库既有记忆惯例同构：`atb.project` /
`atb.lang` / `atb.req.sort`）：

- key：`atb.cmd.recents:<项目根>`，按项目隔离（不同项目命令与参数互不串扰）；
- 写入：`withDone` 成功分支更新去重列表后落盘（结构 `{ name, vals, extra, at }`）；
- 恢复：`enter(project)` 在「项目与上次恢复口径不同」时加载（同会话重复进入不覆盖，
  兼容 localStorage 不可用的会话内降级数据，保 BUG-20260921-009 用例零回归）；
- 健壮性：读取逐项校验字段结构（name/vals/extra/at 类型），非法 JSON 或结构不对
  整单丢弃回退空态；localStorage 不可用（隐私模式等）或写入失败 try-catch 静默
  降级为会话内行为，不阻塞执行；
- 既有口径不变：按命令去重前 10、仅成功执行计入、回填点击链路维持原实现。

**开源选型（REQ-20260909-015）**：未引入开源库——需求仅为「localStorage 单键
JSON 读写 + 结构校验」（约 30 行），仓库已有同构惯例（app.js / i18n.js / splitter.js
均原生实现），无合适且必要引入的库；引入成本高于自研。

## 风险与边界

- 参数值含敏感信息的可能：与既有 `atb.project`（项目路径）记忆同级，且看板为本机
  开发工具，localStorage 同域可见面不变；如后续需要可再议脱敏。
- 存储容量：每项目最多 10 条短记录，远低于配额；写入失败静默降级不影响功能。
- 服务端不感知该持久化（纯浏览器本地记忆），多浏览器/多机器不同步——与「最近执行」
  定位（本机快捷重执行入口）一致。

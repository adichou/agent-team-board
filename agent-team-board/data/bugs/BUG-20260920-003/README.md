# BUG-20260920-003 AI 分析进入待人工确认分析去人后，进入续跑状态，需要自动复制续跑提示词，并提示用户到 AI Agent 中进行续跑操作

- 状态：submitted（待人工接受）
- 归属：独立 Bug（引入来源见 design.md）
- 创建：2026-09-20T12:58:44.710Z

## 现象说明

AI 分析因待人工确认而暂停，人工补齐答案并点击「确认并继续」后，看板显示已确认续跑，但没有自动复制续跑提示词，也未明确告知用户必须回到 AI Agent 会话粘贴发送，容易误以为分析已经自动执行。

代码核实：`scripts/web/app.js` 分析确认成功分支只显示「已确认，正在继续当前条目分析」并刷新；`scripts/server.mjs` 调用 `resumeAfterAnalysisConfirm`；`scripts/lib/refine-store.mjs` 负责旧运行收尾、当前条目重排队首和解除暂停，并不在此处启动外部 Agent。批量完善面板已有同批次提示词及「重新复制」能力，可作为续跑提示词的现有来源。真实浏览器复现环境、浏览器版本及引入源单待确认；上述为代码核实，不冒充现场测试。

范围限 AI 分析的人工确认续跑闭环；不改变 AI 开发确认、条目业务状态、人工答案保存和队列优先级。不要求自动打开、自动发送消息或新建 Agent 会话。

## 复现步骤

1. 在当前项目启动 AI 分析，并由 worker 通过 `refine hold` 提交必答问题，使队列进入待人工确认分析。
2. 在看板打开对应确认面板，补齐必答答案，点击「确认并继续」。
3. 等待确认成功，观察反馈及剪贴板内容。
4. 当前代码仅提示已确认、正在继续；未执行续跑提示词复制，且缺少「到当前项目 AI Agent 会话粘贴发送」的操作引导。

## 期望行为

- 人工确认成功且当前条目已成功进入续跑队列后，自动尝试复制**当前项目、当前分析批次**的完整调度提示词。沿用现有提示词生成口径及模型/推理档位继承规则，不拼凑另一份简化指令、不创建新批次。答案仍由续跑领取结果回传。
- 复制成功后，在确认面板给出持续可见反馈：「已确认并加入续跑队列。续跑提示词已复制，请到当前项目的 AI Agent 调度会话粘贴并发送，继续当前条目分析。」反馈含条目编号和项目路径，避免误贴到其他项目。
- 区分「已进入续跑队列」与「Agent 已开始执行」；确认/复制成功不作为已启动外部 Agent 的证据。
- 复制失败时，保持已成功确认和排队的结果，明确「续跑提示词复制失败」，显示完整可选择文本与「重新复制」按钮；允许手动复制。不重复提交确认、不回滚答案、不新建任务。
- 获取失败或提示词为空时，不复制空文本、不显示复制成功；显示「重新获取」操作及原因。重新获取成功后可复制，同样不重复确认。
- 确认失败（未答齐、版本过期、续跑排队失败等）不触发提示词复制，展示服务端原因及相应重试引导。保存草稿、保持挂起不触发续跑复制。
- 提交和复制进行中禁用重复触发；普通轮询、刷新或重新打开已确认面板不自动覆盖剪贴板，提供显式重新复制入口。
- 新增文案按项目规范同步中文和英文。

## 界面展示

[打开可交互演示](./ui-demo.html)。演示为独立静态交互，不连接真实队列；「实际复制」仅在明确点击时尝试系统剪贴板。

布局：确认侧栏内保留条目编号、项目、问题与答案、底部确认按钮；确认成功后在原侧栏展示续跑提示卡，包含排队结果、复制结果、去 AI Agent 粘贴发送的引导、完整提示词文本及重试入口。

交互：可切换缺陷现象/期望修复、正常/提示词空/加载/复制失败/获取失败/确认失败；点击确认体验复制反馈，点击重新复制或重新获取体验恢复，清空必答答案可查看前置校验。缺陷模式对照原有误导提示。

状态反馈：正常成功明确下一步人工操作；加载态禁用重复提交；空态和获取失败有重试；复制失败保留已确认结果并提供手动选择文本；确认失败保留答案，不误报已复制或已续跑。

## 验收说明

1. 必答齐备且确认与排队成功时，仅自动复制一次与当前项目/批次匹配的完整提示词，持续显示粘贴发送引导；确认不宣称外部 Agent 已运行。
2. 用户粘贴发送后，续跑优先领取当前条目并获得已确认答案；当前条目完成前不越过它处理后续条目。
3. 剪贴板拒绝、接口异常和空提示词分别得到准确反馈，能重新复制/重新获取或手动选择文本；重试不重复确认、不创建批次、不丢失答案。
4. 必答未齐、版本过期及确认/排队失败均不复制；草稿和保持挂起行为不变。
5. 连续点击、轮询和面板重开不会重复确认或无操作覆盖剪贴板；显式重新复制仍可使用。
6. 中英文均有对应提示；项目路径及条目编号可见，长提示词可滚动选择，不遮挡主要操作。
7. 本条仅完善说明与演示，修复方案、引入来源归因和真实实现测试留待开发阶段。

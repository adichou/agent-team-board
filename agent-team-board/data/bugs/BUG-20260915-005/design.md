# 设计 — BUG-20260915-005 挂起确认面板「保持挂起/重新核验/确认并继续」按钮缺少使用场景说明

> 由 Agent 在 /dev 开发前补充，人可随时批注。

## 引入来源（源单）

- 引入来源：REQ-20260914-001（引入「挂起确认」人工闭环：任务页面板与其三按钮「保持挂起 / 重新核验 / 确认并继续」均为该需求交付物）

## 根因分析

`scripts/web/app.js` 挂起确认面板（develop 侧 `renderConfirmForm`）底部按钮仅输出按钮文案，未携带 `title`/`aria-label`，也未提供按钮级说明；顶部 scope 文案只覆盖「确认并继续」一条路径的整体流程，未区分三按钮语义。属交付时缺少可发现性（discoverability）设计，非逻辑错误。

## 方案

**开源选型（REQ-20260909-015）**：纯自研 title/文案增强，无外部依赖诉求（无合适库：原生 tooltip 即可满足，不引入浮层库）。

方向（开发阶段细化并补测试）：

1. develop 侧三按钮各加 `title` 与 `aria-label`：保持挂起=「暂不处理，维持挂起与队列暂停，说明留档」；重新核验=「只重查不提交：重核提交状态并跑测试，终端已自行补交后用它刷新结论」；确认并继续=「授权补交剩余路径+复验+恢复队列」。
2. 按钮区上方加一行紧凑对照说明（`muted small` 样式），不悬停也可读。
3. 分析侧面板（hold 问题「保持挂起/保存草稿/确认并继续」）同口径统一。
4. 全部文案进 `scripts/web/i18n.js` 双语表；面板截图/说明同步 README（如需）。

## 风险与边界

- 文案不改变按钮行为与闭环语义，仅可读性增强；
- 注意面板宽度（移动端/窄窗口）下说明行不破版。

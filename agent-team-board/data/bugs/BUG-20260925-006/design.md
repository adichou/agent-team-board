# 设计 — BUG-20260925-006 文档编写的审查界面要删除编辑功能。

> 由 Agent 在 /dev 开发前补充，人可随时批注。

## 引入来源（源单）

- 引入来源：REQ-20260921-008（经 `atb list` 核验存在，状态 done）——该需求为审查对话框
  （`renderReviewModal`）引入逐栏「编辑 / 预览切换 + 保存」能力（`data-review-mode` /
  `data-review-save` → `saveReviewFile` 走 `/api/build/docs/save` 白名单通道，
  `approveReviewFile` 含「未保存草稿先保存再审核」过渡）。REQ-20260924-006 引入「② 二次
  编辑」专用弹窗后，审查侧编辑能力与之职责重叠，成为本缺陷的暴露点。

## 根因分析

REQ-20260921-008 设计时审查对话框身兼「编辑 + 多语言对照核对 + 逐文件审核」三职责；
REQ-20260924-006 将文档编写固化为五步流程（① AI 总结 → ② 二次编辑 → ③ AI 校对 →
④ AI 翻译 → ⑤ 提交），编辑职责由专用弹窗（`openSecondaryEdit`，默认语言单语言、含
未保存保护）承接，但旧对话框的编辑能力未随之下线，导致：

1. 同一页面两个编辑入口并存，审查环节可被「改完顺手通过审核」绕过（未经 ③ 校对 /
   ④ 翻译基准约束）；
2. 已审核文件在审查对话框被再编辑保存会静默回退待审核，与 ② 二次编辑的回退提示口径
   并存，状态反馈来源不唯一；
3. 「编辑」按钮对非默认语言文件同样可用——直接手改译文绕开「翻译以已审核默认语言为
   基准」的流程约束（基准变更检测只覆盖默认语言变化）。

## 方案

**开源选型（REQ-20260909-015）**：本单为纯前端既有代码删改，无新增能力，不引入开源库
（无合适库的原因：不涉及新功能，仅收敛 UI 职责），不创建 licenses.md。

### 实施要点（`scripts/web/build.js`）

1. **审查对话框只读化**（`renderReviewModal`）：删除每栏「编辑 | 预览」切换（`data-review-mode`）、
   「保存」按钮（`data-review-save`）与编辑态 `<textarea class="bld-review-editor">`；栏内容恒为
   预览态（读取中 / 空文档「（空文档）」占位 / Markdown 富文本渲染，口径不变）；栏头操作仅保留
   「通过审核」；类型页签（四类 + LICENSE 不分语言 + 自定义文档）、状态徽标、页脚「本页签 / 全部」
   计数、各栏按比例同步滚动全部保留（`bindReviewSyncScroll` 选择器随 textarea 移除收敛为
   `.bld-review-preview`）。已审核态按钮禁用提示由「已审核：编辑保存后才会回退待审核」改为
   「已审核：内容再变化会自动回退待审核」（对齐服务端读盘比对回退的真实口径）。
2. **通过审核直取磁盘基准**（`approveReviewFile`）：删除「未保存草稿先保存再审核」的读盘比对
   GET 与 `saveReviewFile` 过渡（对话框已无草稿，审核基准恒为磁盘内容，行为等价）；服务端
   「内容再变化自动回退待审核」（每次求值读盘比对）口径不动、不弱化。
3. **死代码路径全量清理**：`syncReviewDrafts` / `saveReviewFile` / `focusReviewIssue` /
   `pf.review.modes` / `pf.review.pendingFocus` / `data-review-mode`·`data-review-save` 事件绑定 /
   `ATBBuild` 接缝导出（`saveReviewFile`、`focusReviewIssue`）全部移除；调用点（`render()`、
   `closeReview`、`switchReviewTab`、`refreshDocsPane`、`applyDocLangs`）同步清理；
   `style.css` 中 `.bld-review-editor` 联动选择器清理（`.bld-edit-editor` 保留）。
4. **i18n 中英同步**（`scripts/web/i18n.js`）：审查按钮 title 由「…逐文件编辑 / 保存 / 通过审核」
   改为「…逐文件通过审核（只读核对，编辑走「② 二次编辑」）」；已审核禁用提示键替换；EN 同步。

### 待确认三条的结论（README「待确认」逐项落实）

1. **非默认语言文件的人工修正入口**：结论 = **仅允许经 ④ AI 翻译重新覆盖**。依据：期望行为 4
   明确「② 二次编辑」弹窗保持默认语言范围不变（成为唯一编辑入口）；非默认语言文件是 ④ 的
   产物，其修正入口 = 重新运行「④ AI 翻译」（以已审核默认语言为基准整体覆盖）——入口不缺失
   （④ 按钮可重跑），且不引入绕过翻译基准检测的手改通道；不扩展 ② 至全语言（避免与
   REQ-20260924-006 五步分工冲突、不扩大本单范围）。
2. **「✎ 修改」跳转落点与弹层关系**：结论 = 按缺省建议**改跳「② 二次编辑」弹窗并定位该行**
   （`editFromProofread` → `openSecondaryEdit({ file, line })` → `focusEditIssue` 行选区定位），
   AI 校对只覆盖默认语言文件，与该弹窗范围一致；弹层关系沿用一次一层——先关整体审查完结
   对话框（确认完结 busy 中不让位），再开编辑弹窗（`openSecondaryEdit` 内 `render()` 全量重建
   自然移除完结对话框 DOM）。
3. **既有测试断言更新与新增回归**：更新 7 个既有测试文件相关断言
   （`req-20260921-008` / `req-20260921-011` / `req-20260922-002` / `req-20260922-003` /
   `bug-20260922-002` 的渲染契约，`req-20260924-004` 的行为块，`bug-20260925-004` 的
   closeReview），并**新增** `bug-20260925-006.test.mjs`「审查无编辑入口」回归（只读契约 /
   行为 / 死代码移除 / i18n 四层 10 例）。

## 风险与边界

- 「通过审核」删除草稿保存过渡后语义不变（基准恒为磁盘内容）；已审核文件改动回退待审核的
  入径唯一化为「② 二次编辑保存」，反馈来源唯一。
- 整体审查对话框、提交门禁、四态求值、自动检查、AI 校对 / AI 翻译流程均不动（不弱化、不新增
  门禁）。
- 接缝移除（`ATBBuild.saveReviewFile` / `focusReviewIssue`）仅影响测试与内部调用，页面无其他
  引用；行定位职责由 `focusEditIssue`（BUG-20260925-005 口径）承接。
- 非默认语言修正收敛为重跑 ④ 覆盖后，若默认语言未审或有未处理校对建议，④ 门禁按既有口径
  拦截——这是流程约束而非入口缺失。

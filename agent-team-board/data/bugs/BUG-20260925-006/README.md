# BUG-20260925-006 文档编写的审查界面要删除编辑功能。

- 状态：以看板实时状态为准（本文件不维护业务状态）
- 归属：独立 Bug（引入来源归因见 design.md，开发阶段补全；初步指向 REQ-20260921-008 引入的审查对话框逐栏编辑能力）
- 关联：REQ-20260921-008（审查对话框随三段式流水线引入「编辑 / 预览切换 + 保存」）；REQ-20260924-006（五步流程以「② 二次编辑」弹窗承接编辑职责，进行中）；REQ-20260924-004（整体审查 AI 校对「✎ 修改」现跳审查对话框编辑态，受本单影响）
- 创建：2026-09-25T08:03:02.689Z

## 现象

发布模块「文档编写」步中，点击辅助操作行的「审查」按钮打开审查对话框（`scripts/web/build.js` 的 `renderReviewModal`）。该对话框按文档类型分页签（README / CHANGELOG / FEATURES / AGENTS 四类 + LICENSE 单文件类 + 自定义文档），页签内各语言栏并排、同步滚动，本应承担**多语言对照核对与逐文件通过审核**的职责；但现状每栏头部仍保留了完整的编辑能力：

- 每栏有独立的「编辑 | 预览」模式切换（`data-review-mode`），切「编辑」后该栏变为可输入的 `<textarea class="bld-review-editor">`；
- 每栏有「保存」按钮（`data-review-save` → `saveReviewFile`，走 `/api/build/docs/save` 白名单通道）；对已审核文件编辑保存后会回退「已总结待审核」（LICENSE 回退「待审核」）；
- 「通过审核」前若存在未保存草稿，`approveReviewFile` 会先自动保存草稿再记录审核基准（审核基准 = 磁盘内容）。

而 REQ-20260924-006 起，文档编写主流程已按「① AI 总结 → ② 二次编辑 → ③ AI 校对 → ④ AI 翻译 → ⑤ 提交」组织，**编辑职责已由「② 二次编辑」专用弹窗（`openSecondaryEdit` / `renderSecondaryEditModal`，默认语言单语言，含文件切换 / 刷新 / 编辑 / 预览 / 保存 / 未保存保护）承接**。审查对话框内的编辑能力与之职责重叠，形成同一页面两个编辑入口：

1. 用户在「审查」里也能改正文，编辑与核对两种意图混在同一个界面，「审查」环节可被绕过（改完顺手通过审核，未经 ③ 校对 / ④ 翻译基准约束）；
2. 已审核文件在审查对话框里被再编辑会静默回退待审核，与 ② 二次编辑的回退提示口径并存，状态反馈来源不唯一；
3. 每栏头部同时摆「编辑 | 预览」「保存」「通过审核」三组操作，栏头拥挤，且「编辑」按钮对本应由 ④ AI 翻译产出的非默认语言文件同样可用——直接手改译文会绕开「翻译以已审核默认语言为基准」的流程约束（基准变更检测只覆盖默认语言变化）。

「审查」按钮的悬浮提示文案（「逐文件编辑 / 保存 / 通过审核」）同样在宣传该编辑入口。

## 复现步骤

1. 启动状态板服务（`node <插件>/scripts/server.mjs`），浏览器打开 `http://127.0.0.1:8888`，选择一个存在发布版本（「文档编写」步，phase 为 ready）的项目并进入该版本的「文档编写」页签。
2. 点击辅助操作行「审查」按钮，打开审查对话框。
3. 观察任一页签（如 README）：每个语言栏头部均有「编辑 | 预览」切换与「保存」按钮——审查界面提供完整编辑入口（缺陷现象）。
4. 点击某栏「编辑」：该栏变为可输入的文本框；修改内容后点「保存」：toast 提示已保存，文件写盘；若该文件原为「已审核」，状态回退「已总结待审核」（或 LICENSE 的「待审核」）。
5. 对照：同一页签上方五步条中的「② 二次编辑」按钮打开的弹窗同样能编辑默认语言文件——两个编辑入口并存。
6. 鼠标悬停「审查」按钮：title 文案含「逐文件编辑 / 保存 / 通过审核」。

## 期望行为

审查对话框收敛为**只读核对 + 通过审核**，删除其编辑功能；文档编辑一律走「② 二次编辑」弹窗：

1. 各栏不再提供「编辑 / 预览」切换与「保存」按钮，也不再有可输入的 textarea；栏内容恒为预览态（Markdown 渲染富文本，空文档显示占位，读取中 / 读取失败反馈不变）。
2. 每栏头部操作仅保留「通过审核」（已审核态按钮禁用 + 提示的现状口径不变）；类型页签、各语言栏并排、同步滚动、页脚计数（本页签 x/y · 全部 a/b 已审核）与文件状态徽标等核对能力全部保留。
3. 「通过审核」直接以磁盘内容为审核基准记录；既有「内容再变化自动回退待审核」的检测口径（每次求值读盘比对）不弱化。
4. 「② 二次编辑」弹窗的编辑能力与未保存保护不变，成为唯一的文档编辑入口（默认语言）；「审查」按钮 title 等文案同步去掉「编辑 / 保存」表述，i18n 中英同步。
5. 相关联动入口改指向编辑弹窗：整体审查对话框 AI 校对问题行的「✎ 修改」（`editFromProofread`，现状跳审查对话框编辑态并定位行）应改跳「② 二次编辑」弹窗并定位该行（`openSecondaryEdit` 已支持 `{ file, line }` 定位，且 AI 校对只覆盖默认语言文件，与该弹窗范围一致）；具体落点以 design.md 定稿为准。
6. 随编辑入口一并清理其专属死代码路径（如 `rv.modes` 编辑态、`syncReviewDrafts`、`saveReviewFile`、`focusReviewIssue` 的审查侧定位等是否保留 / 移除由开发阶段定），不得留下不可达的 UI 或状态。

### 待确认（修复阶段须给出结论，不得无入口或静默降级）

- **非默认语言文件的人工修正入口**：「② 二次编辑」弹窗只列默认语言文件，删除审查对话框编辑后，其余语言（AI 翻译产物）若需人工修正将没有任何界面入口。是「仅允许重新 ④ AI 翻译覆盖」还是「扩展 ② 二次编辑支持全部语言」**待确认**。
- 「✎ 修改」跳转落点（建议改跳 ② 二次编辑弹窗，见期望行为 5）与弹层关系（先关整体审查对话框再开，沿用一次一层）**待确认**（design.md 定稿）。
- 既有针对审查对话框编辑 / 保存控件的测试断言（`scripts/tests/req-20260921-008.test.mjs`、`req-20260921-011.test.mjs`、`req-20260922-002.test.mjs`、`req-20260922-003.test.mjs`、`bug-20260922-002.test.mjs` 等）随新口径更新，是否需要新增「审查无编辑入口」回归断言由开发阶段定。

## 验收说明

1. 打开审查对话框：任何页签、任何语言栏均无「编辑」/「预览」切换按钮、无「保存」按钮、无可输入文本框；栏内容恒为 Markdown 预览（含空文档「（空文档）」占位）。
2. 每栏可独立「通过审核」：通过后该栏状态徽标变「已审核」、按钮禁用（title 提示），页签计数与页脚「本页签 / 全部」计数即时更新；整体审查、提交门禁口径与现状一致（不弱化、不新增门禁）。
3. 各栏同步滚动、类型页签（含 LICENSE「不分语言」与自定义文档页签）切换、读取中 / 读取失败反馈（toast + 重试路径）与现状一致。
4. 「② 二次编辑」弹窗行为不变：文件切换 / 刷新 / 编辑 / 预览 / 保存 / 未保存三动作保护（保存并继续 / 放弃 / 留下）均可用；在弹窗中修改保存后，已审核文件回退待审核的既有口径不变。
5. 整体审查对话框 AI 校对问题行「✎ 修改」可直达编辑并按行号定位（落点按 design.md 定稿实现，缺省建议为 ② 二次编辑弹窗）；修改保存 → 回退待审核 → 重新通过审核的链路闭环可用。
6. 「审查」按钮 title 及相关界面文案不再含「编辑 / 保存」表述；如新增 / 改动文案，`scripts/web/i18n.js` 中英同步且 i18n 测试通过。
7. 「待确认」三条在 design.md 中有明确结论并落实；非默认语言人工修正不得无入口且不得静默绕过翻译基准检测。
8. `npm test` 全量通过（含上述被更新断言的既有测试文件与其余文档编写相关回归）。

## 界面展示

### 布局

「文档编写」页签上部为语言集输入 + 辅助操作（刷新 / 审查 / 整体审查）+ 五步操作条（① AI 总结 → ② 二次编辑 → ③ AI 校对 → ④ AI 翻译 → ⑤ 提交）。审查对话框（点「审查」弹出，居中 modal）自上而下：

1. 对话框头：标题「审查发布文档（<版本号>）」+「✕ 关闭」。
2. 类型页签行：README（1/2）/ CHANGELOG / FEATURES / AGENTS / LICENSE（不分语言）/ 自定义文档页签，页签名后附「已审核数 / 文件数」。
3. 各语言栏并排（栅格列数 = 语言数）：栏头为「文件名（语言）+ 状态徽标 + 操作区」；栏体为 Markdown 预览，各栏按比例同步滚动。
4. 页脚：全部 x/y 已审核 · 本页签 a/b 已审核 · 同步滚动说明 +「关闭」。

缺陷态（修复前）栏头操作区含「编辑 | 预览」切换、「保存」、「通过审核」三组；修复后仅保留「通过审核」。

### 交互

- 页签切换加载该类型各语言文件；栏内滚动其余栏按比例跟随。
- 通过审核：该栏状态变「已审核」、按钮禁用，计数即时刷新；已审核文件外部或经 ② 二次编辑改动后回退待审核（磁盘基准比对）。
- 编辑（缺陷态演示）：切「编辑」出 textarea，改后「保存」写盘；已审核文件被编辑保存即回退「已总结待审核」（LICENSE「待审核」）——修复后此路径不存在，编辑一律走「② 二次编辑」弹窗（默认语言文件下拉 + 编辑 / 预览 + 保存 / 关闭 + 未保存保护）。
- 整体审查 AI 校对「✎ 修改」直达编辑并定位问题行（修复后落点为 ② 二次编辑弹窗）。

### 状态反馈

- 正常：各栏 Markdown 预览 + 状态徽标（未总结 / 已总结待审核 / 已审核等）+ 计数。
- 加载：栏体显示「正在读取文档内容…」，操作不可用。
- 失败：toast 报错（文件读取失败），失败栏不渲染空白冒充内容。
- 空态：空文档显示「（空文档）」占位，不渲染空白区。
- 回退：已审核文件内容再变化，状态回退待审核并有明确反馈。

可交互演示见 [./ui-demo.html](./ui-demo.html)：单文件、内联 CSS/JS、无外网依赖、浏览器直接打开（数据与提交均为模拟）。顶部「演示控制台」可切换**修复前（缺陷：审查对话框各栏可编辑 / 保存，与 ② 二次编辑入口并存）**与**修复后（期望：审查只读核对 + 通过审核，编辑收敛至 ② 二次编辑弹窗）**对比观察；并可切换正常 / 加载中 / 读取失败 / 空文档状态与深浅色主题。演示同时提供「② 二次编辑」弹窗示意，说明修复后编辑的归属入口。

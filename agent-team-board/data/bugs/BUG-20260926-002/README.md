# BUG-20260926-002 文档编写中的整体审查阶段已经不需要，请在流程各种去除。

- 状态：以看板实时状态为准（本文件不维护业务状态）
- 归属：独立 Bug（引入来源归因见 design.md，开发阶段补全）
- 关联：REQ-20260921-012（文档编写三阶段与「整体审查完结」提交门禁的来源，本单变更其第三阶段语义）；REQ-20260924-001（整体审查自动检查——语言一致性 / 链接可达性 / AI 校对，宿主为完结核对对话框）；BUG-20260926-001（已实施：移除「整体审查」独立按钮、五步合行、完结入口落阶段条 ③——本单在其之上继续去除整个阶段）；REQ-20260924-006（五步操作条，其中「③ AI 校对」为五步入口，与阶段 ③ 无关）
- 创建：2026-09-26T01:55:13.178Z

## 现象

用户诉求：发布模块「文档编写」流程的第三阶段「整体审查完结」已经不需要——逐文件人工审查（①② 阶段）已对内容把关，整体审查不修改任何内容、其自动检查也只读不设门禁，只重复增加一次人工确认动作与一道提交门禁，要求**从流程各处去除**。

现状表现（REQ-20260921-012 引入三阶段门禁、REQ-20260924-001 增强自动检查、BUG-20260926-001 调整入口后的实际界面与后端口径）：

1. **阶段条呈三阶段**（`scripts/web/build.js` `docsStageBar`）：「阶段：① 默认语言先行 ── ② AI 翻译与审查 ── ③ 整体审查完结」，其中 ③ 为可点击按钮（全部文件已审核前 `aria-disabled`，点击给缺口 toast）。
2. **提交门禁叠加完结条件**（`scripts/lib/publish-flow.mjs` `evaluateDocsFlow`：`canCommit = canFinalize && 完结有效`）：语言集内全部文件已审核后「⑤ 提交」仍锁定，必须先打开完结核对对话框人工「确认完结」才解锁；服务端 `/api/build/docs/commit` 同口径拦截，报「整体审查未完结（x/y 已审核）：请先在『整体审查』中人工确认完结后再提交」。
3. **完结核对对话框**（`build.js` `openFinalize` / `data-pf-finalize`，入口即阶段条 ③）承载三项核对清单（各语言内容语义一致 / 所有文档内链接真实可达 / 默认语言错别字与行文规范）与「运行自动检查」「AI 校对」两个动作，footer「确认完结」调 `POST /api/build/docs/finalize`；完结快照固化 `v.review.finalized`（`build-store.recordDocsFinalize`：langsKey + customDocsKey + 全文件内容指纹），语言集变化、任一文件回退待审核、发布范围变化、默认语言基准变更都会使完结失效回退并重新锁上「提交」。
4. **多处文案存在「整体审查」提法**：门禁条（「…整体审查未完结（确认完结后可提交）」/「提交门禁：x/x 已审核 · 整体审查已完结——可提交…」）、完结终态标识（「整体审查已完结 ✓（时间 …；提交已解锁）」）、提交按钮 title 与点击 toast、基准变更提示尾句、`i18n.js` 对应 EN 词条、`atb.mjs` CLI 帮助（summary / translate 口径句、docscheck 提示语）以及根文档（README / AGENTS / DESIGN / FEATURES）的流程描述。

影响为流程冗余：多一道人工确认与失效回退逻辑，拉长操作动线并增加心智负担；不涉及数据错误。

## 复现步骤

1. 启动状态板服务（`node <插件>/scripts/server.mjs`），浏览器打开 `http://127.0.0.1:8888`，选择一个存在发布版本的项目，进入该版本的「文档编写」页签。
2. 观察操作条下方阶段条：三阶段「① 默认语言先行 ── ② AI 翻译与审查 ── ③ 整体审查完结」，③ 为可点击按钮（缺陷现象之一：流程存在第三阶段）。
3. 走完主流程：① AI 总结 → ② 二次编辑 → 「审查」逐文件通过默认语言 → ④ AI 翻译 → 「审查」逐文件通过剩余语言（或取一个语言集内文件已全部审核的版本）——此时门禁条显示 x/x 已审核。
4. 观察「⑤ 提交」仍为禁用（`aria-disabled`），title 为「整体审查未完结：全部文件已审核后，请先在阶段条『③ 整体审查完结』确认完结再提交」；门禁条为「……整体审查未完结（确认完结后可提交）」——全部已审核却仍不可提交（缺陷现象之二：完结门禁）。
5. 点击阶段条「③ 整体审查完结」打开完结核对对话框（可点「运行自动检查」/「AI 校对」核对三项清单），必须点击「确认完结」后「⑤ 提交」才解锁，并出现「整体审查已完结 ✓（时间 …；提交已解锁）」终态标识（缺陷现象之三：冗余人工确认）。
6. 不确认完结直接提交（点击 ⑤ 或调 `POST /api/build/docs/commit`）返回错误「整体审查未完结（x/y 已审核）：请先在『整体审查』中人工确认完结后再提交」。
7. 完结后再改动默认语言文档或增删自定义文档：完结失效回退、「提交」重新锁定，须重新走一遍完结确认（缺陷现象之四：完结快照失效回退逻辑随之存在）。

## 期望行为

文档编写流程回归**两阶段**，「整体审查」从流程各处去除：

1. **阶段条**：仅剩「① 默认语言先行 ── ② AI 翻译与审查」；「③ 整体审查完结」chip 及其点击行为、`aria-disabled` / title 缺口口径整体移除，不存在 `data-pf-finalize` 残留入口。
2. **完结核对对话框整体移除**：三项核对清单、「运行自动检查」「AI 校对」对话框内按钮、「确认完结 / 取消 / 关闭」动作不再有渲染路径（对话框内「AI 校对」能力本身由五步「③ AI 校对」入口与右侧建议栏承载，不受影响；「运行自动检查」去向见待确认）。
3. **提交门禁回归原口径**：`canCommit` 不再叠加完结条件，「语言集内全部文件已审核」即解锁「⑤ 提交」（REQ-20260921-008 原「全部已审核」门禁，不放宽到免审、也不新增其他条件）；服务端 `/api/build/docs/commit` 同步去除完结校验，全审未完结类错误不再出现。
4. **后端完结设施随移除**：`POST /api/build/docs/finalize` 完结接口、`evaluateDocsFlow` 的 `canFinalize` / `finalized` 求值、`build-store.recordDocsFinalize` / `v.review.finalized` 固化口径（历史快照兼容见待确认）。
5. **文案与词典清理**：门禁条、完结终态标识、提交 title / toast、基准变更提示尾句、`i18n.js` 中英词条、`atb.mjs` CLI 帮助（summary / translate 口径句、docscheck 提示语）中「整体审查」提法随流程去除；涉及文案改动中英同步并跑 i18n 相关测试。
6. **与整体审查无关的既有能力不变**：逐文件「审查」对话框、五步操作条（① AI 总结 / ② 二次编辑 / ③ AI 校对 / ④ AI 翻译 / ⑤ 提交）及其门禁（含 ③ AI 校对与右侧建议栏）、基准变更 / 范围变化导致的审核失效回退（该逻辑独立于完结，应保留）、AI 翻译解锁门禁、加载 / 失败态口径均不回退、不放宽。

### 待确认（设计 / 开发阶段须给出结论）

- **「运行自动检查」去向**：各语言内容语言一致性 / 文档内链接可达性检查（`POST /api/build/docs/review-checks`，只读、不设门禁）当前唯一入口是完结核对对话框——随对话框移除是一并去除，还是改挂其他入口（如「审查」对话框），以 design.md 定稿为准，不得静默降级出无入口能力或残留死接口。
- **历史数据兼容**：已含 `v.review.finalized` 快照的旧版本记录，在完结设施移除后的读取 / 展示口径（忽略 / 清理），保证旧版本打开与提交不报错。
- **根文档与 skill 同步**：根第一层文档（README / AGENTS / DESIGN / FEATURES）与 skills 中「三阶段 / 整体审查完结后解锁提交」提法是否随本单同步更新（根第一层发布文档无认领锁可直接改，是否纳入本单范围由 design.md 明确）。
- **测试范围**：`scripts/tests/` 下 REQ-20260921-008 / REQ-20260921-012 / REQ-20260924-001 相关断言（canFinalize / canCommit 完结叠加等）随新门禁口径更新的具体清单由开发阶段定，`npm test` 全量通过。

## 验收说明

1. 「文档编写」阶段条只有「① 默认语言先行 ── ② AI 翻译与审查」两阶段；不存在「③ 整体审查完结」chip，也无任何残留完结入口（DOM 与事件绑定层面均无 `data-pf-finalize`）。
2. 完结核对对话框无渲染路径、不可达；「运行自动检查」按 design.md 定稿落实去向（随对话框移除或另有入口），无死接口。
3. 语言集内全部文件已审核后，「⑤ 提交」直接解锁可提交，全程无需任何「完结」确认动作；门禁条与提交 title 文案不再出现「整体审查」字样；服务端提交接口不再校验完结。
4. 完结相关后端设施（finalize 接口、canFinalize / finalized 求值、recordDocsFinalize 固化）移除；含旧 `v.review.finalized` 快照的版本打开、审核、提交均不报错（兼容口径按 design.md 定稿）。
5. 「整体审查」相关文案与 i18n 中英词条清理干净（界面、toast、title、门禁条、终态标识、CLI 帮助文本），i18n 相关测试通过。
6. 既有能力不回退：逐文件审查、五步操作及各自门禁、③ AI 校对建议栏、基准变更 / 范围变化审核失效回退、加载 / 失败态表现与现状同口径；窄屏 flex-wrap 与深浅色主题表现一致。
7. 「待确认」各项在 design.md 中有明确结论并落实；既有完结相关测试断言随新口径更新，`npm test` 全量通过。

## 界面展示

### 布局

「文档编写」页签（发布模块第五步）现状自上而下：一行操作条（语言集 + 刷新 / 审查 + 五步 ① AI 总结 / ② 二次编辑 / ③ AI 校对 / ④ AI 翻译 / ⑤ 提交，BUG-20260926-001 后形态）→ 阶段条 → 提示词折叠区与运行信息 → 按语言页签的文件列表 + 右侧校对建议栏 → 门禁条（+ 完结终态标识）。

本单涉及范围：

- **修复前（缺陷态）**：阶段条三段「① 默认语言先行 ── ② AI 翻译与审查 ── ③ 整体审查完结」（③ 可点击）；门禁条含「整体审查未完结（确认完结后可提交）」；全审后同屏出现「整体审查已完结 ✓（时间 …；提交已解锁）」终态行；点击 ③ 弹出「整体审查完结核对」模态对话框（三项核对清单 + 运行自动检查 / AI 校对 + 确认完结 / 取消）。
- **修复后（期望态）**：阶段条两段「① 默认语言先行 ── ② AI 翻译与审查」；门禁条文案去掉完结字样（「提交门禁：x/x 已审核——可提交到本地 dev 分支」）；无完结终态行、无完结对核对话框；其余区域布局不变。

### 交互

- 阶段条：修复前 ③ 可点击开完结对核对话框（未全审时点击给缺口 toast）；修复后阶段条 ①② 为纯展示，无可点击段。
- 「⑤ 提交」：修复前需「全部已审核 + 完结」双条件，缺口时 `aria-disabled` + title 列缺口、点击 toast（「尚不可提交：整体审查未完结……」）；修复后仅需「全部已审核」，缺口 toast 只列未审文件明细。
- 对话框内「运行自动检查 / AI 校对」为只读核对动作（本演示内为模拟反馈），「确认完结」成功后关对话框、解锁提交并出终态标识——修复后该组交互整体消失。
- 其余按钮（刷新 / 审查 / ①②③④ 步）交互与现状一致，不因本单变化。

### 状态反馈

- 正常：阶段条 + 门禁条按实时审核进度呈现；门禁未满足时 ⑤ 提供缺口 title 与点击 toast，不静默。
- 加载：操作条恒渲染，数据区显示「正在加载发布流程数据…」。
- 失败：数据区显示「发布流程数据读取失败：<原因>」+ 重试按钮，按钮不隐藏。
- 提交成功：门禁条变绿色「已提交到本地 dev 分支（hash …）」态（现状即有，两方案一致）。

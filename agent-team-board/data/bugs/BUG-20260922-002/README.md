# BUG-20260922-002 文档编写页面的自定义文档要支持删除，并且自定义文档只需要在默认语言中添加一次，其他语种需要自动添加

- 状态：submitted（待人工接受）
- 归属：独立 Bug（引入来源见 design.md）
- 引入来源：REQ-20260922-003（自定义文档能力及其「默认语言单份、不随语言集展开」实现口径，ID 经 atb list 核验）
- 创建：2026-09-22T04:25:29.931Z

## 现象

自定义文档能力由 REQ-20260922-003 引入（dev 提交 9c207d1，2026-09-22 09:40 +0800，早于本单登记）。对照该实现逐项核对，当前 dev 分支行为如下：

1. **其他语种不自动添加（本单核心缺口）**：自定义文档是「默认语言单份」设计——添加 `MIGRATION` 后仅生成默认语言一份 `MIGRATION.md`，只出现在**默认语言页签**（`scripts/web/build.js` `docFilesOf`：自定义文档 `lang: null / single: true`，其余语言页签按 `f.lang === l` 过滤，自定义文档恒不命中）。其他语言页签**不会自动出现** `MIGRATION_en.md` 等对应语种文件；若确需英文版，只能再次手工添加 `MIGRATION_EN`——得到的是又一份"默认语言单份"`MIGRATION_EN.md`（全大写、无 `_en` 语言后缀、仍归默认语言组展示），与 `MIGRATION.md` 之间没有任何语言关联。
2. **自定义文档不进 AI 翻译（阶段二）**：`scripts/lib/publish-flow.mjs` `buildDocTranslatePrompt` 明确排除自定义文档（基准清单过滤 `!f.custom`，目标清单 `restDocFiles` 不含 `lang: null` 的自定义文档）——「AI 翻译」提示词的翻译目标永远只有标准 4 类 × 剩余语言，自定义文档的其他语种版本无法经阶段二产出。
3. **删除（现状核对）**：文件列表中自定义文档行尾**已有**「移除」按钮（`data-doc-rm`；AI 总结运行中禁用；服务端对 merging / 已正式发布锁定 409、总结运行中 400），该项诉求在当前 dev 大体已满足；但存在以下遗留口径：审查对话框内自定义文档页签（单栏、标「自定义」）**没有移除入口**，删除入口仅在文件列表行尾、样式弱、易被忽略；移除仅从版本记录 `v.customDocs` 删除清单项（`scripts/lib/build-store.mjs` `removeCustomDoc`），**不清理磁盘上已生成的 `KEY.md` 文件与已审核留痕**，移除后该文件退出提交 pathspec、成为仓库根的遗留未跟踪文件。用户登记本单时是否正遇到上述某一入口不可用场景，**待确认**。

简言之：添加一次只得到默认语言一份，其他语种既不自动出现文件行、也无任何途径进入 AI 翻译流程；删除虽已提供基本入口，但入口单一且有遗留文件问题。

## 复现步骤

前置：dev 分支（含 REQ-20260922-003 实现），版本计划已创建且语言集含至少两个语言（默认 `cn,en` 即可）。

1. 打开发布看板 → 进入某版本计划详情 → 「文档编写」步。
2. 在默认语言页签（第一个，如 `cn · 中文（默认）`）点击「＋ 添加文档」，输入 `MIGRATION`，点击「添加」。
   - 预期（本单诉求）：其他语种自动出现对应文件。
   - 实际：仅默认语言页签新增一行 `MIGRATION.md`（尾标「自定义」+ 七态 chip「未总结」+「移除」按钮）；表头计数与默认页签角标分母 +1。
3. 切换到其他语言页签（如 `en · English`）：列表仍只有标准 4 类的 `README_en.md / CHANGELOG_en.md / FEATURES_en.md / AGENTS_en.md`（LICENSE 恒「不分语言」归默认组），**没有 `MIGRATION_en.md`**。
4. 尝试补齐其他语种：再次「＋ 添加文档」输入 `MIGRATION_EN` → 添加成功，但得到的是又一份默认语言单份 `MIGRATION_EN.md`（仍显示在默认页签、尾标「自定义」），并非语言集展开命名 `MIGRATION_en.md`，也不出现在 en 页签。
5. 点击「AI 翻译」（默认语言全部审核后可点）：生成的提示词中「翻译基准」与「逐个产出的剩余语言文档」清单均只含标准 4 类，**不含任何自定义文档**。
6. （删除现状）在默认页签点击自定义文档行的「移除」→ 该行从清单消失、计数联动；但项目根下已生成的 `MIGRATION.md` 文件仍在磁盘上，且「审查」对话框内该自定义文档页签从头到尾没有任何删除入口。

## 期望行为

1. **添加一次，其他语种自动添加（核心）**：自定义文档只需在默认语言添加一次（如 `MIGRATION`），文档清单即按语言集自动展开——默认语言 `MIGRATION.md` + 其余语言 `MIGRATION_<lang>.md`，各语言页签自动出现对应文件行（沿用七态状态机与审核计数角标），与标准 4 类同口径；无需也不应再逐语种手工添加。
2. **进入阶段二流程**：自定义文档的其他语种文件进入「AI 翻译」范围——提示词的翻译目标清单包含自定义文档的剩余语言文件（基准为对应默认语言 `KEY.md`）；三阶段门禁计数（默认语言 x/N、剩余语言 a/b、整体审查完结）与提交 pathspec 是否同步纳入，按与标准 4 类一致的口径处理（细节见「待确认」）。
3. **删除支持**：保留并完善现有「移除」能力——按语言展开后移除粒度（整份移除全部语种 / 仅移除某语种）见「待确认」；移除后应同步处理磁盘遗留文件与已审核留痕（至少给出明确提示），不留无人认领的未跟踪文件；删除入口在文件列表保持可见可用（是否在审查对话框内补充入口见「待确认」）。
4. **不回归**：标准 4 类与 LICENSE（不分语言）行为、语言集展开、三阶段门禁、审查对话框、提交口径、README 互链约束不受影响。

## 验收说明

- [ ] 默认语言页签添加一次自定义文档 `KEY` 后，其余每个语言页签自动出现 `KEY_<lang>.md` 行（无需二次添加）；表头计数、各页签角标分母、门禁条按新清单联动。
- [ ] 「AI 翻译」提示词的翻译目标清单包含全部自定义文档的剩余语言文件；翻译回执（`atb translate file --file KEY_<lang>.md`）被接受，状态按 已翻译待审核 → 已审核 推进（参与门禁与 pathspec 的口径按落定结果验收，落定前不得弱化既有门禁）。
- [ ] 自定义文档可删除：移除后清单、计数、提示词、门禁即时联动；磁盘遗留文件与审核留痕有明确处理（删除或提示），不残留退出 pathspec 的孤儿文件；AI 总结运行中 / merging / 已正式发布时的移除拦截口径保持。
- [ ] 以 `MIGRATION_EN` 之类"手工逐语种添加"的旧 workaround 不再是达成多语言的途径（自动展开后同名即重名拦截，报错口径与现状一致）。
- [ ] 标准 4 类、LICENSE 单文件、语言集编辑、审查对话框、提交行为不回归；涉及界面改动的新增 / 变更文案中英文同步（`scripts/web/i18n.js`，BUG-20260912-001 基线）。

## 待确认

1. **展开后各环节参与口径**：自定义文档的其他语种文件是否计入三阶段门禁计数与提交 pathspec（建议与标准 4 类完全同口径；这同时回答 REQ-20260922-003 遗留的「待确认 2/3」——本单登记即表明用户选择"随语言集展开"而非"默认语言单份"）。
2. **移除粒度**：按语言自动展开后，「移除」是整份移除（全部语种）还是支持单语种移除；移除已总结 / 已审核 / 已提交后的自定义文档的口径（现状：仅拦截 merging / pushed / 总结运行中）。
3. **磁盘清理**：移除时是否删除项目根对应的 `.md` 文件（含已写入内容时是否需二次确认）；已审核留痕 / 完结快照中该文件的记录如何失效。
4. **用户场景还原**：登记人提出「要支持删除」时是否遇到移除不可用的具体场景（旧版前端 / 审查对话框无入口 / 拦截提示），用于确定删除侧是否还需增强。

## 界面展示

- **布局**：文档编写页文件区——表头行「文件（N · 默认语言 x/y 已审核 · 剩余语言 a/b 已审核）」+ 右侧「＋ 添加文档」；其下按语言页签（默认语言标「默认」+ 审核计数角标），页签内为文件行（文件名 + 「自定义」标识 + 七态 chip + 「移除」）；修复后自定义文档在**每个**语言页签各有一行（默认语言 `KEY.md`，其余 `KEY_<lang>.md`）。
- **交互**：添加一次自动展开到全部语言页签；「移除」删除整份自定义文档并联动计数；「AI 翻译」提示词目标清单包含自定义文档剩余语言文件；缺陷态与修复态可切换对比（含 `MIGRATION_EN` 手工 workaround 的错误示范）。
- **状态反馈**：覆盖正常（添加 / 移除 / 总结 / 翻译提示词联动）、空态（无自定义文档 / 空名报错）、加载（添加中 / 读取中 / 总结中 x/N）、失败（非法名 / 重名 / 保留名校验、模拟读取失败重试）等状态切换。
- **可交互演示**：[./ui-demo.html](./ui-demo.html)（单文件 HTML，浏览器直接打开；内置「缺陷现状 / 期望修复后」对照开关、深浅色切换与各状态模拟）。

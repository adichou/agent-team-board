# BUG-20260914-019 REQ-20260914-004 生成的提示词末尾追加一个换行符，用户的问题和提示词有明确的换行分隔

- 状态：accepted（已接受；实际状态以 status.json 为准）
- 归属：独立 Bug（引入来源见 design.md）
- 创建：2026-09-14T14:23:46.030Z

## 现象

REQ-20260914-004（commit 8196d60）落地后，需求 / Bug 详情抽屉文档页签右键「💬 讨论」复制到剪贴板的提示词**末尾没有换行符**：组装函数 `buildDocRef`（`scripts/web/app.js` 约 4390–4406 行）以 `lines.join('\n')` 返回，最后一行是「4. 每轮回答回显本轮 commit log 与 commit 号（短哈希即可）。」，字符串到行尾即结束。

该提示词的标准用法是「粘贴到 Agent 会话输入框 → 紧接着输入自己的问题」。由于末尾无换行，粘贴后光标停在末行行尾，用户直接键入的问题会接在同一行：

```
4. 每轮回答回显本轮 commit log 与 commit 号（短哈希即可）。这里第 3 条是不是可以先只讨论不改文件？
```

用户的问题与提示词没有明确的换行分隔：轻则难读、边界不清，重则 Agent 可能把问题当作「讨论要求」第 4 条指令的延续（问题被并入指令语义）。自动复制失败时的回退弹窗 `uiCopyBox`（`scripts/web/app.js` 约 4494–4531 行）只读 textarea 展示并全选的是同一文本，手动 ⌘C / Ctrl+C 复制的粘贴结果同样末尾无换行。

现状链路（均经源码核实，2026-09-14）：

1. **组装**：`buildDocRef`（约 4390–4406 行）`lines.join('\n')` —— 无末尾换行。
2. **复制**：`onDocCtxDiscuss`（约 4456–4466 行）`copyPlain(info.text)`；`copyPlain`（约 1677 行起）`navigator.clipboard.writeText` 主路径 + 临时 textarea `execCommand('copy')` 回退，均为原样写入。
3. **失败回退**：`uiCopyBox('手动复制讨论引用', info.text)`（约 4494–4531 行）只读 textarea `value = text` 并 `select()` 全选。
4. **测试基线**：`scripts/tests/doc-ctx-discuss-req-20260914-004.test.mjs`（T1–T3 断言现格式）、`doc-ctx-discuss-20260909-014.test.mjs` / `doc-ctx-discuss-bug-20260913-003.test.mjs`（T4 断言 buildDocRef）——补末尾换行后相关断言需同步。

## 复现步骤

前置：项目目录运行 `atb serve`（默认端口 8888，`ATB_PORT` 可覆盖），浏览器打开 `http://localhost:8888`，顶栏选中该项目。

1. 打开任一需求（如 REQ-20260914-004）或 Bug 详情抽屉，切到「说明」「设计」或「测试用例」文档页签，待文档加载完成（右键弹菜单的前提）。
2. 在文档内容区（`#docView` 内，可先选中一段文字，也可不选）右键 → 点「💬 讨论」→ 出现 toast「已复制 引用：xxx 第 x–y 行」。
3. 切到任意 Agent 会话输入框，⌘V / Ctrl+V 粘贴，观察光标落点：光标停在末行「4. 每轮回答回显本轮 commit log 与 commit 号（短哈希即可）。」**行尾，不在新行**。
4. 不按回车、直接键入问题（如「这里第 3 条是不是可以先只讨论不改文件？」）——问题与「（短哈希即可）。」连在同一行，无换行分隔，即本 Bug 现象。
5. 对照实验：粘贴后先手动按一次回车再输入，问题才另起一行——说明现状缺的正是提示词末尾的一个换行符。
6. 失败回退路径（可选）：在自动复制失败的环境（如非安全上下文）下右键「💬 讨论」，出现错误 toast 与「手动复制讨论引用」弹窗，textarea 内已全选，⌘C / Ctrl+C 后粘贴——末尾同样无换行。

## 期望行为

- `buildDocRef` 返回的提示词**末尾追加一个换行符 `\n`**（如 `lines.join('\n') + '\n'` 或等效实现）：用户粘贴后光标已在新行，直接输入的问题与提示词有明确的换行分隔。
- 只在末尾追加**一个**换行符：不追加两个及以上（避免多余空行），不在开头 / 中间加空行；提示词其余内容（【文档讨论引用】引用要素 + 【讨论要求】四条指令）一字不变。
- 有选中 / 无选中两场景、README.md / design.md / test-cases.md 三份文档页签与需求 / Bug 详情抽屉（共用 `buildDocRef`，一处修改全部生效，同 REQ-20260914-004 design.md「覆盖范围」结论）末尾均带换行。
- 交互零回退：右键菜单唤起 / 收起（点外部 / Esc / 滚动 / 切页签 / 关抽屉）、`copyPlain` 双回退、toast 摘要口径（「已复制 引用：xxx 第 x–y 行」）均不变；自动复制失败弹窗（`uiCopyBox`）textarea 展示与全选复制的文本同样末尾带换行。
- 纯前端剪贴板文本改动：不新增后端 API、不写文件 / 记录、不改状态机、不改样式。
- 范围边界（待确认）：`scripts/web/req-disc.js` 讨论区块的另一套提示词（启动 / 收尾提示词，REQ-20260914-003 优化）是否同样追加末尾换行——本单标题指向 REQ-20260914-004 的右键讨论提示词，按 REQ-20260914-004 design.md 结论 4 同口径**默认不改**；如需对齐另行确认。

## 验收说明

1. **粘贴分隔验证**：右键「💬 讨论」复制 → Agent 会话粘贴后光标位于新空行，直接输入问题，问题自动另起一行；提示词末行「…（短哈希即可）。」与问题首行之间恰一个换行、无多余空行。
2. **两场景一致性**：有选中 / 无选中复制的提示词均以 `\n` 结尾且不以 `\n\n` 结尾；「说明」「设计」「测试用例」三份页签与 Bug 单详情抽屉口径一致。
3. **交互回归**：toast 摘要、菜单收起通道、`copyPlain` 双回退均与现状一致；「文档未创建 / 加载中 / 加载失败」时右键仍不弹菜单（口径不变）。
4. **失败回退**：模拟自动复制失败，「手动复制讨论引用」弹窗 textarea 全选（⌘C / Ctrl+C）复制的结果同样末尾带一个换行。
5. **测试同步**：`scripts/tests/doc-ctx-discuss-req-20260914-004.test.mjs` 补 buildDocRef 末尾换行断言（`endsWith('\n')` 且不以 `'\n\n'` 结尾），必要时同步 `doc-ctx-discuss-20260909-014.test.mjs`、`doc-ctx-discuss-bug-20260913-003.test.mjs` 相关断言，`node scripts/tests/run-all.mjs` 全量通过。
6. **外观与壳**：纯文本内容改动，无样式变化；深浅色与 Electron 桌面壳内复制行为一致。

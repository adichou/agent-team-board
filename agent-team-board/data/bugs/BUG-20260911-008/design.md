# 设计 — BUG-20260911-008 已完成的文案需要精简，确保和开始 Commit 能在同一行。

> 由 Agent 在 /dev 开发前补充，人可随时批注。

## 引入来源（源单）

- 引入来源：REQ-20260910-008（经 `atb list` 核验存在，done）
  —— 该需求把 `#reqCount` 转为条件提示时写入了这段约 38 个全角字符的长文案
  「N / M 个条目（已完成默认仅显示最新 100 项，更早请用搜索获取）」。
- 显现叠加：BUG-20260911-005（经 `atb list` 核验存在，done）在已完成档右组
  `#captionActions` 新增「▶ 开始 Commit」快捷入口后，长文案 + 右组整组宽度相加
  超出列表列可用宽度，右组被兜底换行挤到第二行，缺陷才显现。

## 根因分析

`renderBoard` 拼装已完成档截断提示（`scripts/web/app.js` L1998）时文案冗余：
「个条目」「已完成默认仅显示」「项」「更早请用搜索获取」等字词造成约 38 个全角字符。
列表头 `.req-caption` 为 flex 单行工具栏（`flex-wrap: wrap` 兜底），列表列宽为内容区
1fr:2fr 分轨的约 1/3（宽屏下限 1021px 时约 324px）。已完成档下提示（左侧）与
`#captionActions`（右侧整组 `nowrap`，含「▶ 开始 Commit」）相加超宽，
flex-wrap 兜底把右组整组换到第二行——「▶ 开始 Commit」单独成行（见 README 截图）。
布局规则本身（单行、按组换行兜底、不裁切不横滚）符合预期，问题只在文案宽度。

## 方案

**纯文案精简，不动布局规则**（`scripts/web/app.js` L1998 单行改动）：

- 旧：`${items.length} / ${laneTotal} 个条目（已完成默认仅显示最新 ${REQ_DONE_LIST_LIMIT} 项，更早请用搜索获取）`
- 新：`${items.length} / ${laneTotal} 项，仅列最新 ${REQ_DONE_LIST_LIMIT}，更早请搜索`

三要素语义完整保留（与条目 ui-demo.html「期望修复」模式定稿一致）：

1. 「100 / 241 项」——显示数 / 总数；
2. 「仅列最新 100」——默认仅显示最新 100 项；
3. 「更早请搜索」——更早条目用搜索获取。

精简后约 26 个字符（全角约 12 个），在列表列既有保底口径（宽屏下限约 324px）下
与「▶ 开始 Commit」同行显示（ui-demo「同行检测」已按该口径预演）；宽度极端不足时
维持既有「按组整体换行」兜底。同步更新既有断言旧文案的测试
`scripts/tests/caption-toolbar-20260910-008.test.mjs`（L140–L156）：
断言新文案三要素 + 不再含「个条目」冗余词 + 长度量级上限，防回归变长。

**开源选型（REQ-20260909-015）**：本次为单行展示文案精简，无合适开源库承担该职责，
不引入依赖（引入成本高于自研：改动仅一处字符串模板与对应断言）。

## 风险与边界

- 其余提示场景不受影响：普通档无提示、搜索命中「搜索命中条目 N 项（当前档可见 M 项）」
  文案与逻辑维持现状（搜索提示仍不含「个条目」口径断言继续成立）。
- 布局规则（`.req-caption` wrap 兜底、右组 `nowrap` 整组靠右）零改动，
  相关 CSS 契约测试（caption-two-row / selection-bar-merge / lane-quick-entry）不回归。
- 文案仍含动态数值（显示数 / 总数随数据变化），总量为 4~5 位数时长度略增，
  极端宽度下仍由既有按组换行兜底，不裁切、不横向滚动。

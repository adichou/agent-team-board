# BUG-20260907-009 内置浏览器中触发 window.confirm 的操作冻结整页：单卡「✓ 接受」/批量接受/停止执行无可见弹窗

## 现象

## 现象
app.js 三处同步 window.confirm（单卡接受约 1302 行、批量接受约 1249 行、停止当前执行约 2438 行）。在 ZCode 内置浏览器（IAB，Status Board 的主打入口）中点击后：
- 页面主线程冻结，2 秒轮询停摆；
- 无任何可见的原生弹窗 UI 供用户点击；
- 自动化层面 click 超时、连 CDP screenshot 都 30s 超时（渲染线程不可服务）；
- 只能整页刷新恢复（刷新又会触发 BUG-20260907-002 空列表）。

## 复现（沙盒实测）
点击「接受所选（4）」→ click 超时 + screenshot 超时；getJsDialog 可取到 confirm（用 dismiss/accept 应答后页面立即恢复，批量接受本身逻辑正确）。

## 建议
前端改用页面内自绘确认条/对话框（项目已有 toast+撤销模式，REQ-20260906-014 已为详情页按钮去掉二次确认），彻底移除 window.confirm/alert/prompt 依赖。

## 影响
在内置浏览器里，用户点单卡接受/批量接受/停止执行后疑似整页卡死（外部浏览器未验证，待人工确认）；至少自动化与轮询被完全阻塞。

## 期望行为

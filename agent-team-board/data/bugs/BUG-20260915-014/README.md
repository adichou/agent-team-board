## 现象

用户反馈：点击发布按钮后提示发布模块已被隐藏。用户要求在右侧版本计划详情增加「发布」页签，展示发布情况，原有页面移入「概况」页签。

代码可确认的链路：`scripts/web/build.js` 的 `doCreateRelease()` 创建草稿成功后调用 `gotoProductRelease()`；「查看发布记录」同样使用跨模块入口。`scripts/web/app.js` 将 `release` 纳入 `HIDDEN_VIEWS`，`setView()` 会提示「发布模块暂时隐藏，已回到需求模块」。因此用户离开正在查看的版本，无法通过该入口查看发布结果。草稿可能已创建，不能将跳转失败等同于创建失败。

实际受影响浏览器、版本、用户最初点击的是「创建发布」还是「查看发布记录」、现场运行 ID：待确认。以下复现步骤依据源码链路整理，尚未实机复现。

## 复现步骤

前置：使用已初始化 Git 的项目，存在已合并（merged）的版本计划；创建路径还需满足现有产品发布配置与冻结校验条件。

1. 打开「构建 → 版本计划」，选中一个已合并版本。
2. 点击右侧「查看发布记录」，观察是否提示发布模块隐藏并回到需求模块。
3. 单独验证创建路径：选择符合发布条件的版本，点「创建发布」，输入发行版本号并确认。
4. 在创建接口成功返回草稿后，观察后续跳转；检查该草稿是否实际存在，避免重复创建。
5. 对照修复后页面：重复查看操作，应留在同一版本详情并激活「发布」页签。创建验证仅在可控开发环境执行，创建草稿不应自动执行真实发布。

## 期望行为

### 布局与交互

- 保留构建模块的「版本计划 / 分支浏览」以及左侧版本列表。在右侧选中版本详情标题下提供「概况」「发布」两个页签，默认进入概况。
- 概况承接当前版本名称、描述、关联条目与 commit、合并反馈、管理记录提交反馈及现有编辑限制；创建发布和查看发布记录入口保持可发现。
- 点击「查看发布记录」只切换当前版本的发布页签；点击「发布」页签同样可查看，不跳转隐藏模块，不新增顶栏发布模块入口。
- 创建发布保留现有发行版本号确认与服务端校验。成功后切换本版本发布页签并选中新建草稿；失败保留输入和明确错误，不伪报成功。创建期间禁用重复确认。
- 发布页签仅展示当前项目、当前版本（运行 `bldId` 对应选中版本）的记录；列表可选择运行，详情展示运行 ID、发行版本号、状态、阶段、Web App / 官网目标结果与错误信息。已有数据缺失时明确显示未提供，不猜测结果。
- 预检、计划确认、执行和重试沿用现有发布流程与允许状态，入口应在该页签可达。切换页签、选择记录和刷新均为只读，不能自动启动发布。
- 切换版本时清除旧版本记录与错误，切换项目后不得串用旧项目结果。异步旧请求返回不得覆盖新选择。

### 状态反馈

- 正常：显示当前版本的发布记录与所选运行详情，草稿、执行中、成功、失败按实际数据区分；草稿不显示为已发布。
- 空态：提示「当前版本暂无发布记录」；已合并版本可创建，未合并版本说明「请先完成合并入 main」并禁用创建。
- 加载：右侧发布区显示加载提示，页签及版本选择仍可用，不以旧版本记录代替新版本内容。
- 读取失败：区分「发布记录读取失败」与发布运行自身失败，提供只读重试入口；概况仍可访问。
- 运行失败：展示失败阶段与原因；是否允许重试服从现有执行规则，不把读取重试实现成重复创建或重复发布。

## 验收说明

- [ ] 右侧出现概况/发布页签；原有详情内容和编辑、合并限制在概况中保留。
- [ ] 查看发布记录与成功创建后的落点均为当前版本发布页签；不再出现隐藏模块提示或回到需求模块。
- [ ] 发布记录按项目和版本隔离；至少用两个版本验证切换，旧请求慢返回不串记录。
- [ ] 新建草稿可被选中查看，发行版本、运行状态、阶段、目标及错误展示来自实际记录；支持选择已有运行。
- [ ] 空、加载、读取失败及重试均可观察；失败重试只读取数据，返回概况不受阻。
- [ ] 未合并版本无法创建；创建失败保留输入并显示错误；创建中重复点击不会生成额外请求。
- [ ] 现有预检与计划确认入口可达；创建草稿、页签切换、刷新不触发真实发布；执行仍需原有明确确认。
- [ ] 演示文件离线直接打开可操作，能切换缺陷/期望以及正常/空/加载/失败场景。

# BUG-20260915-002 dev 命令收尾缺少 Git 提交与待测试状态闭环

- 状态：待测试（以 status.json 为准）
- 归属：独立 Bug（引入来源见 design.md）
- 引入来源：未定位（命令历史仅追溯至 6f2ead6 聚合提交，无法可靠映射单一源单；详见 design.md）
- 创建：2026-09-14T23:13:10.964Z

## 现象

当前 dev 流程未明确要求将本单代码、测试与文档提交 Git，并核验条目实际进入待测试；在用户授权绕过认领阻塞修复 BUG-20260915-001 后，Agent 只改工作区并手写测试报告，条目仍停留 planned。期望 dev 技能及相关执行入口明确提交与状态闭环：真实测试通过、核对本单差异、仅提交本单文件、通过工具上报进入待测试、核验提交 hash 与状态后再报告完成。认领受阻且获用户例外授权时应覆盖合法收尾；不能完成时明确说明阻塞，不宣称已完成。

## 复现步骤

1. 使用 dev 流程处理 BUG-20260915-001，遇到项目提交挂起导致认领失败。
2. 用户明确授权例外修复，完成代码和测试。
3. 收尾只交付工作区修改，未提交 Git，条目仍为 planned。

## 期望行为

执行 dev 后应完成本单 Git 提交并进入待测试；异常时应明确报告未完成项。

## 验收说明

- dev 技能明确要求检查本单差异、运行相关测试、提交代码/测试/文档并记录提交 hash。
- 上报后核验条目为待测试（in-progress 且有本轮 agentCompletedAt/lastReport），不得以手写报告替代上报。
- 未授权混入其他任务的修改，保持其他工作区变更不动；不自动验收为 done 或推送远端。
- 认领受阻、用户授权例外修复的场景有可执行收尾规则；无授权时不绕过挂起。
- Git 提交或上报失败时明确报告阻塞及未完成步骤，不宣称完整交付。

## 现象

用户反馈：版本已经发布，右侧详情仍显示「已合并」。已发布版本应只能查看，但版本计划的修改类按钮未全部置灰。

代码核对：`scripts/web/build.js` 的列表使用 `versionChip(v)`，优先读取 `v.release.published` 显示「已发布」；`renderDetail(v)` 的标题使用 `statusChipFor(v)`，只判断合并与文档合并状态，造成两处口径不一致。详情「编辑」按钮当前只判断合并中；名称和描述还存在行内编辑入口。列表删除按钮也只检查合并中及全局合并忙碌。以上是静态检查发现，不代表已完成浏览器复现或接口防护验证。

`build-publish-store.mjs` 的 `publishedByBld` 以任一 succeeded 运行判定发布成功，后续草稿或失败不撤销该标记；`server.mjs` 构建状态接口另提供 `released`。两字段当前语义不同，不得把「合并完成」直接等同「发布成功」。具体受影响版本号、浏览器、用户现场发布运行编号待确认。

## 复现步骤

1. 在具有发布成功记录的项目打开「构建」，选择已发布的版本计划；测试数据需具有成功运行，勿为复现向远端执行真实发布。
2. 对比左侧版本卡片与右侧详情标题状态；用户报告右侧仍显示「已合并」，代码支持该差异路径。
3. 在「选择条目与提交」查看「编辑」、名称/描述行内编辑、AI 完善、添加/移出条目及提交调整入口；再检查列表删除、文档与翻译、挑选合并、文档合并、发布步骤的修改入口。
4. 尝试以鼠标和键盘进入编辑，观察是否仍可打开表单或提交修改。哪些操作目前能实际写入待开发阶段在隔离数据验证，不可凭按钮外观断言服务器接受修改。
5. 刷新页面、切换版本后返回，并覆盖已打开编辑表单期间版本变成已发布的情况。

## 期望行为

已发布版本的列表和详情统一显示「已发布」，不会因后续失败或草稿运行退回「已合并」。未发布的版本维持已有计划中、合并中、失败、代码已并入但文档与翻译未合并、已合并等口径。

已发布版本只能查看，所有会修改该版本计划或其关联内容的按钮应保留可见并置灰：信息编辑/保存、AI 完善结果回填、关联条目及提交增删调整、删除版本计划、文档编辑/保存/审查写入、合并与重新合并、文档合并、重复发布及其他改变当前计划的操作。行内名称/描述入口同时取消编辑能力；发布后已打开的表单不得继续保存。开发阶段须逐一核对真实入口，不能只修复显式「编辑」按钮。

禁用原因统一表达「已发布，版本计划仅可查看；如需调整请新建版本」。查看详情、步骤切换、搜索、分页、展开记录、复制只读信息仍可用；新建其他版本不受影响。只读约束同时覆盖事件处理与写入校验，陈旧页面的请求不得改变已发布数据。保留发布确认后既有更早锁定规则，不因本次统一显示而放开操作。

## 验收说明

- [ ] 同一已发布版本的列表、详情及重新打开后的标题均为「已发布」，与发布成功记录一致；后续草稿/失败不会撤销成功标记。
- [ ] 未发布状态显示与现有门禁不回归，不把只有合并或推送证据的版本误标为发布成功。
- [ ] 已发布版本所有修改入口置灰且说明原因；鼠标、键盘、行内快捷编辑和已打开表单均不能绕过。覆盖上述步骤及列表删除入口。
- [ ] 对已发布版本的写入请求被拒绝，名称、描述、关联、文档和发布计划记录不变；具体接口清单在开发阶段核实。
- [ ] 查看、步骤导航、搜索、分页、复制与记录展开正常；空、加载、失败及重试不误开放修改。
- [ ] 刷新、切换版本、发布成功状态到达时即时应用只读；新建/编辑其他未发布版本不受此锁误伤。
- [ ] 中英文界面同步，禁用状态可用键盘和辅助技术辨识。

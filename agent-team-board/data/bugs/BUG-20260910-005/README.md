# BUG-20260910-005 打开 XX 工作区改为去新建 XX 会话

- 状态：以看板机器状态为准，本说明不维护状态副本。
- 归属：独立 Bug
- 创建：2026-09-10T01:59:53.478Z

## 现象

原始反馈要求：根据系统安装情况检测 Code Agent；新建 Agent 会话时传入当前项目目录；将「去新建 XX 会话」放在「批量开发」页签旁边，以超链接区别于前两个页签。

当前源码中的入口仍是提示词分区底部的「打开 Zcode 工作区」「打开 Codex 工作区」按钮，任务模块顶部只有「批量完善 / 批量开发」两个页签。入口位置、样式和文案与反馈不符。Zcode 现有链接只打开工作区，不能据此认定已支持自动创建会话。

以上为静态代码核对，未启动浏览器或外部 Agent 实测；用户实际客户端版本、安装位置和失败截图均待确认。

## 复现步骤

1. 在已启动的 Status Board 中选择当前项目，进入「任务」模块；准备有可查看提示词的批量完善或批量开发记录。无记录时的现有入口表现待实测确认，无需为文档完善实际启动批次。
2. 查看顶部「批量完善 / 批量开发」页签右侧，核对是否有「去新建 XX 会话」超链接；当前源码没有该入口。
3. 打开提示词分区，核对底部仍显示「打开 Zcode 工作区 / 打开 Codex 工作区」按钮，而非顶部的会话入口。
4. 在安装了对应客户端的环境中点击原入口，检查传入的项目目录以及落点。源码中 Zcode 使用 `zcode://workspace/open?path=…`，Codex 使用 `codex://threads/new?path=…`；实际新会话落点需开发阶段实测。
5. 分别用仅安装一个、两个均安装、均未检测到及探测失败的环境核对展示；切换项目后重复操作，检查是否仍使用旧项目路径。以上分支为待执行复现检查，不代表已确认每个分支有故障。

## 期望行为

- 根据本机检测结果呈现对应 Agent 的「去新建 XX 会话」入口，支持范围以项目已实现的 Zcode / Codex 为起点；其他 Agent、非默认安装目录及非 macOS 的支持范围待确认。
- 点击入口携带当前选中项目的绝对目录，进入对应 Agent 的新会话创建流程。不得只改文案便宣称已实现新会话；Zcode 缺少已核实的创建会话通道，具体实现能力待确认，受限时应明确告知需要手动新建。
- 延续现有提示词复制后由用户粘贴发送的流程，不因导航自动发送提示词或启动批次。

## 界面展示、交互与状态反馈

- [交互演示（ui-demo.html）](./ui-demo.html)：切换「缺陷现象 / 修复后状态」——缺陷态顶部无会话入口、底部为「打开 XX 工作区」旧按钮；修复态「去新建 Zcode / Codex 会话」链接位于「批量开发」页签旁并携带当前项目目录、旧按钮移除。含 两端可用/仅一端/未检测到/检测中/探测失败 的入口状态切换示意（真实唤起结果与 Zcode 新会话协议以验收实测为准）。
- 布局：「批量完善」「批量开发」保持页签布局，在「批量开发」旁边放置「去新建 Zcode 会话」「去新建 Codex 会话」文字超链接；与页签留出间距，不使用页签选中样式。将原底部入口迁移到这里，避免重复。
- 交互：链接可通过鼠标和键盘触发，导航不切换完善/开发选中页签，不改变批次和队列；切换项目后使用最新目录。
- 正常：检测到可用客户端且已选择项目时，入口可操作，提示其打开的 Agent 与当前项目。
- 空态：未选择项目时不可触发，并说明先选择项目；未检测到客户端时明确提示未检测到，避免将「检测不到」误写成「一定未安装」。未安装入口隐藏还是保留禁用态的最终视觉取舍待确认，但须有可见解释。
- 加载：探测过程中显示正在检测，不把未知结果当作未安装；探测不应阻断页签与提示词复制操作。
- 失败：探测失败或能够识别的唤起失败提供说明及重试/手动打开指引；浏览器无法确认外部应用启动结果时，只能提示已请求打开，不宣称会话创建成功。

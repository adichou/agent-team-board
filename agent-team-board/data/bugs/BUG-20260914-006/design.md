# 设计 — BUG-20260914-006 分支浏览「无远端分支」空态缺解释：远端仓库为空与本地未同步不可区分

> 由 Agent 在 /dev 开发前补充，人可随时批注。

## 引入来源（源单）

本 Bug 由哪个需求 / Bug 引入？登记时可暂空或写「未定位」，修复阶段必须归因（三选一，禁止编造）：

- 引入来源：REQ-20260913-001（`atb list` 已核验存在）
  - 该需求建立构建模块「分支浏览」子页，其「远端」分组空态文案（scripts/web/build.js 约 996 行）只有一句「（无远端分支：先「同步远端」或推送本地分支）」：数据层 `listBranches()` 只读本地 `git branch -r`，天然无法区分「远端仓库确实为空（从未推送）」与「本地尚未同步（远端有分支但没 fetch）」，界面亦无解释提示。README「现象」节含 2026-09-14 会话完整排查（本仓库 origin 已配置、GitHub 空仓库、本地无任何远端跟踪引用）。

## 根因分析

- 数据层只读本地跟踪引用：`listBranches()`（scripts/lib/build-git.mjs）用 `git branch -r` 列远端跟踪分支，
  该命令只反映本地 `refs/remotes/*`，**天然无法区分**「远端仓库确实为空（从未推送）」与「本地尚未 fetch」。
- 返回体不含远端配置信息：前端拿到的只有 `{ isRepo, current, local, remote }`，连「是否配置了远端」都不知道，
  「未配置远端」与「配置了但为空」也只能共用同一句空态文案。
- 前端空态一句走天下：`renderBranchesPane()`（scripts/web/build.js）远端分组为空时固定渲染
  「（无远端分支：先「和远端同步」或推送本地分支）」，且 `doFetch()` 成功后也不区分语义——
  同步刚成功却仍被告知「先和远端同步」，自相矛盾（README 复现步骤 3）。
- 本仓库形态（经 `ensureDevWorkflow()` 空仓库路径初始化，自动提交只 commit 不 push）使「远端为空」
  成为真实常见状态，而非边角。

## 方案

采取 README 期望行为 a+b 组合（与 ui-demo.html「期望修复后」一致）；**不引入任何隐式网络操作**
（分支浏览保持只读，`git remote` 是本地配置读取，非网络；同步仍是唯一显式网络按钮）：

1. **数据层**（build-git.mjs `listBranches`）：返回体增加 `remotes` 字段——本仓库已配置的远端名列表
   （复用既有 `remoteNames()`，即 `git remote`，本地读）。非 git 仓库分支形状补 `remotes: []`，其余字段不变。
2. **前端状态**（build.js）：`state.remoteSynced` 会话内标志——`doFetch()` 成功（fetch ok）后置 true，
   切换项目时随其余分支状态一并重置；含义是「最近一次成功同步后本地跟踪引用即为最新」。
3. **空态区分**（`renderBranchesPane()` 远端分组为空时三分支）：
   - **未配置远端**（`remotes` 为空）：保持既有文案「（无远端分支：先「和远端同步」或推送本地分支）」不动
     （README 验收 4 / ui-demo 注②：该既有空态不在本 Bug 范围）。
   - **已配置远端 + 本次会话尚未同步**（修复方向 b）：灰字「本地无远端跟踪分支：尚未与远端同步，可点上方
     「⟳ 和远端同步」拉取；若同步后仍为空，说明远端仓库尚无任何分支（从未推送），可在上方「本地」分组推送分支。」
     ——初始态即解释两种成因与两条出路，满足验收 1 前半句（打开即能解释「远端为空（从未推送）」并引导推送）。
   - **已配置远端 + 本次会话同步成功后仍为空**（修复方向 a）：信息色调解释块（`role="note"`，样式
     `.bld-remote-hint`，沿用 ui-demo `.bld-fix-hint` 拟真）：标题「远端仓库尚无任何分支（从未推送）。」
     + 说明「刚才的同步已成功——列表仍为空说明远端仓库本身就是空的。可在上方「本地」分组对分支点「推送」，
     首推将建立上游跟踪。」；同时本地分支行「推送」按钮加 `attn` 高亮（outline + nudge 呼吸动画）指出出路，
     远端分组出现分支后自动消失。
4. **样式**（style.css）：新增 `.bld-remote-hint`（info 蓝左边条卡片，对齐既有 `.bld-main-hint` 的弱提示形态）
   与 `.bld-push.attn` + `@keyframes nudge`；不动既有类。
5. **i18n**（i18n.js EN 词典）：新文案各文本节点收录词条（沿 BUG-20260914-005 先例），值唯一、不含中文。

不做：不自动 fetch / 不 ls-remote / 不改 `branch -r` 数据口径 / 不改未配置远端与非 git 仓库空态。

**开源选型（REQ-20260909-015）**：动手自研前先评估是否有成熟、维护中的开源库，优先复用——以依赖方式引入
（Node/Web 项目走 npm，Apple 平台走 SPM / CocoaPods），禁止复制开源库源码进项目仓库；仅当库无包分发渠道
且确需使用时才允许 vendor（内嵌源码），须在 licenses.md 标注复制范围与原因。License 只用开源友好白名单：
MIT / Apache-2.0 / BSD-2-Clause / BSD-3-Clause / ISC / 0BSD / Unlicense；GPL / LGPL / AGPL / SSPL 等
强传染许可及 License 不明的库禁止引入。自研须写明理由（三选一）：引用了哪些库 / 无合适库的原因 /
引入成本高于自研的原因。引入开源库须在条目目录维护 licenses.md（库名 / 版本 / 引入方式 / License / 仓库地址），
未使用开源库的条目不创建该文件。

自研理由：无合适库——本修复是本项目自研 UI（build.js 单文件渲染层）内约 20 行文案分支 + 1 个返回体字段
+ 少量 CSS，引入任何视图/状态库的成本与体积都远高于自研，且项目现有零依赖结构（纯原生 ESM）是既定约束。

## 风险与边界

- **`remoteSynced` 是会话内知识**：页面刷新后回到初始空态（引导先同步）——刻意为之：不做持久化，
  避免陈旧结论（远端可能在别处已被推送）误导；同步一次即可得到确定结论，成本一个显式点击。
- **多远端混合**：fetch --all 成功后仍为空 ⇒ 所有已配置远端都无分支，文案「远端仓库尚无任何分支」仍准确。
- **既有回归面**：`（无远端分支：先「和远端同步」或推送本地分支）」仍保留于「未配置远端」分支——
  bug-sync-btn-wording-20260914-005 S1 源码断言与 U2（载荷无 remotes → 走该分支）不回归；
  bug-branch-main-missing-20260914-003 U1 断言随载荷语义显式化微调（补 `remotes: []` 注明走未配置远端分支）。
- **API 兼容**：`/api/build/branches` 仅增字段不删字段，旧载荷（测试注入无 `remotes`）按「未配置远端」
  兜底（`b.remotes || []`），不会误报「远端仓库为空」。
- **推送高亮动画**：仅 outline/透明度动画，无布局位移，不干扰既有 hover/选中态；沿用既有
  `prefers-reduced-motion` 逐动画消减先例（style.css rf-pulse 同款）对 nudge 一并禁用。

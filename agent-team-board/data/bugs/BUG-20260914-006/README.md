# BUG-20260914-006 分支浏览「无远端分支」空态缺解释：远端仓库为空与本地未同步不可区分

- 状态以本条目 status.json 和看板为准。
- 归属：独立 Bug（引入来源见 design.md；涉及界面为构建模块「分支浏览」子页，由 REQ-20260913-001 建立）。
- 引入来源：REQ-20260913-001（构建模块「分支浏览」远端分组空态文案只有一句「（无远端分支：先「同步远端」或推送本地分支）」，未区分「远端仓库确实为空」与「本地尚未同步」，也无解释提示）。
- 创建：2026-09-14T03:57:22.995Z。

## 现象

构建模块「分支浏览」子页「远端」分组显示灰字「（无远端分支：先「和远端同步」或推送本地分支）」（scripts/web/build.js 约 1021 行，`renderBranchesPane()`；文案所引导的「同步远端」按钮已由 BUG-20260914-005 更名为「⟳ 和远端同步」）。用户预期远端应有分支（origin 已配置且指向 GitHub 仓库），认为显示异常，无从得知为什么是空的。

排查核实（2026-09-14 会话定位，已对照源码与本仓库 git 状态，供开发阶段直接引用）：

- **显示链路无缺陷**：前端「远端」分组渲染 `state.branches.remote`（数据来自 `/api/build/branches`）；后端 `listBranches()`（scripts/lib/build-git.mjs 约 54–63 行）用 `git branch -r --format=%(refname:short)` 读本地远端跟踪引用（排除 `origin/HEAD`），如实反映本地 git 状态。
- **本仓库本地确无任何远端跟踪引用**：`git branch -r` 为空；`.git/refs/remotes/` 目录为空、packed-refs 无远端条目；`dev` 无上游（`git rev-parse --abbrev-ref dev@{upstream}` 报 no upstream）。
- **远端仓库确实为空**：`git remote -v` 显示 origin 已正确配置（github.com/adichou/agent-team-board，fetch/push 均指向）；但 `git ls-remote origin`（直接查询 GitHub）返回**无任何引用**——该 GitHub 仓库从未被推送过任何分支。
- **成因与 BUG-20260914-003 同源**：本仓库经 `ensureDevWorkflow()` 空仓库路径初始化，全部提交落本地 dev；`atb` 自动提交（run receipt / autocommit）只 commit 本地、从不 push；BUG-20260914-003 补建本地 main 时也明确不推送远端。因此远端始终为空。
- **落差本质**：「（无远端分支：…）」这句空态文案把两种语义不同的情况混为一谈——**远端仓库确实为空（从未推送）**与**本地尚未同步（远端有分支但没 fetch）**，本地只读 `git branch -r` 无法区分，界面也没有任何解释，用户误判为显示缺陷（本单即由此而来）。

## 复现步骤

前置：agent-team-board 仓库（远端 origin 已配置，GitHub 仓库为空，本地无远端跟踪引用——本仓库当前即此状态）。

1. 打开 Agent Team Board 看板（Web 或 Electron 端），顶栏切到「构建」页，切到「分支浏览」子页签。
2. 观察「远端」分组：仅显示灰字「（无远端分支：先「和远端同步」或推送本地分支）」。
3. 点「⟳ 和远端同步」（fetch --all --prune 成功，toast 回显「✓ 已同步远端（fetch --prune）」）后刷新：「远端」分组**仍**显示同一句空态——用户刚同步过远端却被告知「先和远端同步」，语义自相矛盾，且无法得知真实原因是「远端仓库为空」。
4. 终端对照：`git branch -r` 为空、`git ls-remote origin` 无任何引用——界面与 git 实际状态一致，即远端为空是事实，缺的是解释与区分。

## 期望行为

- **空态可解释、可区分**：远端分组为空时，界面应给出明确解释而非一句笼统文案。期望最终形态为以下方向之一或组合，具体由开发阶段 design.md 定案：
  - a. 文案区分：点「⟳ 和远端同步」成功后远端仍为空 → 提示「远端仓库尚无任何分支（从未推送）」并引导到「本地」分组的「推送」操作；未同步时的初始空态则引导「和远端同步」。
  - b. 状态自检：远端分组为空但 `git remote` 已配置时，附一行解释（如「本地无远端跟踪分支；若同步后仍为空，说明远端仓库为空」），说明两条出路（同步 / 推送）各自的含义。
- **不破坏既有口径**：分支列表仍如实反映本地 git 状态（`git branch -r`），只改空态解释，不引入自动 fetch / ls-remote 等隐式网络操作（分支浏览保持只读；同步远端仍是显式按钮）。
- **非 git 仓库 / 未配置远端** 的既有空态不受影响。

## 界面展示

可交互演示：[`./ui-demo.html`](./ui-demo.html)（单文件、内联 CSS/JS、无外网依赖，浏览器直接打开；数据为模拟，布局与交互按 scripts/web/build.js `renderBranchesPane()` / `doFetch()` 现行为复刻，并提供「缺陷现状 ↔ 期望修复后」对照开关与多场景切换）。

### 界面布局

- 构建模块「分支浏览」子页为左右分栏：左栏「分支列表」顶部是工具条（「⟳ 和远端同步」按钮 + 「刷新」次要按钮），下方依次为「本地」「远端」两个分组（灰字小号组头）。
- 「本地」分组：当前分支行加粗并带「当前」蓝色状态章；其余本地分支每行右侧有「推送」按钮。
- 「远端」分组：逐行列出 `origin/*` 远端跟踪分支；为空时整个分组只剩一句灰字小号空态文案——本 Bug 的位置。
- 右栏「提交记录」：默认显示「点击左侧分支查看提交记录」；点击任一分支后列出该分支最近提交（短 hash + 说明 + 作者 · 时间）。

### 交互行为

- 「⟳ 和远端同步」：执行期间按钮禁用、文案变「同步中…」；成功后 toast「✓ 已同步远端（fetch --prune）」并刷新分支列表，失败 toast「✕ 同步远端失败：<原因>」。分支浏览保持只读，同步是唯一的显式网络操作。
- 「推送」（本地分支行内）：弹出确认框（目标远端下拉 + 「该分支尚未建立上游跟踪：首推将加 -u 建立跟踪」提示），确认后 toast 回显「✓ 已推送 <分支> → origin/<分支>（已建立上游跟踪）」，远端分组随之出现对应 `origin/*` 行——这也是修复后空态引导用户走的出路。
- 点击任意分支行（含当前分支与远端分支）：右栏切换为该分支的提交记录。
- 演示页顶部提供场景切换（远端仓库为空 / 本地未同步远端有分支 / 正常已同步 / 读取失败）与「缺陷现状 / 期望修复后」对照开关，用于对比两种空态语义。

### 状态反馈

- 加载：进入子页或刷新时列表区显示「加载分支中…」。
- 失败：读取失败显示「分支读取失败：<原因>」+「重试」按钮（`role="alert"`）；同步失败经红色 toast 提示。
- 空态（本 Bug 核心，演示页可对照观察）：
  - 缺陷现状：远端为空时只有一句「（无远端分支：先「和远端同步」或推送本地分支）」，同步成功后仍显示同一句——「远端仓库为空」与「本地未同步」不可区分。
  - 期望修复后：未同步的初始空态提示「本地无远端跟踪分支」并引导「和远端同步」；同步成功后仍为空则提示「远端仓库尚无任何分支（从未推送）」并引导到本地分支「推送」（最终文案与形态以开发阶段 design.md 定案为准）。
- 操作结果一律经底部居中胶囊 toast 反馈（常规深色、失败红色，约 3 秒自动消失）；按钮执行期间禁用防重复触发。

## 验收标准

1. 本仓库当前状态（origin 已配置、GitHub 空、本地无跟踪引用）打开分支浏览：远端分组空态能解释「远端仓库为空（从未推送）」并引导推送；点「⟳ 和远端同步」成功后仍为空时，文案不再自相矛盾。
2. 正常有远端分支的仓库（本地已 fetch）：远端分组正常列出 `origin/*`，不出现新提示。
3. 本地未同步但远端有分支的仓库：空态引导「同步远端」，同步后分支出现。
4. 未配置远端（`git remote` 为空）的仓库：不出现「远端仓库为空（从未推送）」类误导提示。
5. 既有空态文案相关回归测试（scripts/tests/bug-branch-main-missing-20260914-003.test.mjs 约 183 行断言「（无远端分支」不回归）随文案调整同步更新并保持通过；build-ui.test.mjs 远端分支渲染断言不回归。

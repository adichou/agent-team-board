# BUG-20260912-004 操作提示出现多个已，请定位

- 状态：accepted（已接受；本条目处于完善阶段，仅补全文档，不改状态）
- 归属：独立 Bug
- 引入来源：REQ-20260911-005（经 `atb list` 核验真实存在，状态 done；该需求引入 `scripts/web/i18n.js`

- 创建：2026-09-12T02:11:47.601Z

## 现象

中文界面下，执行会弹出成功提示（toast）的操作后，提示文案中「已」字重复叠加。截图为在详情抽屉确认 BUG-20260912-003 完成后的提示，显示为：

> ✓ BUG-20260912-003 已已已已已已已已已确认完成

「已」连写 9 个，右侧带「撤销」按钮。「已」的个数不固定，随提示停留时间增长——每遍页面翻译重放多叠一个「已」。

影响面（Node 下对 i18n 模块实测复现）：

- 中文界面下所有以「✓ 」开头且含空格的动态提示均受累（✓ … 已接受 / 已移入计划 / 已移出计划 / 已确认完成 等）；
- 不以「✓ 」开头的提示不受影响（如失败提示「进展记录读取失败：…」、「↩ 已撤销 …，状态已回退」均实测稳定）；
- 英文界面不受影响（提示文案正确且稳定）。

## 复现步骤

1. 运行 `atb serve`，浏览器打开看板，界面语言为中文（默认，navigator 语言不含 en 即为中文）。
2. 打开任一可完成条目的详情抽屉，点击「确认完成」（或「接受」「移入计划」等会弹「✓ …」提示的操作），通过待人工决策防呆（如弹二次确认，选「仍要确认完成」）。
3. 页面顶部出现「✓ 条目号 已确认完成」提示，右侧带「撤销」按钮，停留 8 秒。
4. 保持页面打开不动：看板前端每 2 秒轮询重渲染（`scripts/web/app.js` 中 `setInterval(poll, 2000)`），每轮触发整页重翻译；提示每被重翻一遍就多一个「已」，数秒后即见「已已已…确认完成」（截图时已叠至 9 个）。
5. 等价的最小复现（无需等轮询）：浏览器控制台对 i18n 模块连调 `ATBI18N.t('✓ BUG-20260912-003 已确认完成')`，每调一次多一个「已」（已实测：第 1 次后 2 个，第 6 次后 7 个）。

## 期望行为

- 操作提示文案恒定为「✓ 条目号 已确认完成」（或对应动作文案），无论提示停留多久、页面轮询重渲染多少遍，「已」不重复、不丢失。
- 中英文往返切换（zh→en→zh）后提示文案不变形、不残留英文、不叠字。
- 其余「✓ 」开头提示（已接受 / 已移入计划 / 已移出计划 等）同样不叠字；失败、撤销等提示行为不变。

## 验收说明

1. 中文界面：详情抽屉点「确认完成」，提示出现瞬间文案恰为一个「已」（`✓ 条目号 已确认完成`）；提示停留满 8 秒自然消失，期间经至少 4 轮轮询重渲染后文案仍不变。
2. 中文界面：「接受」「移入计划」「移出计划」等操作的「✓ …」提示均不叠字。
3. 英文界面：提示显示 `✓ 条目号 confirmed done` 等英文文案；切换回中文后回译为「✓ 条目号 已确认完成」，往返一致。
4. 回归：不以「✓ 」开头的提示（失败提示、「↩ 已撤销 …」回执等）显示与消失行为不变；英文界面不受本次修复影响。
5. 既有口径保持：i18n 只译界面文案、不动用户数据（条目标题/描述/文档）；未命中词条保持原文的降级策略不变。

## 定位（完善阶段已查明，供开发参考）

- 元凶词条：`scripts/web/i18n.js` 动态词典（EN_DYNAMIC）中的泛化键 `'✓ ◇ 已◇': '✓ $1 $2'`（由 6f2ead6 提交随 REQ-20260911-005 引入）。
- 机制：反向词典（en→zh）把英文模板 `✓ $1 $2` 编译为锚定正则 `^✓ (.+?) (.+?)$`、回译模板 `✓ $1 已$2`。中文界面下，纯中文的「✓ 条目号 已…」提示并未经过英文翻译，却仍能被该正则命中并再套一次模板——每命中一次多补一个「已」。该词条「自匹配」：它的译文（仍以「✓ 」开头且含空格）依旧满足它自己的正则，形成每遍翻译叠一个「已」的自馈循环。
- 放大器：看板每 2 秒轮询重渲染 → MutationObserver → scheduleTranslate → translateTree(document.body) 重放整页翻译（`scripts/web/i18n.js`），仍在显示中的 toast 文本节点随之被反复重翻；带「撤销」按钮的提示停留 8 秒（`scripts/web/app.js` toast 组件），足以叠出连续多个「已」。
- 生成源无责：提示模板本身正确——详情抽屉路径 `✓ ${id} 已${label}`（`scripts/web/app.js` drawerAction，约 2782 行），待决策卡路径 `✓ ${id} 已确认完成`（holdCardConfirmDone，约 2934 行）；重复发生在 i18n 翻译层，不在业务拼接处。
- 修复方向（开发阶段定案）：让该反向模式不再自匹配（如第二个捕获组排除以「已」开头的文本），或为这些提示补精确的双向词条，或遵循词典「未命中保持原文」降级原则——对已含中文的文本跳过反向匹配；修复后按上方验收说明回归中英文两个界面。

## 界面展示

- 界面元素：页面顶部居中的操作提示条（toast），深色圆角长条——左侧「✓ 条目号 + 动作文案」，右侧可选「撤销」描边圆角按钮；普通提示 3.2 秒自动消失，带「撤销」的停留 8 秒；失败提示呈红色（err）形态。
- 缺陷形态：中文界面下「✓」与动作词之间的「已」随停留时间不断叠加（见上方截图）。
- 期望形态：文案稳定为「✓ 条目号 已确认完成」，不随时间与轮询次数变化。
- 可交互演示：[./ui-demo.html](./ui-demo.html)（单文件、内联 CSS/JS、无外网依赖、浏览器直接打开）。演示对照展示「缺陷现象」与「修复后状态」两种形态，可手动「重放翻译」直观看到叠字过程，并覆盖提示条的正常（成功）/失败/加载中/空态等状态反馈与深浅色适配。

# BUG-20260921-007 分支浏览中的分支提交记录在第三页后就无法显示数据了，请修复。而且第二页的 dev 分支应该是黄色的，却变成了蓝色，请修复。

- 状态：submitted（待人工接受）
- 归属：独立 Bug（引入来源见 design.md）
- 创建：2026-09-21T01:57:33.302Z

## 现象

看板 Web 界面「发布」模块 →「分支浏览」页签，左侧选中分支（main 或 dev，两支并存时为并集视图）后，右侧展示提交记录（提交树 + 分页条，默认 50 条/页）。存在两个缺陷：

1. **翻到第 3 页及以后无数据**：第 1、2 页提交记录正常显示，从第 3 页起提交记录区域不再显示任何数据（用户原话「无法显示数据了」；空白区域与分页条的具体残留表现：待确认，可人工复核）。
2. **第 2 页起 dev 泳道变色**：第 1 页双泳道配色正确——主分支（main）泳道为蓝色、dev 泳道为黄色（`--git-lg0` / `--git-lg1`，与降级列表徽标 `bt-main` / `bt-dev` 同源）；从第 2 页起 dev 泳道变为蓝色，不符合 BUG-20260920-002 确立的「按 side 稳定配色：同 hash 恒同色，翻页 / 搜索不跳变」口径。

**已核实的事实（登记时排查，供开发阶段参考）**：

- **数据层无截断**：以本仓库实测（main∪dev 并集共 387 条提交、50 条/页共 8 页），`/api/build/branch-log`（`scripts/lib/build-git.mjs` 的 `branchLog` → `git log -n <limit> --skip <offset>`）在第 1–8 页均正常返回满页数据，无空页、无重复、无缺口。即「第 3 页后无数据」不是数据层问题，症状指向前端渲染环节；具体根因待确认（排查线索：提交树由 vendored `@gitgraph/js` 渲染，其绘制经 `setTimeout` 异步调度（`next()`），若渲染异常发生在异步回调内，将逃逸 `mountTree`（`scripts/web/build.js`）的同步 try/catch 降级，`#bldTreeBox` 保持空白且不落入 `fallbackTreeHtml` 行式列表——该线索待开发阶段证实或推翻）。
- **变色机理（代码读证）**：`treeData`（`scripts/web/build.js`）只把「当前页内命中的分支头 hash」转成 gitgraph refs；第 1 页含 main/dev 两支头 → 图内两个分支，gitgraph 按分支创建顺序分配泳道色（第 1 支取 `colors[0]` 蓝、第 2 支取 `colors[1]` 黄），dev 恰为黄色；第 2 页起两支头 hash 均不在页内 → 图内只剩本页首行标注的所选分支名单支 → 恒取 `colors[0]` 蓝色。且 `treeData` 未使用服务端逐提交附带的 `side` 字段（`side` 仅用于降级列表徽标），树模式天然无法维持 side 稳定配色。

相关条目线索（编号已经仓库条目目录核验存在）：REQ-20260921-002（提交树引入 vendored `@gitgraph/js`）、BUG-20260920-002（双支并集与 side 稳定配色口径）、BUG-20260914-009（提交记录分页）、REQ-20260920-001（历史拓扑图）。

## 复现步骤

前置条件：项目为 git 仓库，本地 main 与 dev 两支并存（选中任一即进入并集视图），分支提交总数足以翻过 2 页（默认 50 条/页时 > 100 条；不足时可把「每页条数」切到 20 条/页）。

1. 启动看板 Web 界面，顶部导航进入「发布」模块，切到「分支浏览」页签。
2. 左侧「本地」分组点击 dev（或 main）：右侧显示「并集视图」提交记录，第 1 页正常——两条泳道，主分支为蓝色、dev 为黄色（本页含 main/dev 两支头标签）。
3. 点击分页条「下一页」（或页码 2）：第 2 页数据仍显示，但 dev 泳道（含其分支名标签）由黄色变为蓝色——缺陷二。
4. 继续翻到第 3 页及以后：提交记录区域不再显示任何数据——缺陷一。
5. 辅助核验（可选，人工复核时确认）：开发者工具 Network 面板中 `/api/build/branch-log?branch=…&limit=50&offset=100`（及更大 offset）响应是否仍含 `commits` 数据；Console 面板是否有未捕获异常。此两项的实测表现：待确认。

## 期望行为

1. **分页全程有数据**：在 1 至末页之间任意翻页（含「上一页 / 下一页 / 页码 / 切换每页条数」），提交树均渲染对应区段的提交；若树渲染异常，必须降级为行式列表（`fallbackTreeHtml`）保底展示，不允许出现空白内容区。
2. **泳道配色稳定**：dev 泳道恒为黄色（浅色 `#d97706` / 深色 `#fbbf24`，即 `--git-lg1`），主分支泳道恒为蓝色（浅色 `#2563eb` / 深色 `#60a5fa`，即 `--git-lg0`）；同一提交在任何页码、搜索（高亮定位 / 过滤）模式下颜色一致，页间来回切换、刷新后不跳变（BUG-20260920-002 口径）。
3. **既有口径不受影响**：分页条「第 x–y 条 / 共 N 条」进度、页边界提示「父提交在后续页，轨道继续；此处不是历史起点。」、末页「已到末尾 · 共 N 条提交（可翻至分支首个提交）」、切换每页条数回第一页、翻页失败保留旧内容 + 行内错误 + 重试（BUG-20260914-009 口径）、深浅色跟随系统重画树。

## 验收说明

- **数据显示**：在 main 与 dev 并存的仓库（本仓库即满足：并集 387 条、50 条/页共 8 页）逐页翻至末页，每页均渲染本页提交（前 7 页各 50 条、末页 37 条），无空白页；切到 20 / 100 条/页后同样逐页有数据；「上一页」回翻正常。
- **配色稳定**：任意页码下 dev 泳道恒黄、主分支泳道恒蓝（浅 / 深色两套色板各自稳定）；页间来回切换、点「刷新」重载当前页后颜色不跳变；搜索两模式（高亮定位 / 过滤（保留祖先））下同样不跳变。
- **降级保底**：人为制造树渲染异常（或 vendor 加载失败）时，提交记录以行式列表保底展示，不出现空白（验证方式由开发阶段测试设计确定）。
- **回归**：第 1 页 main/dev 双分支头标签显示不受影响；降级列表 `bt-dev` / `bt-main` 徽标配色不受影响；相关既有测试（BUG-20260914-009 分页、REQ-20260914-002 搜索、REQ-20260921-002 提交树、BUG-20260920-002 双支并集口径）随 `npm test` 全量通过。

## 界面展示

可交互演示：[./ui-demo.html](./ui-demo.html)（单文件、无外网依赖，浏览器直接打开；以开关对照展示「缺陷复现」与「修复后」两种状态）。

- **界面布局**：复刻「发布 → 分支浏览」两栏布局——左栏为分支列表（工具行「⟳ 和远端同步 / 刷新」、「本地」分组（dev 当前 + main）、「远端」分组（origin/dev、origin/main））；右栏为提交记录区：头部行（分支名 + 搜索控件 + 刷新）、并集视图提示行、选中提交详情行、提交树（双泳道 SVG：圆点 + 泳道线 + 分支名标签 + message + 短 hash）、页边界延续提示 / 末尾提示、底部分页条（上一页 / 折叠页码 / 下一页 / 每页条数 20·50·100 / 「第 x–y 条 / 共 N 条」）。
- **交互行为**：点左侧分支切换并回第一页；点分页条页码 / 上一页 / 下一页翻页（每次加载有短暂「加载提交记录中…」过渡）；切换每页条数回第一页；点提交行在顶部详情行显示该提交（短 hash + message + 父提交 + 合并标识）；关键词搜索对当前页高亮定位并可一键清除；「刷新」重载当前页。
- **状态反馈**：正常（满页数据 + 进度计数 + 页边界 / 末尾提示切换）、空（「该分支暂无提交」）、加载（「加载提交记录中…」，可驻留观察）、失败（首次读取失败显示「提交记录读取失败：…」；翻页失败保留旧内容 + 行内错误 + 重试）四种接口状态可切换；顶部「缺陷复现 / 修复后」开关对照展示——缺陷态：第 2 页起整树只剩单条蓝色泳道（dev 变蓝）、第 3 页起内容区空白；修复态：任意页 dev 恒黄、主分支恒蓝，各页均有数据。深浅色跟随系统（可选适配）。

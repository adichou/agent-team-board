# 设计 — BUG-20260921-007 分支浏览中的分支提交记录在第三页后就无法显示数据了，请修复。而且第二页的 dev 分支应该是黄色的，却变成了蓝色，请修复。

> 由 Agent 在 /dev 开发前补充，人可随时批注。

## 引入来源（源单）

- 引入来源：REQ-20260921-002（提交树升级为 vendored `@gitgraph/js` 渲染时，`treeData` 只把「当前页内
  命中的分支头 hash」转成 gitgraph refs，未处理分页 / 搜索子集下 gitgraph 的可达过滤与泳道配色语义；
  分页能力本身来自 BUG-20260914-009，编号已经 `atb list` 核验存在）

## 根因分析

两缺陷同源，均为 vendored `@gitgraph/js` 1.4.0 的渲染语义与「分页 / 搜索子集数据」不匹配（读证 + 本机
真实仓库复现量化，非数据层问题——`/api/build/branch-log` 各页均满页返回）：

1. **第 3 页起无数据（可达过滤静默丢提交）**：gitgraph `import()` 渲染时只保留「从分支 ref 沿
   parents[0] 首父链可达 ∪ 合并行次父闭包」的提交，其余提交被**静默丢弃**（不抛异常）。旧 `treeData`
   只把「页内命中的分支头 hash」转为 refs：第 1 页两支头都在页内 → 覆盖良好；第 2 页起页内无任何 ref
   → 仅剩合并闭包覆盖，其余全丢。本仓库实测（main∪dev 并集 399 条、50 条/页）：第 3 页 50/50 全丢
   （界面空白），第 2/4/5/6/7 页分别丢 7/17/39/47/2 条。丢弃发生在 vendor 的 `setTimeout` 异步渲染
   内，逃逸 `mountTree` 同步 try/catch，降级行式列表也不触发 → 空白内容区。main 单支视图第 2 页起
   同理丢提交（9/46/1/39…）；dev 单支本仓库历史近似线性未复现，但机理相同。
2. **第 2 页起 dev 泳道变蓝（泳道色按页内出现顺序分配）**：gitgraph 泳道色 = `colors[分支名在渲染
   序列中的首次出现序]`。第 1 页 main/dev 两支头都在页内 → 两支两色恰为蓝/黄；第 2 页起页内无 ref
   → 全部提交落入 DELETED 分支（或单支）→ 恒 `colors[0]` 蓝。另有两处加剧因子：页内首次出现顺序
   本身随翻页跳变；仅一侧在页时（本仓库现状第 1 页被更新的 dev 提交占满）该侧占 0 号位。

## 方案

不改动 vendored 库（licenses.md 口径不变），全部在 `scripts/web/build.js` 适配层修复：

1. **`treeData` 双支 side 锚定 + 严格同侧链**（heads ≥2 且行带 side 的并集载荷）：每侧以「本页该侧
   最新行」为锚（heads 命中页内即头行，第 1 页行为不变）；`parents[0]` 改写为**严格同侧显示序链**
   （下方最近同侧行；同侧真实父可能跳过交错的同侧段行，以真实父为首父会留下不可达行 = 缺陷一根因），
   真实父（同侧跨行 / 跨侧）保留为附加父（合并 / 分叉曲线仍由 gitgraph 绘制）；最老 main 行补挂
   主分支名锚钉 ref 写入序，使共享历史 `branchToDisplay` 恒主分支名。整页提交从本侧锚首父可达，
   零丢弃（结构保证）。
2. **`treeData` 单支保真 + 页外断层续锚**（无 side 载荷）：parents 仍按集合内截断保真
   （REQ-20260920-001「不虚构父边」口径不变）；镜像 gitgraph 可达语义（锚首父链 ∪ 合并闭包）找出
   未覆盖的断层泳道顶（其合并提交在更早页），以「分支名·n」续锚补覆盖——第 3 页起空白的单支形态
   由此杜绝。
3. **泳道配色钉定**：双支 `createGitgraph` 传 `compareBranchesOrder`（gitgraph 原生选项）钉
   main 恒 0（`--git-lg0` 蓝）/ dev 恒 1（`--git-lg1` 黄）；色板按「本页出现的 side」排头（仅 dev
   在页 → dev 色打头，杜绝单分支占 0 号位错染）；单支用单色板（含续锚泳道同色，翻页 / 搜索 /
   刷新不跳变）。深浅色仍两套色板跟随系统重画。
4. **异步渲染保底**（期望 1 的「不允许空白内容区」）：`mountTree` 在 `import()` 后注册一个更晚的
   核查 tick（同延迟 FIFO，晚于 vendor 渲染 tick）：树容器无 SVG 或提交圆点数不足（含「提交被静默
   丢弃」类故障）即降级 `fallbackTreeHtml` 行式列表；渲染成功则补挂高亮 / 选中 / 合并标识
   （`decorateTree` 在异步渲染完成后才有效，顺带修正其生效时机）。
5. 回归口径：降级列表 `bt-main`/`bt-dev` 徽标、merge-base 标注、页边界提示、分页条、翻页失败
   保留旧内容 + 重试等既有行为均不变；`fallbackTreeHtml` 与详情 / 合并标识继续用原始 parents 数据。

**开源选型（REQ-20260909-015）**：未引入新开源库，复用既有 vendored `@gitgraph/js` 1.4.0（REQ-20260921-002
已维护 licenses.md）；不修改 vendor 源码，修复全部落在自研适配层 `scripts/web/build.js`。

## 风险与边界

- **同侧链改写仅限双支并集载荷**（行带 side）：单支 / 无 side 载荷 parents 全保真，既有
  「不虚构父边」测试口径（REQ-20260920-001 G 组）零回归；双支模式下泳道为「按 side 归并的双泳道
  模型」，同侧多段（如被合并进主侧的旧 dev 段）折入本侧泳道，合并 / 分叉曲线经附加父保留。
- **钉 ref 写入序依赖 vendor `import()` 的旧→新处理序**（已读证 + 真实数据验证）：仅影响共享历史行
  的 `branchToDisplay` 取主侧名，与配色比较器双保险。
- 断层续锚标签（「分支名·n」）为泳道继续的可见标识，属标识不是文案（不进 i18n 词典）。
- 真实数据终验（本仓库）：union 8 页 399 条 / main 7 页 342 条 / dev 7 页 347 条、20 与 100 条/页、
  filter 搜索闭包子集 —— 覆盖缺口全部为 0，dev 恒黄 / main 恒蓝零错染。

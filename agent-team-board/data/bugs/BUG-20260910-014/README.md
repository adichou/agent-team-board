# BUG-20260910-014 批量 Commit 功能需要有 UI

- 归属：独立 Bug
- 创建：2026-09-10T07:21:55.097Z
- 当前状态以系统记录为准；本文不维护状态。

## 现象

任务模块缺少批量 Commit 类型，用户无法通过看板发现、启动及查看该类任务；需求模块的已完成条目缺少是否提交标记、提交号与复制入口。原始诉求为增加任务类型，并让已完成需求默认显示「未提交」，执行批量 Commit 后显示提交号且可复制。

已核实的代码依据：`scripts/web/app.js` 的任务类型筛选与 `GLOBAL_KIND_LABEL` 仅列出 develop/refine；`scripts/atb.mjs` 已有 `commit create/next/check/records` 等 CLI；`scripts/lib/commit-store.mjs` 的 `listCommitRuns` 已返回条目编号、result、reason 与 commits 数组。因此本单补齐已有批量提交能力的 UI。浏览器现场版本、用户实际批次与截图待确认；未在本次完善中执行真实提交。

## 复现步骤

1. 在当前项目打开 Status Board，进入「任务」模块，查看任务类型选择与创建入口。
2. 检查是否能选择「批量 Commit」并查看该类型的批次与逐项结果。当前代码只定义批量开发/完善类型。
3. 进入「需求」模块的已完成需求列表及详情，检查是否显示「未提交/已提交」、提交号和复制按钮。
4. 在后续修复验证环境中准备已有成功 Commit 账本的已完成需求，刷新列表并打开详情，核对是否能找到和复制对应提交号。具体现场数据待确认；验证不得以本项目真实提交作为文档完善操作。

## 期望行为

- 任务模块增加与批量完善、批量开发并列的「批量 Commit」类型，展示当前项目批次编号、任务状态、进度、当前条目及逐项结果。支持创建任务并取得派发提示词，沿用现有人工启动流程；浏览任务或切换项目本身不会触发提交。
- 已完成需求默认显示「未提交」。有经核验的成功提交记录后显示「已提交」及对应提交号，列表和详情一致，刷新后保持。一个条目可能有多个提交号，必须可展开全部并分别复制完整 hash。
- 失败、跳过或仅创建任务不能标记已提交；保留已有成功记录，并展示新一轮失败原因。查询失败时显示「提交状态加载失败」，不能伪装成未提交。
- 创建中禁用重复提交按钮；无候选时明确说明并禁止启动；运行时显示进度，失败时显示原因和重试读取入口。提交只作用于本地 Git，沿用底层归因、幂等和回执核验规则。

## 界面展示

[打开交互演示](./ui-demo.html)（离线单文件，全部数据为模拟，不执行 Git 或调用服务）。

- 布局：顶部在任务/需求间切换；任务页类型区加入批量 Commit，下方依次为批次状态、创建入口和逐项结果；需求页已完成列表右侧显示提交状态、hash 及复制操作。
- 交互：选择缺陷/修复后模式对照；切换正常、空、加载、失败场景；点击创建模拟任务后显示执行中与成功回执；需求行支持展开多个 hash、复制完整 hash，复制失败可手动选择。
- 状态反馈：正常状态展示未提交与成功记录；空状态提示无候选/无已完成需求；加载禁用创建与复制；失败提示重试，不抹掉成功历史；复制成功或失败均提供可读反馈。

## 验收说明

- [ ] 任务模块可选择批量 Commit，创建后可见批次、状态、当前条目与记录；人工复制派发提示词可操作，重复点击不会重复创建。
- [ ] 无成功记录的已完成需求显示未提交；成功回执核验后显示已提交和真实完整 hash；刷新、列表/详情切换与项目切换后不串项目数据。
- [ ] 多 hash 条目可查看并逐个复制完整值；复制成功有反馈，剪贴板权限失败有手动复制提示，不误报成功。
- [ ] 失败或跳过不新增成功标记；已有成功记录不会因后续失败消失；加载失败有明确错误与重试入口。
- [ ] 空、加载、失败和正常场景均可辨识，运行中不会误触重复创建；只浏览 UI 不执行 Git，不自动 push。
- [ ] 使用隔离测试仓库核对显示值与成功账本/Git 记录一致；本次演示仅用于界面验收讨论，不代表修复已实现。

## 待确认

- UI 是否开放 include-reported、自选条目及其他 CLI 高级选项待确认；默认以当前 CLI 的 done 候选口径为基线。

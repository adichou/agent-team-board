# 设计 — BUG-20260914-011 和远端同步是指先 fetch，然后 push，确保本地和远端的记录一模一样

> 由 Agent 在 /dev 开发前补充，人可随时批注。

## 引入来源（源单）

- 引入来源：REQ-20260913-001（已核验存在于看板，状态 done）。

REQ-20260913-001 落定「同步远端」= 仅 `fetch --all --prune` 的单向口径，推送作为独立显式
操作（分支行「推送」按钮）。BUG-20260914-005（done）把按钮更名为「和远端同步」后，名称的
「双向对齐」语义与仅 fetch 的实现之间落差被放大——本单即该原始口径在新名称下的暴露。

## 根因分析

「和远端同步」按钮的执行链自 REQ-20260913-001 起只有拉取半程：

- 前端 `scripts/web/build.js` `doFetch()`（#bldFetchBtn）→ `POST /api/build/fetch`；
- 服务端 `scripts/server.mjs` 直接映射 `buildGit.fetchRemote(root)`；
- 数据层 `scripts/lib/build-git.mjs` `fetchRemote()` 只执行 `git fetch --all --prune`，
  全程不上传任何本地提交。推送只有分支行「推送」按钮（`POST /api/build/push`）一个手动入口。

用户按「和远端同步」的字面语义（两边记录一致）操作后，本地领先的提交并未上传，名不副实。

## 方案

同步语义改为**先 fetch、后 push**，推送范围按以下口径落定（README「待确认」三候选的裁定）：

**推送范围 = 除 main 外的全部本地分支**（含当前分支与功能分支；未建上游的首推 `-u`
建立跟踪）。理由：

1. 满足用户主诉求「本地和远端的记录一模一样」——开发分支全部上传，无需逐个手点；
2. **main 排除**：与 REQ-20260913-001 design.md「发布是推送远端，构建是本地集成分支，语义
   不同」及关联单 BUG-20260914-012（去掉 main 分支行推送按钮，main 推送归发布模块
   release-git 七阶段流水线受控）治理口径一致——若同步连 main 一起推，012 的按钮治理即被
   绕过、两单矛盾；排除后两单自洽（构建模块只推开发分支，main 永远走发布模块）；
3. 不采用「仅已建上游分支」（本仓库现状远端为空、dev 无上游，该口径下用户场景得不到
   解决）；不采用「仅当前分支」（功能分支仍需逐个手点，与「一模一样」诉求不符）。

分层实现：

1. **数据层** `build-git.mjs` 新增 `syncRemote(root, { remote })`：
   - 前置校验沿用既有口径（非 git 仓库 / 远端名不合法 → AtbError）；
   - 远端选择：未传 remote 时 origin 优先、否则取已配置远端第一个；未配置远端报错引导；
   - 第一步 `git fetch --all --prune`（保留清理失效引用口径，失败即整体抛错、不进推送）；
   - 第二步逐分支复用 `pushBranch()` 推送除 main 外的全部本地分支：单分支失败不中断
     其他分支，结果逐条收集（成功 / 失败含原因 / main 跳过），不用 `--force`、不强推；
   - 返回 `{ ok, remote, pushed[], failed[], skipped[] }`，`ok = failed.length === 0`。
2. **服务端** `server.mjs`：`POST /api/build/fetch` 替换为 `POST /api/build/sync` →
   `buildGit.syncRemote(root)`（旧接口无其他调用方，语义已变不留误导入口）。
3. **前端** `build.js` `doFetch()` 改造（按钮 id 保留 `#bldFetchBtn`）：
   - 调 `/sync`；fetch 失败 toast 维持「✕ 同步远端失败：<原因>」；
   - 成功 toast 汇总两步：「✓ 已同步远端：fetch 完成，已推送 dev、feat → origin」；
     全部跳过（本地仅 main）时说明无可推送分支；存在失败分支时错误 toast 列明分支与原因
     （不静默，可重试）；
   - `state.lastSync` 记录本次推送结果供空态细分；
   - 防重沿用 `syncBusy`（执行中禁用显示「同步中…」）。
4. **空态与文案联动**（BUG-20260914-006 口径在新语义下复核）：
   - 同步含 push 后「推送成功 ⇒ 远端必非空」，故「同步成功后仍为空」的确定性解释按推送
     结果细分：有失败分支 → 解释推送失败并引导重试 / 逐分支推送；无任何可推分支
     （本地仅 main）→ 说明 main 由发布模块管理、可对开发分支手动推送；
   - 悬停提示更新为 fetch+push 双动作描述；`i18n.js` 新增静态整句词条（悬停提示、空态
     解释），动态 toast（含分支名列表）沿用既有「不进词典」模式（如「✓ 已推送 X → Y」）。

**开源选型（REQ-20260909-015）**：本修复为既有分层（build-git / server / build.js / i18n）
内的小幅扩展，全部动作由本机 git CLI 完成，无合适开源库可替代该内部结构整合，不引入新依赖，
无需 licenses.md。

## 风险与边界

- 不引入 pull / rebase / merge / 删远端分支 / `--force` 等写操作；远端领先（非快进被拒）
  时该分支计入 failed 并展示 git 原始原因，不自动改写本地历史（`build-git.mjs` 头注释
  「除此外不提供任何 git 写操作」口径同步修订为「fetch + push」）；
- 多远端仓库：fetch 固定 `--all`（现状），push 目标 origin 优先（与分支行推送确认框的
  默认远端一致），非 origin 唯一远端时取第一个并在结果中回报远端名；
- 分支名经 `assertRefName` 既有校验（防参数注入）；`pushBranch` 的远端未配置 / 分支
  不存在等错误按分支收集进 failed，不掩盖其他分支结果；
- BUG-20260914-012 未实施前，分支行 main「推送」按钮仍存在（属 012 范围）；本单只保证
  「和远端同步」不推 main，两单口径已对齐；
- 既有断言（005 文案 / 006 空态 / build-serve S9、S10 fetch 接口）随语义同步更新。

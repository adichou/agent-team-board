# BUG-20260914-011 和远端同步是指先 fetch，然后 push，确保本地和远端的记录一模一样

- 状态：accepted（已接受）
- 归属：独立 Bug（引入来源见 design.md；涉及界面为构建模块「分支浏览」子页，由 REQ-20260913-001 建立）
- 创建：2026-09-14T05:23:27.070Z

## 现象

构建模块「分支浏览」子页签中，分支列表顶部工具栏的「⟳ 和远端同步」按钮**只做 fetch（拉取），不做 push（上传）**，点击后本地与远端的记录并不一致——与按钮名称「和远端同步」给用户的预期（先 fetch 再 push，两边记录一模一样）不符。

现状链路（均经源码核实）：

1. **按钮与交互**：`scripts/web/build.js` `renderBranchesPane()`（按钮 `#bldFetchBtn`，约 1050 行）默认态显示「⟳ 和远端同步」，悬停提示「fetch --all --prune：拉取远端最新并清理失效引用」；执行中按钮禁用显示「同步中…」，完成后恢复。
2. **前端逻辑**：`doFetch()`（约 661 行）请求 `POST /api/build/fetch`，成功后 toast「✓ 已同步远端（fetch --prune）」并刷新分支列表与提交记录——**全程没有任何推送动作**。
3. **服务端与数据层**：`scripts/server.mjs`（约 2191 行）把 `POST /api/build/fetch` 直接映射到 `buildGit.fetchRemote(root)`；`scripts/lib/build-git.mjs` `fetchRemote()`（83–90 行）只执行 `git fetch --all --prune`（下载远端引用 + 清理失效远端分支引用），**不上传本地任何提交**。
4. **推送是另一个手动入口**：目前只有「本地」分组每个分支行上的「推送」按钮（`data-push`）→ 确认弹窗（`renderPushConfirm()`，区分首推 -u 建立跟踪 / 更新已有远端分支）→ `doPush()` → `POST /api/build/push` → `pushBranch()`。用户点完「和远端同步」以为两边一致了，实际本地提交仍未上传。

实际落差（本仓库当前即此状态，2026-09-14 核实）：本地 `dev` 分支已有 53 个提交、`main` 有 1 个提交，远端 origin（github.com/adichou/agent-team-board）**一个引用都没有**（`git ls-remote origin` 为空，`main` 上游显示 `[origin/main: gone]`）。此时点「⟳ 和远端同步」：fetch 成功（远端为空、无内容可拉）、toast 报「✓ 已同步远端」，但远端依旧为空——**本地远端记录完全不同，"同步"名不副实**。

口径沿革（供开发归因）：REQ-20260913-001 落定「同步远端」= 仅 fetch 的单向口径，推送是独立显式操作；BUG-20260914-005（done）把按钮更名为「和远端同步」后，名称的"双向对齐"语义与仅 fetch 的实现之间的落差被放大，本单即用户据此提出：**和远端同步 = 先 fetch、再 push，确保本地和远端的记录一模一样**。

## 复现步骤

前置：一个 git 仓库项目，本地分支有提交、远端为空或落后于本地（agent-team-board 本仓库当前即满足：origin 已配置、远端无任何引用、本地 dev 领先）。

1. 启动看板：项目目录终端运行 `atb serve`（默认端口 8888，`ATB_PORT` 可覆盖），浏览器打开 `http://localhost:8888`，顶栏项目选择器选中该 git 仓库项目。
2. 顶栏切到「构建」模块，切到「分支浏览」子页签。
3. 观察初始状态：「本地」分组列出 `dev`（当前）、`main`；「远端」分组为空态提示（BUG-20260914-006 的解释：「远端仓库尚无任何分支（从未推送）…可在上方「本地」分组对分支点「推送」…」）。
4. 点击「⟳ 和远端同步」：按钮禁用显示「同步中…」，随后 toast「✓ 已同步远端（fetch --prune）」，分支列表与提交记录刷新。
5. **实际结果**：「远端」分组**仍为空**；终端对照 `git ls-remote origin` 依旧返回空——本地 53 个 dev 提交没有被上传，本地与远端记录完全不一致，与「和远端同步」的语义相悖。
6. 要真正让远端出现这些分支，只能再对每个本地分支逐个点「推送」并确认——用户预期这一步应由「和远端同步」一并完成。
7. 边界确认（远端落后场景）：在远端落后本地的仓库（远端分支存在但落后）重复上述操作，fetch 后远端跟踪引用不变（远端本就落后），本地新提交同样不会被推送——「同步」永远只拉不推。

## 期望行为

- **同步语义改为「先 fetch、后 push」**：点「⟳ 和远端同步」先执行 `git fetch --all --prune`（保留清理失效引用口径），随后推送本地分支，使本地与远端的分支记录一致（远端出现/更新与本地相同的分支与提交）。
- **推送范围口径待确认**（由开发阶段 design.md 落定，候选方向）：
  - a. 推送全部本地分支（逐一 `push`，未建上游的首推 `-u` 建立跟踪）；
  - b. 仅推送当前分支（本仓库日常工作流即 dev）；
  - c. 仅推送已建立上游跟踪的分支，另保留逐分支手动首推。
- **结果反馈可分辨**：toast / 行内反馈汇总 fetch 与 push 两步的结果（如「✓ 已同步：fetch 完成，已推送 dev、main → origin」）；push 失败（网络、权限、非快进被拒等）不静默——列明失败分支与原因，fetch 成功的拉取结果仍生效展示，整体可重试。
- **执行中防重**：沿用既有口径——同步执行中按钮禁用显示「同步中…」，完成后恢复；期间不并发触发推送。
- **不越界**：不引入 pull / rebase / merge / 删远端分支等写操作（`build-git.mjs` 头注释「除此外不提供任何 git 写操作」口径需随修复同步修订为「fetch + push」）；若远端领先本地（push 非快进被拒），只明确报错并说明需人工处理（如何引导**待确认**），不自动改写本地历史。
- **关联文案与状态联动复核**：
  - 悬停提示（现「fetch --all --prune：拉取远端最新并清理失效引用」）、成功/失败 toast、`scripts/web/i18n.js` 英文词条（现 `'⟳ 和远端同步': '⟳ Sync with remote'`）随新语义更新；
  - BUG-20260914-006 的空态解释依赖 `remoteSynced`（同步成功后远端仍空 ⇒ 远端仓库为空）：同步含 push 后，「推送成功 ⇒ 远端必非空」，该断言与空态文案需按新口径复核自洽；
  - 与 BUG-20260914-012（去掉 main 分支推送按钮）的边界需协调：若同步推送全部本地分支，逐分支「推送」按钮的存废/去留在两单中需口径一致（**待确认**）。
- **非 git 仓库 / 未配置远端**：保持现有错误与引导（「项目不是 git 仓库：请先初始化 git…」等），不因语义调整回归。

## 验收说明

1. **核心场景（本仓库现状即可验证）**：本地 dev/main 有提交、远端为空时，点「⟳ 和远端同步」→ fetch 成功且本地分支被推送——终端 `git ls-remote origin` 出现对应分支引用、界面「远端」分组列出 `origin/dev` 等，toast 汇总成功信息；本地与远端记录一致。
2. **稳态幂等**：两边已一致时再次同步：fetch 无更新、push 报 up-to-date，不报错、无重复推送副作用，记录保持一致。
3. **失败可分辨、可重试**：构造推送失败（断网 / 远端仓库拒绝 / 远端领先非快进）：反馈明确区分 fetch 与 push 结果、列明失败分支与原因；fetch 拉到的新远端分支仍出现在列表中；恢复后重试成功。
4. **防重与反馈**：同步执行中按钮禁用显示「同步中…」，不可重复触发；完成后按钮恢复、分支列表与提交记录自动刷新。
5. **边界不越界**：远端领先的分支不被强推（不使用 `--force`），本地历史不被改写；不出现 pull / rebase / 删除远端分支等额外写操作。
6. **空态与关联文案自洽**：BUG-20260914-006 的「远端仓库尚无任何分支」空态在新语义下逻辑成立（有本地分支且推送成功后远端必非空；仅无本地分支或推送失败时仍为空）；悬停提示、toast、空态提示、英文界面（i18n）均与新语义一致，无旧口径残留。
7. **错误路径回归**：非 git 仓库、未配置远端时错误提示与现状一致。
8. **测试同步**：既有断言（`scripts/tests/bug-sync-btn-wording-20260914-005.test.mjs` 对 toast「已同步远端」等现状串的断言、`bug-remote-empty-explain-20260914-006.test.mjs` 空态断言）随实现同步更新；`node scripts/tests/run-all.mjs` 全量通过。

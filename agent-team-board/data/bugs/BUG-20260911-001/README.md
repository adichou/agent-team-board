## 现象

用户再次反馈 BUG-20260910-018「排序下拉组件没有和搜索框平齐」仍未解决。原单明确“平齐”指排序在左、搜索在右、左右相邻且高度一致。本单承接该可见结果要求，不以先前修复上报或样式声明存在作为关闭依据。

### 已核实事实与待确认项

- [原单 README](../BUG-20260910-018/README.md)记录上述人工定义；[原单测试报告](../BUG-20260910-018/test-report.md)已上报定位组搜索框 `min-width: 0` 的修复及自动测试通过。该报告不证明本次用户所见页面已满足要求。
- 当前 `scripts/web/index.html` 的 `#locateGroup` 内已有 `#reqSort` → `.module-search` 顺序。
- 当前 `scripts/web/style.css` 已在定位组作用域内为两组件设置 `height: 32px`，搜索组已有 `min-width: 0`，但定位组仍声明 `flex-wrap: wrap`，搜索组仍有 `flex: 0 1 380px`。这些是排查线索，不能据此断言本次复发根因。
- `scripts/web/app.js` 的 `syncReqSortVisibility` 控制需求模块且已初始化时显示排序。设置、营销的模块搜索显隐另由模块逻辑控制。
- 本次反馈未提供浏览器、窗口宽度、缩放比例、运行版本、截图与具体错位尺寸，均为「待确认」。是上下堆叠、高度差、边缘错位或资源未更新，待实际页面复核；不能直接归因缓存或宣称已复现。

## 期望行为

- 排序与搜索组在同一行左右相邻，排序在左、搜索在右，外框同高且上下边缘平齐。沿用现有 32px 外框口径。
- 宽屏副标题居左、定位组靠右；空间不足允许整个定位组移至副标题下方，组内仍保持左右相邻。搜索区域可收缩但输入、范围标签、清除按钮仍可用，不相互覆盖或引起页面横向滚动。
- 最小支持视口宽度与极窄屏退化方式待确认；开发阶段需明确可验收边界，不能用未定义的“极窄例外”解释常规窗口堆叠。
- 排序五个选项、选择记忆、搜索及清除、键盘操作、模块显隐逻辑维持已有行为。局部布局修复不影响讨论排序和全局面板搜索。
- 正常、空、加载、失败反馈展示在定位组下方，不改变两个控件高度和相对位置；状态变化保留当前排序与关键词。

## 验收说明

- 在真实运行页面记录环境、视口宽度和截图，并检查外框几何尺寸：排序位于搜索左侧，两者上下边缘一致、高度均为 32px；常规窗口及双方确认的窄屏范围内无组内堆叠、遮挡和横向溢出。
- 明确验证先前修复之后的页面仍需通过视觉检查；不能仅以 `min-width: 0` 或等高规则存在、选择器测试通过作为解决证明。
- 覆盖 720px 断点上下、长搜索词、清除按钮出现和消失、五种排序选项、主题切换，记录最小可用宽度。极窄边界未确认时保留限制，不宣称全宽度通过。
- 正常/空/加载/失败状态下控件仍相邻等高；失败与恢复不丢失排序及关键词，反馈条不挤入定位组。
- 切换模块再返回需求，排序显示与记忆正常；搜索输入、清除、Esc、`/` 聚焦正常；讨论排序、全局面板搜索无样式回归。

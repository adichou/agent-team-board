## 根因分析

**为什么 BUG-20260910-018 修复后仍会堆叠（复发根因）**：

CSS 多行 flex（`flex-wrap: wrap`）的断行判定按各项**假设主尺寸**（hypothetical main size =
`flex-basis` 经 `min-width`/`max-width` 截断）贪心打包，**不是**按收缩后的最终宽度。定位组内：

- 排序下拉（`select`，无显式 flex）假设主尺寸 ≈ 固有宽度 ~80px；
- 搜索组 `flex: 0 1 380px` 假设主尺寸恒为 380px（`min-width: 0` 只在 0~380px 区间截断，380 > 0，不参与拉低）。

因此当定位组可用宽度 < 80 + 6(gap) + 380 ≈ **466px** 时，搜索组被打包到第二行——两控件上下堆叠。
`min-width: 0`（018 修复）只影响**行内收缩**与**最小内容尺寸**，不参与断行判定，无法阻止该换行。

触发面：≤720px 媒体查询内定位组独占整行（宽 = 视口 − 36px 页边距），视口 ≲ **~502px** 时组宽跌破 466px
即堆叠；>720px 时长副标题挤压整组进入同行收缩，一般不触发。这正是本 Bug README 复现步骤 3
「逐步缩窄至 720px 附近及更窄宽度」覆盖的区间——用户再次反馈与此吻合（用户现场视口宽度未取得，待确认）。

**用户现场限制（如实记录）**：本次反馈未提供浏览器、窗口宽度、缩放比例、运行版本与截图；不能断言用户所见
即此形态，也不能排除现场资源未刷新。但代码侧该堆叠路径在 018 修复后确实**结构性可达**，与「仍未解决」的
反馈一致，按可达缺陷修复。

## 方案

1. **组内恒不换行（核心）**：`.page-head .locate-group` 由 `flex-wrap: wrap` 改为 `flex-wrap: nowrap`——
   断行在结构上不可达，任意宽度排序在左、搜索在右恒同一行；空间不足时**整组**随 `.page-head` 的
   `flex-wrap: wrap` 移至副标题下方（本 Bug 期望行为明确允许，非组内堆叠）。
2. **收缩链路沿用**：排序下拉默认 `min-width: auto`（不缩破固有宽度，不裁切）；搜索组保留 018 的
   `min-width: 0` 全宽度收缩 + 380px 宽屏基准（nowrap 下 flex-basis 仅作收缩基准，不再触发断行）。
3. **极窄退化方式显式化**（回应「不能用未定义的极窄例外解释常规窗口堆叠」）：新增 ≤480px 媒体查询，
   隐藏定位组搜索内辅助键位提示 `.kbd-hint`（`/` 提示为辅助信息），扩大可用收缩范围；输入、范围标签、
   清除按钮不裁切。**最小支持视口 320px**：组宽 284px ≥ 排序 ~80px + 6px + 搜索内容最小（图标 + 范围标签 +
   间距 ≈75px），恒一行、不溢出、无横向滚动；<320px 为未支持边界。
4. 高度侧不动：沿用 REQ-20260910-025 同高 32px 合并块（含边框等高、上下边缘对齐）。

**开源选型（REQ-20260909-015）**：自研（无新增依赖）。理由：纯 CSS 布局缺陷修复，两行声明级改动
（wrap→nowrap + 一条退化媒体查询），不存在承担此职责的成熟库引入场景；引入任何布局库成本均高于自研，
且会与现有零依赖前端冲突。未引入开源库，不创建 licenses.md。

**TDD**：新增 `scripts/tests/bug-sort-search-flat-recurrence-20260911-001.test.mjs`（C1–C7）先跑红
（C1 nowrap / C2 退化与边界声明两项红），实施后跑绿。同步把三处守护旧「极窄允许组内换行」口径的存量断言

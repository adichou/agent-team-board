# 设计 — BUG-20260912-001 中英文国际化要求在批量开发提示词中添加要求，确保每次开发都要确保中英资源正确

> 由 Agent 在 /dev 开发前补充，人可随时批注。

## 引入来源（源单）

- 引入来源：REQ-20260911-009（经 `atb list` 核验存在，状态 done）。
  该需求新增设置页「Git 工作流」分区：状态行在 app.js 内整句动态拼接为单个文本节点
  （`当前分支：${branch} · dev 分支：${已存在|未创建}`），并在词典登记整句动态键
  `'当前分支：◇ · dev 分支：◇'`。动态回填只做 `$N` 原样替换、不递归翻译捕获组，
  英文态下「已存在/未创建」残留中文；静态词条 `'已存在': 'exists'`、`'未创建': 'not created'`
  因全文匹配前提（独立文本节点）永远命不中，形同虚设。

## 根因分析

i18n 翻译层（scripts/web/i18n.js）按「文本节点全文命中才替换」工作：

1. 动态键捕获组不做翻译（设计上避免误翻用户数据），整句动态回填必然把中文状态词带进英文；
2. 状态词从未以独立文本节点出现在 DOM，静态词条死键；
3. 词典覆盖率测试（i18n-coverage）只校验「源码片段 → 词典有键」，片段 `当前分支：◇ · dev 分支：◇`
   有动态键即算覆盖，测不出「捕获组内中文在英文态不可译」。

## 方案

**开源选型（REQ-20260909-015）**：本条目为既有自研翻译层的缺陷修复，未引入任何新依赖，
不涉及开源库复用评估（无包可解此问题：i18n 词典为本仓库自维护资产）。

修复（不引入任何运行时递归翻译捕获组的机制，避免误翻用户数据）：

1. **DOM 拆段**（scripts/web/app.js `gitWorkflowAreaHtml`）：状态行把分支名与 dev 状态词
   各包一层 `<span>`，拆成 4 个文本节点——`当前分支：`、分支名、`· dev 分支：`、状态词。
   app.js 仍零引用 i18n 机制（i18n-wiring W1c 契约：源码不含 "i18n"/"ATBI18N" 标识）。
2. **词典补段**（scripts/web/i18n.js EN）：新增 `'当前分支：' → 'Current branch: '`、
   `'· dev 分支：' → '· dev branch: '`；既有 `'已存在'/'未创建'/'未知'` 词条自此真正生效。
3. **移除不可达旧动态键**：`'当前分支：◇ · dev 分支：◇'` 从 EN_DYNAMIC 删除（拆段后无节点可命中）。
4. **往返补丁（translateTree）**：词典值尾随空白（`'Current branch: '`）会被文本节点外侧
   空白剥离吞掉，en→zh 反向查不中；翻译未命中时把外侧尾随空白贴回键里重试一次。
   顺带修复既有同类值（如 `'未知接口：' → 'Unknown API: '`）的往返盲区。

## 风险与边界

- 分支名等用户/服务端数据仍不翻译（拆段后作为独立节点原样保留），符合「用户数据不误翻」设计。
- translateTree 往返补丁仅在「精确查未命中 + 键含外侧尾随空白可命中」时生效，不影响既有命中路径；
  zh 初始渲染不受影响（拆段不改变中文视觉）。
- 状态行 en→zh 往返后与初始 zh 完全一致（补丁保证）；en 态分支缺省显示 `Unknown`（既有词条）。

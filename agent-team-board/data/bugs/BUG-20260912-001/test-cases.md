# 测试用例 — BUG-20260912-001 设置页 Git 工作流「已存在」缺英文资源

> Bug 条目原文档只有 README；本文件为修复阶段补录的用例清单（TDD 先行）。

## 复现口径

设置 → Git 工作流分区，就绪态状态行动态拼接为单个文本节点：
`当前分支：main · dev 分支：已存在`。i18n 动态词典 `'当前分支：◇ · dev 分支：◇'`
整体命中后，捕获组（已存在 / 未创建 / 未知）原样回填、不再翻译 → 英文界面残留中文。
静态词条 `'已存在': 'exists'`、`'未创建': 'not created'` 因全文匹配永远命不中（非独立文本节点）。

## 用例

- T1 英文态状态行全译：按渲染结构（文本「当前分支：」+ span 分支名 + 文本「· dev 分支：」+ span 状态词）
  逐节点翻译后，整行无中文残留；分支名（用户/服务端数据）保持原样；
  `已存在 → exists`、`未创建 → not created`、分支缺省 `未知 → Unknown`。
- T2 双语往返：英文译出后切回中文能还原（当前分支：main · dev 分支：已存在）。
- T3 词典契约：EN 含 `当前分支：`、`· dev 分支：` 词条；`已存在`/`未创建` 词条在英文态 t() 生效。
- T4 结构契约（app.js 源码级）：gitWorkflowAreaHtml 状态行把分支名与 dev 状态词分别包进独立
  `<span>`，使「已存在/未创建/未知」成为可独立命中的文本节点（i18n 全文匹配的前提）。
- T5 词典卫生：旧动态键 `当前分支：◇ · dev 分支：◇` 在 DOM 拆分后不可达，从 EN_DYNAMIC 移除。

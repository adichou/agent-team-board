# BUG-20260925-005 二次编辑界面的编辑和预览功能要和审查界面保持一致。

- 状态：以系统看板为准（开发已实施：编辑 / 预览对齐审查界面口径，测试通过，待人工验收）
- 归属：独立 Bug（引入来源见 design.md）
- 创建：2026-09-25T08:02:40.488Z

## 现象

发布模块「文档编写」五步流程中，「② 二次编辑」弹窗（REQ-20260924-006 新增，默认语言单语言编辑：文件下拉 / 刷新 / 编辑·预览切换 / 保存 / 关闭 / 未保存挂起保护）与既有「审查」对话框（按文档类型页签 + 全语言多栏，每栏 编辑·预览·保存·通过审核）都提供文档的编辑与 Markdown 预览，但两处能力不一致——同一文件在二次编辑弹窗里的编辑与预览体验低于审查界面：

1. **预览缺富媒体增强（与 BUG-20260923-002 后的审查界面不一致）**：审查对话框的预览容器（`.bld-review-preview.md`）渲染后经 `ATBMdRich.enhance` 增强——仓库相对路径图片（如 `image/xxx.png`）改写为 `/api/fs/raw` 白名单端点加载、加载失败就地占位提示；` ```mermaid ` 围栏渲染为图（深浅色自适应）；plantuml 给降级提示 + 源码。二次编辑弹窗的预览容器（同一 `.bld-review-preview.md` 类名，`renderSecondaryEditModal` 输出）只做 marked 基础渲染，**未调用** `ATBMdRich.enhance`：相对路径图片按当前页面地址解析通常加载失败，呈浏览器原生裂图、无占位与原因提示；mermaid / plantuml 只显示为普通围栏代码块。
2. **编辑器字体口径不一致**：审查对话框编辑框为等宽字体（`ui-monospace, Menlo, Consolas, monospace`，12.5px/1.65）；二次编辑弹窗编辑框为 `font: inherit`（界面默认非等宽字体）。Markdown 源码中的表格管道对齐、缩进层级、代码缩进在非等宽字体下观感明显差于审查界面。
3. **建议行定位缺落点反馈**：从「③ AI 校对」建议卡片「✎ 修改」跳入二次编辑弹窗（`openSecondaryEdit({file, line})` → `focusEditIssue`）只做选区 + 聚焦 + 滚动；审查对话框同名定位（`focusReviewIssue`）还额外加 2 秒描边闪烁动画提示落点。弹窗内注释自称「口径同 focusReviewIssue」，实际缺少该闪烁。
4. **（次要）预览排版口径不一致**：二次编辑预览容器位于 `.bld-edit-body` 内，不匹配审查对话框 `.bld-review-col-body .bld-review-preview` 的专门样式（无边框、13px/1.7、围栏代码等宽收敛换行），走 `.md` 通用样式（带外框边框 + 圆角 + 13.5px）——同一文档在两个界面的预览排版观感不同。

### 已核实的代码依据（当前 dev 代码阅读结果）

- 富媒体增强仅挂审查对话框：`scripts/web/build.js` 事件绑定段仅对 `#bldReviewWrap`（审查对话框）内的 `.bld-review-preview.md` 调用 `window.ATBMdRich?.enhance(el, { imgBase: … /api/fs/raw … })`；二次编辑弹窗 `#bldEditWrap` 的绑定段（文件切换 / 刷新 / 编辑·预览 / 保存 / 关闭 / 挂起三动作）无任何 enhance 调用。`scripts/web/md-rich.js` 头注释的宿主清单（build.js 审查对话框 / app.js 文件面板与条目文档 / req-disc.js / oncall.js）不含二次编辑弹窗。
- 时间线：富媒体增强层由 BUG-20260923-002（09-23）引入并只接入当时的宿主；二次编辑弹窗由 REQ-20260924-006（09-24）新增，实现时预览只接了 `renderMd` 基础渲染、编辑器样式与定位反馈未对齐审查对话框既有口径。
- 编辑器样式：`scripts/web/style.css` 中 `.bld-review-col-body textarea` 为等宽 `12.5px/1.65 ui-monospace, Menlo, Consolas, monospace`；`.bld-edit-body .bld-edit-editor` 为 `font: inherit; line-height: 1.7`。
- 定位反馈：`focusReviewIssue`（审查对话框）加 `bld-review-focus-flash` 类 2 秒后移除；`focusEditIssue`（二次编辑弹窗）无对应逻辑（`bld-review-focus-flash` 样式类存在，可复用）。

## 复现步骤

前置：看板 Web 界面（Status Board）进入某项目 → 发布模块，选择一个处于文档编写阶段（五步条可见、「② 二次编辑」可点）的版本；其默认语言文档（如 `README.md`）中含仓库相对路径图片（如 `image/xxx.png`）或 ` ```mermaid ` 围栏。

1. 点击「② 二次编辑」打开弹窗，文件下拉选择含图片 / mermaid 的文档，切到「预览」→ 观察：图片呈裂图（相对路径未改写、无占位提示），mermaid / plantuml 只显示为代码块源码。
2. 关闭弹窗，点击「审查」打开审查对话框，选同一文档的类型页签，该栏切「预览」→ 观察：图片正常显示（或失败时有带路径与原因的占位提示），mermaid 渲染为图。同一文件两界面呈现不一致。
3. 在两个界面分别切到「编辑」态对比：审查栏为等宽字体，二次编辑弹窗为界面默认字体——Markdown 表格 / 缩进对齐观感不同。
4. 在「③ AI 校对」建议侧栏（须已有校对结果）点某条建议的「✎ 修改」→ 二次编辑弹窗打开并选中目标行，但无落点闪烁提示；对照：从整体审查对话框 AI 校对问题行跳转审查编辑时有 2 秒描边闪烁。
5. 期间核对既有行为未受影响：弹窗内未保存修改时切文件 / 刷新 / 关闭出现「保存并继续 / 放弃修改并继续 / 留在本文件」三动作；保存成功有反馈。

## 期望行为

1. 二次编辑弹窗的预览与审查对话框口径一致：预览容器渲染后同样接入富媒体增强——仓库相对路径图片改写 `/api/fs/raw` 白名单端点加载、失败就地占位（含路径与原因）；` ```mermaid ` 围栏渲染为图（深浅色自适应，失败回退源码 + 可见提示）；plantuml 同既有降级口径（明确提示 + 源码）。
2. 预览排版口径与审查界面一致：同一文档在二次编辑弹窗与审查对话框中的预览观感一致（容器字号 / 行高 / 围栏代码等宽换行 / 无内外框差异）。
3. 编辑器为等宽字体（与审查对话框编辑框同口径），Markdown 源码可读性一致。
4. 「✎ 修改」跳入二次编辑弹窗的定位落点反馈与审查对话框一致：选区 + 聚焦 + 滚动 + 短暂描边闪烁提示落点。
5. 职责边界不变：二次编辑弹窗仍是默认语言单语言弹窗——不引入其他语种对照列、不新增「通过审核」按钮（审核门禁仍在审查 / 整体审查流程）；文件切换、刷新、未保存挂起三动作（保存并继续 / 放弃修改并继续 / 留在本文件）、保存成功反馈、读取失败重试且不丢输入等既有行为不回退。
6. 关联说明：同批 BUG-20260925-006 计划移除审查界面的编辑功能（编辑职责收敛到二次编辑弹窗）。移除后编辑 / 预览能力完全由二次编辑弹窗承接，本条的能力对齐是该收敛的前提；本条不实施审查界面编辑功能的移除（另单范围）。

## 界面展示

可交互演示：[ui-demo.html](./ui-demo.html)。单文件内联 CSS/JS，无外网依赖、无需构建，可直接在浏览器打开；演示仅使用内存模拟（图片以内联 SVG 模拟端点加载结果、mermaid 以内联 SVG 模拟渲染产物），不读取或修改真实文档，不代表修复已完成。

- **界面布局**：模拟「② 二次编辑」弹窗——顶栏（标题 + 关闭）、工具条（文件下拉 / 刷新 / 编辑·预览切换）、内容区（编辑 textarea 或预览富文本）、底部（状态说明 + 保存 / 关闭）、未保存挂起三动作内联条；演示页另设评审控件（不属于产品功能）：「缺陷现状 / 期望修复后」模式切换、模拟校对建议条（含「✎ 修改」）、对照说明卡（四项差异的现状与期望短句）。
- **交互行为**：可切换文件（含正常 / 空文档 / 模拟读取失败三种）、切换编辑·预览、编辑输入触发未保存提示、切文件 / 刷新 / 关闭走挂起三动作、保存显示成功反馈；「缺陷现状」模式再现裂图 / mermaid 代码块 / 非等宽编辑框 / 无落点闪烁，「期望修复后」模式展示图片显示（或失败占位）、mermaid 成图、等宽编辑框、定位闪烁——同一文档两种模式即时对照。
- **状态反馈**：读取中（正在读取文档内容…）、读取失败（原因 + 重试按钮，不丢已输入内容）、空文档（占位文案）、未保存（提示 + 挂起三动作）、保存成功反馈；图片失败占位（含路径与原因）；深浅色跟随系统。

## 验收说明

以下为开发及人工验收标准，不是已经通过的测试结果：

- [ ] 同一含相对路径图片的文档，在二次编辑弹窗「预览」与审查对话框「预览」中呈现一致：图片均显示，或均给出带路径与原因的占位提示（不出现原生裂图）。
- [ ] 含 ` ```mermaid ` 围栏的文档，二次编辑预览渲染为图，与审查界面一致（含深浅色自适应、渲染失败回退源码 + 提示）；plantuml 为同一降级口径。
- [ ] 二次编辑编辑框为等宽字体，与审查对话框编辑框口径一致。
- [ ] 从校对建议「✎ 修改」跳入二次编辑弹窗：定位行为与审查对话框一致（选区 + 聚焦 + 滚动 + 短暂描边闪烁），行号缺失 / 超界时保持既有兜底（仅打开编辑态，不报错）。
- [ ] 预览排版口径与审查界面一致（同一文档两界面预览观感无差异）。
- [ ] 既有行为不回退：未保存挂起三动作、刷新询问、保存成功反馈、读取失败重试且不覆盖已输入内容、默认语言单语言范围（无其他语种对照列、无「通过审核」）。
- [ ] 深浅色两种外观下预览 / 编辑 / 闪烁提示均正常；富媒体增强失败（如 mermaid 库缺失）静默降级不白屏。
- [ ] 涉及文案中英文同步（scripts/web/i18n.js）；测试先行（scripts/tests/ 新增 bug-20260925-005 测试先红后绿），`npm test` 全量通过。

# BUG-20260914-002 版本计划中关联条目与 commit 无法全选，新建版本计划中也无法全选

- 状态以本条目 status.json 和看板为准。
- 归属：独立 Bug（引入来源见 design.md；涉及界面为构建模块前端，由 REQ-20260913-001 建立）。
- 创建：2026-09-14T02:46:30.466Z。

## 现象

构建模块「版本计划」的两个条目选单面板共用同一套「全选 / 全不选」实现，缺陷表现一致：

1. **「＋ 新建版本」面板无法全选**：点右上「＋ 新建版本」打开侧拉面板，点选单工具行的「全选」按钮——当候选列表中存在**至少一条无关联提交**的已完成条目（行尾标注「暂无关联提交（先完成开发提交）」）时，只弹出 toast「已全选有 commit 候选的条目；N 个条目暂无关联提交已跳过」，但界面**没有任何变化**：所有复选框仍为未勾选、「已选 0 项」计数不变、各行 commit 下拉仍保持禁用——表现为「无法全选」。
2. **版本详情「关联条目与 commit」→「＋ 添加条目」面板无法全选**：在版本计划详情的「关联条目与 commit」区点「＋ 添加条目」打开的面板，点「全选」表现同上（与新建面板共用同一代码路径与同一对按钮）。
3. **「全不选」按钮完全失效**：两个面板中，无论候选构成如何，点「全不选」后复选框勾选全部保留、「已选 N 项」计数不变，界面毫无反应。
4. **界面勾选态与实际提交内容错位**（比「看不到变化」更严重）：
   - 点「全选」界面未变后**直接点「创建版本计划 / 添加所选条目」会提交成功**——把界面上看似未勾选的条目悄悄纳入了版本（内部勾选集合已被更新，只是未重渲染）；
   - 点「全选」界面未变后**手动勾选/取消任意一条**会触发整面板重渲染，所有条目**突然全部变为已勾选**；
   - 勾选若干条后点「全不选」（界面勾选残留）再提交，会报错「请至少勾选一个条目（无关联 commit 的条目不可纳入版本）」——点击提交前界面明明显示有勾选，勾选此刻才被重渲染清掉，与所见相矛盾。
5. **时好时坏**：当候选**全部**都有 commit 候选（无「暂无关联提交」条目）时，「全选」又能正常勾选——缺陷是否触发取决于候选里有无无提交条目，易被当成偶发问题。

定位线索（供开发阶段归因，已对照源码 `scripts/web/build.js` 核实，并经 DOM 模拟环境复现验证）：

- `pickAll()`（约 236–245 行）只更新 `state.createPanel/addPanel.picked`，**自身不调用 `render()`**；
- `#bldPickAll` 点击处理（约 1163–1168 行）写法为 `const skipped = pickAll(key, true); if (skipped) toast(…) else render();`——`skipped > 0`（存在无 commit 候选）时只弹 toast、不重渲染，界面复选框、计数与 commit 下拉禁用态全部保持旧值；
- `#bldPickNone` 点击处理（约 1169–1172 行）调用 `pickAll(key, false)` 后**没有任何 `render()`**，任何候选构成下界面都不更新；
- 对照组：单条复选框走 `pickItem()`（约 229–234 行），内部有 `render()`，故单点勾选/取消显示正常——这也解释了现象 4 中「手动一点就突然全勾上」；
- 现有自动化测试 `scripts/tests/build-ui.test.mjs` N7b 仅断言 `selectableCandidates` 纯函数口径（全选只纳入有 commit 候选的条目），未覆盖点击按钮后的 DOM 同步，故未拦截本缺陷。

## 复现步骤

前置：看板所在项目为 git 仓库；看板中存在若干已完成（done）的需求单 / Bug 单，其中**至少一条有关联提交、至少一条无关联提交**（打开面板时能看到「暂无关联提交（先完成开发提交）」标注即可）。若无无提交条目，见步骤 5 的对照场景。

1. 打开 Agent Team Board 看板（Web 或 Electron 端），顶栏切到「构建」页，保持在「版本计划」子页签。
2. **场景一（新建版本计划）**：点右上「＋ 新建版本」打开侧拉面板，点选单工具行的「全选」按钮。
   - **实际结果**：弹出 toast「已全选有 commit 候选的条目；N 个条目暂无关联提交已跳过」，但所有复选框仍未勾选、「已选 0 项」计数不变、commit 下拉仍禁用——无法全选。
3. **场景二（版本计划中添加条目）**：选中任一「计划中 / 失败」状态的版本，在右侧详情「关联条目与 commit」区点「＋ 添加条目」，在面板中点「全选」。
   - **实际结果**：同场景一，无法全选。
4. **场景三（全不选失效与状态错位）**：
   1. 手动勾选 2 个条目（此时计数与 commit 下拉均正常联动），点「全不选」——复选框勾选全部残留、计数不变；
   2. 接着点「创建版本计划 / 添加所选条目」——点击前界面明明显示有勾选，却报红字「请至少勾选一个条目（无关联 commit 的条目不可纳入版本）」，勾选此刻才被清掉；
   3. 重开面板点「全选」（界面未变），不碰任何复选框直接点提交——**提交成功**（版本被创建 / 条目被加入），纳入的正是界面上看似未勾选的条目；
   4. 重开面板再点「全选」（界面未变），随后手动点击任意一条复选框——全部条目瞬间变为已勾选。
5. **对照场景（偶发正常）**：若当前候选全部有 commit 候选（可先让无提交条目转入其他状态再打开面板），点「全选」勾选、计数、commit 下拉解禁均正常——说明缺陷只在「存在无提交候选」时触发；「全不选」则在该场景下同样失效。

## 期望行为

- **「全选」即时生效**：点击后，所有有 commit 候选的条目复选框**立即**变为已勾选，「已选 N 项」计数同步更新，各行 commit 下拉同步解禁；无提交条目保持禁用并保留「暂无关联提交（先完成开发提交）」标注。跳过提示（toast「已全选有 commit 候选的条目；N 个条目暂无关联提交已跳过」）与界面更新**同时生效**——提示不替代渲染。
- **「全不选」即时生效**：点击后所有复选框立即清空、计数归零、commit 下拉恢复禁用；在两个面板、任意候选构成下行为一致。
- **界面与数据一致**：勾选态与实际提交内容始终一致——不再出现「界面未勾选但提交成功」「界面显示勾选但提交报请至少勾选一个条目」或「手动点一条后突然全部勾上」的错位。
- **不回归**：既有口径保持——全选只纳入有 commit 候选的条目（REQ-20260913-001 口径）；单条手动勾选 / 取消与 commit 换选正常；候选仅含已完成（done）条目（BUG-20260913-001 口径）；面板加载中 / 读取失败重试 / 空候选等状态展示不受影响。
- 具体修复方案（如统一在 `pickAll` 内渲染或补齐两处点击处理的 `render()` 调用）由开发阶段 design.md 落定。

## 验收说明

1. **全选修复（存在无提交候选）**：按复现步骤 2 / 3 操作，点「全选」后有 commit 候选的条目全部立即勾选、「已选 N 项」计数与 commit 下拉解禁同步更新，同时保留跳过 toast；无提交条目仍禁用并带标注。
2. **全选不回归（全部候选有提交）**：按复现步骤 5 对照场景操作，「全选」行为与修复前正常路径一致。
3. **全不选修复**：在两个面板、分别于「含无提交候选 / 全部有提交候选」两种构成下点「全不选」，复选框立即清空、计数归零、commit 下拉恢复禁用。
4. **界面与提交一致**：
   - 全选（界面已正确显示）后直接提交，成功纳入所显示的条目；
   - 全不选后提交，报「请至少勾选一个条目（无关联 commit 的条目不可纳入版本）」且界面无勾选残留；
   - 全选后手动点击任意复选框，不再出现「其余条目突然被勾上 / 取消」的跳变。
5. **面板其余状态不回归**：候选加载中（「正在读取条目…」）、读取失败（错误 + 重试）、空候选（「暂无可纳入版本的条目…」）展示正常；ESC / 遮罩 / ✕ 关闭面板正常；名称输入与提交 busy 态正常。
6. **回归测试**：`node scripts/tests/run-all.mjs` 全量通过；建议补充点击 `#bldPickAll` / `#bldPickNone` 后 DOM 勾选态与「已选 N 项」计数的断言（现有 N7b 仅覆盖纯函数口径，未覆盖点击渲染路径——已核实）。

## 界面展示

**界面布局**：看板顶栏「构建」页 → 「版本计划」子页签：顶部工具栏（右侧「＋ 新建版本」主按钮）；下方左右分栏——左侧版本卡片列表（版本名 + 状态徽章「计划中 / 合并中 / 已合并 / 失败」、单号 · 关联单数 · 更新时间、行内「AI 完善 / 合并入 main / 删除」操作）；右侧版本详情（可点击行内编辑的名称与描述、「关联条目与 commit」区：条目行 = 单号 + 标题 + commit 下拉 + 合并结果标记 + 「移出」，区头右侧「＋ 添加条目」按钮）。新建版本 / 添加条目均为右侧滑出的侧拉面板（带遮罩）：头部标题 + 适用范围说明 + 关闭 ✕；主体为选单工具行（「全选」「全不选」按钮 + 「已选 N 项 · M 个条目暂无关联提交将被跳过」计数提示）与候选行列表（复选框 + 单号 + 标题 + commit 下拉，无提交条目复选框禁用并显示「暂无关联提交（先完成开发提交）」；新建面板底部另有版本名称输入）；面板底部为主操作键（「创建版本计划 / 添加所选条目」）。

**交互行为**：打开面板异步拉取候选；点「全选」勾选所有有 commit 候选的条目并弹跳过提示，点「全不选」清空勾选；勾选单条解禁该行 commit 下拉（未勾选时禁用），可换选关联提交；底部主键按当前勾选提交，未勾选任何条目时红字拦截；ESC / 点遮罩 / 点 ✕ 关闭面板。本 Bug 缺陷所在：点「全选 / 全不选」后界面不更新（详见现象），且内部勾选集合与界面显示错位，导致提交内容与所见不符。

**状态反馈**：候选加载中显示「正在读取条目…」；读取失败显示错误信息 + 「重试」；无候选显示「暂无可纳入版本的条目：仅已完成（done）的需求单 / Bug 单会出现在候选中」；无提交条目行显示禁用复选框 + 「暂无关联提交（先完成开发提交）」；全选跳过无提交条目时 toast 提示；提交校验失败红字「请至少勾选一个条目（…）」；提交成功 toast「✓ 版本计划已创建 / ✓ 已添加条目」并关闭面板刷新列表。

**可交互演示**：[./ui-demo.html](./ui-demo.html)——单文件、无外网依赖，浏览器直接打开。内含「缺陷现状 / 修复后」对照开关，可切换「新建版本 / 添加条目」面板与候选构成（含无提交条目 / 全部有提交 / 空候选 / 读取失败），忠实复现：缺陷模式下「全选」只弹 toast 不勾选、「全不选」毫无反应、提交内容与界面错位（静默提交成功 / 手动一点全勾上）；修复模式下勾选、计数、commit 下拉解禁均即时同步。

# BUG-20260921-006 分支浏览中 dev 分支只需要显示 dev 分支的提交就行，请修改

- 状态：以看板实时状态为准（本文不维护状态副本）
- 归属：独立 Bug（引入来源见 design.md）
- 创建：2026-09-21T01:54:30.100Z

## 现象

用户报告（原文）：「分支浏览中 dev 分支只需要显示 dev 分支的提交就行，请修改」

### 已核实的现状（代码事实）

问题在「构建 → 分支浏览」**选中 dev 分支**时的右侧提交记录：

- **dev 选择也走了双支并集口径**：`scripts/lib/build-git.mjs` 的 `dualBranchScope`（BUG-20260920-002 引入）在「所选分支为主分支解析结果（main / master）**或 dev**，且两支本地引用并存」时返回 `{ main, dev }`；`branchLog` / `branchSearchLog` 随即改走 `branchUnionLog` —— 读取 `git log <main> <dev>` 的并集，而不是所选 dev 分支单独的历史。
- **浏览 dev 时混入 main 独有提交**：并集包含 dev 不可达、仅 main 可达的提交——即「合并入 main」流程产生、只落在 main 上的版本合并提交（`build: … 合并 REQ-/BUG-…（BLD-…）`）。以本仓库实测（2026-09-21，当前分支 dev）：`git rev-list --count dev` = 335，并集 `git rev-list --count main dev` = 387，其中 `git rev-list --count dev..main` = 52 —— 浏览 dev 时多显示了 52 条与 dev 无关的提交，这些提交在 `git log dev` 中不存在。
- **并集模式专属 UI 在 dev 视图出现**（`scripts/web/build.js` renderBranchesPane / fallbackTreeHtml）：
  - 列表上方常驻提示「并集视图：同时显示 main 与 dev 的提交（含未合并提交）」；
  - 提交行 / 详情区出现 main 与 dev 双分支头标签与「main ∩ dev 汇聚点（merge-base）」标注；
  - 分页总数与「已到末尾 · 共 N 条提交」按并集计数（387，而非 dev 的 335）；
  - 关键词搜索（`branchSearchLog`，高亮定位 / 过滤保留祖先两模式）在 dev 上的匹配数据集同样是双支并集（分支名命中规则也按并集两支 heads 计算）。
- 主分支名为 master 的历史仓库同样命中（`dualBranchScope` 按解析结果取主分支，dev 判定不变）。
- 用户报告时所浏览的具体仓库与观察到的具体条数：待确认（上文以本产品自身仓库实测数据为准）。

## 复现步骤

前提：项目为 git 仓库，同时存在本地主分支（main 或 master）与 dev 分支，且 `dev..main` 非空（存在已合并入 main、未在 dev 上的提交；本产品自身仓库即满足——2026-09-21 实测 52 条）。

1. 启动 Status Board（`node scripts/server.mjs`）并打开 Web 界面。
2. 切换到「构建」模块，顶部页签选「分支浏览」。
3. 在左侧分支列表「本地」分组点击 `dev`，等待右侧「提交记录」加载完成。
4. 观察右侧提示行、提交列表 / 提交树与底部分页总数（对照 ./ui-demo.html「缺陷现状」模式）。

实际结果（缺陷现状）：

- 列表上方显示「并集视图：同时显示 main 与 dev 的提交（含未合并提交）」提示。
- 提交记录包含 main 独有的版本合并提交（`build: … 合并 …`；本仓库实测 dev 视图共 387 条 vs dev 自身 335 条，多出 52 条），这些提交在 `git log dev` 中不存在。
- 分页条按并集计数（「第 1–N 条 / 共 387 条」），末页提示「已到末尾 · 共 387 条提交」。
- 提交行出现 main 分支头标签与 merge-base 标注；在该视图搜索关键词时，匹配 / 高亮的数据集同样包含 main 独有提交。

## 期望行为

- **选中 dev 浏览时只显示 dev 可达的提交**（等价 `git log dev`，本仓库当前即 335 条）：列表 / 提交树 / 分页总数 / 搜索数据集（filter 与 highlight 两模式）一致收窄为 dev 单支口径，不再混入 main 独有提交。
- **dev 视图不再出现并集模式专属元素**：无「并集视图：…」提示；无 main 分支头标签与「main ∩ dev 汇聚点」标注（dev 单支视图与现有其他非主支分支的表现一致）。
- **选中 main（或 master）不在本单改动范围**：维持 BUG-20260920-002 落定的双支并集口径（该单用户诉求即「要显示 dev 和 main 两条分支的提交历史」）。是否同步把 main 也改为单支：待确认（默认不改，如需变更另行登记）。
- **既有能力不回退**：分页（20/50/100）、关键词搜索双模式、刷新、加载 / 空 / 失败态与重试、提交选中详情、只读语义（不切换工作区分支、不改引用与文件）均保持。
- 因本单删减 / 调整的界面文案（如 dev 视图不再显示的并集提示），中英文词典同步维护（BUG-20260912-001 口径）。

## 验收说明

- [ ] 前提仓库同复现步骤（本仓库即可）。「分支浏览」选中 dev：右侧不再显示「并集视图」提示；分页总数等于 `git rev-list --count dev` 的值（本仓库当前 335）；列表与提交树中不出现 `git log dev..main` 的任何提交。
- [ ] dev 视图提交行 / 详情区不再出现 main 分支头标签与 merge-base 标注；dev 视图表现与现有其他非主支分支的单支口径一致。
- [ ] dev 视图搜索：filter 与 highlight 两模式下匹配 / 高亮数据集均不含 main 独有提交；清除搜索恢复默认列表；分页与末页计数按 dev 单支口径。
- [ ] 选中 main（或 master）时并集口径保持不变（对照 BUG-20260920-002 的既有验收不回归）；选中其他本地分支维持单支口径不回归。
- [ ] 既有分页、搜索、刷新、加载 / 空 / 失败重试行为不回退；全程只读，不切换工作区分支、不修改引用与文件。
- [ ] 相关测试（scripts/tests/ 中 branchLog / branchSearchLog / dualBranchScope 相关断言）同步更新：dev 改为断言单支数据集；`npm test` 全量通过。
- [ ] 涉及的界面文案增删中英文同步（scripts/web/i18n.js 两语言同步，i18n 相关测试通过）。
- [ ] README 链接的 ui-demo.html 可离线直接打开，缺陷 / 期望对照切换、分支切换、提交选择、搜索与状态（正常 / 空 / 加载 / 失败重试）交互可用，且明确注明模拟数据。

## 界面展示

[打开可交互演示](./ui-demo.html)。演示为单文件、内联 CSS/JS、无外网依赖，浏览器直接打开可交互；数据为明确标注的虚构提交，非真实项目历史。

- **布局**：复刻「构建 → 分支浏览」结构——左侧分支列表（本地：dev（当前）/ main，远端：origin/dev、origin/main）+ 工具行（和远端同步 / 刷新）与同步说明，右侧提交记录（头部为分支名 + 搜索框 + 刷新；下方依次为对照说明条、并集提示行（仅缺陷模式 / main 选择出现）、选中提交详情、逐行拓扑列表：轨道 SVG + 短 hash + 分支头标签 + 合并标签 + 主题 + 作者 / 时间，底部末尾提示与分页条）。
- **对照缺陷与期望**：顶部「缺陷现状 / 期望效果」切换，默认选中 dev（本单问题分支）——缺陷模式复现现状：dev 视图显示「并集视图：同时显示 main 与 dev 的提交（含未合并提交）」提示、列表混入 main 独有合并提交（示例 2 条，红色标注且悬停说明 dev 不可达）、出现 main 分支头标签与 Merge-base 标注、总数按并集计（示例 6 条 vs dev 自身 4 条，附红色缺陷说明条与真实仓库数据脚注）；期望模式展示修复后形态：仅 dev 可达提交、无并集提示 / main 头标签 / merge-base 标注、总数按 dev 单支计（附绿色说明条）。两种模式下选中 main 均维持并集（BUG-20260920-002 口径，不在本单范围，说明条注明）。
- **交互**：点击左侧分支切换视图（切分支重置搜索与选中）；点击提交行切换选中详情（短 hash / 主题 / 父提交 / 合并与汇聚点标注）；搜索框按关键词过滤提交（计数行反馈，无命中给空态），「清除」一键复位；刷新模拟一次加载态后恢复。
- **状态反馈**：状态选择器覆盖正常 / 空（该分支暂无提交）/ 加载（加载提交记录中…，输入与按钮禁用）/ 失败（行内错误 + 重试，重试后恢复）；支持深浅色切换。

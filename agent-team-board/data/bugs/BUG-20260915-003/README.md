# BUG-20260915-003 提交确认面板计数与核验不一致、缺少待提交差异且 Git 错误被截断

- 状态：submitted（待人工接受）
- 归属：独立 Bug（引入来源见 design.md）
- 创建：2026-09-15T00:14:52.109Z

## 现象

BUG-20260914-020 自动提交失败后，确认面板显示已提交 0 组、待人工 0 路径，但重新核验提示仍有 11 个本单路径未入库；面板未展示这些路径的文件清单和差异，用户无法核对后再确认。原 Git 错误在仓库路径处截断，无法判断实际失败原因。核验列表还包含 config.json、dispatch/settings.json 等全局文件，不能直接认定全部属于本单。需要统一计数/文件列表/核验的数据来源，展示实际待提交差异并区分归属待确认项，保留可查看的完整错误。

## 复现步骤

1. 在 BUG-20260914-020 自动提交失败并挂起的现场，打开任务页「查看并确认」。
2. 观察面板显示「已提交 0 组（补交 0 组）· 待人工 0 路径」，且没有实际待提交文件及差异列表。
3. 点击「重新核验」，返回「仍有 11 个本单路径未入库」，包含条目文档、业务文件以及 config.json、dispatch/settings.json 等全局文件。
4. 查看失败原因，仅显示到仓库绝对路径，Git 原始错误关键部分丢失。

## 期望行为

用户应能在一个面板内看清待提交范围、具体差异、归属及完整失败原因，然后决定是否确认；重新核验与确认补交的行为区别应明确。

## 验收说明

- 文件列表、数量与最近核验结果使用一致的数据口径。自动提交在 git add 阶段失败、未生成 pendingManual 时，也应展示实际候选文件；无法确定范围时显示「待核对」，不显示误导性的 0。
- 每个候选文件可查看工作区与 Git 基线的差异；支持已跟踪修改、新增未跟踪文件及删除文件。读取失败有明确错误与重试，不冒充无差异。
- 明确区分「本单可归属」与「归属待确认」。全局配置、调度设置及其他任务混合修改不得只因出现在工作区差集中就自动归为本单。
- 确认前显示实际将提交的文件范围；归属不明或内容变化时应要求重新核对，不能静默整批提交或遗漏文件。具体归属判断实现由开发阶段核对现有快照机制后确定。
- 显示完整 Git 错误（摘要可折叠，全文可展开/复制），并保留原始错误用于诊断。对已经被截断且无原日志的历史错误明确说明信息不足，不编造原因。
- 「重新核验」明确说明只检查；「确认并继续」明确说明将补交、运行测试，通过后恢复队列。实际操作前用户能看到待提交差异。
- 测试覆盖 git add 失败、空 pendingManual 但存在候选文件、全局文件归属不明、差异读取失败、内容变化、完整错误展示，以及正常补交的既有流程。
- 不通过本 Bug 的登记或开发自动解除 BUG-020 挂起，不代替人工确认提交或验收。

## 界面展示

可交互演示：[./ui-demo.html](./ui-demo.html)（单文件 HTML，无外网依赖，浏览器直接打开；支持「当前（缺陷）↔ 修复后」一键对比，由任务页卡片「查看并确认」打开侧拉面板，可切换挂起现场 / 已补交完成空态场景、模拟详情读取失败、差异读取失败与确认时内容变化指纹拦截，深浅色切换）。

- 界面布局：还原任务页「待人工确认」置顶卡片（类型徽标「AI 开发 / 待人工确认提交」+ 单号 + 标题 + 已等待时长、挂起原因行、统一口径计数行、最近核验行、「查看并确认 / 重新核验」按钮）与右侧滑出的挂起确认侧拉面板——头部（标题「待人工确认提交 · 单号」+ 关闭 ✕）与范围说明行（「核对文件与差异后确认：服务端将重新核验、补交并验证测试，通过后恢复队列」）；主体自上而下为：挂起原因、统一口径计数行、Git 失败错误区（修复后：摘要行 + 可展开全文 + 复制，并说明历史截断错误信息不足）、按归属分组的待提交文件表（「本单可归属」/「归属待确认」两组，列为文件 / 变更类型（修改·新增·删除）/ 状态（已入库·未提交）/ 差异按钮，归属待确认行附「计入本次补交 / 排除」选择）、差异展示盒、最近核验结果（原因清单 + 可折叠测试输出）、处理说明输入框；底部操作键「关闭 / 保持挂起 / 重新核验 / 确认并继续」及确认范围摘要。
- 交互行为：「重新核验」只检查不改现场（执行中按钮禁用并显示「正在核验提交与测试…」，结果回写卡片与面板核验行）；「确认并继续」先显示实际将提交的文件范围（本单 N 个 + 归属待确认中已计入 M 个）再补交并跑测试；修复后每个「归属待确认」文件须显式选择计入 / 排除才能确认，全局文件不得静默整批并入；内容与挂起指纹不符时确认被拦截并要求先重新核验；文件行「查看差异」在差异盒内展示工作区与 Git 基线差异（已跟踪修改 / 新增未跟踪 / 删除文件），读取失败显示错误并可重试，不冒充无差异；「保持挂起」记录处理说明并保留现场与队列暂停。
- 状态反馈：缺陷模式复现——卡片与面板显示「已提交 0 组（补交 0 组）· 待人工 0 路径」、无文件清单与差异可核对，重新核验却报「仍有 11 个本单路径未入库」（计数 / 清单 / 核验口径互相矛盾），Git 错误截断到仓库路径无法判断原因；修复模式——计数、文件表与核验同源（无法确定归属时归入「归属待确认」并显示待核对，不显示误导性 0）、错误摘要可折叠全文可展开复制、面板打开显示「正在读取挂起详情…」加载态、详情读取失败显示错误 + 重试、无待提交文件时显示「无待提交文件：全部路径已入库」空态、确认成功提示「已确认恢复：补交 N 组提交，核验通过，队列已恢复；条目验收仍走『确认完成』」且确认失败原因逐行列出。

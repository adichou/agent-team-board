# BUG-20260925-004 不要每次关闭文档编写的编辑界面都重新刷新界面

- 状态：submitted（待人工接受）
- 归属：独立 Bug（引入来源见 design.md）
- 创建：2026-09-25T07:59:26.690Z

## 现象

在发布模块「文档编写」步，每次关闭编辑类界面——「审查」对话框（多语言双栏对比编辑）或五步条「② 二次编辑」弹窗（默认语言单语言编辑）——底层的文档编写窗格都会被整块清空，先显示「正在加载发布流程数据…」，待一次 publish-plan 请求返回后窗格再整体重建回来。每次关闭都重复上述过程，观感即「关闭编辑界面 = 整个界面重新刷新」：

- 窗格主体闪烁：列表 / 门禁条 / 阶段条消失 → 「正在加载发布流程数据…」→ 重新出现，时长约等于一次 `/api/build/publish-plan` 请求；
- DOM 全量重建：窗格内滚动位置丢失（如文件列表滚动处被重置回顶部），需要重新定位；
- 关闭动作本应瞬时完成，却被一次网络请求的节奏拖住，编辑多份文档时反复打断。

代码定位（供开发参考，均在 `scripts/web/build.js`）：

- `closeReview()`（约 2183 行）与 `closeEditDialog()`（约 3906 行）在关闭后均调用 `ensurePublishPlan(true)`（注释「关闭后同步最新四态与门禁」）；
- `ensurePublishPlan(force)`（约 1664 行）先置 `pf.phase = 'loading'` 并 `render()`，请求返回后再 `render()`；
- `renderDocsPane()` 在 `phase === 'loading'` 时（约 3197 行）将窗格主体替换为「正在加载发布流程数据…」占位；
- `render()` 为「文档编写」窗格的全量 DOM 重建（BUG-20260925-001 注释已佐证，校对建议列表滚动是专项保留，其余滚动无保留逻辑）。

归因线索（最终归因在 design.md 由开发阶段核验确认）：`closeReview` 的关闭刷新由 REQ-20260921-008（提交 01db0bf）引入，`closeEditDialog` 由 REQ-20260924-006（提交 675a215）引入。

## 复现步骤

1. 启动看板 Web 界面（仓库根目录 `bin/atb serve --open`，或 Electron 壳）；
2. 顶栏切到「发布」模块页签；
3. 左侧版本列表选中一个已进入文档编写阶段的版本（无现成版本时：待确认——需先在「版本计划」创建版本并推进到文档编写步，具体前置以实际版本状态为准）；
4. 右侧详情五步页签点「文档编写」；
5. 二选一打开编辑界面：
   - 动作行点「审查」打开审查对话框，随即点 ✕ / 关闭；
   - 或五步条点「② 二次编辑」打开编辑弹窗，随即点 ✕ / 关闭（有未保存修改时选「放弃修改并继续」）；
6. 观察关闭瞬间：窗格主体变为「正在加载发布流程数据…」，约一次请求时长后文件列表整体重建；
7. 辅助观察：先把语言页签内的文件列表滚动到中部再关闭编辑界面，重建后列表回到顶部（滚动位置丢失）。

## 期望行为

关闭「审查」对话框 /「② 二次编辑」弹窗是轻量本地操作：

- 底层文档编写窗格内容保持原样、立即可交互——不出现「正在加载发布流程数据…」占位、不整块重建、滚动位置与页签选中保持不变；
- 如确需在关闭后同步文件四态与门禁（防外部修改导致状态过期），应在后台静默拉取，完成后再仅更新有变化的区域（状态徽标 / 门禁条 / 计数等），无变化时不重绘窗格主体；
- 后台同步失败不打断当前界面：保留现有内容，给出轻量提示与重试入口（不进入整页 error 态）；
- 不改变既有数据口径：保存后回退待审核、审核基准、门禁计算等行为不回归。

## 验收说明

- 关闭「审查」对话框与「② 二次编辑」弹窗时，窗格主体无「正在加载发布流程数据…」闪烁、无整体消失再出现；
- 关闭前后窗格滚动位置、语言页签 / 文档类型页签选中保持一致；
- 关闭后文件四态、门禁条、阶段进度仍能反映最新磁盘状态（后台同步生效，含外部 IDE 改动场景——口径与现有「刷新」按钮一致）；
- 后台同步失败时界面不被清空，出现可重试的轻量提示；
- 既有交互回归检查：审查对话框内编辑 / 保存 / 通过审核、二次编辑弹窗未保存三动作保护（保存并继续 / 放弃 / 留下）、AI 校对建议栏滚动保留（BUG-20260925-001）行为均不变；
- 现有 Node 测试（`npm test`）通过，涉及关闭路径的行为有对应单测覆盖。

## 界面展示

可交互演示见 [./ui-demo.html](./ui-demo.html)（单文件、内联 CSS/JS、无外网依赖，浏览器直接打开）。

- 界面布局：模拟发布模块「文档编写」窗格——顶部「语言集」输入与「刷新 / 审查」动作行、五步操作条（① AI 总结 ② 二次编辑 ③ AI 校对 ④ AI 翻译 ⑤ 提交）、按语言页签分组的文件七态列表（右侧含 AI 校对建议栏入口示例）；「② 二次编辑」打开编辑弹窗（文件切换、编辑 / 预览、保存、关闭，含未保存保护）。
- 交互行为：提供「缺陷现状 / 修复后期望」行为模式开关对照演示——缺陷模式下关闭编辑弹窗，窗格主体被「正在加载发布流程数据…」替换、约一次请求时长后整体重建且列表滚动回到顶部；期望模式下关闭后窗格原样保留、滚动不丢，后台静默同步完成后仅以轻量提示与状态徽标呈现变化。
- 状态反馈：覆盖正常（列表就绪）、加载（正在加载发布流程数据占位）、失败（读取失败 + 重试按钮，可在勾选「模拟同步失败」后于关闭触发的刷新中观察两种模式下的差异）、空（无文档文件）四态切换；深浅色随系统自动适配。

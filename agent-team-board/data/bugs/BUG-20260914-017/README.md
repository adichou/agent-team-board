# BUG-20260914-017 分支同步界面缺少 main 必须经过发布流程推送的规则说明

- 状态：accepted（已接受）
- 归属：独立 Bug（引入来源见 design.md）
- 创建：2026-09-14T12:10:13.167Z

## 现象

构建 → 分支浏览的同步范围设计排除 main（BUG-20260914-011 落定「和远端同步 = 先 fetch、再推送除 main 外的本地分支」），但**该规则只存在于悬停提示与设计文档中，界面无常驻说明**——用户不悬停、不读文档就无法理解为什么 main 不随同步推送、也没有推送按钮，容易把「和远端同步」理解为包含 main 的全部分支同步。

现状链路（均经源码核实，2026-09-14）：

1. **按钮说明只在悬停提示里**：`scripts/web/build.js` `renderBranchesPane()` 的「⟳ 和远端同步」按钮（`#bldFetchBtn`，约 1244 行）悬停提示为「fetch --all --prune 拉取远端，再推送本地开发分支（main 除外）：确保本地与远端一致」——「main 除外」的关键规则**仅出现在 title 悬停提示中**，按钮附近没有任何常驻文字；且该 title 串未收录进 `scripts/web/i18n.js` 词典（`title` 属性属 i18n `TRANSLATABLE_ATTRS` 可译范围，但词典无此串），英文界面下悬停提示仍为中文。
2. **main 分支行无任何说明**：同步推送范围排除 main（`scripts/lib/build-git.mjs` `syncRemote()` 约 143 行：`if (branch === 'main') { skipped.push(branch); continue; }`），分支行的「推送」按钮也已按 BUG-20260914-012 去除——但 main 行本身**没有「通过发布流程推送」的说明或标识**，用户只看到 main 行「既不随同步推送、又没有推送入口」，原因不可知（行仍可点击查看提交记录）。
3. **同步结果不提 main 被跳过**：`doSync()`（约 788–811 行）成功 toast「✓ 已同步远端：fetch 完成，已推送 dev → origin」、部分失败 toast「✕ 同步完成但部分推送失败：…」均未提示「main 已跳过」；仅当本地只有 main 时才带一句「无可推送的开发分支（main 由发布模块推送）」。服务端 `syncRemote()` 已返回 `skipped: ['main']`、前端也已存入 `state.lastSync.skipped`，但该数据未在任何结果反馈中呈现——用户同步后看不到 origin/main 时容易误以为同步遗漏或出错。
4. **规则目前只能靠文档解释**：把「main 必须走发布模块推送」讲清楚的只有 BUG-20260914-011/design.md（方案节「推送范围 = 除 main 外的全部本地分支」及发布治理口径），界面自身不能自解释。

## 已确认规则

用户明确确认：推送 main 必须经过发布流程。「和远端同步」只推送 main 以外的本地分支；本单补充界面说明，不改变该规则。

## 复现步骤

前置：一个 git 仓库项目，本地有 dev + main 双分支（当前分支 dev）、已配置远端 origin。

1. 启动看板：项目目录终端运行 `atb serve`（默认端口 8888，`ATB_PORT` 可覆盖），浏览器打开 `http://localhost:8888`，顶栏项目选择器选中该项目。
2. 顶栏切到「构建」模块，切到「分支浏览」子页签。
3. 观察「⟳ 和远端同步」按钮：**不悬停时**按钮附近没有任何关于同步范围（排除 main）的常驻说明；悬停才能看到提示里的一句「main 除外」；切换英文界面后悬停提示仍为中文（i18n 词典未收录该串）。
4. 点击「⟳ 和远端同步」：按钮禁用显示「同步中…」，完成后 toast「✓ 已同步远端：fetch 完成，已推送 dev → origin」——**没有任何「main 已跳过」的提示**；「远端」分组出现 origin/dev 等、却始终不出现 origin/main，界面也不解释原因。
5. 看「本地」分组 main 行：无「推送」按钮（BUG-20260914-012 已去除），行本身可点击查看提交记录，但行上没有说明 main 应通过什么途径推送。
6. 对照：当前把 main 推送规则讲清楚的只有 BUG-20260914-011/design.md——用户需要离开界面去读设计文档才能理解，即本 Bug 所述「界面缺少规则说明」。

## 期望行为

- **常驻说明**：在「和远端同步」按钮附近常驻显示简短说明：「同步仅推送 main 以外的本地分支；main 必须通过发布流程推送。」不只放在悬停提示中；按钮悬停提示保留并同步说明范围（含英文词条，补入 `scripts/web/i18n.js`）。
- **main 行标识**：本地 main 分支行显示「通过发布流程推送」说明或标识；保留查看提交记录的交互，不增加直接推送入口。
- **同步结果反馈**：同步结果中明确提示「main 已跳过，请通过发布流程推送」（可直接利用既有 `state.lastSync.skipped` / `skipped` 数据），与其他分支成功、失败结果一同呈现，避免让用户误认为 main 已同步或被遗漏。
- **仅 main 场景**：本地仅有 main 时，明确说明「没有可推送的开发分支；main 必须通过发布流程推送」，不提示用户寻找 main 的推送按钮，也不声称全部分支已同步。
- **外观与翻译**：说明在深浅色外观下清晰可读，英文界面有对应翻译。
- **不越界**：不修改发布流程，不新增绕过发布流程推送 main 的入口（`syncRemote()` 排除 main 的行为不变，仅补充展示层说明）。

## 验收说明

1. **常驻说明可见**：dev + main 双分支仓库（当前分支 dev）打开 构建 → 分支浏览，不悬停即可见「和远端同步」按钮旁的常驻说明（同步仅推送 main 以外的本地分支；main 必须通过发布流程推送）；悬停提示与常驻说明口径一致，无矛盾。
2. **main 行标识**：「本地」分组 main 行显示「通过发布流程推送」说明或标识；点击 main 行仍能查看提交记录；main 行无「推送」按钮、无任何直接推送入口。
3. **同步成功反馈**：点「⟳ 和远端同步」成功后，结果反馈同时呈现已推送分支清单（如「已推送 dev → origin」）与「main 已跳过，请通过发布流程推送」；远端分组不出现 origin/main，且用户能从反馈直接理解原因，无需查文档。
4. **部分失败反馈**：构造部分分支推送失败（断网 / 远端拒绝）：失败分支与原因列明、可重试，「main 已跳过」提示仍出现；fetch 成功的拉取结果照常生效。
5. **仅 main 场景**：本地仅有 main 分支的仓库执行同步：反馈为「没有可推送的开发分支；main 必须通过发布流程推送」，不声称全部分支已同步，不引导用户寻找 main 的推送按钮。
6. **外观与 i18n**：深浅色外观下常驻说明与 main 行标识均清晰可读；切换英文界面：常驻说明、悬停提示、main 行标识、同步结果反馈（含「main 已跳过」）均有对应翻译（词条补入 `scripts/web/i18n.js`），无中文残留——现状「悬停提示英文缺失」一并修复。
7. **不越界核对**：无新增绕过发布流程推送 main 的入口；发布模块流程未改动；`build-git.mjs` `syncRemote()` 排除 main 的行为与既有测试断言不回归。
8. **测试同步**：受影响的既有断言（toast 文案等）随实现同步更新，`node scripts/tests/run-all.mjs` 全量通过。

## 界面展示

可交互演示：[`./ui-demo.html`](./ui-demo.html)（单文件、内联 CSS/JS、无外网依赖、无构建步骤，浏览器直接打开可交互；数据为模拟，布局与交互按 `scripts/web/build.js` `renderBranchesPane()` / `doSync()` 及 `scripts/lib/build-git.mjs` `syncRemote()` 现行为复刻）。提供「当前（缺陷）↔ 修复后」一键对照、场景切换（典型 dev+main / 仅 main / 非 git 仓库）、中英文切换与推送失败模拟，覆盖分支列表加载、同步执行中、成功、部分失败、fetch 失败等状态反馈。

- 界面布局：还原「构建 → 分支浏览」子页签——主体左右分栏：左侧分支列表（顶部工具栏「⟳ 和远端同步」「刷新」，**修复后模式在工具栏下常驻同步范围说明**；下方按「本地 / 远端」分组——本地组当前分支置顶带「当前」徽标，**修复后 main 行带「通过发布流程推送」标识**，dev / 功能分支行右侧保留「推送」按钮），右侧为选中分支的提交记录。
- 交互行为：点击分支行懒加载右侧提交记录（main 行同样可点开，修复后仍无推送入口）；「和远端同步」点击后执行 fetch + 推送除 main 外分支（按钮禁用显示「同步中…」，远端分组出现 origin/dev 等、永不出现 origin/main）；点「推送」弹确认框 → 推送后远端分组出现对应分支；演示控制条可切「当前（缺陷）/ 修复后」对照常驻说明与 main 行标识的有无，切「仅 main」场景验证无可推送分支文案，切中 / 英文验证翻译覆盖。
- 状态反馈：缺陷态成功 toast 不提 main（对照修复后明确「main 已跳过，请通过发布流程推送」）；勾选「模拟推送失败」演示部分失败反馈（失败分支 + main 已跳过同时呈现）；勾选「模拟同步失败」演示 fetch 失败错误 toast；进入 / 刷新列表显示「加载分支中…」；仅 main 场景同步后显示「没有可推送的开发分支；main 必须通过发布流程推送」；英文切换下缺陷态悬停提示仍为中文（现状事实）、修复后全部翻译。

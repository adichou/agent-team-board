## 现象

![截图](attachments/paste-1790526366098.png)

用户反馈：「正式发布」步下方圈注区域（「本版本发布」区）冗余堆叠，要求删除并补充一个「发布」按钮。

本轮源码核实（`scripts/web/build.js`）：

- 入口路径：构建模块 →「版本计划」页签 → 选中版本 → 右侧详情五步导航（`STEP_LABEL`：版本计划 → 关联条目与提交 → 文档编写 → 合并入 main → 正式发布）→ 第 5 步「正式发布」（`renderReleaseFlowPane` + `renderReleasePane`）。
- 截图圈注区域由两部分组成，无发布记录时同屏堆叠：
  1. 顶部操作条（`renderPublishActions`，BUG-20260916-001 引入）：「发布」主按钮（未就绪时禁用）+「创建并预检」+ 灰色原因文案（如「请先创建并预检」），未配置官网仓库时另有「前往设置」；
  2. 空态区（`renderReleasePane` 无记录分支，BUG-20260915-014 引入）：「当前版本暂无发布记录」+ 又一个「创建并预检」按钮（版本未合并时附「请先完成合并入 main」说明）。
- **两个「创建并预检」出自同一函数 `relCreateBtnHtml`，功能完全相同**——同一屏出现两个重复入口；有发布记录时同样存在两处（顶部操作条 + 记录列表底部）。「发布」按钮（`data-rel-act="plan"`，打开发布计划确认弹窗）只存在于顶部操作条。
- 结果即截图所示：禁用的「发布」、「创建并预检」、原因文案、空态文案、第二个「创建并预检」五段元素分散堆叠，视觉冗余、操作入口重复。

实际受影响安装版本与浏览器：待确认（截图来自桌面端深色主题，未附环境信息）。

## 复现步骤

前置：任意已初始化的项目；无需真实发布、不推送代码、不部署站点。版本是否已合并不影响现象（未合并仅多一条说明文案）。

1. 打开「构建 → 版本计划」页签，选中任一版本计划，进入右侧详情五步导航第 5 步「正式发布」。
2. 不执行任何发布操作，查看「动作二 · 官网资料更新」下方的「本版本发布」区域，应与截图一致：顶部一行「发布（禁用）+ 创建并预检 + 请先创建并预检」，下方「当前版本暂无发布记录」+ 第二个「创建并预检」。
3. 数同一屏「创建并预检」按钮个数：应为 2 个，且点击任一均走同一创建流程（同一 `relCreateBtnHtml`、同一 `data-ver-release` 键）。
4. 点击任一「创建并预检」创建草稿后再观察：记录列表底部仍有第三个「创建并预检」入口，重复模式在有记录态同样存在。

## 期望行为

用户原话：「这部分区域删除。补充给一个发布按钮。」

### 收敛目标

「正式发布」步中截图圈注的「本版本发布」区域不再堆叠重复入口与分散说明，收敛为**唯一的「发布」主按钮**（唯一发布入口）；原堆叠的「创建并预检」重复入口随区域删除，不再作为发布前置。能力不回退：原因就近说明、缺配置引导、预检守卫（转入发布链路自动执行）与发布全流程语义全部保留（沿 BUG-20260920-006「点击必反馈」与 BUG-20260916-001「发布主按钮始终可见」的原则，只收敛呈现形态，不删除能力）。

### 布局与交互行为（可直接确认的部分）

- 「发布」为唯一发布入口：同屏不再出现独立「创建并预检」前置入口（运行详情内的恢复类动作除外，见下）。
- 「发布」按钮唯一、醒目；未就绪时禁用并就近显示原因，禁用与原因口径（本轮随一键发布调整）：请先配置官网仓库 / 请先完成合并入 main / 发布中… / 已发布；「请先创建并预检」不再作为发布按钮的前置原因（预检转由发布链路自动执行），预检类提示保留于运行详情动作区。发布中显示「发布中…」，成功后显示「已发布」。
- 未配置官网仓库时保留「前往设置」入口，跳转后保留来源版本上下文（现 `goPublishSettings` 口径不变）。
- 发布按钮逻辑简化（本轮确认）：点击「发布」直接弹出二次确认提示，用户确认后直接发布——不再要求先手动「创建并预检」，也不再先走「预览发布计划」读取步骤；确认后由发布链路自动创建发布草稿并完成预检再启动，预检阻塞时发布中止并就近反馈原因、不静默。服务端链路、守卫与允许状态不变；二次确认弹窗即授权，取消不发出任何执行请求，本条不引入无确认的自动发布。
- 发布成功后，版本计划标签更新为「已发布」（源码现状已有：`versionChip` 按 BUG-20260917-001 口径，存在成功运行即绿色「已发布」标签）；本条确认该口径保留、不回退。
- 发布成功后发布计划锁定，不允许再修改（源码现状已有：BUG-20260920-005 推送完成后锁定关联条目与提交 / 合并入 main / AI 完善，文档合并范围锁定 toast「已正式发布，范围锁定」，概况编辑在 merging 即锁定）；本条确认锁定不放宽、不新增解锁路径，如需调整请新建版本。
- 记录列表、运行详情（预检 / 重新冻结 / 预览发布计划 / 重试失败阶段 / 取消后续阶段 / 刷新状态）按现有允许状态呈现，不因收敛而丢失。

### 状态反馈

- 空 / 加载 / 读取失败 / 有记录 / 发布中 / 已发布 / 未配置各状态下布局正常：加载显示「正在加载发布记录…」；失败显示原因与重试（重试只重新读取记录，不执行发布操作）；空态不再堆叠重复按钮；切换项目或版本时迟到响应不覆盖当前页面。
- 禁用按钮的禁用原因可发现（就近文字或点击反馈），不静默。

### 形态细节（不阻塞本 README，开发前 design.md 定稿）

- 「这部分区域」的精确边界（仅删顶部操作条 / 顶部操作条 + 空态重复块 / 整块收敛为单一发布按钮）：**已确认（2026-09-28 讨论轮）**——整块收敛：圈注区域删除，收敛为唯一「发布」主按钮；最终布局以 design.md 为准。
- 空态（无发布记录）下唯一「发布」按钮与「创建并预检」动作的关系：**已确认（2026-09-28 讨论轮）**——一键发布：空态下「发布」可直接点击（版本已合并且已配置官网仓库时），点击直接弹二次确认，确认后自动创建草稿并预检并直接启动发布；不再保留独立「创建并预检」前置入口。
- 「本版本发布」标题文字是否保留：**待确认**（演示按「随区域收敛移除标题、仅保留唯一发布按钮行」示意）。
- 有记录态下「发布」按钮与记录列表、运行详情动作区的排布：**待确认**（演示保持发布按钮置顶 + 记录列表 / 运行详情双栏）。
- 涉及文案增改时的中英文同步：**按仓库基线执行（非可选项）**，必须同步两语言并跑 i18n 相关测试（BUG-20260912-001）。

## 界面展示

[打开可交互演示](./ui-demo.html)。单文件内联 CSS/JS，无外网依赖、无需构建，浏览器直接打开。演示对照展示：

- **缺陷态（现状）**：忠实还原截图——「本版本发布」操作条（发布 + 创建并预检 + 原因文案）与空态区（当前版本暂无发布记录 + 第二个创建并预检）堆叠，并标注重复入口。
- **期望态（收敛后，本轮确认口径）**：删除圈注的堆叠区域，收敛为唯一「发布」主按钮；点击「发布」直接弹出二次确认提示，确认后直接发布（演示中自动创建草稿并预检后启动，模拟发布中 → 已发布）；发布成功后左侧版本卡标签更新为「已发布」，并提示发布计划已锁定、不允许再修改。

顶部可切换缺陷态 / 期望态，以及空、加载中、读取失败、有记录（未预检 / 预检通过）、发布中、已发布、未配置官网仓库等状态；另提供「版本未合并」开关与深浅色切换。布局为简化的左侧版本卡 + 右侧五步导航（正式发布步激活），交互覆盖发布（二次确认 → 直接发布）、取消、预检、预览发布计划、刷新状态、重试、前往设置的点击反馈与禁用原因提示（「创建并预检」仅作为缺陷态重复入口出现）。演示全部使用内存虚构数据，不调用真实接口、不执行真实发布、不访问文件系统；缺陷态为按源码整理的示意，不代表实机截图。

# BUG-20260915-012 Codex 粘贴讨论提示词后未保留末尾换行

- 状态：以 status.json 为准。
- 范围：按用户要求定位跨应用差异；本次未修改 Codex 安装包或看板业务代码。

## 现象与复现

用户反馈：BUG-20260915-010 修复后，同一讨论提示词在 ZCode 和其他应用可以末尾换行，在 Codex 仍停在末行。打开条目说明文档，右键「讨论」，复制到 Codex 输入框，紧接着输入问题即可观察。

## 定位结论

1. 本仓库生成端返回末尾恰一个 LF（字符码 10）；`copyPlain` 的 Clipboard API 主路径和 textarea/execCommand 降级路径均原样传递文本。新增边界测试与既有提示词测试通过。
2. 本机 Codex（应用路径 `/Applications/ChatGPT.app`，版本 `26.901.51231`）的输入框粘贴实现存在 Markdown 解析分支：读取 `text/plain` 后，解析成文档节点，再 `replaceSelection`。编号列表等格式可能触发该分支；此路径没有显式补回原始文本末尾 LF。普通文本另有按换行拆段的插入路径。
3. **高度怀疑接收端的 Markdown 解析/插入语义丢失末尾换行；尚未通过 Codex 输入框现场实测锁定具体分支。** 不能把代码中用于图片判断的 `o?.trim()` 当成已确认根因，后续插入仍使用原始变量 `o`。
4. 之前「文本 endsWith LF → 任意 Agent 粘贴后光标已在新行」的验收推断不成立。BUG-20260915-010 的生成端修复有效，但它未覆盖接收端粘贴行为。

## 期望与后续验收

- 看板继续输出末尾一个 LF，不添加零宽字符或额外空行。
- 在 Codex 输入框分别粘贴 `普通文本\n`、`1. 编号项\n` 和完整讨论提示词，随后输入可见标记，比较标记位置；不要发送消息。
- 临时可在粘贴后按 Shift+Enter 再输入问题（本机源码配置了该快捷键；现场效果待人工验证）。
- Codex 输入框修复需要在其粘贴解析/插入层保留终止换行，并进行真实输入框验收。本单不宣称该外部缺陷已修复。

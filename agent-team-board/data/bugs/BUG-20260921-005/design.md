# 设计 — BUG-20260921-005 AI 写作的提示词优化，不在提示词中带上大量的需求和 bug 单标题

> 由 Agent 在 /dev 开发前补充，人可随时批注。

## 引入来源（源单）

本 Bug 由哪个需求 / Bug 引入？登记时可暂空或写「未定位」，修复阶段必须归因（三选一，禁止编造）：

- 引入来源：REQ-20260920-003（`atb list` 核验：done。git -S 追溯：commit `58bfd1e` 首次在
  `scripts/lib/publish-flow.mjs` 引入「- <编号>（commit <短hash>）<标题>」逐条内嵌循环）；
  后经 REQ-20260921-008（commit `01db0bf`，`buildDocSummaryPrompt`）与 REQ-20260921-012
  （commit `0cab4e3`，`buildDocTranslatePrompt`）沿用并重构为当前两个提示词函数，两者均真实存在
  （`atb list` 核验 in-progress）。

## 根因分析

- 提示词装配把版本关联条目（`v.items`：itemId + commit + title，标题上限 200 字）逐条拼成
  `- <编号>（commit <短hash>）<标题>` 内嵌「关联范围」小节；条目数随版本规模线性膨胀
  （BLD-20260920-001 达 341 条，仅该小节即约 8.2 万字符），而标题对写作 / 翻译语境价值有限。
- 条目说明文件本就磁盘可达（`agent-team-board/data/requirements/<REQ-ID>/` 等），提示词内嵌
  标题属于冗余信息搬运：子代理按编号自行读取即可。

## 方案

新增共享装配 `docScopeLines(items)`（`scripts/lib/publish-flow.mjs`），`buildDocSummaryPrompt`
与 `buildDocTranslatePrompt` 的「关联范围」小节统一替换为精简口径：

1. REQ 条目：仅一行一个编号（`- REQ-…`），不带 commit 短 hash、不带标题；小节末尾给一行路径
   规则 `需求详情按上列编号自行读取条目说明文件：<项目根>/agent-team-board/data/requirements/
   <REQ-ID>/（README.md、design.md 等），了解本版语境；Bug 修复无需逐条了解。`（项目路径已在
   提示词头部给出，占位符形态与 README 示例一致）。
2. BUG 条目：不逐条罗列、不引导读取，汇总一句 `- 修复了 N 个 bug（BUG 条目不逐条展开）`。
3. 边界：无 BUG 条目不出汇总句；无 REQ 条目不出路径规则行；items 为空时小节仅保留标题行。
4. 其余要素（项目路径 / 计划号 / 版本号 / 执行编号 / 文档清单 / atb summary / translate 回执
   指令 / 写作与翻译约束 / 翻译唯一基准）逐字保持不变；四个透出出口（server 两接口、CLI 两命令、
   看板预览 / 复制）均为纯文本透传，无需改动。

README「待确认」项的落定（均为低风险展示口径，README 已授权「待开发定 / 开发前明确」）：

- 是否保留 commit 短 hash：**不保留**（编号行保持最短；提交核实按「按实际代码与提交核实变化」
  既有约束由子代理在仓库内自查）。
- BUG 汇总是否带条数：**带**（`修复了 N 个 bug`，提供规模感且零体量成本）。
- BUG / REQ 编号是否保留为不带标题的清单：REQ 保留编号清单（供按编号读取文件）；BUG 不保留
  （176 个编号仍是冗余体量，与「总结为一句」口径冲突）。
- 「显著缩短」量化阈值：341 条 × 200 字标题场景下，整份提示词长度 < 旧口径「关联范围」标题块
  长度的 50%（实测整份提示词约 4.3k 字符，对旧整份约 8.6k 缩短约 95%）。

测试（`scripts/tests/bug-20260921-005.test.mjs`，TDD 先红后绿，8 用例）：L1-1/2 两提示词同口径
（无标题内嵌、REQ 编号清单、BUG 汇总一句、路径规则）；L1-3 其余要素保持；L1-4 量化阈值；
L1-5 边界。同步在 4 个既有 L1 提示词断言（req-20260920-003 L1-4、req-20260921-008 L1-6、
req-20260921-010 L1-5、req-20260921-012 L1-3）各补一条「夹具标题不内嵌」负断言锁定新口径。

**开源选型（REQ-20260909-015）**：不适用——纯既有 Node ESM 模块内字符串装配调整，无新增依赖
（自研理由：无库可复用的自身提示词口径，改动即本模块内聚逻辑）。

## 风险与边界

- 子代理需按编号自行读取条目文件：条目目录布局稳定（`core.mjs` 条目目录 + build-store
  `ITEM_ID_RE` 校验编号形态），提示词已含项目路径，可达性不变。
- 非 REQ-/BUG- 前缀条目防御性按 REQ 清单处理（build-store 已校验，正常不会出现）。
- 预存无关失败：全量 316 个测试文件中 `req-20260918-002` / `req-doc-entry-20260916-003` 两个
  文件失败，均因工作区中他人未提交的 AGENTS.md / README.md 改动触发文档结构断言，与本修复无关
  （两文件不引用 publish-flow）。

# BUG-20260928-012 发布页面取消草稿模块

- 状态：submitted（待人工接受）
- 归属：独立 Bug（引入来源见 design.md）
- 创建：2026-09-28T12:21:40.767Z

## 现象

![截图](attachments/paste-1790598083544.png)

发布页面（构建模块「发布」页签，scripts/web/build.js）的发布记录列表中出现一个状态为「草稿」的 BPUB 运行卡片（BPUB-711ea71f-31b9-4edf-a3fe-16ab9d7ff021，来源 BLD-20260927-001），存在两类问题：

1. **草稿无法取消 / 清理**。该草稿为一键发布链路自动创建（BUG-20260928-002：确认后自动「创建草稿 → 预检 → 启动」，scripts/web/build.js `doOneClickPublish`，当前 dev 工作区约 2466-2545 行），链路中止（如预检未通过、确认弹窗被关闭）后草稿残留在列表中。而草稿状态（draft）的运行详情动作区只有「预检 / 重新冻结 / 预览发布计划 / 刷新状态」，「取消后续阶段」按钮仅在 prechecking / running 状态出现（scripts/web/build.js 约 2683-2693 行），也没有删除运行记录的入口；服务端 `cancel`（scripts/lib/build-publish.mjs 约 306 行）本身支持将 draft 置为 canceled，但界面无对应模块/入口。
2. **摘要行显示异常**。列表卡片摘要显示 `v1.0.0 · Web App [object Object] · 官网 …`（官网部分在截图中被截断；按同一渲染路径推断同样异常）。摘要渲染（scripts/web/build.js 约 2657 行）把 `r.targets.webapp` 当作字符串状态键使用：`REL_STEP_LABEL[r.targets?.webapp] || r.targets?.webapp`，而运行数据中 targets 的值是对象（scripts/lib/build-publish-store.mjs 约 69 行：`targets:{webapp:{status:'pending'},site:{status:'pending'}}`），标签表按对象取值必然未命中，回退分支把对象整体字符串化为 `[object Object]`。

## 界面展示

界面布局、交互行为与状态反馈的文字说明见上文「现象」与下文「复现步骤」「期望行为」，可交互演示见 [./ui-demo.html](./ui-demo.html)（单文件、浏览器直接打开）。演示含「缺陷态 / 期望态」对照开关：

- 缺陷态：还原现状——发布记录列表残留草稿卡片（摘要 `Web App [object Object]`）、详情无清理入口，并覆盖发布中 / 已取消 / 空 / 加载 / 读取失败等页面状态；
- 期望态：还原修复后——发布页签不再有草稿展示模块，点击「发布」→ 按检查规则提示 → 二次确认 → 执行 → 显示执行结果（成功显示发布时间·本地时间；失败显示错误信息与「重试」按钮），并覆盖空闲 / 成功 / 失败等状态切换；执行期间无中间进度界面（仅按钮显示「发布中…」并置为不可用），执行结束后直接显示结果。

## 复现步骤

1. 准备：项目看板已初始化；设置中已配置官网仓库根目录；构建模块存在一个已合并（merged）且尚无发布成功记录的版本计划（本例 BLD-20260927-001）。
2. 进入构建模块该版本的「发布」页签，点击「发布」按钮。
3. 在二次确认弹窗填写发行版本号（本例 1.0.0）并点「确认发布」。
4. 链路自动创建发布草稿（`POST /api/build-publish/from-build`，run.status=draft，`targets={webapp:{status:'pending'},site:{status:'pending'}}`），随后自动预检。
5. 使链路中止（例如预检未通过：官网仓库不可访问、冻结输入不满足等），发布条下方出现「发布中止：预检未通过…」，弹窗关闭。
6. 观察发布页签的发布记录列表与运行详情。

实际结果：

- 发布记录列表残留状态「草稿」的 BPUB 卡片，摘要行显示 `v1.0.0 · Web App [object Object] · 官网 …`（截图现象）；
- 打开该草稿运行详情，动作区（预检 / 重新冻结 / 预览发布计划 / 刷新状态）没有任何取消或清理草稿的入口，列表中的草稿卡片无法移除。

说明：只要草稿创建成功且未走到发布成功，草稿卡片即一直保留；同一缺口也覆盖一键发布链路执行中确认弹窗被关闭（切换项目等）的场景——`doOneClickPublish` 创建草稿后若弹窗已关闭，仅清理忙碌标记、不清理已创建的草稿。

## 期望行为

人工确认口径（2026-09-28）：**不是为草稿提供取消按钮，而是把整个草稿展示的页面模块删掉**，发布交互收敛为「提示 → 确认 → 执行 → 出结果」一条直线：

- 发布页签删除整个用于展示草稿（发布运行记录）的页面模块：发布记录列表卡片与运行详情面板不再展示，草稿态运行不再驻留页面；不新增「取消草稿」按钮或清理入口；
- 点击「发布」后按检查规则提示：检查（预检）规则存在不通过项时给出明确提示，且不进入执行；通过后进入二次确认，确认后才执行；
- 执行过程无中间进度展示（人工口径，2026-09-28）：确认后不出现「执行中」页面或分阶段进度列表，仅「发布」按钮置为不可用并显示「发布中…」；执行结束后直接显示执行结果：
  - 成功：显示发布时间，按用户本地时间格式化；
  - 失败：显示相关错误信息，并提供「重试」按钮，重试重新走同一发布流程；
- 摘要 `[object Object]` 的展示路径随模块删除一并消除；若 `targets` 状态摘要在其他位置仍有展示，需按状态标签显示（待执行 / 进行中 / 已完成 / 失败 / 已取消），字段缺失显示「未提供」；
- 模块删除后，原运行详情中的既有入口（预检 / 重新冻结 / 预览发布计划 / 刷新状态 / 取消后续阶段）不再出现在发布页签；服务端能力（`cancel` 等）与内部草稿复用机制（draft/failed/canceled 可续跑）的去留由开发设计阶段（design.md）确定，不在本节承诺。

## 验收说明

1. 发布页签不再展示发布运行记录模块：列表卡片与运行详情面板已删除，页面不存在「草稿」运行展示，也没有「取消草稿」一类清理入口；
2. 点击「发布」后先按检查规则提示：存在不通过项时给出明确提示且不进入二次确认；检查通过后弹出二次确认，确认后才执行；
3. 执行期间无中间进度界面（页面不出现「执行中」或分阶段进度展示，仅发布按钮禁用并显示「发布中…」）；执行结束后展示执行结果：成功显示发布时间（本地时间格式化），失败显示相关错误信息与「重试」按钮，点击重试重新走发布流程并可再次到达结果态；
4. 全局检索确认不再存在把 `targets` 对象当状态字符串拼接的摘要展示路径（无 `Web App [object Object]` 一类文案）；
5. 新增测试覆盖发布流程链路（检查提示 → 二次确认 → 执行 → 结果展示，含成功 / 失败 / 重试分支）与发布时间本地化展示；模块删除不破坏构建模块其余页签功能；
6. 涉及的新增 / 变更文案中英文同步（scripts/web/i18n.js）。

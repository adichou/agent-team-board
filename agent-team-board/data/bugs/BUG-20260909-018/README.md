# BUG-20260909-018 单详情也太矮了，请优化

## 现象

看板「需求」模块的条目详情抽屉（`#drawer`，`scripts/web/index.html` 第 111 行）打开后，说明文档页签（「说明」，即 README 渲染页签，REQ-20260909-006 五页签布局）的内容**整体挤在面板上部、观感"太矮"**，高度利用率过低。以附件截图（[attachments/paste-1788969043935.png](attachments/paste-1788969043935.png)，1194×1402，即本单自己详情抽屉的实测截图）为例，宽屏分栏形态下可量化为两点：

1. **内联截图被压得过小**：README 现象节末尾的内联截图（`.doc-shot`，`linkupDocImages` 接管后加类，`scripts/web/app.js` 第 279 行）受 `scripts/web/style.css` 第 654–661 行约束——`max-width: min(420px, 100%); max-height: 260px; object-fit: contain`。一张 1194×1402 的竖版截图按比例缩到约 **221×260**（原图的约 18.5%），界面截图里的文字、控件完全不可辨认，不点开放大基本没有信息量。
2. **内容区下方大段空白**：抽屉本身是撑满工作区高度的（宽屏为 `.req-split` 网格常驻右栏，`scripts/web/style.css` 第 454–459 行；`drawer-height.test.mjs` D5 固化），但内容区 `.drawer-body`（第 475 行：`padding: 14px 18px 26px; overflow-y: auto`，无拉伸约束）内的说明文档框（`#docView.md`，`scripts/web/app.js` 第 2253–2255 行）按内容自然高度渲染。README 内容结束后文档框底边即止——附件截图实测：文档框底边位于视口约 73% 处（y≈1019 / 1402），其下约 **360px（约四分之一视口高）是纯空白面板**。截图被压小与下方留白同时存在，形成"上面挤、下面空"的观感，即标题所述「单详情也太矮了」。

既有交互通道本身是通的：点击截图经 `#oncallLightbox` 放大（点击任意处 / Esc 关闭），加载失败就地替换为「截图 xxx 无法加载（文件可能被移动、删除或超过 8MB 上限）」占位（`scripts/web/app.js` 第 280–291 行）——问题只出在**默认展示尺寸与高度利用**。

范围与边界（依据代码核实）：

- 讨论模块 `.oncall-fig img` 同款 260px 上限（`scripts/web/style.css` 第 1411 行）：与本 Bug 同模式，但本单截图反馈的是**条目详情抽屉**；讨论侧是否一并调整，属修复范围决策，**待确认**（design.md 裁定）。
- 窄屏（≤1020px）覆盖式抽屉、REQ-20260908-005「顶边低于状态筛选行、与列表等高」的定位口径与本 Bug 无冲突（该口径约束抽屉容器高度，不约束内容展示尺寸），修复不得回退。
- BUG-20260909-010（旧服务进程丢附件致截图不显示）是前置问题：本单成立的前提是截图已能内联显示（本单附件在详情中可见，前置已满足）。

## 复现步骤

前置：看板服务已启动（`node scripts/atb.mjs serve`，默认 `http://127.0.0.1:8888`）。直接用本单即可复现——其 README 现象节自带一张 1194×1402 竖版截图。

1. 打开看板，进入「需求」模块（浏览器窗口宽度保持 1020px 以上，宽屏分栏形态）。
2. 在列表中找到并点击 `BUG-20260909-018` 行（或任意 README 描述 / 现象节带高分辨率竖版截图的条目）。
3. 详情抽屉打开，切换到「说明」页签，等 README 渲染完成。
4. 观察「现象」节末尾的内联截图：被压缩为高约 260px 的小缩略图（约 221×260），截图内文字不可辨认；鼠标悬停显示放大镜指针。
5. 继续看文档框（带边框的 markdown 卡片）底边以下：约四分之一视口高度的空白面板，无任何内容；整个详情内容挤在上部——「单详情太矮」。
6. 点击截图：`#oncallLightbox` 放大正常可用（说明放大通道没问题，问题在默认尺寸）。
7. 把窗口宽度压到 1020px 及以下重开详情：覆盖式抽屉形态下同样呈现"截图小 + 下方空白"。
8. 切换系统深 / 浅色外观重复观察：两种主题下问题一致。

## 期望行为

- **内联截图默认展示显著增大**：`.doc-shot` 的 260px 高度上限放宽，竖版高分辨率截图在详情抽屉可用高度内尽量放大，不点击放大也能辨认截图主体内容。具体上限取值 / 缩放策略（固定上限提高、按视口或面板高度动态计算等）**待确认**，由开发阶段 design.md 定夺。
- **减少内容区大段空白**：说明页签内容不足一屏时，内容区对抽屉可用高度的利用应更充分，不再出现"内容结束 + 约四分之一视口空白"的观感；具体形态（拉伸文档框、随截图放大自然填充、或其它方案）由 design.md 决定。
- **既有交互与口径不回退**（REQ-20260909-009 交付项）：点击截图 `#oncallLightbox` 放大、点击任意处 / Esc 关闭；加载失败占位文案；`loading="lazy"`；单张 ≤8MB、9 张上限等创建侧口径不受影响。
- 宽屏分栏（>1020px）与窄屏覆盖（≤1020px，REQ-20260908-005 定位口径不回退）两种形态均适用；深浅色外观均正常。
- 讨论模块 `figure.oncall-fig` 的 260px 上限是否同批调整：**待确认**（范围决策，design.md 裁定；若不动须在修复说明中记录豁免理由）。

## 界面展示

- 布局：条目详情抽屉自上而下为「头部（类型 chip + 单号 + ✕ + 标题）→ 页签行（基本信息 / 说明 / 设计 / 测试用例 / 测试报告(若有) / 讨论纪要）→ 内容区」。现状（缺陷）：说明页签内 markdown 文档框中内联截图压至高 ≤260px（约 221×260），文档框底边以下余约四分之一视口高的空白面板；期望：截图默认显著放大、内容区高度利用充分（形态示意，最终以 design.md 为准）。演示页在模拟看板内并排呈现两种模式，另含窄屏覆盖抽屉形态。
- 交互：点击左侧列表行打开详情（经「加载中…」过渡）；页签切换（说明页签为功能页，其余为占位）；点击截图进入放大层，点击任意处或 Esc 关闭；「现状 / 期望」与「宽屏 / 窄屏」「深 / 浅色」随时切换对照；操作日志逐条记录关键交互。
- 状态反馈：说明页签四种内容状态可切换——加载中（「加载中…」占位）、正常（README 渲染 + 内联竖版截图）、无截图（纯文字 README）、截图加载失败（「截图 xxx 无法加载（文件可能被移动、删除或超过 8MB 上限）」占位，对应 linkupDocImages error 分支）；设计 / 测试用例页签另演示文档未创建空态（「尚未创建，开发阶段补充。」，对应 activateDrawerTab 固定页签缺失分支）；窄屏模式含遮罩与抽屉滑入。

可交互演示：[./ui-demo.html](./ui-demo.html)（单文件、无外网依赖、无构建，浏览器直接打开；内置现状 / 期望对照、宽窄屏与深浅色切换、五种内容状态与操作日志）。

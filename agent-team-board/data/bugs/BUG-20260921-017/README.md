## 现象

1、删除文档编写三阶段的标题文本和下方的副标题
2、语言集组件和刷新等按钮布局在同一行

![截图](attachments/paste-1789997501506.png)

「发布」模块版本详情五步流程的「文档编写」步中，面板顶部副标题条 `.bld-docs-sub`（`scripts/web/build.js` 的 `renderDocsPane`，约 2739–2749 行）当前为**三行纵向结构**（BUG-20260921-012 调整后的落位）：

1. 标题行 `.bld-docs-titlebar`：左侧标题 `<strong>文档编写 · 三阶段</strong>`，右侧「语言集」控件（标签 + 输入框，「保存中…」提示、辅助说明与行内错误换行显示在输入框下方）；
2. 副标题说明行：`<p class="muted small">先总结审查默认语言四文档，审核完毕后 AI 翻译生成剩余语言文档，逐语言审查，最后整体审查完结后方可提交。</p>`——静态教学式文案，与下方阶段条（① 默认语言先行 → ② AI 翻译与审查 → ③ 整体审查完结）与门禁条信息重复；
3. 按钮行 `.bld-docs-actions`：刷新 / AI 总结 / AI 翻译 / 审查 / 整体审查 / 提交 六按钮。

即：标题与副标题两行占位却无操作价值（本步自身已有「文档编写」页签标识，流程含义由阶段条 / 门禁条 / 按钮禁用态传达），且「语言集」控件与六按钮分处两行，操作动线被说明文字隔断。对应样式在 `scripts/web/style.css` 的 `.bld-docs-sub` / `.bld-docs-subtitle` / `.bld-docs-titlebar` / `.bld-docs-langset` / `.bld-docs-actions`（约 3699–3720 行）；标题与副标题句在 `scripts/web/i18n.js` 有对应词条（约 1111、1186 行）。

## 复现步骤

前置：看板项目已存在至少一个构建版本（发布模块版本列表非空）；界面语言不限（中英文均可复现）。

1. 启动看板界面：`node scripts/server.mjs`（默认端口 8888）或桌面壳 `npm run app`。
2. 进入「发布」模块，在版本列表选中任一版本，右侧打开版本详情（五步流程：版本计划 → 关联条目与提交 → 文档编写 → 合并入 main → 正式发布）。
3. 点击步骤页签「文档编写」（步骤页签只改变浏览位置，前置未满足也可浏览）。
4. 观察面板顶部副标题条：第一行「文档编写 · 三阶段」标题（左）+ 语言集控件（右），第二行副标题说明句，第三行才是 刷新 / AI 总结 / AI 翻译 / 审查 / 整体审查 / 提交 按钮行——标题与副标题占位、语言集与按钮不同行，即为本缺陷（见上方截图）。
5. 对照功能正常：语言集回车 / 失焦应用、六按钮门禁（AI 翻译需默认语言 4/4 已审核、整体审查需全部已审核、提交需全部已审核 + 整体审查完结）与刷新 / 保存中 / 错误反馈均工作正常——问题仅在文案占位与控件落位。

## 期望行为

1. **删除标题与副标题**：「文档编写 · 三阶段」标题文本与下方副标题说明句不再渲染；`i18n.js` 中对应词条同步清理（遵循 BUG-20260912-001 中英文同步基线）。
2. **语言集与按钮同行**：「语言集」控件（标签 + 输入框）与 刷新 / AI 总结 / AI 翻译 / 审查 / 整体审查 / 提交 六按钮合并到**同一水平行**内布局（窄屏按现有响应式口径换行，不产生横向溢出）；行内相对次序与对齐细节待开发阶段 design 定稿，但不得回退为「标题行 → 说明行 → 按钮行」的多行现状。
3. 语言集辅助说明（「第一个为默认语言（不带后缀），其余为 KEY_lang.md；回车 / 失焦应用」）的处理方式（换行保留 / 并入输入框 `title` 悬浮提示 / 其他收纳）**待确认**，以不重新占满独立大段为前提，最终以开发阶段 design 定稿为准。
4. 既有交互与状态反馈全部保留，不因删文案 / 并行弱化：
   - 语言集回车 / 失焦应用；输入中草稿不因轮询重渲染丢字；
   - 客户端校验（空值 / 连续逗号空项 / 非 2–3 字母缩写 / 重复语言）就地行内红字报错，不应用非法值；
   - 应用成功 toast「✓ 语言集已应用：…」并联动文档清单（4 类 × N 语言）、门禁与审查对话框；保存中「保存中…」提示 + 输入框禁用；
   - 六按钮恒渲染（加载 / 失败态不隐藏）：刷新运行中禁用并显示「正在读取…」；发布流程数据加载中 / 读取失败时语言集输入禁用（沿用 `phase !== 'ready'` 口径），失败态给错误横幅 + 「重试」。

## 验收说明

1. 布局：进入 发布 → 选中版本 → 文档编写步，面板顶部不再出现「文档编写 · 三阶段」标题与副标题说明句；语言集（标签 + 输入框）与六按钮位于同一行。
2. 文案清理：页面与 i18n 词典中不再残留已删除词条；中英文界面切换均正常（右上语言按钮往返切换检查），i18n 相关测试通过。
3. 交互回归：语言集回车 / 失焦应用正常——合法值（如 `cn,en,fr`）应用后文件清单按语言重新分组（语言页签 + 审核计数角标）、门禁计数随动；非法值（空 / `cn,,en` / `cn1` / `cn,cn`）分别给出对应行内错误且不应用；输入中草稿在自动轮询刷新后不丢字。
4. 状态反馈回归：保存中显示「保存中…」并禁用输入；加载中 / 读取失败态六按钮仍渲染、失败横幅与「重试」可用（重试恢复）；刷新运行中按钮禁用并显示「正在读取…」；AI 翻译 / 整体审查 / 提交的禁用口径（默认语言 4/4 / 全部已审核 / 全部已审核 + 整体审查完结）不变，`title` 缺口提示保留。
5. 窄屏（≤640px）无横向溢出，同行控件按现有响应式口径换行。
6. `npm test` 全量通过（涉及 i18n 词典调整时一并跑 i18n 相关测试）。

## 界面展示

可交互演示：[ui-demo.html](./ui-demo.html)（单文件、内联 CSS/JS、无外网依赖、浏览器直接打开）。

- 界面布局：还原「文档编写」步顶部副标题区结构，提供「缺陷现状 / 期望修复」开关对照——现状为三行纵向（标题行「文档编写 · 三阶段」+ 语言集 → 副标题说明行 → 六按钮行）；期望为删除标题与副标题后语言集与 刷新 / AI 总结 / AI 翻译 / 审查 / 整体审查 / 提交 同一行，下方阶段条、语言页签文件列表与门禁条保留（演示中语言集辅助说明按并入输入框 `title` 悬浮提示示意，最终落位以开发阶段 design 定稿）。
- 交互行为：语言集输入框可编辑，回车 / 失焦应用——合法值（如 `cn,en,fr`）重新分组文件清单（新增语言页签与未翻译文件）并弹 toast；非法值（清空 / 连续逗号 / 非法缩写 / 重复项）就地行内红字报错且不应用；语言页签可切换；「刷新」触发读取反馈，「AI 总结」演示提示词复制反馈，禁用按钮悬浮给缺口原因。
- 状态反馈：演示控制条可切换 正常 / 加载中 / 读取失败 状态（加载与失败态语言集输入禁用、失败附错误横幅 + 重试按钮，重试可恢复）；应用语言集出现「保存中…」过渡反馈；成功 / 失败均有 toast；另附深浅色切换（可选能力）。

# 设计 — BUG-20260921-017 文档编写页面布局优化，去掉无用的文案提示

> 由 Agent 在 /dev 开发前补充，人可随时批注。

## 引入来源（源单）

现状三行纵向布局由两个已实施条目叠加落定（编号均经 `atb list` 核验存在，commit 经 `git log -S` 核验）：

- **REQ-20260921-012**（发布模块文档编写流程三阶段改造，commit `0cab4e3`）：引入顶部副标题条 `.bld-docs-sub` 内的标题 `<strong>文档编写 · 三阶段</strong>` 与副标题说明句「先总结审查默认语言四文档……最后整体审查完结后方可提交。」——两行静态教学式文案的源头。
- **BUG-20260921-012**（语言集移到文档编写三阶段的右侧对齐，commit `684a708`）：把语言集控件自副标题条下方独立行迁入标题行右侧，同时把整体落位定成「标题行（标题 + 语言集）→ 说明行 → 按钮行」三行纵向结构，并引入可见辅助说明行 `.bld-docs-langset-hint`（「第一个为默认语言（不带后缀），其余为 KEY_lang.md；回车 / 失焦应用」）。

## 根因分析

文档编写步顶部区域在两轮增量改造中各自「加行 / 挪行」而未评估既有行的信息价值：

1. REQ-20260921-012 加了标题 + 副标题两行教学式文案，但该步自身已有「文档编写」页签标识，流程含义由阶段条（① 默认语言先行 → ② AI 翻译与审查 → ③ 整体审查完结）、门禁条与按钮禁用态 `title` 缺口提示完整传达——两行文案与既有信息重复，仅占竖向空间；
2. BUG-20260921-012 修语言集落位时沿用该标题行，把语言集塞进「标题右侧」，导致语言集与六按钮被说明文字行隔断成三行，操作动线断开；
3. 语言集可见辅助说明与输入框 `title` 悬浮提示内容重复（title 已含「第一个语言为默认语言（文件不带后缀），其余语言文件为 KEY_lang.md；回车或失焦应用」全量口径），可见行属冗余。

## 方案

**开源选型（REQ-20260909-015）**：无合适库——本单是既有自有 Web UI（`scripts/web/build.js` 内联模板 + `scripts/web/style.css`）的去文案 / 并行布局微调，不涉及新能力，自研（模板与样式调整）成本远低于引入任何前端库；未引入开源依赖，不创建 licenses.md。

改动面（全部在既有结构内，交互与状态反馈口径零变化）：

1. `scripts/web/build.js` `renderDocsPane`：
   - 删除标题 `<strong>文档编写 · 三阶段</strong>` 与副标题说明句 `<p>`，连同 `.bld-docs-subtitle` / `.bld-docs-titlebar` 两层包裹容器一并清理；
   - `.bld-docs-sub` 收敛为单一水平行：语言集簇（`.bld-docs-langset`：标签 + 输入框 +「保存中…」+ 行内错误）在前，六按钮行（`.bld-docs-actions`：刷新 / AI 总结 / AI 翻译 / 审查 / 整体审查 / 提交）随后，同一 flex 行内布局；
   - 删除可见辅助说明行 `.bld-docs-langset-hint`——信息并入输入框既有 `title` 悬浮提示（内容已全量覆盖，README 期望行为第 3 条「以不重新占满独立大段为前提」的收纳方式，与 ui-demo 演示一致）；
   - 语言集交互钩子全部保留：`data-pf-langs` / `label[for]` / 草稿回显（`langsInput` 优先）/ 保存中禁用 + 「保存中…」/ `phase !== 'ready'` 禁用 / 行内错误 `role=alert`；六按钮数据钩子（`data-pf-refresh` 等）与门禁禁用口径不动。
2. `scripts/web/style.css`：
   - `.bld-docs-sub` 由纵向列改单行 flex（`align-items:center; gap:8px 10px; flex-wrap:wrap`），边框 / 圆角 / 内边距保留（窄屏按现有响应式口径自然换行，不产生横向溢出）；
   - `.bld-docs-langset` 去右对齐独占语义，改内容自适应簇（`flex:0 1 auto; min-width:0`）；行内错误 `.bld-docs-langset-err` 保持 `flex-basis:100%` 换行到簇下方右对齐；
   - `.bld-docs-actions` 允许收缩（`flex:0 1 auto; min-width:0`），窄屏整簇放不下时内部换行而非溢出；
   - 删除 `.bld-docs-subtitle` / `.bld-docs-titlebar` / `.bld-docs-titlebar strong` / `.bld-docs-subtitle p` / `.bld-docs-langset-hint` 五条已无对应节点的规则。
3. `scripts/web/i18n.js`：清理三条不再渲染的词条（遵循 BUG-20260912-001 中英文同步基线）：「文档编写 · 三阶段」、「先总结审查默认语言四文档……」、「第一个为默认语言（不带后缀），其余为 KEY_lang.md；回车 / 失焦应用」（title 属性词条「逗号分隔的语言缩写……」保留在用）。
4. 测试：新增 `scripts/tests/bug-20260921-017.test.mjs`（删标题 / 副标题断言、同行结构、交互与状态反馈回归、CSS 契约、i18n 清理与邻近词条保留）；同步更新受布局口径变化影响的既有断言（`bug-20260921-012.test.mjs` 布局与词条部分按新口径重述、`req-20260921-012.test.mjs` L6-1 副标题词条移入已清理清单）。

## 风险与边界

- i18n 词条删除后，若其他界面仍引用同名词条会反向翻译落空——三条词条经全仓 grep 核验仅文档编写步在用（title 属性词条不在删除之列）。
- 窄屏（≤640px）依赖 flex-wrap 自然换行，两簇均允许收缩，不引入横向滚动。
- 阶段条 / 门禁条 / 语言页签文件列表 / 审查对话框均不在改动面，零波及。

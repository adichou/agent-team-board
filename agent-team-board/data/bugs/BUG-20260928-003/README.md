# BUG-20260928-003 发布文档提交流程不携带文档引用的本地图片，AI 翻译与 AI 校对不检查图片语种一致性

## 现象

现象：①看板「文档提交」（docs: 发布文档 BLD-…）的提交范围只由语言集展开的 .md 文档清单生成（server.mjs /api/build/docs/commit → lib/build-git.mjs commitPublishDocs），不含文档正文引用的本地图片；BUG-20260927-001 的修复只放行了 Agent 手工提交通道（state-guard），发布流程路径未覆盖——实际发布提交 7a71eab（BLD-20260927-001）只含 4 个 md 文件，image/README/1790092127929.png 至今未被 git 跟踪，仓库内已提交文档存在悬空图片引用。②发布文档的 AI 翻译与 AI 校对流程均不检查图片引用语种：中文文档应引用中文图片、其他语种文档应引用对应语种图片（如 <name>.png 与 <name>_en.png 的既有惯例），当前两环节均无此检查。复现步骤：1.在看板发布模块完成文档编写、翻译、审查后点「文档提交」，对生成的 docs: 发布文档提交执行 git show --stat，可见只有 .md 文件，文档引用的 image/ 下图片仍是未跟踪状态；2.对引用了中文图片的英文文档走翻译与校对，两环节均不提示图片语种不一致。期望行为：①文档提交时把本次提交文档正文引用的本地图片并入提交范围（口径对齐 BUG-20260927-001 的静态解析：相对路径、图片扩展名白名单、排除源码目录与 agent-team-board/ 目录），保证发布后的文档渲染不破图；无 pathspec 裸提交、--amend、夹带源码等不可核验形态拦截不放松。②AI 翻译对图片引用按语种检查并对齐：中文文档对应中文图片、其他语种文档对应各语种图片；若找不到对应语种的图片则不阻塞、不强求，保持原引用即可，界面显示不出图片由用户自行检查判断。③AI 校对检查图片引用语种一致性，不符合语种的引用必须在校对结果中显式提示出来，交由用户确认处理。

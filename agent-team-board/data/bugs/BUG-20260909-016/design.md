## 根因分析

三轮设置区改造（去模型配置 → 去运行参数 → 去 Agent 化）中，每次改动都把**当轮的机制说明**追加进分区文案，却从不删减上一轮遗留的口径：

- REQ-20260909-011 重写通用说明时，把「提示词单一通用版 / 可在任意一种 Agent 会话粘贴执行 / 无需按 Agent 配置 /（与当前主调度会话一致）」等机制细节全部写进分区说明，形成 119 字两长句；
- REQ-20260909-010 加开关时，又把「done 核验通过 / 仍为已接受 / 自动移入计划（planned）/ 进入批量开发候选 / 不追溯」等流转机制完整复述了**两遍**（`title` 提示 + 可见说明），开头几乎逐字重复。

即：文案按「需求说明书」堆叠而非按「界面提示」提炼——同一口径多处重复、机制术语（done 核验 / accepted / planned / 追溯）直接暴露给用户、句子过长。属纯展示层文案复杂度问题，无配置读写或任务执行故障。

## 方案（实施记录，2026-09-09）

仅改 `scripts/web/app.js` `taskSettingsHtml` 的三处文案，不改任何行为/绑定/接口；新建契约测试 + 同步旧契约断言：

1. **分区说明**（119 字 → 39 字，单句）：
   「两类批量任务均为子代理模式，子代理模型跟随主调度会话；保存仅对后续新任务生效。」
2. **开关说明**（93 字 → 27 字，单句）：
   「开启后完善完成即自动移入计划；默认关闭＝人工移入计划。」
3. **`title` 悬停提示**（73 字 → 与可见说明统一为同一 27 字短句，不再两处长文重复）。

语义四要点保留情况（对照 README 期望行为 1）：
- (a) 子代理模式 / (b) 模型跟随主调度会话 / (d) 保存仅对后续新任务生效 → 分区说明；
- (c) 默认关闭＝人工移入计划、开启＝完善完成即自动移入 → 开关说明（title 同句）。

**待确认项结论**（README「范围与待确认」逐条）：

# BUG-20260925-001 文件编写页面的AI 校对结果页面，每次接收一条都会自动跳到第一条，需要修改为保留在当前修改的条

- 状态：以看板实时状态为准（本文件不维护业务状态）
- 归属：独立 Bug（引入来源归因见 design.md，开发阶段补全）
- 关联：REQ-20260924-006（文档编写流程优化——③ AI 校对建议侧栏为该需求引入的界面）
- 创建：2026-09-24T16:10:28.841Z

## 现象

发布模块「文档编写」步（phase 为 ready 的发布版本）中，右侧「校对建议」侧栏展示某文件的逐条 AI 校对建议。当用户滚动列表查看中间或靠后的建议并点击该条的「接受」后，界面发生整块重渲染，建议列表的滚动位置被重置回列表顶部——视图自动跳到第一条建议，而不是保留在当前正在处理的条目上。

后果：当文件问题较多、建议列表超出可视高度出现滚动条时，用户每接受（或拒绝）一条都要重新滚动定位到刚才的位置才能继续处理下一条，逐条处理效率低，且容易看错条目。「拒绝」操作与校对结果的轮询自动刷新同样会触发重渲染，产生同样的跳回现象。

已核对代码，跳回机制如下（均为可复现的真实行为，非猜测）：

- 「接受」流程 `acceptChkSuggestion` 与「拒绝」流程 `rejectChkSuggestion`（`scripts/web/build.js`）在决断前后都会调用 `render()`；校对 run / 文档状态变化时轮询（`scripts/web/build.js`）也会调用 `render()`。
- `render()` 全量重建「文档编写」窗格 DOM，建议列表容器 `.bld-chk-list`（`scripts/web/style.css`，`max-height: 460px; overflow-y: auto` 的纵向滚动容器）随之被重建，滚动位置丢失、回到顶部。
- 文件下拉的选中文件由 `pf.chkFile` 记忆，文件级选择不会丢；「跳到第一条」发生在建议条目层面（列表滚动位置重置），不是文件切换。

## 复现步骤

1. 打开一个 phase 为 ready 的发布版本，进入「文档编写」步。
2. 点击「③ AI 校对」复制提示词并派发 AI Agent 核查；待回执后，右侧「校对建议」侧栏出现逐条建议。选择一个建议条数较多、列表超出可视高度出现滚动条的文件（可通过文件下拉切换）。
3. 在该文件的建议列表内向下滚动到中间或靠后的某条建议（第 N 条，N > 1）。
4. 点击该条的「接受」（或「拒绝」）。
5. 观察建议列表：滚动位置被重置，视图跳回列表顶部（第一条建议处），刚操作的条目已移出可视区，需重新滚动定位才能继续处理下一条；轮询自动刷新触发重渲染时同样跳回。

## 期望行为

接受（或拒绝）一条建议后，界面应保留在当前正在处理的条目上：不跳回列表顶部第一条，用户能直接看到该条操作后的最新状态（已接受 / 已拒绝）与提示反馈，并可顺势继续处理相邻的下一条建议，无需重新滚动定位。

具体保留方式（如保持列表滚动位置、或重渲染后锚定刚操作的条目）由开发阶段设计定夺；轮询等被动刷新引起的重渲染同样不应打断用户当前查看与处理的位置。主动切换文件下拉仍按现有行为展示新文件列表（从顶部开始不视为缺陷）。

## 验收说明

1. 同一文件存在多条建议且列表出现滚动条时，滚动到第 N 条（N > 1）点「接受」：接受成功后视图停留在第 N 条（或锚定该条）附近，该条状态变为「已接受」，不跳回列表顶部第一条；toast 成功反馈照常。
2. 第 N 条（N > 1）点「拒绝」：视图同样保留在当前条目，该条状态变为「已拒绝」，原文不变。
3. 接受 / 拒绝后侧栏「待处理 N 项」计数同步减少；连续处理下一条建议时无需重新滚动定位。
4. 校对 run 状态变化触发轮询自动重渲染时，建议列表滚动位置不被重置（不打断当前处理位置）。
5. 建议过期（stale）路径不受影响：文本已变化时仍标记「过期」并提示，不覆盖人工修改；「待确认」类建议、不可自动应用的建议及「✎ 修改」跳转行为不变。
6. 文件下拉手动切换仍为主动操作，切换后展示新文件列表从顶部开始属正常行为。
7. 如修复涉及界面文案新增 / 改动，须中英文同步（`scripts/web/i18n.js`）并跑 i18n 相关测试。
8. `npm test` 全量通过，含 `scripts/tests/req-20260924-006.test.mjs` 既有口径回归（修复不得破坏校对建议解析 / 应用 / 计数纯函数与既有交互接缝）。

## 界面展示

### 布局

「文档编写」步主区左侧为发布文档文件列表（语言页签 + 文件卡片），右侧为「校对建议」侧栏（窄屏纵向堆叠）。侧栏自上而下：

1. 侧栏头：标题「校对建议」+「待处理 N 项」计数徽标（全部决断后变绿色并解锁「④ AI 翻译」）。
2. 文件行：「文件」标签 + 文件下拉（列出校对范围文件，问题文件名后附问题条数）。
3. 建议列表：纵向滚动容器（`max-height: 460px; overflow-y: auto`），每条建议一张卡片——类型标签（链接 / 错别字 / 语法 / 行文规范 / 待确认）、位置（第 N 行 / 无行号）、状态徽标（待处理 / 已接受 / 已拒绝 / 过期 / 待确认）、问题原文；可展开「查看修改前后差异」（左删右增双列对照）；操作行含「接受」「拒绝」「✎ 修改」按钮。

### 交互

- 文件下拉切换：列表切换为所选文件的建议。
- 「接受」：按钮进入忙碌态 → 应用前后差异并保存 → 该条变「已接受」、待处理计数减一、toast「✓ 已接受并保存…」；保存失败 toast 报错且不误标。
- 「拒绝」：该条变「已拒绝」，原文不动，toast「已拒绝该条建议」。
- 「✎ 修改」：跳入二次编辑弹窗并定位到该行。
- 差异折叠：点卡片内「查看修改前后差异」展开 / 收起对照。

### 状态反馈

- 正常（已完成）：逐条建议卡片 + 待处理计数。
- 进行中：进度文本「校对进行中 X/Y · 当前：<文件>」。
- 失败（中断）：错误原因 +「重试 AI 校对」按钮，已回执结论保留。
- 空态：尚未校对（引导文案）、无默认语言文档、该文件未发现问题（✓ 提示）。
- 特殊条目：「待确认」（无法验证的链接，仅展示不走自动接受）、「过期」（提示文本已变化不覆盖）。

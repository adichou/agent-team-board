# BUG-20260915-008 确认与核验流程同步跑测试阻塞看板服务数分钟，面板整体冻结且无进度提示

- 状态：accepted（已接受）
- 引入来源：REQ-20260914-001（引入挂起确认闭环：核验/确认并继续的测试复验由 `runProjectTests` 以 spawnSync 同步执行）
- 创建：2026-09-15T01:31:53.862Z

## 现象

任务页触发「重新核验」或「确认并继续」时，服务进程用 `spawnSync` **同步**执行 `npm test`（超时上限 600 秒）。Node 单进程模型下这会阻塞整个事件循环，测试运行期间（本项目全量约 4 分钟）：

- 面板 2 秒轮询停摆，页面呈现整体冻结；
- 其他一切操作（接受条目、看板切换、健康探活）排队挂起，按钮停在忙态。

实测（2026-09-15 09:22–09:26）：BUG-20260914-020「确认并继续」触发的 4 分钟测试期间，用户对 BUG-20260915-007 的「接受」操作被阻塞、请求最终丢弃未落盘，页面按钮一直显示「正在接受中」，事后需刷新重试。测试期间无任何进度提示，用户无法区分「在跑」与「卡死」。

## 复现步骤

1. 看板开着（8888 服务运行中），任一条目处于「待人工确认（提交挂起）」；
2. 任务页点「确认并继续」或「重新核验」（项目测试量大时效果显著，本项目约 4 分钟）；
3. 观察期间面板：轮询停止、其他操作全部无响应、按钮停留忙态、无进度信息。

## 期望行为

- 核验/确认的测试执行改为**异步**（`child_process` 异步 spawn），服务事件循环保持响应：测试期间面板可正常轮询、可操作其他条目；
- 前端有**进度上报**：至少「测试运行中 · 已运行 N 秒 / 超时上限 M 秒」级别的进行中状态与阶段提示（核验 → 补交 → 测试 → 恢复队列），完成后回填结果；
- 同一条目同一时刻的核验任务互斥（防重复触发并发跑两份测试）。

## 验收标准

1. 触发核验后 2 秒内 `/api/health` 仍可响应，面板可对其他条目正常操作；
2. 测试运行期间该条目卡片/面板显示进行中状态与运行时长，不再呈现整页冻结；
3. 完成后结果落账与现状口径完全一致（verify 字段、挂起闭环流转、队列恢复不变）；
4. 同条目重复触发核验被互斥拒绝并有明确提示；
5. 服务重启后运行中任务的账本状态可恢复或明确标记为中断，不出现「测试跑完但确认没落账」的中间态；
6. 异步执行、进度回传、互斥三条路径有测试覆盖。

# BUG-20260921-014 去掉合并入 main 页签下面的发布范围区域

- 状态：submitted（待人工接受）
- 归属：独立 Bug（引入来源见 design.md）
- 创建：2026-09-21T07:59:51.879Z

## 现象

Web 看板「构建」模块中，选中一个版本后右侧详情为五步导航（版本计划 → 关联条目与提交 → 文档编写 → **合并入 main** → 正式发布，REQ-20260920-003 引入）。切到「合并入 main」页签后，页面最上方第一个区块是「发布范围」（`scripts/web/build.js` 的 `renderMergePane(v)` 内首个 `<section><strong>发布范围</strong>` 区块），内容包括：

- 关联条目清单：每行「条目号 + commit 短 hash + 已合并 / 失败徽标」，部分合并重试时徽标混合出现；无关联条目时显示「（无关联条目：回到「关联条目与提交」步骤关联）」。
- 「文档提交：`<短hash>`（只随本版发布最新文档提交）」一行（存在文档提交时）。

该区块与页面其余信息完全重复，属冗余展示：

- 同样的条目 + commit + 已合并（✓）/ 失败（✕）状态，上一步「关联条目与提交」页签已完整展示（还带搜索、分页、移出操作，`renderDetail` 的关联列表）；
- 文档提交 hash，「文档编写」页签的提交门禁条已展示（「已提交到本地 dev 分支（hash …）：满足「合并入 main」前置」）；
- 点击「合并入 main」按钮后的确认弹窗（`renderMergeConfirm`）会再次列出将合并的完整 commit 清单。

结果是「合并入 main」页签首屏被重复信息占据，用户须滚动才能看到真正与本步相关的内容（隔离分析、分支检查、门禁与合并按钮）。

## 复现步骤

1. 打开 Web 看板，进入「构建」模块（版本计划页签）。
2. 在左侧版本列表选中一个已有关联条目、且发布流程数据可加载的版本（任意状态；draft / failed 均可观察）。
3. 在右侧详情的五步导航中点击「合并入 main」页签。
4. 等待发布流程数据加载完成（loading / 失败态下不渲染该区块）。
5. 观察：页签内容第一个区块即「发布范围」，重复列出关联条目 + commit 与文档提交信息——即为缺陷现象。
6. 对照：切回「关联条目与提交」页签，可见完全相同的条目与 commit 状态信息（此即冗余依据）。

## 期望行为

- 「合并入 main」页签不再渲染「发布范围」区块：整个 `<section>`（含关联条目清单、空态提示「（无关联条目：回到「关联条目与提交」步骤关联）」与「文档提交：…（只随本版发布最新文档提交）」行）一并移除，不保留空壳标题。
- 移除后页签剩余内容与顺序保持不变：隔离分析 → 当前分支提示（dev / 非 dev 阻止提示）→ 门禁禁用原因（如有）→「合并入 main」主按钮及说明 → 合并失败原因 / 合并完成结果。加载中、读取失败（重试）态行为不变。
- 信息不丢失口径（修复不弱化既有能力）：
  - 关联条目 + commit + 已合并 / 失败状态：仍在「关联条目与提交」页签查看与操作；
  - 文档提交 hash：仍在「文档编写」页签提交门禁条查看；
  - 合并前核对：REQ-20260920-003 的「合并前列出计划条目提交」要求由合并确认弹窗继续承担，弹窗内容不变。
- 同步清理死文案：`scripts/web/i18n.js` 中「发布范围: 'Release scope'」词条若因此不再有使用处，按 BUG-20260912-001 口径中英文一并清理，不留半语言残留。

## 验收说明

- 手动验收：
  - 选中已有关联条目的版本，切到「合并入 main」页签：首区块直接为「隔离分析」（或后续区块），整页不出现「发布范围」标题区块；
  - 分别在无关联条目、部分条目已合并（failed 重试场景）、已合并（merged）状态下检查，均无该区块、无空壳残留；
  - 「关联条目与提交」页签仍完整展示条目 + commit + 合并状态；「文档编写」页签仍显示文档提交 hash；点击「合并入 main」确认弹窗仍列出完整 commit 清单；
  - 中 / 英界面语言下检查均无「发布范围 / Release scope」残留（i18n 词典同步清理）。
- 测试验收：新增 / 更新测试断言 `renderMergePane` 输出不含「发布范围」区块（现有引用该函数的测试如 bug-build-merge-click-feedback-20260920-006.test.mjs 不得回归）；`npm test` 全量通过。
- 不改动后端 / 发布流程语义：仅前端展示层移除，`/api/build/publish-plan` 等接口与合并、隔离分析、门禁逻辑不受影响。

## 界面展示

- 界面布局：演示复现「构建」模块右侧版本详情——顶部版本名与状态，其下为五步导航页签（版本计划 / 关联条目与提交 / 文档编写 / 合并入 main / 正式发布），当前聚焦「合并入 main」页签；页签内区块顺序为 发布范围（仅缺陷现状）→ 隔离分析 → 分支提示 → 门禁与「合并入 main」主按钮 → 合并结果反馈。
- 交互行为：顶部开关可在「缺陷现状」与「修复后」之间切换对比；场景条可切换 就绪（有关联条目）/ 空关联 / 加载中 / 读取失败 / 合并失败 / 已合并；五步页签可点击切换（「关联条目与提交」页签用于对照信息仍完整可见）；点击「合并入 main」弹出确认弹窗（列 commit 清单），确认后模拟合并执行 → 完成；读取失败可点「重试」恢复。
- 状态反馈：加载中显示「正在加载合并分析…」；读取失败显示错误条 + 重试入口；合并执行中按钮禁用防重复；合并成功 toast 提示并展示合并完成信息（主分支头 hash）；合并失败显示失败原因与「重试合并入 main」按钮；深浅色随系统自动适配。

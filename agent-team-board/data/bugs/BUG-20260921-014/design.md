本 Bug 由哪个需求 / Bug 引入？登记时可暂空或写「未定位」，修复阶段必须归因（三选一，禁止编造）：

## 根因分析

`scripts/web/build.js` 的 `renderMergePane(v)` 首个 `<section><strong>发布范围</strong>` 区块无条件渲染三类信息：

1. 关联条目清单（条目号 + commit 短 hash + 已合并 / 失败徽标，`scopeRows` 拼装）——与「关联条目与提交」页签（`renderDetail` 的关联列表，带搜索 / 分页 / 移出）完全重复；
2. 无关联条目空态提示——与关联页签空态引导重复；
3. 文档提交 hash 行——与「文档编写」页签提交门禁条重复；合并确认弹窗（`renderMergeConfirm`）还会第三次列出 commit 清单。

冗余区块占据页签首屏，用户须滚动才能到达与本步真正相关的隔离分析 / 分支检查 / 门禁与合并按钮。属展示层冗余，无后端语义问题。

## 方案

纯前端展示层移除（不引入开源库——单区块删除、无第三方依赖场景，自研即删除本身）：

1. `renderMergePane` 删除整个「发布范围」`<section>`（含 `scopeRows` 清单、空态提示、文档提交行），同时删除只服务于该区块的死变量 `scopeRows`；其余区块（隔离分析 → 分支提示 → 门禁禁用原因 → 主按钮及说明 → 失败原因 / 完成结果）与 loading / error 态不变。
2. `scripts/web/i18n.js` 删除因此不再有使用处的死词条 `'发布范围': 'Release scope'`（中英一并清理，不留半语言残留；其余含「发布范围」字样的长句词条各有独立键，不受影响）。
3. 信息不丢失口径：关联条目 / commit / 合并状态仍在「关联条目与提交」页签；文档提交 hash 仍在「文档编写」页签门禁条；合并前核对仍由 `renderMergeConfirm` 弹窗承担。

**开源选型（REQ-20260909-015）**：本单为纯删除类前端修复，无新增能力，未引入开源库（无合适库的原因：不涉及新功能实现，仅移除冗余渲染分支），不创建 licenses.md。

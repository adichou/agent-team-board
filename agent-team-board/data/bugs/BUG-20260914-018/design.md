> 由 Agent 在 /dev 开发前补充，人可随时批注。

## 引入来源（源单）

本 Bug 由哪个需求 / Bug 引入？登记时可暂空或写「未定位」，修复阶段必须归因（三选一，禁止编造）：

- 引入来源：BUG-20260914-017（经 `atb list` 核验存在，状态 done）——该单为让「和远端同步排除
  main」的规则在界面上自解释，在分支浏览本地 main 分支行（当前行 / 非当前行两处）新增了常驻
  「通过发布流程推送」虚线徽标（`mainFlagHtml()` + `.bld-main-flag` 样式 + 两条 i18n 词条）。
  用户现反馈要删掉这段文字（未说明动机，按 README「移除徽标、不加替代」口径处理）。

## 根因分析

BUG-20260914-017 的修复在 main 行上叠加了常驻说明徽标。规则说明本身有价值（main 不随同步推送、
也无单独推送按钮），但用户明确要求删除 main 行上的这段文字——徽标占据了其他分支「推送」按钮的
位置，属展示层过度自解释。规则说明在界面上并非只剩这一处：工具栏常驻说明「同步仅推送 main 以外
的本地分支；main 必须通过发布流程推送。」与同步结果 toast「main 已跳过，请通过发布流程推送」
均不在 main 行上，按 README 范围边界默认保留。

## 方案

仅展示层删除（`scripts/web/build.js` / `style.css` / `i18n.js`），不触碰数据层与服务端：

1. **删徽标（两处）**：`renderBranchesPane()` 中删除 `mainFlagHtml()` 及其两个拼接点——当前分支
   为 main 的「当前」行与本地非当前 main 行；main 行右侧不再渲染任何徽标 / 说明（`${x === 'main'
   ? '' : …}` 仅去掉推送按钮，无替代标识），行点击查看提交记录语义不变。
2. **死代码 / 死词条清理**：`style.css` 删除 `.bld-branch .bld-main-flag` 规则及注释；
   `i18n.js` 删除「通过发布流程推送」「main 由发布流程推送：不随『和远端同步』推送，也无单独推送
   按钮」两条 EN 词条并更新组注释。
3. **测试反向调整**：`bug-sync-main-release-note-20260914-017.test.mjs` U2 / U2b 断言改为
   「main 行无该标识、无悬停详释、无推送入口」（非 main 行推送按钮不受影响）；W1 对应词条断言
   改为死词条清理断言；S1 增加 `mainFlagHtml` / `.bld-main-flag` 在 build.js / style.css 的
   无残留静态断言，并保留 syncRemote 排除 main 的服务端不越界断言。U1 / U3–U6 / W2 不变
   （范围边界：仅删 main 行上的文字）。

**开源选型（REQ-20260909-015）**：无合适库的原因——本单为纯展示层删除既有徽标 / CSS / 词条，
不涉及任何可复用的第三方能力，引入库成本高于自研；未引入开源库，不创建 licenses.md。

## 风险与边界

- 不修改 `build-git.mjs syncRemote()` 排除 main 的行为与发布模块流程（S1 断言守护）；main 行
  仍无「推送」按钮（BUG-20260914-012 口径，U2/U2b 断言守护）。
- 不删同批引入、但不在 main 行上的说明（工具栏常驻说明、同步 toast「main 已跳过」、按钮 title
  「main 除外」）——README「范围边界（待确认）」默认口径；用户若要求一并删除需另行确认后扩展。
- 删除后 main 行仅剩分支名（当前行另有「当前」徽标），右侧留白为预期形态；不新增任何替代说明
  （README「不加替代」）。

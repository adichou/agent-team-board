# BUG-20260914-018 分支浏览页面中的 main 分支通过发布流程推送的文字删掉

- 状态：accepted（已接受）
- 归属：独立 Bug（引入来源见 design.md）
- 创建：2026-09-14T14:18:52.685Z

## 现象

BUG-20260914-017 为让「和远端同步排除 main」的规则在界面上自解释，在 构建 → 分支浏览 的**本地 main 分支行右侧加了常驻的「通过发布流程推送」说明徽标**（虚线描边、右对齐，悬停有详释 title）。用户现反馈：**这段文字要删掉**。用户未说明删除动机（待确认），本单按「移除 main 行上的该徽标文字」处理，不改同步行为。

现状链路（均经源码核实，2026-09-14）：

1. **徽标生成**：`scripts/web/build.js` `mainFlagHtml()`（约 1156–1160 行）输出
   `<span class="bld-main-flag" title="main 由发布流程推送：不随「和远端同步」推送，也无单独推送按钮">通过发布流程推送</span>`。
2. **两处拼接**：`renderBranchesPane()` 中——本地非当前 main 行（约 1181–1183 行，main 行以此徽标占住其他分支「推送」按钮的位置）与当前分支恰为 main 时的「当前」行（约 1177 行）都渲染该徽标。
3. **配套样式**：`scripts/web/style.css` `.bld-branch .bld-main-flag`（约 3061–3066 行）。
4. **配套 i18n 词条**：`scripts/web/i18n.js`（56–57 行）收录「通过发布流程推送」「main 由发布流程推送：…」及英文译文。
5. **测试断言依赖**：`scripts/tests/bug-sync-main-release-note-20260914-017.test.mjs` 的 U2 / U2b（约 125–152 行）断言 main 行（当前行与非当前行）含该标识——删除后断言需随实现反向调整。

## 复现步骤

前置：git 仓库项目，本地存在 main 分支（dev + main 双分支、当前分支 dev 最典型）。

1. 项目目录终端运行 `atb serve`（默认端口 8888，`ATB_PORT` 可覆盖），浏览器打开 `http://localhost:8888`，顶栏项目选择器选中该项目。
2. 切到「构建」模块 → 「分支浏览」子页签。
3. 观察「本地」分组 main 行：右侧显示虚线徽标**「通过发布流程推送」**，鼠标悬停出现详释提示「main 由发布流程推送：不随「和远端同步」推送，也无单独推送按钮」——即本 Bug 要求删除的文字。
4. 补充路径：把当前分支切到 main 后点「刷新」——main 以「当前」行置顶，右侧同样显示该徽标（删除需两处一并处理）。
5. 对照其余「发布流程」文字：工具栏下常驻说明「同步仅推送 main 以外的本地分支；main 必须通过发布流程推送。」与同步 toast 中的「main 已跳过，请通过发布流程推送」**不在 main 行上**，属 BUG-20260914-017 的其他修复点（范围见「期望行为」）。

## 期望行为

- **删除徽标**：分支浏览「本地」分组 main 分支行不再显示「通过发布流程推送」徽标及其悬停详释——当前分支为 main 的「当前」行与本地非当前 main 行两处都删；行上仅保留分支名（当前行另保留「当前」徽标）。
- **不加替代**：不在 main 行新增任何替代说明/标识（用户要求删文字；若需保留说明属产品决策：待确认）。
- **行为不变**：main 行点击仍可查看提交记录；main 仍无「推送」按钮（BUG-20260914-012 口径不变）；「⟳ 和远端同步」仍不推送 main（`scripts/lib/build-git.mjs` `syncRemote()` 排除 main 不变）。
- **范围边界（待确认）**：本单标题仅指 main 分支行上的文字。BUG-20260914-017 同批引入的工具栏常驻说明「同步仅推送 main 以外的本地分支；main 必须通过发布流程推送。」、同步结果 toast「main 已跳过，请通过发布流程推送」、按钮悬停提示里的「main 除外」**默认保留不删**；若用户要求一并删除，需另行确认后扩展。
- **清理配套**：`.bld-main-flag` 样式、`mainFlagHtml()` 及 i18n 词条（「通过发布流程推送」「main 由发布流程推送：…」）随之清理，不留死代码/死词条；`scripts/tests/bug-sync-main-release-note-20260914-017.test.mjs` U2 / U2b 断言改为「main 行无该标识且无推送入口」，`node scripts/tests/run-all.mjs` 全量通过。

## 验收说明

1. **非当前 main 行**：dev + main 双分支仓库（当前分支 dev）打开 构建 → 分支浏览：「本地」分组 main 行无「通过发布流程推送」徽标、无对应悬停提示，行右侧不再有徽标占位。
2. **当前 main 行**：当前分支切为 main 后刷新：main 置顶「当前」行同样无该徽标，仅显示分支名 + 「当前」。
3. **交互回归**：main 行点击仍能查看提交记录；main 行无「推送」按钮、无任何直接推送入口；非 main 行「推送」按钮与推送确认流程不受影响。
4. **同步回归**：「⟳ 和远端同步」行为不变（fetch + 推送除 main 外分支，toast 口径不变）；按「范围边界」默认口径，工具栏常驻同步说明与「main 已跳过」反馈保留。
5. **i18n**：切英文界面无残留徽标；清理后的 i18n 词典无「通过发布流程推送」相关死词条，其余词条不受影响。
6. **静态与测试**：`build.js` / `style.css` 无 `.bld-main-flag` / `mainFlagHtml` 残留；`bug-sync-main-release-note-20260914-017.test.mjs` U2 / U2b 反向断言通过；`node scripts/tests/run-all.mjs` 全量通过。

## 界面展示

可交互演示：[`./ui-demo.html`](./ui-demo.html)（单文件、内联 CSS/JS、无外网依赖、无构建步骤，浏览器直接打开可交互；数据为模拟，布局与交互按 `scripts/web/build.js` `renderBranchesPane()` 现行为复刻）。提供「当前（缺陷）↔ 修复后」一键对照——缺陷态 main 行右侧为「通过发布流程推送」徽标，修复后该徽标消失、行仅剩分支名；并含场景切换（典型 dev+main / 当前为 main / 仅 main / 非 git 仓库）、中英文切换、推送失败与同步失败模拟、分支列表与提交记录加载态。

- 界面布局：还原「构建 → 分支浏览」子页签——左右分栏：左侧分支列表（顶部「⟳ 和远端同步」「刷新」工具栏与常驻同步范围说明；下方「本地 / 远端」分组，本地组当前分支置顶带「当前」徽标，**缺陷态 main 行右侧带「通过发布流程推送」虚线徽标，修复后消失**，dev / 功能分支行右侧保留「推送」按钮），右侧为选中分支的提交记录。
- 交互行为：点击分支行懒加载右侧提交记录（main 行同样可点开，两种模式下均无推送入口）；「和远端同步」执行 fetch + 推送除 main 外分支（按钮禁用显示「同步中…」，远端分组出现 origin/dev 等、永不出现 origin/main）；点「推送」弹确认框；演示控制条可切「当前（缺陷）/ 修复后」对照 main 行徽标的有无，切「当前为 main」验证当前行徽标同样被删，切「仅 main」验证无可推送分支文案，切中 / 英文验证翻译清理。
- 状态反馈：同步成功 toast「已推送 …；main 已跳过，请通过发布流程推送」在两种模式下口径一致（本单不改）；勾选「模拟推送失败」演示部分失败反馈；勾选「模拟同步失败」演示 fetch 失败错误 toast；进入 / 刷新列表显示「加载分支中…」、点选分支显示「加载提交记录中…」、空提交分支显示「该分支暂无提交」；英文切换下徽标词条在缺陷态仍可翻译（现状事实）、修复后整行无徽标可译。

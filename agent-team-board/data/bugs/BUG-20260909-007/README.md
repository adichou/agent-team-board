# BUG-20260909-007 详细页面的返回按钮多余，因为已经有关闭按钮了

- 状态：accepted（已接受；本轮仅完善说明，未实施修复）
- 归属：独立 Bug（引入来源见 design.md）
- 引入来源：REQ-20260907-004（窄屏覆盖式抽屉 + 返回入口）。关闭按钮 `✕` 在该需求之前已存在并由 REQ-20260906-005 定位到单号紧右侧；REQ-20260907-004 新增的「← 返回」与其在同一头部并存且行为完全相同，形成冗余。两编号均经 `atb list` 核验真实存在（2026-09-09，均 in-progress）。
- 创建：2026-09-09T04:48:09.914Z

## 现象

看板「需求」模块的需求 / Bug 详情抽屉（drawer）头部第一行（`.card-top`）同时渲染了两个功能完全相同的关闭出口：

1. 「← 返回」按钮（`#drawerBack`，标记 `drawer-back`，`scripts/web/app.js` 第 2141 行）——仅窄屏（≤1020px）可见：`scripts/web/style.css` 第 451 行默认 `display: none`，第 653 行起的 `@media (max-width: 1020px)` 内第 670 行恢复 `display: inline-flex`。它由 REQ-20260907-004 随「窄屏覆盖式抽屉 + 返回入口」引入。
2. 「✕」关闭按钮（`#drawerClose`，`scripts/web/app.js` 第 2143 行）——任意宽度常驻，按 REQ-20260906-005 固定在单号行紧右侧，hover 有背景高亮。

两者的点击处理完全一致：都直接调用 `closeDrawer()`（`scripts/web/app.js` 第 2202–2203 行）。窄屏下详情是覆盖在列表上的抽屉，「返回列表」与「关闭」本就是同一动作（抽屉收起、遮罩消失、露出列表），不存在语义差异。

此外窄屏模式还有两个等价出口：键盘 Escape（`scripts/web/app.js` 第 4225–4227 行）与点击遮罩（`scripts/web/app.js` 第 4212 行；遮罩仅在覆盖模式下显示，第 2037 行）。

由此产生的问题：

- **冗余占位**：窄屏详情头部同时出现「← 返回」与「✕」两个按钮，行为一模一样，挤占单号行空间且让用户困惑「返回」与「关闭」是否有区别（如返回是否保留阅读位置——实际没有任何区别）。
- **宽窄屏行为不一致的假象**：宽屏（>1020px）下「← 返回」被 CSS 隐藏、只剩「✕」，说明宽屏早已只靠关闭按钮工作；窄屏多出的返回按钮并无独占能力。
- **死代码与双重断言负担**：`drawer-back` 样式、`drawerBack` 按钮与绑定仅为这个重复出口存在，`scripts/tests/drawer-height.test.mjs`（D4「窄屏返回入口可见」）、`scripts/tests/workbench-layout.test.mjs`（`/drawerBack/`、`/.drawer-back/` 断言）、`scripts/tests/portrait-board.test.mjs`（「窄屏显示返回列表入口」）三处测试固化了该冗余现状。

范围界定（依据代码核实）：

- 讨论模块详情（`scripts/web/oncall.js` 第 330 行 `#ocBack`「← 返回列表」）**没有**并存的「✕」关闭按钮，返回入口是其唯一出口，不冗余、不在本 Bug 范围；但该按钮与需求侧共用 `.drawer-back` 样式类与同一条窄屏媒体查询规则（`scripts/web/style.css` 第 670 行），修复时不得误伤。
- 批次抽屉（`scripts/web/app.js` 第 2772 行 `#batchClose`，title「返回需求模块」）现状只有单一「✕」，无冗余，不在本 Bug 范围。

## 复现步骤

前置：看板服务已启动（`node scripts/atb.mjs serve`，默认 `http://127.0.0.1:8888`），当前项目内至少有 1 条需求或 Bug 条目（无则顶栏「新建」任建一条并「接受」）。

1. 浏览器窗口宽度压到 1020px 及以下（或用开发者工具设备模拟 / 窄窗口）。
2. 进入「需求」模块，点击任一条目行：详情以覆盖式抽屉从右滑入，列表上方出现半透明遮罩。
3. 观察详情头部第一行：单号左侧有「← 返回」按钮，单号紧右侧又有「✕」按钮——两个出口并存。
4. 点击「← 返回」：抽屉收起、遮罩消失、回到列表。
5. 重新点开同一详情，点击「✕」：结果与步骤 4 完全一致（同一 `closeDrawer()`，无任何状态或滚动差异）。
6. 再点开详情，分别按 Escape 键、点击遮罩空白处：同样关闭详情——窄屏下同一动作共有四个出口。
7. 把窗口拉宽到 1020px 以上再点开详情：「← 返回」消失（CSS `display: none`），头部只剩「✕」；宽屏并排布局下关闭详情右栏回到「选择左侧列表中的条目查看详情」空态。
8. 结论：窄屏独有的「← 返回」没有任何「✕」不具备的能力，属多余按钮。

## 期望行为

- 需求 / Bug 详情抽屉头部移除「← 返回」按钮：`scripts/web/app.js` 中的 `drawerBack` 标记（第 2141 行）与其事件绑定（第 2203 行）删除，`scripts/web/style.css` 中需求侧对应的 `.drawer-back` 规则（第 451、670 行）按开发阶段 design.md 的样式拆分结论处理；关闭出口唯一收敛为既有「✕」（位置保持 REQ-20260906-005 的单号紧右侧不变）。
- 窄屏关闭详情的三条既有路径保持可用（回归项）：点击「✕」、键盘 Escape、点击遮罩，行为均为抽屉收起、遮罩消失、回到列表，列表滚动位置与选中态按现状处理（`closeDrawer()` 现有逻辑不变）。
- 宽屏（>1020px）并排布局不回归：详情右栏常驻、空态文案、「✕」关闭行为保持。
- 讨论模块（oncall）详情的「← 返回列表」保持可见可用（回归项）：`.drawer-back` 为两处共用的样式类，修复须精确移除需求侧按钮而不得影响讨论侧返回入口的窄屏显隐。
- 断言现状的既有测试随功能移除同步更新，不留红灯：`scripts/tests/drawer-height.test.mjs`（D4 窄屏返回入口断言）、`scripts/tests/workbench-layout.test.mjs`（`/drawerBack/` 与 `/.drawer-back/` 断言）、`scripts/tests/portrait-board.test.mjs`（窄屏显示返回列表入口断言）。
- `scripts/web/app.js`、`scripts/web/style.css` 中不残留需求侧 `drawerBack` / `.drawer-back` 死代码；讨论侧保留部分的最终样式组织方式（独立类名或保留共用规则）由 design.md 定夺。

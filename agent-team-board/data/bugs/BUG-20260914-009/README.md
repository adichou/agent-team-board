# BUG-20260914-009 dev 界面只加载最近 50 条，需要修复成显示所有，并支持分页展示

- 状态：submitted（待人工接受）
- 归属：独立 Bug（引入来源见 design.md；涉及界面为构建模块「分支浏览」提交记录面板，由 REQ-20260913-001 建立）
- 创建：2026-09-14T04:51:58.340Z

## 现象

构建模块「分支浏览」页签中，点选任一分支（日常开发主战场是 dev 分支）后，右侧提交记录列表**只显示最近 50 条提交，且没有任何分页 / 加载更多入口**——更早的提交历史在界面上完全无法查看。「dev 界面」即指以 dev 分支视角查看提交记录的这一界面。

具体链路（均经源码核实）：

1. **前端不传条数参数**：`scripts/web/build.js` 的 `selectBranch()`（约 210 行）请求 `` api(`/branch-log?branch=${encodeURIComponent(branch)}`) ``，只带分支名，不带 `limit` / `offset` 等任何分页参数；随后把返回的 `commits` 一次性平铺渲染进 `<ul class="bld-log">`（约 1023–1046 行），无分页控件。
2. **服务端默认 50 条**：`scripts/server.mjs` 的 `GET /api/build/branch-log` 处理器（约 2089 行）调用 `buildGit.branchLog(root, branch)` 时未传 `limit`；其接口文档注释（约 2019 行）也明确写着「指定分支最近提交（≤50 条）」。
3. **数据层默认 50、上限 200 且不支持翻页**：`scripts/lib/build-git.mjs` 的 `branchLog(root, branch, limit = 50)`（66–79 行）执行 `git log -n <n>`，`n = Math.max(1, Math.min(200, Number(limit) || 50))`——默认 50，即使调用方显式传更大值也被硬顶在 200；函数不支持 offset / skip，**任何调用方式都无法取到第 200 条之前的提交**。
4. **dev 分支最先触顶**：本项目 git 工作流约定「dev 分支承载需求设计、开发和测试」（`scripts/web/app.js` 约 7041 行），每次开发运行都会在 dev 上自动提交——dev 的提交数持续增长、很快超过 50 条，界面上第 51 条以前的提交从此不可见（例如想核对某个 REQ-/BUG- 单号在何时首次提交时查不到）。
5. **界面无任何「未显示完」提示**：列表在 50 条处静默截断，不显示总数（如「共 137 条」）、不提示还有更早记录，用户容易误以为分支只有 50 条提交。

## 复现步骤

前置：看板所在项目为 git 仓库，且当前工作分支（dev）提交数超过 50 条（本项目日常使用下 dev 分支很快满足；也可临时用循环提交造 60+ 条验证）。

1. 打开 Agent Team Board 看板（Web 或 Electron 端），顶栏切到「构建」页。
2. 切到「分支浏览」子页签，左侧分支列表出现「本地 / 远端」分组。
3. 点击本地分支 `dev`（标「当前」）。
4. **实际结果**：右侧提交记录面板列出提交（短 hash + 说明 + 作者 + 时间），**恰好停在第 50 条（最新 50 条）**；面板内没有「上一页 / 下一页 / 加载更多」任何入口，头部只有「刷新」按钮。
5. 对照 git 事实：终端执行 `git log --oneline dev | wc -l`（或 `git rev-parse dev` 后数提交）得到真实总数（如 137 条）——第 51 条及更早的提交在看板界面上无法查看。
6. **边界确认**：点「刷新」仍只有 50 条；切到 `main` 或其他提交数 ≤ 50 的分支时列表看似「完整」，实为同一上限逻辑（数据层 `branchLog` 默认 limit=50 对所有分支一致生效），并非 dev 独有。

## 期望行为

- **显示所有（核心）**：「分支浏览」中任一分支的提交记录都能完整查看，不存在第 51 条（及第 201 条）以后永远不可见的情况；数据层 `buildGit.branchLog` 的「默认 50 / 上限 200 且无翻页」限制需放开（`git log` 支持 `-n` + `--skip` 组合做偏移分页，或等价实现）。
- **支持分页展示**：提交记录列表提供分页交互（页码 / 上一页 / 下一页，或「加载更多」追加，具体交互形式**待确认**、由开发阶段 design.md 落定），并展示「已加载第 x–y 条 / 共 N 条」之类的进度信息，替代现在的静默截断；末页到底有明确反馈。
- **服务端接口具备分页能力**：`GET /api/build/branch-log` 支持 `limit` + `offset`（或页码）参数并返回总数，供前端分页；不传参数时的缺省行为（是否仍默认 50 条首屏）**待确认**。
- **既有行为不回归**：分支切换、头部「刷新」、加载中（「加载提交记录中…」）/ 读取失败 / 空分支（「该分支暂无提交」）状态反馈保持现有口径；切换分支后分页重置回第一页；非 git 仓库、非法 ref 注入拒绝等错误路径不变。

## 验收说明

1. **完整性**：在提交数 > 200 的分支（可临时造数）上，通过分页能逐页看到**全部**提交直到分支首个提交，末页有「已到末尾 / 共 N 条」类反馈；总数与 `git log --oneline <branch> | wc -l` 一致。
2. **分页交互**：上一页 / 下一页 / 页码（或「加载更多」追加，按 design.md 落定的形式）可正常翻页；首页时「上一页」禁用、末页时「下一页」禁用；翻页期间有加载反馈，失败可重试且不影响已加载内容。
3. **切分支重置**：切换分支后回到第一页并重新加载；「刷新」刷新当前页；未选分支时保持「点击左侧分支查看提交记录」占位。
4. **状态反馈不回归**：加载中 / 读取失败（含错误信息展示）/ 空分支三种状态展示与现状一致；本地分组「当前」标记、远端分组、「和远端同步」等分支列表功能不受影响。
5. **接口与测试**：`GET /api/build/branch-log` 分页参数生效且对非法输入（负数 / 超大 limit 等）有合理归一或拒绝；`scripts/tests/build-serve.test.mjs`（S8 branches / branch-log）与 `scripts/tests/build-ui.test.mjs` 补充分页用例并通过（含 >50、>200 条与跨页取数的断言）。
6. **边界**：提交数恰好 50 / 51、单条提交、空分支等边界下分页控件正确（无多余空页）；`limit` 缺省时行为与 design.md 落定口径一致（**待确认**项以 design.md 为准验收）。

## 界面展示

以下为构建模块「分支浏览」相关界面的布局、交互与状态反馈说明，可交互对比演示见 [./ui-demo.html](./ui-demo.html)（单文件、浏览器直接打开；含「缺陷现状 / 期望修复」模式切换，正常 / 加载中 / 失败 / 空分支状态切换，以及期望修复态下的分页翻页操作，演示数据以 dev 分支 137 条提交为例）。

- **界面布局**：顶栏「构建」页 →「分支浏览」子页签；左右分栏（窄屏折为上下）——左侧分支列表（工具行「⟳ 和远端同步 / 刷新」+「本地」分组：dev（标「当前」chip）、main、feature 分支行（本地非当前分支带「推送」按钮）+「远端」分组），右侧提交记录详情面板（头部为分支名 +「刷新」按钮，下方为提交行列表：`短hash` + 提交说明 + 「作者 · 时间」右侧弱化）。
- **交互行为**：点左侧分支行加载该分支提交记录；头部「刷新」重新拉取当前分支；**缺陷交互**：列表在第 50 条静默截断，无分页 / 加载更多入口，也无总数提示，更早历史不可达；**修复后期望**：列表分页展示（页码 / 上一页 / 下一页，或「加载更多」追加，形式待确认），显示「第 x–y 条 / 共 N 条」进度，翻页有加载反馈，可翻到分支首个提交，切换分支重置回第一页。
- **状态反馈**：未选分支显示占位「点击左侧分支查看提交记录」；加载中显示「加载提交记录中…」；读取失败行内显示「提交记录读取失败：<原因>」；空分支显示「该分支暂无提交」；修复后新增「总数 / 当前范围」与「已到末尾」反馈，替代静默截断。深浅色外观跟随系统（演示页同）。

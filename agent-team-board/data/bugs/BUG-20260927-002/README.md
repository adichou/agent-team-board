# BUG-20260927-002 文档与翻译界面的二次边界对话框，底部的关闭按钮无法关闭窗口

- 状态：submitted（待人工接受）
- 归属：独立 Bug（引入来源见 design.md）
- 创建：2026-09-27T14:42:29.772Z

> 术语说明：登记标题中「二次边界对话框」实指发布模块「文档与翻译」步的「② 二次编辑」弹窗（代码中 aria-label 为「二次编辑（默认语言）」，标题为「二次编辑 · 默认语言（◇）」）。「边界」疑为「编辑」笔误，本文按代码口径叙述（是否更改登记标题：待确认）。

## 现象

发布模块 →「文档与翻译」步打开「② 二次编辑」弹窗后，点击弹窗底部右侧的「关闭」按钮无任何反应：弹窗不关闭、无报错、无 toast 提示。其余三条关闭路径均正常：头部「✕ 关闭」按钮、Esc 键、点击遮罩。弹窗内其他功能（文件切换 / 刷新 / 编辑·预览切换 / 保存）不受影响。

有未保存修改时点击底部「关闭」同样无响应（正常情况下应先出现未保存保护条）。

## 复现步骤

前置：看板服务已启动（`atb serve`），浏览器打开 Web UI；存在一个处于「文档与翻译」步、发布流程数据就绪（五步操作条可点）的版本。

1. 进入发布模块，选中该版本，切换到「文档与翻译」步。
2. 点击五步操作条中的「② 二次编辑」按钮，打开默认语言编辑弹窗（标题「二次编辑 · 默认语言（<版本 ID>）」）。也可从 ③ AI 校对建议栏点击「✎ 修改」跳入同一弹窗。
3. 等待文档内容读取完成（弹窗主体从「正在读取文档内容…」变为编辑框）。
4. 点击弹窗底部右侧的「关闭」按钮。
5. 实际结果：弹窗保持打开，无任何反馈。对照：点击头部「✕ 关闭」或按 Esc 可正常关闭（有未保存修改时先出现保护条）。

## 期望行为

底部「关闭」与头部「✕ 关闭」为同一关闭入口，行为应完全一致（调用同一 requestEditClose）：

- 无未保存修改：直接关闭弹窗。
- 有未保存修改：不直接关闭，弹窗内出现未保存保护条（「保存并继续」/「放弃修改并继续」/「留在本文件」三动作内联呈现），由人选择后再执行对应动作。
- 保存中（busy）：底部「关闭」按钮渲染为禁用，点击不响应属预期（非本 Bug）。

## 代码定位（修复参考）

- 弹窗渲染：`scripts/web/build.js` 的 `renderSecondaryEditModal`——头部与底部各有一个 `data-edit-close` 按钮（头部「✕ 关闭」约 4059 行、底部「关闭」约 4085 行）。
- 事件绑定：`scripts/web/build.js` 约 5136 行 `q('[data-edit-close]')?.addEventListener('click', requestEditClose)`，而 `q = (s) => view.querySelector(s)`（约 4830 行）只命中 DOM 顺序第一个匹配（头部按钮），底部按钮从未绑定监听——点击无响应的直接原因。
- 同文件正确范式：审查对话框的 `data-review-close` 同样是双关闭按钮（头部 + 底部），用 `view.querySelectorAll('[data-review-close]')` 循环逐个绑定（约 5205 行），两处均可用。

## 验收说明

1. 底部「关闭」点击行为与头部「✕ 关闭」完全一致：无未保存修改直接关闭；有未保存修改先弹未保存保护条，三动作（保存并继续 / 放弃修改并继续 / 留在本文件）语义不变。
2. 既有关闭路径不回归：头部「✕ 关闭」、Esc（未保存挂起态第一次 Esc 先撤保护条、再按才关）、遮罩点击（busy 时不关）。
3. busy 守卫不回归：保存中底部「关闭」禁用，头部「✕ 关闭」与遮罩点击不关闭。
4. 关闭后不整块重建文档窗格（保持 BUG-20260925-004「只摘弹窗元素、不回顶」口径）。
5. 测试：`scripts/tests/` 新增 `bug-20260927-002` 对应测试（先红后绿），`npm test` 全量通过。
6. 界面效果对照本条目 [./ui-demo.html](./ui-demo.html) 的「修复态」验收；缺陷态仅作现象复现对照，不作为验收目标。

## 界面展示

### 布局

「② 二次编辑」弹窗（居中模态、遮罩背景，宽约 860px）自上而下四段：

- 头部栏：标题「二次编辑 · 默认语言（<版本 ID>）」+ 右侧「✕ 关闭」静音按钮。
- 编辑工具条：文件下拉（只列默认语言文件）+「刷新」按钮 +「编辑 / 预览」切换组。
- 内容区：编辑态为等宽字体大文本框；预览态为 Markdown 渲染；加载中显示「正在读取文档内容…」，失败显示错误与「重试读取」，空文档显示「（空文档）」占位。
- 底部栏：左侧状态注记（如「默认语言初稿编辑（其余语言由「④ AI 翻译」产出）」「保存中…」「已保存 ✓…」），右侧「保存」与「关闭」两个按钮——本次缺陷即右侧「关闭」。

入口位于「文档与翻译」步的五步操作条（「五步：① AI 总结 ② 二次编辑 ③ AI 校对 ④ AI 翻译 ⑤ 提交」，② 在流程数据就绪前禁用）。

### 交互与状态反馈

- 状态切换：读取中（占位提示）→ 就绪（编辑框）；读取失败给错误信息 +「重试读取」，不丢已输入内容；预览态空文档有「（空文档）」占位。
- 未保存保护：编辑框有改动即出现「有未保存的修改：切换文件 / 刷新 / 关闭前会先询问保存或放弃。」提示条；此时切换文件 / 刷新 / 关闭（含 Esc）会先出现内联保护条三动作，不做阻塞式 confirm。
- 保存反馈：保存中按钮禁用、底部注记「保存中…」；成功注记「已保存 ✓（未提交：需审核通过并「提交」后进入本地 dev…）」并出 toast；失败 toast 给原因且内容保留。
- 关闭路径：头部「✕ 关闭」、Esc、遮罩点击三条正常；底部「关闭」在缺陷态无响应——可交互对照演示见 [./ui-demo.html](./ui-demo.html)（顶部开关切换「缺陷态 / 修复态」，可切换 读取中 / 读取失败 / 空文档 / 保存中 等状态并实际点击验证）。

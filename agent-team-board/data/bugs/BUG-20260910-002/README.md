# BUG-20260910-002 列表占太多空间，应该调整下，列表和详情页面占比应为 1:2

- 状态：accepted（已接受；本轮仅完善说明，未实施修复）
- 归属：独立 Bug（引入来源见 design.md）
- 引入来源：REQ-20260907-004（「看板整体布局优化：统一导航、三类新建入口与列表工作区」——宽屏需求工作区改为「列表 + 详情并排」双栏，`scripts/web/style.css` 第 247–253 行 `.req-split` 的 `grid-template-columns: minmax(0, 1fr) minmax(0, 460px)` 即该交付口径：左列表栏取全部剩余宽度、右详情栏上限固定 460px，未规定两栏比例）。编号经 `atb list` 核验真实存在（2026-09-10，REQ-20260907-004 in-progress）。
- 创建：2026-09-09T16:06:39.175Z

## 现象

看板「需求」模块宽屏工作区（`.req-split`，`scripts/web/index.html` 第 67 行）左右两栏比例失衡——**列表栏远宽于详情栏，且窗口越宽越严重**。附件截图（[attachments/paste-1788969967036.png](attachments/paste-1788969967036.png)，2612×1428，Retina 2x 截屏、等效视口约 1306×714）实测：列表栏约占 **63%**、详情栏约占 **37%**（约 1.7 : 1，列表约 2/3），而标题要求列表 : 详情 = **1 : 2**（列表约 1/3、详情约 2/3），方向正好相反。

量化归因（依据代码核实）：

1. **详情栏被 460px 上限锁死**：`.req-split` 网格两列为 `minmax(0, 1fr) minmax(0, 460px)`（`scripts/web/style.css` 第 251 行），详情栏最多 460px，剩余宽度全部落入列表栏。以截图等效视口 1306px 计：内容区宽 = 1306 − 左右 padding 36 − 栏间 gap 14 = 1256px，详情栏取满 460px 后列表栏约 796px（≈ 63% : 37%）。
2. **窗口越宽失衡越大**：视口 1920px 时列表栏约 1410px、占比升至约 73%（约 3 : 1）；详情栏恒为 460px，比例不随视口收敛。
3. **详情栏宽完全由网格决定**：宽屏下 `#drawer` 为 `position: static; width: auto`（`scripts/web/style.css` 第 454–459 行），填满网格右列，自身不设宽。
4. **用户无法自行调整**：需求模块列表 / 详情之间没有可拖拽分隔条（`scripts/web/splitter.js` 仅服务「文件」模块的树 / 详情，`TREE_DEFAULT = 300`），比例是纯 CSS 口径，只能改代码。
5. **波及讨论模块**：讨论看板复用同一结构（`.disc-view .req-split`，`scripts/web/style.css` 第 1365 行；`scripts/web/oncall.js` 第 161 行渲染 `<div class="req-split disc-split">`），本比例调整会同步作用于讨论模块的列表 / 详情。

范围与边界（依据代码核实）：

- 窄屏（≤1020px，`scripts/web/style.css` 第 738–742 行媒体查询）为单列 + 覆盖式抽屉形态，不存在左右比例问题，不在本单现象内。
- 本单只关两栏**宽度占比**；详情抽屉高度口径（REQ-20260908-005「顶边低于状态筛选行、与列表等高」）不受影响，修复不得回退。
- 列表栏收紧后的可读性边界（行内单号 / 标题截断、勾选与批量操作两行 caption 结构，BUG-20260909-009 口径）需在修复中保底。

## 复现步骤

前置：看板服务已启动（`node scripts/atb.mjs serve`，默认 `http://127.0.0.1:8888`），板上至少有一个条目（直接用本单 BUG-20260910-002 即可）。

1. 打开看板，进入「需求」模块，浏览器窗口宽度保持 1020px 以上（宽屏分栏形态）。
2. 在列表中点击任一条目（如本单）打开右侧详情抽屉。
3. 观察工作区左右两栏：列表栏明显宽于详情栏——附件截图（等效视口约 1306px）实测列表约占 63%、详情约 37%（约 1.7 : 1），详情栏停在 460px 上限；与期望的 1 : 2 相比，列表多占了约一倍。
4. 把窗口拉宽到 1920px 级别重复观察：列表栏继续变宽（占比升至约 73%），详情栏仍为 460px——失衡随视口放大，而非收敛到固定比例。
5. 尝试拖动两栏之间的栏间空隙：无可拖拽分隔条（「文件」模块树 / 详情才有该能力），无法手动调整比例。
6. 切到「讨论」模块并打开任一讨论记录：同样呈现列表宽、详情窄（讨论看板复用 `.req-split`）。
7. 把窗口宽度压到 1020px 及以下：变为单列 + 覆盖式抽屉形态，此形态无左右比例问题（属预期形态，不在本单范围）。
8. 切换系统深 / 浅色外观重复观察：两种主题下比例失衡一致（纯布局问题，与主题无关）。

## 期望行为

- **宽屏（>1020px）列表 : 详情 ≈ 1 : 2**：详情成为主阅读区（约 2/3 宽），列表收纳为约 1/3 宽。具体落地口径（如 `grid-template-columns: minmax(320px, 1fr) minmax(0, 2fr)`、按视口百分比、或其它等价方案）由开发阶段 design.md 定夺，本单只锁定目标比例。
- **比例随视口保持**：拖宽 / 拖窄窗口时两栏按 1 : 2 同步伸缩，详情栏不再被 460px 固定上限锁死；超宽视口（如 2560px）详情栏是否另设可读上限（避免单行过长）**待确认**，由 design.md 裁定。
- **列表栏保底可用**：收紧后列表行（状态点 + 类型 + 单号 + 标题）仍可读，勾选、全选 / 全不选、批量操作（接受所选 / 移入计划等）正常使用，caption 固定两行结构（BUG-20260909-009）不破坏。
- **讨论模块同步情况有结论**：因复用 `.req-split`，比例会一并变为 1 : 2；是否接受同比例、还是需差异化（讨论列表更窄 / 更宽）**待确认**（design.md 裁定，修复说明中记录）。
- **窄屏与既有口径不回退**：≤1020px 单列 + 覆盖式抽屉形态、REQ-20260908-005 抽屉定位口径（顶边低于状态筛选行、与列表等高）不变。
- 深 / 浅色两种外观下两栏边框、背景显示正常。
- 是否顺带引入需求模块列表 / 详情可拖拽分隔条（对齐「文件」模块 `scripts/web/splitter.js` 的拖拽 + 持久化能力）：非本单必须项，**待确认**（若做须复用 splitter 口径并写明默认 1 : 2、持久化键）。

## 界面展示

- 布局：需求工作区在状态筛选行之下为左右双栏网格——左列表栏（圆角面板：两行 caption「计数 + 排序 + 快捷入口 / 全选区」+ 可滚动条目行）、右详情抽屉（头部单号行 + 页签行 + 可滚动内容区）。现状（缺陷）：列表取全部剩余宽度、详情被 460px 上限锁死，等效视口 1306px 时约 63% : 37%，视口越宽列表占比越高（1920px 时约 73%）；期望：两栏恒约 1 : 2（列表 1/3、详情 2/3），随视口同步伸缩。演示页在模拟看板内并排呈现「现状 / 期望」两模式，并提供视口宽度滑杆实时观察比例变化与实测读数。
- 交互：点击列表行打开详情（经「加载中…」过渡）；✕ / Escape（窄屏另有遮罩点击）关闭；页签切换；搜索框过滤列表；「现状 / 期望」「宽屏 / 窄屏」「深 / 浅色」随时切换对照；视口宽度滑杆（900–2200px）拖动时两栏宽度与比例读数实时刷新，操作日志逐条记录关键交互。
- 状态反馈：详情区四种状态可切换——加载中（「加载中…」空态占位）、正常（README 渲染）、未选择空态（「选择左侧列表中的条目查看详情」）、详情加载失败（占位提示）；另含列表为空态（0 个条目空提示）；窄屏模式含遮罩与抽屉滑入动效；比例读数区实时显示两栏实测像素宽与百分比（现状模式动态失衡 vs 期望模式恒定 1 : 2 的对照即本单核心反馈）。

可交互演示：[./ui-demo.html](./ui-demo.html)（单文件、无外网依赖、无构建，浏览器直接打开；内置现状 / 期望对照、视口宽度滑杆与实时比例读数、宽窄屏与深浅色切换、四种详情状态 + 空态与操作日志）。

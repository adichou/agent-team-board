# BUG-20260910-009 任务模块搜索不过滤批量完善/批量开发面板

- 状态：planned（已计划；2026-09-10 完善收尾时由看板「完善后自动转入计划」设置自动流转自 accepted，见 status.json history）
- 归属：独立 Bug（引入来源见 design.md）
- 创建：2026-09-10T04:01:07.548Z

## 现象

REQ-20260910-009 搜索模块优化实施时发现的既有缺口：任务模块（runs 视图）搜索框语义为「搜任务、编号或执行器…」前端过滤，但 `renderBatchDrawer()`（scripts/web/app.js，约 4420 行）虽按 `state.search.q` 计算出关键词 q，却只传给存量深链保留的 Codex 面板（`renderCodexPanel(q)`，入口已隐藏，仅其内部 `renderCxRuns(q)` 真实过滤执行记录）；当前实际使用的批量完善（`renderRefinePanel`）/ 批量开发（`renderZcodeBatchPanel`）面板不接收关键词、不按关键词过滤——输入关键词后两个面板的候选队列、待处理队列、排队批次、本轮处理记录均无变化。搜索反馈条（REQ-20260910-009，`renderSearchFeedback` runs 分支，app.js 约 1384 行）提示「关键词在下方面板内前端过滤（编号 / 标题 / 执行器），不发请求」，与两个可见面板的实际行为不符；待本 Bug 修复后该口径应为真实过滤。修复方向：`renderRefinePanel` / `renderZcodeBatchPanel` 的列表按 `state.search.q` 前端过滤（编号/标题/执行器），清空恢复全量，并同步反馈条提示文案。

## 复现步骤

前置条件（任一即可产生可过滤的列表）：

- 项目已初始化看板，且满足以下至少一项：
  - 存在「已接受未完善」条目 → 批量完善启动态有候选（待完善）队列；
  - 存在「已计划且未认领」条目 → 批量开发启动态有待开发队列；
  - 存在批量完善 / 批量开发批次（进行中或已收尾）→ 运行态有排队批次、待处理队列与处理记录。

步骤：

1. 启动看板服务并打开 Web 页面：项目根目录执行 `node scripts/server.mjs`（默认 http://127.0.0.1:8888）。
2. 顶部模块导航切到「任务」。
3. 在搜索框输入任一关键词：条目编号片段（如 `REQ-` / `BUG-`）、标题片段、批次号（`RFB-` / `batch-`）或执行器名。
4. 观察下方面板（批量完善或批量开发）：候选/待处理队列、排队批次、本轮处理记录均不收窄，与未输入时完全一致；顶部仅搜索反馈条出现「关键词在下方面板内前端过滤（编号 / 标题 / 执行器），不发请求」提示——提示承诺的过滤没有发生。
5. 在一级页签「批量完善 / 批量开发」、二级页签「队列 / 记录」间切换并重复步骤 3：任何列表均不过滤。
6. 清空搜索（✕ 按钮或 Esc）：面板内容无变化（全量本就从未被过滤）。

## 期望行为

1. 过滤生效范围（纯前端过滤、不发请求，沿用 runs 视图 `runSearch` 现有的「清签名 + 立即重渲染」机制）：
   - 批量完善：启动态候选（待完善）队列；运行态「队列」页签的待完善队列、「记录」页签的本轮处理记录。
   - 批量开发：启动态待开发队列；运行态「队列」页签的排队批次列表与待开发队列、「记录」页签的本轮处理记录。
2. 匹配字段（大小写不敏感，包含即命中）：条目编号（itemId）、标题；排队批次另可匹配批次号（batchId）与开发人员；处理记录与当前项可匹配执行器（owner，子代理会话名）。口径与隐藏 Codex 面板 `renderCxRuns` 的既有过滤对齐，最终字段范围以开发阶段 design 为准。
3. 过滤结果为空时，列表显示「无匹配」类空态（参照 `renderCxRuns` 的「没有匹配的执行记录，清空搜索恢复。」），不得误显「暂无待处理条目」「暂无执行记录」等误导文案；被过滤条数以「N 条被搜索过滤」类标注体现（口径对齐 Codex 面板，具体样式 design 定）。
4. 清空关键词（✕ / Esc / 删空）后恢复全量列表；清空按钮显隐与焦点行为维持 REQ-20260910-009 口径不变。
5. 搜索反馈条文案与真实行为一致；过滤在一/二级页签切换与 2 秒轮询重渲染后持续生效（`state.search.q` 不因重渲染丢失）。
6. 不回退：存量 Codex 深链面板（`renderCodexPanel(q)`）的过滤不受影响；快照恢复（REQ-20260910-001，关键词进快照后按模块重新解释）不受影响；概况区统计计数（已完成/异常/待处理等账面数字）默认保持全量口径，如 design 决定调整须显式说明。

## 验收说明

1. 手动验收：按「复现步骤」重做——修复后步骤 4/5 应看到列表随关键词收窄、无匹配显示空态、清空恢复全量；「批量完善 / 批量开发 × 启动态 / 运行态」四种组合各验证一遍。
2. 反馈条一致性：输入关键词后反馈条提示与实际过滤行为一致；清空后反馈条隐藏。
3. 空态区分：「无匹配（清空恢复）」与「暂无待处理条目」两种空态不混淆，后者只在全量即空时出现。
4. 自动化回归：`npm test`（scripts/tests/run-all.mjs）全绿；建议按 scripts/tests 现有静态契约测试风格补一条回归用例：`renderBatchDrawer` 将 `q` 传入 `renderRefinePanel` / `renderZcodeBatchPanel`，两面板列表消费 `state.search.q` 过滤。
5. 深链回归：带关键词打开存量 Codex 深链，`renderCxRuns` 过滤行为不回退。

## 界面展示

- 界面布局：任务模块自上而下为——模块导航行（「任务」Tab 激活）→ 模块副标题「进度、队列与结果集中在这里」+ 搜索组（常显范围标签「任务」+ 搜索框「搜任务、编号或执行器…」+ 有词时出现的 ✕ 清空按钮）→ 统一搜索反馈条（关键词 + 范围 + 过滤口径说明 + 清除搜索）→ 任务面板（一级页签「批量完善 / 批量开发」；运行态下再分二级页签「概况 / 队列 / 提示词 / 记录」，待过滤列表集中在「队列」「记录」页签与启动态队列区）。
- 交互行为：搜索框输入关键词（250ms 防抖）→ 下方面板列表即时前端过滤（编号 / 标题 / 执行器，排队批次含批次号），不发任何请求；✕ / Esc / 删空关键词 → 恢复全量并把焦点交还输入框；一级 / 二级页签切换与轮询刷新期间关键词持续生效。
- 状态反馈：反馈条展示关键词与「前端过滤、不发请求」口径；列表侧区分五种状态——全量（「最近 N 条 / 共 M 条」）、过滤命中（行数收窄 + 「N 条被搜索过滤」标注）、无匹配空态（「没有匹配…清空搜索恢复」）、面板加载中（「加载中…」）、数据加载失败（toast 报错，列表保留旧内容）。
- 缺陷对照：现状输入关键词后面板列表纹丝不动，反馈条却宣称「在下方面板内前端过滤」；修复后口径成真。可交互对照演示见 [./ui-demo.html](./ui-demo.html)（内置「缺陷现状 / 修复后」切换、四种面板场景与加载/失败状态模拟）。

# 设计 — BUG-20260925-003 英文界面下 AI 校对建议侧栏等文案不翻译（REQ-20260924-006 词条误入 EN_CLI 块）

> 由 Agent 在 /dev 开发前补充，人可随时批注。

## 引入来源（源单）

- 引入来源：REQ-20260924-006（文档编写流程优化——五步流程 / 校对建议侧栏 / 二次编辑弹窗的
  约 28 条静态词条加进了 EN_CLI 块而非主 EN 词典，经 `atb list` 核验存在）。
- 连带源：REQ-20260920-004（EN_CLI 块的创建者，命令注册表词条；同根因运行时查不到，
  本单一并修复，见「方案」）。
- EN_CLI「仅并入测试口径」的分叉本身由 REQ-20260920-004 建立（当时注释称「组装时并入 EN」
  但实现只改了 `_dict.EN` 导出合并），REQ-20260924-006 往该块追加 Web 界面词条使分叉可见化。

## 根因分析

- `t()`（i18n.js）运行时只查主 `EN` 词典与 `EN_DYNAMIC` 编译正则；`EN_CLI` 是物理独立块，
  仅在导出的 `_dict: { EN: { ...EN, ...EN_CLI } }`（测试暴露口径）合并。运行时与测试查表
  分叉：i18n-dict / i18n-coverage 等既有套件经 `_dict.EN` 断言全部通过，而运行时
  `t('校对建议')` 原样返回中文——英文界面中英混排。
- 反向词典 `ZH_EXACT` 同样只从主 `EN` 构建，EN_CLI 词条即使译出也无法切回中文（往返缺口）。
- 词典分叉（实施时核实，比 README 登记多出三处）：主 EN 与 EN_CLI 有 4 个重复键——
  「待确认」「人工决策」「挂起确认」「重试读取」，两处定义值不同。

## 方案

在 EN_CLI 块闭合后、`ZH_EXACT` 构建前执行 `Object.assign(EN, EN_CLI)` 组装并入：运行时
`t()`、反向词典 `ZH_EXACT` 与导出 `_dict.EN`（改为直接引用同一对象）三者同一查表口径。
EN_CLI 保留为物理独立块不搬移——realtime-round RT-09 依赖正则剔除该块后断言词表无排队
概念词汇，词条并入主 EN 字面量会破坏该契约。

四个重复键收口（消除双定义歧义，均改为源内单定义）：

| 键 | 收口值 | 依据 |
| --- | --- | --- |
| 待确认 | EN_CLI 'To verify' | 唯一独立渲染点是校对建议状态 chip（build.js classifyChkIssue「无法验证的链接标待确认」），即 REQ-20260924-006 为该面写的值；主 EN 旧值 'To confirm' 无独立渲染点，删除 |
| 人工决策 | 主 EN 'Human decisions' | 线上既有值（hold 面板标题 index.html 同文复用），删除 EN_CLI 重复定义 |
| 挂起确认 | 主 EN 'Suspension confirmation' | 线上既有值（侧拉面板标题），删除 EN_CLI 重复定义 |
| 重试读取 | 主 EN 'Retry loading' | 线上既有值（app.js / build.js / req-disc.js 三处复用），删除 EN_CLI 重复定义 |

「人工决策」「挂起确认」「重试读取」三键遵循 EN_CLI 块头注释既有惯例（分组名「AI 开发」
「AI 分析」沿用主 EN 词条不重复定义）；命令注册表词条（REQ-20260920-004，README 连带
影响段）经同一 Object.assign 一并恢复运行时翻译，属本单范围（同根因、同一行修复）。

测试口径合一（防再漏检）：i18n-dict 新增 D1f——_dict.EN 每键必须经运行时 `t()` 可查且
en 译值可回 zh；新增 bug-20260925-003 专项测试 8 例（代表词条 / 全量遍历 / 往返 /
双定义收口 / translateTree 渲染路径 / zh 回归 / 源级组装契约）。

**开源选型（REQ-20260909-015）**：无合适库——本单是自研 i18n 词典组装口径的确定性修正
（一行 Object.assign + 词典收口 + 测试），不存在可复用的第三方能力；未引入开源库，
不创建 licenses.md。

## 风险与边界

- 「待确认」英文值从 'To confirm' 变为 'To verify'：唯一可见变化面是校对建议状态 chip
  （引入源单的本意），其余三键英文界面显示与修复前完全一致（零回归）。
- `_dict.EN` 从合并副本改为与运行时同一对象引用：既有测试全部只读该对象（已全量核跑
  npm test 351 文件通过）；后续若有测试试图原地改写 _dict.EN 将直接污染运行时词典，
  属预期禁止行为。
- EN_CLI 必须保持「`const EN_CLI = {` 起始、行首两空格词条、`\n};` 结束」的物理形态
  （RT-09 剔除正则与 B8 源级契约共同把守）；往 EN_CLI 追加词条仍是唯一入口，键不得与
  主 EN / EN_DYNAMIC 重复（D1c/D1e 在并入后词典上把关，D1f 把守运行时口径）。

# BUG-20260925-003 英文界面下 AI 校对建议侧栏等文案不翻译（REQ-20260924-006 词条误入 EN_CLI 块）

- 状态：submitted（待人工接受）
- 归属：独立 Bug（引入来源见 design.md）
- 创建：2026-09-24T17:00:30.661Z

## 现象

scripts/web/i18n.js 的 EN_CLI 块注释称「组装时并入 EN（t() 单一查表口径不变）」，但运行时 t() 只查主 EN 词典，EN_CLI 仅在 _dict.EN（测试暴露口径）合并。REQ-20260924-006 / REQ-20260924-004 的 Web 界面词条（校对建议侧栏标题、待处理计数、接受 / 拒绝 / 过期 toast、二次编辑弹窗等，约 i18n.js 1541-1597 行）被加进 EN_CLI，英文界面下这些文案运行时不翻译、仍显示中文；既有 i18n 测试查 _dict.EN（合并副本）故未拦截。修复方向：词条移入主 EN 词典，或运行时把 EN_CLI 并入 t() 查表，并补 t() 口径覆盖测试。发现于 BUG-20260925-002 实施过程（本单新增词条已直接放主 EN 词典，不受影响）。

补充（登记后核实，2026-09-25）：

- 已用 Node 直接加载 scripts/web/i18n.js 实测（`setLang('en')` 后调 `t()`）：EN_CLI 内 REQ-20260924-006 / 004 的静态词条（i18n.js 1543-1597 行）共约 28 条 `t()` 原样返回中文，含五步条「① AI 总结」～「⑤ 提交」、侧栏标题「校对建议」、空态 / 失败态说明、「重试 AI 校对」、建议卡片类型标签（错别字 / 链接 / 语法 / 行文规范）与状态 chip（过期 / 已拒绝）、「无行号」、「查看修改前后差异」「修改前（删除）」「修改后（新增）」、拒绝 toast「已拒绝该条建议：原文保持不变」、过期 toast「✕ 建议已过期：…」、二次编辑弹窗标题「二次编辑（默认语言）」、未保存确认条「保存并继续 / 放弃修改并继续 / 留在本文件」等；同屏主 EN 既有词条（「待处理」「已接受」「接受」「拒绝」「文件」「待确认」等）与 EN_DYNAMIC 动态词条（「待处理 ◇ 项」「✓ 已接受并保存 ◇ 的建议…」）翻译正常，英文界面因此中英混排。
- 词典分叉细节：「待确认」主 EN 已有词条（'To confirm'，i18n.js:504），EN_CLI 又定义 'To verify'（i18n.js:1564）；当前运行时命中主 EN，若修复采用「EN_CLI 并入 t() 且后者覆盖」的口径，该词英文值会从 'To confirm' 变为 'To verify'，实施时需明确取哪一侧。
- 连带影响（同根因、待实施时确认是否属本单范围）：EN_CLI 同块前段的命令注册表词条（REQ-20260920-004，命令模块分组名 / 说明 / 参数标签 / 常用选项，i18n.js 1435-1542 行）走同一条 `translateTree → t()` 渲染路径（commands.js 分组名以普通文本节点插入，无 data-i18n-skip），运行时同样查不到，英文界面下命令模块这些数据文案也应中英混排。

## 复现步骤

方式 A — Web 界面：

1. 在仓库根执行 `bin/atb serve --open` 启动看板 Web 界面（已有实例运行则直接打开页面）；
2. 进入左侧「发布」模块（view=build），选择一个已创建的版本计划，切到「文档编写」步；
3. 点击顶栏右侧语言按钮「EN」（#btnLang，scripts/web/index.html:59）把界面切到英文；
4. 观察英文界面下仍显示中文的区域：
   - 五步操作条：① AI 总结 / ② 二次编辑 / ③ AI 校对 / ④ AI 翻译 / ⑤ 提交；
   - 完成一轮 ③ AI 校对后，右侧建议侧栏（build.js bld-docs-chk）：标题「校对建议」、文件下拉的 aria-label「选择要查看校对建议的文件」、空态「尚未校对：…」/「该文件未发现问题 ✓…」、失败态「重试 AI 校对」按钮、建议卡片类型标签与状态 chip（过期 / 已拒绝）、「查看修改前后差异」折叠（修改前（删除）/ 修改后（新增））、接受 / 拒绝按钮悬停 title；
   - 点「拒绝」后的 toast「已拒绝该条建议：原文保持不变」；原文已变化时接受后的 toast「✕ 建议已过期：…」；
   - 点「✎ 修改」打开的二次编辑弹窗：对话框 aria-label「二次编辑（默认语言）」、未保存修改确认条（保存并继续 / 放弃修改并继续 / 留在本文件）与「有未保存的修改：切换文件 / 刷新 / 关闭前会先询问保存或放弃。」提示、底部说明「默认语言初稿编辑（其余语言由「④ AI 翻译」产出）」；
   - 对照组（应已翻译，可佐证只有 EN_CLI 静态词条漏译）：同屏「待处理 N 项」计数 chip、接受成功 toast「✓ 已接受并保存 … 的建议…」（EN_DYNAMIC 动态词条）、「待处理 / 已接受 / 接受 / 拒绝」（主 EN 既有词条）。

方式 B — 脱离 UI 的最小验证（Node，任一环境可跑）：

```bash
cd <仓库根>
node --input-type=module -e "import('./scripts/web/i18n.js').then(()=>{const I=globalThis.ATBI18N;I.setLang('en');console.log(I.t('校对建议'),'|',I._dict.EN['校对建议']);})"
```

输出 `校对建议 | Proofread suggestions` 即复现：`t()` 查不到（返回中文原文），而测试口径 `_dict.EN` 里有英文值。换 `'五步：'`、`'已拒绝'`、`'二次编辑（默认语言）'` 等同。

## 期望行为

1. 英文界面（lang=en）下，EN_CLI 块内的 Web 界面词条与主 EN 词典同口径：`t()` 能查到并返回英文——五步条、校对建议侧栏全部文案、拒绝 / 过期 toast、二次编辑弹窗文案均显示英文；中文界面（lang=zh）原样显示，不受影响。
2. EN_CLI 块注释「组装时并入 EN（t() 单一查表口径不变）」与实际行为一致：词条移入主 EN 词典，或运行时把 EN_CLI 并入 t() 查表（实施时二选一，连带影响段的两处口径问题——命令注册表词条、「待确认」双定义——需一并明确处理）。
3. en→zh 往返一致：英文界面切回中文后，已渲染的英文文案能译回中文原文（ZH_EXACT / ZH_PATTERNS 反向词典不因修复产生新缺口）。
4. 测试口径与运行时口径合一：i18n 相关测试改为经 `t()`（或等效运行时查表口径）断言覆盖，杜绝「测试查 _dict.EN 合并副本、运行时查主 EN」的分叉再次漏检。

## 验收说明

1. 方式 B 最小验证：`setLang('en')` 后 `t('校对建议') === 'Proofread suggestions'`（或选定方案下的等价值），且 t() 对 EN_CLI 全部键可查（遍历断言，无「键在 _dict.EN 而 t() 查不到」的残留）。
2. Web 界面英文模式走查（同复现步骤 A 第 4 点清单）：五步条、校对建议侧栏（标题 / 空态 / 失败态 / 类型标签 / 状态 chip / 差异折叠 / 按钮悬停 title）、拒绝与过期 toast、二次编辑弹窗（标题 / 未保存确认条 / 底部说明）全部为英文；同屏无中英混排。
3. 往返一致性：英文界面切回中文，上述区域全部还原中文原文，无英文残段（i18n-dict D1e 反向映射口径不回退）。
4. 中文界面回归无变化（全部文案仍为中文原样）。
5. 新增 / 改造测试覆盖 t() 运行时口径并真实通过（`npm test` 全绿，含既有 i18n-coverage / i18n-dict / i18n-runtime / i18n-wiring 套件）。
6. 「待确认」双定义（主 EN 'To confirm' vs EN_CLI 'To verify'）与命令注册表词条（若确认属本单）在修复后命中口径明确、无行为歧义；不属本单的在 design.md 记录去向。

可交互演示：[./ui-demo.html](./ui-demo.html)（单文件、内联 CSS/JS、无外网依赖、无构建步骤，浏览器直接打开）。

- 布局：复刻「发布 → 文档编写」步的核心区域——顶部五步操作条（① AI 总结 … ⑤ 提交），下方左文件列表 + 右「校对建议」侧栏（标题 + 待处理计数 chip、文件下拉、建议卡片：类型标签 / 行号 / 状态 chip / 差异折叠 / 接受 / 拒绝 / ✎ 修改按钮）；「✎ 修改」打开二次编辑弹窗（编辑 / 预览切换、未保存修改确认条、底部说明）。
- 交互行为：接受 / 拒绝逐条决断并更新状态 chip 与待处理计数；「模拟原文已变化」触发过期路径（卡片标过期 + 过期 toast）；toast 自动消失；弹窗内切换文件触发未保存确认三选一。
- 状态反馈：侧栏五态可切换——尚未校对（空态引导）/ 校对中（进行中文案）/ 失败（中断说明 + 重试按钮）/ 有建议（正常卡片流）/ 未发现问题（清零态）；顶部提供「缺陷现象 ↔ 修复后」对照开关与「中 / EN」语言切换。
- 对照演示口径（本 Bug 核心）：选「EN + 缺陷现象」时，EN_CLI 静态词条（五步条、侧栏标题、类型标签、过期 / 已拒绝 chip、差异折叠、拒绝 / 过期 toast、二次编辑弹窗文案等）保持中文，而主 EN / 动态词条（待处理 N 项、已接受 chip、接受成功 toast、接受 / 拒绝按钮）显示英文——即线上中英混排现象；切到「修复后」同屏全部为英文。

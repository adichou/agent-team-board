# BUG-20260909-014 任务模块面板在批量完善和批量开发上方空白较多，而且需要去掉关闭按钮

- 状态：accepted（已接受；本轮仅完善说明，未实施修复）
- 归属：独立 Bug（引入来源见 design.md）
- 创建：2026-09-09T08:52:31.844Z

## 现象

![截图](attachments/paste-1788943920125.png)

看板「任务」模块面板（`renderBatchDrawer()`，`scripts/web/app.js` 第 2981–3009 行）的头部结构自上而下为：

1. `header.drawer-head`（`scripts/web/style.css` 第 452–455 行，内边距 `16px 18px 12px`）内第一行 `.batch-head`：左侧 `.batch-title` 仅剩一个 11px 灰色等宽字体的项目路径 `span.path`（`scripts/web/style.css` 第 116–125 行），右侧 `.batch-head-actions` 内是「✕」关闭按钮 `#batchClose`（`scripts/web/app.js` 第 2997 行，`title="返回需求模块"`）；
2. 第二行 `nav.tabs.batch-modes`（`scripts/web/style.css` 第 1165 行，`margin-top: 10px`）才是「批量完善 / 批量开发」两个一级页签。

BUG-20260908-009 移除头部「任务」大标题后（注释见 `scripts/web/app.js` 第 2987 行），这一行只剩小号弱化路径文字与「✕」，导致面板顶边到「批量完善 / 批量开发」页签之间出现一条几乎空白的横带（约 16px 头部上内边距 + 一行 11px 路径 + 10px 页签上外边距），肉眼观感即截图中的「上方空白较多」。且该路径与第一行顶栏品牌区 `#dataDir`（`scripts/web/index.html` 第 22 行）展示的项目路径完全重复；≤640px 极窄屏下 `.path` 本就被隐藏（`scripts/web/style.css` 第 1139 行），该行只剩「✕」，空白更纯粹。

「✕」关闭按钮点击后仅执行 `setView('status')` 返回需求模块（绑定见 `scripts/web/app.js` 第 4127 行），与第二行模块导航「需求」页签（`scripts/web/index.html` 第 34–39 行）功能重复；而同为页面化模块的「讨论 / 文件 / 设置」均无此类关闭按钮，任务模块独有，呈现不一致。

两个问题在「批量完善」「批量开发」两个子面板均存在（头部为共用模板），并随轮询重渲染持续保留。

## 复现步骤

前置：看板服务已启动（`node scripts/atb.mjs serve`，默认 `http://127.0.0.1:8888`）。

1. 打开看板，点击第二行模块导航「任务」页签（或从需求模块点已接受行的完善徽标 / 已计划行「▶ 开始开发」跳入，效果相同）：进入任务模块面板。
2. 观察面板顶部：「批量完善 / 批量开发」页签上方有一条基本空白的横带——左上角仅有小号灰色项目路径文字，右上角是「✕」关闭按钮；对照下方内容区，该空白带明显偏大（即截图现象）。
3. 在「批量完善」「批量开发」两个页签间来回切换：两个子面板头部结构相同，空白带与「✕」均不消失（页签记忆与轮询刷新也不影响）。
4. 点击右上角「✕」：整个视图切回「需求」模块——确认其效果与点击第二行导航「需求」页签完全相同，功能重复。
5. 对照「讨论 / 文件 / 设置」三个页面化模块：均直接以内容开始、且无关闭按钮；仅任务模块多出「✕」与空白带。
6. （可选）把窗口缩窄到 ≤640px：路径文字被隐藏，空白带内仅剩右上角「✕」，空白观感更明显。

## 期望行为

- **去掉关闭按钮**：任务模块面板头部不再渲染「✕」关闭按钮（`#batchClose`），对应事件绑定（`scripts/web/app.js` 第 4127 行）一并移除；离开任务模块统一走第二行模块导航页签，与「讨论 / 文件 / 设置」一致。「批量完善」「批量开发」两个子面板均生效。
- **消除页签上方空白带**：「批量完善 / 批量开发」页签不再悬在一大段近似空白的头部之下，面板顶部到页签的间距收紧至与其他模块头部相当的紧凑程度。实现手段（如整行移除与顶栏重复的项目路径 `span.path` / 收紧 `.drawer-head` 内边距与 `.batch-modes` 上外边距）由修复阶段 design.md 定夺，此处只约束结果：无可感知的空白横带。项目路径若从面板移除，顶栏 `#dataDir` 仍持续展示，信息不丢失。
- **功能与口径零回归**：一级页签切换（含 `state.batch.mode` 记忆）、二级页签（`state.batch.pane` / `state.refine.pane`）、轮询刷新、各入口深链跳转（完善徽标 `gotoRuns('refine')`、已计划「▶ 开始开发」`gotoRuns('develop')` 等）行为不变。
- **范围边界**：条目详情抽屉（`renderDrawer`）的关闭按钮属浮层抽屉交互，不在本条目范围，保持原样；`#runsView` / `#batchDrawer` 的 `aria-label` 等非可见辅助信息不因本修复强制变更。
- 深浅色外观沿用现有 CSS 变量，无新增配色。

## 界面展示

- 布局：「任务」模块面板（`#runsView` → `#batchDrawer`）。现状（缺陷）：`.drawer-head` 内先渲染一行仅含 11px 弱化项目路径 +「✕」关闭按钮的近似空白行，再叠加 `margin-top:10px` 的「批量完善 / 批量开发」页签，页签上方形成空白横带；期望：去掉「✕」、头部收紧，页签直接贴近面板顶部，离开模块统一走第二行导航。演示页内置「现状 / 期望」对照切换与子面板状态切换（正常 / 加载 / 空 / 失败），并复刻顶栏路径重复、≤640px 路径隐藏两处佐证。
- 交互：第二行模块导航「讨论 → 需求 → 任务 → 文件 → 设置」可切换视图（仅「任务」渲染面板，其余为占位说明）；「批量完善 / 批量开发」一级页签切换并记忆；现状模式下「✕」可点击并回到「需求」视图（演示其与导航页签功能重复），期望模式下无「✕」；面板主体提供正常（启动区）/ 加载 / 空 / 失败四态切换，失败态含「重试」按钮。
- 状态反馈：页签切换即时重渲染并记入操作日志；「✕」返回与导航返回均给出提示条；四态切换各有可辨识的界面反馈（骨架、空占位、错误条 + 重试）；深浅色按钮一键切换主题复查对比度。

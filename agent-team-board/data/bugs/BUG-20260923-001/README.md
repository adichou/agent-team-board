# BUG-20260923-001 点击人工确认页面的关闭按钮和右上角的叉按钮都无法关闭，只有刷新才能关闭

- 状态：submitted（待人工接受）
- 归属：独立 Bug（引入来源见 design.md）
- 创建：2026-09-22T16:36:15.745Z

## 现象

看板任务页「待人工确认」挂起确认侧拉面板（`#confirmPanel`，`scripts/web/index.html`，aria-label「挂起确认」；入口为挂起卡片「查看并确认」）打开后，点击底部「关闭」按钮（`#confirmPanelCancel`）与右上角 ✕（`#confirmPanelClose`）均无任何反应，按 Esc 也无效，只有刷新页面才能让面板消失。

定位线索（`scripts/web/app.js`）：

- 三个关闭入口全部被 `if (!confirmSide.busy) closeConfirmPanel()` 门控（`#confirmPanelClose` 监听、表单内 `#confirmPanelCancel` 监听、Esc 关闭链中的挂起确认面板层）；busy 期间点击被静默吞掉——按钮未禁用、无提示、无任何反馈。
- 「确认并继续」的提交核验（develop）分支自 `confirmContinueAction` 起：`confirmSide.busy = true` 后 `await watchConfirmTask(...)` 轮询服务端确认任务至终态，观察窗口 = 任务超时 + 20 秒（服务端默认按 `timeoutMin`（缺省 60 分钟）计，见 `scripts/server.mjs` 确认任务 `timeoutMs`），即 busy 可持续约 60 分 20 秒；只有任务终态后 `finally` 才复位 busy。
- 期间面板完全不可关闭：确认任务在服务端异步跑核验 / 补交 / 全量测试复验，前端只是轮询呈现；从用户视角看就是「点了没反应，只能刷新」。
- 关闭面板本身并不会中断服务端任务（`closeConfirmPanel` 仅关闭面板并丢弃迟到响应；刷新页面等效于关闭面板，任务照常完成、结论由主轮询回填），因此「确认中暂不可关闭」的门控在此场景并无保护意义。
- 附带风险：前端 `api()` 基于原生 `fetch`、无超时，分析侧同步确认等请求悬挂时 `confirmSide.busy` 可能永久滞留 true，面板彻底无法关闭。

## 复现步骤

1. 启动看板服务（终端 `atb serve`）并打开看板页面；
2. 使某开发条目产生「部分提交，开发未完成」提交挂起（report 后自动提交不完整），任务页「待人工确认」区出现该条目的挂起卡片；
3. 点卡片「查看并确认」打开挂起确认侧拉面板；
4. 逐项处理「归属待确认」路径后点「确认并继续」——按钮变为「正在核验提交与测试…」，服务端开始异步核验 / 补交 / 测试复验（观察窗口按任务超时口径，默认约 60 分 20 秒）；
5. 期间分别点击面板右上角 ✕、底部「关闭」按钮、按 Esc：三处均无任何反应（按钮未禁用、无提示、面板不关闭）；
6. 刷新页面（F5）后面板才消失；刷新前后确认任务本身均在服务端继续运行，终态结论照常回填。

（分析侧确认请求悬挂时会出现同样的不可关闭现象，属同一门控，具体频率待确认。）

## 期望行为

1. 挂起确认面板任何时刻都可通过右上角 ✕、底部「关闭」或 Esc 关闭；已受理的确认 / 核验任务在服务端继续执行，关闭面板不中断任务——进度仍显示在任务页挂起卡片，终态结论由轮询自动回填，重开面板展示的状态与实际一致。
2. 不得出现「按钮可点但静默无响应」的门控：若个别阶段确需暂时禁止关闭，关闭入口须呈现可见禁用态并说明原因。
3. 前端忙标志（`confirmSide.busy` 等）不得因长任务观察期或请求悬挂而长期 / 永久滞留 true。

## 验收说明

1. develop 挂起确认面板点「确认并继续」进入「正在核验提交与测试…」运行态后：右上角 ✕、底部「关闭」、Esc 三个入口均能立即关闭面板；
2. 关闭后确认任务不中断：任务页卡片进度持续推进至终态（通过 / 失败 / 中断），结论自动回填，重开面板显示的「最近核验」与确认状态正确；
3. 分析侧确认、保存草稿、保持挂起、重新核验进行中同样可关闭面板且不破坏对应流程；
4. 关闭入口不再出现「可点击但无任何反馈」的静默门控（若保留禁止关闭场景，须有禁用态与提示文案）；
5. `npm test` 全量通过，confirm 面板相关既有用例（如 `scripts/tests/confirm-serve-20260914-001.test.mjs`、`scripts/tests/bug-confirm-panel-scope-20260915-003.test.mjs`）不回归。

## 界面展示

- 界面布局：任务页「待人工确认」区挂起卡片（状态 / 原因 / 「重新核验」入口）+ 从右侧拉出的挂起确认面板（头部标题与右上角 ✕、表单区：文件核对表与归属选择 / 说明输入、底部操作行「保持挂起 / 保存草稿 / 确认并继续 / 关闭」）。
- 交互行为：点「查看并确认」打开面板 →「确认并继续」触发服务端异步任务，按钮进入「正在核验提交与测试…」运行态；缺陷模式下此期间 ✕ / 「关闭」/ Esc 三入口均静默无效，仅刷新可关；期望模式下三入口随时可关，任务在卡片上继续推进并回填结论。
- 状态反馈：面板消息区与卡片进度条呈现 正常（表单可操作）/ 运行中（busy，进度推进）/ 失败（错误提示 + 可重试）/ 已确认（resolved 只读）状态切换；缺陷与修复的差异通过页面顶部开关对照展示。

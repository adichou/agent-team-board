## 现象

用户反馈条目详情中的说明、方案等文档没有滚动条。原始截图显示 REQ-20260910-002 的「说明」页签已选中，正文超出截图下缘，右侧未见明显滚动条，影响长文档阅读及对剩余内容的感知。

![原始问题截图](attachments/paste-1789001378139.png)

截图只能佐证可见区域与反馈，不能证明滚轮完全失效。是否仅滚动条不可见、是否实际无法滚到底、受影响浏览器或桌面宿主、系统滚动条显示偏好、窗口尺寸与发生频率均为「待确认」。标题中的「方案」对应当前界面「设计」页签（design.md）。

### 已核对的静态上下文

- scripts/web/app.js 的 renderDrawer() 将详情组织为标题栏、页签栏和 drawer-body；README.md 显示为「说明」，design.md 显示为「设计」，文档在详情正文区域呈现。
- scripts/web/style.css 已给 drawer-body 设置 overflow-y: auto，给 #drawer > .drawer-body 设置 flex: 1 与 min-height: 0；文档面板和 Markdown 框使用 flex 布局，且已有全局细滚动条样式。因此不能把根因直接写成「未设置 overflow」；实际容器高度、溢出范围及宿主表现留待开发阶段验证。
- 以上为静态阅读，不是浏览器复现实测，也不据此认定任何已有条目为引入来源。

## 复现步骤

以下为根据用户反馈整理的复现路径，实际复现结果待确认。

1. 打开当前项目 Status Board，在需求列表打开截图中的 REQ-20260910-002；如该条目的内容已变化，选择现有正文超过一屏的条目，并记录所用编号、浏览器或桌面宿主版本、窗口尺寸和系统滚动条偏好。
2. 点击「说明」页签，使正文高度超过详情可用高度；观察内容区右侧是否能辨认滚动条。
3. 将指针置于正文上，尝试滚轮或触控板滚动；在系统允许显示原生滚动条时尝试拖动滚动条，核对是否可以看到文档最后一段。分别记录「不可见但可滚动」与「内容无法到达」，不要混为同一事实。
4. 切换到有长内容的「设计」「测试用例」「测试报告」文档页签，重复检查；没有对应文件时不作为长文档样本。
5. 缩小窗口高度并在宽屏详情栏、窄屏详情形态下重复步骤 2–4，记录实际受影响组合；原始反馈是否覆盖这些组合待确认。

## 期望行为

- 正文超出可用高度时，详情文档区域可独立纵向滚动，最后一段及底部内容完整可达，不被窗口边缘裁切。
- 滚动条可被识别和操作；使用系统自动隐藏滚动条时，滚动操作期间应能观察滚动指示，系统设置为始终显示时应有可见滑块。是否要求跨系统始终常驻显示为「待确认」。
- 滚动正文时标题、页签和关闭入口保持可用；不以整页失控滚动或遮挡文档换取正文可达。
- 文档切换、窗口缩放后滚动范围随当前内容更新；短文档、空内容及未创建文档不产生无意义的巨大空白滚动区域。
- 正文中的宽代码块保留自身横向滚动，不应因此阻止详情正文纵向阅读；沿用现有文档展示和操作，不扩展为文档编辑器改造。

## 界面展示

沿用原始截图所示布局：上方条目编号、标题和关闭按钮，中间文档页签，下方 Markdown 内容框。修复重点是下方长内容的滚动可达性和右侧滑块辨识度，不改变文档文本或页签含义。

- [交互演示（ui-demo.html）](./ui-demo.html)：切换「缺陷现象 / 修复后状态」——缺陷态长内容被裁剪、无滚动指示且滚不到底；修复态可滚动到底并保留滚动指示；另含 短内容/空/加载/失败 状态切换与页签切换（单文件 html，无外网依赖；原始截图仍作为现状佐证）。

交互：点击「说明／设计」等页签后，在正文区滚动并可到达末尾；正常长内容展示滚动指示，短内容自然填充可用区域。空内容、文档未创建、加载或加载失败时保持既有提示可见；这些状态下不应残留上一份长文档造成的异常滚动范围。实际加载及失败提示文案沿用项目实现，具体异常触发条件待确认。

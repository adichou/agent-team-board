# BUG-20260928-015 发布运行失败后确认锁不回滚：计划被误锁为已发布、无法调整范围与重新提交

- 状态：submitted（待人工接受）
- 归属：独立 Bug（引入来源见 design.md）
- 引入来源：BUG-20260928-005（正式发布判定改为「发布按钮 + 二次确认」时点，recordReleaseConfirm 幂等固化首次确认、失败/取消/重试均不回滚）
- 创建：2026-09-28T15:36:48.337Z

## 现象

BLD-20260927-001 点击「发布」并通过二次确认后，发布运行 BPUB-711ea71f 在 site-deploy 阶段失败（官网 content/ 双语成对文件缺失，即 BUG-20260928-013 所修检查），发布实际未成功；但 `release.confirmedAt` 已在运行启动时固化（recordReleaseConfirm，幂等不回滚），`isReleased()` 判定为真：

- 条目增删 / 换 commit / 补入提交被拦：「版本已正式发布，条目已锁定（如需调整请新建版本）」
- 文档范围操作被拦：「已正式发布，范围锁定（如需调整请新建版本）」
- 拦截文案称「已正式发布」，与实际状态（发布运行 failed、未发布成功）矛盾。

后果：发布失败后计划范围被锁死，只能按原范围重试发布或新建版本，无法解除确认、调整范围后再发布。

## 复现步骤

1. 准备一个 `status: merged`、发布文档已就绪的版本计划（本次实例：BLD-20260927-001，2026-09-28 09:56Z 已推送）。
2. 点击「发布」并通过二次确认 → `recordReleaseConfirm` 落盘 `release.confirmedAt`（本次 14:28:45Z）。
3. 发布运行在某阶段失败（本次 BPUB-711ea71f 于 15:22:49Z 在 site-deploy 阶段 failed）。
4. 尝试对该计划增删条目 / 换 commit / 重新提交文档 → 被按「已正式发布」口径拦截。

## 期望行为

1. 发布运行以失败终态结束时，确认锁回退：计划回到确认前的可编辑状态（merged，确认前已有的推送事实 pushedAt / site 保留），可调整范围后重新走发布确认。
2. 发布运行成功（succeeded）后确认锁不可逆，维持现状。
3. 拦截文案不再把「已确认但发布失败」的计划表述为「已正式发布」。
4. 存量修复：BLD-20260927-001（confirmedRunId=BPUB-711ea71f，该运行 failed，且无 succeeded 运行）自动恢复可编辑，无需手工改 runtime 数据。

## 验收标准

- 发布运行失败后，`isReleased` 口径对计划为假：条目增删、换 commit、文档提交/合并不再被「已正式发布」拦截。
- 发布运行成功后，行为与现状一致（锁定不可逆）。
- 存量 BLD-20260927-001 在修复生效后即恢复可编辑（重试发布或调整范围均可），不需要人工改 `runtime/builds/versions/**/version.json`。
- 取消（cancel）后的运行同样按失败口径回退确认锁（取消 ≠ 发布成功）。

# BUG-20260926-001 文档编写界面去掉整体审查按钮，然后下面的五步按钮上移到审查那一行

- 状态：以看板实时状态为准（本文件不维护业务状态）
- 归属：独立 Bug（引入来源归因见 design.md，开发阶段补全）
- 关联：REQ-20260924-006（五步操作条引入，「刷新 / 审查 / 整体审查」辅助行与五步行两行并存的来源）；REQ-20260921-012（文档编写三阶段与「整体审查完结」提交门禁）；BUG-20260921-017（删标题 / 副标题后语言集与六按钮合并同一水平行——第一行现状形态）

## 现象

发布模块「文档编写」步的顶部操作区自 REQ-20260924-006 起呈**两行布局**（`scripts/web/build.js` 的 `renderDocsPane`，约 3134–3160 行）：

1. 第一行（`.bld-docs-sub`）：语言集输入框 + 辅助动作行（`.bld-docs-actions`）——「刷新」「审查」「**整体审查**」三按钮；
2. 第二行（`.bld-docs-steps`）：「五步：」标签 + ① AI 总结 / ② 二次编辑 / ③ AI 校对 / ④ AI 翻译 / ⑤ 提交五个主流程按钮。

问题（用户诉求指向的界面缺陷）：

- 「整体审查」按钮作为常驻独立按钮占据第一行，而主流程五步按钮被压到第二行，同页主操作入口分散在两行、纵向占用高；
- 主流程（①–⑤）与辅助动作（刷新 / 审查 / 整体审查）层级混杂：主流程按钮反而低于辅助按钮一行，视觉主次颠倒。

影响为界面布局与操作动线问题：功能均可触达，但两行堆叠造成冗余纵向空间与主次不清的观感，不涉及数据错误或门禁失效。

## 复现步骤

1. 启动状态板服务（`node <插件>/scripts/server.mjs`），浏览器打开 `http://127.0.0.1:8888`，选择一个存在发布版本的项目，进入该版本的「文档编写」页签。
2. 观察页签顶部：第一行为「语言集 [输入框] 刷新 审查 整体审查」，第二行为「五步：① AI 总结 ② 二次编辑 ③ AI 校对 ④ AI 翻译 ⑤ 提交」——两行操作条上下堆叠（缺陷现象）。
3. 注意「整体审查」按钮常驻第一行（语言集内文件未全部审核时呈禁用态也照常占位）。
4. 缩窄浏览器窗口：两行各自 flex-wrap 换行，纵向占用进一步增加。
5. 对照：五步按钮（主流程）位于辅助按钮（刷新 / 审查 / 整体审查）下一行。

## 期望行为

「文档编写」步顶部收敛为**一行操作条**，主流程入口与辅助动作同层：

1. **去掉「整体审查」独立按钮**：第一行辅助动作不再渲染该按钮（`renderDocsPane` 的 `actionsHtml` 移除 `finalizeBtnHtml` 输出）。
2. **五步按钮上移到「审查」那一行**：① AI 总结 / ② 二次编辑 / ③ AI 校对 / ④ AI 翻译 / ⑤ 提交与语言集、刷新、审查合并为同一水平行（窄屏沿用 flex-wrap 换行），不再保留单独的五步行。
3. 五步按钮的顺序、编号文案、门禁禁用与运行中进度文案（如「③ 校对中 x/y」「④ 翻译中 x/y」）口径与现状一致，不因合行改变。
4. **提交门禁不弱化**：「⑤ 提交」仍需「语言集内全部文件已审核 + 整体审查已完结」（`canCommit` 口径，REQ-20260921-012）；整体审查完结前的缺口反馈（toast 文案）保持现状。
5. 完结核对对话框入口去向**待确认**（见下），但不得出现「无入口」或静默降级。

### 待确认（设计 / 开发阶段须给出结论，不得无入口或静默降级）

- **完结核对对话框的唯一入口即该按钮**：现状 `data-pf-finalize` 是 `openFinalize`（整体审查完结核对对话框）的唯一触发点（`scripts/web/build.js` 约 5210 行），而「提交」门禁要求整体审查已完结——若按钮直接移除且不安排替代入口，完结对话框将不可达、「⑤ 提交」永久锁定。入口去向（如并入「⑤ 提交」流程 / 收进「审查」对话框 / 阶段条「③ 整体审查完结」可点击等）**待确认**，以 design.md 定稿为准。
  - 开发阶段定稿（BUG-20260926-001 实施）：入口落到**阶段条「③ 整体审查完结」可点击**（保留 `data-pf-finalize` 钩子与 `openFinalize` 守卫，未解锁 aria-disabled + title 缺口，完结后可重新核对再确认），详见 design.md「方案」节。
- 该按钮为 REQ-20260924-006 实施时按「既有入口与门禁不移除——边界第 1 条」保留的辅助动作（`renderDocsPane` 内注释），本单与其边界的关系（由本单取代该条边界）在 design.md 中明确。
- 既有针对文档编写面板布局 / 按钮的测试断言（`scripts/tests/` 下 REQ-20260921-012、REQ-20260924-006 相关用例等）随新布局更新的具体范围由开发阶段定。

## 验收说明

1. 「文档编写」步顶部只有一行操作条：语言集 + 「刷新」「审查」+ ① AI 总结 / ② 二次编辑 / ③ AI 校对 / ④ AI 翻译 / ⑤ 提交；不存在独立的「整体审查」按钮，也不存在单独的五步操作行。
2. 五步按钮的顺序 / 编号 / 禁用门禁 / 运行中进度文案与现状一致：④ AI 翻译在默认语言 4/4 已审核（或存在未处理校对建议）前禁用并给缺口 title；③ AI 校对运行中显示「③ 校对中 x/y」；门禁口径不新增、不放宽。
3. 「⑤ 提交」门禁不弱化：全部文件已审核但整体审查未完结时点击提交，仍给「尚不可提交：整体审查未完结……」缺口反馈（文案随入口去向同步调整的，中英 i18n 同步）。
4. 整体审查完结核对对话框有明确可达入口（按 design.md 定稿落点实现），完结后「⑤ 提交」解锁、完结后可重新核对的现状能力不变。
5. 加载 / 失败态行为与现状同口径：数据未就绪时操作条仍渲染（按钮不隐藏），失败给错误横幅与重试。
6. 窄屏 flex-wrap 换行正常，深浅色主题下表现一致；如涉及文案改动，`scripts/web/i18n.js` 中英同步且 i18n 测试通过。
7. 「待确认」各项在 design.md 中有明确结论并落实；`npm test` 全量通过（含按新布局更新的既有断言）。

## 界面展示

### 布局

「文档编写」页签顶部操作区（本单涉及范围，下方另有阶段条与文件列表，不受影响）：

- **修复前（缺陷态）**两行：
  1. 第一行：`语言集 [zh,en]` + `刷新` `审查` `整体审查`；
  2. 第二行：`五步：` `① AI 总结` `② 二次编辑` `③ AI 校对` `④ AI 翻译` `⑤ 提交`。
- **修复后（期望态）**一行：`语言集 [zh,en]` + `刷新` `审查` + `① AI 总结` `② 二次编辑` `③ AI 校对` `④ AI 翻译` `⑤ 提交`；「整体审查」独立按钮移除（完结入口定稿落阶段条「③ 整体审查完结」可点击）。

其下「阶段：① 默认语言先行 ── ② AI 翻译与审查 ── ③ 整体审查完结」阶段条与按语言页签的文件列表保持现状。

### 交互

- 行内按钮悬停显示 title 提示（缺口明细 / 操作说明），与现状一致。
- 五步按钮点击走各自既有流程（本演示内为模拟反馈：如刷新短暂「正在读取…」、提交在未完结时给缺口 toast）。
- 禁用逻辑不变：数据未就绪或门禁未满足时按钮禁用（或 aria-disabled 点击给缺口反馈）。

### 状态反馈

- 正常：一行操作条 + 阶段条 + 文件列表，按钮按门禁启用 / 禁用。
- 加载：操作条仍渲染，数据区显示「正在加载发布流程数据…」。
- 失败：数据区显示「发布流程数据读取失败：<原因>」+ 重试按钮，按钮不隐藏。
- 门禁缺口：点击未解锁按钮给 toast 缺口反馈（如「尚不可提交：整体审查未完结……」），不静默。

### 缺陷演示

可交互演示见 [./ui-demo.html](./ui-demo.html)：单文件、内联 CSS/JS、无外网依赖、浏览器直接打开（数据与动作为模拟）。顶部「演示控制台」可切换**修复前（缺陷：两行操作条，整体审查独立按钮占第一行）**与**修复后（期望：一行操作条，五步按钮上移与审查同行，完结入口落阶段条「③ 整体审查完结」）**对比观察；并可切换正常 / 加载中 / 数据失败状态与深浅色主题。

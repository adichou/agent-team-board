# 设计 — BUG-20260926-001 文档编写界面去掉整体审查按钮，然后下面的五步按钮上移到审查那一行

> 由 Agent 在 /dev 开发前补充，人可随时批注。

## 引入来源（源单）

- 引入来源：REQ-20260924-006（经 `atb list` 核验真实存在，状态 in-progress）。
  该需求实施「文档编写流程优化（五步）」时把顶部操作区改为两行布局：第一行辅助动作
  保留「刷新 / 审查 / 整体审查」三按钮（其边界第 1 条「既有入口与门禁不移除」使
  「整体审查」独立按钮常驻第一行），主流程五步按钮压到第二行 `.bld-docs-steps`——
  即本 Bug 的两行堆叠、主次颠倒形态的直接来源。关联背景：REQ-20260921-012 引入
  「整体审查」完结核对对话框与提交叠加门禁（`data-pf-finalize` 为其唯一入口），
  BUG-20260921-017 定型了第一行「语言集 + 六按钮」单行形态；两单均为能力来源而非
  本布局缺陷的引入者。

## 根因分析

REQ-20260924-006 实施时按其边界第 1 条原样保留了「整体审查」独立按钮，并新增独立
五步操作行，导致同一页主流程（①–⑤）与辅助动作（刷新 / 审查 / 整体审查）分层在两行：
主流程按钮反而低于辅助按钮一行，纵向占用高、视觉主次颠倒。功能本身均可触达，属
布局与操作动线缺陷，不涉及数据错误或门禁失效。

## 方案

### 1. 一行操作条（`scripts/web/build.js` renderDocsPane）

- `.bld-docs-sub` 单行内依次：语言集簇 → `.bld-docs-actions`（刷新 / 审查）→
  `.bld-docs-steps`（「五步：」标签 + ① AI 总结 / ② 二次编辑 / ③ AI 校对 /
  ④ AI 翻译 / ⑤ 提交）；
- 删除独立的五步操作行（原 `stepsBarHtml` 不再作为 `.bld-docs-sub` 的兄弟节点渲染，
  改为并入行内；`.bld-docs-steps` 容器与 aria-label「文档编写五步操作」保留，
  五按钮字重 600 的既有样式不变）；
- 加载 / 失败态同一行恒渲染（原两行恒渲染口径收敛为一行恒渲染）；窄屏沿用
  flex-wrap 换行；
- 五步按钮的顺序、编号文案、门禁禁用、运行中进度文案（「③ 校对中 x/y」
  「④ 翻译中 x/y」「① 总结中 x/y」）与现状一致，不因合行改变。

### 2. 去掉「整体审查」独立按钮与完结合口去向（README 待确认项定稿）

**结论：完结核对对话框入口落到阶段条「③ 整体审查完结」，该项可点击。**

- `renderDocsPane` 的 `actionsHtml` 移除 `finalizeBtnHtml(pf)` 输出，函数删除；
- `docsStageBar` 的第三阶段由 `<span class="bld-stage">` 改为
  `<button type="button" class="bld-stage bld-stage-fin" data-pf-finalize …>`：
  - 保留 `data-pf-finalize` 既有事件绑定与 `openFinalize` 守卫（未就绪 / 未解锁点击
    toast 缺口，不静默），行为零改动；
  - 未解锁（`canFinalize` 非 true）：`aria-disabled="true"` + title 列缺口明细
    （「整体审查未解锁：尚缺 N 个文件审核（…）」），模式同 BUG-20260920-006；
  - 解锁未完结：title 为打开完结核对说明；已完结：title 为「重新核对再确认（更新
    完结时间）」——完结后可重新核对的现状能力天然保留（阶段条 ready 态恒渲染）；
  - 阶段 chip（✔ 已完成 / ● 进行中 / ○ 未解锁）原样保留在按钮内。
- 选此落点的理由（README 给出的三个候选中定稿）：
  1. 「并入 ⑤ 提交流程」会把提交点击与完结确认耦合，且完结后再核对入口无处安放
     （提交门禁通过后点击即提交）；
  2. 「收进审查对话框」把「逐文件通过审核」与「整体完结人工确认」两个层级混在一屏；
  3. 阶段条本就承载「③ 整体审查完结」阶段语义，解锁即可点是最小改动、入口常驻可见、
     完结前后均可达，且不新增任何门禁口径。
- `⑤ 提交` 门禁不弱化：`canCommit`（全部已审核 + 整体审查已完结）口径不动；
  全部已审核未完结时点击提交仍给缺口 toast，文案同步指向新入口：
  「尚不可提交：整体审查未完结（全部文件已审核后，请先在阶段条「③ 整体审查完结」
  确认完结）」；提交按钮 title 同步（「…请先在阶段条「③ 整体审查完结」确认完结再提交」）。
- 加载 / 失败态：阶段条本就仅 ready 态渲染（现状），完结入口随阶段条在数据未就绪时
  不出现——数据未就绪时完结本不可进行，操作条按钮（刷新 / 审查 / 五步）仍恒渲染，
  失败给错误横幅与重试，与现状同口径。

### 3. 文案与 i18n（`scripts/web/i18n.js` 中英同步）

- 新增 / 替换两条提交缺口文案（见上），旧两条含「请先「整体审查」」的键删除；
- 「整体审查」独立词条随按钮移除清理（阶段条键「③ 整体审查完结」、完结对话框各键
  不受影响）；「五步：」标签保留、词条保留。

### 4. CSS（`scripts/web/style.css`）

- `.bld-docs-sub` / `.bld-docs-actions` / `.bld-docs-steps` 规则保留（注释随新布局更新）；
- 新增 `.bld-docs-stages .bld-stage-fin`：按钮样式重置（无边框 / 背景 / padding，
  font 与颜色继承），aria-disabled 时不显手型，解锁态 hover 下划线提示可点。

**开源选型（REQ-20260909-015）**：本单为既有自研 Web 面板的布局与入口调整，无独立
功能域可引入成熟开源库（无 npm 分发的「布局微调」类库；引入 CSS 框架 / UI 库成本与
回归面远大于改动本身），自研理由：改动量为既有代码内的模板与样式调整。

## 风险与边界

- 只动 `scripts/web/build.js`（renderDocsPane / docsStageBar / commitBtnHtml /
  commitDocs 文案）、`scripts/web/style.css`、`scripts/web/i18n.js` 与相关测试；
  不触碰服务端门禁求值（publish-flow）、完结 / 提交 API；
- 既有测试断言随新布局更新：`finalizeBtnHtml` 从各测试提取清单移除（函数已删）；
  「整体审查」词条从 bug-20260921-017 / req-20260921-012 的在用词条清单移除；
  其余阶段条 / 门禁 / 五步断言不回退；
- 本单取代 REQ-20260924-006 边界第 1 条中对「整体审查」独立按钮的保留要求
  （该边界其余部分——刷新 / 审查等入口与全部门禁——不回退）；
- 不改 `index.html` 结构与 `ui-demo.html` 之外的演示文档；条目 ui-demo.html 的
  修复后态随定稿更新（完结入口标注从「待确认」改为阶段条落点）。

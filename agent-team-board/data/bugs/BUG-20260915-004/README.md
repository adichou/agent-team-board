# BUG-20260915-004 挂起确认面板错误提示透传截断的原始 git 报错，缺少可读原因与处理指引

- 状态：submitted（待人工接受）
- 引入来源：REQ-20260914-001（引入挂起确认闭环：提交不完整挂起 + 任务页「待人工确认」面板展示挂起原因）
- 创建：2026-09-15T00:28:10.088Z

## 现象

BUG-20260914-020（run-20260914-250）自动提交因 `.git/index.lock` 瞬时冲突失败后，Status Board 任务页「待人工确认」面板的错误提示只显示了一句被拦腰截断的原始 git stderr：

> 自动提交失败：git add失败：fatal: Unable to create '/Users/adichou/Documents/src/agent-team-board

用户从该提示无法得知：

1. 真正的失败原因（`.git/index.lock` 被并发 git 进程占用，属可重试的瞬时冲突，不是数据损坏）；
2. 该怎么处理（点「重新核验」或「确认并继续」重试即可），只能靠猜或求助。

## 复现步骤

1. 构造场景：在 `receipt` 收尾自动提交的同时让另一 git 进程持有 `.git/index.lock`（或直接查看现存现场 `docs/agent-team-board/dispatch/runs/run-20260914-250/receipt.json` 的 `suspended.reason`）；
2. 打开 Status Board 任务页「待人工确认」，点开 BUG-20260914-020 的挂起详情；
3. 观察错误提示：仅显示截断的原始报错，无原因归类、无处理指引。

## 期望行为

- 挂起原因为「现象原文 + 归类原因 + 处理指引」分层呈现：原始 stderr 可折叠查看全文（不丢失），默认展示人话结论，如「git 索引被其他进程占用（瞬时冲突）：重新核验或确认并继续即可重试补交」；
- 截断策略不得丢关键信息：现有 `slice(0, 120)` 把报错中段（含 `index.lock': File exists`）截掉，应改为保头保尾或提高上限，或干脆按「归类原因 + 全文折叠」组织，不再依赖截断串；
- 至少覆盖本次实测的 `index.lock: File exists` 一类（并发冲突可重试）；其余未知错误归「原因未知，附原始输出」。

## 验收标准

1. 用 run-20260914-250 的挂起数据打开面板：默认提示包含「索引被占用/瞬时冲突/可重试」语义的归类原因与下一步指引；
2. 原始完整错误可通过折叠区查看，不再出现拦腰截断丢原因的展示；
3. 新增原因归类逻辑有测试覆盖（index.lock 场景 + 未知错误兜底）。

# BUG-20260921-013 文档编写界面的文件区域应该采用页签布局，每个语言是一个页签

- 状态：submitted（待人工接受）
- 归属：独立 Bug（引入来源见 design.md）
- 创建：2026-09-21T07:55:28.016Z

## 现象

「发布」模块版本详情五步流程的「文档编写」步中，发布文档文件区域（「文件（N · 默认语言 x/y 已审核 · 剩余语言 z/w 已审核）」表头 + 文件列表）是一个**单列纵向长列表**：默认语言四个文件（README.md / CHANGELOG.md / FEATURES.md / AGENTS.md）与各剩余语言四个文件（README_en.md 等 `KEY_lang.md`）全部平铺在同一个 `<ul class="bld-docs-list">` 里，仅靠插入分组标题行（`li.bld-doc-group`，如「默认语言（中文，文件不带后缀）」「剩余语言（en · AI 翻译）」）做视觉分隔。

问题：语言集语言数 N 增多时（REQ-20260921-010 起语言集动态、4 类 × N 文件），列表线性增长；查看某一语言的四个文件需要在长列表中滚动定位，默认语言与各翻译语言的行相互穿插，跨语言对照与聚焦单语言都不方便。对照同页的审查对话框（`renderReviewModal`）已采用页签布局（按文档类型四页签 + 语言并排），文件区域仍是平铺列表，交互形态不一致。

缺陷位置：`scripts/web/build.js` 的 `renderDocsPane`——文件区域由 `<section class="bld-docs-files">` 渲染，`groupHtml`（默认语言组 + `restLangs.map` 各剩余语言组）把分组标题与文件行全部拼进单个列表；对应样式在 `scripts/web/style.css` 的 `.bld-docs-files` / `.bld-docs-list` / `.bld-doc-row` / `.bld-doc-group`。该平铺布局由 REQ-20260921-008 文档编写页三段式布局引入、经 REQ-20260921-010 语言集动态清单与 REQ-20260921-012 三阶段视图沿袭为按语言成组的单列表。根因分析与修复方案留待开发阶段写入 design.md。

## 复现步骤

前置：看板项目已存在至少一个构建版本（发布模块版本列表非空）；界面语言不限（中英文均可复现）。

1. 启动看板界面：`node scripts/server.mjs`（默认端口 8888）或桌面壳 `npm run app`。
2. 进入「发布」模块，在版本列表选中任一版本，右侧打开版本详情（五步流程：版本计划 → 关联条目与提交 → 文档编写 → 合并入 main → 正式发布）。
3. 点击步骤页签「文档编写」（步骤页签只改变浏览位置，前置未满足也可浏览）。
4. 观察文件区域：所有语言的所有文件在一个纵向列表里连续排列，中间仅有「默认语言（…）」「剩余语言（… · AI 翻译）」小字分组标题行——即为本缺陷。
5. 扩大现象：把「语言集」输入框改为 `cn,en,fr` 回车应用，文件列表变为 12 行单列（3 语言 × 4 文件），列表更长、语言间穿插更明显。
6. 对照参考：点击「审查」打开审查对话框——该对话框为页签 + 分栏布局；关闭后回到文件区域仍是平铺单列，形态不一致。

## 期望行为

- 文件区域改为**页签布局，每个语言一个页签**：语言集内有几个语言就有几个语言页签；激活某语言页签时，页签内仅列出该语言的四个文件（README / CHANGELOG / FEATURES / AGENTS，默认语言文件不带后缀、其余语言 `KEY_lang.md`）及各自状态 chip。
- 页签形态细节（页签标签文案——如是否含语言缩写 / 显示名 / 默认语言标记、是否在页签上显示该语言审核进度计数如 2/4、激活页签记忆策略等）**待开发阶段 design 定稿**，但不得回退为「全部语言平铺单列表 + 分组标题行」的现状。
- 现有信息与能力必须全部保留，不得因改版弱化：
  - 文件级七态状态 chip（未总结 / 正在总结 / 已总结待审核 / 未翻译 / 正在翻译 / 已翻译待审核 / 已审核，图标 + 颜色 + 文字三重区分）逐行保留；
  - 表头汇总计数「文件（N · 默认语言 x/y 已审核 · 剩余语言 z/w 已审核）」保留（页签化后仍需一眼看到全局审核进度，不只见当前语言）；
  - AI 总结 / AI 翻译运行中的「当前文件」行内进度标注（`AI 总结 x/total` / `AI 翻译 x/total`）保留；当运行中当前文件不在激活页签的语言组内时如何提示（如页签角标 / 不自动跳页签避免打断浏览）**待确认**（design 定稿）；
  - 语言集动态联动：修改语言集（回车 / 失焦应用）后语言页签随新语言集重建（页签数 = 语言数，默认语言始终为第一个页签）；
  - 「刷新」按钮的列表读取中覆盖层「正在读取最新内容…」、发布流程数据加载中 / 读取失败态（错误横幅 + 重试）、阶段条、门禁条、基准变更提示均不受影响；
  - 文件名与语言显示名是标识不是文案，保持 `data-i18n-skip` 豁免（BUG-20260921-004 口径），不进界面翻译词典。
- 文件区域无「空文件列表」空态（文件清单由语言集推导恒为 4×N，加载 / 失败态按现有口径整区显示加载文案或错误横幅），无需新增空态。
- 中英文界面同步（BUG-20260912-001 基线）：页签相关新增界面文案在 scripts/web/i18n.js 双语维护。

## 验收说明

1. 布局：进入 发布 → 选中版本 → 文档编写步，文件区域呈现语言页签行（语言集 `cn,en` 时为 2 个语言页签）；激活任一页签仅显示该语言四个文件行，不再出现多语言平铺单列与「剩余语言（…）」分组标题行。
2. 交互：点击各语言页签可切换所列文件（键盘可达，`role="tablist"` / `role="tab"` / `aria-selected` 与既有页签组件口径一致）；切换步骤 / 版本 / 重进页面行为与 design 定稿一致（默认落在默认语言页签或记忆上次选择）。
3. 语言集联动：语言集改为 `cn,en,fr` 应用后出现 3 个语言页签且文件清单随动；非法值（空 / `cn,,en` / `cn1` / `cn,cn`）行内报错不应用、页签不变（回归 REQ-20260921-010 行为）。
4. 状态反馈回归：文件状态 chip 七态正常展示；「刷新」读取中显示覆盖提示；发布流程数据读取失败态显示错误横幅 + 重试；AI 总结 / AI 翻译运行中的当前文件进度标注可见（含 design 定稿的非激活页签提示口径）；门禁条与阶段条计数不受页签切换影响（始终反映语言集全局）。
5. 中英文界面切换后页签布局与文案均正确（右上语言按钮往返切换检查）。
6. 窄屏（≤640px）无横向溢出，页签行按现有响应式口径换行或滚动。
7. 若实现涉及 i18n 词典调整，遵循中英文同步基线并跑 i18n 相关测试；交付前 `npm test` 全量通过。

## 界面展示

可交互演示：[ui-demo.html](./ui-demo.html)（单文件、内联 CSS/JS、浏览器直接打开）。

- 界面布局：还原「文档编写」步的阶段条、文件区域与门禁条上下文。「缺陷现状 / 期望修复」开关对照两种布局：现状为全部语言文件平铺单列、仅小字分组标题分隔；期望为语言页签行（每语言一页签，页签上带该语言审核计数角标）+ 页签内该语言四文件列表，表头仍保留全局汇总计数（页签标签具体形态为演示示意，最终以开发阶段 design 定稿为准）。
- 交互行为：语言页签可点击切换（键盘 Tab + 方向键可达，`aria-selected` 联动）；语言集输入框可编辑，回车应用——合法值（如 `cn,en,fr`）重建语言页签与文件清单并弹 toast，非法值（清空 / 连续逗号 / 非法缩写 / 重复项）就地行内红字报错且不应用；另有「AI 总结运行中」「AI 翻译运行中」场景可演示当前文件标注与页签角标提示。
- 状态反馈：正常 / 加载中 / 读取失败（错误横幅 + 重试可恢复）/ 刷新中（列表覆盖层）/ 保存中（语言集输入禁用 + 提示）状态切换；文件行七态状态 chip 三重区分（图标 + 颜色 + 文字）；文件区域无空态（清单由语言集推导恒有文件，演示内有说明）；另附深浅色切换（可选能力）。

# BUG-20260914-012 main 分支的推送按钮不需要，请去掉

- 状态：submitted（待人工接受）
- 归属：独立 Bug（引入来源见 design.md）
- 引入来源：REQ-20260913-001（构建模块引入分支浏览，`renderBranchesPane()` 自始对除当前分支外所有本地分支渲染「推送」按钮，未对 main 区分；经 `atb list` 核验存在）
- 创建：2026-09-14T05:24:04.772Z

## 现象

Web 看板「构建」模块 →「分支浏览」子页签中，左侧「本地」分组里 **main 分支行右侧渲染了「推送」按钮**，属多余入口（功能本身可点通）：

- 按钮位置：`scripts/web/build.js` 的 `renderBranchesPane()`——「本地」分组对**除当前分支外的所有本地分支**逐行渲染「推送」按钮（`data-push`，约 1012–1014 行），未对 main 做任何区分；
- 按钮可用：点击弹「推送分支 main」确认框（`renderPushConfirm()`：目标远端下拉 + 首推建立跟踪 / 更新已有远端分支提示）→「确认推送」（`doPush()`）→ `POST /api/build/push`（`scripts/server.mjs`）→ `buildGit.pushBranch()`（`scripts/lib/build-git.mjs`）执行 `git push [-u] <remote> main`——服务端对 main 不做任何拒绝；
- 与既有语义边界冲突：REQ-20260913-001 design.md 已落定「**发布是推送远端，构建是本地集成分支，语义不同**」——main 推到远端属发布模块（release-git 七阶段流水线：预检 dry-run 不推送 → 计划冻结确认 → 仅快进推送 → 结果核验）的受控动作；分支浏览的「推送」入口是为 dev / 功能分支首推建立上游跟踪而生，main 行出现该按钮绕开了发布治理口径（另 `scripts/lib/git-flow.mjs` 的 `ensureMainBranch` 补建 main 时也明确「只创建分支、不推送远端」）；
- 出现条件：仅当 **main 不是当前分支** 时出现（main 为当前分支时按「当前」行渲染、本就无按钮）；看板默认 dev + main 双分支工作流（REQ-20260911-009：开发在 dev），工作区常驻 dev，故该按钮常态可见。

## 复现步骤

1. 启动看板服务：在项目目录终端运行 `atb serve`（默认端口 8888，可用环境变量 `ATB_PORT` 覆盖），浏览器打开 `http://localhost:8888`；
2. 顶栏项目选择器选择一个 **git 仓库** 项目，且该仓库存在 main 分支、**当前分支不是 main**（典型：dev + main 双分支、工作区在 dev；任意功能分支亦可）；
3. 顶栏切到「构建」模块页签；
4. 模块内切到「分支浏览」子页签（首次进入自动加载分支列表）；
5. 观察左侧「本地」分组：main 行右侧有「推送」按钮，点击可走完整推送流程——即本 Bug 所述待去掉的入口。

## 期望行为

- 「本地」分组中 **main 分支行不再渲染「推送」按钮**；main 行本身保留（仍可点击查看提交记录，浏览只读语义不变）；
- 其余本地分支（dev / 功能分支）的推送按钮、推送确认弹窗（首推 `-u` 建立跟踪 / 更新已有远端分支提示）、推送执行与成功 / 失败 toast 均维持现状；
- BUG-20260914-006 的空远端解释文案与 `attn` 高亮逻辑不变（高亮对象为 dev 等非 main 分支的推送按钮）；
- i18n 无需新增词条（`scripts/web/i18n.js` 的「推送: Push」继续用于其他分支）；
- 服务端 `POST /api/build/push` 是否同步封禁 main（防绕过 UI 直调接口推 main）：**待确认**，由开发阶段 design.md 落定；本 Bug 验收以 UI 入口移除为准。

## 验收说明

1. dev + main 双分支仓库（当前分支 dev）打开 构建 → 分支浏览：「本地」分组 main 行**无**「推送」按钮，dev 行按钮仍在、点击流程（确认弹窗 → 推送 → toast / 防重复）与改前一致，无回归；
2. main 为当前分支的仓库：main 以「当前」行渲染、无按钮（现状即如此，回归确认未破坏）；
3. BUG-20260914-006 场景回归（已配置远端 + 「和远端同步」成功后远端列表仍为空）：解释块与非 main 分支推送按钮的 `attn` 高亮仍出现，既有断言 `scripts/tests/bug-remote-empty-explain-20260914-006.test.mjs`（其 `bld-push attn` 断言基于 dev 分支）保持通过；
4. 边界场景（**待确认**）：若除当前分支外本地仅剩 main（无 dev / 功能分支），空远端引导文案「可在上方『本地』分组对分支点『推送』」将无处可点——该极端场景的文案口径验收时与提出人 / 开发者确认处理方式；
5. 切换英文界面语言：dev 等分支按钮文案「Push」正常翻译，无中文降级残留；
6. 改动范围核对：仅 `scripts/web/build.js` 分支行渲染处移除 main 的推送按钮（及必要注释 / 关联断言更新）；`scripts/tests/` 现无针对 main 行推送按钮的断言，开发中若新增「main 行无按钮」断言需一并落地；`build-git.mjs` / `server.mjs` 的推送能力是否封禁 main 以 design.md 落定口径为准。

## 界面展示

可交互演示：[./ui-demo.html](./ui-demo.html)（单文件 HTML，无外网依赖，浏览器直接打开；支持「当前（缺陷）↔ 修复后」一键对比——缺陷态 main 行有「推送」按钮、修复态无；可切换当前分支（dev / main）、远端为空（首推场景）、模拟请求失败，覆盖分支列表与提交记录的加载 / 空 / 失败状态，深浅色随系统自动适配）。

- 界面布局：还原「构建 → 分支浏览」子页签——模块内子页签行（版本计划 / 分支浏览），主体左右分栏：左侧分支列表（顶部工具栏「⟳ 和远端同步」「刷新」；下方按「本地 / 远端」分组——本地组当前分支置顶带「当前」徽标，dev / main 等行右侧带「推送」按钮（随模式与分支变化），远端组列 `origin/` 分支或空态解释块），右侧为选中分支的提交记录（标题栏带「刷新」）。
- 交互行为：点击分支行懒加载右侧提交记录（含加载态）；点「推送」弹确认框（目标远端下拉 + 首推 `-u` 建立跟踪 / 更新已有远端分支提示）→「确认推送」后按钮禁用防重复 → 成功 toast 并在远端分组出现对应 `origin/` 分支；「和远端同步」执行中禁用显示「同步中…」；演示控制条可切「当前（缺陷）/ 修复后」对照 main 行按钮的有无，并切换当前分支验证「main 为当前分支时本就无按钮」的现状口径。
- 状态反馈：推送 / 同步执行中按钮禁用；成功弹「✓ …」toast、失败（勾选「模拟推送失败」）弹「✕ …」错误 toast 且可重试；进入 / 刷新列表显示「加载分支中…」；远端为空时显示 BUG-20260914-006 口径的解释块与非 main 分支推送按钮的高亮；未选分支时右侧显示「点击左侧分支查看提交记录」引导空态；勾选「模拟分支读取失败」时列表区显示错误与「重试」按钮。

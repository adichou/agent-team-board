## 根因分析

纯措辞问题，无行为缺陷：REQ-20260913-001 落地时把分支浏览工具栏同步按钮文案定为
「⟳ 同步远端」，与用户期望措辞「和远端同步」不一致。

排查附带发现：⟳ 图标前缀与文案同处一个文本节点，i18n 运行时（`translateTree` → `t()`）
按**文本节点全文命中**翻译，原词条键 `'同步远端'`（不含前缀）实际无法命中该按钮——
英文界面本就对该按钮降级显示中文。更名时一并以「⟳ 和远端同步」为键修正词条，
英文界面不再降级（词典既有惯例：`✓ …` 等图标前缀随键全文收录）。

## 方案

1. `scripts/web/build.js` `renderBranchesPane()`：
   - 按钮默认态 `⟳ 同步远端` → `⟳ 和远端同步`（保留 ⟳ 前缀与 title 提示）；
   - 远端空态指称同步更新：`（无远端分支：先「和远端同步」或推送本地分支）`；
   - 文件头注释中按钮名引用一并更名（注明 BUG 编号）；
   - 行为零改动：仍 `POST /api/build/fetch`（fetch --all --prune）；执行中禁用显示「同步中…」；
     成功 / 失败 toast（`✓ 已同步远端（fetch --prune）` / `✕ 同步远端失败：<原因>`）
     与列表、提交记录自动刷新维持现状。
2. `scripts/web/i18n.js`：词条 `'同步远端': 'Sync remote'` 更名为
   `'⟳ 和远端同步': '⟳ Sync with remote'`（键含前缀全文命中；旧键随更名清理，避免死词条）。
3. 新增测试 `scripts/tests/bug-sync-btn-wording-20260914-005.test.mjs`（先红后绿）：
   U1/U2 文案与空态指称、U3/U4 busy 态与成功失败 toast 现状不回归（vm 桩驱动 doFetch）、
   W1 词典新词条中英往返、S1 源码旧文案无残留。

**开源选型（REQ-20260909-015）**：未引入开源库。自研理由：单处按钮措辞修改与词典
词条调整，不涉及任何第三方库能力，无合适库可复用（改动量与风险均高于自研）。

## 风险与边界

  与本条目文档；源码与测试无残留。

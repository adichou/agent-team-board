## 现象

需求模块已通过顶部状态筛选将条目分成「待接受、已接受、已计划、开发中、待测试、已完成」六档，但每张列表卡片的单号后仍重复显示所在档位名称，增加视觉噪声并占用首行空间。标题所述“每个单后面加上状态显示”，本轮按需求模块中 REQ / BUG 列表的业务状态标签明确验收范围。

2026-09-09 静态核实结果：

- `scripts/web/app.js` 的 `applyReqFilter()` 按 `laneOf(it) === state.reqFilter` 过滤，同一档列表内的业务状态标签与筛选名称重复。
- `reqRowEl()` 仅对 `planned` 省略状态标签，其他五档仍生成 `<span class="state …">`。因此当前「已计划」已满足去重目标，其他五档仍需统一。
- 「待测试」由 `in-progress` 且存在 `agentCompletedAt` 派生，并非独立存储状态；去除重复展示不能改变这个分类规则。
- 同一行还可能出现「未完善 / 完善中 / 已完善」按钮及「模型配置待处理」提示，它们不是档位标签，承担额外信息或跳转入口。

未提供问题截图、浏览器版本和窗口尺寸；以上为当前源码事实，实际页面复现及首次出现版本待确认。

## 复现步骤

1. 打开本项目的 Status Board，进入「需求」模块，确认当前筛选档中有至少一条 REQ 或 BUG。复现无需改变条目状态。
2. 点击「已接受」档，观察某一条卡片首行：单号及复制按钮后出现「已接受」，与顶部选中档位重复；其旁边的完善按钮另有语义。
3. 分别切换有数据的「待接受、开发中、待测试、已完成」档，观察同类重复标签。某档无数据时记录未覆盖，后续用独立验收数据补齐。
4. 切换「已计划」档作对照：当前源码已不生成逐条「已计划」标签。
5. 点击一条卡片打开详情，区分列表上的重复标签与详情中的「状态」字段；后者仍提供完整条目上下文。

## 期望行为

- 需求模块六档下所有 REQ / BUG 列表卡片，均不再逐条显示与筛选档位重复的业务状态文字或状态徽章；也不改成另一处常驻角标重复展示「待测试」等名称。
- 顶部六档筛选、选中反馈与计数继续显示，用户通过当前档位获知列表分类。行悬停说明、详情的状态字段与上报提示仍可帮助识别条目状态。
- 首行移除标签后自然收拢，不保留空占位。单号、复制按钮、可用的复选框和行内操作继续可用；标题、认领者、更新时间及下属 Bug 信息正常展示。
- 默认保留完善按钮及其跳转、模型配置待处理提示等提供额外信息的控件；不将其当作冗余业务状态标签一并删除。
- 搜索、排序、切换档位、轮询刷新以及宽窄屏返回列表后遵循同一显示规则；空列表继续显示空态，加载或请求失败继续提供原有页面反馈，不借移除标签掩盖失败信息。

- [ ] 完善按钮的三态文字及跳转、模型配置待处理提示保持可识别；详情仍显示实际业务状态，待测试条目详情仍显示已上报信息，已完成详情不重新出现待测试提示。

- [ ] 空结果、初始加载和接口失败场景保持原有页面反馈，不出现伪造的条目或成功状态。

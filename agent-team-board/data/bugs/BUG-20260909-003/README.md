# BUG-20260909-003 改标题描述改为修改

- 状态：accepted（已接受；本轮仅完善说明）
- 归属：独立 Bug（引入来源见 design.md）
- 创建：2026-09-08T23:05:24.528Z

## 现象

Status Board 待接受条目的直接编辑入口仍显示「✎ 改标题/描述」，与本条要求的简短文案「修改」不一致。列表卡片和详情抽屉各有一处，需同步统一，避免同一功能在不同入口使用不同名称。

本次已通过当前仓库代码核实：

- `scripts/web/app.js` 的卡片渲染处与 `drawerActionsButtonHtml()` 均输出「✎ 改标题/描述」，且仅对 `submitted` 条目显示。
- 两处通过 `data-rename-id` 与 `bindRenameButtons()` 调用同一个 `editItem()`，打开标题、描述双字段编辑弹窗；该操作直接保存内容，并非复制修改提示词。
- `editItem()` 从 README 读取需求的「描述」节或 Bug 的「现象」节，提交到 `/api/item/:id/content`；服务端 `core.editItem()` 同样只允许待接受条目编辑。
- `scripts/tests/edit-content.test.mjs` 已有双字段编辑及「修改提示词」功能下线的相关验证约定，可作为修复后的回归依据。

核实范围为静态代码与文档，尚未在运行中的浏览器复现；具体浏览器、窗口尺寸与原始截图待确认。本条没有证据表明编辑保存本身失效。

## 复现步骤

1. 打开使用当前项目代码的 Status Board，选择一个已有的「待接受（submitted）」需求或 Bug。若当前项目没有该状态的条目，在独立测试项目准备；不要为复现改变本 Bug 的 accepted 状态。
2. 在列表中观察该条目的操作区，当前排列包含「✓ 接受」「✎ 改标题/描述」「🗑 删除」，记录直接编辑按钮的可见文案。
3. 点击条目打开详情抽屉，观察操作区，同一编辑入口仍显示「✎ 改标题/描述」。
4. 点击任一「✎ 改标题/描述」入口，确认打开的是预填现有标题和描述的编辑弹窗，随后取消即可完成入口识别，无需修改实际数据。
5. 对需求和 Bug 各重复一次，确认两类条目都存在该文案；非待接受条目没有该入口，不能用本 Bug 当前状态直接复现。

## 期望行为

将列表卡片和详情抽屉中该直接编辑按钮的可见文字统一为「修改」，沿用原位置、按钮样式与铅笔图标，最终显示「✎ 修改」。该标题理解为入口文案调整；弹窗标题、字段名称、保存与取消按钮仍沿用现有语义。

- **布局与展示**：列表操作区显示「✓ 接受 / ✎ 修改 / 🗑 删除」，详情操作区同样显示「✎ 修改」。按钮缩短后相邻操作顺序不变，不能出现重叠或截断。普通宽度与窄窗口均检查实际可用布局。
- **交互**：点击「修改」仍打开同一个标题与描述编辑弹窗；卡片按钮点击不冒泡打开详情。标题、描述可以分别修改或一起保存；取消及 Esc 不写入数据。
- **含义提示**：悬停说明与无障碍名称继续明确“修改标题与描述”“仅待接受”，无障碍名称保留条目编号。短文案不会把作用范围扩展为任意字段、任意状态编辑。
- **状态反馈**：正常时预填现有内容；描述为空仍能进入编辑；标题为空或超长给出校验提示且不保存；无变化有提示且不发写请求。保存中沿用「保存中…」及禁止重复提交；成功更新列表和已打开详情并提示完成；读取失败给出错误反馈，保存失败保留输入并支持重试。

本条不恢复已下线的「修改提示词」按钮，不改变待接受以外状态的编辑权限，不新增后端编辑能力。是否连弹窗标题「编辑 <编号>」也要改为「修改 <编号>」未在原登记中说明，记为待确认，不列入本次必需范围。

## 现象

2026-09-08 14:13 由用户在看板登记（by board）：在网页统一新建弹窗（顶栏「＋ 新建」）创建讨论单（类型选「讨论（ASK）」），标题已填写、**问题正文留空**，点击「创建」按钮后页面弹出错误提示，文案含「正文不能为空」（登记原文一句话，精确文案待确认，见排查线索候选一/二的两种可能），讨论单未创建成功、弹窗保留。

背景：REQ-20260908-013（讨论单创建时正文可留空＝以标题作为正文）已于 2026-09-08T13:42:37Z 上报完成（覆盖率 100%，等人工确认），本 Bug 登记时间晚其约 31 分钟，说明该改造在登记人的实际运行环境中未生效——正文留空仍被「不能为空」拦截，与 REQ-20260908-013 的验收标准直接冲突。

## 复现步骤

登记时的浏览器页面状态与服务进程启动时间均待确认；按环境前提分两种情况：

1. 启动看板服务（`node scripts/server.mjs`）并打开看板页面。
   - 候选一路径：页面为 REQ-20260908-013 改码**前**打开、此后未刷新（旧 app.js 留在浏览器内存）；
   - 候选二路径：页面已刷新为新版，但 `server.mjs` 进程为改码**前**启动、未重启（进程内仍是旧版 lib/oncall-store.mjs）。
2. 点击顶栏「＋ 新建」，类型下拉选「讨论（ASK）」。
3. 填写标题（必填，≤120 字），问题正文留空（附件可有可无）。
4. 点击「创建」。
5. 预期复现：弹出含「正文不能为空」的错误提示——候选一为「讨论单的问题正文不能为空」（前端拦截，不发请求）；候选二为「创建失败：问题正文不能为空」（服务端旧 createTicket 抛错回传）——弹窗不关闭、讨论列表无新单。

若在最新代码环境（页面刷新 + 服务重启）下复测仍出现拦截，则为真实代码缺陷，需修复阶段重新定位（当前磁盘代码创建路径已无该拦截，见排查线索第 1 条）。

## 期望行为

与 REQ-20260908-013 口径一致：

- 统一新建弹窗类型选讨论（ASK）时，问题正文留空可直接点「创建」成功，不出现任何「正文不能为空」提示。
- 留空创建成功后：弹窗关闭、toast「✓ 已创建 ASK-…（待回复）」、自动进入讨论模块返回列表；`oncall/tickets/ASK-…/question.md` 落盘标题文本，详情抽屉第 1 轮问题区（`.oncall-q`）显示标题文本，派单提示词「当前待答问题（第 1 轮）」同为标题文本。
- 填写了正文、纯空白正文、附件组合等场景行为不变（完整回归口径见 REQ-20260908-013 验收标准）；标题必填与 ≤120 字校验保持。
- 范围排除：详情抽屉「问询（针对本单追问）」与 CLI 追问正文仍必填（追问轮次无标题可回退），提示「追问内容不能为空」为设计行为，不在本 Bug 范围。

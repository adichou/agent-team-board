## 信息架构与职责

当前项目模块导航增加“营销”，内部为概览、定位与定价、渠道与行动、效果与复盘。阶段二从营销概览打开全部项目侧面板，不复用当前“全局任务”的指标语义。宽屏表单与详情并排，窄屏顺序展示；深浅色和键盘行为沿用宿主。

渠道是长期触点，实验是可验证假设，行动是一次内容或发布，观察记录是带口径与来源的数据，复盘是基于指定观察版本的结论。实验可包含多条行动，行动可关联开发 REQ。营销状态与开发状态独立；营销已发布不代表已有效，开发完成不代表推广完成。

## 建议文件契约

每个项目 docs/agent-team-board/marketing/ 内保存：

```text
profile.json                 # 项目营销元数据、目标、阶段及当前定价引用
positioning.md               # 定位、证据、假设和未决问题
pricing/<version>.json       # 不可覆盖的定价版本
channels/<id>.json           # 渠道与账号/社区档案
experiments/<id>/             # 实验元数据、行动引用和复盘
  experiment.json
  reviews/<id>.md
activities/<id>/              # 行动元数据与内容
  activity.json
  content.md
metrics/definitions.json      # 指标字典、口径和可聚合性
metrics/observations/         # 按周期分片的观察与修订
agent-runs/<id>/              # AI 输入引用、草稿、摘要及回执
integrations.json             # 仅非敏感配置和凭据引用（阶段二）
```

最终文件名可在设计阶段调整，但边界与语义不可丢失。所有机器实体含 schemaVersion、稳定 ID、createdAt、updatedAt、revision；项目归属以现有注册机制与校验后的项目根目录为准，不能仅用目录名。ID 分配、写入与状态变更经统一数据层和 CLI/API；原子替换、版本冲突检测与操作幂等必须共用，不能由 UI 或 Agent 任意拼写机器状态。路径引用限定在当前项目授权范围，跨项目聚合只读。

Markdown 策略、内容、复盘以及有限聚合快照可入 Git。凭据、个人用户明细、海量原始事件和执行日志置 Git 外；第一版只收集汇总数据。示例数据仅用于 Demo，不能注入真实项目指标。删除优先归档，已被活动或复盘引用的版本保持可读。

数据错误保留最后有效内容；缺少可选字段与不支持的 schemaVersion 分开处理。并发编辑使用 revision 拒绝过期写入并允许保留本地草稿，不静默覆盖。

## 指标和归因原则

- 明确区分存量、期间增量、事件次数和独立人数；日期范围、时区、来源、单位与去重口径随值保存。
- null 为未知，0 为实际零。无数据、未接入、同步失败不能折算成零。
- 粉丝、订阅、Star 不跨平台相加为总人数。不同币种不默认换算，同一来源重复导入不重复计数。
- 第一版支持在行动上记录 UTM 参数或独立链接及人工来源，但不声称实现跨平台身份识别或多触点归因。
- 转化率只基于兼容群体和期间计算，分母为零显示不可计算。没有完整获客成本数据，不将广告支出除付费人数标成完整 CAC。
- 复盘结论绑定观察版本，区分相关性与已验证因果，低样本明确为数据不足。

## 第一版端到端验收

用一个隔离测试项目建立定位和两个候选定价→显式选当前版本→建立一个渠道、一个实验和两条行动→复制文案并手工登记发布结果→导入一批指标→再次导入验证幂等→生成并采纳复盘草稿→复制新实验。重载和跨会话读取后结果一致，旧定价和复盘依据仍可追溯。

另用第二个同名项目验证隔离；以未知/零、错误CSV、并发编辑、数据不足和损坏文件验证反馈。第一版不依赖外部平台账号即可完成闭环。依赖条目完成不等于本条通过，集成验收必须实际执行。

## 暂不纳入

自动对外发布、自动发私信或邮件、广告投放及扣费、线上价格自动变更、全平台抓取、CRM、跨设备身份去重、自动多触点归因、常驻自主营销代理、自动定时同步。后续按真实渠道与使用频率单独立项。

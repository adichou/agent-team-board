状态：**两轮 AB/BA 正式主测已完成，四组均为 10/10 通过**。模型为 `gpt-5.6-luna`、推理强度 `high`；免费完整额度重置没有使用。

本次按 [A/B 测试方案](../../codex-ab-test-plan.md) 执行两轮 AB/BA：R1-A → R1-B → R2-B → R2-A。每组包含相同的 10 条合成需求并串行执行。A 由 Codex 主调度会话为每项创建一个 `fork_context=false` 子 Agent；受单个父会话累计 6 个子 Agent 上限影响，每批实际按 6＋4 使用两个主调度会话。B 由普通程序为每项启动一个全新的 `codex exec`。所有主调度和 worker 固定为 `gpt-5.6-luna`、`high`、default service tier。

## 已完成的预检

- 四个工作区共 40 个基线检查全部按预期失败，没有提前存在的实现。
- 一份隔离参考实现已通过全部 10 个固定检查，验证了测试夹具可完成。
- 四个工作区的文件哈希一致，持久化需求文档与执行输入逐字节一致。
- A、B 使用同一 CLI 0.153.4、Luna/high、代理、worker 提示词、任务顺序和验收命令。
- 执行器按组保存 JSONL 事件、进程信息、最终消息、回执和独立检查结果；任一任务失败后停止新派发。
- 没有创建、接受、认领或上报生产看板需求，也没有修改任何生产 `status.json`。

第一次 R1-A 启动在派发前发现 CLI 的 `spawn_agent` 使用 `fork_context` 参数，而不是桌面协作工具的 `fork_turns`，因此按能力边界停止；工作区没有变化。该次 39,288 Token 记为配置预检并排除。正式 A 组统一使用 `fork_context=false`，其语义仍为不复制主调度历史。

R1-A 在 M01～M06 全部通过后，创建 M07 子 Agent 时返回 `agent thread limit reached`。当前入口没有关闭已完成子 Agent 并释放父会话名额的工具，因此单个主调度会话不能完成 10 个“每项新子 Agent”。为完成主测，A 组固定按 6＋4 分为两个主调度会话；R1 的失败派发计入结果，R2 预先采用相同分段。该轮换是实测发现的协议偏差，也是 A 方案的稳定性与人工介入结果。

## 模型预检与额度停止条件

正式主测改用 Luna/high。最小 CLI 预检成功返回 `MODEL_OK`，共使用 15,518 Token；该调用排除在主测结果之外。[OpenAI 模型说明](https://developers.openai.com/api/docs/models)将 Luna 定位为成本敏感的高吞吐模型，适合本次 40 次批量执行。此前 Terra/high 的 17,083 Token 可用性预检同样排除。

Astra/xhigh 试跑的两任务配对总量为 1,018,431 Token；按任务数线性折算为 10,184,310 Token，加入 30% 余量为 13,239,603 Token。由于主测已更换模型和推理强度，这些数值只作为历史容量参考，不能预测 Luna/high 的实际用量。

准备时 5 小时窗口已使用 23%，周窗口已使用 71%。账户有一次完整额度重置，本次不使用。执行器遇到认证、额度、模型变化或隔离异常时停止新派发并保留失败成本。

## 结论

在本次 Luna/high、10 项串行批次中，**长期无人值守应优先采用 B：普通后台程序＋每项独立 `codex exec`**。两组质量相同，但 A 两轮 Token 分别多 61.90% 和 71.76%，合并多 66.89%。A 的活动执行时间只多 2.81%，因此差异主要是模型调度成本，不是做了更多业务工作。

A 的 worker 合计只比 B 多 4.65%；A 的 3,246,576 个主调度 Token 占 A 总量 37.30%，解释了 A/B 总差额的 93.05%。将队列、状态与短回执留在普通程序中，可以直接消除这部分模型上下文和 Token。

A 仍适合需要在 Codex 桌面中观察父子会话的小批量实施。当前 CLI 0.153.4 的父会话最多累计创建 6 个子 Agent，已完成的子 Agent 也占名额，而且没有可用的释放工具。因此超过 6 项时必须由外部监督器自动轮换主调度会话；否则无法无人值守完成整批。

## 数据有效性与适用范围

- 计入 4 个 A 主调度、20 个 A 子 Agent 和 20 个 B 根 worker，共 44 个会话；父子会话分别计量，没有把父、子累计重复相加。

- 四个工作区来自相同哈希基线，最终重新运行的 40 个冻结检查全部通过；生产看板和 `status.json` 没有变化。
- 这是两批合成 Node.js 任务的工程测试，只能支持 Luna/high、CLI 0.153.4、每批 10 项、并发 1 的结论。两轮不是统计显著性证明，也不能直接外推到其他模型、真实大型仓库或 100 项批次。
- B 使用的是最小普通程序调度器，不含完整 ATB 状态机的数据库、租约和恢复开销；这些程序开销不会产生模型 Token，但会增加少量 CPU、I/O 和工程复杂度。

# REQ-20260906-025 批次排队：执行中可继续创建新批次，结束后自动接续下一批

- 状态：submitted（待人工接受）
- 创建：2026-09-06T15:44:48.472Z

## 描述

## 背景与目标

当前 atb batch create 对未结束批次幂等：项目里已有执行中/未结束批次时再次创建只会返回原批次（created=false），不能在当前批次执行期间为后续新接受的条目准备下一批。期望：批次执行中可继续创建新批次，新批次以队列形式排到当前批次之后，在当前批次的调度会话中入队，当前批次结束后由同一会话自动开始下一批，无需人工新开会话、重新发送提示词。

## 期望行为

1. 有未结束批次（running/prepared/paused/待启动）时仍可创建新批次：新批次冻结当时的候选快照，状态为「排队中」，按创建时间 FIFO 排在现有批次之后；同一时间仍只有一个批次在执行，项目实施互斥不变。
2. 新批次在当前批次的调度会话中入队，不需要新开会话：当前批次收尾（batch check 返回 stop）且队列中还有排队批次时，核对响应携带下一批次标识与接续指令，主调度提示词模板支持自动接续，同一会话直接开始执行下一批。
3. batch next / batch check / batch summary 不带 --batch 时解析到「最早未结束批次」（队首）而非最新创建的批次，避免排队批次抢先被领取。
4. 看板「批量实施」抽屉展示队列：当前执行批次置顶显示「执行中」，其后依次列出排队批次（批次号、条目数、排队序号/创建时间、状态「排队中」）；队列变化随现有 2 秒轮询刷新。
5. 批次执行中点「创建批次并复制提示词」不再提示「已有未结束批次（幂等返回，未新建）」，改为创建并入队，提示「已加入队列，排第 N 位，当前批次结束后自动开始」；当前无执行中批次时行为不变（立即成为队首并复制提示词）。
6. 排队批次可查看其提示词与清单；排队批次的暂停、移出队列等管理操作范围在设计阶段细化，至少不破坏现有暂停/恢复语义。

## 界面与状态反馈

- 批次展示新增「排队中」语义（账本可沿用 prepared 表示排队；执行中/待启动/暂停/待核对/已结束语义不变）。
- 当前批次结束、下一批自动开始时，抽屉内当前条目/计数切换到新批次，无需人工刷新。
- 主调度核对响应保持 ≤2KiB：批次收尾时给 nextAction 与下一批次标识，不携带完整队列清单。

## 约束

- 不改变条目状态机与人工验收边界；不改变「每项目同一时间仅一个实施任务」互斥。
- 无排队批次时，现有创建、check、续接、暂停/恢复行为全部不回归。
- 兼容既有账本：已存在的 batch.json 无需迁移即可被队列识别（队列序即创建时间序）。

## 验收要点

- 批次 A 执行中创建批次 B：A 正常收尾后，同一调度会话不重开即自动开始 B；B 的条目在 A 结束前不被领取。
- B 创建后 A 的 batch check（--batch A）响应与看板展示不受影响。
- 看板抽屉显示 A「执行中」+ B「排队中（第 1 位）」；A 结束后 B 转为待启动/执行中。
- 现有 batch-cli / batch-core / batch-serve / batch-ui 测试全部通过，无排队场景无回归。

# REQ-20260910-002 任务模块中的提示词要新增打开 zcode 工作区和打开 codex 工作区

- 状态：accepted（已接受；本轮仅完善说明，未实施开发）
- 创建：2026-09-09T16:11:37.383Z

## 描述

### 口径解读（「提示词」指什么）

标题中的「提示词」指任务模块（看板「任务」页签）两个子面板的**「提示词」二级页签区域**，不是提示词文本本身：

- 同期 Bug **BUG-20260910-001** 排查清单第 5 条已明确把「`zcode://workspace/open` 深链与『打开 Zcode 工作区』按钮」归为**工作区入口功能**，其增删「属另一条目（候选中『任务模块中的提示词要新增打开 zcode 工作区和打开 codex 工作区』）」——即本条；
- 提示词文本自 REQ-20260909-011 起已通用化（执行端无关、可在任意一种 Agent 会话粘贴执行），在**文本里**新增「打开某端工作区」指令没有意义——打开工作区是粘贴提示词**之前**的用户动作，不发生在会话内。

因此本需求口径：在任务模块「提示词」页签提供成对的「打开 Zcode 工作区」「打开 Codex 工作区」快捷入口按钮，**批量完善与批量开发两个子面板都要有**，让用户复制主调度提示词后一键打开/聚焦对应 Agent 的本项目工作区，再手动新建会话粘贴发送。

### 背景 / 现状（基于代码静态核查，2026-09-10）

任务模块结构（`scripts/web/app.js` `renderBatchDrawer()` 约 3288–3307 行）：

- 一级页签仅两个子面板：**批量完善 / 批量开发**（Codex 后台自动派发面板入口已隐藏，渲染分支保留给存量执行记录深链）；
- 两个子面板运行态（有批次时）均有二级页签：概况 / 队列 / **提示词** / 记录（`TASK_PANES` 约 4018 行 + `taskPaneShell()`，页签记忆互相独立，REQ-20260909-008）；
- 无批次时面板为**启动区**（候选统计 + 开发人员输入 + 「启动」＝创建任务并复制提示词），没有二级页签，也就没有提示词页签。

「提示词」页签现状：

1. **批量开发**（`renderZcodeBatchPanel()` prompt 分区，约 4151–4162 行）：说明行「主调度提示词（在本项目的 Agent 会话粘贴发送，提示词通用）：」+「重新复制」（`#batchRecopy`）+「复制续接提示词」（`#batchResumeCopy`）+ `<pre id="batchPrompt">` 全文；下方工具行已有**「打开 Zcode 工作区」**按钮（`#batchOpenZcode`，title：「打开/聚焦本项目 Zcode 工作区；需手动新建会话并粘贴，深链不会自动新建或发送」）。点击行为（`bindBatchDrawer()` 约 4415–4418 行）：`state.project` 非空时 `location.href = zcode://workspace/open?path=<encodeURIComponent(state.project)>`，为空时静默无反应。深链构造纯函数 `buildZcodeWorkspaceUrl()` 在 `scripts/lib/dispatch.mjs`（官方 workspace/open 路由，Finder「在 ZCode 中打开」同款，无会话创建/命名参数；前端现为内联构造，未复用该函数）。
2. **批量完善**（`renderRefinePanel()` prompt 分区，约 4277–4285 行）：只有说明行 +「重新复制」（`#refineRecopy`）+ `<pre id="refinePrompt">`，**没有任何打开工作区入口**；存量批次缺 `prompt` 字段时该页签显示空态说明「暂无调度提示词（存量批次可能缺失）」。

差距：提示词已通用（任意 Agent 会话可粘贴执行），但工作区快捷入口只有 Zcode 一端、且只在批量开发一侧——批量完善用户与 Codex 用户都只能自己找到并打开对应工作区。

Codex 侧「打开工作区」可依赖的事实（供 design 选型）：

- ChatGPT.app 注册了 `codex://` scheme；项目内实机调研（REQ-20260903-003，2026-09-03）只验证过 `codex://threads/new?prompt=<文本>`（未文档化深链），**没有**验证过与 `zcode://workspace/open` 对应的「打开/聚焦工作区」路由——是否存在：待确认；
- codex CLI 随 ChatGPT.app 内置（`/Applications/ChatGPT.app/Contents/Resources/codex`，与桌面版共用 `~/.codex`），支持 `-C/--cd <dir>` 精确指定工作根目录（REQ-20260903-003 实测）；看板已有 CLI 探测与显式配置（`scripts/lib/scheduler.mjs` `detectCli`，设置页「CLI 路径」可覆盖，`scripts/lib/codex-preflight.mjs` 负责环境核验）；
- 「.command 临时脚本 + `open` 拉终端 + codex:// 深链降级」链路已随 REQ-20260906-019 移除（`scripts/lib/dispatch.mjs` 头注释），现役 codex 执行路径为调度器后台 `codex exec`（无人值守）——那是「自动执行」形态，与本条「打开工作区给用户手动粘贴」是两种不同用途。

### 目标

1. **批量开发「提示词」页签**：在既有「打开 Zcode 工作区」旁并列新增**「打开 Codex 工作区」**按钮（「重新复制 / 复制续接提示词」与 Zcode 按钮既有行为保持不变）。
2. **批量完善「提示词」页签**：新增**「打开 Zcode 工作区」与「打开 Codex 工作区」**两个按钮（与「重新复制」并存，布局与开发侧同款）。
3. 两按钮行为口径与既有 Zcode 按钮一致：**打开/聚焦当前看板项目（`state.project` = 项目根）在对应 Agent 中的工作区；只负责打开，不自动新建会话、不注入/发送提示词**（提示词仍由用户复制后手动粘贴，按钮 title 说明沿用现状句式）。
4. Zcode 通道沿用 `zcode://workspace/open?path=<encodeURIComponent(项目根)>` 深链；**Codex 通道的具体机制由开发阶段 design.md 定夺**（候选与约束见上节），机制不可用（ChatGPT.app 缺位 / CLI 探测失败 / 深链路由不存在等）时如实反馈或降级，不得静默无反应、不得抛未捕获错误。

### 边界（明确不做）

- 不改两个主调度提示词生成函数（`generatePrompt()` / `buildRefinePrompt()`）产出的文本，不改批次账本结构、`atb` CLI 参数与「重新复制 / 复制续接提示词」行为（提示词**文本**残留 zcode 字样问题归 BUG-20260910-001，与本条正交）。
- 不做「一键派发 / 自动执行提示词」：Zcode 深链无会话创建/注入参数（官方能力边界）；Codex 自动执行现役形态是任务模块调度器后台 `codex exec`（REQ-20260906-019），与手动粘贴的主调度模式互不影响——本条只补「打开工作区」这一步的快捷入口。
- 不改任务模块一级页签、二级页签结构与页签记忆逻辑；不新增调度/执行能力（Codex 通道若需服务端配合，仅限「打开/聚焦工作区」所需的最小端点，由 design 论证）。
- 批量完善 / 批量开发**启动区**（无批次状态）不加工作区入口（默认口径，是否加见「待确认」）。

### 实现方向（供 design 参考，不预设结论）

- 前端落点集中在 `scripts/web/app.js`：两个 prompt 分区模板 + `bindBatchDrawer()` 绑定；两面板可抽共用工具行渲染与绑定避免双份拷贝；Zcode URL 可复用 `scripts/lib/dispatch.mjs` `buildZcodeWorkspaceUrl()`。
- Codex 通道候选（择一或组合，design 定夺并实机验证）：A. `codex://` 工作区类深链（若实机验证存在）；B. 服务端最小端点用内置 CLI 以项目根为工作目录拉起终端会话（参考已移除的 REQ-20260903-003 链路，须说明恢复理由与 REQ-20260906-019 移除决策的关系）；C. 仅打开 ChatGPT.app 不绑定项目（能力最弱，如实标注局限）。
- `state.project` 为空（未选项目）时的形态（禁用 + 提示 vs 维持现状静默不响应）与存量批次缺 `prompt` 空态下按钮的显隐，由 design 定夺。

## 界面展示

本条只改任务模块「提示词」页签内的工作区入口按钮区，不改任务模块整体结构。**可交互演示：[./ui-demo.html](./ui-demo.html)**（单文件、无外网依赖、无构建，浏览器直接打开；提供「现状 / 期望」形态对照、批量完善与批量开发两面板切换、正常（含待启动批次）/ 空（无批次启动区）/ 加载 / 失败 / 未选项目状态切换、Zcode 深链实时构造预览、Codex 通道三候选模拟、深浅色切换与操作日志）。

### 界面布局

- 演示还原看板任务模块骨架：顶栏（标题 + 项目根）→ 模块导航（讨论 / 需求 / **任务** / 文件 / 设置，任务高亮）→ 任务面板一级页签（**批量完善 / 批量开发**）→（运行态）二级页签（概况 / 队列 / **提示词** / 记录）。
- 「提示词」页签自上而下：说明行「主调度提示词（在本项目的 Agent 会话粘贴发送，提示词通用）：」+「重新复制」（批量开发另有「复制续接提示词」）；提示词全文 `<pre>`（虚线边框、等宽、限高滚动）；**底部工具行**：期望形态为「打开 Zcode 工作区」「打开 Codex 工作区」两按钮并列，批量完善与批量开发同款；现状形态仅批量开发有 Zcode 一个按钮、批量完善没有（对照组）。
- 演示侧栏为控制区（形态对照 / 状态切换 / Codex 通道选型 / 深链预览 / 日志），非看板真实界面。

### 交互行为

- 点击「打开 Zcode 工作区」：以当前项目根构造 `zcode://workspace/open?path=<encodeURIComponent(项目根)>` 触发深链，打开/聚焦 Zcode 中本项目工作区；需用户在打开的工作区**手动新建会话并粘贴**提示词（深链不自动新建或发送，title 说明沿用现状句式）。演示中不真实跳转，把构造出的完整 URL 记入日志。
- 点击「打开 Codex 工作区」：按选定通道打开/聚焦本项目 Codex 工作区（机制待 design 定夺：`codex://` 深链（待实机验证）/ 内置 CLI 以项目根为工作目录拉起 / 其他）；同样只打开不发送。演示提供三通道模拟切换与日志反馈，「机制待定」通道点击时如实提示待确认。
- 「重新复制 / 复制续接提示词」行为不变（剪贴板写入，失败 toast 引导手动复制）。
- 未选项目时（演示「未选项目」态）：期望形态下两按钮禁用并给 title 说明（现状为点击静默无反应；最终口径见「待确认」）。
- 状态切换只影响面板内容呈现，不改变按钮口径；失败态提供「重试」恢复到正常态。

### 状态反馈

- **正常**：批次存在（含「待启动」）时提示词页签完整展示，两按钮可点；点击后的打开动作本身静默（现状口径，深链触发无打扰式弹窗），引导靠按钮 title 与后续手动粘贴流程。
- **空（无批次）**：面板为启动区（候选统计 + 开发人员输入 + 「启动」），无提示词页签与工作区按钮；点「启动」创建任务并复制提示词后进入运行态（演示可从空态一键切回正常态模拟该过程）。
- **加载**：面板显示「加载中…」占位，按钮区不渲染。
- **失败**：接口异常 toast 报错 + 页签区错误说明与「重试」，按钮不可用（无数据可依），恢复后回到正常态。
- **空态提示词（存量批次缺 prompt）**：显示「暂无调度提示词（存量批次可能缺失）」；工作区按钮是否仍展示由 design 定夺（演示按「随提示词一起隐藏」呈现）。
- **未选项目 / 通道不可用**：按钮禁用或点击如实提示；Codex 通道不可用时不静默无反应、不抛未捕获错误。

## 验收标准

- [ ] 批量开发「提示词」页签工具行并列展示「打开 Zcode 工作区」「打开 Codex 工作区」两按钮；「重新复制 / 复制续接提示词」与 Zcode 按钮既有行为零回归（点击仍以项目根构造 `zcode://workspace/open?path=<encodeURIComponent(项目根)>` 并打开/聚焦本项目 Zcode 工作区）。
- [ ] 批量完善「提示词」页签新增同款两按钮（与「重新复制」并存，布局与批量开发一致）。
- [ ] 点击「打开 Codex 工作区」按 design.md 定夺并实机验证的机制打开/聚焦本项目 Codex 工作区；design.md 对机制有明确结论（深链验证结果 / CLI 端点方案 / 放弃理由），测试用例覆盖其构造逻辑（URL 编码、路径注入转义）。
- [ ] 通道机制不可用（ChatGPT.app 缺位 / CLI 探测失败 / 深链路由不存在等）时如实反馈或降级（禁用 + 说明 / toast），无静默无反应、无未捕获错误。
- [ ] 两按钮只打开/聚焦工作区，不自动新建会话、不发送提示词；title 说明与现状「需手动新建会话并粘贴」口径一致。
- [ ] 提示词文本、批次账本（batch.json）、`atb` CLI 参数与 `/api/batch/*`、`/api/refine/*` 既有响应结构零变化（本条只增 UI 入口及 Codex 打开通道所需的最小服务端配合，若设计引入端点须在 design.md 单独论证）。
- [ ] 未选项目（`state.project` 为空）与存量批次缺 `prompt` 空态下的按钮形态按「待确认」结论验收，不出现可点但无效果的入口。
- [ ] 浏览器直连与 Electron app（`npm run app`）两场景按钮可用性一致（深链 / 端点在 app 内置页面场景经实测验证）；`node scripts/tests/run-all.mjs` 全部通过，新增测试覆盖两面板按钮存在性与打开通道构造。

## 待确认

- **Codex「打开工作区」机制（核心待确认项）**：ChatGPT.app 是否存在 workspace/open 类 `codex://` 深链需实机验证；若走 CLI 终端方案，恢复已随 REQ-20260906-019 移除的「服务端生成脚本拉终端」链路是否合适，由 design 定夺。
- 未选项目时按钮形态：禁用 + title 说明，或维持现状「点击静默不响应」。
- 启动区（无批次状态）与「启动」成功 toast 是否也提供工作区入口 / 引导文案（默认不加，仅提示词页签）。
- 存量批次缺 `prompt` 的空态提示词页签中，工作区按钮是否仍展示（默认随提示词一起隐藏）。

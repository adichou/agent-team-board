# REQ-20260914-001 自动提交不完整时挂起条目并暂停队列，人工确认后恢复开发

- 状态：submitted（待人工接受）
- 创建：2026-09-14T07:40:13.313Z

## 描述

本需求覆盖 AI 分析与 AI 开发两个阶段的人工确认流程：任一阶段遇到必须由人工决定的问题，挂起当前条目并持久化暂停所在任务队列，后续条目不得继续执行。看板提供统一的人工确认入口，按分析决策或提交核验展示对应内容；人工确认且核验通过后，先恢复当前条目的未完成步骤，再继续后续条目。

自动提交出现归属不明、待人工提交、部分提交或提交失败时，挂起当前条目并持久化暂停整个开发队列，禁止领取、认领或派发后续条目。文档提交或部分文件提交成功不得视为开发完成；人工核对差异、确认归属并完成全部必要代码和测试提交，系统重新验证提交完整性及测试结果后，才允许继续当前条目收尾并恢复队列。沿用当前工作目录，不采用 worktree。看板待人工确认区和条目详情提供挂起原因、已提交/未提交文件及差异、相关提交、依赖与测试结果；提供查看差异、重新核验、确认并继续、保持挂起操作，验证失败保留挂起并明确原因。人工确认只解除提交阻塞，不代替需求验收确认完成。

AI 分析中遇到需求歧义、方案选择、信息缺失或其他必须人工确认的事项时，记录具体问题、背景、备选方案及影响，进入「挂起：待人工确认分析」。不得用 AI 自行选择、文档已生成或部分分析完成代替人工确认，也不得将条目标为分析完成。人工在界面逐项选择或填写答案，确认后由 AI 依据答案继续分析；仍有未解决问题则保持挂起。分析确认只解除对应分析阻塞，不等于接受需求、批准开发或验收完成。

## 验收标准

- [ ] 自动提交存在归属不明、pendingManual、heldGroups、部分失败或必需文件遗漏时，当前条目进入明确的「挂起：待人工确认提交」状态，不进入开发完成/待测试成功态。
- [ ] 挂起与队列暂停持久化；后续 batch next、claim、自动派发和 /dev loop 均受到服务端统一守卫，刷新、重启和新会话不能绕过。
- [ ] 暂停时不释放为可被后续任务占用的开发执行权；已预留但未开始的后续条目不能启动。当前条目的核验、补交与恢复仍可执行，避免死锁。
- [ ] 文档提交、单个分组提交或发现任意带单号 commit 均不足以判定完成；需核验本单必要实现、测试、文档完整入库，无未解决归属/暂扣项，且测试验证的是提交后的完整内容。
- [ ] 纯文档任务按其明确的文件范围核验，不要求凭空存在实现或测试；无改动任务必须记录可验证原因，不能以跳过提交冒充成功。
- [ ] 看板持续显示挂起原因、已提交与待提交文件、差异、依赖、提交 hash 和验证结果；部分成功显示「部分提交，开发未完成」，不显示普通成功徽标。
- [ ] 人工「确认并继续」携带当前差异版本/指纹；服务端重新核验，文件变化、提交遗漏、测试失败或无效/过期确认均保持挂起并解释原因。
- [ ] 人工确认归属后，由明确授权的恢复流程补交必要文件并执行验证；如果人工已在终端补交，重新核验可识别。不能要求普通用户自行猜测 Git 命令。
- [ ] 仅全部核验通过后收尾当前条目、解除本次队列暂停并从下一条继续；重复确认幂等，不重复提交、不重复派发。
- [ ] 「保持挂起」保留现场和队列；人工取消本次队列须显式操作，不得隐式跳过阻塞条目继续。
- [ ] 人工确认提交不等于人工验收 done；条目最终验收仍由现有「确认完成」流程处理。
- [ ] 不引入 worktree、额外分支合并或后台自动分割归属不明的修改；复用现有人工挂起基础设施，避免两套互不相通的阻塞状态。

- [ ] AI 分析发现必须人工确认的问题时，挂起当前条目并暂停所在分析队列，所有领取/派发分析任务的入口均受守卫，后续条目不能绕过继续执行。
- [ ] 分析确认界面列出问题背景、必须确认的事项、可选方案及影响；支持选择和自由文本回答，必答项未完成时禁止「确认并继续」。推荐选项不自动视为人工答案。
- [ ] 支持多项问题、保存草稿与保持挂起；刷新/重启后恢复问题、答案草稿及队列暂停状态，不要求到聊天窗口或终端才能完成确认。
- [ ] 分析确认绑定当前问题与文档版本，记录人工答案及确认时间；问题已变或确认过期时保留挂起并提示重新核对。保存草稿不解除阻塞。
- [ ] 确认成功后把人工答案交回当前分析任务继续未完成步骤；再次发现待确认问题时重新挂起，只有当前条目分析完整完成且无未决问题后才处理下一条。
- [ ] 分析恢复失败时保留已确认答案、显示失败原因并允许重试；重复确认不重复启动，不自动接受需求、启动开发或标记验收完成。

## 界面与交互

在任务页顶部现有「待人工确认」区域置顶显示阻塞卡片，明确标注「AI 分析 / AI 开发」及阻塞类型，条目详情提供同源入口，队列区域显示暂停条目与原因。卡片显示单号/标题、挂起原因、已提交和待提交数量；展开后按文件展示归属、差异入口、已有提交和测试结果。确认面板列出本次将补交的具体文件与关联条目，人工核对后点击「确认并继续」。若归属仍不清晰，可填写处理说明并保持挂起。

- 检查中：按钮禁用，显示「正在核验提交与测试…」。
- 校验失败：保持暂停，逐项列出未提交文件、变化的指纹或失败测试，提供重试入口。
- 恢复成功：显示补交 hash 和核验结果，队列继续；不自动标记人工验收完成。
- 页面刷新/服务重启后：从持久化记录恢复同一卡片与暂停状态。

AI 分析的卡片显示单号、标题、待确认问题数量、挂起原因和后续等待条目数，提供「查看并确认」入口。打开确认面板后，上方展示当前分析背景与相关文档，中间逐项列出问题、方案及影响，并提供选项或文本输入；底部提供「保存草稿」「保持挂起」「确认并继续」。必答项就地校验，提交期间禁用重复操作。确认成功显示「已确认，正在继续当前条目分析」，待当前分析完成后才恢复下一条；失败保留答案并提供重试。该面板与提交确认复用统一入口，但不向分析决策展示无关的 Git 文件或测试核验字段。

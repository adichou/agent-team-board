# REQ-20260909-008 任务界面采用多页签布局优化

- 状态：accepted（已接受；实际状态以 status.json 为准）
- 创建：2026-09-09T04:26:20.936Z

## 描述

任务模块（主导航「任务」，`scripts/web/index.html` 的 `#runsView` → `#batchDrawer`）目前是「一级页签 + 单页长滚动」结构：头部下方已有「批量完善 / 批量开发」两个一级页签（REQ-20260908-020 收敛口径），但每个页签下的内容——运行状态行、通知条、当前条目信息、计数、待处理队列、排队批次、主调度提示词、操作按钮、本轮处理记录——全部纵向堆叠在一页里，运行中批次的信息密度高，用户要滚动很长距离才能在「看进度」和「取提示词 / 看记录」之间切换。

本需求两点：

1. **完善和开发是两个独立页签**：批量完善与批量开发保持为两个相互独立的一级页签（现状已有，明确为基线口径，不合并、不回退）；两个页签各自的数据拉取路径（`/api/refine/current` + `/api/refine/candidates` 与 `/api/batch/current`）、状态与交互互不串扰。
2. **每个页签下的内容也采用页签布局**：一级页签（批量完善 / 批量开发）内部再引入一层二级页签，把现在纵向堆叠的内容块按职责归组分区呈现，单屏内切换查看，不再长滚动。

### 现状依据（基于当前代码）

- 任务视图骨架：`scripts/web/index.html` `#runsView`（约 130 行）内仅一个 `#batchDrawer` 容器，内容由 `scripts/web/app.js` 动态渲染。
- 一级页签现状：`renderBatchDrawer`（`scripts/web/app.js` 约 2756 行）——头部（项目路径 `state.project` + 「返回需求模块」`#batchClose`）+ `.tabs.batch-modes` 页签行（`data-bmode="refine" | "develop"`），`state.batch.mode` 记忆当前页签。
- 批量完善页签内容（`renderRefinePanel`，约 3625 行）：
  - 无任务：启动区（说明文案 + 候选统计 + 执行 Agent 选择 `#refineMode` + 开发人员 `#refineDev` + 「启动」`#refineCreate`）+ 待完善队列（`pendingQueueHtml`，最近 2 条 / 全量计数）。
  - 有任务：状态行（状态 chip + `batchId` + 执行 Agent / 创建时间 / 开发人员）+ notice 通知条（终止 / 暂停 / 完毕等）+ `meta-grid`（当前条目 / 子代理会话 / 开始时间 / 耗时 / 最近回执 / 最后活动）+ 计数行 `taskStatsLine`（已处理 / 异常 / 处理中 / 待处理 / 共 N）+ 待完善队列 + 主调度提示词块（`#refinePrompt` + 「重新复制」）+ 操作（暂停后续领取 / 终止任务 / 启动新一轮）+ 本轮处理记录 `runAttemptsHtml`（四列表格，最近 2 次，含「重新执行」）。
- 批量开发页签内容（`renderZcodeBatchPanel`，约 3488 行；启动区 `renderDevStartBar` 约 2631 行）：同上结构，另有排队批次列表（`data.queue`，REQ-20260906-025）、提示词块的「复制续接提示词 / 打开 Zcode 工作区」、操作区的「排队新批次 / 删除本批次」。
- 共用渲染件：`taskStatsLine`（约 2484 行）、`pendingQueueHtml`（约 2502 行）、`runAttemptsHtml`（约 2531 行）。
- 轮询与重渲染：`refreshBatch`（约 2685 行）/ `refreshRefine`（约 3602 行）每 2 秒拉取，签名（sig）无变化不重渲染，避免打断输入 / 点击——页签化后**当前二级页签选择必须跨重渲染保持**。
- 页签式布局既有先例：详情抽屉五页签（REQ-20260909-006，`renderDrawer` 约 2131 行；`.tabs.drawer-tabs` / `.drawer-pane` 样式见 `scripts/web/style.css` 约 513 行），`role="tablist" / "tab" / "tabpanel"` + `aria-selected`，页签状态入 `state.drawer.tab`，轮询重渲染不重置当前页签。
- 相关既有需求：REQ-20260907-004（任务模块页面化）、REQ-20260908-020（子面板收敛为批量完善 / 批量开发）、REQ-20260908-026（任务面板共用渲染与最近记录口径）、REQ-20260909-006（详情抽屉页签式布局）、REQ-20260909-007（档位快捷入口跳转任务模块）。

### 目标口径

1. **只改布局，不改流程**：纯前端改动（`scripts/web/app.js` 为主，样式入 `scripts/web/style.css`），不新增后端 API、不改状态机、不写任何 status.json；批量完善 / 批量开发的创建、领取、回执协议与现有全部操作（启动 / 暂停后续领取 / 终止 / 重新复制 / 复制续接提示词 / 排队新批次 / 删除本批次 / 重新执行等）全部保留，仅位置按二级页签归组。
2. **一级页签独立**：批量完善 / 批量开发仍是仅有的两个一级页签（`data-bmode` 机制不变）；存量 Codex 执行记录深链（`mode === 'codex'` 渲染分支）保持可打开，不新增一级入口。
3. **二级页签纯前端切换**：切换不触发数据重新拉取（数据仍随 2 秒轮询刷新）；当前二级页签记忆在前端状态（如 `state.batch.pane` / `state.refine.pane`），一级页签切换时两个页签各自记忆、互不重置；轮询重渲染（签名变化触发 `renderBatchDrawer` 重建 DOM）不重置当前二级页签、不打断正在进行的输入与点击。
4. **可达性**：沿用详情抽屉页签模式——原生 `<button type="button">` + `role="tablist" / "tab" / "tabpanel"` + `aria-selected`，可 Tab 聚焦、回车触发。
5. **内容块归组建议（命名与最终集合由 design.md 定稿）**：运行态二级页签建议划分为「概况（状态行 + 通知条 + meta-grid + 计数行 + 操作按钮）/ 队列（待处理队列 + 排队批次）/ 提示词（主调度提示词块）/ 记录（本轮处理记录）」四区；无任务（启动态）内容较少，建议保持启动区 + 队列单屏不拆二级页签（或仅并入同一级呈现），不强制分页。

## 界面布局

改动集中在任务模块面板（`#batchDrawer` 渲染结果），层级自上而下：

1. **面板头部**（不变）：项目路径 + 「✕ 返回需求模块」。
2. **一级页签行**（不变）：「批量完善」「批量开发」，沿用 `.tabs.batch-modes`。
3. **二级页签行**（新增）：位于一级页签之下、内容区之上，与一级页签视觉区分（如缩进、字号 / 形态差异，具体样式 design.md 定稿，可参照详情抽屉 `.drawer-tabs` 的下划线式页签）；运行态呈现「概况 / 队列 / 提示词 / 记录」四个二级页签，启动态（无进行中任务）不渲染二级页签行。
4. **内容区**：同一时刻只显示当前二级页签对应分区，其余分区隐藏（`hidden` 切换，不销毁表单草稿以外的状态）。

```
┌ 任务面板 ────────────────────────────────────────────────────┐
│ /Users/…/agent-team-board                          [✕ 返回] │
│ ┌─────────┐ ┌─────────┐                                    │
│ │批量完善● │ │批量开发  │   ← 一级页签（独立，现状保留）      │
│ └─────────┘ └─────────┘                                    │
│ ┌概况──┐ ┌队列──┐ ┌提示词─┐ ┌记录──┐                        │
│ │ ●    │ │      │ │       │ │      │   ← 新增二级页签        │
│ └──────┘ └──────┘ └───────┘ └──────┘                        │
│ ┌ 内容区（当前二级页签分区）────────────────────────────────┐ │
│ │ [执行中] BAT-… zcode · 创建 14:02 · 开发人员 张三        │ │
│ │ 当前条目 REQ-… · 子代理会话 … · 已处理 3/6              │ │
│ │ [暂停后续领取] [终止任务]                                │ │
│ └─────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────┘
```

- **窄屏**：两级页签行均 `flex-wrap: wrap` 换行（对齐 `.drawer-tabs` 现状），不产生横向滚动、不与模块搜索框重叠。
- **深浅色**：沿用现有 CSS 变量体系，不新引入配色。

## 交互行为

1. **一级页签切换**：点击「批量完善 / 批量开发」切换子面板，行为与现状一致（`state.batch.mode` 切换 + 对应数据拉取路径）；切回时恢复该页签各自记忆的二级页签。
2. **二级页签切换**：点击（或 Tab 聚焦后回车）即切换内容区分区，纯前端，不发起请求、不弹确认；切换后滚动位置随分区独立（是否记忆各分区滚动位置属实现细节，design.md 定）。
3. **轮询不打断**：2 秒轮询签名变化触发重渲染时，当前二级页签保持、正在输入的开发人员 / 选择中的执行 Agent 等草稿状态沿用现有保护机制（签名比对 + 草稿不回落），不被重置。
4. **操作按钮归组**：运行操作（暂停 / 终止 / 启动新一轮 / 排队新批次 / 删除本批次）与提示词操作（重新复制 / 复制续接 / 打开工作区）、记录操作（重新执行）分别归入对应二级页签的分区内部，行为、确认口径与现状一致，仅入口位置变化。
5. **深链兼容**：存量执行记录深链（`mode === 'codex'`）打开任务模块时按现有逻辑渲染对应面板，不因二级页签引入而失效；无法归属的分区回落「概况」页签。
6. **启动态不拆页签（建议口径）**：无进行中任务时保持现状单屏（启动区 + 队列预览），任务创建成功后随运行面板出现二级页签。

## 状态反馈

- **正常（运行中）**：一级页签角标 / 状态行即时反映批次状态（待启动 / 执行中 / 已暂停 / 已结束 / 已终止，沿用 `batchStatusLabel`）；计数行、队列、记录随 2 秒轮询自动更新；二级页签切换即时显示对应分区最新数据。
- **加载**：进入任务模块或切换一级页签后数据拉取期间，内容区显示现有「加载中…」占位（`renderRefinePanel` / `renderZcodeBatchPanel` 现状）；二级页签行在数据到达后渲染（加载期间不显示空页签）。
- **空（启动态）**：无进行中任务时不渲染二级页签行，显示启动区 + 队列空态文案（「暂无可完善候选：已接受条目均已完善（或尚无已接受条目）」「（空，等待已计划条目）」「暂无待处理条目。」均沿用现状）；有任务但某分区无内容时（如无排队批次、无执行记录），该二级页签保留并在分区内显示空态说明，不隐藏页签。
- **失败**：面板数据拉取失败沿用现有 toast 错误提示（`refreshBatch` / `refreshRefine` catch 路径）；失败不改变两级页签选择，恢复后随下一轮轮询自动刷新；操作失败（如终止 / 复制失败）toast 反馈与现状一致。
- **收尾/终态**：批次结束或终止后仍保留全部二级页签可回看（记录 / 提示词），操作区按现有终态口径（不显示暂停 / 终止，显示启动新一轮）呈现。

## 验收标准

- [ ] 批量完善与批量开发保持两个独立一级页签：切换行为、数据口径（完善 = 已接受未完善候选，开发 = 已计划队列）与现状一致，互不串扰。
- [ ] 两个一级页签下的内容均采用二级页签布局：运行态内容按「概况 / 队列 / 提示词 / 记录」（或 design.md 定稿的等价归组）分区呈现，同一时刻仅显示一个分区，不再单页长滚动堆叠。
- [ ] 二级页签纯前端切换：不发起数据请求、不弹确认；批量完善与批量开发的二级页签选择相互独立记忆，一级页签来回切换不重置。
- [ ] 2 秒轮询重渲染不重置当前二级页签、不打断输入 / 点击（沿用签名比对与草稿保护机制）；状态、计数、队列、记录数据随轮询在各分区内自动更新。
- [ ] 现有功能零回退：启动（含执行 Agent 显式选择与禁用口径）、暂停后续领取、终止任务、启动新一轮、重新复制、复制续接提示词、打开 Zcode 工作区、排队新批次、删除本批次 / 排队批次、重新执行、条目深链跳转（`data-goto-item`）全部可用。
- [ ] 启动态（无进行中任务）保持启动区 + 队列单屏（不拆二级页签），空态文案沿用现状。
- [ ] 页签键盘可达：原生 button、`role="tablist"/"tab"/"tabpanel"`、`aria-selected`，Tab 聚焦回车可切。
- [ ] 存量 Codex 执行记录深链仍可打开对应面板，不因页签化失效。
- [ ] 深浅色外观正常（沿用现有 CSS 变量）；窄屏（≤1020px）两级页签行换行显示、不横向滚动、不遮挡操作。
- [ ] 不新增后端 API、不改状态机与任何 status.json；改动范围限于 `scripts/web/`（app.js 为主，样式入 style.css）。

### 待确认（开发阶段 design.md 给出结论即可）

- 二级页签最终集合与命名（本 README 的「概况 / 队列 / 提示词 / 记录」为建议归组），以及操作按钮区归属（概况内还是独立常驻底栏）。
- 二级页签是否带轻量角标计数（如「队列 (6)」「记录 (2)」）。
- 执行记录分区是否放宽「最近 2 条」展示上限（REQ-20260908-026 口径），或维持 2 条 + 全量计数。
- 一级 / 二级页签的视觉层级样式（下划线式 vs 胶囊式、缩进与字号差异）。
- 是否需要键盘左右方向键在页签间移动焦点（现状详情抽屉仅 Tab + 回车）。

# REQ-20260909-012 讨论详情也要支持多页签布局

- 状态：accepted（已接受；实际状态以 status.json 为准）
- 创建：2026-09-09T08:47:35.590Z

## 描述

讨论模块（主导航「讨论」，`scripts/web/index.html` 的 `#oncallView`，前端逻辑在 `scripts/web/oncall.js`）的详情右栏（宽屏常驻 `#ocDetail` 右栏、窄屏 ≤1020px 覆盖层）目前是「头部 + 单列纵向堆叠」结构：meta-grid（讨论方式 / 讨论范围 / 成果 / 创建 / 更新）→ 旧绑定需求链接 → 阶段通知条 `#ocNotice` → 提示词浮层 `disc-prompt`（点「启动提示词 / 讨论完毕」时插入）→ 内容双页签（背景与纪要 ｜ 生成需求 / Bug）→ `#ocPane`。纪要较长、候选草稿多、或带旧版历史问答时，通知条与提示词浮层把正文一路下推，用户要在「看概况 / 取提示词」和「读纪要 / 编草稿」之间长距离滚动。

任务模块已在 REQ-20260909-008 完成同类改造（运行态二级页签：概况 / 队列 / 提示词 / 记录，`scripts/web/app.js` 的 `TASK_PANES` / `taskPaneShell` / `activateTaskPane`，约 3713–3758 行），需求 / Bug 单详情抽屉也已在 REQ-20260909-006 改为五页签（`.drawer-tabs`）。本需求把讨论详情对齐为同样的多页签布局：**把详情抽屉内纵向堆叠的内容块按职责归组到页签分区，单屏内切换查看，不再长滚动**。

本需求两点：

1. **详情内容页签化**：讨论详情 `drawer-body` 内的各内容块（meta-grid 概况、阶段通知、背景与纪要、候选草稿与已创建成果、启动 / 收尾提示词、旧版历史问答）归组到一行页签下分区呈现，同一时刻只显示当前页签对应分区。
2. **只重组布局，不改流程**：纯前端改动（`scripts/web/oncall.js` 为主，样式入 `scripts/web/style.css`），不新增后端 API、不改讨论两态状态机（讨论中 / 已归档，REQ-20260909-004 口径）、不写任何 status.json；创建 / 收尾 / 归档 / 重新读取 / 批量创建草稿等全部操作语义保留，仅入口位置按页签归组。

- 页签记忆与防打断：`refreshDetail` 的重渲染签名 `detailSig` 已包含 `state.tab`（约 265 行），2 秒轮询重渲染不重置页签；草稿编辑中 `detailEditing()` 跳过详情重绘、失焦后 `pendingRefresh` 补绘（约 248–251、511–532 行）。
- 打开 / 切换记录：`openItem()`（约 215 行）切换讨论时重置 `state.tab = 'minutes'`；`doFinish()` 成功后跳 `minutes` 并展示收尾提示词浮层；`doCreate()` 完成后跳 `drafts` 展示逐项结果；`reveal()`（统一新建定位）直接展示启动提示词；`closeDetail()` 关闭详情。

- 样式注意：`#ocBack` 复用 `.drawer-back` 顶层规则（BUG-20260909-007 口径，讨论侧返回是详情唯一出口），页签化改样式时不得误伤。

### 目标口径

1. **只改布局，不改流程**：不新增后端 API、不改状态机、不改各操作语义；启动提示词、讨论完毕（生成收尾提示词）、归档 / 继续讨论、重新读取纪要、候选草稿编辑 / 勾选 / 批量创建（含失败重试与防重复创建）、已创建成果跳转条目（`data-goto-item` / `data-jump-item`）、旧绑定需求跳转（`#ocGotoReq`）、历史问答只读展示、附件点击放大全部保留。
2. **页签纯前端切换**：切换不发起数据请求（数据仍随 2 秒轮询刷新）、不弹确认；当前页签在前端状态记忆（沿用 / 扩展 `state.tab`），轮询重渲染（签名变化触发 `renderDetail` 重建 DOM）不重置当前页签、不打断草稿编辑与输入。
3. **切换记录重置默认页签**：换一条讨论记录（`openItem`）时页签回落默认页签（现状回落 `minutes`），口径保持。
4. **可达性对齐**：沿用任务模块 / 需求抽屉页签模式——原生 `<button type="button">` + `role="tablist" / "tab" / "tabpanel"` + `aria-selected`（补齐现状讨论页签缺失的 `role="tab"` / `aria-selected`），可 Tab 聚焦、回车触发。
5. **内容块归组建议（命名与最终集合由 design.md 定稿）**：建议划分为「概况（meta-grid + 旧绑定需求链接 + 阶段通知条）/ 纪要（讨论背景 + 讨论纪要 + 旧版历史问答）/ 成果（已创建成果 + 候选草稿编辑与创建）/ 提示词（启动 / 收尾提示词展示与复制，由浮层迁入）」四页签；通知条是否常驻页签行之上、提示词是否保留浮层形态、历史问答是否独立页签，均见待确认。

## 界面布局

改动集中在讨论详情抽屉（`#ocDetail` 渲染结果），层级自上而下：

1. **头部**（不变）：返回列表 + 编号 + 状态 chip + 标题 + 操作按钮行（启动提示词 / 讨论完毕 / 归档讨论｜继续讨论）。
2. **页签行**（重构）：位于头部之下、内容区之上，替换现状「meta-grid → 通知条 → 浮层 → 双页签」的纵向堆叠；样式可参照 `.drawer-tabs`（下划线式）或 `.tabs` 现有胶囊式，与任务模块视觉层级一致（具体 design.md 定稿）；页签行 `flex-wrap: wrap`，窄屏换行不横向滚动。
3. **内容区**：同一时刻只显示当前页签对应分区，其余分区隐藏（`hidden` 切换）；各分区内部结构沿用现状渲染函数。

```
┌ 讨论详情（#ocDetail）────────────────────────────────────────┐
│ ← 返回列表  ASK-20260909-001  [讨论中]                      │
│ 关于批量任务提示词通用化的开放式讨论                          │
│ [启动提示词] [讨论完毕]                    [归档讨论]         │
│ ┌概况──┐ ┌纪要──┐ ┌成果(2)┐ ┌提示词─┐                        │
│ │ ●    │ │      │ │       │ │      │   ← 页签行（新增归组） │
│ └──────┘ └──────┘ └───────┘ └──────┘                        │
│ ┌ 内容区（当前页签分区）───────────────────────────────────┐ │
│ │ 讨论方式 Agent 外部会话 · 成果 1 条已生成 · 2 项草稿      │ │
│ │ [notice] 纪要已生成，有 2 项候选草稿待确认创建。          │ │
│ └─────────────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────────┘
```

- **窄屏（≤1020px）**：详情为覆盖层形态，页签行换行显示；返回列表、遮罩点击、Esc 关闭交互不变。
- **深浅色**：沿用现有 CSS 变量体系，不新引入配色。

## 交互行为

1. **页签切换**：点击（或 Tab 聚焦后回车）即切换内容分区，纯前端，不发起请求、不弹确认；当前页签写入 `state.tab` 记忆，2 秒轮询重渲染不重置、不打断草稿编辑（沿用 `detailSig` 签名 + `detailEditing` 防打断 + 失焦补绘机制）。
2. **切换讨论记录**：点击列表另一条讨论时默认页签重置（口径同现状 `openItem` 重置 `minutes`）；返回列表再进入同样重置。
3. **自动跳页签保持等价**：「讨论完毕」生成收尾提示词后定位到提示词所在分区（现状为展示浮层 + 跳 `minutes`，页签化后跳「提示词」或等价位置，具体随归组结论）；「创建勾选的条目」完成后回到草稿 / 成果分区展示逐项结果；新建讨论 `reveal()` 直接展示启动提示词——三个入口的最终可见效果与现状等价，具体落点由 design.md 定稿。
4. **提示词操作**：展示、复制（剪贴板 + execCommand 双回退，失败全选提示手动复制）、收起——若迁入页签则「收起」语义改为切回默认页签或关闭展示（design.md 定稿），复制口径与提示文案不变。
5. **草稿编辑与创建**：勾选、字段编辑（切换记录与会话内保留 `draftEdits`）、必填校验、批量创建、失败项单独重试、成功项防重复创建——全部沿用，仅位于「成果」分区内。
6. **跨模块跳转**：已创建成果跳条目详情、旧绑定需求跳需求详情、Esc / 遮罩 / 返回列表关闭详情——全部沿用。
7. **归档 / 继续讨论**：头部按钮不变；归档后各页签仍可回看（纪要与成果保留），按钮变「继续讨论」。

## 状态反馈

- **正常**：阶段提示（等待纪要 / 纪要已生成 / 有待创建草稿 / 外部会话中 / 成果已保留）与计数随 2 秒轮询在各分区自动更新；页签切换即时显示对应分区最新数据；页签可带轻量计数角标（如「成果 (2)」，是否采用见待确认）。
- **加载**：进入详情或显式重新读取时「正在读取纪要……（按约定目录检测发布标记）」在通知条 / 对应分区内展示（后台轮询不闪加载态，现状口径）；数据到达后按记忆页签渲染。
- **空**：无纪要（「尚无纪要。对话内容保留在 Agent 会话中……」）、零候选草稿（「零候选为正常空态；归档无须以生成条目为前提」）、无已创建成果、无历史问答（该区块不渲染）——空态文案沿用现状，空分区保留页签并在分区内显示空态说明，不隐藏页签。
- **失败**：纪要读取失败显示 warn 通知 + 「重新读取纪要」按钮（位置随通知条归组结论）；API 请求失败沿用 toast 错误提示；失败不改变当前页签选择，恢复后随下一轮轮询自动刷新。
- **归档终态**：阶段提示「成果已保留」，全部页签可回看，头部按钮变「继续讨论」。

### 待确认（开发阶段 design.md 给出结论即可）

- 最终页签集合与命名（本 README 的「概况 / 纪要 / 成果 / 提示词」为建议归组）；默认激活页签（建议「概况」或保持现状正文优先的「纪要」）。
- 阶段通知条（含读取中 / 读取失败 + 重新读取入口）是常驻页签行之上（全局阶段反馈）还是仅归入「概况」分区。
- 提示词是独立页签，还是保留现状头部按钮触发的浮层形态（仅浮层收进分区）；「收起」在页签形态下的语义。
- 旧版历史问答（`legacyRounds` 只读区）保留在「纪要」尾部还是独立页签；仅旧单有该区块，无历史问答时对应入口不渲染。
- 页签是否带轻量计数角标（如「成果 (2)」）与「概况」meta-grid 的字段取舍。
- 是否需要键盘左右方向键在页签间移动焦点（现状任务模块与需求抽屉仅 Tab + 回车）。

# REQ-20260910-016 排序菜单放到搜索框左侧，因为都是用于定位单号的

- 创建：2026-09-10T07:11:57.058Z
- 状态以本条目 status.json 和看板为准。

## 描述

将需求模块的排序菜单移到当前模块搜索框左侧，把按时间/单号浏览与输入关键词定位集中在同一组控件内，减少用户在页面不同区域寻找入口的成本。

### 已核实的现状与范围

- `scripts/web/index.html` 中，`#reqSort` 位于需求列表 `#reqCaption`，`#searchInput` 位于模块副标题行 `#pageHead`，两者分离。
- `scripts/web/app.js` 定义五个排序选项：最新更新、最早更新、最新创建、最早创建、单号；默认最新更新，偏好保存在 `atb.req.sort`，时间相同按单号稳定排序。
- 当前需求可见条目处理顺序为状态筛选、搜索过滤、排序、已完成档默认截断。本次位置调整保持这些规则及现有搜索范围、清除按钮和快捷键。
- 本需求明确覆盖需求模块已有排序菜单。讨论、任务、文件模块是否新增或迁移排序入口：待确认；本次不据此扩展新排序能力。

### 界面布局

宽屏模块副标题保持左侧，右侧为一个定位控件组，顺序固定为「排序菜单 → 搜索框（范围标签、输入框、清除按钮、快捷键提示）」。两者垂直居中、相邻呈现，中间不插入批量操作。原列表工具栏移除排序入口，仅保留原有选择及批量操作等控件，不留占位空洞。

窄屏副标题与定位组可分行，组内排序仍在搜索左侧；搜索可伸缩，极窄宽度允许整组内部换行但阅读与 Tab 顺序仍为排序后搜索，不能遮挡、裁切控件或产生页面横向滚动。切换到其他模块隐藏需求排序菜单；回到需求模块恢复当前排序。未初始化或无项目时不展示可操作的需求排序入口，避免产生无效操作。

### 交互行为

- 使用原有单一排序控件及五项选项，切换后即按所选规则重排当前过滤结果，显示所选文案并继续记忆偏好；不得清空搜索词或改变状态筛选。
- 输入关键词、清除、Esc 清空以及 `/` 聚焦搜索沿用现有行为；清除仅恢复当前范围列表，保留排序偏好。选择操作不因移动控件而新增副作用。
- 排序菜单有可访问名称「列表排序」，支持键盘选择；Tab 从排序进入搜索，焦点轮廓可见。搜索反馈继续位于副标题行下方，不混入定位组。

### 状态反馈

- 正常：显示当前排序与搜索范围，结果按所选规则排列。
- 空结果：保留排序及关键词，反馈无匹配结果并可清空关键词恢复；切换排序不会伪造命中。
- 加载：保留定位组和当前值，反馈搜索中；不得把加载误报为空结果。
- 失败：保留排序及关键词，显示搜索失败反馈，沿用现有恢复入口与机制；重试不重置排序。

# REQ-20260906-023 批量实施的批次最多保留 100 个，超出的删除最旧的

- 状态：in-progress（batch-20260907-003 / run-20260907-023）
- 创建：2026-09-06T14:48:45.158Z

## 描述

批量实施功能（REQ-20260906-002）在 `docs/agent-team-board/dispatch/batches/<batchId>/` 下为每个批次保存账本目录（batch.json 等）。批次随日常使用不断累积（如 2026-09-07 当天已有 3 个批次、604 个运行记录），没有任何清理机制，长期使用会让批次目录无限增长。

本需求为批次账本增加保留上限：

- **最多保留 100 个批次目录**；超出上限时，**删除最旧的批次**。
- 清理在**成功创建新批次时**自动触发（`atb batch create` 与看板「批量实施」入口共用同一创建函数）；幂等返回既有批次（未新建）时不触发。
- 「最旧」按批次 `createdAt` 排序（同毫秒时以 `batchId` 定序，batchId 含日期与全局递增序号，字符串序即创建序）。
- **存在未收尾运行（在途执行）的批次跳过不删**，避免删除正在执行的批次账本；这类批次保留，其余更旧的已收尾批次照常删除（删除数以可安全删除者为限，不强制凑数）。
- 删除范围仅限 `dispatch/batches/<batchId>/` 批次目录；`dispatch/runs/` 运行账本不在本需求范围内，不随批次删除。
- 删除操作不抛错中断创建流程：单个批次目录删除失败时跳过该批次，其余照常。

## 验收标准

- [ ] 连续创建批次使总数超过 100 后，`dispatch/batches/` 下批次目录数不超过 100，且被删的是最旧批次、保留的是最新 100 个。
- [ ] 创建第 102 个批次后：最旧的 2 个批次目录被删除，最新 100 个（含刚创建的）仍在。
- [ ] 总数未超 100 时创建批次不删除任何批次。
- [ ] 幂等创建（返回既有未结束批次）不触发清理。
- [ ] 有在途运行的旧批次不被删除（跳过保护），其余更旧已收尾批次仍被删除。
- [ ] 被删除的批次不再出现在批次列表/最新批次查询中；删除失败（目录异常）不影响批次创建成功。
- [ ] `atb batch create` 输出本次清理摘要（清理了几个最旧批次）。
- [ ] 既有 batch-core / batch-cli / dispatch 相关测试全部通过（无回归）。

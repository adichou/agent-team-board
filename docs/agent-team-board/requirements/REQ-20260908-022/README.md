# REQ-20260908-022 支持就单一需求和 Agent 进行讨论的功能

- 状态：submitted（待人工接受）
- 创建：2026-09-08T10:00:22.349Z

## 描述

### 背景与目标

看板现有三类对象分工明确：需求（REQ）面向开发实施、有严格状态机与人工验收；讨论单（Oncall / ASK，REQ-20260907-001）是**与需求完全隔离**的独立轻量问答；聊天命令（/req /bug /dev /board）面向条目管理。缺一等能力：**就某一条需求与 Agent 进行讨论**——澄清需求含义、评审 design 取舍、追问实现影响面。当前只能新建普通讨论单后把需求内容手工粘贴进问题正文，讨论记录也不在需求侧沉淀，事后无法回答「这条需求讨论过什么」。

本需求为单一需求提供绑定式讨论：讨论线程归属某个 REQ-ID，Agent 自动获得该需求的完整文档上下文，多轮问答双向可见。

### 现状与差距（基于当前代码）

- **数据完全隔离**：scripts/lib/oncall-store.mjs 文件头注释（L1-5）明确「与 requirements/bugs 完全隔离，不进 REQ/BUG 状态机、不占 impl.lock」；`createTicket`（L192-233）写出的 ticket.json 字段（id / title / status / rounds / dispatches / history）**没有任何需求关联字段**。
- **派单提示词不带需求上下文**：codex 单单提示词 `buildOncallWorkerPrompt`（L481-513）仅含单号、标题、项目根、历轮问答与截图附件路径；zcode 主调度提示词 `buildOncallPrompt`（L459-477）只传单号，子 Agent 靠 `atb oncall show <ASK-ID>` 读单。两处都不会自动带入需求条目的 README / design / test-cases。
- **Web 无需求侧入口**：需求详情抽屉（scripts/web/app.js `renderDrawer`，约 L2047-2131）有元信息、下属 Bug、批次设置与文档 tabs，没有「讨论」区块；讨论单在独立 Oncall 视图（scripts/web/oncall.js），卡片与详情抽屉均无归属需求展示，也不能按需求过滤。
- **CLI 无关联参数**：`atb oncall new --title`（scripts/atb.mjs L400-406 用法）没有 `--req` 类参数；统一新建弹窗（REQ-20260907-004，app.js 约 L2148）的讨论单表单也没有「关联需求」字段。

### 目标行为

1. **需求维度发起讨论**：从需求详情抽屉「发起讨论」或 CLI（如 `atb oncall new --req <REQ-ID> --title …`，具体命令形态 design 阶段定）创建与该 REQ-ID 绑定的讨论线程；关联字段与目录落位在 design 阶段决定（候选：扩展讨论单增加关联字段，复用 oncall 机制）。
2. **上下文自动注入**：派单时 zcode 子 Agent 的读单输出（`oncall show`）与 codex worker 提示词两处均自动携带该需求的 README / design / test-cases 全文及状态、标题等元信息，人工不再手工粘贴；讨论回答始终基于最新落盘文档。
3. **多轮追问沿用现有机制**：轮次目录 `rounds/<N>/{question,answer}.md`、追问拉回待回复、zcode / codex 两种派单模式、客服人员归属、Markdown 渲染与截图内联，全部复用讨论单现状（REQ-20260907-001）。
4. **双向可见**：需求详情抽屉新增「需求讨论」区块，列出归属该需求的讨论（单号、标题、状态徽标、轮数、最近活动时间），点击进入讨论抽屉；讨论单卡片与详情显示归属 REQ-ID，可跳回需求详情。
5. **只读口径不变**：讨论不改变 REQ/BUG 状态机、不占 impl.lock、不进 /dev 选单；回答结论涉及改代码时，建议另建 /req 或完善既有文档（沿用 oncall「只读回答」口径）。

### 交互行为

- **发起**：需求详情抽屉「需求讨论」区块点「＋ 发起讨论」弹出表单（标题 + 问题正文 + 截图附件，口径同统一新建弹窗 REQ-20260907-004），归属 REQ-ID 自动带入并在表单顶部只读展示；保存即创建线程（待回复），无需人工接受。
- **上下文注入**：派单（单条 / 批量）生成的 zcode 调度提示词与 codex worker 提示词自动附该需求 README / design / test-cases 全文与状态元信息；追问轮同样携带。
- **追问**：讨论抽屉底部输入框提交追加轮次，已回复单拉回待回复；派单模式与客服人员交互沿用讨论单现状（客服输入框记忆上次值）。
- **双向跳转**：需求讨论区块条目 → 讨论抽屉；讨论抽屉「归属需求」→ 需求详情抽屉。
- **CLI 对等**：`atb oncall new --req <REQ-ID>`（命令形态待 design 定）创建；`atb oncall list` 支持按需求过滤；`atb oncall show` 输出含归属需求与（派单口径下的）需求文档上下文。

### 状态反馈

- 创建成功：toast「✓ 已创建 ASK-…（待回复）」，需求讨论区块即时出现新条目。
- 回复中：条目状态徽标「回复中」，随现有 2 秒轮询刷新，无需手动刷新。
- 已回复：徽标转「已回复」，轮数与最近活动时间更新。
- 失败：显示失败原因与「重派」入口（口径同讨论单现状）。
- 空态：需求讨论区块无讨论时显示引导文案「尚无讨论，点击发起讨论与 Agent 澄清本需求」。

## 验收标准

- [ ] 从需求详情抽屉可就该需求发起讨论：创建成功后线程归属该 REQ-ID，需求讨论区块即时显示（单号、状态、轮数、最近活动时间），无需人工接受。
- [ ] CLI 可创建需求绑定讨论（`--req` 类参数，具体命令以 design 定），`oncall list` 可按需求过滤，`oncall show` 可见归属需求。
- [ ] zcode 与 codex 两种模式派单，派单提示词均自动携带该需求 README / design / test-cases 全文与状态元信息，无需人工粘贴（以落盘提示词 / `oncall show` 输出核验）。
- [ ] 多轮追问按轮次追加展示、按单落位不串单；回答 Markdown 渲染、截图内联点击放大；追问将已回复单拉回待回复。
- [ ] 双向跳转可用：需求讨论区块 → 讨论抽屉；讨论抽屉归属 REQ-ID → 需求详情。
- [ ] 讨论不改变 REQ/BUG 状态机，不占 impl.lock，不进 /dev 选单；需求被删除或状态流转时讨论线程行为符合 design 定案（不崩坏、不串单）。
- [ ] 现有讨论单（无需求关联）创建、派单、追问、展示无回归；批量实施与批量完善功能不受影响。
- [ ] 现有看板 / 文件 / 派发 / oncall 相关测试无回归，新增能力按 TDD 补用例。

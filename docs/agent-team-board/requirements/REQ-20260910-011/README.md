# REQ-20260910-011 去掉接受、驳回待接受和加入计划，移出计划等二次提示框，意义不大，因为可以撤销

- 创建：2026-09-10T03:21:48.465Z
- 状态以看板机器记录为准。

## 描述

Status Board 上「接受、驳回待接受（驳回接受）、移入计划、移出计划」四个状态流转操作都存在
合法回退边（可一键撤销），逐个弹二次确认框打断操作节奏、收益有限。本需求把这几个操作的
二次确认框全部去掉：点击立即执行，误操作通过既有撤销机制或反向操作回退。

同时按「可撤销即免确认、不可撤销必须确认」的原则整体梳理看板全部二次确认框：删除这类
看板层面不可撤销的操作保留二次确认，且确认框必须显示所操作单号及其标题。

### 现有依据与范围

- 免确认 + 撤销范式已存在（REQ-20260906-014）：详情页（抽屉）操作按钮点击立即执行，成功
  toast 附「撤销」按钮（`scripts/web/app.js` 的 `drawerAction` / `undoActionFor`，toast 撤销
  按钮停留 8 秒，`app.js` toast 实现）。本需求把该范式从详情页扩展到卡片按钮与批量工具栏。
- 仍保留确认的四个入口（均在 `scripts/web/app.js`）：
  - 接受：待接受卡片「✓ 接受」与工具栏「接受所选」（`acceptItems`，提交侧 `submitted → accepted`）；
  - 移入计划：工具栏「移入计划」（`moveToPlan`，`accepted → planned`）；详情页单条「➤ 移入计划」已免确认；
  - 驳回待接受：工具栏「驳回待接受」（`rejectToSubmitted`，`accepted → submitted`）；详情页单条「↩ 驳回接受」已免确认；
  - 移出计划：工具栏「移出计划」（`removeFromPlan`，`planned → accepted`）；详情页单条「↩ 移出计划」已免确认。
- 可撤销依据（`scripts/lib/core.mjs` TRANSITIONS 人工边 + `app.js` ACTION_UNDO 回退映射）：
  接受 ↔ 驳回接受（REQ-20260907-011）、移入计划 ↔ 移出计划（REQ-20260908-010）、
  确认完成 ↔ 驳回完成（REQ-20260903-001）。四个操作的反向操作在界面上始终可用。
- 删除待接受条目（`deleteItem`）移除整个条目目录，看板层面不可恢复（仅能靠 git 历史找回），
  属不可撤销操作：保留 danger 二次确认，确认框需显示单号与条目标题（现状文案已含单号与标题，验收防回归）。
- 其他确认框盘点（均非「可撤销的条目状态流转」，维持现状不动）：
  - 删除批次（`deleteBatchById`，删除批次账本，显示批次号）；
  - 终止批量完善任务 / 终止批量开发任务（`abortRefineTask` / `abortDevTask`，剩余项出局、在途需人工停止，不可撤销）；
  - 停止当前执行（任务模块，中断在途 Agent 执行）；
  - 项目面板「移出项目 / 移出所有不存在目录」（项目级注册记录操作，非条目单号操作）。
- 边界：`attemptTransition`（拖拽换列路径的确认）为遗留代码——拖拽换列已随 REQ-20260907-004
  移除，当前无调用方；实现时可顺带清理，是否清理不影响本需求验收。
- 批量操作完成后的 toast 是否也追加「撤销」按钮（现仅详情页单条路径有），作为可选增强，待确认；
  验收只要求批量误操作可通过「勾选后执行反向批量操作」回退。

- 成功反馈沿用右下角 toast；带「撤销」按钮的 toast 保持 8 秒停留窗口（对齐 REQ-20260906-014）。

## 交互行为

1. 待接受卡片「✓ 接受」、工具栏「接受所选」：点击立即逐条流转（submitted → accepted），
   不再出现二次确认弹窗；批量进行中沿用现有进度反馈与防重复提交。
2. 工具栏「移入计划 / 驳回待接受 / 移出计划」：勾选后点击立即逐条流转，不再出现二次确认弹窗；
   资格过滤沿用现状（如已进入开发中的单不能移出计划、完善中的单驳回被服务端拦截计入失败清单）。
3. 单条入口（卡片「✓ 接受」等）成功 toast 提供「撤销」按钮，点击走状态机合法回退边回退本次
   流转；超过 8 秒窗口或状态已被其他操作变更时撤销失败，按错误 toast 如实提示，不出现假成功。
4. 批量误操作通过反向批量操作回退（如误「接受所选」后勾选同一批执行「驳回待接受」）；
   批量 toast 追加撤销按钮属可选增强（待确认）。
5. 删除待接受条目保留 danger 二次确认：标题显示单号，正文显示条目标题并说明删除移除整个
   条目目录、看板层面不可恢复；取消不删除，确认后删除并 toast 结果（无撤销按钮）。
6. 其余确认框（删除批次、终止批量完善 / 开发任务、停止当前执行、项目面板移出）交互不变。

## 状态反馈

- 正常：操作立即执行，toast 报告结果（单条「✓ {单号} 已接受」等；批量「接受完成：成功 X 条，失败 Y 条」）。
- 进行中：批量操作显示「正在接受 1 / N…」式进度，勾选框与相关按钮禁用防误触（沿用现状）。
- 空：无可操作勾选时对应批量按钮禁用；整列清空后列表显示空态占位。
- 失败：批量按现状成功 / 失败分列反馈（如完善中的单被驳回拦截计入失败清单），不因单项失败回滚已成功项。
- 撤销失败：超过撤销窗口或状态已变时，错误 toast 提示失败原因，不显示假成功。

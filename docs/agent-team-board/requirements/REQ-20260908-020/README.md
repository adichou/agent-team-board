# REQ-20260908-020 重构批量流程和任务管理。

- 状态：submitted（待人工接受）
- 创建：2026-09-08T08:32:47.811Z

## 描述

1、提供批量完善和批量开发两类批量处理任务。可以在任务模块中进行监控管理，支持启动，查看当前处理详情，暂停，终止；
2、批量处理提供一种处理模式，即以当前 zcode 模式为基础的子代理模式， codex 后台模式目前没有跑通，暂时不提供。
3、批量处理支持 codex 和 zcode 两种 Agent，子代理模式的提示词要根据两种 Agent 进行差异化设计；可以在设置中配置哪些 Agent 展示，哪些隐藏。
2、批量完善针对所有已接受状态的单进行处理，每次处理都要实时读取所有已接受状态的单进行处理，在每个已接收状态的单上要显示"完善中"，"已完善"，"未完善"三个状态。每个单从待接受变成已接受时均呈现"未完善"状态。
3、已接受状态的单，除了完善中之外，其他完善状态的单均可以返回待接受状态，若待接受状态变为已接收状态，不管之前是否已经完善，这时均设置为未完善，直到本轮的批量完善工作任务将其完善。
4、批量开发工作流程和批量完善类似，只不过针对的是已计划的单。未在开发中的单均可以移出计划。
5、在设置中可以针对批量完善和批量开发的子代理模型分别进行设置。完善工作流需要使用更高智能的模型以完善需求或单说明。开发工作流可以采用一般程度的智能模型。需针对不同的 Agent 配置不同的模型和智能水平。

### 现状与差距（完善阶段整理，基于当前代码）

- 批量完善（REQ-20260907-003）现状：候选口径是「待接受（submitted）且文档不全」，创建批次时冻结候选快照（`scripts/lib/refine-store.mjs` 的 `refineCandidates` 过滤 `status === 'submitted'`，`createRefineBatch` 冻结候选与文档基线），不是本需求要求的「已接受单 + 每轮实时读取」。
- 批量开发（REQ-20260906-002 / REQ-20260908-010）现状：已按「已计划（planned）」实时串行取单（`scripts/lib/batch.mjs`，领取时实时吸收新置计划条目），与本需求第 4 点方向一致；「未在开发中的单可移出计划」已有（`scripts/lib/core.mjs` 状态机 `planned → accepted`，人工执行）。
- 处理模式现状：zcode 子代理模式（主调度会话 + 每项一个子代理，文件化回执）与 codex 后台模式（`scripts/lib/scheduler.mjs` 每项后台 `codex exec`）并存。本需求明确：只保留子代理模式，codex 后台模式暂不提供。
- 任务模块现状（REQ-20260907-004 五模块视图）：「任务」模块内是三个子面板——Zcode 批次 / Codex 自动派发 / 需求完善（`scripts/web/app.js` 的 `renderRuns`）。本需求要求重构为「批量完善 / 批量开发」两类任务视图，统一提供启动、查看当前处理详情、暂停、终止。
- 暂停/终止现状：两类批量均已有「暂停后续领取」（`/api/refine/pause`、`/api/batch/pause`，不停止在途执行）；「终止」能力目前没有，需新增（含剩余项出账与在途子代理处置）。
- 完善状态现状：只有批次/运行级 phase（reserved/running/done/failed/skipped/interrupted，`REFINE_RESULT_LABEL`），卡片与详情页没有「未完善 / 完善中 / 已完善」三态标记，需新增。
- 驳回现状：已接受单可人工驳回回待接受（REQ-20260907-011，`accepted → submitted`）。本需求追加约束：完善中的单不可驳回，其余完善状态均可；再次接受时完善状态重置为未完善。
- 模型设置现状：设置模块只有 Codex 派发的「模型与推理强度」（REQ-20260906-024，`scripts/lib/codex-model-config.mjs`），没有按「完善 / 开发」分开、也没有 zcode 侧的子代理模型与智能水平配置，也没有 Agent 展示/隐藏配置。

### 目标细化（完善阶段口径）

1. **两类批量任务统一管理**：任务模块以「批量完善」「批量开发」两类任务为主体；每类均支持：启动、查看当前处理详情（当前项单号 + 标题、开始时间、子代理会话标识、最近回执摘要）、暂停/恢复后续领取、终止任务。
2. **仅子代理模式**：两类任务唯一处理模式 = 以现有 zcode 批量模式为基础的子代理模式（主调度会话逐项派子代理、文件化短回执）。Codex 后台自动派发（scheduler 的 `codex exec` 路径）本期隐藏/下线，不提供入口。
3. **双 Agent 差异化**：子代理模式的执行 Agent 支持 zcode 与 codex 两种；主调度提示词与子代理提示词按 Agent 差异化设计（CLI 约定、会话命名、工具口径不同）。设置中可配置哪些 Agent 展示、哪些隐藏；隐藏的 Agent 不出现在任务启动选项中。
4. **批量完善口径（面向已接受单）**：
   - 候选 = 全部「已接受（accepted）」状态的单，每轮领取时实时读取（新接受的单自动进入本轮候选，不做创建时冻结排除；文档基线仍按项冻结用于完成核验）。
   - 每个已接受单展示三态完善标记：**未完善 / 完善中 / 已完善**（需求看板卡片 + 详情页 + 任务模块当前详情）。
   - 置位规则：待接受 → 已接受时一律置「未完善」；子代理领取后置「完善中」；`refine done` 回执且文档变更核验通过后置「已完善」；`refine fail` 后回置「未完善」。
   - 完善对象与文档口径沿用 REQ-20260908-015：需求只补 README（描述 + 验收标准 + 涉及 UI 时的界面展示），Bug 补现象/复现步骤/期望行为/验收说明；条目状态机不受影响（本需求下完善发生在已接受态，条目保持 accepted）。
5. **驳回与重置**：除「完善中」外，其他完善状态的已接受单均可人工驳回回待接受（沿用 REQ-20260907-011 入口）；完善中的单驳回入口禁用并提示；任何单重新由待接受变为已接受时，无论此前是否完善过，完善状态一律重置为「未完善」，直到下一轮批量完善任务处理。
6. **批量开发口径（面向已计划单）**：沿用 REQ-20260908-010 的实时串行队列；未认领（不在开发中）的已计划单可移出计划退回已接受（沿用现有 `planned → accepted` 人工操作，入口在卡片/详情与多选工具栏保留）。
7. **子代理模型分设**：设置模块新增「批量任务」配置区，为批量完善与批量开发分别配置子代理模型与智能水平，且按 Agent（zcode / codex）分别配置。默认建议：完善工作流配置更高智能模型（用于补全需求/单说明），开发工作流可用一般智能模型（默认值仅为建议，可改）。

## 界面展示

### 1. 任务模块（重构后布局）

入口不变（顶栏「任务」，沿用 REQ-20260907-004 五模块导航）；子面板从「Zcode 批次 / Codex 自动派发 / 需求完善」改为「批量完善 / 批量开发」。

```
┌────────────────────────────────────────────────────────────────┐
│ 任务                                              <项目路径>  ✕ │
│ ┌────────────┬────────────┐                                      │
│ │ 批量完善   │ 批量开发   │   ← 两类任务子面板切换               │
│ └────────────┴────────────┘                                      │
│ ── 启动区（无进行中任务时显示）──────────────────────────────   │
│  执行 Agent：(•) zcode   ( ) codex     [ 启动批量完善 ]          │
│  候选：已接受未完善 5 项（每轮实时读取，含本轮新接受的单）        │
│  （未选 Agent 时启动按钮禁用；设置中隐藏的 Agent 不出现）        │
│ ── 当前处理详情（运行中显示）────────────────────────────────   │
│  ● 完善中   REQ-20260908-021 修复导出乱码    子代理 zcode-refine │
│    开始 16:44 · 最近回执：补全验收标准与界面展示                 │
│    计数：完成 3 / 失败 0 / 待处理 5（共 8）                      │
│ ── 操作 ─────────────────────────────────────────────────────   │
│  [ 暂停后续 ]  [ 终止任务 ]                                      │
│ ── 执行记录（分页，沿用现有样式）────────────────────────────   │
│  run-20260908-1644-021  REQ-20260908-020 重构批量流程…  已完成   │
└────────────────────────────────────────────────────────────────┘
```

交互行为与状态反馈：

- **启动**：选择执行 Agent 后点击启动 → 生成主调度提示词并复制（复制成功 ≠ 执行中，沿用现有口径：登记运行后才算执行中）；启动区收起，切换为「当前处理详情 + 操作」运行态。无候选时启动按钮禁用并说明原因。
- **当前处理详情**：随轮询实时刷新当前项（单号 + 标题，沿用 REQ-20260908-001 口径）、子代理会话标识、最近回执摘要与计数；无进行中项时显示「等待领取下一项」。
- **暂停**：点击后按钮切换为「恢复后续领取」，状态条提示「已请求暂停后续领取；在途子代理不受影响」（沿用现有文案口径）。
- **终止**：走二次确认弹窗（沿用看板 confirm 弹窗），确认后任务转「已终止」：停止派发后续项，账本中剩余项标记出局，在途项提示需在对应子代理会话人工停止；终止后启动区恢复，可重新启动新任务。

### 2. 需求看板：已接受单的完善状态徽标

已接受列（含卡片与详情页）单号右侧显示三态徽标：

```
┌ REQ-20260908-021 导出文件名乱码 ──────── [未完善] ┐   灰色
┌ REQ-20260908-022 增加导出进度条 ───────── [完善中] ┐   蓝色 + 动效
┌ REQ-20260908-023 支持批量重命名 ───────── [已完善] ┐   绿色
```

- 徽标随领取/回执实时变化；点击徽标跳转任务模块「批量完善」面板。
- 详情页操作区：「驳回回待接受」按钮在徽标为「完善中」时禁用，悬停提示「完善中，待本轮结束后再驳回」；其余完善状态可正常驳回（沿用 REQ-20260907-011 行为）。
- 已计划 / 开发中 / 已完成等后续状态列不显示完善徽标（完善标记只属于已接受阶段）。

### 3. 设置模块：新增「批量任务」配置区

在「项目设置」内新增分区（现有「模型与推理强度」「运行环境」保留）：

```
── 批量任务 ──────────────────────────────────────────────
 Agent 展示：  批量完善 [✓] zcode  [✓] codex
              批量开发 [✓] zcode  [ ] codex
 完善子代理模型： zcode [________▾]  智能水平 [高 ▾]
                codex [________▾]  推理强度 [high ▾]
 开发子代理模型： zcode [________▾]  智能水平 [中 ▾]
                codex [________▾]  推理强度 [medium ▾]
 [ 保存设置 ]
```

- Agent 展示开关决定任务启动区的可选 Agent；两类任务分别配置。
- 模型与智能水平按「任务类型 × Agent」四路独立配置；完善侧默认推荐高智能模型（占位建议，可改），开发侧默认一般智能模型。
- codex 侧的模型目录 / 推理强度沿用 REQ-20260906-024 的解析能力；zcode 侧子代理模型指定机制待确认（见 design.md 待确认项）。

## 验收标准

- [ ] 任务模块重构为「批量完善 / 批量开发」两类任务子面板；两类均支持启动、查看当前处理详情、暂停/恢复后续领取、终止，且全程不需要离开任务模块。
- [ ] 处理模式仅子代理模式：两类任务只保留「主调度 + 每项一个子代理」的执行方式；Codex 后台自动派发入口（scheduler `codex exec` 路径）在看板中隐藏/下线，本需求交付内不依赖该路径。
- [ ] 子代理模式支持 zcode 与 codex 两种执行 Agent；两套主调度/子代理提示词按 Agent 差异化（CLI 约定、会话命名、执行口径），分别维护且互不混用。
- [ ] 设置模块可为批量完善、批量开发分别配置展示哪些 Agent；被隐藏的 Agent 不出现在对应任务启动选项与执行记录筛选中。
- [ ] 批量完善面向全部已接受单：每轮领取时实时读取全部已接受单作为候选，创建任务后新接受的单自动进入本轮处理范围（不再因创建时点冻结而被排除）。
- [ ] 每个已接受单在列表卡片与详情页显示「未完善 / 完善中 / 已完善」徽标；待接受 → 已接受时置「未完善」；子代理领取后置「完善中」；done 回执且文档变更核验通过后置「已完善」；fail 回执后回置「未完善」。
- [ ] 除「完善中」外，其他完善状态的已接受单均可驳回回待接受（入口不因本需求减少）；「完善中」的单驳回入口禁用并给出提示；任何单重新变为已接受时完善状态重置为「未完善」，直到下一轮批量完善处理。
- [ ] 批量开发沿用已计划（planned）实时串行队列（REQ-20260908-010 口径不回退）；未认领的已计划单可移出计划退回已接受，已认领（开发中）的单不可移出。
- [ ] 设置模块可按「任务类型 × Agent」四路分别配置子代理模型与智能水平；完善侧默认值为更高智能档，开发侧默认值为一般智能档（默认值可修改）。
- [ ] 终止操作有二次确认；终止后停止派发后续项、账本剩余项标记出局、任务转终止态并可在任务模块重新启动新任务；在途子代理的停止方式在界面上有明确提示。
- [ ] 当前处理详情实时显示：当前项单号 + 标题、开始时间、子代理会话标识、最近回执摘要与计数；执行记录列表沿用现有分页与搜索。
- [ ] 回归：claim/report 状态机、impl 互斥锁、回执协议（≤2KiB）、批次保留上限（REQ-20260906-023）等既有机制不受影响；`atb batch` / `atb refine` CLI 仍可正常使用。

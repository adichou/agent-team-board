# 界面设计

## 设计基准

采用用户已确认的第二版统一工作台演示，参考同目录 layout-demo.html。以 README 中的四行布局、文案、交互和验收标准为实施依据；演示是 HTML 片段，包含局部模拟数据，不是生产实现。

## 信息架构

全局栏（产品、项目、新建）→ 模块导航（讨论、需求、任务、文件，末尾设置）→ 模块说明与搜索 → 适用筛选 → 列表/树与详情工作区。

统一新建先选类型，再使用相应业务字段及现有创建接口；需求/Bug 进入需求模块，讨论单进入讨论模块。模块搜索与各自筛选联动，任务搜索覆盖编号、标题和执行器。详情动作、批量动作和配置分别留在相关上下文中。

## 实施约束

- 复用现有数据、权限、状态机、派发和持久化能力，不以演示的模拟状态替代真实逻辑。
- 移除面向用户的看板模式切换；处理旧布局偏好，默认及刷新后稳定为列表。
- 兼容旧模块深链与历史单据；内部 oncall/ASK 等标识无需因文案更名迁移。
- 讨论保留附件、富文本、持续讨论、批量/单条派发及失败处理；任务保留现有批次、队列、暂停/续跑和记录能力。
- 项目切换继续隔离数据；响应式布局保留详情返回入口，避免模态框或工具栏遮挡内容。
- 本次仅登记需求与设计；实现细节、测试执行和报告在认领开发后记录。

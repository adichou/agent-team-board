# REQ-20260908-018 已接受列表要要支持批量移入计划

- 状态：in-progress（Agent 已认领）
- 创建：2026-09-08T06:07:16.780Z

## 描述

标题笔误更正：「已接受列表**需**要支持批量移入计划」。

Status Board 需求列表中，「已接受」档的条目目前只能逐条在详情抽屉点
「➤ 改为已计划」排入开发计划（REQ-20260908-010 引入的人工排期路径）。
当一轮评审接受了很多单时，逐个打开详情再点按钮是重复劳动。

本需求把「移入计划」（accepted → planned）升级为与「批量接受」「批量移出计划」
同构的列表级批量操作：在「已接受」行提供常驻复选框，勾选后用选择工具条的
「移入计划」按钮一次把多条已接受单排入开发计划。

### 现状（源码真实路径）

- 单条移入计划入口只有详情抽屉按钮：`drawerActionsButtonHtml(it)`
  （scripts/web/app.js）`case 'accepted'` 分支的
  `data-act="planned" data-label="改为已计划"` 按钮，走 `postTransition` 单条
  POST `/api/item/<ID>/status` `{to:'planned'}`。
- 列表行复选框只覆盖两档：`reqRowEl(it)` 中 submitted 行 `data-select-id`
  （批量接受）、planned 行 `data-impl-id`（批量开发 / 批量移出计划）；
  accepted 行没有任何复选框。
- 服务端流转边已存在、无需改动：`core.TRANSITIONS.accepted` 含 `planned`，
  server `/api/item/<ID>/status` 允许人工 accepted → planned
  （scripts/server.mjs，REQ-20260908-010 引入）。
- 选择工具条 #selectionBar（scripts/web/index.html）现有按钮：
  接受所选 / 进入批量开发 / 移出计划 / 需求完善 / 清空选择，
  合并计数文案为「已选 N 项（待接受 X · 已计划 Y）」。

### 方案口径

- 「已接受」行新增复选框（`data-plan-id`），勾选进独立集合 `state.plan.selected`，
  资格 = 已接受（与详情页「改为已计划」同口径，含已入批次未派发的单）；
  与既有契约一致：勾选资格跨筛选档保留、叠搜索时只作用搜索可见行、轮询自动剪枝失效勾选。
- 选择工具条新增「移入计划（N）」按钮 `#planAdd`：逐条 POST `{to:'planned'}`，
  页面内二次确认（对齐批量接受/移出计划），成功/失败分列反馈，单项失败不回滚整批。
- 合并计数升级为「已选 N 项（待接受 X · 已接受 Y · 已计划 Z）」；
  「选择可操作项」在「已接受」档全选本档可见已接受条目（其余档行为不变）。
- 不改名既有「改为已计划」文案（另行由 BUG-20260908-006 处理），
  不改状态机、服务端接口与批量开发候选口径（仍是 planned 未认领）。

## UI 设计（界面展示）

需求列表（Status Board 首页）交互形态，与批量接受完全同构：

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ [筛选档] 待接受 3   已接受 5   已计划 2   开发中 1   待测试 0   已完成 12        │
│                                                                              │
│ ┌ #selectionBar（勾选任意复选框后出现）────────────────────────────────────┐ │
│ │ 已选 3 项（待接受 1 · 已接受 1 · 已计划 1）                                │ │
│ │ [接受所选(1)] [移入计划(1)] [进入批量开发] [移出计划(1)] [需求完善] [清空选择]│ │
│ └──────────────────────────────────────────────────────────────────────────┘ │
│ 12 个条目            [排序 ▾]  [选择可操作项]                                 │
│                                                                              │
│ ┌─ 已接受档 · 卡片行 ─────────────────────────────────────────────────────┐ │
│ │ ☑ REQ-20260908-018  [已入批次/未入批次]                        刚刚      │ │
│ │    已接受列表要要支持批量移入计划                                          │ │
│ ├─------------------------------------------------------------------------┤ │
│ │ ☐ REQ-20260908-014  [已入批次 batch-…（已完成）]                1 小时前  │ │
│ │    需求完善批次每一轮上报需在主调度会话中显示单号和标题                    │ │
│ └────────────────────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────────────────┘
```

- **复选框常驻**：每个「已接受」行左上角显示复选框（提交待接受、已计划两档
  复选框维持现状）；点击复选框不打开详情抽屉。
- **工具条随勾选出现**：任意档有勾选即出现 #selectionBar；「移入计划（N）」
  仅在已接受勾选数 > 0 时可用，N 为已接受勾选数；进行中显示「移入中…」并禁用。
- **二次确认弹窗**（页面内，非 window.confirm）：

```
┌─ 确定移入计划所选 3 条（排入开发计划，最旧优先处理）？ ─────────┐
│ REQ-20260908-018                                                │
│ REQ-20260908-016                                                │
│ REQ-20260908-017                                                │
│                                        [取消]  [移入计划]        │
└─────────────────────────────────────────────────────────────────┘
```

- **进度与结果反馈**：确认后逐条流转，工具条下方结果区先显示
  「正在移入计划 2 / 3…」，结束显示「移入计划完成：成功 3 条，失败 0 条」；
  失败单逐条列在结果区（如已被他人流转的极端并发），并 toast 同步结果；
  成功的单从勾选集合移除、行随轮询刷成「已计划」档（复选框换成已计划口径）。
- **失效剪枝**：轮询发现勾选单已不在已接受状态（如被并行流转）时自动移出
  勾选集合并 toast 提示「…已不在已接受状态，已从选择中移除」。
- **清空选择**：一并清空已接受勾选（与待接受、已计划勾选同时清空）。
- **选择可操作项**：在「已接受」档点它 = 全选本档（叠搜索）可见已接受条目。

## 验收标准

- [ ] 「已接受」档列表行有常驻复选框，勾选/取消不打开详情；勾选跨档保留、
      叠搜索时只作用于搜索可见行（与待接受/已计划勾选同契约）。
- [ ] 选择工具条出现「移入计划（N）」按钮：N=0 禁用，进行中禁用并显示
      「移入中…」；合并计数升级为「待接受 X · 已接受 Y · 已计划 Z」。
- [ ] 点击「移入计划」先弹页面内二次确认，取消不发任何请求。
- [ ] 确认后对每条已接受勾选 POST `/api/item/<ID>/status` `{to:'planned'}`，
      逐条进度与完成反馈（成功/失败计数 + 失败清单），单项失败不回滚整批，
      请求绑定当前项目。
- [ ] 非已接受条目（待接受/已计划/开发中等）混入调用时被资格过滤，不发请求。
- [ ] 轮询剪枝：勾选单离开已接受状态后自动从勾选集合移除并 toast 提示。
- [ ] 「清空选择」清空已接受勾选；「选择可操作项」在已接受档全选本档可见
      已接受条目，其他档行为不回退。
- [ ] 切换项目时已接受勾选随其他勾选一并重置。
- [ ] 既有单条「改为已计划」详情按钮、批量接受、批量移出计划、进入批量开发
      行为不回退；状态机与服务端接口不变（accepted→planned 仍为人工专属，
      Agent 置计划仍被守卫拦截）。

# REQ-20260906-013 在开发中和已完成之间增加待确认分类

- 状态：in-progress（owner: zcode-batch-001-1，批量实施 batch-20260906-001 / run-20260906-002）
- 创建：2026-09-06T03:53:26.881Z

## 描述

Status Board 看板目前按状态机四态分列：待接受 / 已接受 / 开发中 / 已完成。
Agent 上报测试报告后条目仍是 `in-progress`（仅卡片上挂一个绿色「待确认」小旗），
和仍在开发中的条目混在同一列，人工不容易看出「哪些等着我确认完成」。

本需求在看板「开发中」与「已完成」之间新增「待确认」分类（列）：

- Agent 已上报（`agentCompletedAt` 非空）的 in-progress 条目进入「待确认」列；
- 未上报的 in-progress 条目留在「开发中」列；
- 「待确认」是展示层派生分类，不改后端状态机（仍为 submitted → accepted → in-progress → done）；
- 人工把「待确认」卡片拖到「已完成」列即确认完成（沿用现有 done 流转）；
- 「待确认」列不接受手动拖入（该分类只能由 Agent 上报进入），拖入时给提示。

## 验收标准

- [ ] 看板列顺序为 待接受 / 已接受 / 开发中 / 待确认 / 已完成（含竖屏左缘 tab 条）
- [ ] 已上报的 in-progress 条目渲染在「待确认」列并计数；未上报的留在「开发中」列
- [ ] 拖卡片到「已完成」仍走确认完成；拖到「开发中」仍走驳回完成；拖入「待确认」被拒绝并提示原因
- [ ] 「待确认」列有独立列色（与四态色均可区分）；卡片「待确认」小旗配色与列一致
- [ ] 桌面五列网格无横向溢出（列最小宽收窄）；≤1020px 竖屏横滑布局自然容纳五列
- [ ] 现有测试套件（npm test）除存量 BUG-20260906-012 红灯外全部通过；受影响的旧契约（四列网格断言）随本需求更新

# REQ-20260907-001 Oncall 咨询看板：咨询单创建、批量/单条派单回复，富文本与截图展示，支持 zcode 与 codex

- 状态：submitted（待人工接受）
- 创建：2026-09-06T16:11:21.198Z

## 描述

## 背景与目标

现有看板条目（REQ/BUG）面向开发实施，有严格状态机与人工验收环节，不适合轻量问答。用户经常需要就项目向 AI 会话提问（如某模块如何工作、某问题原因分析），并希望问答沉淀在看板上、富文本阅读、可带截图。本需求新增 Oncall 咨询看板：创建咨询单、批量或单条派给 zcode / codex 会话回答、回答自动回传看板展示。

## 界面布局、交互与反馈

- 入口：顶栏新增「Oncall」按钮（与「批量实施」并排），点击进入 Oncall 视图；视图切换样式与现有「看板/文件」一致，窄屏不遮挡项目名。
- 列表页：咨询单卡片（单号、标题、状态徽标、派单模式徽标、提问时间、回复轮数），支持按状态筛选（待回复/回复中/已回复）；空态显示引导文案。
- 新建咨询单：表单含标题、问题正文（Markdown，支持粘贴/上传截图作为附件）；保存即入列表，状态「待回复」，无需人工接受。
- 批量回复：列表勾选多个「待回复」单，选择派单模式后「批量派单」；派单时填写「客服人员」（输入框记忆上次使用值），写入派单账本并在看板展示：
  - zcode 模式：生成 oncall 主调度提示词（复制到本项目新会话，参考批次实施主调度模式；每单一个新子 Agent，回答后经受控入口回传看板）。提示词含会话命名指令「将当前会话名改为：oncall-<标识>-<客服人员>」，与 REQ-20260907-002 批次开发人员命名风格一致。
  - codex 模式：服务后台逐单启动 codex exec 会话（参考 Codex 自动派发），回答自动回传；客服人员记录在派单账本用于归属展示。
- 单条问询：咨询单详情提供「问询」输入框与模式选择（zcode/codex），可针对该单追问；追问与历次回答按轮次线程展示。
- 详情页：问题正文与各轮回答 Markdown 渲染，截图/图片内联展示、点击放大；标注每轮派单模式、时间与来源会话。
- 状态反馈：派单成功显示「回复中」，回执落盘后转「已回复」，随现有 2 秒轮询刷新；派单或回传失败显示原因与「重派」入口。

## 数据与状态

- 咨询单使用独立编号序列（前缀如 ASK-YYYYMMDD-NNN，具体在 design 定），数据存放于项目内独立目录，与 requirements/bugs 完全隔离。
- 状态：待回复 → 回复中 → 已回复；追问将已回复单拉回待回复/回复中。回复账本由受控 CLI/HTTP 入口维护，Agent 不手写 JSON。
- 回复内容为 Markdown；图片以附件文件保存并在详情页内联渲染。
- 派单账本记录客服人员（zcode/codex 两种模式一致）；名称仅用于展示与会话命名，不参与权限判断，长度限制与 REQ-20260907-002 对齐；未填写时展示「未指定」，不阻塞派单。

## 约束与边界

- 不改变 REQ/BUG 状态机；咨询单不进入 /dev 与 /dev next 选单，不占用项目实施互斥（impl.lock）——咨询为只读问答，若结论涉及改代码，引导另建 /req。
- zcode/codex 复用现有派发基础设施（深链、提示词模板、codex exec 适配），依赖就绪情况在 design 阶段核对；未就绪的模式隐藏入口，不显示假按钮。
- 不承诺派单会话修改代码或代替人工实施；产出为答复本身。

## 验收要点

- 可创建含截图附件的咨询单；批量勾选派单后每单状态流转正确、回复按单落位不串单。
- 批量派单填写客服人员后：zcode 主调度提示词含会话命名指令（会话名含客服人员），派单账本与看板展示客服人员；未填写时派单流程不回归，显示「未指定」。
- 指定单条问询可用 zcode、codex 两种模式分别派发，回复按轮次追加展示。
- 回复支持 Markdown 富文本与内联截图渲染。
- 咨询单不出现在 REQ/BUG 列表与 /dev 选单；实施互斥与批量实施功能不受影响。
- 现有看板/文件/派发/批量实施测试无回归。

## 关联

- 复用 REQ-20260903-003（一键派发/深链）、REQ-20260906-002（Zcode 批次主调度）、REQ-20260906-003（Codex 后台派发）的派发基础设施；共享派发适配，不共用实施账本。
- 调度会话命名沿用 REQ-20260907-002（批次开发人员命名）同一风格：开发侧写开发人员、咨询侧写客服人员。

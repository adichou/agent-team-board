# REQ-20260915-001 统一产品源码、公开官网文档、私有运营资料与个人博客的仓库职责及引用机制

## 背景与目标

根据 2026-09-14 至 09-15 的讨论，为多个 App 建立可持续的四仓库协作规范，并以 agent-team-board 实际落地一个样板。App 源码可能公开或私有，用户获取官网、安装说明和使用文档不能依赖源码访问权限。不是只写建议：交付规则、产品登记、文档入口和样板内容。

## 仓库职责

| 仓库（均位于 /Users/adichou/Documents/src） | 职责 | 可见性与边界 |
| --- | --- | --- |
| agent-team-board（其他 App 对应各自源码仓库） | 源码、测试、构建配置、架构与开发文档、工程需求与 Bug 记录 | 可公开或私有；公开前核查工程文档及历史中的私有内容 |
| app-homepage-repo | 官网、安装与用户文档、FAQ、公开更新日志、支持入口、适用的隐私/条款、公开素材 | 公开；允许网站自身实现代码，不放 App 实现源码；独立构建不依赖私有仓库 |
| app-info-repo | 产品定位、市场/社区调研、竞品分析、定价策略、推广计划与渠道稿、素材源文件、效果数据、复盘和适用的商店材料 | 始终私有；凭据不进入任何仓库 |
| myblog | 可公开的开发、产品和推广心得，带日期的个人观点与案例 | 公开；未公开草稿留私有仓库，不能依赖 draft 标记隐藏仓库文件 |

沿用现有 CamMan 的 REPOSITORY_BOUNDARIES.md 和 app.yaml 约定；已有 App 目录及已发布 URL 不为统一命名而强制迁移。

2026-09-16 起 app-homepage-repo 复用 myblog 的站点架构（Vite + Vue，GitHub Pages 子路径部署）：站点实现代码在 `src/`，文档内容源在 `content/`，各 App 的静态产品页从仓库根目录迁至 `public/<app-id>/`（如 `public/aldistudio.cam-media-man-mobile/`）。App 实现源码仍不得进入本仓库，此调整仅改变官网静态页的目录位置，不改变仓库职责边界与已发布 URL。

## 产品身份与引用机制

- 样板 product_id 固定为 agent-team-board；显示名称可变。其余产品沿用已有稳定标识，Bundle ID 与产品标识有需要时分别登记。
- app-info-repo/<product_id>/app.yaml 保存完整四仓库映射、源码可见性、公开网站和支持入口；私有本机路径配置不导出到公开内容。
- 官网产品元数据只包含可公开字段；源码私有时不写其私有 URL，源码按钮不显示；源码公开时链接源码与贡献文档。
- 源码 README 链接官网、用户文档和支持入口；博客文章链接产品官网与相关指南；官网可精选链接开发故事。公开仓库不反向引用私有运营资料。
- 仓库内使用相对链接，对外使用稳定网页地址。未部署页面不冒充可用链接；登记待发布状态，发布后回填并核验。
- 每类内容一个权威来源：实现与架构在源码，用户操作在官网，运营分析在私有资料，个人文章在博客。允许摘要和链接，避免手动维护多份完整教程。

## 源码 README 与 Agent 阅读

README 是开发者与 Agent 共用的项目入口，须包含项目定位、核心概念、目录与模块职责、环境与运行方式、构建/测试命令、关键机制、官网链接，以及按任务类型查找规则和开发文档的导航。

- 根 AGENTS.md 承载开发维护本产品的行动规则；docs/development/ 承载按需读取的详细知识。
- 区分根 AGENTS.md（开发本产品）与插件 skills/agent-team-board/SKILL.md（使用产品管理任务），说明同时适用时的阅读入口，不复制整套规则。
- 保留本地足够的开发信息；Agent 无外网或官网权限时仍能定位代码、运行验证与维护项目。
- 现有源码 README 内容按受众梳理，保留开发所需知识，不因官网建立而一概删成营销简介。

## 样板交付与内容流转

- 四仓库 README/边界文档明确职责；私有仓库保存完整协作规范。
- 官网新增 agent-team-board 产品入口、快速上手、常用操作、FAQ、支持、公开更新日志和素材目录。
- 私有资料新增 positioning/、research/、campaigns/、assets/、retrospectives/（按实际内容创建，避免空目录堆积）；本次中文社区调研保存来源、检索日期、直接提及与相关话题的区别。
- 博客建立产品标识/标签关联与文章入口约定，准备一篇基于真实经历的开发心得草稿，草稿先留私有资料，不编造数据或直接发表。
- 私有素材经选定可公开范围后按文件清单复制/生成正式内容；禁止整仓镜像或把私有仓库作为公开站点构建依赖。公开后私有记录保存 URL、版本和效果数据。

## 官网界面与交互

沿用现有站点技术和视觉约定。产品页自上而下：名称与一句话定位、主要价值、真实截图、快速上手与文档入口、版本动态、支持与相关故事。顶部提供首页/文档/更新/支持导航；源码入口按公开配置显示。文档页提供目录与当前位置，窄屏目录可折叠。无截图时不显示占位假图；无发布版本时说明尚未发布；无故事时隐藏故事区。失效链接有明确提示或在发布检查中阻塞。

## 验收标准

- [ ] 四仓库职责落地为可阅读文档，现有 CamMan 约定一致，旧 URL 不被破坏。
- [ ] agent-team-board 的稳定标识、完整私有映射与公开字段分离；公开/私有源码两种配置均核验，私有链接不泄漏。
- [ ] 源码 README 同时满足人和 Agent 阅读，AGENTS.md 与插件 SKILL 的角色清楚，开发命令和文档链接经实际核对。
- [ ] 官网样板可本地构建预览，首页/文档/更新/支持可导航；窄屏与公开源码入口条件正确。
- [ ] 私有运营目录含真实定位和带来源日期的社区研究；博客草稿与产品引用约定准备完毕。
- [ ] 私有到公开的文件清单与检查规则可执行，公开构建无需读取私有仓库。
- [ ] 此需求交付本地可审阅成果；部署上线由关联发布需求执行，未上线不得声称已发布。

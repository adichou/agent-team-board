# BUG-20260903-001 点击操作按钮后，单状态变化了，导致过滤条件也变化了。

- 状态：in-progress（zcode-drawer-nav-freeze 修复中）
- 归属需求：REQ-20260901-001
- 创建：2026-09-02T23:47:41.566Z

## 现象

详情页上一条/下一条导航的过滤条件跟着条目实时状态走。例如当前待接收（submitted）有三条需求，打开其中
一条的详情后，导航只在三条内切换（i/N 为状态组内序号）；但点击「✓ 接受」把这条需求改为已接收后，再点
导航键就只能访问已接收列表中的需求——导航范围从「待接收」漂移到了「已接收」。期望是仍访问待接收的需求。

## 复现步骤

1. 打开 Status Board，保证待接收列有 ≥2 条条目；
2. 点开其中一条进入详情，确认「上一条/下一条」与 i/N 在待接收条目间切换；
3. 点「✓ 接受」将该条目转为已接收（抽屉保持打开）；
4. 再点「下一条」或按 → 方向键：导航目标变成已接收列表里的条目，i/N 也按已接收列表重算。

## 根因分析

`scripts/web/app.js` 的 `drawerNeighbors()` 直接按当前条目的**实时** `status` 过滤导航列表
（`all.filter((it) => it.status === me.status)`）。`me.status` 随操作按钮触发的状态流转实时变化，
于是每次流转后过滤条件都指向新状态的同状态列表——「过滤条件」并非用户设定，而是隐式绑定了会变的
条目状态。导航切换（`navDrawer` → `openDrawer`）又按目标条目重算一遍，漂移被延续放大。

## 修复方案（2026-09-05 实施）

导航范围在**打开抽屉那一刻冻结**：`scopeIdsFor(id)` 按打开时刻的同状态条目序列生成快照
`state.drawer.navIds`，`drawerNeighbors()` 优先用该快照计算 prev/next 与 i/N；prev/next 导航
（`openDrawer(target.id, true)`）沿用快照不重算；点卡片、点跳转链接仍按新条目重算范围。快照中已被
删除的单号按存活条目剔除；快照不可得时回退为原实时同状态过滤。状态流转后当前条目保留其在快照中的
位置（i/N 不跳变），prev/next 始终落在原列表内。详见 test-cases.md（B1–B5）与 test-report.md。

## 期望行为（验收标准）

- [ ] 抽屉打开后，点击接受/确认完成/驳回等操作按钮使状态流转，导航（按钮与方向键）仍只在打开时刻的同状态列表内切换，i/N 不跳变到新状态列表
- [ ] prev/next 导航不重算范围；点卡片、点「归属需求/下属 Bug」跳转链接按新条目重算范围
- [ ] 快照中的条目被删除时导航自动跳过，不会点开不存在的条目
- [ ] 键盘左右方向键与按钮行为一致；深浅色、D1–D4 既有契约不受影响

# REQ-20260830-004 缺陷修复方案必须标注引入来源（哪个需求/Bug 引入）

- 状态：submitted（待人工接受）
- 创建：2026-08-30T00:40:48.557Z

## 描述

开发（/dev）修复 Bug 时，修复方案（design.md 或 README 的根因分析）与 test-report 必须写明该缺陷是由哪个需求（REQ-…）或哪个 Bug（BUG-…）的变更引入的，形成可追溯的缺陷归因链（如 BUG-20260830-001 由 REQ-20260830-002 引入 File Board 视图切换所致）。定位不到引入来源时如实标注「未定位」并说明排查过程，不得猜测编造。目的：让看板上的需求/缺陷之间建立因果链，人工复核时可快速定位影响面与回归责任。

## 验收标准

- [ ] `/bug` 流程（commands/bug.md 与 SKILL.md 对应章节）要求 Bug 记录中含「引入来源」字段：REQ-… / BUG-… / 未定位（附排查说明）三选一。
- [ ] `/dev` 流程（commands/dev.md 与 SKILL.md TDD 流程）要求修复 Bug 时在修复方案（design.md 或 README 根因分析）与 test-report 中写明引入来源；已有来源信息的 Bug 直接引用，缺失的由开发 Agent 定位补充。
- [ ] 「未定位」必须附排查过程说明（查了哪些变更/文件），禁止为通过检查而猜测编造来源。
- [ ] 引入来源指向的条目 ID 必须真实存在于看板（格式校验 REQ-/BUG-YYYYMMDD-NNN）。
- [ ] 示范样例：BUG-20260830-001 的 README「关联」一节已含来源链（REQ-20260830-002 引入），新规范与其一致并标准化。
- [ ] 现有命令（/req /bug /dev /board）的其他行为不变；纯流程/文档规范，不涉及运行时代码。

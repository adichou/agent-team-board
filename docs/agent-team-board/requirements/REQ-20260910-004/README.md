# REQ-20260910-004 StatusBoard 命令优先以提示词中提及的项目来打开看板，若提示词中没有项目再根据左侧项目栏的项目来打开卡板

- 状态：accepted（已接受；实际状态以 status.json 为准）
- 创建：2026-09-09T16:21:08.102Z

## 描述

`/board`（StatusBoard 命令）打开网页看板时，目标项目按两级优先级解析：

1. **提示词中提及的项目优先**：命令参数或用户消息里明确提到某个项目（项目名或路径）时，打开**那个项目**的看板——即使当前会话位于另一个项目。
2. **左侧项目栏的项目兜底**：提示词里没有提到任何项目时，按 ZCode 左侧项目栏中当前会话所属项目（即当前会话项目根）打开，保持现状行为不变。

### 背景与现状

- `/board` 命令（`commands/board.md`）与 skill 的 Status Board 流程（`skills/agent-team-board/SKILL.md`）目前**固定打开当前会话项目**：探测服务（`curl /api/health`）→ 未运行则后台拉起 → 打开 `http://127.0.0.1:8888/?project=<encodeURIComponent(项目根绝对路径)>`，其中项目根 = 向上找 git root 或含 `docs/agent-team-board/` 的目录（兜底 cwd，服务端 `resolveProject` 校验绝对路径并向上探测）。命令文档写明「无需参数」。
- Status Board 本身已是**单服务多项目**：`?project=<项目根绝对路径>` 决定数据源；`/api/health` 返回注册表（`~/.agent-team-board/projects.json`，环境变量 `ATB_REGISTRY` 可覆盖）中的 `projects` 与 `defaultProject`；页面顶栏有项目切换器（`#projectSel`）供手动切换兜底；页面启动定位顺序为 URL 深链 > localStorage（`atb.project` 上次选择）> 服务端默认项目；服务端对首次显式访问的项目自动登记注册表。
- 痛点：用户说「/board 看看 agent-team-board 项目」「打开 xxx 项目的看板」时，命令无视提示词中的项目，仍打开会话所在项目的看板，用户必须再到顶栏项目切换器手动切换。

### 目标方案（重述）

1. **解析优先级**：提示词提及的项目（显式）> 左侧项目栏当前会话所属项目（兜底）。命令从「无需参数」改为接受可选的项目参数。
2. **「提示词中提及的项目」解析规则**（细则由 design 定）：
   - **绝对路径**（含 `~` 展开）：目录存在即用，沿用服务端 `?project=` 既有校验与首访登记；
   - **项目名**（如 `agent-team-board`）：与已知项目（`/api/health` 的 `projects`，即注册表）的路径末段匹配，唯一命中即用；
   - **无命中 / 同名歧义**：不静默打开猜测的项目，向用户说明原因并列出已知项目（含完整路径）请用户确认后再打开。
3. 打开动作仍是既有 URL 形态 `?project=<目标项目根绝对路径>`；目标项目尚未 `atb init` 时打开不报错，显示既有「当前项目尚未初始化看板」空态与初始化按钮，不算失败。
4. 提示词未提及项目时流程与现状完全一致（服务探测 / 后台拉起 / 打开会话项目看板均不回归）。
5. 命令文档同步：`commands/board.md`（`argument-hint` 与正文）与 `skills/agent-team-board/SKILL.md` 的 Status Board 节写明上述解析优先级与规则。

### 待确认

- 提示词同时提及多个项目的取舍（取第一个，还是列出请用户选择）——建议列出请用户确认，由 design 定。
- 是否需要 `atb projects`（或等价 CLI 子命令）辅助 Agent 列出已知项目，还是沿用 `/api/health` 一次拿全——由 design 定。
- 项目名匹配是否支持路径片段（如 `src/agent-team-board`）与大小写无关匹配——由 design 定。
- 「左侧项目栏」以 ZCode 桌面客户端左侧项目/会话列表为准，Agent 侧等价实现为「当前会话项目根」探测（git root / 含 `docs/agent-team-board/` 的目录）——该等价口径是否满足原始诉求，待人工确认。

### 界面布局、交互行为与状态反馈（UI 要求）

本需求不新增看板界面元素，用户可感知面是**会话内执行 `/board` 的过程反馈**与**打开后看板页面呈现的项目**：

- **界面布局**：看板页面布局不变（顶栏含右上项目切换器、模块导航、需求列表区）；变化在于执行命令后顶栏项目切换器的选中项 = 解析出的目标项目（短名显示，悬停见完整路径），列表展示该项目的条目数据。
- **交互行为**：
  - `/board <项目>`：Agent 探测服务（`/api/health`，同时取回已知项目列表用于项目名解析）→ 按上述规则解析目标项目 → 打开 `?project=<目标项目根绝对路径>`；
  - `/board`（未提及项目）：跳过解析，直接按现状打开会话项目看板；
  - 解析遇到歧义 / 无命中时，Agent 在会话中回复候选清单请用户确认，用户回复后继续。
- **状态反馈**：
  - 正常：浏览器面板打开目标项目看板，顶栏切换器显示该目标项目，数据区加载该项目 `docs/agent-team-board/` 的条目；
  - 加载：探测 / 后台拉起服务期间沿用现有等待与日志排查反馈（`/tmp/agent-team-board.log`）；
  - 失败：项目无法解析（路径不存在、同名歧义、无命中）时在会话中说明原因并列出已知项目候选，不打开任何猜测项目；
  - 空态：目标项目未初始化时，看板显示既有「当前项目尚未初始化看板」空态与「初始化」按钮。

## 验收标准

- [ ] 提示词（命令参数或用户消息）明确提及某项目时，打开 `http://127.0.0.1:8888/?project=<该项目根绝对路径>`：看板顶栏项目切换器选中该项目、数据源为其 `docs/agent-team-board/`，即使当前会话位于另一项目。
- [ ] 支持两种提及方式：绝对路径（含 `~` 展开，目录须存在）与项目名（注册表路径末段匹配、唯一命中）；按名打开的项目沿用服务端首访登记，出现在顶栏项目切换器与注册表中。
- [ ] 提示词未提及项目时行为与现状完全一致：打开左侧项目栏当前会话所属项目的看板（git root / 含 `docs/agent-team-board/` 的目录，兜底 cwd）。
- [ ] 项目名无命中或有多个同名项目时：不打开猜测项目，向用户说明原因并列出已知项目（含完整路径）供确认；用户澄清后按澄清结果打开。
- [ ] 服务未运行时仍自动后台拉起并验证（现有流程不回归）；打开后的自动刷新（2 秒轮询）与人工操作提示等既有反馈不变。
- [ ] 目标项目尚未 `atb init` 时打开不报错，展示既有初始化空态；点「初始化」后进入正常看板。
- [ ] `commands/board.md` 的 `argument-hint` 与正文、`skills/agent-team-board/SKILL.md` 的 Status Board 节同步写明「提示词项目优先、左侧项目栏会话项目兜底」的解析规则，文档不再出现「无需参数」表述。
- [ ] 多项目场景无回归：`?project=` 校验、注册表登记、`defaultProject` 与页面启动定位顺序（URL 深链 > 上次选择 > 默认项目）均保持既有行为。

## 界面展示

演示覆盖布局、交互与状态反馈的完整流程：左侧为模拟 ZCode 客户端的「左侧项目栏」（当前会话项目高亮）与聊天输入区，右侧为模拟 Status Board 看板窗口（顶栏项目切换器 + 需求列表）。

- **布局**：会话区（项目栏 + 消息流 + 命令输入框）在左，看板窗口（顶栏切换器显示当前项目短名、列表区）在右。
- **交互**：在输入框执行 `/board` 变体（或点快捷示例：带项目名、带路径、不带参数、同名歧义、路径不存在、未初始化项目），逐步展示「探测服务 → 解析项目 → 打开看板」的过程；解析歧义时需先在会话里确认候选。
- **状态反馈**：正常打开（看板切换到目标项目）、加载中（探测 / 拉起服务）、失败（无命中 / 同名歧义 / 路径不存在，会话内说明并列候选）、空态（未初始化项目的「初始化」引导）四类状态均可切换演示；支持深浅色自动适配。

可交互演示见 [./ui-demo.html](./ui-demo.html)（单文件、无外网依赖，浏览器直接打开）。

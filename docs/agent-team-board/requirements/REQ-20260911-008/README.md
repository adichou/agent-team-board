# REQ-20260911-008 去新建 Zcode 或 Codex 会话自动拷贝最新的提示词

- 状态：accepted（已接受；实际状态以 status.json 为准）
- 创建：2026-09-11T14:48:17.076Z

## 描述

Status Board 任务抽屉（批量完善 / 批量开发 / 批量 Commit 三类面板）头部、一级页签旁有
「去新建 Zcode 会话」「去新建 Codex 会话」两个文字超链接（BUG-20260910-005 引入，
`scripts/web/app.js` 的 `newSessionLinksHtml` 渲染、`bindBatchDrawer` 内 `[data-new-session]` 绑定）。
现状点击只做一件事：构造深链跳转（`zcode://workspace/open?path=<项目>` /
`codex://threads/new?path=<项目>`），toast 提示「请手动粘贴提示词」。

提示词需要用户另行获取：创建任务时自动复制一次，或事后点提示词分区的「重新复制」
（批量开发走 `GET /api/batch/prompt`，完善 / Commit 面板取面板数据里的任务提示词）。
两步操作（先复制、再去新建会话）之间，用户一旦在别处复制过任何内容，剪贴板里的调度提示词
就被覆盖，到新会话 Cmd+V 粘贴出来的不是提示词，只能回看板重新复制再来一次。

本需求把两步并成一步：**点击「去新建 Zcode / Codex 会话」时，先把当前面板任务的
最新主调度提示词自动写入剪贴板，再触发既有深链跳转**。用户到新会话直接粘贴发送即可。

### 已核实的现状要点

- 深链边界（必须保留，不因本需求改变）：zcode 官方深链只有 `workspace/open`（只打开工作区，
  会话需手动新建）；codex `threads/new?path=` 落在新会话输入框但深链不传 prompt、不自动发送。
  因此「自动拷贝提示词」是浏览器侧剪贴板动作，打开后仍由人工粘贴发送——不宣称自动发送。
- 链接的守卫状态（BUG-20260910-005 状态机）：宿主探测中显示「正在检测」；探测失败显示
  「重新检测」；未检测到宿主时该端链接禁用并带「（未检测到）」；未选择项目时两端禁用。
  这些状态下点击均不导航。
- 「最新的提示词」随当前面板取材（与面板提示词分区、既有「重新复制」同源）：
  - 批量开发：`GET /api/batch/prompt`（解析队首批次，不新建批次；存量提示词按
    BUG-20260910-001 归一口径返回）；
  - 批量完善：当前完善任务提示词（`state.refine.data.batch.prompt`，存量批次可能缺失）；
  - 批量 Commit：当前批量 Commit 任务提示词（`state.commit.data.batch.prompt`）。
- 复制工具沿用 `copyDispatchText`（navigator.clipboard 优先，失败返回 false）。
- 点击链接现约定：不切页签、不重渲染、不动批次与队列；鼠标与键盘（聚焦后 Enter）行为一致。

## 界面展示

本单不改界面布局（链接位置、样式不变），只改点击行为与 toast 文案，属 UI 行为需求。
可交互演示：[./ui-demo.html](./ui-demo.html)（单文件、内联 CSS/JS、无外网依赖、无构建步骤，
浏览器直接打开；覆盖正常 / 无任务 / 复制失败 / 提示词获取失败 / 未检测到宿主 / 未选项目 /
客户端检测失败等场景与深浅色切换；全部数据为模拟，不访问真实服务、不写真实剪贴板——
剪贴板以页面内的「剪贴板模拟」面板呈现）。

### 布局（零改动，仅列参照）

- 任务抽屉头部一级页签（批量完善 / 批量开发 / 批量 Commit）右侧的
  「去新建 Zcode 会话」「去新建 Codex 会话」文字超链接保持原位置、原样式
  （`.ws-entry-link`；禁用态 `.is-off` + 「（未检测到）」标注不变）。
- 三类面板的提示词分区（任务信息 + 提示词文本 + 「重新复制」）保持不变，
  仍可独立使用，不因头部自动复制而移除。

### 交互行为

1. 点击「去新建 Zcode / Codex 会话」（守卫状态通过时）：
   ① 取当前面板任务的最新主调度提示词写入剪贴板（批量开发面板先经
   `/api/batch/prompt` 获取，完善 / Commit 面板直接用面板数据，均不新建任务/批次）；
   ② 复制动作完成后触发既有深链跳转（先复制后跳转，保证剪贴板写入发生在用户手势上下文内）；
   ③ toast 反馈「已复制提示词并请求打开 XX，请在新建会话中粘贴发送」。
2. 提示词内容不特化：复用各面板现行主调度提示词原文（含续接场景仍按队首/当前任务口径），
   不为链接点击另造模板。
3. 复制失败不静默：会话入口照常打开（打开不依赖复制），toast 明确「复制失败」并指引
   回面板「重新复制」后再粘贴。
4. 当前面板无任务 / 无提示词（含存量批次提示词缺失）：不复制、不报错，深链照常打开，
   toast 提示「当前面板暂无任务提示词，请先创建任务」。
5. 守卫状态行为与 BUG-20260910-005 一致：未选项目、未检测到对应宿主、探测失败/
   正在检测时不导航也不复制，点击（可点时）仅说明原因。
6. 点击仍不切页签、不重渲染面板、不动批次/任务与队列；键盘 Enter 与鼠标点击行为一致。
7. 深链语义承诺不变：zcode 只打开工作区（会话手动新建）、codex 打开新会话但都不自动
   发送提示词——自动的只是「拷贝到剪贴板」这一步。

### 状态反馈

- 正常：点击后 toast「已复制提示词并请求打开 XX…」；剪贴板即时为最新提示词。
- 加载：批量开发面板取 `/api/batch/prompt` 期间的短暂等待不阻塞跳转提示，
  复制完成与打开请求在同一 toast 序列内交代清楚。
- 失败：提示词获取失败 / 复制失败各有明确 toast（失败原因 + 人工补救路径：重新复制），
  不出现「看似成功实则剪贴板没变」的静默失败。
- 空：面板无任务时提示先创建任务；宿主探测的「正在检测 / 重新检测 / 未检测到」
  三态文案沿用现状。

## 待确认

- 面板无任务时点击是否仍打开会话（本 README 按「仍打开 + 提示」编写）。

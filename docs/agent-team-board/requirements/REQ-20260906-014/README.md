# REQ-20260906-014 详细页面的操作按钮不要二次确认，提供撤销按钮

- 状态：submitted（待人工接受）
- 创建：2026-09-06T03:55:30.110Z

## 描述

Status Board 详情页（抽屉）的操作按钮「✓ 接受 / ✓ 确认完成 / ↩ 驳回完成」目前点击后先弹
`window.confirm` 二次确认，操作链路长、打断节奏。改为：点击立即执行；执行成功后用带
「撤销」按钮的 toast 提供事后回退（撤销按状态机合法回退边执行，见 design.md）。

范围仅详情页按钮；看板卡片按钮、批量接受工具栏、拖拽换列的既有确认行为不变。

## 验收标准

- [x] 详情页三个操作按钮点击后立即发起点流转，不再出现 `window.confirm` 二次确认弹窗。
- [x] 「确认完成」「驳回完成」成功后 toast 内提供「撤销」按钮，点击即回退本次流转
      （done ↔ in-progress 为状态机仅有的合法回退边）。
- [x] 「接受」成功后仅普通成功 toast（状态机无 accepted → submitted 回退边，不提供撤销）。
- [x] 撤销请求失败（如状态已被其他操作变更）时以错误 toast 提示，不出现假成功。
- [x] 看板卡片「✓ 接受」、批量「接受所选」、拖拽换列入口的二次确认行为保持不变（回归）。

# REQ-20260915-002 支持从已合并的版本计划发起跨仓库产品发布并跟踪发布结果

## 背景与已核实基线

用户已具备构建模块中的版本计划并完成 main 合并。现有 REQ-20260913-001 已为 done；本地 main 有 BLD-20260914-001 的合并记录（登记时 tip 为 4d044f1，仅为观察证据，不作为未来默认发布提交）。现有 build-store/build-git 支持 BLD 草稿、合并和逐项结果，release-store 及 Git/Apple/Electron 执行器已存在。

本需求在既有构建与发布模块上增量打通产品发布，不重新实现版本计划或重复合并 main。以 agent-team-board 验证 Web App 与官网/用户文档发布流程；本次仅讨论并完善需求，不执行真实发布。

## 依赖与边界

- REQ-20260915-001：产品标识、官网仓库职责、文档与引用规范；本需求仅依赖其中与 Web App 和官网/用户文档发布相关的约定，不以私有运营资料、博客或社区推广准备为前置。
- REQ-20260913-001：现有构建与版本计划；REQ-20260910-029：现有发布模块。
- 构建计划保留 merged 状态，发布运行独立建模并关联 BLD；发布不自动更改关联 REQ/BUG 的人工验收状态。
- 本期软件交付新增 Web App 支持，暂不设计 Git/Electron/Apple 执行器；既有执行器的存在不代表本期需扩展或接入这些渠道。
- 私有运营资料准备、博客与社区推广不在本次需求范围内，不进入发布阶段、目标选择或完成判定。
- 发布 Web App 与公开源码是不同目标。源码私有仍可部署可访问的 Web App 与官网，绝不因此公开源码或改变仓库可见性。

## 流程与发布内容

### 1. 从版本计划创建发布

构建详情中已 merged 版本显示「创建发布」；未合并版本说明前置条件。进入发布模块创建草稿，自动带入 product_id、BLD ID、版本名称/描述、关联条目与 commit、合并证据，不要求重复选单。版本显示名和实际发行版本号分开。已有运行可查看；同目标活动运行禁止重复创建执行。

### 2. 冻结范围和预检

记录确切的发行版本号、源码提交 SHA、关联条目快照、目标仓库/分支、材料清单与内容指纹。验证选定提交位于 main 历史且包含计划条目；不能直接用执行时最新 main 替换计划结果。老计划无合并结果 SHA 时，展示候选、main 额外提交及来源证据供明确选择；不能声称发行仅包含所选条目而隐去合并带入的额外变更。

预检检查产品映射、源码可见性、目标权限、版本冲突、构建/测试、材料与链接、可公开文件范围。未提交修改不自动提交/暂存/覆盖；在隔离目录验证冻结源码。输入或材料变化使旧预检失效，需重新展示具体发布计划。

### 3. 软件与版本交付

本期新增 Web App 发布支持：按产品配置记录构建命令、构建产物目录、部署目标/环境、部署方式和公开访问 URL。基于冻结源码执行构建与验证，记录实际版本、源码 SHA 与产物摘要，部署后回验访问 URL、页面可用性和版本标识。源码私有时，部署产物与公开入口不得暴露私有源码或依赖用户访问私有仓库。

暂不设计 Git/Electron/Apple 执行器，不将 Git 引用推送、标签/Release、Electron 安装包或 Apple 商店交付纳入本期软件发布验收。版本号修改如需源码提交，应在最终冻结与验证前完成，禁止已验证 SHA 与实际构建源码不一致。Web App 部署方式缺少执行支持时明确阻塞/待外部操作，不把生成命令当执行成功。

### 4. 官网与用户文档发布（必备目标）

官网仓库目录必须支持按用户和产品配置，不硬编码 `app-homepage-repo` 或固定绝对路径。`app-homepage-repo` 仅为目录示例；配置指定官网仓库根目录及产品内容子目录（默认示例为 `<product_id>/`），支持不同用户选择不同位置。目录配置保存在本地不跟踪或私有配置中，创建草稿时带入，冻结时记录实际目标；路径变更使旧预检失效。预检校验目录存在、可访问、仓库及目标分支有效、产品内容路径位于配置的仓库内；未配置或配置无效时阻塞并提示设置入口。

在配置的官网仓库及产品内容目录中更新产品信息、Web App 访问/使用方式、用户指南/FAQ、公开更新日志与版本截图；检查源码 README 的人/Agent 入口和公开互引是否需更新。按版本条目生成可编辑草稿，使用用户可理解的变化，不原样发布内部需求报告。冻结官网提交与软件版本关联，执行站点构建及配置的部署流程，并回验公开页面、版本标识、Web App 入口和文档链接。源码保持私有时官网仍独立可访问与构建。允许先部署无新版 Web App 入口的准备页面；正式新版入口须在 Web App 部署并回验成功后启用。

### 5. 结果核验与发布记录

分开显示 Web App 已发布、官网已上线。两个必备目标均完成回验才显示整体已发布；部分成功保留各目标真实状态。保存提交、版本、产物摘要、执行日志、部署运行标识和公开链接，私有记录保留完整信息，公开报告只导出允许字段。部署命令成功不等于站点上线，需以公开入口和版本回验结果为准。

## 界面布局、交互与反馈

- 构建版本详情操作区新增「创建发布」「查看发布记录」，保留原有合并功能；未 merged 禁用创建并说明原因。
- 发布模块沿用左运行列表/右详情。列表显示产品、发行版本、来源 BLD、整体状态；详情顶部展示冻结 SHA 与版本范围，下方「Web App / 官网文档」两个必备目标卡。
- 创建侧拉面板预填 BLD 信息，配置发行版本号、Web App 构建与部署目标、官网仓库根目录/产品内容子目录及目标分支；可保存草稿与预检。预检不推送、不上传、不部署、不发帖。
- 「预览发布计划」集中展示实际会更新的仓库/分支、文件差异、Web App 构建产物、部署环境和公开入口；用户启动即授权所展示的明确操作，不对已授权的相同步骤重复确认。变更发布范围后需重新确认新计划。
- 详情提供「概览 / 材料与差异 / 日志与证据 / 发布链接」；阶段可见失败原因、重试、待人工处理入口与取消后续阶段。
- 空态引导选择已合并版本；未配置映射给出具体字段与设置入口；执行中禁用重复操作；失败保留成果与原因；部分上线明确显示各目标状态；深浅色与窄屏遵循现有布局规范。

## 一致性、恢复与私有数据

- 跨仓库发布不宣称原子事务；单目标成功落证据，后续失败保留已上线事实，重试只补未完成操作。取消不撤回已发布内容。
- 超时先查询远端/部署/上传真实结果，再决定重试；服务重启不重复发版；同产品版本目标加互斥与幂等标识。
- 来源计划后来改名或被删除不破坏发布快照及历史；关联悬空时说明来源已删除。
- 发布运行中的私有仓库路径、材料全文与日志放本地不跟踪或私有存储，不因看板源码公开被带出；公开页面和报告不暴露此类数据。

## 验收标准

- [ ] 已合并 BLD 可一键生成发布草稿并双向查看记录；不重复选单/合并，未合并计划有明确阻塞。
- [ ] 冻结 SHA、条目、实际版本及材料指纹可追溯；覆盖 main 前进、旧计划缺失 SHA、额外提交和材料变更场景。
- [ ] 公开与私有源码两种配置均可走完产品发布；私有源码不被公开、Web App 公开入口可访问。
- [ ] Web App 支持配置构建、产物目录、部署环境/方式和访问 URL，版本与冻结源码及产物来源一致，部署后回验可用性与版本；失败有真实日志，缺少部署能力不可伪报成功。本期不设计 Git/Electron/Apple 执行器。
- [ ] 官网/用户文档/更新日志按清单准备并真实部署，公开 URL 与版本/Web App 入口回验；独立构建不依赖私有 repo。
- [ ] 官网仓库根目录和产品内容子目录可配置；覆盖不同用户目录、未配置、无效路径及配置变更使预检失效的场景，不依赖固定 `app-homepage-repo` 目录。
- [ ] 发布流程、界面及整体完成判定仅包含 Web App 与官网/用户文档；不包含私有运营资料准备、博客或社区推广。
- [ ] 发布计划可预览并显式启动，预检无外部写入；正确展示空态、阻塞、运行、失败、部分上线和完成。
- [ ] 重试、超时、重启、并发、取消、来源计划修改/删除不导致重复发布或历史丢失；REQ/BUG 人工状态不改变。
- [ ] 用 agent-team-board 样板验证完整流程；测试/演练与真实上线证据分开记录，真实上线需执行具体计划授权。

# REQ-20260915-002 支持从已合并的版本计划发起跨仓库产品发布并跟踪发布结果

## 背景与已核实基线

用户已具备构建模块中的版本计划并完成 main 合并。现有 REQ-20260913-001 已为 done；本地 main 有 BLD-20260914-001 的合并记录（登记时 tip 为 4d044f1，仅为观察证据，不作为未来默认发布提交）。现有 build-store/build-git 支持 BLD 草稿、合并和逐项结果，release-store 及 Git/Apple/Electron 执行器已存在。

本需求在既有构建与发布模块上增量打通产品发布，不重新实现版本计划或重复合并 main。以 agent-team-board 验证 Web App 与官网/用户文档发布流程；本次仅讨论并完善需求，不执行真实发布。

## 依赖与边界

- REQ-20260915-001：产品标识、官网仓库职责、文档与引用规范；本需求仅依赖其中与 Web App 和官网/用户文档发布相关的约定，不以私有运营资料、博客或社区推广准备为前置。
- REQ-20260913-001：现有构建与版本计划；REQ-20260910-029：现有发布模块。
- 构建计划保留 merged 状态，发布运行独立建模并关联 BLD；发布不自动更改关联 REQ/BUG 的人工验收状态。
- 本期软件交付新增 Web App 支持，暂不设计 Git/Electron/Apple 执行器；既有执行器的存在不代表本期需扩展或接入这些渠道。
- 私有运营资料准备、博客与社区推广不在本次需求范围内，不进入发布阶段、目标选择或完成判定。
- 发布 Web App 与公开源码是不同目标。源码私有仍可部署本机可访问的 Web App 与官网，绝不因此公开源码或改变仓库可见性。

## 流程与发布内容

### 1. 从版本计划创建发布

构建详情中已 merged 版本显示「创建发布」；未合并版本说明前置条件。进入发布模块创建草稿，自动带入 product_id、BLD ID、版本名称/描述、关联条目与 commit、合并证据，不要求重复选单。版本显示名和实际发行版本号分开。已有运行可查看；同目标活动运行禁止重复创建执行。

### 2. 冻结范围和预检

记录确切的发行版本号、源码提交 SHA、关联条目快照、目标仓库/分支、材料清单与内容指纹。验证选定提交位于 main 历史且包含计划条目；不能直接用执行时最新 main 替换计划结果。老计划无合并结果 SHA 时，展示候选、main 额外提交及来源证据供明确选择；不能声称发行仅包含所选条目而隐去合并带入的额外变更。

预检检查产品映射、源码可见性、目标权限、版本冲突、构建/测试、材料与链接、可公开文件范围。未提交修改不自动提交/暂存/覆盖；在隔离目录验证冻结源码。输入或材料变化使旧预检失效，需重新展示具体发布计划。

### 3. 软件与版本交付

本期新增 Web App 本机发布支持：系统检查冻结源码的框架、项目架构、包管理器、脚本与框架配置，自动生成构建命令，自动配置产物目录、本机部署环境与部署方式，无需用户填写。无需独立构建步骤的项目按其运行架构自动处理，不强制套用 `npm run build` 或 `dist/`。基于冻结源码执行构建与验证，记录实际版本、源码 SHA 与产物摘要，自动分配本机端口并生成本机访问地址，部署后回验页面可用性和版本标识；不需要公开访问 URL，不配置公网部署。源码私有时，本机运行不得依赖浏览器访问私有仓库。自动识别失败时展示具体原因和诊断信息，不把手填构建参数作为正常流程，也不猜测执行。

暂不设计 Git/Electron/Apple 执行器，不将 Git 引用推送、标签/Release、Electron 安装包或 Apple 商店交付纳入本期软件发布验收。版本号修改如需源码提交，应在最终冻结与验证前完成，禁止已验证 SHA 与实际构建源码不一致。Web App 部署方式缺少执行支持时明确阻塞/待外部操作，不把生成命令当执行成功。

### 4. 官网与用户文档发布（必备目标）

官网仓库根目录在设置模块中按用户一次设置，供后续项目构建与发布复用，不硬编码 `app-homepage-repo` 或固定绝对路径。首次未设置时，创建入口引导到设置页面，保存后返回原发布流程并保留草稿；后续无需每次设置。产品内容子目录自动使用当前项目名（本项目为 `agent-team-board/`），官网目标分支默认为 `main`，均无需用户关注或填写。项目名必须校验为安全子目录，不允许路径越界；无效或冲突时给出明确诊断。目录配置保存在本地不跟踪或私有配置中，创建草稿时自动带入，冻结时记录实际目标；设置中的路径变更使旧预检失效。预检校验目录存在、可访问、仓库及目标分支有效、产品内容路径位于配置的仓库内；未配置或配置无效时阻塞并提示设置入口。

在配置的官网仓库及产品内容目录中更新产品信息、Web App 访问/使用方式、用户指南/FAQ、公开更新日志与版本截图；检查源码 README 的人/Agent 入口和公开互引是否需更新。按版本条目生成可编辑草稿，使用用户可理解的变化，不原样发布内部需求报告。冻结官网提交与软件版本关联，自动识别站点构建方式并部署到本机，回验本机页面、版本标识、Web App 入口和文档链接。源码保持私有时官网仍可在本机独立访问与构建。允许先部署无新版 Web App 入口的准备页面；正式新版入口须在 Web App 部署并回验成功后启用。

### 5. 结果核验与发布记录

分开显示 Web App 已发布、官网已上线。两个必备目标均完成回验才显示整体已发布；部分成功保留各目标真实状态。保存提交、版本、产物摘要、执行日志、部署运行标识和自动生成的本机链接，私有记录保留完整信息，公开报告只导出允许字段。部署命令成功不等于站点上线，需以本机入口和版本回验结果为准。

## 界面布局、交互与反馈

- 构建版本详情操作区新增「创建发布」「查看发布记录」，保留原有合并功能；未 merged 禁用创建并说明原因。
- 发布模块沿用左运行列表/右详情。列表显示产品、发行版本、来源 BLD、整体状态；详情顶部展示冻结 SHA 与版本范围，下方「Web App / 官网文档」两个必备目标卡。
- 创建面板预填 BLD 信息，仅需核对发行版本号；构建命令、产物目录和本机部署环境自动识别配置，产品内容子目录自动取项目名，目标分支默认 `main`。面板不提供上述技术参数或公开访问 URL 输入框，官网仓库根目录仅从设置模块读取；首次缺失显示「前往设置」，保存后返回继续。可保存草稿与预检。预检不推送、不上传、不部署、不发帖。
- 「预览发布计划」集中展示实际会更新的仓库/分支、文件差异、Web App 构建产物、自动配置的本机环境和本机入口；用户启动即授权所展示的明确操作，不对已授权的相同步骤重复确认。变更发布范围后需重新确认新计划。
- 详情提供「概览 / 材料与差异 / 日志与证据 / 发布链接」；阶段可见失败原因、重试、待人工处理入口与取消后续阶段。
- 空态引导选择已合并版本；未配置映射给出具体字段与设置入口；执行中禁用重复操作；失败保留成果与原因；部分上线明确显示各目标状态；深浅色与窄屏遵循现有布局规范。

## 一致性、恢复与私有数据

- 跨仓库发布不宣称原子事务；单目标成功落证据，后续失败保留已上线事实，重试只补未完成操作。取消不撤回已发布内容。
- 超时先查询远端/部署/上传真实结果，再决定重试；服务重启不重复发版；同产品版本目标加互斥与幂等标识。
- 来源计划后来改名或被删除不破坏发布快照及历史；关联悬空时说明来源已删除。
- 发布运行中的私有仓库路径、材料全文与日志放本地不跟踪或私有存储，不因看板源码公开被带出；公开页面和报告不暴露此类数据。

## 补充核实与待确认

- 代码基线：`scripts/lib/release-store.mjs` 的 `TARGET_TYPES` 当前将 `web` 标记为 `enabled: false`，`scripts/web/release.js` 同样未开放网站入口。本 README 的双目标 Web App 流程是目标行为，不能把现有枚举视作可部署能力。
- `scripts/lib/build-store.mjs` 的 `finishMerge` 当前记录逐项合并时间与错误、版本合并完成时间；该函数未保存最终 main SHA。旧计划候选提交必须补可核验来源，不能用时间戳或登记时 tip 代替冻结证据。
- 自动配置边界：实施时从冻结源码识别 Web App 与官网的框架/架构、构建及运行方式，自动确定产物目录、本机环境、端口和版本探测规则；覆盖无构建步骤的项目。识别失败或缺少执行支持时明确阻塞并给出诊断，不要求用户选择部署环境或提供公开 URL。官网仓库根目录是设置模块的一次性配置；子目录自动取项目名，目标分支默认 main。演示中的识别结果、路径、SHA 与地址仅为示例。
- 待确认：官网截图具体清单与无界面变化版本是否复用旧截图的规则；草稿应标明待补材料，不生成虚假截图。

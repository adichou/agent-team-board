# REQ-20260909-002 列表头与批量操作条合并为单行：去清空选择、文案精简

- 状态：accepted（已接受；实际状态以 status.json 为准）
- 创建：2026-09-08T23:04:40.243Z

## 描述

Status Board 需求列表勾选条目后，当前独立的批量操作条与列表头上下排列，重复占用高度；「清空选择」与「☐ 全不选」功能重复，计数和动作按钮也重复显示数量。本需求将批量操作区域并入列表头右侧，以单行呈现条目计数、排序、选择入口及当前档动作，减少重复文案。只调整布局和展示文案，保留现有批量流转、确认、资格过滤与选择隔离行为。

### 现状依据与范围

- `scripts/web/index.html`：`#selectionBar`、`#acceptResult`、`.req-caption` 当前为三个相邻区域；`#clearSelection` 在独立操作条内。
- `scripts/web/app.js` 的 `syncAcceptance`：按当前档展示动作，计数为「已选 N 项（档位）」，部分按钮带「（N）」后缀；`selectOperable` / `deselectOperable` 已提供成对全选、全不选。
- 本需求覆盖待接受、已接受、已计划三档。开发中、待测试、已完成无批量动作，保留列表头和当前不可用的选择入口行为；文件、讨论等视图不受影响。

### 界面布局

从上到下为现有筛选区、合并列表头、按需出现的批量进度/结果区、条目列表。合并列表头内部顺序如下：

```
N 个条目  [排序 ▾]  [☑ 全选] [☐ 全不选]  │  已选 M 项  [当前档动作]
```

- 左组保留条目计数、原排序选项与选择入口；右组在当前档选中数大于 0 时显示，以竖分隔线区分组别。充足宽度下两组处于同一行，右组靠右。
- 当前档无选择时隐藏整个右组和分隔线，不预留独立空行；条目计数仍表示列表条目数，选择计数表示当前档勾选数，二者不能互相替代。
- 窄屏允许右组整体换到下一行，组内按钮必要时继续换行，保留顺序与间距，不能遮挡、截断文案或产生页面横向滚动。具体断点待确认，按内容是否容纳确定，不能为了单行而隐藏操作。
- 批量结果区独立位于合并行下方；进度、成功数、失败清单不塞入合并行。右组因成功后零选择隐藏时，结果区仍可查看。
- 保留批量区域 `role="group"` 和可理解的 `aria-label`、按钮已有 title 提示、排序标签、键盘焦点样式；结果区保持 `role="status"` / `aria-live="polite"`。

### 交互行为与文案

| 当前筛选档 | 当前档有勾选时的右组动作 |
| --- | --- |
| 待接受 | 接受所选 |
| 已接受 | 移入计划、驳回待接受 |
| 已计划 | 进入批量开发、移出计划 |
| 开发中、待测试、已完成 | 无右组 |

1. 移除「清空选择」入口；清除选择统一使用「☐ 全不选」。全选仅勾选当前档搜索范围内的可操作条目；全不选清当前档集合，其他档既有选择仍保留。切档后只显示当前档计数和动作，排序不改变勾选身份。
2. 选择计数统一为「已选 M 项」，去掉档位括号；静止时动作按钮统一采用上表文案，不带数量后缀。数量只在右组计数处显示一次；确认弹窗及进度/结果中的必要数量保留。
3. 单项勾选、全选、全不选、切档及轮询后同步更新计数和按钮；不能为更新计数而重建整个列表头，避免焦点丢失或闪烁。勾选反馈保持复选框打勾，不新增行边框高亮。
4. 保持现有页面内二次确认，取消不执行；进入批量开发保持现有入口和候选范围逻辑，不在此需求内改为直接启动任务。

### 状态反馈

- 正常：零选择仅显示左组；勾选后即时出现右组，按钮资格和禁用条件沿用当前行为。
- 空列表/搜索无结果：显示 0 个条目与明确空态，全选无可操作候选时禁用；右组是否出现取决于当前档有效选择集合，不能简单由列表行数推断。全不选按当前档有效选择数量决定是否可用。
- 列表加载：保留现有加载反馈，不把暂未返回的数据误当作零条目或成功；稳定列表头不因加载反复拆建。首次加载无可操作数据时不开放批量操作。
- 批量进行中：按钮显示既有「接受中…」「移入中…」「驳回中…」「移出中…」文案，相关动作、复选框、全选与全不选保持既有禁用规则；结果区显示逐项进度，防止重复提交。
- 成功/部分失败：结果区保留成功数、失败数和「条目编号：原因」。逐条流转、单项失败不回滚；成功项从选择中消费，失败项保持选择便于重试，右组显示剩余数量。
- 完善中被拒绝、并发资格变化、网络错误：沿用既有错误与剪枝反馈，不能只隐藏操作条或仅靠颜色提示。完善中拦截不得因合并布局而被绕过。

## 验收标准

- [ ] 宽度可容纳时，待接受、已接受、已计划三档的条目计数、排序、全选/全不选及选择动作处于同一列表头行，不再出现独立批量操作条；零选择时右组及分隔线完全隐藏且无空占位。
- [ ] 三档动作严格符合上表；在多个档已有选择后切档，只显示当前档计数及动作，其他档选择不被本档全不选清除。开发中、待测试、已完成不出现批量右组。
- [ ] 页面不再存在「清空选择」按钮；全不选能清除当前档选择并使右组消失。全选的搜索范围和资格过滤保持现状。
- [ ] 右组静止计数为「已选 M 项」，不含档位括号；五种动作按钮均无括号数量后缀；确认、进度、结果保留必要数量，进行中文案正常。
- [ ] 勾选与轮询更新不重建整个列表头、不导致排序/仍可见按钮焦点丢失或闪烁，选择行不新增蓝色边框。
- [ ] 窄屏（至少以 390px 视口检查）能有序换行，按钮不重叠、不裁切且无横向滚动；内容足够宽时恢复单行。
- [ ] 空列表与无搜索结果均有明确反馈，无候选时全选禁用；首次加载不能触发批量动作；批量过程中禁用行为及逐项进度不回退。
- [ ] 页面内确认取消不执行；成功项从选择中移除，失败项保留；部分失败不回滚成功项，结果在右组隐藏后仍可读；完善中拒绝及原 title 提示保留。
- [ ] 批量区域具备可读分组标签，键盘能操作排序、选择及动作；结果可由读屏获知。已计划批量开发入口范围、其余视图与既有单条流转无回归。
- [ ] 开发阶段更新并通过 accept-ui 及相关选择/批量操作检查；当前完善阶段只交付 README 与可直接离线打开的 ui-demo.html，design 与 test-cases 留待开发补充。

### 口径解读（「所有任务」指什么）

看板「任务」模块现有三类批量任务（均为「启动 = 创建任务 + 复制主调度提示词」形态）：**批量开发 / 批量完善 / 批量 Commit（批量提交）**。三类任务的启动区目前各带一个「开发人员」输入框（REQ-20260907-002 引入，用途仅两件事：调度会话命名与看板展示，不参与任何权限判断）。

本需求口径：把**三类任务中的「开发人员」设置功能整体删除**——启动区不再有输入框、创建链路不再提交该值、主调度提示词不再含会话命名指令、展示侧不再显示开发人员、记忆/预填链路移除、CLI `--dev` 参数移除。截图所示为批量 Commit 启动区的「开发人员」输入，标题「所有任务」按三类批量任务全量删除理解（若有例外见「待确认」）。

### 背景 / 现状（基于代码静态核查，2026-09-10）

**输入（设置）入口——3 处 UI + CLI：**

- 批量开发启动区 `renderDevStartBar()`（`scripts/web/app.js`）：`#batchDev`（maxlength 30，placeholder「如 张三（可留空）」）；初值链 `batchDevInitial()`：重渲染保留已输入值 → 上次使用值（localStorage `atb.batch.dev`）→ 项目 git user.name 首次预填（`/api/batch/current` 无批次时返回 `gitUser`，`scripts/server.mjs` `gitUserName()`）→ 空
- 批量完善启动区 `renderRefinePanel()`：`#refineDev`（placeholder「如 张三（可留空，仅展示与命名用）」），初值取 localStorage
- 批量 Commit 启动区 `renderCommitPanel()`：`#commitDev`（同上文案），初值取 localStorage
- CLI：`atb batch create --dev <名称>`、`atb refine create --dev`、`atb commit create --dev`

**创建链路：**

- 前端创建请求均携带 `developer`（`createBatchAndCopy()` / `createRefineBatchAndCopy()` / `createCommitBatchAndCopy()`）；非空时写 localStorage 记忆上次值，清空则移除（回到 git 预填）
- 服务端透传至 `createBatch` / `createRefineBatch` / `createCommitBatch`（`scripts/lib/batch.mjs` / `refine-store.mjs` / `commit-store.mjs`）；`normalizeDeveloper()`（`scripts/lib/batch.mjs`）校验超 30 字符或含换行/控制字符即拒绝（CLI die / API 400），拒绝不产生账本副作用
- 批次账本（batch.json 等）记录 `developer` 字段（null=未指定，存量批次缺字段同义，不迁移）

**提示词：**

- developer 非空时，主调度提示词追加「请将当前会话名改为：<batchId>-<开发人员>。」（`generatePrompt()` / `buildRefinePrompt()` / `buildCommitPrompt()`）；未填时不加该指令

**展示（含存量批次）：**

- 运行面板状态行（三任务概况页签）：「… · 创建 <时间> · 开发人员 <名|未指定>」
- 排队批次行：「… · 开发人员 <名|未指定>」
- 全局任务面板任务行 meta：「开发人员 <名|未指定>」
- 任务搜索（BUG-20260910-009）与全局面板搜索的过滤字段包含开发人员（排队批次按批次号/开发人员匹配）
- `atb` CLI 多处状态输出行显示「开发人员 <名|未指定>」

### 目标（删除后的期望行为）

1. 三类任务启动区删除「开发人员」输入：批量开发启动区顶行只剩「启动」按钮与既有队列预览文案；批量完善 / 批量 Commit 启动区为「说明文案 + 候选统计 + 启动」，不再出现输入框
2. 创建不再携带开发人员：前端请求不带 `developer`；终态「启动新一轮」不再回退上次值；localStorage `atb.batch.dev` 读写链路与 git user.name 首次预填（`/api/batch/current` 的 `gitUser` 字段）随之移除或不再使用（口径由 design 定）
3. 新建任务的主调度提示词不再含「请将当前会话名改为：<batchId>-<开发人员>」指令（新任务不再有非空 developer 来源）
4. 展示侧不再显示开发人员：运行面板状态行、排队批次行、全局任务行、CLI 输出均移除该片段；任务/全局搜索不再按开发人员字段过滤
5. CLI 不再提供 `--dev` 参数（帮助文本同步更新）
6. 存量兼容：历史批次账本中已有的 `developer` 字段不要求迁移；看板与 CLI 对存量批次正常展示与操作（不再展示开发人员）

### 边界（明确不做）

- 不动三类任务的候选口径、排队/幂等、暂停/终止、回执与状态机
- 不动「启动 = 创建任务并复制提示词」「复制成功 ≠ 执行中」「只 commit 不 push」等既有口径文案（仅去掉其中开发人员相关内容）
- 不做开发人员替代方案（如自动取 git user.name 展示或命名）：字段整体下线，命名指令不再出现
- 不迁移/清洗存量账本数据（字段去留由 design 定）

### 待确认

- 删除动机与是否保留任何替代展示（截图未说明原因；按彻底删除理解）
- API/CLI 收到遗留 `developer` 入参时的处理（忽略 vs 报错）——design 定
- `/api/batch/current` 的 `gitUser` 字段与服务端 `gitUserName()` 是否一并移除——design 定
- 账本 `developer` 字段是否物理删除（建议保留不迁移，兼容存量账本读取）

## 验收标准

- [ ] 批量开发 / 批量完善 / 批量 Commit 三处启动区均无「开发人员」输入框（`#batchDev` / `#refineDev` / `#commitDev` 移除），布局不塌陷
- [ ] 启动 / 启动新一轮创建请求不携带 `developer`；前端不再读写 localStorage `atb.batch.dev`
- [ ] 新建任务主调度提示词不含「请将当前会话名改为：<batchId>-<开发人员>」类命名指令
- [ ] 展示侧不再出现「开发人员」：运行面板状态行 / 排队批次行 / 全局任务行 / CLI 状态输出均移除；任务与全局搜索不再按开发人员字段过滤
- [ ] `atb batch create` / `atb refine create` / `atb commit create` 无 `--dev` 参数，帮助文本同步更新
- [ ] 移除后三类任务的创建、启动、排队、回执、暂停/终止与看板展示全流程正常；无候选时启动禁用等既有状态反馈不回归
- [ ] 存量批次（账本含 `developer`）在看板与 CLI 正常展示与操作，不要求数据迁移
- [ ] 相关既有测试按移除后口径更新（batch-ui U14 / refine-ui R12-3 / commit-ui / batch-core REQ-20260907-002 段 / refine-store 等）且全量测试通过

## 界面布局

改动集中在三类任务的**启动区（无进行中任务时）**与**运行态展示行**，其余布局不变：

- **批量开发启动区**：顶行原为「开发人员 输入框 + 启动 按钮」，删除后顶行只剩「启动」按钮（右侧）；候选统计行与已计划队列预览文案不变
- **批量完善启动区**：原为「说明文案 → 候选统计行 → 开发人员 输入框 → 启动 按钮 → 口径说明」，删除后为「说明文案 → 候选统计行 → 启动 按钮 → 口径说明」，输入框所在行整体消失
- **批量 Commit 启动区**：同上，删除「开发人员 输入框」行，保留说明文案、候选统计（已完成口径）与「启动」
- **运行态**：概况页签状态行由「<状态> <批次号> 模式 · 创建 <时间> · 开发人员 <名|未指定>」变为去掉末段开发人员片段；排队批次行、全局任务行 meta 同步去掉该 span；搜索过滤字段列表去掉开发人员

## 交互行为

- 「启动」点击即创建任务并复制主调度提示词——不再有、也无法填写开发人员；输入焦点链路（重渲染保留已输入值）随输入框一并删除
- 终态批次「启动新一轮」同样直接创建，不再回退 localStorage 上次开发人员值（该记忆链路删除）
- 提示词复制（启动时 / 「重新复制」）行为与文案不变，仅新任务提示词文本中不再可能出现开发人员命名指令
- 任务搜索 / 全局搜索输入仍按其余字段（编号、标题、批次号、执行器、提交号等）过滤，开发人员不再是匹配字段

## 状态反馈

- 无候选：启动按钮禁用并保留各自 title 说明（批量开发「暂无已计划候选…」、批量完善「暂无可完善候选…」、批量 Commit「暂无已完成候选…」），不因移除输入框而改变
- 面板加载中显示「加载中…」、加载失败提供重试（设置视图「任务设置加载失败 + 重试」口径不变），均与开发人员无关
- 创建成功/失败、复制成功/失败的 toast 口径不变（不含开发人员字样）
- 存量批次（升级前已创建、账本含 developer）在移除后的看板/CLI 中正常展示与操作，仅不再显示开发人员

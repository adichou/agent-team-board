# REQ-20260914-003 优化讨论生成的提示词

- 状态：submitted（待人工接受）
- 创建：2026-09-14T08:28:26.282Z

## 描述

开放式讨论的启动/继续提示词由看板服务端拼装（`scripts/lib/oncall-store.mjs` 的 `buildStartPrompt` / `buildContinuePrompt`，讨论详情抽屉内折叠展示并可复制）。本需求在不重构既有提示词内容的前提下，为讨论 Agent 追加「按需更新文件并自动提交」的工作约定：

1. 现有提示词内容保留不改变：上下文恢复、逐轮保存（`atb disc round`）、纪要维护（`atb disc minutes`）、共识/建议/未决区分等既有章节与措辞不删改，新约定以追加方式并入。
2. Agent 每轮回答后，若该轮结论需要更新相应文件（如讨论中约定的文档、配置等），则按需更新文件；更新完成后自动执行 git 提交（只 commit，是否允许 push 待确认），commit 消息须体现单号（讨论单号 ASK-YYYYMMDD-NNN；是否需同时体现关联 REQ/BUG 单号待确认）并对本次修改做简单摘要记录，便于事后按单号追溯。
3. Agent 的回答内容中要显示本次的 commit 消息（单号 + 修改摘要，建议含提交号）；本轮无文件更新时明示无修改，不产生空提交。

与既有约束的边界：自动提交只覆盖「按需文件更新 + commit」；讨论期间不创建/不接受需求/Bug 条目、不改看板状态、轮次与纪要仍走 `atb disc` 统一入口等既有保护保持不变。现有提示词中「不修改代码、不执行 git commit」的禁止性表述与本需求的冲突如何收敛（整体放开，还是仅放开讨论明确支撑的文件范围、仍禁止改业务代码）——待确认。

## 验收标准

- [ ] 启动讨论提示词与继续讨论提示词在既有章节基础上追加上述约定：既有内容（上下文恢复、逐轮保存、纪要维护、讨论约定分节与措辞）逐条保留，无删改。
- [ ] 提示词明确：每轮回答后按需更新文件，更新后自动 git 提交；无文件更新时不提交（不产生空提交），并在回答中说明本轮无修改。
- [ ] 提示词对 commit 消息提出硬性要求：包含讨论单号与本次修改的简要摘要；格式建议沿用项目既有自动提交口径（`git-flow.mjs` 的 `类型: 摘要 单号`），最终格式待确认。
- [ ] 提示词要求 Agent 在回答内容中展示本次 commit 消息（单号、摘要，建议含提交号），用户无需另行查 git log 即可知道本轮落了什么提交。
- [ ] 新约定不突破既有保护：不改看板条目状态机、不自动创建/接受需求/Bug 条目、轮次与纪要仍经 `atb disc round` / `atb disc minutes` 统一入口。
- [ ] 看板侧生成与展示不受影响：启动提示词折叠块、「复制继续讨论提示词」等入口照常工作，复制所得文本即含新约定。
- [ ] 整理结论提示词（`buildOrganizePrompt`）与收尾提示词（`buildFinishPrompt`）是否同样追加该约定——待确认；若不追加，其现有内容保持不变。
- [ ] 既有断言提示词内容的测试（如 `scripts/tests/discussion-rounds-20260910-018.test.mjs`、`discussion-shot-20260910-028.test.mjs`）按新口径更新并通过，新增用例覆盖：提示词含单号提交要求、含回答展示 commit 消息要求、既有章节未被删改。

## 界面与交互

本需求不改看板界面结构，新增约定随启动/继续讨论提示词进入既有讨论详情抽屉：

- 界面布局：沿用讨论详情抽屉——头部单号/标题/状态与轮数、纪要版本；操作区四按钮（启动提示词、复制继续讨论提示词、整理结论、归档讨论）；启动提示词为 drawer-body 内折叠块，展开显示完整提示词文本（新增「按需更新与自动提交」段落随文本一并展示、可复制）。
- 交互行为：点「启动提示词」展开/收起折叠块；点「复制继续讨论提示词」直接复制（不展开折叠块），成功 toast 反馈；剪贴板不可用时回退并提示展开后手动复制。提示词文本本身即交互载体，不新增其他控件。
- 状态反馈：复制成功显示「已复制，粘贴到任意会话即可接续同一讨论」；失败回退提示；读取讨论中按钮禁用防重复；读取失败展示原因与重试入口；讨论为空时展示空态说明。

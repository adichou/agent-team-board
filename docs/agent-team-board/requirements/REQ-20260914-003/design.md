# 设计 — REQ-20260914-003 优化讨论生成的提示词

> 由 Agent 在 /dev 开发前补充，人可随时批注。

## 背景

开放式讨论的启动/继续提示词由服务端拼装（`scripts/lib/oncall-store.mjs` 的 `buildStartPrompt` / `buildContinuePrompt`），经讨论详情抽屉折叠块展示、经「复制继续讨论提示词」入口复制。本需求为讨论 Agent 追加「按需更新文件并自动提交」的工作约定，不重构既有提示词内容。

## 方案

（技术选型、接口设计、影响面）

- 实现：`oncall-store.mjs` 新增内部函数 `fileUpdateCommitLines(id, extra = [])` 生成「按需更新与自动提交（每轮回答后检查）」段落；`buildStartPrompt` 在「讨论约定」节后插入，`buildContinuePrompt` 在「约束」行后追加（含一条续聊专属的目录边界说明）。既有章节逐行保留，零删改。
- 展示与复制走既有抽屉/剪贴板入口，`scripts/web/oncall.js` 与服务接口零改动（`discussionFull` 的 `startPrompt`/`continuePrompt` 即带新文本）。
- README 五个待确认项按以下默认收敛（保守口径，后续人工可放开）：
  1. 「不修改代码」放开范围：仅放开讨论明确支撑的文档、配置类文件，业务代码（源码逻辑）仍不改；既有「不修改代码」措辞原样保留，新段落中显式说明其指业务代码。
  2. commit 单号：硬性要求为讨论单号（ASK-YYYYMMDD-NNN，段落带实际单号）；关联 REQ/BUG 单号不强制（如明确相关可写入摘要）。
  3. push：不允许，只 commit（与项目既有自动提交口径一致，新段落明写「只 commit，不 push」）。
  4. 整理结论（`buildOrganizePrompt`）与收尾（`buildFinishPrompt`）提示词：不追加，既有内容保持不变。
  5. commit 消息格式：沿用 `git-flow.mjs` 的 `类型: 摘要 单号`（`commitSubjectOf`），新段落给出示例 `"doc: 更新导出说明 <讨论单号>"`。
- 续聊提示词原「只写入本讨论目录」与新约定（可更新讨论目录外的项目文档/配置）的冲突：既有措辞保留，新段落补一行说明该约束针对轮次与纪要，按需文件更新可写本项目内讨论明确支撑的文件、仍不串其他项目或讨论。
- 边界：不改看板条目状态机、不自动创建/接受需求/Bug 条目、轮次与纪要仍经 `atb disc round` / `atb disc minutes` 统一入口；无文件更新时明示无修改、不产生空提交；回答中展示本次 commit 消息（单号 + 摘要，建议含提交号）。

**开源选型（REQ-20260909-015）**：本次为纯提示词文本生成与追加，无运行时依赖引入，未使用开源库（无合适库的原因：无第三方库需求），不创建 licenses.md。

## 风险与边界

- 快照式「既有章节未被删改」断言（P4）锁定了现有措辞，未来合法改写提示词需同步更新该测试（属预期保护，防误删既有约定）。
- 待确认项均按保守默认实现，人工确认后如需整体放开（含业务代码）或允许 push，只需调整 `fileUpdateCommitLines` 文案与对应断言，不影响其余章节。
- 讨论目录内文件（纪要等）更新与 git 提交并存的场景：提示词口径已区分「轮次与纪要走 atb disc 统一入口」与「按需文件更新 + git commit」，不与看板自身落盘冲突。

# BUG-20260914-008 新建版本是关联条目重复提示。导入条目到已有版本一样重复提示，请修复

- 状态：submitted（待人工接受）
- 归属：独立 Bug（引入来源见 design.md）
- 创建：2026-09-14T04:38:44.075Z

## 现象

构建模块「版本计划」的两个选单侧拉面板中，同一条候选口径文案重复出现两次——一次在面板头部说明（副标题），一次在候选空态正文，读起来啰嗦且像 bug（见截图）：

![截图](attachments/paste-1789360686772.png)

截图为「添加条目」面板（导入条目到已有版本），同一面板内先后出现：

1. 头部说明：「仅已完成（done）且未纳入任何版本的需求单 / Bug 单可加入本版本（已纳入版本的条目不再出现）」
2. 空态正文：「暂无可纳入版本的条目：仅已完成（done）且未纳入其他版本的需求单 / Bug 单会出现在候选中」

「新建版本」面板同样如此（头部说明为「仅已完成（done）且未纳入任何版本的需求单 / Bug 单可纳入版本；全选只纳入有 commit 候选的条目」，空态正文重复同一段口径）。

代码位置（均为 `scripts/web/build.js`）：

- `renderPanel()`（约 800–831 行）：头部副标题渲染 `scope` 参数；候选为空且 `totalDone` 为 0 / 缺省时，正文渲染「暂无可纳入版本的条目：仅已完成（done）且未纳入其他版本的需求单 / Bug 单会出现在候选中」（约 813–815 行）——与头部口径重复。
- 两处调用（约 1090–1091 行）：`新建版本` / `添加条目` 面板各自传入的 `scope` 都含「仅已完成（done）且未纳入…版本的需求单 / Bug 单」口径。

补充事实：

- 重复只发生在「候选为空且无 done 条目（`totalDone` 为 0 或缺省）」的空态；`totalDone > 0`（done 条目均已被版本占用）时空态文案为「已完成的条目均已纳入版本计划：可从『计划中 / 失败』版本移出条目，或删除版本后重新纳入」（BUG-20260914-004 引入的两分支空态），不与头部口径重复；有候选的正常态只有头部一处口径，也无重复。
- 空态文案被既有测试断言引用：`scripts/tests/bug-build-candidates-done-only-20260913-001.test.mjs`（断言 `/暂无可纳入版本的条目/`）、`scripts/tests/bug-build-candidate-occupied-20260914-004.test.mjs`（断言同前缀、并断言不与占用态文案混用）。

## 复现步骤

前置：一个 git 仓库项目（看板已 `atb init`），且当前**没有任何已完成（done）状态的需求单 / Bug 单**（或候选接口返回前 `totalDone` 为 0 / 缺省的等价状态）。

1. 启动看板服务并打开 Web UI：`node scripts/atb.mjs serve --open`（`--dir` 指向该项目），在项目切换器中选择该项目。
2. 左侧导航进入「构建」模块，停在「版本计划」子页签。
3. 点击右上「＋ 新建版本」——右侧弹出「新建版本」面板：头部副标题出现「仅已完成（done）且未纳入…可纳入版本…」，正文空态再次出现「暂无可纳入版本的条目：仅已完成（done）且未纳入其他版本的需求单 / Bug 单会出现在候选中」——**口径重复出现两次**。
4. 关闭面板；在左侧版本列表任选一个已有版本（若没有，先用有 done 条目的仓库建一个，再回到无候选状态），右侧详情点「＋ 添加条目」——「添加条目」面板出现同样的重复（即截图场景：导入条目到已有版本）。
5. 对照：把某需求单推进到 done 且未纳入任何版本后再打开面板，候选列表正常显示时只有头部一处口径，无重复——说明问题仅在空态文案分支。

## 期望行为

- 同一候选口径（「仅已完成（done）且未纳入版本的需求单 / Bug 单…」）在单个面板内**只出现一次**：保留面板头部副标题（两面板各自现有文案），空态正文不再整段重复口径，改为简短空态说明（例如「暂无可纳入版本的条目」；最终文案以开发阶段定稿为准，待确认）。
- 「新建版本」与「添加条目」两个面板一并修复（用户报告的两处场景）。
- 不得丢失 BUG-20260914-004 的空态区分：`totalDone > 0` 时仍显示「已完成的条目均已纳入版本计划：可从『计划中 / 失败』版本移出条目，或删除版本后重新纳入」，不与「无 done 条目」空态混用。
- 有候选的正常态、加载中（「正在读取条目…」）、加载失败（错误 + 重试）等其他状态不受影响。

## 界面展示

可交互演示：[`./ui-demo.html`](./ui-demo.html)（单文件、浏览器直接打开；含「缺陷现状 / 期望修复后」对比开关）。

- 界面布局：还原构建模块「版本计划」页（工具栏「＋ 新建版本」+ 左版本列表 / 右版本详情），选单面板为右侧贴边侧拉抽屉（宽 min(420px, 92vw)、遮罩、头部标题 + 口径副标题 + 关闭键、正文候选区、底部主操作键），与 `scripts/web/style.css` 中 `rel-panel` / `bld-*` 范式一致。
- 交互行为：点「＋ 新建版本」/ 详情「＋ 添加条目」经短暂「正在读取条目…」加载后弹出面板；✕ 或点遮罩关闭；面板内提供状态切换（正常有候选 / 空态-无 done 条目 / 空态-均已被占用 / 加载失败重试）与「缺陷现状 ↔ 期望修复后」对比开关，正常态含全选 / 全不选、勾选条目、commit 下拉与「版本名称」输入。
- 状态反馈：加载中、加载失败（错误条 + 重试按钮，重试后恢复）、空态两分支（无 done 条目 / 均已被占用）、正常候选态；缺陷模式下空态正文整段重复头部口径（红色标注重复段），修复模式下仅头部一处口径、空态正文精简——直观对照修复前后差异；另附深 / 浅色主题切换（截图为深色）。

## 验收说明

1. 在「无 done 条目」的仓库状态下分别打开「＋ 新建版本」与版本详情「＋ 添加条目」面板：口径文案「仅已完成（done）且未纳入…」在整块面板中只出现一次（头部保留、正文不重复）。
2. 「done 条目均已纳入版本」状态（`totalDone > 0`）打开两面板：仍显示占用态文案「已完成的条目均已纳入版本计划：…」，与「无 done 条目」空态可区分（回归 BUG-20260914-004）。
3. 有候选的正常态：头部口径 + 候选列表 / 全选条 / 版本名称输入表现不变（回归）。
4. 加载中「正在读取条目…」、加载失败错误 + 重试行为不变（回归）。
5. 既有测试中空态文案断言（`scripts/tests/bug-build-candidates-done-only-20260913-001.test.mjs`、`scripts/tests/bug-build-candidate-occupied-20260914-004.test.mjs`）随文案精简同步调整并通过；两面板（新建 / 添加）口径单次出现的断言新增覆盖。
6. 以 `./ui-demo.html` 的「缺陷现状 / 期望修复后」对照演示作为人工核对口径。

## 根因分析

`runSearch()`（app.js）在 runs 视图只做「清 `state.batchSig` + 重渲染」：`renderBatchDrawer()` 据此重算关键词 `q = state.search.q`，但 `q` 仅传给存量深链 Codex 面板 `renderCodexPanel(q)`（入口已隐藏）；当前实际渲染的 `renderRefinePanel()` / `renderZcodeBatchPanel()` 不接收也不读取 `state.search.q`，其列表（`pendingQueueHtml`、`runAttemptsHtml`、排队批次节）恒为全量——输入关键词后候选队列、待处理队列、排队批次、本轮处理记录纹丝不动，与反馈条宣称的「前端过滤」不符。

## 方案

**开源选型（REQ-20260909-015）**：纯 vanilla JS 前端字符串过滤（trim + toLowerCase + includes），无第三方库可用场景；自研理由：无合适库（问题域为项目自有 DOM 渲染函数的参数接线，任何库都无法替代）。不引入开源库，不创建 licenses.md。

### 1. 接线方式：面板内部消费 `state.search?.q`（不改函数签名）

`renderRefinePanel` / `renderZcodeBatchPanel` 保持空参签名，函数体内以
`const ql = String(state.search?.q || '').trim().toLowerCase()` 取关键词（可选链兼容既有 vm 桩测试的最小 `state`）。理由：README「修复方向」本即「两面板的列表按 `state.search.q` 前端过滤」；且既有契约测试（refine-ui R12-8/9/10、batch-ui U16）以 `/function renderRefinePanel\(\)/` 空参正则提取函数源码在最小桩 vm 中执行，改参会破坏这些用例。`renderBatchDrawer` 对 `renderCodexPanel(q)` 的既有传参不动。

### 2. 过滤点与匹配字段（大小写不敏感、包含即命中；与 `renderCxRuns` 同口径）

| 列表 | 落点 | 匹配字段 | 无匹配空态 |
| --- | --- | --- | --- |
| 完善候选（启动态）/ 待完善队列（运行态）/ 待开发队列（启动态）/ 开发待处理队列（运行态） | `pendingQueueHtml(pending, { action, q })` 新增可选 `q`（缺省 `''` 零回归） | 条目编号 `id`、标题 `title` | 「没有匹配的待处理条目，清空搜索恢复。」 |
| 两面板本轮处理记录 | `runAttemptsHtml(records, total, kind, q)` 新增第 4 可选参数 | 执行编号 `runId`、条目编号 `itemId`、标题 `title`、执行器 `owner`（子代理会话名） | 「没有匹配的处理记录，清空搜索恢复。」 |
| 批量开发排队批次 | `renderZcodeBatchPanel` 内排队批次节 | 批次号 `batchId`、开发人员 `developer` | 「没有匹配的排队批次，清空搜索恢复。」 |

计数与标注口径（对齐 Codex 面板「（N 条被搜索过滤）」）：

- 待处理队列：命中标注 `（N 条被搜索过滤）` 挂在「待处理队列」标签后；「最近 X 条 / 共 N 条」随过滤收窄（共 = 命中数）；全量即空仍显示「暂无待处理条目。」，不与无匹配混淆。
- 处理记录：`（N 条被搜索过滤）` 挂在「本轮处理记录」标签后；「共 N 条」保持全量账面（`recordsTotal`，README 期望行为 6 的账面口径），过滤仅作用于已加载记录（服务端最近 5 条，与 Codex 面板过滤已加载 runs 同语义）；全量即空仍「暂无执行记录」。
- 排队批次：无排队批次时整节不显示（现状不变）；有批次但无命中时保留节并显示无匹配空态。

### 3. 明确不入过滤范围（保持全量口径）

- 两面板「概况」页签全部内容（当前条目、子代理会话、计数行、通知与操作按钮）；
- 启动区候选统计（「候选：已接受未完善 N 项」「已计划候选 N」）与启动按钮资格判定（按全量候选数）；
- `renderDevStartBar` 的「已计划队列（最旧优先）：…」预览行（启动说明文案，非列表）。

### 4. 反馈条文案对齐真实行为

`renderSearchFeedback` runs 分支文案改为「关键词在下方面板内前端过滤（编号 / 标题 / 执行器；排队批次含批次号），不发请求」。

### 5. 持续生效与恢复

过滤在每次 `renderBatchDrawer()`（`runSearch` 清签名重渲染 / 2 秒轮询 / 一二级页签切换）时按当时 `state.search.q` 重算；✕ / Esc / 删空关键词即恢复全量（`clearSearch` 既有链路重渲染）。快照恢复（REQ-20260910-001）与 Codex 深链（`renderCodexPanel(q)` / `renderCxRuns(q)`）不受影响、零改动。

## 风险与边界

- **共用函数加参的零回归**：`pendingQueueHtml` / `runAttemptsHtml` 新参数均可选缺省空串，既有三处/多处调用不传 q 时行为与输出逐字不变（既有 tasks-panel-26 K5/K6、refine-ui R12-11、batch-ui U15 断言零改动）。
- **计数口径分叉**：过滤后「共 N 条」在队列为命中数、在记录为全量账面——以「（N 条被搜索过滤）」标注弥合解释，测试 F2/F3 分别断言两种口径，防误读。
- **记录过滤仅作用已加载 5 条**：关键词若只命中未加载的历史记录，界面不出现该行（与 Codex 面板「加载更多」前同语义）；面板无加载更多入口，属展示上限既有口径，不在本 Bug 扩项。
- **空态混淆防护**：三种空态文案互斥（无匹配 → 清空恢复话术；全量空 → 暂无话术；无排队批次 → 整节隐藏），测试逐一断言。
- **手动验收依赖真实批次数据**：自动化以静态契约 + vm 渲染断言覆盖（F1–F7），「批量完善 / 批量开发 × 启动态 / 运行态」四组合的真机走查留人工验收（README 验收说明 1–3）。

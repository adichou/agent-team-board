# BUG-20260913-002 新建版本和版本查看界面的需求或 bug 如果标题过长，需要显示 tips

- 状态：以 status.json 与看板实时状态为准（本文仅完善说明）
- 归属：独立 Bug（引入来源见文末「关联」）
- 创建：2026-09-13T09:52:16.076Z

## 现象

构建模块（REQ-20260913-001，「版本计划」子页签）中，候选条目行的「单号 + 标题」在标题过长时被单行省略号截断，且截断处**没有悬浮提示（tips）**，鼠标悬停无法看到完整标题，长标题条目在界面上不可辨识全名。涉及两个入口，缺陷同源：

1. **新建版本侧拉面板**：版本计划列表右上「＋ 新建版本」打开的右侧面板，候选条目行截断且悬停无提示。
2. **版本查看界面的「＋ 添加条目」侧拉面板**：点左侧版本卡片查看右侧详情（空态文案即「点击左侧版本查看详情」），点「＋ 添加条目」打开的面板与新建版本面板**共用同一候选行渲染函数**（`build.js` `renderCandidateRows()`），截断与无提示现象相同。

代码核对（现状依据）：

- `scripts/web/build.js` 第 551 行：候选行标题为 `<span class="bld-cand-title">${esc(it.itemId)} ${esc(it.title || '')}</span>`，**未带 `title` 属性**。
- `scripts/web/style.css` 第 3026 行：`.bld-cand-title { flex: 1; min-width: 0; overflow: hidden; text-overflow: ellipsis; white-space: nowrap; }`——单行省略截断。行内另有复选框与 commit 下拉（第 3013 / 3024 行 flex 布局、第 3017 行下拉样式）挤占宽度，面板宽仅 `min(420px, 92vw)`（第 2959 行起），标题可展示空间有限。
- 对照（既有正确形态）：版本详情正文「关联条目与 commit」行的标题 `bld-item-title`（`build.js` 第 600 行）**已带** `title="${esc(it.title || '')}"`，同款截断样式下悬停可见完整标题——项目内已有可对齐的既定形态。
- 看板条目标题无长度上限（本 Bug 自身标题即超 30 字），候选行还前置 16 字符单号（如 `REQ-20260913-001`），长标题极易触发截断。

补充说明：版本详情正文条目行已有 tips；若提单人所指「版本查看界面」还包括正文条目行在特定浏览器 / 主题下的提示缺失，具体环境待确认（按当前代码查证，正文行已带 `title` 属性）。

## 复现步骤

1. 启动 Status Board 服务（`atb serve`，默认端口 8888）并在浏览器打开看板，顶部进入「构建」模块（默认「版本计划」子页签）；深浅色主题均可复现。
2. 准备数据：至少一条已完成（done）且标题较长（约 25 字以上）的需求单 / Bug 单，有已关联的 commit；另备一条短标题条目作对照。仅完成但无关联 commit 的条目也会出现在候选中（不可勾选，行内显示「暂无关联提交」），同样受截断影响。
3. 点版本计划列表右上「＋ 新建版本」打开侧拉面板，观察候选列表中的长标题条目：「单号 + 标题」单行显示、超宽处省略号截断。
4. 将鼠标悬停在截断的标题上：**无任何 tips / 悬浮提示**，无法看到完整标题（缺陷点）；短标题条目完整显示，不受影响。
5. 点左侧任一版本卡片查看右侧详情（无版本时先随意勾选并创建一个），点「＋ 添加条目」打开侧拉面板：候选行长标题同样截断且悬停无 tips（与新建版本共用渲染函数，现象一致）。
6. 对照既有形态：右侧详情正文「关联条目与 commit」区内的长标题条目行同样单行截断，但悬停会出现原生 tips 显示完整标题。

## 期望行为

- 新建版本、添加条目两个侧拉面板的候选条目行，标题被截断时**悬停须显示 tips**，与版本详情正文条目行的既有形态对齐（原生 `title` 属性或等效方案）。
  - **人工优化口径（本单实施时拍板）**：tips 内容**只显示完整标题、不含单号**，与详情正文条目行口径一致；行内展示口径不变，仍为「单号 + 标题」。
- 未截断的短标题条目行为不变（是否额外加 tips 不作要求，加了不算回退）。
- 布局不回退：候选行保持单行省略截断（不换行、不撑破侧拉面板与行高），复选框、commit 下拉、全选 / 全不选工具条位置与可用性不变。
- 安全不回退：tips 文案须经既有 `esc()` 转义后再进属性（标题可含引号 / 尖括号），防 HTML 注入，与项目现状口径一致。
- 功能零变化：候选口径（仅 done 条目、添加条目面板排除已在版本中的条目，BUG-20260913-001）、全选 / 全不选仅对有 commit 候选的条目生效并提示跳过数、勾选联动 commit 下拉启停、创建 / 添加校验与 toast 反馈等全部保持。

## 界面展示

- 布局：构建模块「版本计划」子页签为左版本列表 + 右详情分栏；右上「＋ 新建版本」与详情内「＋ 添加条目」各拉出右侧贴边通高侧拉面板（宽 420px），面板内自上而下为全选 / 全不选工具条、候选行列表（复选框 + 单号 + 标题 + commit 下拉）、（新建面板多一个）版本名称输入与错误提示。修复后候选行长标题截断处悬停显示完整标题 tips（不含单号）。
- 交互：可切换「缺陷现象 / 修复后（示意）」对照两种形态（作用于新建版本与添加条目两个面板的候选行）；可实际勾选条目、全选 / 全不选（仅对有 commit 候选的条目生效，并提示将跳过的无提交条目数）、切换 commit 下拉、填版本名并提交（toast 反馈）；「＋ 添加条目」从详情打开第二个面板。
- 状态反馈：正常——候选列表可勾选、已选计数即时更新；空——无已完成条目时显示「暂无可纳入版本的条目」空态；加载——面板内显示「正在读取条目…」；失败——读取失败显示错误与「重试」按钮；提交无勾选时面板内报错；另含深 / 浅色主题切换（两种主题下缺陷同样可见）。

[打开可交互演示](./ui-demo.html)。单文件离线演示，对照呈现缺陷现象（候选行长标题截断且悬停无提示）与期望修复后状态（截断处悬停显示完整标题 tips，不含单号，行内仍展示「单号 + 标题」，以详情正文条目行既有形态为准）；演示数据与加载 / 失败反馈均为模拟，不写入看板。

# BUG-20260915-013 REL Git 发布 local-precheck 误判看板目录内已跟踪文件为脏（porcelain 首行前导空格被 trim 吃掉）

- 状态：以 status.json 的系统记录为准。
- 归属：独立 Bug。
- 创建：2026-09-15T12:24:11.464Z

## 现象

REL Git 发布的本地预检读取 `git status --porcelain` 后，将整段输出 `trim()` 再按固定列解析。首行若是工作区修改、暂存区未修改的已跟踪文件，原始格式为 ` M path`；首个空格被移除后，`slice(3)` 得到的路径丢失首字符。

当该文件在 `docs/agent-team-board/` 内时，解析结果变成 `ocs/agent-team-board/…`，无法命中看板数据豁免规则。即使没有看板外的未提交修改，`local-precheck` 仍以 `dirty` 错误阻塞，错误文件列表也显示截断路径。发布无法继续。

### 代码核实与影响范围

- `scripts/lib/release-git.mjs`：`gitCmd` 返回 `r.stdout.trim()`；`stageLocalPrecheck` 通过该函数获取 porcelain，并用 `line.slice(3)` 提取路径。上述路径错位可从现有代码确认。
- `scripts/lib/product-release-git.mjs`：`worktreeDirtyFiles` 已直接按原始 stdout 分行，注释明确提醒不可整体 trim。它是修复后行为的参考。
- `scripts/tests/release-git.test.mjs`：已有真实临时 Git 仓库、bare 远端及 `runGitPipeline` 测试入口；G2 检查普通脏文件阻塞，但不足以覆盖首行看板内已跟踪修改。
- 登记说明记录：问题在 REQ-20260915-002 实施期间发现。发现条目不等于引入来源；最初引入提交、实际受影响发布记录与系统版本均为「待确认」。
- 本项是 Git 输出解析及预检判定问题，修复范围无需新增或调整界面布局、交互或组件；沿用现有阶段结果与错误展示。本文不将运行状态误判扩展为界面改造。

## 复现步骤

以下为开发阶段的复现操作说明，本轮文档完善未创建仓库、提交或执行发布。

1. 在隔离的临时测试仓库准备有效分支和提交、可访问的本地 bare 远端及 REL 发布配置；参考现有测试的 `mkEnv`、`newRun` 和 `full` 夹具。确保没有 detached HEAD、未完成 merge/rebase 等其他预检阻塞条件。
2. 在夹具准备阶段使 `docs/agent-team-board/repro.md` 成为已跟踪且已提交文件，再只修改该文件内容，不暂存；确保没有看板目录外的未提交变更。
3. 原样读取 `git status --porcelain`，确认首行是 ` M docs/agent-team-board/repro.md`（首字符为空格）。若不是首行，先调整隔离夹具；不得用 `.trim()` 验证原始输出。
4. 使用现有 REL `runGitPipeline` 入口执行到本地预检，在隔离环境观察 `local-precheck` 的结果。后续发布步骤仅使用临时本地远端。
5. 当前预期复现结果：该阶段失败，错误类型为 `dirty`，错误文件包含 `ocs/agent-team-board/repro.md`，后续推送未执行。
6. 对照检查：将同一原始 porcelain 字符串分别作整体 trim 后解析与保留首行空格解析，前者路径丢失 `d`，后者得到完整路径。将同一夹具交给产品发布的 `worktreeDirtyFiles`，应不将该看板文件列为脏文件。

## 期望行为

1. 解析保留 porcelain 的两个状态列及分隔空格，完整识别首行与后续行路径，不因首行位置或工作区修改状态而改变判断。
2. 只有看板数据目录内的已跟踪未暂存修改时，本地预检通过；看板数据豁免遵循现有规则，继续执行后续阶段。通过本地预检不代表整条发布已成功。
3. 看板外存在真实未提交修改时仍以 `dirty` 阻塞，错误文件列表保持完整路径，并沿用现有提交引导。
4. 预检不自动执行 add、commit、stash、丢弃修改或绕过其他仓库安全检查；预检失败不得触发推送。
5. 修复聚焦原始状态输出解析，不扩大目录豁免、不改变发布确认流程或远端操作策略。

- [ ] 预检失败场景确认远端引用未变化且未发起 push；验收记录区分本地预检结果与整条发布最终结果。

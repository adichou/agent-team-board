# BUG-20260915-010 需求或 bug 详情中的说明文档的讨论按钮生成的提示词最后没有换行

- 状态：accepted（已接受；实际状态以 status.json 为准）
- 归属：独立 Bug（引入来源见 design.md）
- 创建：2026-09-15T07:29:46.679Z

## 现象

**登记现象**：在需求或 Bug 详情中，对说明文档点「讨论」按钮，生成的提示词（复制到剪贴板、准备粘贴到 Agent 会话）**最后没有换行**——粘贴后光标停在末行行尾，用户直接输入的问题与提示词末行连排同一行，没有明确的换行分隔。

**当前代码核查（2026-09-15，均经源码与测试核实）**——标题所述「说明文档的讨论按钮」在代码里有两条提示词链路，现状不同：

1. **右键「💬 讨论」（需求 / Bug 详情抽屉「说明 / 设计 / 测试用例」文档页签，BUG-20260913-003 起 Bug 单同口径）——已修复，当前不复现。**
   提示词由前端 `buildDocRef` 组装（`scripts/web/app.js` 约 4740–4756 行），BUG-20260914-019（2026-09-14 22:50 修复、23:10 合并，早于本单登记约 16 小时）已把返回值改为 `lines.join('\n') + '\n'`——末尾恰一个换行。专项断言 T9（`scripts/tests/doc-ctx-discuss-req-20260914-004.test.mjs`：「以单个 `\n` 结尾且不以 `\n\n` 结尾」）当前通过。服务端静态资源 `Cache-Control: no-store`（`scripts/server.mjs` 约 404–408 行）、Electron 壳加载同一本地服务（`electron/main.mjs`），不存在带旧代码的缓存 / 打包副本。

2. **「文档讨论」区块的讨论按钮（需求详情「讨论纪要」页签，`scripts/web/req-disc.js`）——同类缺陷至今存在。**
   「开始讨论 / 启动提示词 / 讨论完毕 / 再次查看收尾提示词」按钮生成的启动 / 收尾提示词由服务端 `scripts/lib/req-disc-store.mjs` 的 `buildStartPrompt`（约 180–203 行）/ `buildFinishPrompt`（约 205–224 行）生成，两者均以 `].join('\n')` 返回、**末尾无换行**：末行分别是「三件都完整写完才算发布；看板检测到发布标记后才会读取展示，半成品不会被读取。」与「…不要直接修改 README.md、不要覆盖已归档纪要、不要改变需求状态。」。提示词面板「复制内容」按钮（`req-disc.js` 约 293 行 `copyPlain(ta.value)`）原样复制该文本，粘贴后光标停在末行行尾。BUG-20260914-019 修复时曾把这套提示词列为「范围边界（待确认），默认不改」——本单即该遗留缺口的追认。讨论（oncall）模块的启动 / 收尾提示词（`scripts/lib/oncall-store.mjs` 约 875 行起 / 926 行起，同样 `.join('\n')`）同口径无末尾换行。

3. **当前界面可达性**：讨论模块暂态隐藏（REQ-20260909-013：`scripts/web/app.js` 约 1088 行 `HIDDEN_VIEWS` 含 `'oncall'`；约 4314 / 4362–4365 / 4409 行据此不渲染「讨论纪要」页签与「文档讨论」区块、不挂载）——第 2 条链路当前在界面暂不可达（机制保留，恢复入口后即重新可达）；右键「💬 讨论」不受隐藏影响，需求与 Bug 详情当前均可用。

**待确认**：登记人观察到「末尾无换行」的具体入口与环境——若为右键「💬 讨论」，当前最新代码已不复现，可能是修复合并（2026-09-14 23:10）前的旧剪贴板 / 旧会话草稿，需复核；若指「文档讨论」区块按钮生成的启动 / 收尾提示词，缺陷在最新代码确实存在，按第 2 条链路修复。

## 复现步骤

前置：项目目录运行 `atb serve`（默认端口 8888，`ATB_PORT` 可覆盖），浏览器打开 `http://localhost:8888` 并选中该项目。

**路径 A：右键「💬 讨论」（标题字面入口——当前版本不复现，供复核）**

1. 打开任一需求或 Bug 详情抽屉，切到「说明」页签，待文档加载完成。
2. 在文档内容区右键 → 点「💬 讨论」→ 出现 toast「已复制 引用：README.md 第 x–y 行」。
3. 切到 Agent 会话输入框粘贴：当前版本光标**已在新行**（BUG-20260914-019 修复后口径），直接输入的问题另起一行。
4. 若在此步仍观察到光标停在末行「…（短哈希即可）。」行尾、输入的问题连排同一行：记录条目编号、时间与粘贴文本末行内容（是否含「讨论要求」四条指令，可判断新旧提示词），转「待确认」归因——排除旧剪贴板 / 旧会话草稿 / 旧环境后按实际复现信息重新定位。

**路径 B：「文档讨论」区块按钮（缺陷在最新代码仍存在；区块当前随讨论模块暂态隐藏，恢复入口后走 UI，或直接代码直证）**

1. （UI 路径，需先恢复讨论模块入口——恢复方式见 REQ-20260909-013 design.md）打开任一需求详情抽屉 →「讨论纪要」页签 →「文档讨论」区块。
2. 点「开始讨论」：生成讨论编号并展开「启动提示词 · 复制到 Agent 新会话」面板 → 点「复制内容」。
3. 粘贴到 Agent 会话输入框：光标停在末行「…半成品不会被读取。」**行尾，不在新行**；直接输入问题（不按回车）——问题与该末行连排同一行，即本 Bug 现象。
4. 点「讨论完毕」→「再次查看收尾提示词」→「复制内容」：同口径，末行「…不要改变需求状态。」后同样无换行。
5. （代码直证，无需 UI）`node --input-type=module -e "…"` 断言 `req-disc-store.mjs` 的 `buildStartPrompt` / `buildFinishPrompt` 返回值不以 `'\n'` 结尾（两函数末尾均为 `].join('\n')`，约 202 / 223 行）。
6. 自动复制失败回退路径（可选）：复制失败时面板提示「自动复制失败，文本已选中，请按 ⌘C / Ctrl+C 手工复制」，textarea 全选手工复制的结果同样末尾无换行。

## 期望行为

- 所有「讨论」入口生成并复制到剪贴板的提示词，**末尾恰追加一个换行符 `\n`**（与 BUG-20260914-019 对 `buildDocRef` 的修复同口径）：用户粘贴后光标已在新行，直接输入的问题与提示词有明确的换行分隔。
- 只在末尾追加**一个**换行符：不追加两个及以上（避免多余空行），不在开头 / 中间加空行；提示词其余内容一字不变。
- 具体到本单核实的仍存缺陷链路：`scripts/lib/req-disc-store.mjs` 的 `buildStartPrompt` / `buildFinishPrompt` 返回值以单个 `\n` 结尾且不以 `\n\n` 结尾；前端「复制内容」按钮与自动复制失败的手工复制（textarea 全选）承载同一文本，自动生效。讨论（oncall）模块同名两函数（`scripts/lib/oncall-store.mjs`）是否随本单一并修复——**待确认**（同缺陷同口径，建议一并，以免恢复入口后再次登记同类 Bug）。
- 右键「💬 讨论」链路维持 BUG-20260914-019 修复后行为**不回退**（含 T9 断言继续通过）。
- 纯提示词文本追加换行：不新增 API、不改状态机、不改样式、不改其他提示词内容。

## 验收说明

1. **提示词末尾断言（先红后绿）**：`buildStartPrompt` / `buildFinishPrompt`（及经范围确认纳入的 oncall 同名函数）返回值 `endsWith('\n')` 且不以 `'\n\n'` 结尾，其余内容与现状逐字一致。
2. **粘贴分隔验证**（恢复讨论模块入口后走 UI）：「开始讨论 / 启动提示词 / 讨论完毕 / 再次查看收尾提示词」四入口复制的提示词粘贴后光标位于新空行，直接输入的问题另起一行；末行与问题首行之间恰一个换行、无多余空行。
3. **回退一致**：自动复制失败时提示词面板 textarea 全选（⌘C / Ctrl+C）手工复制的结果同样末尾带一个换行。
4. **零回退**：右键「💬 讨论」链路 T7 / T9 回归通过；提示词面板收起、toast 文案、`copyPlain` 双回退、讨论状态机与轮询行为不变。
5. **测试同步**：`scripts/tests/req-disc-store.test.mjs`、`discussion-prompt-commit-20260914-003.test.mjs`（oncall，若纳入）补末尾换行断言，`node scripts/tests/run-all.mjs` 全量通过。
6. **待确认消解**：与登记人核对实际观察入口；若确认右键链路在最新版本仍无换行（已排除旧剪贴板 / 旧环境），以复现信息为准补充定位后再验收。

## 界面展示

可交互演示：[`./ui-demo.html`](./ui-demo.html)（单文件、内联 CSS / JS、无外网依赖、无构建步骤，浏览器直接打开可交互；数据为模拟，不连真实看板、不写任何记录，粘贴按钮仅向演示输入框插入文本、不触系统剪贴板）。

- **界面布局**：左侧为需求 / Bug 详情抽屉文档页签模拟（「说明」页签内容区可右键弹「💬 讨论」菜单，可选中文字或整块引用），右侧为 Agent 会话输入框（「粘贴提示词」+ 直接输入问题），下方「最终消息预览」以不可见字符标记（⏎）可视化末尾换行的有无；顶部提供「缺陷态 / 修复态」模式切换与抽屉类型（需求 / Bug）切换。
- **交互行为**：右键「💬 讨论」按当前模式生成提示词 → 会话框「粘贴提示词」→「模拟输入问题」：缺陷态问题接在提示词末行同一行（红色标界），修复态问题自动另起一行（绿色标界）；另有「文档讨论区块」面板模拟「开始讨论 / 启动提示词」「讨论完毕 / 收尾提示词」按钮，其提示词随全局模式切换（缺陷态＝当前代码现状无末尾换行，修复态＝本单期望），并标注「当前版本该区块随讨论模块暂态隐藏，机制保留」。
- **状态反馈**：复制成功 toast「已复制 引用：README.md 第 x–y 行」；文档状态可切「已就绪 / 加载中 / 未创建 / 加载失败」，后三者右键不弹讨论菜单（口径同现状）；勾选「模拟自动复制失败」演示错误 toast 与手动复制引导（只读 textarea 全选，标注末尾换行有无）；深浅色随系统并可手动切换。

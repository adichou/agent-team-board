# BUG-20260908-018 执行记录为什么没有显示完所有的单

- 状态：submitted（待人工接受）
- 归属：独立 Bug（引入来源见 design.md）
- 创建：2026-09-08T14:06:15.324Z

## 现象

Web 看板「任务」模块（REQ-20260907-004）的需求完善面板（REQ-20260907-003）中，「执行记录」列表最多只显示最新 5 条 run 记录：批次处理的条目超过 5 个时，更早的执行记录在界面上不可见——既没有「共 N 条」总数提示，也没有开发批次面板那样的「加载更多」入口；而同一面板的「计数」行显示的 完成/失败/出局 合计可以远大于 5，两处对不上，看起来就像「没有显示完所有的单」。

定位线索（真实源码路径）：

- 前端渲染截断：`scripts/web/app.js` 的 `refineRecordsHtml()`（约 3509–3522 行）直接渲染 `/api/refine/current` 返回的 `records`，无分页控件；对照开发批次 `recordsHtml()`（约 3617–3638 行）有 `recordsTotal` 与「加载更多（x/N）」按钮。
- 后端源头截断：`scripts/lib/refine-store.mjs` 的 `refineSummary()`（约 934 行）以 `{ offset: 0, limit: 5 }` 调用 `listRefineRuns()`，且返回体不含 `total`；`/api/refine/current`（`scripts/server.mjs` 约 1470–1483 行）原样透传这 5 条。
- 既有分页接口未被使用：`/api/refine/records`（`scripts/server.mjs` 1487–1496 行，支持 offset/limit，上限 100）前端从未调用。
- 真实数据佐证：`docs/agent-team-board/refine/runs/` 下 RFB-20260908-009 有 18 条 run 记录、RFB-20260908-008 有 5 条；前者在面板最多只能看到 5 条。

## 复现步骤

1. 启动看板服务并打开 Web 界面：`node scripts/server.mjs`（端口以命令输出为准）。
2. 准备一个终态 run 记录数 > 5 的完善批次，任选其一：
   - 新建数据：在「任务」模块 → 需求完善启动区创建完善任务（候选 ≥ 6 项），派子代理逐项领取并回执 done/fail，累计产生 ≥ 6 条终态 run（`docs/agent-team-board/refine/runs/<runId>/run.json`，`batchId` 均为该批次）；
   - 存量数据：对 RFB-20260908-009 调 `GET /api/refine/current?batchId=RFB-20260908-009` 或 `GET /api/refine/records?batchId=RFB-20260908-009` 对照——records 分页接口能列出 18 条，current 的 `records` 只有 5 条。（待确认：面板 UI 只显示队列头批次，历史批次暂无切换入口，故存量批次需经 API 或在 UI 显示该批次时观察。）
3. 打开「任务」模块 → 需求完善子面板，查看「执行记录」区。
4. 实际结果：列表恒为最新 5 行，更早的记录无处可看；无「共 N 条」提示、无「加载更多」按钮，而「计数」行显示的 完成/失败/出局合计 > 5。

## 期望行为

1. 完善面板「执行记录」可完整查看当前批次的执行记录：直接显示全部，或对齐开发批次面板的分页交互——底部显示「加载更多（已加载 x / 共 N）」，点击经既有 `/api/refine/records` 增量拉取，N 与该批次 run 总数一致。
2. 列表与计数自洽：每个有终态回执（完成/失败/出局）的条目都能在执行记录中找到对应行，点击条目编号可跳转其文档；记录行保留现有信息（结果 chip、owner、时间、summary/reason）。
3. 首屏数据量可控：初始只取 5 条的做法本身可保留（性能考虑），但必须给出总数与补齐手段，不允许出现「计数显示 10、列表只有 5 且无任何入口」的静默截断。

## 验收说明

1. 用终态 run > 5 的批次（如 RFB-20260908-009，18 条）验证：完善面板的执行记录可完整查看——一次性全量，或经「加载更多」分页看完全部；末尾总数提示与该批次 run 记录数一致（18）。
2. 抽查 2 条修复前被截断的最早记录：条目编号可点击跳转到对应条目文档，结果 chip、owner、时间、summary/reason 显示正常。
3. 回归：run ≤ 5 的批次（如 RFB-20260908-008）显示不变；无 run 的批次仍显示「（暂无执行记录）」；开发批次面板 `recordsHtml()` 的「加载更多」分页不回归。
4. 主轮询刷新（`refreshRefine()`）与「加载更多」的状态共存：刷新重渲染后已加载的记录不丢失或可恢复（具体交互以开发阶段 design.md 方案为准，待确认）。

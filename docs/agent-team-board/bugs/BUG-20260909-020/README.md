# BUG-20260909-020 app 版本无法按住标题栏进行移动，请修复

- 状态：accepted（已接受；本轮仅完善说明，未实施修复）
- 归属：独立 Bug（引入来源见 design.md）
- 创建：2026-09-09T15:54:48.047Z

## 现象

macOS 上以 Electron 桌面壳运行「app 版本」（项目根 `npm run app`，即 `electron .`，REQ-20260905-001）时，窗口**无法通过按住标题栏拖动来移动位置**：壳层建窗使用 `titleBarStyle: 'hiddenInset'`（`electron/main.mjs` 第 27 行），原生标题栏被隐藏、红黄绿交通灯悬浮于页面左上，看板顶栏 `.topbar` 在视觉上承担了标题栏的角色；但按住顶栏（logo「▦」、标题「智能体团队看板」、项目路径一带，或顶栏其余空白处）向任意方向拖动，窗口纹丝不动。

根因方向明确：`hiddenInset` 隐藏原生标题栏后，窗口拖动依赖页面内容声明的**拖动区**（CSS `-webkit-app-region: drag`），而全项目源码（`electron/`、`scripts/`，排除 `node_modules`）检索 `-webkit-app-region` / `app-region` **零命中**——壳层唯一的注入样式 `TRAFFIC_LIGHT_INSET_CSS` 只做交通灯让位（`.topbar { padding-left: 78px; }`，BUG-20260905-003 口径），web 业务样式也不含任何拖动区规则。即页面内不存在任何可拖区，窗口因此无法按住「标题栏」移动。

「app 版本」指 Electron 桌面壳；浏览器直连 `http://127.0.0.1:8888` 时窗口由浏览器自己的标题栏/系统窗口管理，不受此缺陷影响，属对照口径。

### 核实依据（源码与看板记录，2026-09-10 核对）

- `electron/main.mjs` 第 24–37 行：`new BrowserWindow({ width: 1360, height: 850, titleBarStyle: 'hiddenInset', show: false })`；未设置 `movable` 等可移动性属性（默认可移动，缺陷不在窗口属性，而在无拖动区）。
- `electron/shell-css.mjs` 第 6–9 行：壳层注入样式仅 `.topbar { padding-left: 78px; }`，无 app-region 规则；`electron/main.mjs` 第 33–35 行经 `webContents.insertCSS` 注入（每次 `did-finish-load` 重注入，含 Cmd-R 重载）。
- `scripts/web/index.html` 第 14–31 行：顶栏结构 `.brand`（`.logo-badge` = logo「▦」 + 实时状态点 `#pollState`；`.brand-text` = 标题 + `#dataDir` 项目路径）居左、`.top-actions`（`#projectSel` 项目切换器 / `#cxPendingBadge` 待处理徽标 /「＋ 新建」）居右。
- `scripts/web/style.css` 第 92–102 行：`.topbar` 基础规则（`padding: 10px 18px`）；第 1157–1159 行 `@media (max-width: 640px)` 竖屏分支覆盖为 `8px 12px`——均无 app-region。
- `scripts/web/app.js`：`#projectSel` 有 `change` → `switchProject`（第 4798 行）；`#btnNew`、`#cxPendingBadge` 为按钮；`#pollState` 仅更新文本与 `title` 悬停提示（第 1165–1195 行）；`#dataDir` 仅文本展示（第 1326 行）——即顶栏内的可交互控件集中在 `.top-actions`。
- 全仓 grep（`electron/`、`scripts/`，排除 `node_modules`）：`-webkit-app-region` / `app-region: drag` 零命中。
- `scripts/tests/electron-shell.test.mjs`：V2 契约断言 `hiddenInset`（第 108–114 行）、V4 注入契约断言让位样式（第 134–158 行）；无任何拖动区相关断言（本单修复应考虑补契约）。
- 「hiddenInset 下窗口拖动依赖页面 drag region」属 Electron/macOS 平台通用机制；本轮未启动 Electron 实测（约定不自动运行 app），「完全不可拖」的结论基于源码静态核查与用户报告一致，是否存在个别可拖边缘区域（如交通灯周围原生残留热区）**待确认**，确切行为留待开发阶段 design.md 归因。

## 复现步骤

前置：macOS、本项目依赖已安装（Electron 37）。

1. 项目根执行 `npm run app` 启动桌面壳，等待看板页加载完成（顶栏出现蓝色 logo、标题与项目路径）。
2. 按住顶栏品牌区（logo「▦」/ 标题「智能体团队看板」/ 项目路径一带，避开左上交通灯与右侧控件）向任意方向拖动 → 窗口不移动，即为标题所述缺陷。
3. 换顶栏其他空白处、乃至页面任意位置按住拖动 → 同样无法移动窗口（全页无拖动区）。
4. 对照检查窗口其他操作仍正常：拖窗口边缘可调整大小、左上交通灯可关闭/最小化/缩放——确认窗口未进入不可操作状态，缺陷仅限「按住移动」。
5. 对照实验：浏览器打开同一服务 `http://127.0.0.1:8888` —— 窗口移动由浏览器自身标题栏完成，不受影响。
6. 记录环境：窗口默认 1360×850；深 / 浅色外观与 ≤640px 窄宽度下的表现差异**待确认**（理论上无差异，源码无外观相关分支）。

## 期望行为

1. **按住顶栏即可移动窗口**：桌面壳窗口内，按住 `.topbar`（至少覆盖品牌区 `.brand` 及顶栏空白处；顶栏整体纳入还是仅品牌区，由开发阶段 design.md 定夺）拖动即可移动窗口位置，手感与原生标题栏一致。
2. **顶栏内可交互控件不受影响**：`#projectSel` 项目切换、`#cxPendingBadge`、`#btnNew`「＋ 新建」保持可点击 / 可展开（对应 CSS 需 `no-drag`）；模块导航 `.module-nav` 与页面其余区域默认不纳入拖动区，避免与列表 / 导航交互冲突（是否纳入待开发阶段定夺）。
3. **实现层约束（沿 BUG-20260905-003 口径）**：拖动区样式应经壳层注入（`webContents.insertCSS` 一类机制，扩展 `TRAFFIC_LIGHT_INSET_CSS` 或新增常量由开发阶段定夺），web 业务代码零改动，浏览器直连不加载拖动区规则、不受影响。
4. **持续有效**：首次加载、Cmd-R 重载（`did-finish-load` 会重新注入，参照 REQ-20260910-001 场景）、任意窗口宽度（含 ≤640px 竖屏分支）、深浅色外观下拖动区均生效；与交通灯让位（`padding-left: 78px`）共存，交通灯按钮自身仍可点击。
5. **取舍点留档**：拖动区会抑制区内鼠标事件——`#pollState` 状态点与 `#dataDir` 路径的 `title` 悬停提示、路径文本选择在纳入拖动区后的取舍**待确认**，由开发阶段 design.md 明确（不在此预判）。

## 界面展示

界面布局与状态反馈的文字说明（对照缺陷现状与修复后期望）：

- 界面布局：macOS 壳窗口自上而下为「看板顶栏 `.topbar`（左上：交通灯悬浮；左：logo「▦」+ 右上角实时状态点 + 标题「智能体团队看板」+ 等宽字体项目路径；右：项目切换器 / 待处理徽标 /「＋ 新建」）→ 模块导航（讨论 / 需求 / 任务 / 文件 / 设置）→ 列表工作区」。缺陷现状：整条顶栏（乃至整页）无任何拖动热区，按住拖动窗口不动；修复后期望：顶栏成为拖动热区（右侧控件除外），按住即可拖动窗口，交通灯与让位区不受影响。
- 交互行为：「缺陷现状 / 修复后期望」两种形态切换对照（缺陷态按住顶栏拖动窗口纹丝不动并给出提示；期望态按住顶栏即可在演示桌面内移动窗口）。「桌面壳（app）/ 浏览器直连」环境对照（浏览器形态带独立标题栏，窗口移动不受缺陷影响）。顶栏内控件（项目切换、「＋ 新建」）在任何形态下保持可点，验证拖动区不误伤交互；交通灯关闭/最小化/缩放在任何形态下可用。「重新加载页面」按钮模拟 Cmd-R，经加载态后回到当前形态（验证拖动区在重载后是否保持）。列表「正常 / 空 / 服务离线」三态切换；深 / 浅色外观切换（默认跟随演示页偏好）。
- 状态反馈：正常——绿色状态点「● 实时」悬于 logo 右上角，列表正常渲染；空——列表区显示项目未初始化空态卡；加载中——重载时顶栏与列表以「页面加载中…」占位过渡；失败（离线）——状态点转灰「○ 服务离线」，列表停止刷新并提示；拖动动作即时反馈——缺陷态抖动提示「窗口未移动（无可拖区）」、期望态窗口跟手移动，操作日志逐条记录关键动作。

可交互演示：[./ui-demo.html](./ui-demo.html)（单文件、无外网依赖、无构建，浏览器直接打开；含缺陷 / 期望形态对照、桌面壳 / 浏览器直连对照、顶栏拖动与控件交互、重载加载态、空态与离线态、深浅色切换和操作日志）。演示为缺陷现状与期望形态的示意，最终修复方案以开发阶段 design.md 为准。

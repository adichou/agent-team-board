# BUG-20260914-003 为什么会显示无其他本地分支的？main 分支应该是要显示的

- 状态以本条目 status.json 和看板为准。
- 归属：独立 Bug（引入来源见 design.md；涉及界面为构建模块「分支浏览」子页，由 REQ-20260913-001 建立）。
- 创建：2026-09-14T02:47:19.501Z。

## 现象

![截图](attachments/paste-1789354024957.png)

截图为构建模块「分支浏览」子页（左分支列表 + 右提交记录分栏）：

1. 「本地」分组只显示一行 `dev`（加粗并带「当前」标识），其下紧接着显示灰字「（无其他本地分支）」——用户预期应出现的 `main` 分支完全没有出现。
2. 「远端」分组显示「（无远端分支：先「同步远端」或推送本地分支）」。
3. 界面上没有任何关于 main 分支去向的解释；而同模块「版本计划」的核心操作「合并入 main」依赖本地 main 存在，用户在此界面上无从得知 main 缺失。

排查核实（已对照源码与本仓库 git 状态，供开发阶段归因）：

- **显示链路本身无缺陷**：后端 `listBranches()`（scripts/lib/build-git.mjs 约 54–63 行）用 `git branch --format=%(refname:short)` 取本地分支、`git branch -r` 取远端分支（排除 `origin/HEAD`）；前端 `renderBranchesPane()`（scripts/web/build.js 约 962–1010 行）把「当前分支行 + 其余本地分支行（各带「推送」按钮）」渲染进「本地」分组，其余分支为空时才显示「（无其他本地分支）」（约 984 行）。即：**若本地真的存在 main，界面会显示它**。
- **本仓库本地确实没有 main 分支**：`git branch` 仅列 `dev`；`.git/refs/heads/` 下仅 `dev`；`git rev-parse --verify refs/heads/main` 失败。远端 origin（GitHub adichou/agent-team-board）为空仓库（`git ls-remote origin` 无任何引用），本地亦无任何 `refs/remotes` 跟踪分支——「远端」分组空态同样属实。
- **main 从未出生的原因（代码注释已写明）**：`ensureDevWorkflow()`（scripts/lib/git-flow.mjs 约 68–86 行）在空仓库上执行 `git init -b main` 后立即 `git switch -c dev`，注释明确「空仓库（HEAD 未出生）时 `git switch -c dev` 等价于把未出生分支改名，首个提交自然落在 dev」——首个提交落在 dev，`refs/heads/main` 从未被创建。本仓库 reflog 多次「commit (initial)」均落在 dev，与该口径一致。
- **连带影响**：构建模块「合并入 main」前置校验 `precheckMerge()`（scripts/lib/build-git.mjs 约 126–137 行）要求 `refs/heads/main` 存在，main 缺失时报「main 分支不存在」——REQ-20260913-001 的核心流程「版本计划合并入 main」在本仓库当前状态下不可用，而分支浏览界面对此无任何提示。

结论：这不是分支列表漏列的显示缺陷，而是「用户预期 main 存在并显示」与「本仓库初始化工作流下 main 从未出生、界面无任何提示」之间的落差；修复方向（补建 main / 界面提示引导）由开发阶段 design.md 定案。

## 复现步骤

前置：agent-team-board 仓库本地分支仅 `dev`（终端 `git branch` 可验证，`git rev-parse --verify refs/heads/main` 应失败——本仓库当前即此状态）。

1. 打开 Agent Team Board 看板（Web 或 Electron 端），顶栏切到「构建」页，切到「分支浏览」子页签。
2. 观察「本地」分组：仅显示 `dev`（带「当前」标识），下方显示「（无其他本地分支）」。
   - **实际结果**：main 完全不出现（与截图一致），且界面无 main 缺失的任何解释。
3. 终端对照：`git branch` 仅列 dev、`git rev-parse --verify refs/heads/main` 报错——界面与 git 实际状态一致，即 main 不显示的直接原因是仓库本地确实没有 main，而非列表漏列。
4. 连带影响复现：切到「版本计划」子页签，对任一版本点「合并入 main」→ 报错「main 分支不存在」（main 缺失使该核心操作不可用）。
5. 对照场景（显示链路正确性验证）：临时执行 `git branch main` 创建本地 main（验证后可 `git branch -D main` 删除），回到分支浏览点「刷新」——main 出现在「本地」分组并带「推送」按钮，证明分支列表会如实显示已存在的本地分支。

## 期望行为

- **分支列表如实反映 git 状态**：「本地」分组显示当前分支（置顶带「当前」标识）与全部其余本地分支（各带「推送」操作）；「（无其他本地分支）」仅在本地确实没有其他分支时出现；「远端」分组同理。该链路当前已正确（见现象排查），修复不得破坏。
- **main 缺失不应成为不可解释的状态**：构建模块核心流程依赖本地 main（「合并入 main」，REQ-20260913-001 口径）。期望最终形态为以下方向之一或组合，具体由开发阶段 design.md 定案：
  - a) **仓库侧**：本仓库补建 `main` 分支（基点选择如 dev 当前提交 / 初始提交，以及是否推送远端，由 design.md 落定）——补建后分支浏览「本地」分组应能看到 main；
  - b) **产品侧**：main 缺失时分支浏览给出明确提示 / 引导（提示文案与位置待确认），口径与「合并入 main」的「main 分支不存在」报错一致，消除「main 应该显示却没有」的困惑。
- 无论采用哪种方向，验收时「为什么看不到 main」必须有确定答案：存在则显示，缺失则可解释。

## 验收说明

1. **列表一致性**：在本地含 main 与其他分支的仓库（含本仓库补建 main 后）打开分支浏览——「本地」分组完整列出 main 等分支，当前分支置顶带「当前」标识，其余本地分支带「推送」；显示与 `git branch` 输出一致。
2. **main 缺失处理落地**：按 design.md 定案口径验收——
   - 若定案补建 main：本仓库分支浏览显示 main；「合并入 main」前置校验通过（不再报「main 分支不存在」）；若定案推送远端，「远端」分组出现对应 `origin/main`；
   - 若定案界面引导：在无 main 的仓库打开分支浏览，能看到 main 缺失的明确提示（文案 / 位置以 design.md 为准），且与「合并入 main」报错口径一致。
3. **空态正确性**：「（无其他本地分支）」仅当本地无其他分支时显示；「（无远端分支：先「同步远端」或推送本地分支）」仅当无远端分支时显示——提示与真实 git 状态不出现矛盾。
4. **不回归**：分支浏览其余能力不受影响——点击分支查看提交记录（hash / 说明 / 作者 / 时间）、「同步远端」（fetch --all --prune，执行中禁用防重复、成功 / 失败 toast）、「推送」确认与执行、分支列表加载中 / 读取失败重试、非 git 仓库引导空态（对齐 REQ-20260913-001 验收口径）。
5. **回归测试**：`node scripts/tests/run-all.mjs` 全量通过；若改动前端渲染或新增提示，补充对应断言（现有测试对本场景的覆盖范围待确认）。

## 界面展示

**界面布局**：看板顶栏「构建」页 → 「分支浏览」子页签，左右分栏——左侧分支列表（头部工具行：「⟳ 同步远端」按钮[执行中禁用并显示「同步中…」]与「刷新」按钮；下方「本地」分组 = 当前分支行[加粗 + 绿色「当前」标识] + 其余本地分支行[右端「推送」按钮]，分组内无其他分支时显示「（无其他本地分支）」；「远端」分组 = `origin/xxx` 行，为空时显示「（无远端分支：先「同步远端」或推送本地分支）」）；右侧所选分支的提交记录（头部分支名 + 「刷新」，列表行 = 短 hash + 提交说明 + 作者 · 时间；未选分支时提示「点击左侧分支查看提交记录」）。

**交互行为**：点左侧分支行（键盘可达）懒加载右侧提交记录；「同步远端」执行 fetch --all --prune 后刷新列表；本地分支「推送」先弹确认框（目标远端 / 分支名，首推说明将建立上游跟踪）再执行；「刷新」重读分支列表。本 Bug 缺陷所在：本仓库本地仅 dev 时「本地」分组显示「（无其他本地分支）」而 main 无踪影，且无任何 main 缺失提示——而「合并入 main」实际会报「main 分支不存在」。

**状态反馈**：分支列表加载中显示「加载分支中…」；读取失败显示「分支读取失败：…」+「重试」按钮；提交记录加载中 / 失败 / 空分别提示；同步执行中按钮禁用防重复、成功「✓ 已同步远端（fetch --prune）」/ 失败显示原因；非 git 仓库显示引导空态（git init / atb init）。

**可交互演示**：[./ui-demo.html](./ui-demo.html)——单文件、无外网依赖，浏览器直接打开。内含仓库情景切换（缺陷现状：本地仅 dev 显示「（无其他本地分支）」／期望 A：补建 main 后 main 出现在本地分组／期望 B：main 缺失但给出明确提示引导／对照：多分支 + 远端正常）与分支列表状态切换（正常 / 加载中 / 读取失败重试 / 非 git 仓库空态），可点分支查看提交记录、触发「同步远端」（含失败模拟）与「推送」确认流程，直观对照「为什么看不到 main」在缺陷与修复两种形态下的差别（期望 A / B 为候选方向，最终口径以 design.md 为准；演示数据为模拟）。

# BUG-20260913-004 版本的提示词与回答回填，合并入 main 两个按钮位置需要改到左侧列表项目中，参考需求列表的设计。

- 状态以本条目 status.json 和看板为准。
- 归属：独立 Bug（引入来源见 design.md；被参照的既有设计为需求列表行内操作按钮，`scripts/web/app.js` `reqRowEl`，操作图标化口径见 BUG-20260910-007；涉及功能由 REQ-20260913-001 建立）。
- 创建：2026-09-13T11:47:36.031Z。

## 现象

构建模块「版本计划」页签（`scripts/web/build.js`，左版本列表 + 右版本详情双栏）的两个关键操作按钮渲染在**右侧详情底部** `footer.rel-acts`（`renderDetail` 内，约 629–630 行）：

- `#bldAnswerBtn`「提示词与回答回填」：打开两段式回填弹窗（上段复制提示词、下段粘贴回答解析回填）。
- `#bldMergeBtn`「合并入 main」/「重试合并入 main」：打开合并确认弹窗。

由此产生两类问题：

1. **入口位置问题**：两个按钮随「选中版本」联动——必须先点击左侧某张版本卡片、右侧出现详情后才可见、可点；未选中时右侧只有「点击左侧版本查看详情」占位，用户从列表上完全看不出每个版本有哪些操作。这与需求模块「操作按钮直接放在列表卡片内」的既有设计不一致：需求列表行（`reqRowEl`）把操作按钮（⧉/✓/✎/🗑，图标化 + `aria-label`/`title`）放在每张卡片顶部 `card-top` 行的 `row-acts` 区，无需打开详情即可对任意行操作，且点击按钮不触发行选中（`e.stopPropagation()`）。
2. **文案问题**：「提示词与回答回填」按钮文案冗长且不直观，应改为「AI 完善」（本单现象栏口径）；`scripts/web/i18n.js` 第 25 行对应的英文词条 `'提示词与回答回填': 'Prompt & answer backfill'` 也需同步调整。

另需注意：按钮迁入列表卡片后，同一操作不能在详情底部与列表卡片两处重复渲染，否则禁用/文案状态（随版本 status 与 `mergeBusy` 变化）会出现双入口漂移。

## 复现步骤

1. 启动 Status Board（`/board` 或 `node scripts/server.mjs`），打开一个 git 仓库项目，进入「构建」模块的「版本计划」页签（`view=build`），项目内已有至少一个版本计划（无版本可先点「＋ 新建版本」从 done 条目创建）。
2. 观察左侧版本列表卡片：卡片上只有名称 / 状态 chip / 元信息（`rel-card` 的 `.t` 与 `.meta`），没有任何操作按钮。
3. 观察右侧：未选中任何版本时显示「点击左侧版本查看详情」占位——此时界面上不存在「提示词与回答回填」「合并入 main」两个入口。
4. 点击左侧任一版本卡片选中，右侧详情底部出现「提示词与回答回填」「合并入 main」两个按钮；换选另一版本，按钮内容随选中版本切换。
5. 核对文案：按钮显示为「提示词与回答回填」而非「AI 完善」。
6. 对照组：进入需求模块需求列表——每张列表卡片顶部行即带操作按钮（⧉ 复制 / ✓ 接受 / ✎ 编辑 / 🗑 删除），无需打开详情即可操作任意一行；两处操作入口设计不一致。

## 期望行为

参照需求列表的行内操作设计（`reqRowEl`），把两个按钮从右侧详情底部**移到**左侧版本列表的每个版本卡片内：

1. **位置**：每张版本卡片（无论是否选中）直接渲染本版本的两个操作按钮；点击按钮操作的是**按钮所在卡片**的版本（如对卡片 B 点「AI 完善」，打开的弹窗标题/内容为版本 B，与当前选中的版本 A 无关），且点击按钮不得触发卡片选中（选中态保持不变）。实现上可沿用列表现有口径：`.rel-list` 点击处理已忽略按钮点击（`e.target.closest('button')` 即返回），新按钮配合 `data-ver-id` 绑定或事件委托即可，具体落法 design.md 定稿。
2. **文案**：「提示词与回答回填」按钮改为「AI 完善」；按钮 `title` 提示语、`scripts/web/i18n.js` 词条同步更新。回填弹窗内部标题「提示词与回答回填（BLD-…）」是否一并改名：待确认（本单按现象栏口径只锁定按钮文案，建议弹窗同步改「AI 完善」保持一致）。
3. **按钮形态**：参考需求列表 `row-acts` 口径——卡片内小号按钮 + `aria-label`/`title` 说明动作与适用状态；「AI 完善」建议保留文字（图标难表意），「合并入 main」可用文字或图标，具体形态 design.md 定稿；长版本名 + 按钮同排时按需求列表口径省略号截断 / 换行不破版。
4. **状态口径不变**（只是搬家，禁用/文案规则逐卡继承原逻辑）：
   - 「AI 完善」：版本 status 为 `merging` 时禁用，其余可用；
   - 「合并入 main」：`merging` / `merged` / 合并执行中（`mergeBusy`）禁用（`merged` 时 title 提示「已合并入 main」）；`failed` 时文案为「重试合并入 main」。
5. **移动而非复制**：两个按钮迁入列表卡片后，右侧详情底部不再重复渲染（避免双入口状态漂移）；详情底部原 `rel-acts` 区如需保留副入口属范围变更，待确认。
6. **空态与边界不变**：无版本时空列表文案不变（按钮随卡片消失，天然无入口）；非 git 仓库引导空态不变；选中联动、详情内编辑、条目增删、回填弹窗、合并确认弹窗、Esc 关闭等既有行为零回归。

## 界面展示

[打开可交互演示](./ui-demo.html)：单文件 HTML，内联 CSS/JS，无外网依赖与构建步骤，浏览器直接打开即可操作。

布局：模拟构建模块「版本计划」页签——顶部「＋ 新建版本」工具条，左版本列表（卡片：名称 + 状态 chip + 元信息）+ 右版本详情（名称/描述编辑态示意、关联条目与 commit 行、底部操作区）；下方回填弹窗与合并确认弹窗。演示顶部提供「演示控制台」：修复前 / 修复后对照开关、场景切换（正常 / 空列表 / 加载中 / 加载失败）、单版本状态切换（draft / merging / merged / failed）、深浅色主题与重置；另有「当前选中」提示行用于验证按钮不改变选中。

交互：修复后模式每张版本卡片直接带「AI 完善」与「合并入 main / 重试合并入 main」按钮——点击按钮对所在卡片的版本生效且不切换选中；「AI 完善」打开两段式回填弹窗（复制提示词 → 粘贴/填入示例回答 → 解析并预览 名称/描述 旧→新对照 → 应用后卡片名称即时更新）；「合并入 main」打开确认弹窗列条目与短 commit，确认后进入合并中（按钮禁用）约 1.5 秒后转已合并并 toast。修复前模式按钮只出现在右侧详情底部、须先选中版本，列表卡片无任何操作入口，与修复后形成直观对照。

状态反馈：覆盖正常 / 空列表 / 加载中 / 加载失败四类场景（失败可重试恢复）；版本四状态（计划中 / 合并中 / 已合并 / 失败）下按钮可用性与文案差异可逐卡切换验证（merging 时「AI 完善」禁用、merging/merged/执行中禁合并、failed 显「重试合并入 main」）；复制成功「已复制 ✓」、解析失败给出与真实实现一致的错误文案、应用 / 合并成功 toast、深浅色适配。演示中的版本号、条目、commit 均为示例数据，不代表真实条目；演示仅用于对照说明，不替代真实页面验收。

## 验收说明

- 修复后，左侧版本列表每张卡片内直接可见本版本的两个操作按钮，未选中任何版本时也可对任意版本直接操作；入口不再随右侧详情联动出现。
- 点卡片按钮操作的是所在卡片版本：对非选中版本点「AI 完善」，弹窗标题与提示词内容对应该卡片版本；确认弹窗、合并结果同样落在该版本；操作后卡片选中态不变（可用演示页「当前选中」提示行核对）。
- 文案与可达性：按钮显示「AI 完善」；`title`/`aria-label` 说明动作；`scripts/web/i18n.js` 词条同步更新（若弹窗标题一并改名，则弹窗与确认框标题口径一致——以 design.md 定稿为准）。
- 状态口径回归：`draft` 两键可用；`merging` 时「AI 完善」与「合并入 main」均禁用、详情显示「合并中，请稍候……」；`merged` 时合并键禁用且 title「已合并入 main」、条目行显 ✓；`failed` 时合并键文案「重试合并入 main」、详情显示失败原因；合并执行中所有卡片的合并键禁用（`mergeBusy` 全局口径）。
- 移动口径：右侧详情底部不再出现这两个按钮，无残留的隐藏入口 / 重复绑定；原 `#bldAnswerBtn` / `#bldMergeBtn` 单实例绑定改为按卡片实例绑定的后，回填弹窗、合并确认、toast、Esc / 点外部关闭等行为与迁移前一致。
- 空态与边界：空列表 / 非 git 仓库空态不出现卡片按钮；长版本名下按钮不破版；窄屏（列表单列压缩）下卡片按钮可用；深浅色下按钮样式正常。
- 回归：卡片点击选中、详情名称/描述行内编辑、条目增删与 commit 换选、「＋ 新建版本 / ＋ 添加条目」侧拉面板、分支浏览页签均不受影响。
- [演示](./ui-demo.html)可在浏览器直接打开，完成修复前 / 修复后对照、四类场景切换、四版本状态切换与按钮不改变选中的演示。
- 范围边界（待确认）：回填弹窗内部标题及「提示词与回答回填」在其他位置（如有）的文案是否同步改为「AI 完善」；详情底部是否保留副入口。

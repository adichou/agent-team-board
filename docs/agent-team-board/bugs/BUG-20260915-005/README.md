# BUG-20260915-005 挂起确认面板「保持挂起/重新核验/确认并继续」按钮缺少使用场景说明

- 状态：submitted（待人工接受）
- 引入来源：REQ-20260914-001（引入挂起确认闭环：任务页面板三按钮「保持挂起 / 重新核验 / 确认并继续」）
- 创建：2026-09-15T00:28:12.652Z

## 现象

任务页挂起确认面板（提交挂起 develop 侧）底部三个操作按钮「保持挂起」「重新核验」「确认并继续」：

- 按钮无 `title`/tooltip，也无按钮旁注，面板顶部仅一句泛化文案「核对文件与差异后确认：服务端将重新核验、补交并验证测试，通过后恢复队列」，无法区分三个按钮各自语义；
- 实际用户反馈（BUG-20260914-020 挂起处理时）：不知道什么场景点哪个、点了会发生什么，不敢下手。

三个按钮的真实语义（用户应当能从界面上获知）：

1. **保持挂起**：暂不处理，条目维持挂起、队列保持暂停，处理说明留档，稍后再来；
2. **重新核验**：只重查不提交——重新核验本单提交状态并跑测试，刷新面板「最近核验」结论；适用于人工已在终端自行补交后、或怀疑状态已变化时；
3. **确认并继续**：授权服务端补交剩余路径 + 复验测试 + 恢复批量队列，一步闭环。

## 复现步骤

1. 任一条目处于「待人工确认（提交挂起）」状态（如现存的 BUG-20260914-020）；
2. 打开 Status Board 任务页「待人工确认」，点开挂起详情；
3. 查看底部三个按钮：无任何悬停提示或场景说明。

## 期望行为

- 每个按钮提供 `title` 属性（悬停可见）与面板内一行场景说明（不依赖悬停，触屏/键盘也可读），内容区分三按钮：适用场景 + 点击后果；
- 分析侧（hold 问题）面板如有同类按钮一并统一口径；
- 文案走 `scripts/web/i18n.js` 双语表。

## 验收标准

1. 悬停/聚焦任一按钮可见其场景与后果说明；
2. 面板内有三按钮用途的一句话对照说明，不悬停也能看懂；
3. 新增文案有 i18n 双语条目，中英文环境均正常显示。

## 界面展示

可交互演示见 [./ui-demo.html](./ui-demo.html)（单文件、无外网依赖、浏览器直接打开；数据为模拟，行为依据 `scripts/web/app.js` `renderConfirmForm` / `confirmCardHtml` 现状实现）。演示覆盖：

- 界面布局：任务页「待人工确认」区——队列暂停横幅（阻塞条目与原因）、确认卡片（「开发 / 提交挂起」徽标、条目号、「部分提交，开发未完成」标记、已等待时长、提交计数、最近核验结论、「查看并确认 / 重新核验」），以及侧拉挂起确认面板（标题 + 顶部 scope 文案、挂起原因、提交计数、文件表「文件 / 状态 / 查看差异」、核验结论与测试输出、处理说明输入、底部「关闭 / 保持挂起 / 重新核验 / 确认并继续」）。
- 交互行为：「Bug 现状 / 修复后期望」模式切换——现状三按钮无 `title`、无按钮级说明，只有面板顶部一句泛化 scope 文案；期望模式为三按钮补 `title`（悬停可见）与 `aria-label`，并在按钮区上方加一行 muted small 三按钮对照说明（不依赖悬停、触屏/键盘也可读）。「查看并确认」打开侧拉面板，「重新核验」只重查不提交并刷新「最近核验」，「保持挂起」留档并保留队列暂停，「确认并继续」授权补交 + 复验 + 恢复队列。另有「模拟失败」开关（读取/核验/确认走失败分支）、「清空待确认」空态模拟与一键重置。
- 状态反馈：面板读取加载态（「正在读取挂起详情…」）与失败态（错误文案 + 重试）、核验中按钮禁用（「正在核验提交与测试…」）、核验通过 / 未通过结论切换（未通过列原因与测试输出尾部）、保持挂起成功 / 失败的面板消息、确认被拒时「确认未通过，保持挂起」、确认成功后「已确认恢复」终态（按钮禁用、队列横幅消失）、无待确认时的空态（区域整体隐藏）、toast 操作反馈。
- 主题适配深浅色（跟随系统 `prefers-color-scheme`，可选）。

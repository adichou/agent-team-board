# BUG-20260907-013 状态守卫误拦：无锁时以重定向日志方式启动/引用插件脚本的命令被判为改写源码

- 状态：submitted（待人工接受）
- 归属需求：无（独立 Bug）
- 创建：2026-09-07T09:00:50.986Z

## 现象

## 现象（本次测试实际被拦）
无有效认领锁时执行：
ATB_PORT=8123 … node <插件>/scripts/server.mjs > /tmp/agent-team-board.log 2>&1
被拦截：「插件源码受看板流程保护，禁止无认领锁时用 Bash 改写」。命令实际只是启动服务并把日志写到 /tmp，并未改写任何插件源码。

## 根因
hasRewriteIntent 检测到段内存在 > 重定向操作符，hitsPluginSource 检测到段内出现插件路径——两者在段内各自独立命中即判改写，未关联「写目标」与「插件源码」的对应关系。与 BUG-20260905-001（sed 只读误拦）同属一类：改写意图与目标路径未做语义关联。

## 建议
仅当重定向/写动作的目标 token 解析为插件源码路径时才拦截；命令参数位置出现的插件路径（被读取/执行）不应计入写目标。

## 影响
常规「启动看板服务 + 日志重定向」的开发动作在无锁期间被误拦，绕行成本高（须去掉重定向或写启动脚本）。

## 复现步骤

1. 确保项目看板无有效认领锁（无 .locks/ 未过期锁文件）。
2. 执行 `ATB_PORT=8123 node <插件>/scripts/server.mjs > /tmp/agent-team-board.log 2>&1`。
3. 观察到 Bash 被拦截，提示「插件源码受看板流程保护，禁止无认领锁时用 Bash 改写」。

## 期望行为

- 启动/执行插件脚本并把输出重定向到插件目录之外（如 /tmp）的命令应放行。
- 仅当改写动作的落盘目标（重定向操作数、tee/cp/mv/rm/chmod/sed -i/perl -pi 的文件操作数、find -delete 起点或 -fprint 族取值）解析为插件源码路径时才拦截。
- 真实改写插件源码的命令保持拦截（含经软链别名路径、写插件目录内新文件）。

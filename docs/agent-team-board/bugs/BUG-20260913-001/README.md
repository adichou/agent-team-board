# BUG-20260913-001 版本创建时应该允许关联的需求范围是已完成的需求或 bug，其他都不应该出现在这个范围内。

- 状态：accepted（已接受）
- 归属：独立 Bug（引入来源见 design.md）
- 创建：2026-09-13T08:31:05.934Z

## 现象

构建模块（REQ-20260913-001）「＋ 新建版本」侧拉面板的条目候选列表中，出现了看板上所有需求单 / Bug 单，而不只是已完成（done）的条目——「待接受」「已接受」「已计划」「开发中」等未完成条目也会出现在候选里；只要该条目有关联 commit，就可以被勾选并纳入版本计划。

代码定位（只陈述现状，不预设修复方案）：

- 后端候选接口 `GET /api/build/candidates`（`scripts/server.mjs` `handleBuildApi`）用 `core.listItems(board)` 全量返回看板条目（每条含 `itemId / title / status / type / commits / lastCommittedAt`），**未按状态过滤**；
- 前端 `scripts/web/build.js` 的 `renderCandidateRows` / `selectableCandidates` 只按「有无关联 commit」决定条目可否勾选与「全选」范围，**未按状态过滤**。

同一候选接口也被版本详情的「＋ 添加条目」面板复用（`build.js` `openAddPanel` 同样请求 `/api/build/candidates`），因此未完成条目同样会出现在「添加条目」候选中。

## 复现步骤

前提：看板中同时存在已完成（done）与未完成（如 submitted / accepted / planned / in-progress）的需求单或 Bug 单，且其中部分条目有关联提交（`itemCommitStatusIndex` 能索引到 commit）。

1. 打开看板网页端（Electron 壳或 `node scripts/server.mjs` 页面），切换到「构建」页签。
2. 点「＋ 新建版本」，打开新建版本侧拉面板。
3. 观察条目候选列表：未完成状态的条目也出现在列表中（列表不展示状态标识，仅展示单号 + 标题 + commit 下拉）。
4. 勾选一个未完成但有关联 commit 的条目，填写版本名称（可留空），点「创建版本计划」。
5. 实际结果：版本创建成功（toast「✓ 版本计划已创建」），未完成条目被纳入版本的「关联条目与 commit」。

## 期望行为

版本创建（新建版本）时，可关联的需求范围只包含**状态为已完成（done）的需求单或 Bug 单**；其他状态（submitted 待接受 / accepted 已接受 / planned 已计划 / pending-alignment 待对齐 / in-progress 开发中，状态集见 `scripts/lib/core.mjs` `STATES`）的条目一律不出现在候选列表中，也不可被纳入版本。

- 「全选 / 全不选」只作用于可见的已完成候选；已完成但暂无关联 commit 的条目仍按现有规则展示为不可勾选并提示「暂无关联提交（先完成开发提交）」，不改变既有全选口径。
- 候选范围内没有任何条目（看板无已完成条目）时，面板给出明确空态提示（具体文案待确认），而不是显示一列不可勾选的未完成条目。
- 实现层面在后端接口过滤还是前端过滤（或两端都做）留待开发阶段的 design.md 决定；无论采用哪种方式，最终界面与数据口径都必须满足「只有已完成条目可被纳入版本」。
- 「添加条目」面板与新建版本共用同一候选接口，是否按同口径一并收窄：待确认（建议一并收窄，保持两处口径一致）。

## 验收说明

1. 看板同时存在 done 与非 done 的需求单 / Bug 单（均有关联 commit）时，「＋ 新建版本」侧拉面板候选列表仅出现 done 条目；非 done 条目不出现、不可勾选。
2. 看板没有任何 done 条目时，面板显示明确空态提示；不出现任何未完成条目。
3. 「全选」后已选计数只包含已完成候选；无关联 commit 的已完成条目被跳过并按现有文案提示（「…个条目暂无关联提交将被跳过」）。
4. 未勾选任何条目点「创建版本计划」时，保留现有行内报错「请至少勾选一个条目（无关联 commit 的条目不可纳入版本）」。
5. 勾选已完成条目创建版本成功后，版本详情「关联条目与 commit」仅含所选已完成条目，commit 关联与现有创建流程（自动命名、成功 toast、列表刷新选中最新）行为不变。
6. 后端校验同样收窄（与界面口径一致）：直接调用 `POST /api/build/version` 提交非 done 条目应被拒绝并给出原因（实现方式待开发阶段定，若只在候选接口过滤则需在创建校验处补同等限制——具体以 design.md 为准）。
7. 「添加条目」面板口径与新建版本一致（若确认一并收窄）：非 done 条目不出现在候选，已在版本中的条目仍不出现。

## 界面展示

涉及 UI：本 Bug 现象为界面候选范围错误，修复会直接改变「新建版本 / 添加条目」侧拉面板呈现的内容。

界面布局与交互（与 REQ-20260913-001 既有范式一致，修复不改变布局，只改变候选内容）：

- 构建模块为「版本计划 / 分支浏览」两个子页签；版本计划为左版本列表 + 右版本详情分栏，「＋ 新建版本」在模块右上（空态时空态卡内也有同款入口）。
- 新建版本走右侧侧拉面板：顶部标题与范围说明、遮罩层、条目候选行（复选框 + 单号 + 标题 + commit 下拉；无 commit 的条目显示「暂无关联提交（先完成开发提交）」且不可勾选）、候选区上方「全选 / 全不选 + 已选计数」、底部版本名称输入与「创建版本计划」按钮。
- 状态反馈：打开面板先显示「正在读取条目…」加载态；读取失败显示错误与「重试」；未勾选提交时行内报错；创建成功 toast「✓ 版本计划已创建」并关闭面板、列表刷新。

可交互演示：./ui-demo.html（单文件、无外部依赖、浏览器直接打开）。演示内置「修复前（现状）/ 修复后（期望）」对照开关——修复前候选列出全部状态条目（未完成条目只要有关联 commit 即可勾选并创建成功，即缺陷现象）；修复后仅列已完成条目，并覆盖正常 / 空态 / 加载 / 读取失败 / 校验报错 / 创建成功等状态切换。演示数据为虚构，仅用于对照说明现象与期望。

# BUG-20260912-003 提交号显示优化

- 归属：独立 Bug
- 创建：2026-09-11T18:24:59.992Z
- 当前状态以系统记录为准；本文不维护状态。

## 现象

需求看板中已完成条目的提交状态展示信息冗余、提交号过长、复制入口绕（用户原话，共三点）：

1. 提交号只显示前 5 位即可——当前列表卡片与详情中提交号以完整 40 位 hash 展示，过长占位。
2. 「已提交」徽标不需要显示，显示提交号即可——当前有提交记录时先渲染绿色「已提交」徽标，提交号还藏在「N 个提交号」可折叠项里，双层信息冗余。
3. 双击提交号可以复制提交号——当前复制需点击每行右侧独立「复制」按钮，双击提交号文本无任何反应。

已核实的代码依据（`scripts/web/app.js`）：

- `commitBadgeHtml`（约 6321 行）：有成功提交记录时渲染 `<span class="commit-badge cm-committed">已提交</span>`，列表卡片再附 `<details class="commit-hashes">`（summary 为「N 个提交号」）；无记录显示「未提交」，查询失败显示「提交状态加载失败」重试按钮。
- `commitHashListHtml`（约 6309 行）：每行 `<code class="commit-hash">` 显示完整 40 位 hash（title 悬停可见），右侧独立「复制」按钮（`data-copy-hash` → `copyHash`，复制完整 hash，含剪贴板降级）。
- 展示位置：需求看板列表卡片顶部（`renderReqCard`，约 1887 行，`expandable: true`）与详情抽屉「提交状态」字段（约 3484 行，`commitBadgeHtml(it) + commitStatusDetailHtml(it)`）；作用条目为已完成（done）与待测试（in-progress 且已上报完成）条目（REQ-20260911-009 扩展口径）。

## 复现步骤

1. 打开 Status Board（`/board` 插件入口或 Electron 壳 `npm run app`，本地端口 8888），进入「需求」模块看板。
2. 找一个已完成（done）或待测试且已上报完成、且在 `/api/commit/item-status` 中存在成功提交记录的条目（此前经核验/自动提交过；具体现场数据待确认）。
3. 观察该条目卡片顶部：显示绿色「已提交」徽标和「N 个提交号」折叠项；点开折叠项后提交号以完整 40 位 hash 展示，每行还需单独点击「复制」按钮才能复制。
4. 点击条目打开详情抽屉，查看「提交状态」字段：同样先见「已提交」徽标，hash 为完整 40 位，复制须逐个点击「复制」按钮。
5. 在列表或详情中双击提交号文本本身：无复制反应（仅触发浏览器默认选词）。

## 期望行为

- 提交号显示前 5 位（十六进制前缀，如 `8c57c`）：列表卡片与详情中的提交号默认只展示前 5 位；完整 hash 仍保留在数据中，通过悬停 title 可见，双击复制时得到完整 hash（口径见待确认）。
- 去掉「已提交」徽标：有提交记录时不再渲染「已提交」徽标与「N 个提交号」折叠层，直接在原徽标位置并列展示提交号（多个提交号则展示多个短提交号，默认不折叠，折叠是否保留见待确认）。
- 双击提交号即可复制：双击任一提交号触发复制并有成功反馈；复制动作不冒泡，不会触发卡片点击打开详情、不会误开抽屉。仅去掉徽标与改展示格式，不改变复制失败的降级提示（剪贴板不可用时仍可手动框选完整值）。
- 其余提交状态展示不受本单影响：「未提交」「提交状态加载失败」（含重试入口）的口径与交互保持现状；数据源仍为 `/api/commit/item-status`（REQ-20260911-009 索引），刷新、列表/详情切换、项目切换后不串项目数据。
- 展示为纯前端裁剪：只截短显示，不修改提交账本、不重新请求、不影响自动提交与回执核验流程。

## 界面展示

[打开交互演示](./ui-demo.html)（离线单文件，全部数据为模拟，不执行 Git 或调用服务。演示可对照「缺陷现象 / 期望修复后」，并切换正常、空、加载、失败场景）。

- 布局：修复后列表卡片顶部原「已提交」徽标处直接显示 1 个或多个 5 位短提交号；详情抽屉「提交状态」字段同样只列短提交号，无徽标、无折叠层。对照模式下保留「已提交」徽标 +「N 个提交号」折叠 + 完整 40 位 hash + 独立「复制」按钮的旧布局。
- 交互：双击短提交号复制完整 hash（修复后）；对照模式双击无反应、须点击「复制」按钮；切换四种场景观察不同状态；悬停短提交号可见完整 hash 提示。
- 状态反馈：正常（已提交条目显示短提交号 / 未提交条目显示「未提交」）；空（无已完成条目）；加载（读取中占位）；失败（「提交状态加载失败」+ 重试读取，已有成功记录保留）；复制成功/失败均有可读提示。

## 验收说明

- [ ] 已完成/待测试且有提交记录的条目，列表卡片不再出现「已提交」徽标，原位置直接显示前 5 位短提交号；多个提交号并列可见（默认无折叠）。
- [ ] 短提交号悬停 title 可见完整 40 位 hash；双击复制成功有反馈，复制内容为完整 hash（若口径定为短格式需另行确认）；双击复制不冒泡，不触发行点击打开详情。
- [ ] 详情抽屉「提交状态」字段与列表口径一致：只列短提交号、无徽标；逐个双击可复制。
- [ ] 「未提交」条目仍显示「未提交」；查询失败仍显示「提交状态加载失败」并可重试，已加载的成功记录不消失。
- [ ] 刷新、列表/详情切换、项目切换后显示正确、不串项目数据；纯展示改动不影响 `/api/commit/item-status` 数据与提交账本。
- [ ] 使用隔离测试数据核对显示值与账本记录一致；本演示仅用于界面验收讨论，不代表修复已实现。

## 待确认

- 双击复制的口径：本单按「双击复制完整 40 位 hash」理解（与现有 `copyHash` 口径一致、git 命令可直接使用）；若需求方期望复制 5 位短格式，实施前需确认。
- 「前 5 位」极短：git 默认短 hash 为 7 位，用户明确要求 5 位；若未来出现歧义/冲突是否需要自动加长展示，待确认。
- 多提交号时是否保留「N 个提交号」折叠交互：本单默认直接并列展示（用户原话「显示提交号即可」）；若担心卡片过高需保留折叠，待确认。

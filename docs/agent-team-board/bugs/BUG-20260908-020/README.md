# BUG-20260908-020 已接受单的批次相关的显示需要删除

- 状态：submitted（待人工接受）
- 归属：独立 Bug（引入来源见 design.md）
- 引入来源：REQ-20260907-012（为已接受条目引入「已入批次/未入批次」批次进入状态显示）、REQ-20260908-010（批次候选口径切换为已计划单使该显示失效；两 ID 均经 atb list 核验）
- 创建：2026-09-08T14:48:38.705Z

## 现象

Web 看板中，已接受（accepted）条目仍按 REQ-20260907-012 显示「批次进入状态」，该显示需要删除：

- **列表卡片（状态模块）**：已接受条目卡片的状态位置不显示通用「已接受」chip，而是渲染「已入批次」/「未入批次」chip（`scripts/web/app.js` 的 `acceptedEntryChip`，约 75–82 行；卡片渲染约 1140 行）。
- **卡片悬停**：已接受行悬停说明显示批次文案——「已入批次 batch-xxx（执行中/排队中…），等待派发实施」或「未入批次：可在详情页『移入计划』排入开发计划，或用 /dev 认领」（`acceptedEntryTitle`，约 83–90 行，挂接在约 1133 行）。
- **详情抽屉「状态」字段**：已接受条目显示批次 chip + 完善状态徽标（约 2128 行）。
- **详情抽屉操作说明 notice**：按批次进入状态显示「已入批次 batch-xxx（…），等待按批次派发实施。」（`drawerActionsNoticeHtml` 的 accepted 分支，约 2066–2073 行）。

该显示已失去价值，原因（均可从代码核实）：

1. REQ-20260908-010 起批量开发批次的候选口径已切换为「已计划（planned）且未认领」（`scripts/lib/batch.mjs` 的 `candidateItems`，约 244–246 行），已接受单不再随批次创建入批；`batchEntry` 仅在「入批后被移出计划退回已接受」的过渡态才非空。因此已接受单的 chip 实际上恒为「未入批次」，不携带任何区分信息。
2. REQ-20260908-020 起已接受单卡片已有「未完善 / 完善中 / 已完善」三态徽标（`refineBadgeHtml`）承载人工真正关注的状态，批次 chip 与之并排反而挤占卡片空间、增加噪音。

批次进入状态数据由 `/api/board` 与 `/api/item/:id` 对 accepted/planned 条目附加的 `batchEntry` 字段提供（`scripts/server.mjs` 约 1511–1525、1644–1647 行；索引构建 `scripts/lib/batch.mjs` 的 `batchEntryIndex`，约 306–315 行）。列表渲染签名也包含 `batchEntry` 以便入批/出批后自动刷新（`scripts/web/app.js` 约 1234 行）。

CLI（`atb list` 等输出）没有「已入批次/未入批次」文案，不受影响。

## 复现步骤

1. 启动看板服务（`node scripts/server.mjs`），浏览器打开 Web 看板（`scripts/web/index.html`）。
2. 前提：看板中存在至少一个已接受（accepted）状态条目。
3. 「状态」模块列表：观察已接受条目卡片——状态位置显示「未入批次」chip（常态，因批次候选仅含已计划单）；鼠标悬停卡片，提示为「未入批次：可在详情页『移入计划』排入开发计划，或用 /dev 认领」。
4. 点击该条目打开详情抽屉：「状态」字段显示「未入批次」chip 与完善状态徽标；操作说明 notice 显示「未入计划。可点『移入计划』……或用 /dev 认领」。
5. （「已入批次」形态复现，可选）对一个已进入未结束批次的已计划单执行「移出计划」（退回已接受），返回列表：该单 chip 变为「已入批次」，悬停与详情 notice 显示「已入批次 batch-xxx（…），等待派发实施」。
6. 上述第 3–5 步出现的所有批次相关标识与文案（已入批次/未入批次 chip、悬停批次说明、详情批次文案）即本 Bug 要删除的对象。

## 期望行为

已接受（accepted）条目在看板上不再出现任何「批次进入状态」相关显示：

- 列表卡片不再渲染「已入批次 / 未入批次」chip；悬停说明不再显示批次进入状态文案。
- 详情抽屉「状态」字段不再显示批次 chip；操作说明 notice 的 accepted 分支不再出现「已入批次 batch-xxx（…），等待按批次派发实施。」文案。
- 删除后该位置的展示形态登记时未指定，**待确认**（建议按最小改动恢复与其他状态一致的通用「已接受」chip，即直接移除 REQ-20260907-012 的 accepted 特例分支；若人工倾向留空仅保留完善状态徽标，以人工意见为准）。
- 已接受条目的其余展示不受影响：「未完善 / 完善中 / 已完善」三态徽标、勾选「移入计划」、驳回回待接受（完善中禁用）等按现状保留。
- **范围边界（已计划单不在本 Bug 范围）**：已计划（planned）条目详情 notice 中的「已入批次 batch-xxx（…）」文案（`scripts/web/app.js` 约 2075–2079 行）与批量实施面板（任务模块）内的批次/队列展示保留不动——批次派发面向已计划单，该展示仍有意义。

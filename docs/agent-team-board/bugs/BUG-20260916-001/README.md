# BUG-20260916-001 发布能力不要复用原来的发布模块，请在构建模块中重新设计。另外设置模块中没有官网仓库目录的设置，请添加

## 现象

用户反馈：发布能力沿用原发布模块，不符合在构建模块内重新设计的要求；设置模块缺少官网仓库目录设置入口，无法按预期完成发布前配置。

本轮源码核实：`scripts/web/build.js` 已有版本详情「概况 / 发布」页签和按版本读取运行记录的逻辑，因此不能将现状描述为完全没有构建内发布。其发布目标、运行状态与交互沿用产品发布流程，调用 `/api/product-release/*`。`scripts/web/release.js` 的 `renderProductConfig()` 仍承载官网目录输入表单；`scripts/web/app.js` 的设置渲染中未找到对应官网配置入口。`scripts/server.mjs` 已提供官网目录读取与保存接口，配置并非没有后端能力。实际受影响安装版本、浏览器和现场截图：待确认；本轮未运行真实发布。

## 复现步骤

前置：当前项目存在已合并的版本计划；使用未配置官网仓库目录的环境。不要为了复现推送代码或部署站点。

1. 打开「构建 → 版本计划」，选择已合并版本，进入右侧「发布」页签，查看创建发布、运行详情与配置引导。
2. 打开顶栏「设置」，查找官网仓库根目录字段及保存入口。
3. 对照源码确认官网目录表单仍在旧发布模块中；核对构建内发布能否独立完成配置引导、计划预览和结果查看。
4. 记录当前项目、所选版本、缺失入口和提示信息。旧版是否会跳转隐藏模块：待确认，已有 BUG-20260915-014 修复相关跳转，不能将其旧现象直接认作本条当前现象。

## 期望行为

### 修复范围

发布能力以构建版本为上下文重新组织，完整归属「构建 → 版本计划 → 发布」，不嵌入旧发布视图、不跳转旧发布模块，也不要求旧模块初始化后才可使用。创建、预检、计划确认、执行进度、结果和重试均在当前版本内完成。已有历史记录可按项目及版本查看，不能因界面调整丢失或串到其他版本。

本条明确替代 REQ-20260915-002 中进入旧发布模块及沿用其布局的界面约定；Web App 与官网文档两个必备目标、冻结范围、执行证据及真实性约束继续适用。是否同时要求完全替换后端产品发布接口、执行器和存储，以及既有配置是否迁为全局共享：待确认；不能将“不要复用原来的发布模块”擅自缩减为只修改按钮文字，也不能未经明确依据声称已要求删除全部后端能力。开发阶段需落实模块依赖边界，本轮不编造方案。

### 界面布局与交互行为

- 左侧保留版本列表及版本操作，右侧顶部展示所选版本名称、合并状态和「概况 / 发布」页签；发布页签顶部为版本发布摘要及创建入口，下方为本版本运行记录、阶段进度、Web App 与官网文档结果、日志与本机访问链接。
- 发布页签的「本版本发布」操作区始终显示醒目的「发布」主按钮，与「创建并预检」「预览发布计划」并列；「发布」页签本身仅负责切换页面。缺配置或未通过预检时禁用主按钮，并在按钮旁说明原因；预检通过后点击「发布」打开计划确认弹窗，点击「确认发布」才启动，取消不执行。执行中主按钮显示「发布中…」并禁用，成功后显示「已发布」并禁用，失败保留原因及重试入口。
- 创建时带入版本上下文，仅核对发行版本号；未合并时禁用创建并解释前置条件。无记录时展示空态和创建入口；已有记录时可选择查看，不将草稿显示为已发布。
- 「设置」增加独立的「官网仓库」区域：显示配置作用范围、官网仓库根目录输入框、保存按钮和校验反馈。目录为绝对路径，需存在、可访问、为有效 Git 仓库且有目标 main 分支；产品子目录自动取项目名，不让用户重复填写。
- 缺配置时，构建发布页显示「前往设置」。进入设置后保留来源项目、版本与草稿信息；保存成功提供「返回发布」，回到原版本继续。保存失败保留输入和原有效配置，允许修正重试；不得假报保存成功。
- 已保存目录再次打开可回显；修改有效目录后提示旧预检失效，重新预检后才可启动。配置作用范围必须明确展示，跨项目共享策略待确认，不能默默覆盖其他项目配置。

### 状态反馈

首次读取显示加载态，失败显示原因和重试；空态区分无版本、无运行及未配置。保存中禁用重复保存。预检中、执行中显示阶段进度并防重复操作；失败显示失败阶段、原因和可用的重试入口；等待人工、取消、部分目标成功保留真实状态。只有必备目标及相关核验全部成功才显示已发布。切换项目或版本时迟到响应不得覆盖当前页面。

## 验收说明

- [ ] 发布主按钮在发布操作区始终可见，缺配置/未预检时有禁用原因；预检通过后可点击，弹窗取消不启动、确认发布才执行；执行中不可重复启动，成功后不重复发布。
- [ ] 构建中可完成发布全流程并查看历史，运行关联当前项目及版本；旧发布模块不可用时仍可使用该流程，无旧视图跳转或依赖其初始化的行为。
- [ ] 设置中可找到官网仓库区域，填写有效目录后保存并重新打开仍回显；空值、相对路径、目录无效、权限不足、非 Git 仓库、缺 main 均给出明确原因，旧有效值不被失败保存覆盖。
- [ ] 未配置时由发布进入设置，保存后返回同一项目、版本和草稿；已有发行版本号不丢失，不重复创建运行。
- [ ] 更改配置使旧计划预检失效；重新预检与确认前不能继续旧计划。作用范围明确且不串项目。
- [ ] 无版本、无运行、加载、读取失败、保存失败、预检失败、执行中、部分成功及全部完成状态可辨识；重试和防重复操作符合真实运行状态。
- [ ] 合并状态与发布状态区分，版本切换不串数据；仅调整文档和演示不视为功能修复验收通过。

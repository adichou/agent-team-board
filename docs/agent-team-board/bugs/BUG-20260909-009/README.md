# BUG-20260909-009 已接受列表的选择区域布局拥挤，需要优化

- 状态：accepted（已接受；本轮仅完善说明，未实施修复）
- 归属：独立 Bug（引入来源见 design.md）
- 创建：2026-09-09T05:33:36.228Z

## 现象

看板「需求」模块的列表头（`#reqCaption`，`scripts/web/index.html` 第 72–101 行）自 REQ-20260909-002 起与批量操作条合并为**单行**；REQ-20260909-007 又在左组末尾新增常驻「▶ 开始完善」。叠加后，「已接受」档成为六档中控件最多、最拥挤的一行：

1. **控件数最多**：勾选 ≥1 项后，单行内并排 9 个元素——左组 `.caption-left` 5 个（条目计数 `#reqCount` + 排序 `#reqSort` + 「☑ 全选」`#selectOperable` + 「☐ 全不选」`#selectNone` + 「▶ 开始完善」`#laneQuickEntry`，`scripts/web/index.html` 第 73–89 行）＋ 右组 `#selGroup` 4 个（1px 分隔线 + 「已选 N 项」`#selCount` + 「移入计划」`#planAdd` + 「驳回待接受」`#planReject`，第 90–100 行）。对照其余档：待接受 7 个、已计划 8 个（BUG-20260909-006 移除「进入批量开发」后）、开发中 / 待测试 / 已完成 左组 4 个（全选/全不选灰显常驻，见 BUG-20260909-008）。
2. **可用宽度被固定抽屉挤压**：需求工作区为 `minmax(0, 1fr) + minmax(0, 460px)` 双栏（`scripts/web/style.css` 第 251 行），列表栏宽度 = 窗口宽 − 页边距/栏距/卡片内边距约 80px − 抽屉 460px。以 1280px 窗口为例列表内容宽仅约 740px，9 个控件以 8px 间距、12px 字号、4px/10px 按钮内边距（`.req-caption` gap（第 270–278 行）、`.sel-group .btn`（第 290 行）、`.btn.small`（第 596 行））挤在该行内，视觉密度显著高于其他档。
3. **换行按项拆散**：`.caption-left` 逐项 `flex-wrap: wrap`（`scripts/web/style.css` 第 280 行）。宽度不足时左组元素一个一个掉行（如「▶ 开始完善」「☐ 全不选」单独落到第二行），计数 / 排序与选择控件被拆散在不同行，换行位置随宽度连续拖动而跳动，呈参差的多行表头。
4. **分隔线悬挂与右组掉行**：右组 `.sel-group` 自身换行且 `margin-left: auto` 靠右（`scripts/web/style.css` 第 281–287 行）；当它整组放不下掉到下一行时，行首残留 1px 竖向 `.caption-divider`（第 288 行），视觉上是一条悬空的短竖线。
5. **表头高度跳变**：右组显隐是「零勾选整体隐藏 / 有勾选整体出现」（`scripts/web/app.js` 第 1497 行 `group.classList.toggle('hidden', curCount === 0)`）。勾选第一个复选框的瞬间一次性新增 4 个元素，整行重新换行、表头高度突变，下方列表整体下移；取消勾选又弹回，反复勾选首项时列表上下跳动。
6. **选择区域被隔断**：与勾选直接相关的控件分居两端——「全选 / 全不选」在左组，「已选 N 项 / 移入计划 / 驳回待接受」在右组，中间隔着与本档选择无关的排序下拉与「开始完善」快捷入口，选择操作区在视觉上不连续。

拥挤主要发生在分栏仍生效的宽度区间（>1020px 且窗口不宽裕时）；≤1020px 窄屏分栏解除（`scripts/web/style.css` 第 715–719 行）、列表栏反而变宽，问题不明显。具体换行阈值随系统字体渲染而异（待确认：登记时未在多档窗口宽度下逐一实测，只确认结构与样式来源）。

## 复现步骤

前置：看板服务已启动（`node scripts/atb.mjs serve`，默认 `http://127.0.0.1:8888`），当前项目至少有 2 条「已接受」条目（无则新建需求后依次「接受」）。

1. 打开看板，进入「需求」模块，切到「已接受」档：列表头左组依次为 「N 个条目 / 排序下拉 / ☑ 全选 / ☐ 全不选 / ▶ 开始完善」5 个控件；此时零勾选，右组隐藏。
2. 勾选任一行复选框：行尾一次性出现 「分隔线 / 已选 1 项 / 移入计划 / 驳回待接受」，单行控件数达 9 个——观察整行的密集程度，以及表头高度是否随右组出现而跳变、下方列表是否整体下移。
3. 保持勾选，把窗口宽度从大逐步缩窄（如从 1400px 拖到 1100px 附近，保持分栏未解除）：观察左组逐项换行（「▶ 开始完善」或「☐ 全不选」单独掉到第二行、控件组被拆散），以及右组整组掉行后行首悬挂的 1px 竖线。
4. 反复勾选 / 取消同一行的第一个复选框：右组随之出现 / 消失，表头行数与高度来回变化，列表内容上下位移。
5. 对照其他档：切到「待接受」（7 个控件）、「已计划」（8 个控件）重复步骤 2–3，观察「已接受」档明显更挤；切到「开发中」等非选择档确认本档无右组（其灰显全选/全不选问题另见 BUG-20260909-008，不在本条目范围）。
6. （可选）拖动系统窗口宽度在 1020–1400px 区间来回：确认换行断点位置不稳定、多行表头参差。

## 期望行为

- **功能与口径零删减**：计数、排序、全选 / 全不选（仅当前档、叠搜索、批量进行中防误触，REQ-20260908-027）、常驻「开始完善」（仅导航，REQ-20260909-007）、「已选 N 项」计数、移入计划（REQ-20260908-018）、驳回待接受（REQ-20260908-027）、结果反馈区全部保留，行为不变。
- **布局优化目标**（具体方案由修复阶段 design.md 定夺，此处只约束结果，不预设唯一解）：
  1. 常规宽度（约 1280px 级窗口、分栏生效）下「已接受」档表头一行完整容纳全部控件，无逐项散落换行；
  2. 宽度不足时**按组整体换行**（组内不拆散），任何宽度下分隔线不出现在行首悬挂；
  3. 勾选首项右组出现 / 消失时表头高度稳定或受控，列表不发生整体跳动；
  4. 选择相关控件（全选 / 全不选 / 已选计数 / 批量动作）在视觉上形成连续的选择区域，或通过分组归并、收折（如溢出菜单）、两行结构等手段降低单行控件密度——取舍待 design.md。
- **优化范围待确认**：仅「已接受」档，还是同步统一六档表头布局（已计划 8 个控件次拥挤；BUG-20260909-008 修复后非选择三档将变短），由 design.md 定。
- **既有呈现契约不无故回退**：REQ-20260909-002「列表头与批量操作条合并」的意图与 REQ-20260909-007「快捷入口常驻列表头、零勾选可见」不因布局调整而消失；若方案需要调整这两项契约（如改为固定两行结构），须在 design.md 中说明理由与替代口径。
- 窄屏（≤1020px）现有换行不遮挡、不产生横向滚动的底线保持；深浅色沿用现有 CSS 变量。

## 界面展示

- 布局：「需求」模块 → 已接受档列表头。现状（缺陷）：左组 5 控件 + 右组 4 元素共 9 项挤在受 460px 抽屉挤压的单行内，宽度不足时逐项散落换行、分隔线悬挂行首、勾选首项表头高度跳变；期望（优化示意）：选择相关控件聚合为连续选择区、按组整体换行、预留稳定表头高度（示意方案之一，最终以 design.md 为准）。演示页内置「现状 / 期望」对照切换与列表栏宽度调节（预设 + 滑杆），实时显示表头行数、表头高度与「分隔线是否悬挂」检测结果。
- 交互：六档 chips 切档驱动列表与表头重建；勾选复选框驱动「已选 N 项」与右组批量动作显隐；全选 / 全不选仅作用当前档；「移入计划 / 驳回待接受」进入批量进行中态（按钮变「…中」、复选框与全选 / 全不选防误触禁用）后完成真实流转（已接受 → 已计划 / 待接受）；拖动宽度滑杆观察两种模式下换行行为的差异。
- 状态反馈：正常态（一行 / 按组换行）、拥挤换行态（现状专属：逐项拆散 + 悬挂分隔线 + 高度跳变提示）、批量进行中（防误触禁用）、批量成功（✓ 反馈条）与批量失败（失败清单反馈条，可开关模拟）、空档空态、切档加载过渡；操作与检测日志区随交互滚动记录。

可交互演示：[./ui-demo.html](./ui-demo.html)（单文件、无外网依赖，浏览器直接打开；内置「现状（缺陷）/ 期望（优化示意）」对照与宽度调节，换行阈值随字体渲染而异，演示仅供行为对照）。

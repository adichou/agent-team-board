# BUG-20260914-016 分支浏览的搜索框要往上移到和分支名在同一行

- 状态：accepted（已接受）
- 归属：独立 Bug（引入来源见 design.md；涉及界面为构建模块「分支浏览」子页提交记录面板的搜索行，由 REQ-20260914-002 建立、其 design.md 落定「`bld-log-head` 下方独立一行」形态，本单改为与分支名同行）
- 创建：2026-09-14T12:00:37.615Z

## 现象

构建模块「分支浏览」子页签中，选中任一分支后，右侧提交记录面板的**搜索框独占一行，位于「分支名 + 刷新」头部行的下方**——用户期望搜索框上移，与分支名在同一行，节省一行纵向空间。

现状排布（均经源码核实）：

1. **头部行**：`scripts/web/build.js` `renderBranchesPane()`（约 1247–1249 行）渲染 `<div class="bld-log-head"><strong>分支名</strong> <button id="bldLogRefresh">刷新</button></div>`——只有分支名与「刷新」，`justify-content: space-between` 分列两端（`scripts/web/style.css` 3078 行 `.bld-log-head`）。
2. **搜索行**：同一函数约 1230–1237 行的 `searchRow`，在头部行**下方另起一行**渲染 `.bld-log-search`（`style.css` 3094 行起：`flex-wrap: wrap; margin-bottom: 8px`）：关键词输入框 `#bldLogSearchInput`（placeholder「搜提交说明 / 作者 / hash…」）+「搜索」按钮 `#bldLogSearchGo` +「清除」按钮（仅已有生效关键词时出现）。
3. 即每次选中分支后右栏首屏为：第一行「`dev` … 刷新」、第二行「[搜提交说明 / 作者 / hash…] [搜索]」，随后才是命中计数与提交列表——搜索框与分支名没有共用一行，头部行右侧大量留白。

口径沿革（供开发归因）：REQ-20260914-002 README「界面布局」节即写明「具体形态（头部并排一行还是独立一行）待确认，以 design.md 为准」，其 design.md（52 行）落定为「`bld-log-head` 下方新增 `.bld-log-search` 行」的独立一行形态。本单是用户对落定形态的修正意见：**搜索框上移与分支名同一行**，属纯布局调整，搜索能力口径（REQ-20260914-002）与分页口径（BUG-20260914-009）本身不变。

## 复现步骤

前置：任一 git 仓库项目（agent-team-board 本仓库即可）。

1. 启动看板：项目目录终端运行 `atb serve`（默认端口 8888，`ATB_PORT` 可覆盖），浏览器打开 `http://localhost:8888`。
2. 顶栏切到「构建」模块，再切到「分支浏览」子页签。
3. 观察未选分支时：右栏为占位「点击左侧分支查看提交记录」，无搜索框（此口径正常）。
4. 点击左侧任一分支（如 `dev`）：右栏先「加载提交记录中…」，加载完成后观察头部——**分支名与「刷新」独占第一行，搜索输入框 +「搜索」另起第二行**，提交列表从第三行起。
5. 输入关键词（如 `BUG-`）回车或点「搜索」：搜索行仍在分支名行下方独立一行（命中计数「共 N 条匹配」、无命中空态等行为本身正常）。
6. 缩窄窗口至 ≤960px（双栏变单栏）重复第 4 步：排布仍是两行，缺陷一致。

## 期望行为

- **搜索控件上移与分支名同行**：选中分支后，提交记录面板头部为**同一行**：分支名 + 搜索输入框 +「搜索」按钮（+「清除」，仅已有生效关键词时出现）+「刷新」按钮；`.bld-log-search` 不再在头部行下方独占一行。输入框吃掉该行剩余宽度（沿用 `flex: 1 1 160px; min-width: 0` 一类既有弹性口径）。
- **行为与状态反馈零回归**（REQ-20260914-002 / BUG-20260914-009 口径不变）：回车或点「搜索」提交；关键词空白等同清除、恢复默认列表；`logPhase === 'loading'` 时输入框与按钮禁用（按钮文案「搜索中…」）；输入草稿经 `input` 事件回写 `state.logQueryInput`、后台刷新不丢字；无命中空态（「没有匹配的提交」+「清除」）、命中计数行、命中词高亮、分页条均保持。
- **出现时机不变**：仅在选中分支后出现搜索控件；未选分支时右栏仍为「点击左侧分支查看提交记录」占位，头部显示「提交记录」且无搜索框。
- **窄屏与长名不破版**：窗口 ≤960px（`.bld-branch-split` 单栏）或分支名/关键词较长导致一行放不下时，不溢出不遮挡——具体换行/收窄策略（如 `flex-wrap` 允许折回两行）由开发阶段 design.md 落定（**待确认**）。
- **纯布局调整、不越界**：不新增/修改任何文案（placeholder「搜提交说明 / 作者 / hash…」、按钮「搜索 / 搜索中… / 清除 / 刷新」均不变，`scripts/web/i18n.js` 无需动）；不涉及服务端与数据层；非 git 仓库引导空态不受影响。

## 验收说明

1. **同一行**：选中分支后，分支名、搜索输入框、「搜索」（及生效关键词时的「清除」）、「刷新」在同一头部行内渲染（DOM 上搜索控件位于头部行容器内或等价合并结构），搜索行不再单独占一行。
2. **搜索行为回归**：关键词可命中提交说明/作者/hash；无命中的空态与「该分支暂无提交」区分且带「清除」；命中计数「共 N 条匹配（关键词：…）」正确；结果可正常翻页（沿用既有分页条）。
3. **状态反馈回归**：加载/搜索执行中输入框与「搜索」按钮禁用且按钮显示「搜索中…」，完成后恢复；执行中不可重复触发；后台刷新（如「刷新」按钮）不丢失输入框未提交的草稿。
4. **出现时机**：未选分支时无搜索控件，右栏占位与头部「提交记录」文案同现状。
5. **窄屏不破版**：≤960px 单栏布局及更窄宽度下，头部行不横向溢出；长分支名（如 `feature/build-branches`）与长关键词下排布可读。
6. **主题**：深浅色跟随系统既有 CSS 变量，无样式残留或对比度异常。
7. **测试同步**：`scripts/tests/build-ui.test.mjs` 相关断言（如 527 行「渲染搜索行容器类 `bld-log-search`」、397 行「未选分支不出搜索行」等）随结构调整同步更新，`node scripts/tests/run-all.mjs` 全量通过。
8. **范围外不回归**：左侧分支列表、「⟳ 和远端同步」「刷新」、推送入口、远端空态提示（BUG-20260914-006）、非 git 仓库引导空态均不受影响。

## 界面展示

- **界面布局**：左分支列表（本地/远端分组 + 「⟳ 和远端同步」「刷新」）、右提交记录面板的双栏布局不变；变化仅在右栏头部——缺陷现状为「分支名 + 刷新」与「搜索框 + 搜索（+清除）」上下两行，期望修复后合并为同一行，搜索框占该行剩余宽度，提交列表整体上移一行。
- **交互行为**：点选分支懒加载提交记录；关键词输入回车或点「搜索」提交过滤（说明/作者/hash）；「清除」恢复默认列表；「刷新」重载当前列表；「和远端同步」执行中按钮禁用显示「同步中…」。
- **状态反馈**：加载中「加载提交记录中… / 搜索中…」（输入框与按钮禁用）；请求失败显示行内错误 + 「重试」；空分支「该分支暂无提交」；搜索无命中的空态带「清除」；未选分支「点击左侧分支查看提交记录」占位。

可交互演示：[`./ui-demo.html`](./ui-demo.html)（单文件、内联 CSS/JS、无外网依赖、无构建步骤，浏览器直接打开；数据为模拟，布局与交互按 `scripts/web/build.js` `renderBranchesPane()` / `style.css` 现行为复刻）。提供「缺陷现状（独立一行）↔ 期望修复后（同一行）」布局对照开关与数据场景切换（正常 / 空分支 / 请求失败；加载态随交互自动呈现），覆盖上述布局、交互与正常/空/加载/失败各状态反馈。

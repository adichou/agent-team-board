# BUG-20260909-008 不支持选择的列表，去掉全选和全不选按钮

- 状态：accepted（已接受；本轮仅完善说明，未实施修复）
- 归属：独立 Bug（引入来源见 design.md）
- 创建：2026-09-09T05:32:49.479Z

## 现象

看板「需求」模块的列表头左组常驻渲染「☑ 全选」「☐ 全不选」两个按钮（`scripts/web/index.html` 第 84–85 行，`#selectOperable` / `#selectNone`，静态节点只绑定一次）。但勾选能力只对三个档开放——`LANE_SELECTION` 仅映射 待接受/已接受/已计划（`scripts/web/app.js` 第 1473 行，第 1472 行注释明确「开发中 / 待测试 / 已完成档无可勾选条目」），行首复选框也只在 status 为 submitted / accepted / planned 时渲染（`scripts/web/app.js` 第 1242–1244 行）。

于是在不支持选择的档（开发中 / 待测试 / 已完成，`LANES` 六档定义见 `scripts/web/app.js` 第 13 行）：

1. 列表每一行都没有复选框，但列表头左组仍显示「全选」「全不选」，只是灰显禁用：`syncAcceptance` 对非选择档只把全选置 `disabled`（`!LANE_SELECTION[lane]` 分支，`scripts/web/app.js` 第 1557–1559 行），全不选因当前档勾选数恒为 0 同样 `disabled`（第 1560–1561 行）；两个按钮从不按档隐藏。
2. 这两个按钮在该档是永远不可用的死控件：无可勾选对象、点击无效果，与行内「无复选框」的事实矛盾，视觉上却暗示「本列表可以勾选」。
3. 同一列表头内其他控件都已按档收敛：批量操作右组 `#selGroup` 零勾选整体隐藏（`scripts/web/app.js` 第 1497 行 `group.classList.toggle('hidden', curCount === 0)`，非选择档恒隐藏，`scripts/tests/selection-lane-scope.test.mjs` S2 已断言）、档位快捷入口 `#laneQuickEntry` 仅已接受/已计划档显示（`scripts/web/app.js` 第 1542–1549 行）——唯独「全选/全不选」在非选择档以灰显形式残留，口径不一致。

现状口径来源：REQ-20260908-027 引入成对「全选/全不选」时按档收窄的是**作用范围**（仅当前档、叠搜索），并以 `disabled` 收敛非适用档，未做按档隐藏；按钮常驻则承袭 REQ-20260907-004「静态节点，绑定一次」的列表头策略。最终归因（三选一）在修复阶段写入 design.md，本 README 不预设结论。

## 复现步骤

前置：看板服务已启动（`node scripts/atb.mjs serve`，默认 `http://127.0.0.1:8888`），当前项目至少有一条状态为 开发中 / 待测试 / 已完成 的条目（无则正常流转生成：待接受 → 接受 → 移入计划 → 任务模块启动开发 / 上报完成 / 人工确认完成）。

1. 打开看板，进入「需求」模块，切到「待接受」档：列表头左组可见「☑ 全选」「☐ 全不选」（无勾选时全不选灰显），行首有复选框，勾选后右组出现「已选 N 项 / 接受所选」——此为支持选择的列表的预期形态。
2. 切到「开发中」档（或「待测试」「已完成」）：列表行首没有任何复选框。
3. 观察列表头左组：「☑ 全选」「☐ 全不选」仍渲染在计数与排序控件之后，呈灰显禁用态，悬停 tooltip 仍是全选/全不选语义（「仅勾选当前筛选档内可见的可操作条目…」/「仅取消当前筛选档的勾选」），与本档无复选框的事实不符。
4. 同档对照：右组批量操作区（`#selGroup`）与档位快捷入口（`#laneQuickEntry`）在本档均整体隐藏，唯独全选/全不选常驻灰显——同一行控件显隐口径不一致。
5. 反复切档与等待轮询刷新：非选择档内这两个按钮始终可见（禁用），不会因数据刷新或切档消失。

## 期望行为

- 开发中 / 待测试 / 已完成（即 `LANE_SELECTION` 之外的档）的列表头**不显示**「全选」「全不选」按钮：整体隐藏或按档不渲染均可，不得以 `disabled` 灰显形式保留（实现方式由修复阶段 design.md 定夺）。
- 三个支持选择的档（待接受 / 已接受 / 已计划）行为完全不回归：全选 = 勾选当前筛选档内可见的可操作条目（叠搜索范围，REQ-20260907-009）；全不选 = 仅清当前档勾选、其他档保留（REQ-20260908-027、BUG-20260907-016 跨档保留契约）；当前档无可操作条目时全选禁用、零勾选时全不选禁用；任一批量操作进行中两者防误触禁用。
- 显隐随档即时切换，与 `#selGroup` / `#laneQuickEntry` 一致由 `syncAcceptance` 每轮同步；轮询只改控件态不重建容器，无闪烁。
- 若实现改为按档条件渲染而移动 `#selectNone` 的静态位次（`#laneQuickEntry` 位于其后），需同步更新 `scripts/tests/lane-quick-entry-20260909-007.test.mjs` 的位次契约断言；若保留静态节点仅按档 `toggle('hidden')` 则该契约不受影响。

## 验收说明

- [ ] 开发中 / 待测试 / 已完成档：列表头左组不再出现「全选」「全不选」——页面不可见（样式隐藏或未渲染均可），且不是灰显禁用态。
- [ ] 待接受档不回归：有可操作条目时全选可用，全选后右组「接受所选」出现；零勾选时全不选禁用、勾选后可用。
- [ ] 已接受档（全选/全不选 + 移入计划 + 驳回待接受）、已计划档（全选/全不选 + 移出计划）批量链路全部不回归。
- [ ] 切档即时与跨档契约：在待接受档勾选若干 → 切到开发中档（两按钮消失、勾选不在本档呈现）→ 切回待接受档，勾选保留、按钮恢复显示。
- [ ] 搜索叠加不回归：待接受档搜索过滤后点全选，只勾选可见条目。
- [ ] `npm test`（`node scripts/tests/run-all.mjs`）全绿：`scripts/tests/selection-lane-scope.test.mjs` 增补非选择档「按钮隐藏」断言（现 S2 仅断言 `#selGroup` 隐藏），S6/S7/S10 及 `scripts/tests/impl-entry-ui.test.mjs` 第 299 行等既有「非选择档禁用」断言按新口径更新。
- [ ] 实现方式（静态节点按档隐藏 vs 条件渲染）与受影响测试清单记录在 design.md。

## 界面展示

- 布局：「需求」模块 → 列表头左组（条目计数 / 排序 / ☑ 全选 / ☐ 全不选 / 档位快捷入口）+ 右组批量操作区 + 列表行。现状（缺陷）：六个状态档均渲染全选/全不选，开发中/待测试/已完成档呈灰显禁用死控件；期望（修复后）：仅 待接受/已接受/已计划 三档显示，非选择档彻底消失，行首亦无复选框。演示页内置「现状 / 期望」对照切换。
- 交互：点击状态档 chip 切档驱动按钮显隐与列表重建；选择档内勾选复选框驱动「已选 N 项」计数与右组批量按钮显隐（零勾选整组隐藏）；全选/全不选仅作用当前档（其他档勾选保留）；批量按钮点击进入「进行中」状态（按钮变文案、复选框与全选/全不选防误触禁用）并完成真实流转（接受 → 已接受、移入计划 → 已计划等）。
- 状态反馈：正常态（有条目可勾）、空档空态（本档暂无条目）、批量进行中（全选/全不选与复选框禁用 + 按钮变「…中」）、完成反馈条（✓ 成功消息）四类状态切换；另附操作日志区呈现状态流转。深浅色适配未做（可选项）。

可交互演示：[./ui-demo.html](./ui-demo.html)（单文件、无外网依赖，浏览器直接打开；内置「现状（缺陷）/ 期望（修复后）」切换对照）。

# BUG-20260911-002 发布模块的副标题有问题，不仅仅是 Git 和 App Store，要更通用

- 归属：独立 Bug
- 引入来源：REQ-20260910-029（发布模块需求将副标题定为「Git 远端与 App Store 发布流水线」口径，后续桌面应用目标加入未同步更新；排查与核验过程见 design.md「引入来源（源单）」节）
- 创建：2026-09-11T00:25:37.817Z
- 状态以系统维护的 status.json 为准。

## 现象

进入「发布」模块，模块副标题显示「Git 远端与 App Store 发布流水线：预检 → 计划确认 → 执行 → 核验」，将模块能力限定为两个具体目标，未能概括当前已包含的桌面应用构建，后续扩展目标时也容易再次过时。

代码依据：`scripts/web/app.js` 的 `MODULE_SUB.release` 保存上述文案；`scripts/web/release.js` 的目标列表与空态说明已包含桌面应用（macOS 应用包与 Windows 安装包）。这是一处模块概述文案与现有能力不一致的问题，不表示执行器失败。最初报告所用客户端版本、窗口尺寸和截图：待确认。

## 复现步骤

1. 打开本项目 Status Board，选择已初始化项目。
2. 点击顶栏「发布」，查看模块导航下的副标题。
3. 对照目标筛选器或新建发布面板中的「桌面应用（Electron）」选项，确认副标题仍只列出 Git 和 App Store。
4. 离开后再次进入发布模块，副标题仍使用相同受限文案。即使没有发布运行记录，模块概述也不应将支持范围缩减为两种目标。

## 期望行为

发布副标题使用目标无关的通用描述。本条目约定修复文案为：**「构建与发布流程：预检 → 计划确认 → 执行 → 核验」**。描述模块流程，不枚举渠道，不宣称所有渠道均已可执行。具体目标能力仍由目标选择器和相关说明表达。

本项只要求修正文案及其展示一致性，不新增发布渠道或改变预检、启动、确认、执行、核验的实际行为。执行器能力与新渠道支持范围不在本项内。最初反馈是否另有指定文案：待确认；本节给出可实施、可验收的统一表述。

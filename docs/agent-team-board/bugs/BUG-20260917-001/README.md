# BUG-20260917-001 版本计划发布后，左侧的列表中没有显示版本计划已发布的标签

- 状态：submitted（待人工接受）
- 归属：独立 Bug（引入来源见 design.md）
- 创建：2026-09-17T05:28:23.712Z

## 现象

构建模块「版本计划」页签下，左侧版本计划卡片列表的状态标签只反映版本计划自身的合并状态（`STATUS_LABEL`：计划中 / 合并中 / 已合并 / 失败，见 `scripts/web/build.js` 顶部常量与 `statusChip()`）。从某个「已合并」的版本计划创建产品发布并发布成功（产品发布运行状态 `succeeded`，界面口径「已发布」，见 `REL_STATUS_LABEL` / `relStatusChip()`）之后，左侧该版本的卡片上仍然只显示「已合并」，没有任何「已发布」标识——发布状态目前只出现在右侧详情「发布」页签的运行卡片里。用户必须逐个选中版本并打开「发布」页签，才能知道哪个版本已经真正发布。

代码层面的事实：

- 左侧卡片标题行用 `statusChip(v.status)` 渲染标签（`scripts/web/build.js` `renderVersionList()`），标签集合只有 draft / merging / merged / failed 四态。
- 版本列表数据来自 `GET /api/build/state`（`scripts/server.mjs`），返回的 `versions` 只带版本计划自身字段，不含产品发布状态；发布记录需另行请求 `/api/build-publish/state` 后按 `bldId` 前端过滤（`ensureReleaseData()`，仅打开「发布」页签时按需加载）。
- 产品发布运行通过 `bldId` 字段与版本计划关联（`scripts/lib/product-release-store.mjs`），数据上可支撑「按版本汇总发布状态」，但列表渲染链路未使用。

## 复现步骤

1. 打开看板 Web 界面，进入「构建」模块（版本计划页签）。
2. 确认左侧列表存在一个状态为「已合并」的版本计划；若无，先从已完成的条目创建版本计划并点「合并入 main」完成合并。
3. 在该版本卡片上点「创建并预检」，填写发行版本号（如 `1.2.0`），确认创建产品发布草稿。
4. 完成「预检」→「预览发布计划」→「确认启动发布」，等待发布运行结束：右侧「发布」页签中该运行的状态变为「已发布」（Web App 部署、官网上线、源码双分支同步全部通过）。
5. 观察左侧版本计划列表：该版本卡片标题行的标签仍为「已合并」，无任何「已发布」标识。
6. 刷新页面后依然如此；只有选中该版本并打开右侧「发布」页签，运行卡片上才显示「已发布」。

## 期望行为

- 当某版本计划存在状态为 `succeeded` 的产品发布运行时，左侧版本计划列表中该版本卡片应可见「已发布」标识，口径与右侧「发布」页签一致（绿色 `st-ok` 样式），页面刷新后仍保持。
- 未发布成功的版本不受影响：未创建发布、或发布处于草稿 / 预检 / 发布中 / 失败 / 已取消的版本，卡片仍按原「计划中 / 合并中 / 已合并 / 失败」四态显示，不误显示「已发布」。
- 「已发布」与「已合并」的展示关系（替换原标签还是两个标签并存），以及发布中间态是否也上卡片：待确认（由 design.md 设计阶段确定）；本 Bug 的最低要求是发布成功后左侧卡片必须可见「已发布」。
- 修复不得破坏右侧详情「发布」页签的既有行为；实现方式（列表接口附带各版本发布状态、或前端汇总）由设计阶段确定，注意避免列表加载时对每个版本逐个发请求造成请求风暴。

## 验收说明

1. 按复现步骤完成一次发布成功后，左侧版本卡片可见「已发布」标签；刷新页面后仍在。
2. 未创建发布或发布未成功（草稿 / 预检 / 发布中 / 失败 / 已取消）的版本卡片不显示「已发布」；「计划中 / 合并中 / 已合并 / 失败」原有标签正常展示、按钮禁用规则不变。
3. 同一版本存在多次发布运行（如失败后重试、再发布成功）时，标签以实际最终状态为准，不出现与右侧「发布」页签矛盾的标签（多次运行取哪一条的口径：待确认，随 design.md 定）。
4. 如新增界面文案，按仓库规范同步中英双语（`scripts/web/i18n.js`，参照 BUG-20260912-001）；构建模块现状状态标签为 `build.js` 内中文常量，是否借本单接入 i18n：待确认（以设计阶段决策为准）。
5. 按仓库 TDD 规范在 `scripts/tests/` 新增对应测试（先红后绿），交付前 `npm test` 全量通过。

## 界面展示

**界面布局**：演示还原构建模块「版本计划」页签的左右两栏——左栏为版本计划卡片列表（标题行 = 版本名 + 状态标签，meta 行 = 编号 / 关联单数 / 更新时间，卡片底部为操作按钮组：AI 完善、合并入 main、创建并预检、查看发布记录、删除）；右栏为选中版本的详情（「概况」/「发布」两个页签，「发布」页签内含本版本发布操作区、运行记录卡片列表与运行详情摘要）。

**交互行为**：点击左栏卡片选中并联动右栏；点卡片上的「查看发布记录」直接激活「发布」页签；在「已合并」版本上点「创建并预检」弹出核对弹窗（填发行版本号）→ 生成草稿运行 → 点「发布」进入运行 → 数秒后转为「已发布」；顶栏「一键演示发布流程」自动走完整链路。核心对照：发布成功后，切到「缺陷现状」模式，左栏卡片仍显示「已合并」（并提示缺陷点）；切到「期望修复后」模式，卡片标签变为绿色的「已发布」。

**状态反馈**：演示覆盖正常态、空态（无版本计划）、加载态（正在加载发布记录…）、失败态（发布记录读取失败 + 重试恢复）；发布运行中标签带蓝色运行样式与进度文案，成功为绿色「已发布」、失败为红色「失败」；支持深浅色切换（默认跟随系统）。

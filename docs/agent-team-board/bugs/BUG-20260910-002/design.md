# 设计 — BUG-20260910-002 列表占太多空间，应该调整下，列表和详情页面占比应为 1:2

> 由 Agent 在 /dev 开发前补充，人可随时批注。

## 引入来源（源单）

本 Bug 由哪个需求 / Bug 引入？登记时可暂空或写「未定位」，修复阶段必须归因（三选一，禁止编造）：

- 引入来源：**REQ-20260907-004**（编号经 `atb list` 核验真实存在，2026-09-10 状态 in-progress）——
  「看板整体布局优化」把宽屏需求工作区改为「列表 + 详情并排」双栏，交付口径为
  `grid-template-columns: minmax(0, 1fr) minmax(0, 460px)`（左列表取全部剩余宽、右详情上限 460px），
  **只规定了详情栏上限、未规定两栏比例**，导致详情栏恒为 ≤460px、列表栏独占其余宽度且随视口放大。

## 根因分析

`scripts/web/style.css` `.req-split` 网格第二轨为 `minmax(0, 460px)`（px 上限）：

1. 视口越宽，`1fr` 列表轨吃掉越多宽度，详情轨停在 460px——等效视口 1306px 时约 63% : 37%，
   1920px 时约 73% : 27%，比例不收敛（README 附件实测）。
2. 宽屏下详情抽屉为 `position: static; width: auto`（`.req-split > .drawer`），宽度完全由网格轨决定，
   自身无任何宽口径可调。
3. 需求 / 讨论两模块复用同一 `.req-split` 规则（`oncall.js` 渲染 `req-split disc-split`，
   `.disc-view .req-split` 仅覆盖 flex/min-height、不覆盖列宽），故两处同病。

## 方案

**开源选型（REQ-20260909-015）**：未引入开源库。理由（三选一之「无合适库的原因」）：
本修复是单条 CSS 网格声明（`grid-template-columns` 双轨比例）与契约测试口径调整，
属于平台原生 CSS Grid 能力，无对应可复用的第三方库，引入任何库均属过度设计。

落地口径（`scripts/web/style.css` `.req-split`）：

```css
grid-template-columns: minmax(0, 1fr) minmax(0, 2fr);
```

1. **恒定 1 : 2**：两轨均为 fr 弹性轨，列表 : 详情恒为 1 : 2，随视口同步伸缩；
   详情不再被 460px 上限锁死，成为约 2/3 宽的主阅读区。1306px 视口 ≈ 419px : 837px，
   1920px ≈ 623px : 1247px（计算：内容宽 = vw − 左右 padding 36 − 栏间 gap 14，按 1 : 2 分轨）。
2. **列表轨保底可用（README 边界）**：不取 README 示例的 `minmax(320px, 1fr)`，保留
   `minmax(0, 1fr)`——宽屏断点下限 1021px 时列表轨 ≈ (1021−50)/3 ≈ 324px，本已 ≥320px 可读底线，
   320px 下限在 >1020px 区间永不触发，两者等效；保留 `minmax(0, …)` 同时守住「防内容撑破网格」
   既有契约（layout T4 / pending-alignment R5 / workbench W4 首轨口径不动）。
   列表行单号 / 标题截断与 caption 两行结构（BUG-20260909-009）由既有 flex-wrap / 省略号规则兜底。
3. **超宽视口（README 待确认项）裁定：不另设上限**。恒定 1 : 2 优先；2560px 级视口详情轨约
   1673px，正文单行过长的可读性问题（如出现反馈）应在内容层（如 `.md` 正文 max-width）另行
   处理，不动双栏比例口径。
4. **讨论模块（README 待确认项）裁定：同步 1 : 2，不差异化**。讨论看板复用 `.req-split`
   （无列宽 override），讨论详情同为 markdown 文档流，同样受益于 2/3 主阅读区；
   差异化需引入新 override 且无需求依据，否决。
5. **契约测试同步**：`confirm-lane.test.mjs` T7、`portrait-board.test.mjs` P4 的精确断言由
   `minmax(0, 1fr) minmax(0, 460px)` 改为 `minmax(0, 1fr) minmax(0, 2fr)`；
   `layout.test.mjs` T6 由「第二轨 minmax(0, Npx)、N∈[380,560]」改为「双 fr 轨且比例 1 : 2」
   （原固定上限口径即本单缺陷，直接作废）；T4 首轨断言不变（改名注明列表轨语义）。
6. **窄屏与抽屉口径零改动**：≤1020px 单列 + 覆盖式抽屉媒体查询、REQ-20260908-005 定位口径、
   `drawer-height.test.mjs` D5 全部不动。
7. **可选扩展（可拖拽分隔条，README 待确认项）裁定：本单不做**。对齐 `splitter.js` 的拖拽 +
   持久化属新增能力，超出「比例失调」缺陷修复范围，如需要另行立项。

## 风险与边界

- **风险：恰在断点上沿（1021–1120px）列表轨约 324–357px 偏紧**。缓解：列表行标题省略号截断、
  caption 行内按组换行兜底（BUG-20260909-009 既允许）；`npm test` 全量回归通过。
- **风险：超宽屏详情正文单行过长**（本单裁定不设上限的代价）。边界：可读性反馈出现时在内容层
  加 max-width，不回退比例口径。
- **边界：深 / 浅色主题**——纯布局改动，`rgba(127,140,170,0.05)` 列表底色与边框口径不变，
  两主题下仅两栏宽度变化。
- **边界：窄屏（≤1020px）形态与 REQ-20260908-005 抽屉定位口径不变**（媒体查询未触碰）。
- **边界：不引入 licenses.md**——未使用任何开源库。

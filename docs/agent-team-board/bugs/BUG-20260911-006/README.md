# BUG-20260911-006 全局任务中需要加上批量 Commit 的任务状态

- 归属：独立 Bug（引入来源登记于 design.md，开发阶段归因）
- 创建：2026-09-11T01:44:52.869Z
- 当前状态以系统记录为准；本文不维护状态。
- 关联：REQ-20260910-003（全局任务看板，聚合口径当时只有批量开发 / 批量完善）、REQ-20260910-013（批量 commit CLI）、BUG-20260910-014（任务模块「批量 Commit」面板；其完善时已把「全局任务聚合是否同时加入 Commit」列为待确认遗留项，本单即该遗留项）、BUG-20260911-005（已完成档「开始 Commit」快捷入口）。

## 现象

顶栏「全局」按钮打开的全局任务面板（跨项目只读聚合；REQ-20260910-003 引入，BUG-20260910-004 迁为顶栏入口 + 右侧面板）聚合所有注册项目「在工作」的批量任务，但聚合口径**只覆盖批量开发与批量完善两类，看不到批量 Commit 任务**：某项目创建并运行批量 Commit 任务（批次号形如 `CMT-20260911-001`，状态为待启动 / 执行中 / 已暂停等）时，全局面板不出现该任务的状态、进度、批次号与当前条目，跨项目总览存在盲区；要了解其状态只能逐个切换项目并进入任务模块的「批量 Commit」页签。

已核实的代码依据：

- `scripts/server.mjs` `projectTaskRows()`（约 283-300 行）：单项目聚合仅读取 `batch.unfinishedBatches(dataDir)`（批量开发）与 `refine.unfinishedRefineBatches(dataDir)`（批量完善），过滤已终止后生成任务行；`/api/batch/global`（约 2030 行）直接返回该聚合。`scripts/lib/commit-store.mjs` 已提供同构的 `unfinishedCommitBatches()`（约 176 行，`status !== 'finished'`），但服务端聚合未调用——commit 批次目录（`commits/batches/`）也未纳入 `corruptBatchIds` 损坏账本扫描（约 318-321 行只扫 dispatch / refine 两目录）。
- `scripts/web/app.js`：`GLOBAL_KIND_FILTERS` / `GLOBAL_KIND_LABEL`（约 4377-4383 行）只定义 `develop: 批量开发`、`refine: 批量完善`，无 commit 档；跳转 `gotoProjectTask()`（约 4614-4628 行）只有 `kind === 'refine' ? 'refine' : 'develop'` 两个分支，无 commit 映射。
- 对照：任务模块一级页签已有「批量 Commit」（`scripts/web/app.js` 约 4756-4758 行），批量 Commit 面板（BUG-20260910-014）展示状态 / 当前条目 / 已提交计数等——仅全局聚合层缺失。

## 复现步骤

1. 启动 Status Board（`node scripts/server.mjs`，默认端口 8888；或 Electron `npm run app`），确保注册了至少一个项目（顶栏项目选择器 / 「管理项目」面板）。
2. 在其中某项目进入「任务」模块 →「批量 Commit」页签：有已完成（done）候选时点击「启动」创建批量 Commit 任务（创建只落账本并复制提示词，本身不执行 Git 提交；提交由人工派发的子代理逐项执行）；无候选时先人工确认若干条目为 done 再创建。记下批次号（形如 `CMT-20260911-001`）。
3. 保持该任务未收尾（待启动 / 执行中 / 已暂停均可），回到看板任意页面，点击顶栏「管理项目」右侧的「全局」按钮打开全局任务面板。
4. 观察：对应项目行里不出现该批量 Commit 任务；类型筛选 chips 只有「全部类型 / 批量开发 / 批量完善」；汇总行「执行中 · 待启动 · 排队中 · 已暂停 · 待核对」也不计入该任务。
5. 在面板搜索框输入该批次号（如 `CMT-20260911-001`）：无任何匹配——服务端聚合根本未返回该任务，前端无从显示。
6. 对照实验：同一项目再创建一个批量开发或批量完善任务，未收尾时全局面板能看到它——确认缺失仅发生在 Commit 类型。

## 期望行为

- 服务端聚合纳入 Commit：`/api/batch/global` 的单项目聚合除批量开发、批量完善外，同时返回该项目「在工作」的批量 Commit 批次——口径与另两类一致：`unfinishedCommitBatches`（`status !== 'finished'`）再排除已终止（aborted）。行结构同构：`kind: 'commit'`、batchId（`CMT-…`）、status（prepared / running / paused）、pauseRequested、current（当前条目编号 / 标题 / 子代理会话）、counts、createdAt / lastActivityAt；非队首的 prepared 批次沿用「排队中」口径。
- 聚合必须只读：不得调用 `checkCommitBatch`（其会实时吸收新候选、可能改写 finished，有副作用），计数等用只读计算（如 `commitBatchState`）；不触发锁、核对、结算。
- 前端类型扩展：`GLOBAL_KIND_LABEL` 增加 `commit: '批量 Commit'`，类型筛选档增加「批量 Commit」；commit 任务行沿用现有行结构与词表：状态 chip（待启动 / 排队中 / 执行中 / 已暂停，复用 `batchStatusLabel`）+ 类型徽标「批量 Commit」+ 批次号 + 当前条目（无在途项时显示待启动引导文案）+ 计数行「已提交 X · 异常 Y（= 失败 + 中断）· 待处理 Z · 共 N · 创建 / 活动时间」，与任务模块批量 Commit 面板的 `taskStatsLine` 口径一致。
- 跳转：点击 commit 任务行或「进入项目任务」进入该项目任务模块并激活「批量 Commit」页签（`gotoProjectTask` 增加 commit 分支 → `gotoRuns('commit')`）；点击当前条目编号打开该条目抽屉——仅导航，不创建任务、不执行任何 Git 操作。
- 收尾移出：commit 批次收尾（finished）或终止（aborted）后不再出现在全局聚合（下一轮轮询自然移出，与另两类一致）。
- 搜索与汇总：面板搜索字段（项目名 / 项目路径 / 批次号 / 当前条目编号与标题 / 子代理会话）对 commit 行同样生效；汇总行「执行中 / 待启动 / 排队中 / 已暂停 / 待核对」计数包含 commit 任务。
- 一致性：`corruptBatchIds` 损坏账本扫描同步覆盖 commit 批次目录（`commits/batches/`），损坏时该项目行降级为错误行并标注原因，与 dispatch / refine 目录同口径。
- 面板保持只读总览：不新增创建 / 暂停 / 终止等写操作入口（这些仍在各项目任务模块的批量 Commit 面板内）；批量开发 / 批量完善在全局面板的既有展示、筛选、跳转不回归。

## 验收说明

- [ ] 在某项目创建未收尾的批量 Commit 任务后，打开全局任务面板能在对应项目行看到该任务：类型徽标「批量 Commit」、批次号（CMT-…）、状态（待启动 / 排队中 / 执行中 / 已暂停）与计数（已提交 / 异常 / 待处理 / 共 N），并随轮询自动更新。
- [ ] 类型筛选档出现「批量 Commit」且能单独筛出 commit 任务；汇总行计数包含 commit 任务；面板搜索能按批次号 / 当前条目编号命中 commit 行。
- [ ] 点击 commit 任务行或「进入项目任务」：切换到该项目任务模块并激活「批量 Commit」页签（仅导航，不创建任务、不执行 Git）；点击当前条目编号打开条目抽屉。
- [ ] 批量开发 / 批量完善在全局面板的展示、筛选、跳转不回归；无任务项目、无注册项目空态、加载骨架、单项目读盘失败错误行等既有状态不回归。
- [ ] commit 批次收尾（finished）或终止（aborted）后，下一轮轮询从面板移出；面板不出现任何写操作入口。
- [ ] 服务端聚合保持只读：不执行 `checkCommitBatch` 的实时吸收 / 收尾改写，不触发锁；只浏览全局面板不产生任何 Git 操作（不 commit、不 push）。
- [ ] 人为损坏某项目 `commits/batches/` 下的 `batch.json` 后，全局面板该项目行显示账本损坏错误，不影响其他项目行。
- [ ] 本演示页仅用于界面验收讨论，不代表修复已实现；真实联调用隔离测试仓库核对显示值与账本一致。

## 待确认

- 「待核对」（needs_attention）档对 commit 行的判定口径：与任务模块批量 Commit 面板一致（当前执行未收尾、等待子代理回执后核对），还是仅按账本 status 展示——待开发阶段定。
- 多个未收尾 commit 批次是否逐批成行（与开发 / 完善逐批成行一致，非队首 prepared 显示「排队中」）：commit 面板自身仅展示队首批次概况，建议全局层逐批成行，待确认。
- 全局 commit 行是否展示每单提交号（hash）明细：现有 develop / refine 行不展示回执明细，建议保持一致不展示，待确认。
- `corruptBatchIds` 覆盖 commit 目录是否纳入本单范围（建议随聚合一并修，成本极低），待确认。

# BUG-20260911-003 发布模块界面的新建发布按钮点击无反应，右上角的正常

- 归属：独立 Bug
- 创建：2026-09-11T00:26:28.045Z
- 状态以看板机器记录为准；本文不维护状态副本。

## 现象

发布模块没有发布运行时，内容区展示「还没有发布运行」和「＋ 新建发布」按钮。用户反馈点击内容区按钮无反应，但右上角工具栏同名按钮正常。截图中目标筛选为「桌面应用（Electron）」、状态筛选为「全部状态」。该问题使用户从空态入口无法继续创建发布。

![用户提供的空态截图](attachments/paste-1789086362880.png)

代码核对：`scripts/web/release.js` 的 `render()` 在工具栏和空态中均输出 `id="relNewBtn"`；`bindCommon()` 通过 `view.querySelector('#relNewBtn')` 给首个节点绑定点击事件。工具栏先渲染，这与两个入口行为不同相符。此为静态代码证据，具体浏览器现场复现、版本及控制台错误待确认；引入来源待开发阶段定位，不据此编造关联条目。

## 复现步骤

1. 打开当前项目的 Status Board，进入「发布」模块；使用没有发布运行记录的项目。现有代码以返回的 `runs` 为空决定展示空态，筛选后列表为空是否与本问题同路径待确认。
2. 在目标类型筛选中选「桌面应用（Electron）」，状态保留「全部状态」，确认内容区显示「还没有发布运行」。
3. 点击内容区的「＋ 新建发布」，观察是否出现右侧「新建发布」面板。反馈中的实际结果为没有反应。
4. 点击右上角同名按钮对照：应能打开新建发布面板。关闭面板后再次点击空态按钮，检查差异是否持续。
5. 在「全部目标」下重复上述对照，检查刷新页面、切换筛选引发重新渲染后两入口是否仍可操作；实际覆盖结果待开发阶段记录。

## 期望行为

两个入口打开同一新建发布面板，使用相同字段、默认值与后续流程。保持当前代码默认选择 Git 远端的行为，不能因截图筛选为 Electron 就擅自新增默认值联动。打开或关闭面板本身不创建发布记录，也不触发预检、推送、上传或构建。

面板仍支持目标类型切换、保存草稿、预检以及预检成功后的启动发布流程；关闭后重新打开以及模块重新渲染后，两入口均正常且一次点击只出现一个面板。失败应显示明确反馈，可恢复操作，不能以静默失效代替错误提示。

## 界面展示

[打开离线可交互演示](./ui-demo.html)。演示只用本地模拟数据，不执行真实发布；布局以已有发布模块为依据，表单字段简化，非新增业务范围。

- 界面布局：顶部保留目标/状态筛选及靠右的新建按钮；空态内容卡居中显示说明和第二个新建按钮；打开后右侧侧拉面板包含标题、关闭按钮、目标类型和表单，以及底部草稿/预检/启动操作，背景遮罩可关闭面板。
- 交互行为：切换「缺陷现象/期望修复」可比较内容区按钮不响应与两个入口均打开面板；右上角入口在两种模式下都可打开。面板默认 Git，可切换 Electron 等类型并查看示意字段；关闭与重新打开不产生记录。
- 状态反馈：演示可切换空、正常有记录、加载中、读取失败；失败可重试恢复空态。面板可模拟预检成功/失败，忙碌时禁止重复提交，失败显示原因并允许重试，成功后启用启动操作。模拟启动仅提示需计划确认，不执行发布。

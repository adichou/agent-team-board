# BUG-20260910-004 全局模块入口放在右上角管理项目右边

- 状态：以 status.json 为准，由看板工具维护。
- 归属：独立 Bug
- 创建：2026-09-10T01:54:07.015Z

## 现象

用户反馈：全局模块不属于任何一个项目，不适宜与项目模块并排；应将入口移到右上角「管理项目」右边，点击后弹出侧边页面。

代码静态核对可见，`scripts/web/index.html` 将「全局」放在第二行模块导航的「任务」与「文件」之间；顶栏已有「管理项目」按钮。`scripts/web/app.js` 的 `switchView` 相关视图切换逻辑将 `global` 作为主视图，`refreshGlobal` 从 `/api/batch/global` 获取跨项目数据。这支持入口层级与数据范围不一致的反馈；本次仅完善文档，未运行浏览器复现，实际浏览器、视口尺寸与发生频率待确认。

## 复现步骤

以下为开发阶段待执行的复现路径，不代表已经实测：

1. 启动当前项目 Status Board，打开看板，选择一个已注册项目。
2. 观察顶栏「管理项目」右边以及第二行模块导航，确认「全局」当前与「讨论」「需求」「任务」「文件」并列。
3. 在需求或任务页面点击「全局」，观察其是否替换主工作区，而不是从右侧打开独立面板。
4. 返回项目页面并切换项目，再打开全局总览，核对其展示跨项目任务，与入口所在的项目模块层级不一致。
5. 用没有运行中批量任务的项目集合复查入口；数据为空不应影响入口位置的复现。

## 期望行为

- 顶栏右上区域以「管理项目」「全局」相邻顺序呈现入口；第二行项目模块导航移除「全局」，避免重复入口。
- 点击「全局」从右侧打开全局任务侧边页面，清楚标注跨项目范围，不把打开面板解释为切换当前项目模块。
- 关闭侧边页面后仍处于打开前的项目与模块，保留原工作区的搜索、筛选和浏览上下文；仅明确点击任务的「进入项目任务」才跳转到相应项目任务页。
- 保留现有全局总览的项目分组、任务信息、筛选、搜索与跳转能力，数据范围不受顶栏当前项目限制。
- 本项只调整入口与展示容器，不改变跨项目聚合口径或任务状态。

## 界面展示

### 界面布局

顶栏「管理项目」右侧紧邻「全局」按钮；项目模块导航只保留项目相关入口。右侧面板包含「全局任务」标题、跨项目范围说明、关闭按钮，以及独立的搜索/筛选区域和可滚动任务内容区。任务按项目分组，保留项目名、批次信息和「进入项目任务」操作。窄屏应保证关闭按钮和内容可访问，不被顶栏或横向溢出遮挡；面板具体宽度与断点待确认。

### 交互行为

点击入口打开一个面板，重复点击不叠加面板；关闭按钮关闭面板并将焦点返回入口。键盘可访问入口、筛选、任务跳转和关闭操作。全局面板搜索与筛选不覆盖底层项目工作区的搜索条件。跳转到指定项目任务后关闭面板，目标项目与任务应与被点击的行一致。遮罩点击、Escape 关闭及现有弹层之间的互斥规则待确认。

### 状态反馈

正常时显示跨项目任务分组；首次加载显示加载提示或骨架；无注册项目时显示项目管理引导；有项目但任务已收尾时显示无运行任务说明；搜索/筛选无匹配时显示无匹配提示。首载失败展示错误与重试反馈；后续刷新失败保留上次成功数据并标明刷新失败；单个项目读取失败只在该项目区域提示，不吞掉其他项目数据。关闭操作不应被加载或失败状态阻塞。

- [交互演示（ui-demo.html）](./ui-demo.html)：切换「缺陷现象 / 修复后状态」——缺陷态「全局」在项目模块导航第二行、点击占满主视图；修复态入口移至顶栏「管理项目」右侧、点击弹出右侧全局面板（遮罩/关闭/搜索/按项目分组），含 无匹配 与 单项目读取失败 的状态反馈示意。面板宽度与遮罩细节以开发定案为准。
